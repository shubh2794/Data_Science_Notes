ReAct: Reasoning and Acting, Interleaved

Let a language model emit free-text thoughts between its actions, and feed every observation back into the prompt. This page goes past the loop diagram: the augmented action space in which a thought is an action that changes only the context, which kinds of thought the original study found useful, why thoughts are dense for question answering and sparse for embodied tasks, the reported numbers on multi-hop QA, fact verification, a text game and a shopping site, the error analysis that explains why ReAct alone loses to chain-of-thought on one benchmark, the two hybrids that fix it, fine-tuning on ReAct trajectories, and where the method stops.

01 The gap it targets: reasoning and acting were studied apart

Chain-of-thought prompting reasons over the model's own internal knowledge and never checks it against the world; action-generation work plans and acts in environments but does not reason in language about what it is doing. The original study asks what happens if one frozen model does both in a single trajectory, each half informing the other.

  • Reason-only is a static black box. A chain of thought is generated from parameters alone. It cannot look anything up, so it cannot update a wrong premise — the study names fact hallucination and error propagation as its failure.
  • Act-only has no working memory of its own intent. A model that maps observations straight to actions has nowhere to write down the goal, what it has learned so far, or what to try next. It must infer all of that, every step, from a raw action history.
  • The synergy claimed runs both ways: reason to act (thoughts create, maintain and adjust plans) and act to reason (actions fetch external information that the next thought can use). The hub's agent-loop section has the generic Reason → Act → Observe stepper and the short argument for why interleaving beats either half; this page is the evidence behind it.
What the method is not. No new training objective, no new architecture, no reward. The headline results come from a frozen 540B-parameter model prompted with one to six hand-written example trajectories. Fine-tuning appears only as a secondary experiment (§08).

02 The formalism: a thought is an action that touches only the context

Start from an ordinary agent interacting with an environment, then enlarge its action space with the space of all language. That one move is the whole method.

the base agentat step t the agent receives an observation oₜ ∈ O and takes an action aₜ ∈ A context cₜ = (o₁, a₁, o₂, a₂, …, oₜ₋₁, aₜ₋₁, oₜ) policy aₜ ~ π(aₜ | cₜ) the ReAct augmentationÂ = A ∪ L L = the space of language if âₜ ∈ A (an action): the environment steps and returns oₜ₊₁ cₜ₊₁ = (cₜ, âₜ, oₜ₊₁) if âₜ ∈ L (a thought): the environment is NOT touched, no observation is returned cₜ₊₁ = (cₜ, âₜ)
  • The thought's only effect is on the future policy. Because π conditions on the whole context, writing "the composer is Ilse Varn; next I need her birthplace" into cₜ₊₁ changes every later action distribution. The thought is a self-addressed message — a computed summary of the context placed where the next step will read it.
  • Why this is hard to learn, and why it is prompted. L is unbounded, so learning a policy over Â from reward alone would need enormous exploration. The study's answer is to borrow a strong language prior: a large frozen model, shown a few example trajectories in the prompt, already produces sensible thoughts in the right format.
  • In the text interface this is just alternating lines — Thought:, Action:, Observation: — where the runtime fills in observation lines and the model writes the rest. The model decides when it has written a thought and when it has written an action; the runtime only acts on the latter.
the three prompting baselines as restrictions of the same trajectoryReAct thoughts + actions + observations policy over Â = A ∪ L Act drop the thoughts policy over A only CoT drop actions and observations one pass over L, then the answer Standard drop everything question → answer

The baselines in §04–§09 are built exactly this way, by deleting parts of the same hand-written ReAct exemplars, so the comparison isolates what the thoughts and the actions each contribute.

03 What a useful thought does — and how often to have one

The study lists the jobs thoughts did in its trajectories. None of them is "reason harder about the answer" in the abstract; almost all are about managing the interaction itself.

plan
Decompose the goal
Break the task into sub-goals and write an action plan ("I need X, then Y, then Z").
knowledge
Inject commonsense
Bring in task-relevant background ("a pepper shaker is more likely on a countertop or in a cabinet").
read
Extract from observations
Pull the one fact that matters out of a long observation, so it sits in the context in usable form.
progress
Track progress, switch plans
Note which sub-goal is done and move on to the next.
recover
Handle exceptions, adjust the plan
Notice that a search came back empty or an object is not where expected, and change course.

The five categories are the study's list. The pepper-shaker phrasing paraphrases the style of its embodied-task exemplars; it is not a quoted line.

The design lesson. "Think before every action" is the knowledge-task setting, not the method. For long action sequences the study deliberately let thoughts be sparse and asynchronous — and §09 shows that forcing a narrower, more regular kind of thought there does worse.

04 Knowledge-intensive tasks: the setup

Two benchmarks that reward finding facts, an action space of three text commands over Wikipedia, and a frozen PaLM-540B prompted with six or three examples.

  • HotpotQA — multi-hop question answering that needs reasoning over two or more Wikipedia passages. Scored by exact match (EM).
  • FEVER — fact verification: each claim is labelled SUPPORTS, REFUTES or NOT ENOUGH INFO according to whether a Wikipedia passage verifies it. Scored by accuracy.
  • Question-only setup. The model receives only the question or claim — not the supporting paragraphs. Everything beyond its parameters must come through the actions below. This is what makes the tasks a test of acting, and what makes it a cousin of retrieval-augmented generation with the model itself writing the queries.
actionwhat the environment returns
search[entity]the first 5 sentences of the entity's Wikipedia page if it exists; otherwise the top-5 similar entity names from the Wikipedia search engine
lookup[string]the next sentence in the current page containing string — a simulated Ctrl+F
finish[answer]ends the episode with answer

The interface is deliberately weak — far weaker than a modern retriever — so the model has to retrieve the way a person browses: by name, then by keyword inside a page. The point was to study reasoning-guided retrieval, not to win on retrieval quality.

Prompts and baselines

  • Exemplars: 6 HotpotQA and 3 FEVER cases drawn at random from the training set, each hand-written as a ReAct trajectory. The study reports that more examples did not improve performance.
  • Standard, CoT and Act prompts are the same trajectories with parts deleted (§02's table).
  • CoT-SC — self-consistency: sample 21 CoT trajectories at temperature 0.7 and take the majority answer.

  • ReAct is slower — more steps, more tokens — and only as good as its searches. If the Merrow page had not named its river, the trajectory would have needed more lookups or would have failed: the search-result failure of §07.

  • Sample efficiency. The study plots accuracy against the number of CoT-SC samples: both hybrids stay above plain CoT-SC at every sample count, and reach CoT-SC's 21-sample accuracy with only 3–5 samples. (The curves are in a figure; only those two statements are taken from it here.)

07 Error analysis: hallucination versus search and reasoning failures

To understand §06, the study hand-labelled HotpotQA trajectories: from each of ReAct and CoT, 50 with a correct answer and 50 with a wrong one (by EM), 200 in total. CoT's dominant failure is hallucination; ReAct essentially does not hallucinate, but gets stuck.

Where the trajectories went right and wrong, ReAct vs CoT (HotpotQA, hand-labelled) highlight one category to compare the two methods directly

The study's reading of the table

  • Hallucination is a serious problem for CoT. It is 56% of CoT's failures, and it also contaminates CoT's successes: 14% of correct CoT answers rest on hallucinated reasoning or facts, against 6% for ReAct. ReAct's trajectory is more grounded, fact-driven and trustworthy because it can consult an external source. The broader taxonomy of this failure is on the hallucination & factuality page.
  • The structural constraint costs flexibility. Interleaving forces every reasoning step to sit between actions, and ReAct's reasoning-error rate is higher than CoT's. One frequent ReAct-specific pattern: the model repeats its previous thoughts and actions and cannot break out of the loop. The study suspects greedy decoding contributes.
  • Search quality is the ceiling. Non-informative searches are 23% of ReAct's failures; a bad observation derails the reasoning that follows and the model struggles to recover and reformulate. This is the same "retrieval recall bounds accuracy" story as in open-domain QA.
  • About 3 in 10 "failures" are not failures. Label ambiguity is 29% / 28%: the prediction is right but does not exactly match the gold string. EM undercounts both methods by a similar amount.
The one-line synthesis. CoT is flexible but ungrounded; ReAct is grounded but brittle. That is precisely the complementarity the hybrids of §06 exploit — and it explains how ReAct can be the more trustworthy method while scoring lower EM on HotpotQA.

08 Fine-tuning smaller models on ReAct trajectories

Prompted, ReAct is the worst of the four methods on the smaller PaLM models; fine-tuned on 3,000 trajectories, it becomes the best. A fine-tuned 8B ReAct model beats every prompting method at 62B, and a fine-tuned 62B one beats every prompting method at 540B.

  • Data by bootstrapping. Run the prompted 540B model, keep 3,000 trajectories that reached the correct answer, and fine-tune on them — the same self-generated-rationale bootstrapping idea used for reasoning traces. Each method (Standard, CoT, Act, ReAct) gets its own data generated the same way.
  • The target is the whole trajectory. The model is fine-tuned to decode entire trajectories — all thoughts, actions and observations — conditioned on the input question or claim.
  • Training details reported: batch size 64; ReAct and Act trained for 4,000 steps on both PaLM-8B and PaLM-62B; Standard and CoT for 2,000 steps (8B) and 1,000 steps (62B).
the scaling result, as stated (HotpotQA)prompting, PaLM-8B / 62B: ReAct is the WORST of Standard, CoT, Act, ReAct fine-tuned, 3,000 examples: ReAct is the BEST of the four fine-tuned ReAct @ 8B > every prompting method @ 62B fine-tuned ReAct @ 62B > every prompting method @ 540B fine-tuning Standard or CoT ≪ fine-tuning ReAct or Act (both sizes)

Why the gap is plausible. The study's explanation: fine-tuning Standard or CoT teaches the model to memorise — potentially hallucinated — knowledge facts, whereas fine-tuning ReAct or Act teaches a generalisable skill: how to reason and act to fetch information from Wikipedia. Prompted small models, conversely, struggle to learn the ReAct format and its reasoning from a few in-context examples at all.

A caveat on numbers. The scaling result is reported as a figure; this page states only the orderings the study writes out in its text and does not read values off the plot. How this line of work developed — training the agent loop itself with reinforcement learning — is on the agentic RL page.

09 Decision making: a text game and a shopping site

Here the comparison is not with chain-of-thought but with agents trained on many demonstrations. With one or two in-context examples, ReAct beats an imitation-learning agent by 34 points of absolute success on ALFWorld and the best learned web agent by about 10 points on WebShop.

ALFWorld

  • A text-only game aligned with an embodied household benchmark: the agent navigates and manipulates objects through text commands ("go to cabinet 1", "take pan 1"). Six task types; evaluation on 134 unseen games, in a task-specific setup.
  • Prompts. For each task type, 3 training trajectories were annotated with sparse thoughts that decompose the goal, track sub-goal completion, decide the next sub-goal, and use commonsense about where objects are. Every ordered pair of 2 of the 3 makes one prompt — 6 prompts per task type, 2 exemplars each. Act prompts are the same trajectories with the thoughts deleted.
  • Baseline. BUTLER, an imitation-learning agent trained on 10⁵ expert trajectories per task type.

Which thoughts? ReAct versus an Inner-Monologue-style variant

To test whether the content of the thoughts matters — not just the presence of feedback in the context — the study ran ReAct-IM: the same setup, but with thoughts restricted to the dense, feedback-style pattern of earlier inner-monologue agents, i.e. only (1) decomposing the current goal and (2) naming the current sub-goal to complete.

  • ReAct 71 vs ReAct-IM 53 overall (best of 6), with ReAct ahead on five of the six task types — Clean is the exception.
  • Why IM loses, by the study's inspection: without high-level goal decomposition it often misjudges when a sub-goal is finished or what the next one should be; and without commonsense reasoning it struggles to work out where an item is likely to be.
  • The lesson: flexible, sparse, model-chosen thoughts — planning, commonsense, progress tracking — beat a fixed vocabulary of status updates. External feedback alone is not the active ingredient.

WebShop

  • An online shopping environment with 1.18M real products and 12k human instructions; the agent must buy a product matching an instruction (for flavour, an invented one: "a nightstand with drawers, nickel finish, under 140 dollars"). Evaluation on 500 test instructions.
  • Actions: search, choose a product, choose options, buy. Act is prompted one-shot; ReAct adds reasoning to decide what to explore, when to buy, and which product options are relevant.
  • Metrics: score — the percentage of desired attributes the chosen product covers, averaged over episodes; success rate (SR) — the percentage of episodes in which the product meets every requirement.
  • Baselines: IL, trained on 1,012 human-annotated trajectories; IL+RL, which additionally uses reinforcement learning on 10,587 training instructions.

10 Editing a thought to fix behaviour — and a second model family

Because the policy conditions on its own thoughts, a human can steer the agent by editing a thought instead of taking over the actions.

  • The example (ALFWorld). A ReAct trajectory fails because of a hallucinating thought at step 17. A human edits two thoughts — at steps 17 and 23 — removing the hallucinated sentence and adding hints. The agent's subsequent reasoning and actions change accordingly, and the task succeeds.
  • Why this is new. Correcting an Act agent would mean typing many actions; an RL policy offers no editable intermediate state at all. A thought is a compact, human-readable control point — one sentence of edit replaces many steps of intervention.
  • The general principle — make the agent's plan inspectable and put a human checkpoint where an edit is cheapest — reappears in practice as plan approval and in the tool-use pattern's emphasis on traces you can read.

11 Limitations the original study states — and ones its own results show

context
Demonstrations do not fit
Complex tasks with large action spaces need more demonstrations to learn well, which can exceed the input-length limit of in-context learning.
data
Fine-tuning needs trajectories
Fine-tuning on HotpotQA looked promising (§08), but the study expects that more high-quality human annotations are needed to improve further.
future work
Multi-task and RL
Scaling ReAct with multi-task training and combining it with complementary paradigms such as reinforcement learning are left open.
from §07
Loops and bad searches
Repetitive thought–action loops and uninformative retrievals account for most ReAct failures; prompted ReAct cannot recover reliably from either.
from §06
Rigid interleaving
Alone, ReAct is behind CoT on HotpotQA EM: the structural constraint reduces reasoning flexibility. The best numbers needed a hybrid.
from §09

12 In practice: what happened to the loop after the original study

Everything above is the original method and its reported evidence. This section is general practice since the study, as of late 2026 — fast-moving, implementation-dependent, and not among the study's claims.

  • The default agent loop. The "Thought / Action / Observation" format became the template for tool-using agents generally; most agent frameworks' basic loop is a ReAct loop with structured calls. The design trade-offs — schemas, parallel calls, observation bloat — are on the agentic design patterns page.
  • Reflection as a successor. Reflexion-style agents add an outer loop: after a failed trial, write a verbal self-critique and carry it into the next attempt — agent learning.
  • Evaluating the trajectory, not just the answer. The study's hand-labelled error taxonomy is an early instance of trajectory-level evaluation; the systematic version is on agent evaluation.
  • Observations are untrusted input. Feeding retrieved text straight into the context — the mechanism that removes hallucination in §07 — is also the channel for prompt injection. The study did not address this; any deployed ReAct loop must (failure modes and safety).

13 Common misconceptions

"ReAct beats chain-of-thought." Not uniformly. On HotpotQA alone, ReAct scores 27.4 EM to CoT's 29.4; it wins on FEVER. Its clearer advantage is in grounding (0% hallucination in sampled failures) and the best QA numbers come from combining it with CoT-SC (§06–§07).
"ReAct means a thought before every action." Only for the knowledge tasks. In ALFWorld and WebShop thoughts are sparse and the model decides when to have one (§03); a denser, more regular thought pattern (ReAct-IM) did worse (§09).
"ReAct is a training method." It is a prompting format first. The main results use a frozen model and one to six exemplars. Fine-tuning on bootstrapped trajectories is a secondary experiment that helps small models (§08).
"Grounding in tools eliminates errors." It trades one failure for others. ReAct's failures shift to reasoning loops (47%) and uninformative searches (23%). Grounding is only as good as the observations, and bad observations derail the trace (§07).
"The thoughts are a faithful explanation of the agent's decisions." They are context the policy conditions on, not a guarantee. Editing a thought changes behaviour (§10), so thoughts are causally used — but the study's own false positives (6% of ReAct's correct answers rest on wrong reasoning or facts) show a trace can look justified and still be wrong.

14 Takeaways

  • Augment the action space to Â = A ∪ L: a thought is an action with no environment effect that only extends the context, cₜ₊₁ = (cₜ, âₜ).
  • Useful thoughts manage the interaction — decompose, inject commonsense, extract from observations, track progress, handle exceptions.
  • Dense for reasoning tasks, sparse for long action sequences, with the model choosing when to think.
  • HotpotQA / FEVER: ReAct 27.4 / 60.9 vs CoT 29.4 / 56.3 vs Act 25.7 / 58.9; the hybrids reach 35.1 (ReAct → CoT-SC) and 64.6 (CoT-SC → ReAct), and match 21-sample CoT-SC with 3–5 samples.
  • Error analysis: CoT fails by hallucinating (56% of failures); ReAct by loops and reasoning errors (47%) and bad searches (23%), with 0% hallucination.
  • Fine-tuning on 3,000 bootstrapped trajectories makes ReAct the best method at 8B and 62B, beating prompting at the next size up.
  • Decision tasks: ALFWorld 71% vs Act 45% and BUTLER 37%; WebShop 40.0% SR vs 28.7–30.1% for the learned and act-only baselines — from one or two exemplars.
  • Thoughts are a control surface: editing one sentence can turn a failed trajectory into a success.
