Data Preprocessing

Models rarely consume raw features as-is. Preprocessing cleans, coerces, fills, rescales and encodes columns so the learner sees comparable, well-behaved inputs. Every step is a learned transform whose parameters are estimated from data — which is why most preprocessing bugs are really leakage bugs.

Data Engineering Feature prep Leakage Fundamentals

01 Why preprocess features

  • Scale mismatch. Age 0–100, income 0–10⁶, click-rate 0–1. Any objective built on a distance or a shared learning rate treats one unit as one unit, so the widest column defines the metric. kNN, RBF-SVM, k-means, PCA and neural nets are scale-sensitive; trees are not.
  • Type mismatch. Estimators want a dense float matrix; strings, timestamps and NaN either crash the fit or get silently coerced into nonsense.
  • Conditioning and regularization. Centring shrinks the condition number of the design matrix. An L2 penalty is unit-dependent, so ridge and lasso are only meaningful on standardized inputs.
  • It is a model, not a script. μ, σ, vocabularies, fills and bin edges are parameters: fit once on train, persist, replay at serving.
Takeaway: preprocessing makes columns comparable, typed and well-conditioned — and because it is fitted from data, it belongs inside the model artifact.

02 Cleaning, coercion, and outliers

Before any statistic is computed, the column has to mean one thing.

Coercion and canonical forms

  • Parse, don't trust. Numeric columns arrive as strings with separators, currency symbols or "N/A". Coerce explicitly and count the failures — silently nulling 12% of a column is an incident, not a cleaning step.
  • Sentinels (-1, 9999, 1970-01-01) are missingness in disguise; left alone they poison the mean and stretch the scaler.
  • Canonicalise categories (trim, case-fold, unify "USA"/"U.S.A."/"us") or one level becomes three; likewise mixed units and timezones, which fake bimodality. Deduplicate on a business key before splitting.

Outliers: detect, then decide

  • Three flavours needing different treatment: errors (age 999 — fix), heavy tails (income — transform), genuine rare events (the fraud you are predicting — keep).
  • The z-rule is self-defeating: the outlier inflates the very σ used to detect it. IQR and MAD are robust because the estimator ignores the tails.
  • Escalating treatments: leave it → transform (log1p, Yeo-Johnson) → winsorize at the 1st/99th percentile → flag with an is_extreme indicator → drop. Clip thresholds are parameters: compute on train, reuse everywhere.

03 Missing values

Why a value is missing matters more than how you fill it: the mechanism decides whether any imputation can be unbiased.

The three mechanisms

  • MCAR — missingness independent of everything (a sensor dropped packets). Dropping rows is unbiased, just wasteful.
  • MAR — depends on observed columns (older customers skip the income field). Conditioning on those columns recovers an unbiased fill.
  • MNAR — depends on the unobserved value itself (high earners refuse to state income). No imputation fixes this; add an indicator, model the missingness, or collect better data.
  • MAR vs MNAR is not testable from the data — it is a domain judgement. What you can test is whether missingness correlates with the target; if it does, the flag is a feature.

04 Scaling: the transforms

Four column rescalings you will actually use, plus one row-wise normalizer that is constantly confused with them. Switch the transform and watch the axis — the shape never changes, only the units.

  • Standardization does not make data Gaussian. It fixes the first two moments and leaves skew and kurtosis alone — the histogram above proves it. Need symmetry? Apply log1p, Box-Cox or a quantile transform first.
  • Min-max has no headroom — a test value beyond the training range maps outside [0,1]; decide up front whether to clip.
  • Sparse matrices: subtracting a mean densifies the matrix. Use max-abs, or standardize without centring, on high-dimensional text features.
Takeaway: learn the four column formulas and keep ‖x‖₂ normalization mentally separate — it acts on rows and encodes direction, not magnitude.

05 Which scaler, and when

  • Standardize by default for linear, kernel and neural models and for PCA — PCA is meaningless unscaled because it maximises variance, and variance carries the units of whichever column is largest.
  • Min-max when a bounded input is required: pixels, bounded activations, dashboards.
  • Robust when the column has a heavy tail you have chosen not to remove: median and IQR barely move when 2% of rows are extreme.
  • Nothing for tree ensembles — splits are within-column threshold tests, so any monotone rescaling yields the identical tree while costing you readable split values.

06 Encoding categoricals

Cardinality k decides everything. Below ~15 levels almost anything works; above a few thousand, one-hot stops being an option.

Low and high cardinality

  • One-hot gives k binary columns — interpretable, no false ordering, perfectly collinear with an intercept (drop one level for unpenalised linear models). Ordinal is one column, correct only when the order is real; trees survive it anyway since they can carve subsets out of the integer axis.
  • Target (mean) encoding is compact and powerful, and the single most reliable way to leak the label. It needs smoothing toward the global mean and out-of-fold estimation, so a row's encoding never sees its own label.
  • Frequency encoding uses no label, so it cannot leak. Hashing maps a level to h(c) mod d: stateless, streaming-friendly, constant memory, unseen levels free — at the cost of collisions and of any inverse mapping for debugging.
  • Learned embeddings give each level a trained dense vector — best when k is huge and levels share latent structure (user IDs, SKUs, tokens); see Embeddings. Always reserve an <UNK> bucket.

07 Feature engineering and selection

Encoding makes a column usable; engineering makes it informative — expressing domain structure the model cannot discover from the sample size you have.

Domain extractions

  • Dates. A raw timestamp is a useless integer. Split into calendar parts, durations (days_since_signup), and encode cyclic parts as a sine/cosine pair so hour 23 sits beside hour 0.
  • Text. TF-IDF for linear baselines, contextual embeddings for semantics; cheap structural features (length, digit ratio, language ID) often carry real signal.
  • Geo. Raw lat/long permits only axis-aligned splits; prefer haversine distance to a landmark or an H3/geohash cell as a categorical.
  • Aggregations. Group statistics (a user's 7-day mean spend, a merchant's chargeback rate) are usually the highest-value tabular features — and the most leak-prone, since the window must close before the prediction timestamp.

Interactions, binning, selection

  • Interactions and polynomials let a linear model express curvature; the width explodes combinatorially. Trees learn interactions for free, which is much of why they dominate tabular tasks.
  • Binning buys outlier robustness and lets a linear model bend, at the cost of resolution and arbitrary boundaries.
  • Selection, three families. Filter (correlation, mutual information) — fast, ignores interactions. Wrapper (recursive elimination) — accurate, expensive, overfits easily. Embedded (L1 zeroing, tree importances) — start here.

08 Leakage, and why pipelines exist

If a validation score looks too good, assume leakage until proven otherwise — it is the commonest cause of a model that shines offline and collapses in production.

Fit on train, transform everywhere

  • Every fitted statistic — μ, σ, min/max, medians, vocabularies, target means, PCA loadings, bin edges — is estimated on train alone and merely applied elsewhere.
  • Scaling before splitting is the classic error: test rows contribute to μ and σ. The bias is always optimistic, which is exactly the direction you cannot detect from the score.
  • Under cross-validation the transform must be re-fitted inside every fold; one scaler fitted outside the loop leaks all folds into each other.

Leakage taxonomy, and train/serve parity

  • Target leakage: a feature caused by the label or recorded after it (account_closed_reason predicting churn). Contamination: transforms fitted on the union, or duplicates straddling the split. Temporal: a random split on time-ordered data. Group: the same user on both sides — use grouped splits.
  • A pipeline chains transforms with the estimator so fit and transform cannot be mixed up and the whole thing serializes as one artifact, with column-wise routing (numeric → impute + scale, categorical → impute + encode).
  • Training–serving skew is the production form of the bug: the offline transform is written twice, in two languages, and drifts. Fixes: one shared library, a feature store serving both paths, or logging the exact inference vector and replaying it offline.
  • Guardrail: assert column order, dtype, range and null rate on the served vector, and alert when a transformed feature's distribution moves — the handoff to Monitoring & Drift. Mechanics live in Pandas; the shared repository is the Feature Store.
Takeaway: split first, fit second, transform third — and put the chain in one serializable pipeline so that ordering cannot be violated by accident.

09 Pitfalls & checklist

Pitfalls

  • Scaling, imputing, resampling or selecting features before the split — optimistic scores you cannot see through.
  • Target encoding computed in-fold — near-perfect validation, worthless model.
  • Mean-imputing an MNAR column and dropping the indicator — you delete the informative part and keep the misleading part.
  • Centring sparse text features — turns a 0.1%-dense matrix dense and exhausts memory.
  • Encoder throws on an unseen category at 3am, or a min-max feature silently exceeds [0,1], because nothing asserts.
  • Winsorizing the class you care about — clipping extreme fraud amounts destroys the cases the model exists to catch.

Checklist before training

  • Split (chronological or grouped where relevant) before any statistic is computed; deduplicate on a business key first.
  • Declared dtype per column; coercion failures counted, not swallowed; sentinels mapped to null.
  • Missingness rate logged per column, mechanism reasoned about, indicator added where MNAR is plausible.
  • Scaler matched to the model family, fitted on train, persisted with the model.
  • Categorical vocabulary frozen with an unknown bucket; high-cardinality columns hashed or embedded.
  • No feature references information unavailable at prediction time; every aggregation window closes before the timestamp.
  • The whole chain is one pipeline artifact and the serving path calls the same code.
