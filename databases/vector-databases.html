Vector Databases — HNSW Indexing

How a vector database finds the nearest neighbors of a query fast. Brute force compares the query to every stored vector — O(N), hopeless at a billion vectors. HNSW (Hierarchical Navigable Small World) is the index most production systems use: a layered proximity graph that answers approximate nearest-neighbor queries in ~O(log N).

Data Engineering Vector Search ANN Indexing

01 The problem: approximate nearest neighbors

Semantic search turns text/images into embedding vectors where similarity = geometric proximity. The query is "find the k vectors closest to this one."

  • Brute force (flat): compute the distance to all N vectors → O(N) per query. At 1M vectors × top-5 that's 5M distance computations; at a billion it's a non-starter.
  • The relaxation: accept approximate answers (ANN). Trading a tiny bit of recall for orders-of-magnitude speed is almost always worth it — hence the "A" in ANN.
  • HNSW does this in ~O(log N) by walking a graph instead of scanning a list. It's the engine inside FAISS, pgvector, Qdrant, Weaviate, Milvus, and powers RAG retrieval.
One line: HNSW = a skip-list of graphs — sparse upper layers let you teleport near the answer, dense lower layers refine it — searched greedily from the top down.

02 Two ideas, combined

IdeaWhat it gives HNSW
Skip lists (hierarchy)Multiple graph layers stacked on each other. The top is sparsest, each layer down is denser. You descend coarse→fine, like express then local trains.
Navigable Small World graphsAny node is reachable from any other in a few "hops." Each vector links to its nearest neighbors per layer — enough connectivity to navigate, without connecting everything to everything.
  • Layer assignment is probabilistic: a node's top layer is drawn so the probability of reaching level ℓ decays exponentially — most nodes live only on the base layer, a few reach high. That's what makes the upper layers sparse.
level = ⌊ −ln(uniform(0,1)) · m_L ⌋ P(node reaches layer ℓ) ∝ e^(−ℓ / m_L)

03 Searching: greedy descent through the layers

Start at a fixed entry point on the top layer; greedily hop to whichever neighbor is closest to the query; when you can't get closer, drop down a layer and repeat. The base layer returns the answer. Step through it:

HNSW layered greedy search ▶ step the search from the top layer down
  • At each layer the search keeps a dynamic candidate pool of size ef (efSearch): it tracks the ef closest nodes found so far, expanding their neighbors until none get closer.
  • Bigger ef explores more of the graph → higher recall, slower query. It's the main accuracy↔latency knob at query time.

04 Building the index (insertion)

  • 1. Pick a level for the new vector from the exponential distribution above.
  • 2. Find entry: greedy-search from the top down to the new node's top level to locate good entry points (just like query search).
  • 3. Connect: from that level down to layer 0, link the new node to its M nearest neighbors on each layer (using Euclidean or cosine distance). A neighbor-selection heuristic keeps links diverse, not just nearest.
  • 4. Prune: if connecting pushes an existing node over its max degree, drop its weakest links to preserve the small-world property.
  • Construction explores with its own, usually larger, pool efConstruction — higher = better-quality graph, slower build.

06 Complexity & trade-offs

Cost
Query~O(log N) — layer-by-layer navigation
Build~O(N log N) — each insert is a search
MemoryO(N · M) — the graph stores M links per node on top of the vectors
  • The three-way tension is recall ↔ query speed ↔ memory. M and ef trade recall for speed/RAM; HNSW is fast and high-recall but memory-hungry and slow to rebuild/delete.
  • Vectors are often quantized (e.g. product quantization) to shrink the memory footprint.

07 HNSW vs other ANN indexes

IndexIdeaTrade-off
Flat (brute force)Compare to every vectorExact, simple; O(N) — fine only for small N
IVF (inverted file)Cluster vectors; search only the nearest few clustersLess memory, fast; recall depends on #probes; needs training
HNSW (graph)Navigable small-world graph, hierarchicalTop recall & speed; high memory, costly updates
IVF + PQClusters + compressed vectorsTiny memory at scale; lower recall

HNSW is the default when recall and latency matter and you can afford the RAM; IVF/PQ wins when memory is the constraint at billion-scale.

09 Takeaways

  • HNSW = hierarchy (skip list) + navigable small-world graph. Sparse top layers teleport you near the target; dense base layer refines.
  • Search is greedy descent: hop to the closest neighbor, drop a layer when stuck; ~O(log N) instead of O(N).
  • Tune with M (degree), efConstruction (build quality), efSearch (live recall↔latency).
  • Cost: excellent recall/speed, but memory-hungry and awkward to update — quantize to shrink it.
  • The retrieval layer under Embeddings + RAG; the approximate cousin of exact k-Nearest Neighbors.
