Attention Mechanisms

The idea that powers modern AI: let a model decide, for each element, which other elements to read from — and how much. From the 2015 seq2seq fix to the efficient variants inside today's LLMs.

Deep Learning Sequence modeling LLM internals

01 The bottleneck attention solved

Attention was born to fix a specific failure in RNN translation models, then turned out to be a general-purpose mechanism.

Early sequence-to-sequence models (Bahdanau et al., 2015) encoded an entire source sentence into a single fixed-size context vector, then decoded from it. For long sentences this is a brutal bottleneck — all the meaning squeezed through one vector, with early words forgotten by the time decoding starts.

The fix: instead of one frozen summary, let the decoder look back at all encoder states at every step, and form a fresh, weighted blend tailored to the word it's currently producing. The model effectively learns to "search" the source for the relevant parts — that search is attention.

One sentence: attention is a differentiable, content-based lookup — a soft "which of these to read, and how much?" that the network learns end-to-end.

02 Alignment & the context vector

Three steps: score every source element, normalize to weights, blend the values.

To produce decoder step i, we compare the decoder's state against each encoder hidden state h_j to get an alignment score e_ij, soften those into weights with softmax, and sum:

eᵢⱼ = score(sᵢ₋₁, hⱼ) αᵢⱼ = softmaxⱼ(eᵢⱼ) (weights sum to 1) cᵢ = Σⱼ αᵢⱼ · hⱼ (the context vector)
  • Scores say how relevant each source position is to what we're decoding now.
  • Softmax turns them into a probability distribution over source positions.
  • Context vector c_i is the attention-weighted sum — a custom summary for this decode step.

The query/key/value framing generalizes this: the decoder state is the query, the encoder states are the keys (for scoring) and values (for blending).

03 Additive vs dot-product scoring

Two ways to compute the alignment score — a small MLP, or a dot product.

Additive (Bahdanau, 2015)

eᵢⱼ = vᵀ · tanh( W·sᵢ₋₁ + U·hⱼ )

A tiny feed-forward net learns the compatibility between query and key. Expressive, but it adds parameters and runs slower because the score can't be expressed as one big matrix multiply.

Multiplicative / scaled dot-product (Luong 2015; Vaswani 2017)

e_ij = (qᵢ · kⱼ) / √dₖ

Just a dot product, scaled by 1/√dₖ. Less expressive per-score, but it maps onto highly optimized matrix multiplication (BLAS/GPU), so it's dramatically faster — and empirically just as good. This is the form used in every modern Transformer.

Why the √dₖ?

Over dₖ dimensions, a dot product of unit-variance vectors has variance dₖ — it grows with dimension. Large scores push softmax into a near one-hot spike where gradients vanish. Dividing by √dₖ rescales variance back to ~1 and keeps training stable.

04 Self vs cross attention

Same mechanism, different sources for Q, K, and V.

  • Self-attention: Q, K, V all come from the same sequence. Every token attends to every other token in its own sequence — this builds rich contextual representations and is what makes the encoder (and decoder-only LLMs) work.
  • Cross-attention: Q comes from one sequence (the decoder), K and V from another (the encoder output). The decoder reads relevant source content while generating — the bridge in encoder–decoder models like translation and summarization.
Self-attention is why Transformers replaced RNNs; cross-attention is how the original encoder–decoder passed information between the two stacks. See Transformers → encoder–decoder.

05 Multi-head attention

One attention map captures one kind of relationship. Run several in parallel and you cover many.

MultiHead(Q,K,V) = Concat(head₁, …, headₕ) · Wᴼ headᵢ = Attention(QWᵢᵠ, KWᵢᴷ, VWᵢⱽ)
  • Project Q/K/V into h subspaces of size d_model/h, attend independently in each, concatenate, and mix with Wᴼ.
  • Different heads specialize — syntax, coreference, local adjacency — giving an ensemble of relationship detectors at roughly the same total cost as one full-size head.
  • Stacked layers compound this: layer 1 relates token pairs, layer 2 relates pairs-of-pairs, broadening the effective receptive field.

The number and sharing of key/value heads is exactly what the efficient variants below change.

06 Masking

Set forbidden scores to −∞ before softmax so they get zero weight.

  • Causal (look-ahead) mask: set e_ij = −∞ for j > i, so position i can only attend to positions ≤ i. Enforces autoregressive generation and is used in language-model pretraining — no peeking at the answer.
  • Padding mask: set e_ij = −∞ wherever j is a padding token, so artificial padding never contributes to the weighted sum.
masked_scores = scores + mask (mask ∈ {0, −∞}) weights = softmax(masked_scores) (−∞ → weight 0)

07 Global vs local attention

Does every token attend to all others, or just a nearby window?

Global attention

Each token attends to the entire sequence — full expressiveness, but O(n²) compute and memory in the sequence length n. This quadratic cost is the central scaling pain of Transformers.

Local / sliding-window attention

Restrict each token to the last W positions: it attends only to [t−W, t]. Cost drops to O(n·W). Crucially, stacking layers recovers a wide effective context — after L layers, information can propagate up to L·W tokens, even though any single layer is local.

Example: Mistral 7B uses sliding-window attention so a deep stack of local windows yields a long effective context cheaply — global reach, local cost.

08 The KV cache problem

Why generation is memory-bound — and why everything below exists.

During autoregressive decoding, the keys and values of all earlier tokens don't change. Recomputing them every step would be O(n²), so we cache them: each new step only computes K/V for the single new token and reuses the rest, making per-step work O(n).

The catch: that cache grows with sequence length × number of heads × layers. For long contexts it becomes the dominant memory cost and the bottleneck on inference throughput — reading it from memory, not the math, is what limits speed.

Standard MHA KV-cache ∝ H · L · dₕ (per token) H = number of heads L = layers dₕ = head dim

The efficiency variants all attack this same term — by sharing or compressing the key/value heads.

09 MQA, GQA & MLA

Keep many query heads, but use far fewer key/value heads. Drag the slider to see the cache shrink.

Query heads → key/value heads 8 query heads, sharing a varying number of KV heads · 1 = MQA, 8 = full MHA

Multi-Query Attention (MQA, 2019)

All H query heads share a single key/value head. KV-cache shrinks from O(H·L·dₕ) to O(L·dₕ) — a big inference speedup, at some cost to quality. Used in PaLM and others.

Grouped-Query Attention (GQA, 2023)

The middle ground: split H query heads into G groups, each group sharing one KV head (1 < G < H). Tunes the quality/efficiency trade-off directly. Used in Llama 2/3, Gemma, Mistral.

Multi-Head Latent Attention (MLA, 2024)

Instead of sharing heads, compress K and V jointly into a low-rank latent c = W_DKV · h, then expand back up when needed. DeepSeek-V3's approach — drastically smaller cache while keeping near-MHA quality.

10 Linear & windowed attention

Attacking the O(n²) compute itself, not just the cache.

  • Linear attention (Linformer, 2020): the attention matrix is empirically low-rank, so project K and V to a small fixed dimension before attending — turning O(n²) into O(n), with a small accuracy trade-off.
  • Sliding-window MQA (Mistral): combine local windows with shared KV heads — cheap on both compute and cache, global reach via depth.
  • Lightning Attention (2024): a hardware-optimized linear attention that splits each sequence into blocks, computing exact intra-block attention plus an accumulated inter-block term for stability at very long lengths.
  • FlashAttention: not a new math formula but a kernel-level reordering that keeps the attention computation in fast on-chip memory, avoiding materializing the full n×n matrix — same result, far less memory traffic.
Two distinct levers: cache size (MQA/GQA/MLA) governs generation memory; compute complexity (linear/windowed/Flash) governs how long a sequence you can process at all.

12 Takeaways

  • Attention = learned, content-based blending. Score every candidate, softmax to weights, sum the values.
  • Born to fix seq2seq — one context vector couldn't hold a long sentence; attention re-reads the source per step.
  • Dot-product won over additive because it's a single fast matmul; the √dₖ scaling keeps softmax gradients alive.
  • Self vs cross, global vs local, causal vs padding masks — same core op, different wiring.
  • Modern LLM efficiency is mostly about the KV cache. MQA/GQA/MLA share or compress key/value heads; linear/windowed/Flash attack the quadratic compute.
