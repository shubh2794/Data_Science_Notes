29 Sliding windows, dilation and sinks: capping n instead of shrinking the per-token cost

MQA, GQA and MLA reduce the bytes per token. The other lever is to reduce the number of tokens each query reads. That is a mask (§15), it costs nothing to implement, and depth quietly gives most of the range back.

the mask, and the receptive field it leaves sliding window position i reads j ∈ [i − w + 1, i] w keys, not i cost O(n·w) instead of O(n²) scores per layer cache capped at w tokens — a ROLLING BUFFER of fixed size, written at index (t mod w), never growing and the reason it is not as restrictive as it looks: stacking. after 1 layer position i has seen w positions after 2 layers position i has seen 2w−1 (its window's windows) after k layers k(w−1) + 1 so a stack of L layers has an effective span of L·(w−1) + 1. w = 4096, L = 32 → 32 × 4095 + 1 = 131 041 ≈ 131 072 = 32 × 4096 That is exactly the argument a 4096-window, 32-layer model makes for having a 131k "theoretical attention span" while every individual layer looks 4096 tokens back.

The word doing the work is "effective". Information can travel L·w tokens, in the same sense that a stack of 3×3 convolutions has a receptive field that grows with depth — and with the same caveat the convolution page measured: the effective receptive field is much smaller than the theoretical one, because the influence of a distant token has been averaged through L attention rows on the way. A token 100 000 positions back is reachable; whether any of it survives is an empirical question and the answer is usually "much less than the arithmetic suggests".

Attention sinks: why the first token has to stay

This is the most useful non-obvious fact about windowed attention, and it follows directly from §07's observation that a softmax has no "no match" output.

The argument — an observation plus the explanation that fits it best. The observation: in trained causal models, a large share of many rows' weight lands on the first token (or the first few), positions whose content is semantically nearly empty. The explanation: a softmax row sums to one whatever the scores are, so a query with nothing relevant to attend to must still put its full unit of weight somewhere, and the model learns to use a sink — a position that everyone can reach and that carries little value — to absorb the leftover mass. In a causal model the natural candidate is the first token, because it is visible to every subsequent position. Evict it — which a naive rolling window does the moment the sequence exceeds w — and every row's spare mass has nowhere to go, so it is redistributed onto genuinely irrelevant recent tokens, and perplexity blows up at exactly the point where the window first slides past position 0. Keeping a handful of tokens (four is the usual number) from the very beginning, permanently, restores it. That is a change of four entries in a mask, and it is the difference between a model that streams indefinitely and one that degrades the instant its buffer wraps. What it does not do is extend the model's memory: a window-plus-sinks model still only sees the last w tokens, and the sinks fix the arithmetic of the softmax, not the reach of the model.

30 Linear attention: what re-associating buys, and what it gives back

Linear attention replaces the softmax with a feature map applied to queries and keys separately, so the weights are φ(q)·φ(k)ᵀ. Then the brackets can be moved — φ(Q)(φ(K)ᵀV) instead of (φ(Q)φ(K)ᵀ)V — and the cost falls from O(n²d) to O(nd²), with a fixed-size state instead of a growing cache. The n² term existed only because the softmax sat between QKᵀ and V and stopped the re-association. What it gives up is not an approximation error; it is a rank, and it is the same rank argument this page opened with.

No cache that grows. This is the property that makes linear attention attractive for generation, and it is exactly the property of the recurrent cell on the RNN page.

What it gives back, stated as the same counting argument as §01

two ways to say the same thingRANK. The mixing matrix is A ∝ φ(Q) φ(K)ᵀ, a product of an (n × d′) and a (d′ × n) matrix, so rank(A) ≤ d′ Softmax attention's A is not so constrained — exponentiating a rank-dₖ score matrix generally produces a FULL-RANK weight matrix, because eˣ applied elementwise is not a low-rank operation. With d′ = 128 and n = 8192, linear attention can express mixing matrices of rank 128 and softmax attention can express rank 8192. CAPACITY. The recurrence stores a fixed (d′ × d_v) state. The input it has to summarise is n·d_v numbers. By exactly the RNN page's bottleneck argument, the average recoverable fraction is d′·d_v / (n·d_v) = d′ / n which falls with the sequence length. THE BOTTLENECK OF §01 IS BACK, with dₕ replaced by d′. That is not a coincidence and it is not a defect of one particular feature map: any mechanism whose per-token state does not grow with n obeys it.

So the honest summary of why linear attention has not displaced softmax attention is not "it is a bit less accurate". It is that softmax attention's advantage is precisely the thing that makes it expensive: it keeps every key and value and so has no fixed-capacity summary to overflow. The O(n²) cost and the exact-recall ability are the same property seen from two sides, and every linear-time method trades one for the other. State Space Models is the same trade made with a differently designed recurrence — one built to keep more of the input within the same fixed state — and it is worth reading against this section.

31 FlashAttention: the same answer, the same arithmetic, a different amount of memory traffic

This is the one entry in the efficiency literature that changes nothing about the mathematics. Same output, bit-comparable up to reassociation, same MAC count. What changes is how many times the data crosses the gap between the chip and its memory — §20 showed that the n² matrix is what binds at training time, and §26 showed why bytes rather than operations are the binding resource in general.

the memory hierarchy the argument is about (the A100 numbers the design was made for) on-chip SRAM ~192 KB per streaming multiprocessor, 108 of them (~20 MB in total), bandwidth on the order of 19 TB/s HBM 40–80 GB, 1.5–2.0 TB/s a factor of ~10 in bandwidth and ~10³ in capacity. An operation that touches HBM once per element is roughly ten times slower than one that keeps its working set on chip, whatever its FLOP count. what a naive attention kernel does to HBM 1 read Q, K write S = QKᵀ n² elements OUT 2 read S write A = softmax(S) n² IN, n² OUT 3 read A, V write Z = A·V n² IN ───────────── at least 3n² HBM round-trips on an object that is n² in the first place. Total: Θ(n·d + n²) HBM accesses. what a fused, tiled kernel does instead Split K and V into blocks that FIT IN SRAM. For each block, load it once, compute that block's partial scores and partial output, and COMBINE it into a running result — never writing S or A to HBM at all. block sizes: B_c = ⌈M / 4d⌉ , B_r = min(⌈M / 4d⌉, d) M = SRAM size Total: Θ( n²·d² / M ) HBM accesses. The tiled kernel's traffic is a FRACTION d²/M of the naive kernel's n² term. With a head width of 64 and 192 KB of SRAM — 49 152 fp32 elements — that fraction is 1/12, and counting the three passes the naive kernel makes through the n² object it is a factor of 36 in the figure below; the reported measured saving on a real kernel is up to about 9× fewer accesses, because the n·d terms and the recompute in the backward pass are not free.

The one piece of mathematics it needs: an online softmax

You cannot normalise a softmax until you have seen every score, and the whole point is not to hold every score. The resolution is a running rescaling, and it is exact:

combining a running result with one new block, exactly state after some blocks: m (running max), ℓ (running sum), O (running output) new block gives: m̃ (its max), ℓ̃ (its sum), Õ (its output) m′ = max(m, m̃) ℓ′ = e⁽ᵐ⁻ᵐ′⁾·ℓ + e⁽ᵐ̃⁻ᵐ′⁾·ℓ̃ O′ = ( e⁽ᵐ⁻ᵐ′⁾·ℓ·O + e⁽ᵐ̃⁻ᵐ′⁾·ℓ̃·Õ ) / ℓ′ Every term is bounded by 1 because both exponents are ≤ 0, so this is as overflow-safe as the ordinary max-subtracting softmax — it IS the ordinary max-subtracting softmax, applied incrementally. The result is EXACT: not an approximation, not a low-rank sketch, not a sparsity pattern. The same numbers, in a different order.
Why the backward pass is the interesting half. The backward pass needs A (§17), and A was never stored. The fix is to recompute it, block by block, from Q, K and the saved row statistics (m, ℓ) — which costs extra arithmetic and saves the same quadratic memory traffic. It is gradient checkpointing applied to one operation, and it wins for exactly the reason §26 gives: the arithmetic was never the binding resource. This is also why the reported end-to-end speedups vary so much by sequence length — 15% on a 512-token model, 3× at 1K, more at longer — since the fraction of time spent in attention is itself a function of §19's crossover.

Tiled attention with an online softmax: the running state, and the traffic it avoids step through the key blocks and watch the running max, sum and output update — the final result is checked against the direct computation
Two things it is not. It is not an approximation — the output is the same function, and any difference from a one-shot computation is floating-point reassociation at the level of round-off. And it does not reduce the O(n²) arithmetic — §18's MAC count is unchanged, to the operation. What it removes is the n² materialisation, which is why its headline effect is on the maximum sequence length that fits (§20) at least as much as on speed.

32 Long context: what breaks in the mechanism itself

Two distinct things fail as n grows, and they are usually conflated. One is about positions the model has never seen, which is a positional-encoding question and belongs elsewhere. The other is about the softmax itself, is independent of the positional scheme, and has a closed form.

Scope, stated before the argument. Position interpolation, NTK-aware scaling, YaRN, needle-in-a-haystack evaluation and the lost-in-the-middle effect are owned by Context-Length Extension, and the positional schemes themselves by the Transformer page. This section owns only the part that would still be true if positions were free: a softmax over more keys is a harder softmax.
the model: one right key with a logit margin m, n−1 distractors with logits ~ N(0, σ²) p(right key) = exp(m) / ( exp(m) + ∑ⱼ exp(sⱼ) ) E[ ∑ⱼ exp(sⱼ) ] = (n−1) · exp(σ²/2) (a log-normal mean) so p ≈ 1 / ( 1 + (n−1)·exp(σ²/2 − m) ) and holding p fixed as n grows requires m*(n) = ln(n−1) + σ²/2 + const THE MARGIN MUST GROW LIKE ln n. Not like a constant, not like √n — logarithmically, which is the good news and the bad news at once.

The measured column matches the closed form to four decimal places at every length past 512, and the residual converges to σ²/2 = 0.5 exactly. So the mechanism-level statement is precise: a head that could reliably find its key among 512 candidates needs about ln(131072/512) = 5.5 more nats of margin to do it among 131 072. Whether it has them is an empirical question about what training produced, not about the architecture.

The same effect seen from the entropy side (§23): at a fixed logit scale, a row's entropy grows almost exactly like ln n — measured H/ln n rises from 0.829 at n = 8 to 0.958 at n = 131 072 for σ = 1. The row keeps reading a roughly constant fraction of an ever-larger set, which is the same statement as the margin one: nothing in the mechanism sharpens automatically as the context grows.

Finding one key among n: the probability, and the margin the softmax demands the fitted intercept in the readout is the derivation checked — it should land on σ²/2, and it does to within the sampling error
Why the news is mostly good. ln n is a very forgiving growth rate: going from 4 096 to 131 072 tokens — a 32-fold extension — requires only ln 32 = 3.47 extra nats of margin, and a logit is a dot product of two dₖ-dimensional vectors, so there is plenty of room. This is part of why long-context extension works at all. It is also why it is not free: the margin has to be learned, the training data has to contain examples that require it, and a model fine-tuned only on short documents has no reason to have produced it. That is the mechanism behind the empirical finding that a big context window is necessary and not sufficient.
