Autoencoders & VAEs

An autoencoder is a network trained to copy its input to its output through a bottleneck it cannot fit the input into. That sounds like a trivial task with a pointless obstacle, and it would be, except that the obstacle is the entire point: forced to throw information away, the network must decide what to throw away, and that decision is a model of the data. The first half of this page is about the deterministic version of that idea and the four different ways of imposing the obstacle — a narrow code, a sparsity penalty, added noise, a penalty on the encoder's Jacobian — each of which buys something different. The second half replaces the deterministic code with a distribution, which turns the same architecture into a probabilistic generative model with a real objective: a lower bound on the log-likelihood of the data. Everything difficult about the variational autoencoder — the trick that makes its gradient usable, the collapse that makes its latent variables vanish, the blur in its samples — follows from that one substitution.

01 A learned identity with something in the way

Two networks, back to back, trained to undo each other. Nothing about that is interesting until you make it impossible.

input x ∈ ℝD→encoder f→code h ∈ ℝd→decoder g→reconstruction r ∈ ℝD→loss L(x, r)

The whole model in one line

  • An autoencoder is a pair of maps h = f(x) and r = g(h), trained by minimising a reconstruction loss L(x, g(f(x))). There are no labels: the target is the input. That makes it self-supervised in the most literal sense.
  • Nothing else in the definition is fixed. f and g can be a single matrix each or a forty-layer convolutional stack; L can be squared error, cross-entropy, or a learned perceptual distance; the code h can be a real vector, a sparse vector, an integer index, or a probability distribution. Every named autoencoder in this page is one choice of those four things.
  • The output is usually thrown away. What is kept is f — the encoder — because the code it produces is a representation, and the training signal that produced it needed no annotation at all.

Why the unconstrained version is worthless

  • If f and g are unconstrained and have enough capacity, the global optimum is g ∘ f = identity, achieving zero loss and learning nothing at all about the data. The model has memorised a routing scheme, not a structure.
  • The pathological case is worth holding in mind even though it does not happen in practice: with a one-dimensional code and a sufficiently powerful nonlinear encoder, a network could in principle encode training example x⁽ⁱ⁾ as the scalar i and have the decoder look up the table. Perfect reconstruction, zero understanding. Narrow does not mean informative.
  • So an autoencoder is only ever as good as the constraint you put on it. Every section from §03 to §11 is one such constraint, and the honest way to read them is as answers to the question "what am I forbidding, and what does forbidding it force the network to notice?"

The two forces, which is the sentence to remember

force 1
Reconstruct
Push g(f(x)) toward x — but only for x drawn from the data. The autoencoder is never asked to reconstruct inputs that the data distribution does not produce, and that asymmetry is the whole source of its usefulness.
force 2
Be insensitive
A constraint or penalty that prefers a map which ignores its input: a narrow code, a sparsity penalty, injected noise, a small Jacobian, a KL pull toward a fixed prior. Alone it would produce a constant.
the compromise
Sensitivity only where the data varies
Neither force alone is useful. Together they force the code to be sensitive along the directions in which the data actually moves and insensitive to everything else — which is a local coordinate system for the data manifold (§11).

02 The family tree, and how to read the rest of this page

Every autoencoder in the literature is the same two networks with a different answer to one question: what stops g ∘ f from being the identity? Read the table as a list of answers.

VariantWhat blocks the identityWhat it buys, and what it costsWhere
UndercompleteThe code is narrower than the input: d < D.The cheapest possible constraint, and with a linear decoder it lands exactly on the principal subspace. Costs you the ability to use a wide code at all, and says nothing about which narrow code you get.§03–§05
SparseA penalty Ω(h) on the code, usually λ‖h‖₁.Lets the code be wide — even overcomplete — while only a few units fire per example. Reads as a latent-variable model with a Laplace prior. Costs a hyperparameter and a scale ambiguity.§07
DenoisingThe input is corrupted; the clean input is the target.The reconstruction cannot be a copy because the copy is wrong. What it learns is a vector field pointing back at the data manifold — which is the score. Costs a noise level you must choose.§08–§09
ContractiveA penalty on ‖∂f/∂x‖²F, the encoder Jacobian.Explicitly asks the code to be flat in every direction, so the directions where it is not flat are the manifold's tangent space. Costs a Jacobian computation and needs the decoder scale pinned down.§10
VariationalThe code is a distribution, pulled toward a fixed prior by a KL term.Turns the whole thing into a generative model with a likelihood bound, so you can sample. Costs a gradient estimator, a bound gap, and a new failure mode (posterior collapse).§16–§25
Vector-quantisedThe code is snapped to the nearest of K learned vectors.Discrete latents with a constant KL, so no collapse; hands the generative modelling to a separate prior over indices. Costs a non-differentiable step that has to be faked.§26
Two halves, one hinge. §03–§15 treat h as a vector and the model as a feature extractor: everything is deterministic, the objective is reconstruction, and there is no probability anywhere. §16 replaces h with a distribution q(z | x), and from that single change the entire second half follows mechanically — a bound instead of a loss, a sampling step inside the forward pass, a prior instead of a penalty, and the ability to generate rather than only to encode.

27 Where this lands today — the latent space everything else runs in

The autoencoder lost the generative-modelling contest and won something larger: it became the coordinate system that the winning generative models operate in. This is why the diffusion page keeps pointing back here.

Latent diffusion, stage by stage

  • Stage one is an autoencoder — this page's subject — trained with a reconstruction term, a perceptual loss and a patch-based adversarial objective, explicitly to keep reconstructions on the image manifold and to avoid the blur that a pure pixel-space L¹ or L² loss produces (§24). It is regularised in one of two ways: a slight KL penalty toward a standard normal — a VAE with a very small β, deliberately mild so the latent does not lose information — or a vector-quantisation layer in the decoder, which is §26's construction absorbed into the architecture.
  • Stage two trains a diffusion model entirely inside that latent space, and decodes once at the end. Everything the diffusion page says about schedules, samplers and guidance happens to z, not to pixels.
  • The economics: attention cost grows quadratically in the number of spatial positions, and every one of the tens of denoising steps pays it. Shrinking the canvas by a factor f per axis discounts all of them. That is the whole reason high-resolution text-to-image fits on one consumer GPU — and the diffusion page's §10 is the same story told from the other end.

The autoencoder is a hard ceiling: anything the encoder discards can never be recovered, however good the diffusion model is.   • Read the f = 16 row against f = 8: squeezing four times harder in space needed four times as many channels to hold the same quality. Compression is a budget, not a free lunch, and the spatial-versus-channel split is a design choice, not a saving.
  • Read the f = 32 row as the ceiling asserting itself: reconstruction FID jumps by 8×. Whatever the diffusion model produces in that latent space, the decoder cannot render fine detail that the encoder threw away — which is exactly the "hard ceiling" the diffusion page warns about.
  • This is also the honest answer to "is Stable Diffusion's first stage a VAE?" It is an autoencoder with a very small KL regularisation term plus perceptual and adversarial reconstruction losses. Calling it a VAE is right about the architecture and misleading about the objective — the KL is there to keep the latent's variance bounded, not to make the model generative.

The same idea everywhere else

  • Audio and speech. Neural audio codecs are residual vector-quantised autoencoders; the tokens they emit are what audio and music language models actually model. Same two-stage split as §26.
  • Video. A spatio-temporal autoencoder compresses time as well as space, and a transformer diffuses over the resulting latents — otherwise the sequence length is hopeless.
  • Multimodal models. Image and audio tokenisers let a single sequence model consume and emit several modalities. The tokeniser is an autoencoder; the intelligence is the prior.
  • Interpretability. Sparse autoencoders (§08) trained on a language model's internal activations, used to pull out candidate features. A twenty-year-old objective pointed at a new kind of data.
  • The road not taken. JEPA-style models argue you should predict in representation space and drop the decoder entirely, precisely to avoid spending capacity on pixel detail. That is a direct rejection of the reconstruction objective — and worth reading against §24, because it targets the same problem from the opposite direction.

28 Practice — recipes, diagnostics, and what to remember

Everything above, compressed into things to do, things to measure, and things to stop believing.

Choosing the model

If you want…Use
A compact representation for downstream modelsAn undercomplete or sparse autoencoder — or, more often these days, a contrastive or masked-prediction objective, which spends less capacity on nuisance variance.
Denoising, inpainting, restorationA denoising autoencoder (§09). If quality matters more than latency, a diffusion model, which is the same idea across all noise levels.
A smooth, sampleable latent spaceA VAE. Report rate and distortion separately, and expect samples to be worse than reconstructions (§23).
Sharp samples above allNot a plain VAE. A GAN, or a diffusion model, or a VAE whose reconstruction loss is perceptual and adversarial (§27).
Discrete tokens for a sequence modelVQ-VAE or a residual-VQ codec (§26), plus a transformer prior over the indices.
A latent space for a generative model to live inAn autoencoder with a perceptual + adversarial reconstruction loss and mild KL or VQ regularisation (§27). This is the industrial default.
To find interpretable features in a network's activationsA wide, heavily L¹-penalised sparse autoencoder on the activations (§08).

The diagnostics that are worth logging every run

  • Rate and distortion separately, never just the ELBO. Two models with equal ELBOs can sit at opposite ends of §21's frontier.
  • Per-dimension KL, and the count above ~0.01 nats. This is the collapse detector, and the total hides it completely (§22).
  • Held-out reconstruction error, against the PCA floor ∑i>d λᵢ at the same code size. If a deep autoencoder does not beat the floor, it has not earned its parameters (§04).
  • The off-manifold probe. Feed inputs the model should not recognise and measure how far it moves them. Little movement means g∘f is near the identity and the model has learned nothing about the distribution (§06). Costs one forward pass.
  • The active fraction of the codebook, for VQ models. Dead entries are the standard failure and they are invisible in the loss.
  • Samples and reconstructions, side by side. A large gap between them is the prior hole of §23, and it is diagnostic rather than cosmetic.

The traps, in the order people fall into them

trap 1
An accidental β
Fixing the decoder variance, or averaging rather than summing over pixels, silently sets the KL weight — and the two together can be off by three orders of magnitude. State β explicitly, or learn σ (§20).
trap 2
Averaging the KL over dimensions
mean instead of sum across the latent axis divides the effective β by d. Sum over dimensions, mean over the batch. Every time.
trap 3
Bernoulli likelihood on non-binary data
"BCE" on targets in [0,1] is not a density, and the missing normaliser changes the objective. Use a continuous Bernoulli, a Gaussian, or a discretised logistic (§20).
trap 4
Reading the weights as components
A linear autoencoder's matrices are defined only up to an invertible mixing. Ordering them or interpreting one column as "the first factor" is reading an arbitrary change of basis (§04).
trap 5
Anomaly detection by reconstruction error
High-capacity autoencoders often reconstruct unseen inputs well, and the error is dominated by high-variance regions rather than by anomalousness. Run the §06 probe before trusting it.
trap 6
Comparing models by ELBO
An ELBO is a bound whose deficit depends on the posterior family. A model with a better encoder can win while having the worse decoder (§17).
trap 7
Believing a traversal
A tidy-looking traversal is a hypothesis. Unsupervised disentanglement is not identifiable without inductive bias, and rotations of the latent leave a factorised Gaussian prior invariant (§21).
trap 8
Judging a VAE from reconstructions
Reconstructions test the encoder–decoder pair. Only ancestral samples test whether the aggregate posterior matches the prior — and that is the part that usually fails (§23).

A starting recipe that usually works

  1. Standardise the data, and pick the decoder likelihood that matches it (§20). Learn a single global σ rather than guessing one.
  2. Start with a latent size you expect to be too large, and let the per-dimension KL tell you how many dimensions the data actually supports. That number is far more informative than a guess.
  3. Anneal the KL weight from 0 to its target over the first 10–30% of training, or use free bits at roughly 0.1–0.5 nats per dimension. Do one or the other from the start; retrofitting them after a collapse means retraining anyway.
  4. Log per-dimension KL, rate, distortion, and held-out reconstruction from step one. Add sample grids next to reconstruction grids.
  5. If samples are blurry and you care, change the reconstruction loss before you change anything else — perceptual, then adversarial (§24, §27). Do not reach for a bigger decoder.
  6. If you need real generative quality, stop asking the autoencoder for it: freeze it and fit a strong prior over its latents — autoregressive over discrete codes, or diffusion over continuous ones (§26, §27).

What to remember

  • An autoencoder is a learned identity with an obstacle, and the obstacle is the model. Shape is not a bottleneck; the learned function is.
  • A linear autoencoder with squared loss spans the principal subspace and hits the PCA error floor exactly — and recovers no basis at all within it. Measured: principal angles under 3 × 10⁻⁵ degrees, decoder columns at |cos| ≈ 0.5 to every principal axis.
  • Denoising and contraction are the same instruction at two scales, and the denoiser's displacement field is exactly σ²∇log pσ — verified here to 10⁻¹⁶. That identity is the bridge to diffusion.
  • The ELBO is a lower bound with an exactly identified deficit, DKL(q ‖ p(z|x)), that you never get to observe. Verified on a toy model: ELBO −7.919220 plus gap 4.060922 equals log p(x) = −3.858298, to 10⁻⁹.
  • Reparameterisation is not elegance, it is variance. Measured at a 128-dimensional latent: 4 556× more samples needed for the score-function estimator to match.
  • Posterior collapse is not an optimisation bug — the collapsed solution is often the global optimum. In the linear case a dimension dies exactly when λᵢ ≤ βσ², confirmed against a trained model to four decimals.
  • Blur is what a factorised squared-error likelihood asks for: the optimal output is a conditional mean. Change the likelihood and the blur goes.
  • And the ending: the autoencoder is now the coordinate system that diffusion models and multimodal transformers run inside. It stopped being the generative model and became the space.
In one sentence: force a network to rebuild its input through something it cannot fit the input into, and the shape of what survives is a model of the data — a subspace if the network is linear, a manifold if it is not, and a probability distribution if the code is one too.
