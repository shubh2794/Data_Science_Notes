Autoencoders & VAEs

An autoencoder is a network trained to copy its input to its output through a bottleneck it cannot fit the input into. That sounds like a trivial task with a pointless obstacle, and it would be, except that the obstacle is the entire point: forced to throw information away, the network must decide what to throw away, and that decision is a model of the data. The first half of this page is about the deterministic version of that idea and the four different ways of imposing the obstacle — a narrow code, a sparsity penalty, added noise, a penalty on the encoder's Jacobian — each of which buys something different. The second half replaces the deterministic code with a distribution, which turns the same architecture into a probabilistic generative model with a real objective: a lower bound on the log-likelihood of the data. Everything difficult about the variational autoencoder — the trick that makes its gradient usable, the collapse that makes its latent variables vanish, the blur in its samples — follows from that one substitution.

01 A learned identity with something in the way

Two networks, back to back, trained to undo each other. Nothing about that is interesting until you make it impossible.

input x ∈ ℝD→encoder f→code h ∈ ℝd→decoder g→reconstruction r ∈ ℝD→loss L(x, r)

The whole model in one line

  • An autoencoder is a pair of maps h = f(x) and r = g(h), trained by minimising a reconstruction loss L(x, g(f(x))). There are no labels: the target is the input. That makes it self-supervised in the most literal sense.
  • Nothing else in the definition is fixed. f and g can be a single matrix each or a forty-layer convolutional stack; L can be squared error, cross-entropy, or a learned perceptual distance; the code h can be a real vector, a sparse vector, an integer index, or a probability distribution. Every named autoencoder in this page is one choice of those four things.
  • The output is usually thrown away. What is kept is f — the encoder — because the code it produces is a representation, and the training signal that produced it needed no annotation at all.
the autoencoderh = f(x) encoder, f : ℝᴰ → ℝᵈ r = g(h) = g(f(x)) decoder, g : ℝᵈ → ℝᴰ and the objective, over the training setminimise J = (1/N) ∑i=1..N L( x⁽ⁱ⁾ , g(f(x⁽ⁱ⁾)) ) typically L(x, r) = ‖x − r‖²

Why the unconstrained version is worthless

  • If f and g are unconstrained and have enough capacity, the global optimum is g ∘ f = identity, achieving zero loss and learning nothing at all about the data. The model has memorised a routing scheme, not a structure.
  • The pathological case is worth holding in mind even though it does not happen in practice: with a one-dimensional code and a sufficiently powerful nonlinear encoder, a network could in principle encode training example x⁽ⁱ⁾ as the scalar i and have the decoder look up the table. Perfect reconstruction, zero understanding. Narrow does not mean informative.
  • So an autoencoder is only ever as good as the constraint you put on it. Every section from §03 to §11 is one such constraint, and the honest way to read them is as answers to the question "what am I forbidding, and what does forbidding it force the network to notice?"

03 Undercomplete autoencoders

Make the code narrower than the input and let the reconstruction loss decide what to keep. The simplest constraint there is, and the one everything else is measured against.

The definition and the accounting

  • An autoencoder is undercomplete when d < D and overcomplete when d ≥ D. Undercompleteness is a hard information constraint: h is a d-dimensional real vector, so at most a d-dimensional worth of variation can survive the round trip. Whatever else the network does, it cannot smuggle a D-dimensional input through a d-dimensional pipe without losing something.
  • Because the network is trained only on samples from the data distribution, the thing it chooses to lose is the variation that the data does not have. That is the entire trick, and it is why "compress and reconstruct" is a proxy for "find structure".
  • The loss is ordinary. For real-valued data, squared error; for data in [0,1], binary cross-entropy; both are negative log-likelihoods of a decoder output distribution, which §13 makes explicit.
undercomplete objective — this is the whole methodminf,g Ex~p̂ ‖ x − g(f(x)) ‖² subject to dim(h) = d < D

What the bottleneck actually costs, exactly

  • For a linear decoder and squared loss, the minimum achievable error is not a matter of opinion: it is the variance the data has outside its top-d principal subspace, which is the sum of the trailing eigenvalues of the covariance. No amount of training beats it, and any nonlinear encoder paired with a linear decoder cannot beat it either.
  • That number is the floor against which every fancier autoencoder should be reported. A deep autoencoder that does not beat the PCA floor at the same d has not earned its parameters.
  • A nonlinear decoder can go below the floor, because the set it projects onto is a curved d-dimensional surface rather than a flat d-dimensional subspace. §05 is about how much that is worth.
the linear floor — eigenvalues of the data covariance, descendingmin E‖x − g(f(x))‖² = ∑i=d+1D λᵢ when g is linear (or affine) and L is squared error
Do not confuse two claims. "The code has d dimensions" is a statement about a tensor's shape. "The code carries d dimensions' worth of information" is a statement about the function, and it is false in general — see the index-code argument in §01 and the capacity trap in §06. Shape is a necessary condition for a bottleneck, never a sufficient one.

04 The PCA connection — stated precisely, because the loose version is wrong

A linear autoencoder trained with squared error finds the principal subspace. It does not find the principal axes. That distinction is the single most-repeated error about autoencoders, and it is easy to settle by measurement.

The claim, in the only form that is true

  • Let the data be centred with covariance S, eigenvalues λ₁ ≥ … ≥ λ_D and eigenvectors v₁ … v_D. Take a linear autoencoder h = W₁x, r = W₂h with W₁ ∈ ℝ^{d×D}, W₂ ∈ ℝ^{D×d}, trained to minimise E‖x − W₂W₁x‖².
  • At any global minimum, the composition W₂W₁ equals the orthogonal projector onto the span of v₁ … v_d, and the minimum value is ∑i>d λᵢ. Both of those are statements about W₂W₁, not about W₁ or W₂ separately.
  • Two conditions are needed for even that much. The data must be centred (or the maps affine) — see below — and the spectrum must have a gap at the cut, λ_d > λ_{d+1}. If the eigenvalues are tied across the boundary then the minimising subspace is itself not unique, because any subspace spanning the tied eigenvectors achieves the same loss. The minimum value ∑i>d λᵢ is unaffected either way.
  • Nothing pins down the factorisation. For any invertible d×d matrix A, the pair (AW₁, W₂A⁻¹) gives the identical loss. So the individual code coordinates are defined only up to an arbitrary invertible mixing: not orthogonal, not unit-norm, not ordered by variance, not unique.
  • PCA additionally fixes the axes: it returns an orthonormal, variance-ordered basis of the same subspace. That extra structure comes from the eigendecomposition, and the reconstruction loss alone contains no information that could produce it — because it is invariant to exactly the transformations that would destroy it.
what is determined, and what is notdetermined: W₂W₁ = V_d V_dᵀ the orthogonal projector onto span(v₁ … v_d) determined: min loss = ∑i>d λᵢ the trailing eigenvalue mass NOT determined: W₁ and W₂ separately — (W₁, W₂) and (A W₁, W₂ A⁻¹) are the same model for every invertible A ∈ ℝ^{d×d}, a d² -parameter gauge freedom
Often said: "a linear autoencoder is PCA / learns the principal components." Accurate version: a linear autoencoder with squared loss spans the same subspace as PCA and reaches the same reconstruction error. Its weight matrices are not the principal components, and reading them as if they were — ordering them, interpreting one column as "the first factor" — is reading noise from an arbitrary change of basis.

Two conditions the loose statement usually forgets

  • Centring. PCA diagonalises the covariance; a bias-free linear autoencoder minimises error against the raw second moment. On the same data shifted off the origin, a bias-free autoencoder reached 3.69117 — exactly the trailing second-moment eigenvalues, and a different subspace — while the centred PCA floor was 2.21454. Restore the biases and it recovers 2.21454 exactly. Affine, or centred: pick one.
  • Squared error specifically. The equivalence is a property of the L² geometry. Swap in cross-entropy, an L¹ loss or a perceptual loss and the optimum is no longer the principal subspace, because you have changed what "close" means.

05 The nonlinear generalisation: projecting onto a curved surface

Replace the linear maps with networks and the flat d-dimensional subspace becomes a curved d-dimensional surface. That is the whole conceptual upgrade, and it is worth a lot when the data is curved and nothing at all when it is not.

What changes and what does not

  • PCA projects onto the best-fitting affine subspace. A nonlinear autoencoder projects onto the best-fitting image of the decoder, M = { g(h) : h ∈ ℝᵈ } — a d-dimensional parametric surface embedded in ℝᴰ, which can bend.
  • The encoder is the map that assigns a coordinate on that surface, and the reconstruction is the surface point at that coordinate. So the pair (f, g) is a chart and its inverse for a learned surface: g is the parameterisation, f is the projection onto it.
  • What does not change: the projection is still lossy, still trained by squared error, and still only obliged to be accurate where the data is. Off the data, both PCA and the autoencoder are extrapolating — but the autoencoder extrapolates in whatever arbitrary way its nonlinearity happens to bend, which is far less predictable.

The numbers the figure in §04 produced

  • On the default curved dataset (curvature 0.90, noise 0.07), the exact d = 1 PCA floor is λ₂ = 0.019541. The linear autoencoder converged to 0.019541 — the floor, to six figures, which is the §04 claim made visible. The nonlinear autoencoder reached 0.004608, about 76% below it.
  • Turn the curvature slider to 0 — genuinely linear data — and the same nonlinear network reaches 0.004403 against a floor of 0.004426: 0.5% better, which is nothing. The nonlinearity is not free capability, it is capability that only pays when the data is curved.
  • Push the noise slider up instead and the advantage narrows the other way (at noise 0.30 the nonlinear model was 30% below the floor rather than 76%): once the off-manifold noise is comparable with the curvature, there is less curve left to follow.
The honest summary of "autoencoders are nonlinear PCA": true as an analogy about what is being projected onto, false as a statement about the objective's solution set. PCA's answer is unique up to sign and rotation within eigenvalue ties; a nonlinear autoencoder's is not unique in any useful sense, has no ordering, no orthogonality and no closed form, and depends on initialisation. You gain the curve and you lose every guarantee.

06 The capacity trap — how a bottleneck stops being a bottleneck

Give the encoder and decoder enough capacity and they will find a way to be the identity, whatever the code's shape. This is the failure mode that every regulariser in §08–§11 exists to prevent.

Three ways to lose the constraint

  • Overcomplete code (d ≥ D). Now the identity is available even with linear layers: set W₁ to any injective map and W₂ to its left inverse. Zero loss, zero learning. Nothing in the objective prefers a useful solution over this one.
  • Too much capacity around a narrow code. Even with d = 1, a sufficiently expressive encoder can build a space-filling map that packs the neighbourhood of the training set into one scalar, with the decoder undoing it. The pathological limit is the index code of §01. In practice you see a milder version: reconstruction improves while the code becomes uninterpretable and useless downstream.
  • Memorisation. With enough parameters relative to data, a network can fit the training set exactly and reconstruct nothing else. Reconstruction error on held-out data is the diagnostic, and it is skipped depressingly often.

The test that actually detects it

  • A useful autoencoder is one whose reconstruction map is close to the identity on the data and far from it off the data. So probe it off the data: take points that are not plausible samples and see whether they come back unchanged.
  • If g(f(x̃)) ≈ x̃ for an off-manifold x̃, the model has learned the identity in that region and knows nothing about the data distribution. If instead g(f(x̃)) is pulled back onto the data, the model has learned where the data lives — which is what you wanted.
  • This is exactly the quantity §09 turns into a score estimate and §12 turns into a statement about manifolds. It is the single most informative thing you can measure about a trained autoencoder, and it costs one forward pass.

07 Representational power, layer size and depth

A one-hidden-layer encoder can approximate any code map, given enough units. A deeper one can approximate the useful ones with exponentially fewer. That gap is the whole argument for deep autoencoders.

Why a shallow autoencoder is not enough, even though it is universal

  • The universal approximation theorem says a network with one hidden layer and enough units can approximate any reasonable function — including the identity along the data's domain. So a shallow autoencoder can certainly represent a good reconstruction.
  • But universality is about the composition g ∘ f, and what you want is a good f. With a single hidden layer split between encoder and decoder, the map from input to code is shallow, and you cannot then impose arbitrary structure on the code — sparsity, near-independence, a particular geometry — because the encoder is not expressive enough to satisfy the structure and stay informative at once.
  • Give the encoder at least one hidden layer of its own and it can approximate any input-to-code map arbitrarily well. That is the minimum architecture at which the phrase "learn a representation with property P" is even coherent.

What depth buys, stated at the right strength

  • Exponential savings in units, for some functions. There are function families for which a depth-k network needs exponentially fewer units than a depth-2 one. This is a statement about some functions, not all of them, and it is the honest form of "depth helps".
  • Exponential savings in data, for some functions. Similarly, depth can reduce the number of examples needed to learn certain structured maps, because it reuses sub-computations rather than re-learning them per region.
  • Experimentally. Deep autoencoders compress much better than shallow or linear ones at the same code size — the classic result behind the 30-unit bottleneck that beat 30-component PCA on both reconstruction and downstream separability.
  • Historically: deep autoencoders were often built by greedily pretraining a stack of shallow ones, each trained to reconstruct the previous one's hidden layer, then fine-tuning the whole stack. Modern initialisation and normalisation made that unnecessary — see Initialization — but it is why shallow autoencoders appear so often in older work even when a deep one was the goal.

Where the extra power comes from: folding

  • With piecewise-linear activations the encoder is a piecewise-linear map, and the input space is cut into linear regions on each of which the encoder is affine. Region count is a concrete, countable proxy for expressive power.
  • A single hidden layer of width n on a D-dimensional input cuts the space with n hyperplanes, giving O(n^D) regions — the count grows polynomially in width.
  • A second layer does not add cuts, it folds: it re-cuts every region the first layer produced. Region counts then compound across layers, which is where the exponential-in-depth statements come from.

08 Sparse autoencoders — a wide code that is mostly zero

Stop constraining the code's width and start constraining its occupancy. The code can then be larger than the input and still carry a bottleneck, because only a handful of its units are allowed to speak at once.

The objective

  • Add a penalty Ω(h) on the code to the reconstruction loss. The standard choice is L¹, which is the only common norm that produces exact zeros rather than merely small values.
  • Use a rectified linear code layer, not a sigmoid or tanh one, if you want actual zeros: ReLU combined with an L¹ pull puts units exactly at zero and keeps them there, which is what makes the code cheap to store and easy to read.
  • The autoencoder must now respond to statistical features of this dataset, because a generic identity map would activate everything and pay the full penalty.
sparse autoencoderJ = L( x , g(f(x)) ) + Ω(h) with h = f(x) Ω(h) = λ ‖h‖₁ = λ ∑ᵢ |hᵢ| L¹ — produces exact zeros Ω(h) = λ ∑ᵢ KL( ρ ‖ ρ̂ᵢ ) the "target average activation" form, ρ ≈ 0.05 with ρ̂ᵢ = mean activation of unit i over the batch

The latent-variable reading, which is the one worth carrying

  • A sparsity penalty looks like a regulariser but is better understood as a prior. Suppose a generative model p(x, h) = p(h) p(x | h). Approximating the intractable marginal log p(x) = log ∑h p(h, x) by a point estimate at a single likely h — the encoder's output — leaves you maximising log p(h) + log p(x | h).
  • Choose a Laplace prior on each code unit and −log p(h) is an absolute-value penalty, up to a constant that does not depend on h. So λ‖h‖₁ is not an arbitrary regulariser at all: it is the negative log-prior of a specific latent-variable model. A Student-t prior gives a different, also sparsity-inducing, penalty.
  • This reframes the objective: a sparse autoencoder is an approximate maximum-likelihood fit of a generative model with a sparse prior, and the features it learns are useful because they describe the latent variables that explain the input — not because a penalty made them tidy.
  • The reframing also explains why the usual Bayesian story does not apply. Weight decay corresponds to a prior over parameters, so it is a MAP approximation. A sparsity penalty depends on the data through h = f(x), so it is not a prior over parameters in the formal sense at all. Calling it "just a regulariser" hides the difference.
Laplace prior ⟺ L¹ penalty, exactlypmodel(hᵢ) = (λ/2) e^(−λ|hᵢ|) −log pmodel(h) = λ ∑ᵢ |hᵢ| − log(λ/2) · d = Ω(h) + const
An overcomplete code, penalised — sweep λ and watch occupancy fall while error rises code width 24 against an input width of 12: with λ = 0 the identity is available and the code is useless
Practical notes. The L¹ weight and the decoder's scale fight each other — the network can shrink h and inflate the decoder to dodge the penalty, so normalise the decoder columns (or tie the weights) or the sparsity is cosmetic. And measure occupancy directly: report the mean number of non-zero code units per example, not the value of the penalty term, which conflates sparsity with scale.

Sparse autoencoders have had a second life as an interpretability tool: train a wide, heavily sparse autoencoder on the internal activations of a large model and read the learned dictionary elements as candidate features. The mechanism is exactly the one above — an overcomplete code held down by an L¹ penalty — applied to activations instead of data.

09 Denoising autoencoders — break the input, keep the target

Do not penalise the model; give it a task it cannot solve by copying. Corrupt the input, ask for the clean original. The identity is now the wrong answer, so capacity stops being dangerous.

The recipe

  1. Sample a training example x from the data.
  2. Sample a corrupted version x̃ from a corruption process C(x̃ | x) — additive Gaussian noise, masking a random subset of coordinates to zero, salt-and-pepper, dropout on the input.
  3. Train on the pair: encode x̃, decode, and compare against the clean x.

  • Nothing else changes. With a deterministic encoder the denoising autoencoder is an ordinary feedforward network with a stochastic data pipeline, trained with ordinary minibatch gradient descent.
  • The corruption is a training-time device. At deployment you feed clean inputs; the noise was only ever there to shape the function.

What it actually learns

  • Under squared error, the optimal reconstruction of a corrupted point is the conditional mean of the clean points that could have produced it: r(x̃) = E[ x | x̃ ]. That is a fact about squared loss, not about neural networks, and it is the key to everything in §10.
  • Because x̃ is a noisy version of a point on the data manifold, that conditional mean sits back on the manifold — it is the centre of mass of the clean points consistent with what was observed. So r(x̃) − x̃ is a vector pointing from wherever you are toward where the data is.
  • Collect those vectors over the whole input space and you have a field. The field is zero on the data manifold (nothing to correct) and grows as you move away from it. Training a denoising autoencoder is training that field.
  • The noise level is a scale knob, not a nuisance. Small noise probes the manifold's immediate neighbourhood and learns fine local structure; large noise probes far away and learns coarse global structure. This is precisely the reason diffusion models sweep a whole schedule of noise levels instead of picking one.

10 The vector field is the score — the bridge to diffusion

The arrows in §09 are not merely suggestive of a gradient. Under Gaussian corruption they are a gradient — of the log-density of the noised data — with an exactly known constant of proportionality.

The identity

  • Let pdata be the data distribution and let the corruption be x̃ = x + σε with ε ~ 𝒩(0, I). Write pσ for the distribution of x̃, which is pdata convolved with a Gaussian of width σ.
  • Then the optimal squared-error denoiser and the score of pσ are the same object, up to the factor σ². This is Tweedie's formula, and it is an exact identity — no approximation, no asymptotics, no assumptions about the network.
  • Consequently a trained denoising autoencoder is an estimator of ∇ log pσ, and the reconstruction-minus-input vector is the estimate. That is the entire content of "denoising autoencoders learn the score".
Tweedie's formula — the whole bridge, in one linex̃ = x + σε, ε ~ 𝒩(0, I) ⟹ E[ x | x̃ ] = x̃ + σ² ∇x̃ log pσ(x̃) so, rearranged, the autoencoder's displacement fieldr(x̃) − x̃ = σ² ∇x̃ log pσ(x̃) ← the score, scaled by the noise variance

The §09 figure computes both sides of that identity independently — the left from a weighted average of clean points, the right from the analytic gradient of the Gaussian mixture — and they agree to machine precision. Across six probe points spread over the plane the largest disagreement in any coordinate was 9.4 × 10⁻¹⁶, and the analytic gradient matched a central finite difference of log pσ to six decimals. It is an identity, and it behaves like one.

What the identity is and is not

  • It is exact for the noised density pσ, not for pdata. At a fixed noise level you learn the score of a blurred version of the data. Regularised score matching at a fixed σ is therefore not a consistent estimator of pdata; you recover the blur along with the signal. Let σ → 0 as the sample size grows and consistency is restored.
  • It needs squared error and Gaussian corruption. Masking noise, cross-entropy losses and discrete data all break the clean identity, though the qualitative "points back at the data" behaviour survives.
  • It does not say the field is a gradient in general. For an arbitrary trained network there is no guarantee that g(f(x)) − x is the gradient of any function at all — only at the optimum, and only under the conditions above, does it coincide with one. Particular shallow parameterisations can be shown to give a genuine conservative field; general ones cannot.

11 Contractive autoencoders — penalise the derivative directly

Denoising asks the model to resist perturbations of finite size, empirically. A contractive autoencoder asks it to resist infinitesimal ones, analytically, by penalising the encoder's Jacobian.

The penalty

  • Add the squared Frobenius norm of the encoder Jacobian J = ∂f(x)/∂x, evaluated at the training points. Because it is imposed only at the data, it forces the code to be flat everywhere except in the directions the data actually explores.
  • The name is literal: a linear operator is contractive when it maps the unit sphere inside itself, i.e. all its singular values are at most 1. Treating J as the local linear approximation of f, the penalty pushes each of those local operators toward being a contraction.
  • The compromise with the reconstruction term is the point. Reconstruction alone would give the identity; the penalty alone would give a constant. Together, most singular values of J fall below 1 and a handful do not — and the ones that do not span the directions the data varies in.

Three things about the CAE that are easy to get wrong

  • It is only locally contractive. Every perturbation of a training point x maps near f(x), but two distant points can easily be mapped further apart than they started — and typically are, in the region between manifolds where the reconstruction function must have a large derivative to push points back.
  • Without a scale constraint the penalty is free to cheat. Let the encoder multiply by a tiny constant ε and the decoder divide by it: Ω goes to zero while reconstruction stays perfect and nothing has been learned. The standard fix is to tie the weights, Wg = Wfᵀ, which pins the scales together.
  • Depth makes it expensive. The Jacobian of a deep encoder is a product of layer Jacobians and the penalty gets costly, so the classic recipe trains a stack of single-layer CAEs, each reconstructing the previous layer's code. The composition is contractive, but it is not the same object as jointly penalising the deep model's Jacobian — an approximation worth naming rather than glossing.

12 Learning manifolds — the conceptual heart of the whole family

Every regulariser in §08–§11 is a different way of asking the same question, and the answer is always a tangent space. This section is the one to remember when the others have faded.

The manifold hypothesis, in the form autoencoders use it

  • Real data concentrates near a low-dimensional manifold — or a small collection of them — embedded in a much higher-dimensional ambient space. Almost all of ℝ784 is noise, not handwriting.
  • A d-dimensional manifold has, at each point, a d-dimensional tangent plane: the space of directions you can move infinitesimally and stay on it. Characterising the manifold is largely the same job as characterising its tangent planes everywhere.
  • Many algorithms merely behave sensibly on the manifold. Autoencoders go further: they aim to learn its structure, which means learning a coordinate system on it. That is exactly what the code h = f(x) is.
The one-sentence version. The two forces of §01 — reconstruct, and be insensitive — combine into a single instruction: be sensitive only along the manifold and insensitive across it. A code that obeys that instruction is a local coordinate system for the manifold, and every regulariser on this page is a different way of enforcing it.

The picture in one dimension, which is worth more than the words

  • Plot the reconstruction function r(x) against the identity line. Wherever there is data, the two must cross — reconstruction is accurate there. Between the data, r is free.
  • There are more crossings than data points. With N isolated points the optimal denoiser crosses the identity 2N − 1 times: N stable crossings, one at each datum, with arrows pointing inward, and N − 1 unstable ones between neighbouring points, with arrows pointing apart. The unstable crossings sit at the local minima of the smoothed density — the same fact that made the ring's centre a zero of the field in §09.
  • Because the model is asked to be flat near the data, each crossing is a stable point with a shallow slope, and the arrows r(x) − x on either side point inward. Between data points the function must swing steeply back to catch up with the identity — so r′ is small on the data and large off it, which is the derivative statement of the same fact.
  • With zero-dimensional "manifolds" — isolated data points — the crossings are the data. With a one-dimensional manifold, the crossings become a curve. Nothing else changes.
Reconstruction against identity, in one dimension — the crossings are the data exact optimal denoiser again; the arrows are r(x) − x — they point inward at every data point and apart at the midpoints between them

Why a parametric encoder beats a nearest-neighbour graph

  • Classical manifold learning is largely non-parametric: build a nearest-neighbour graph over the training points, read a tangent plane off each neighbourhood, then stitch the local charts into a global coordinate system by solving an optimisation or a linear system. It works well when the samples cover the manifold densely.
  • The difficulty is coverage. If the manifold twists, a purely local method needs enough examples in every twist, because it can only generalise by interpolating between neighbours. It cannot extrapolate a pattern it has seen elsewhere.
  • And AI-scale manifolds twist violently. Translate an image by one pixel: a single coordinate xᵢ rises and falls once for every bright-dark alternation in the underlying image. The complexity of the image content becomes the complexity of the manifold generated by a transformation as simple as a shift.
  • A parametric encoder shares parameters across the whole space, so a tangent direction learned in one region constrains its estimate in another. That is the argument for distributed representations and depth here — not elegance, sample efficiency on manifolds you could never cover.
Connections out. The tangent-space view is why a contractive encoder's leading singular vectors look like meaningful transformations of the input — a head turning, a limb moving — rather than noise. The same manifold framing, with a different loss, drives contrastive learning (which never reconstructs and instead asks only that augmented views land nearby) and JEPA-style predictive embedding (which predicts in representation space and skips the decoder entirely).

13 Stochastic encoders and decoders — the hinge into the second half

The decoder was always a probability distribution in disguise. Making that explicit costs nothing, explains where the loss functions came from, and is the exact step that leads to the variational autoencoder.

The decoder as a distribution

  • The standard way to design any network's output layer is to declare an output distribution p(y | x) and minimise −log p(y | x). An autoencoder is the same construction with y = x: declare pdecoder(x | h) and minimise its negative log-likelihood.
  • Every loss on this page is that construction with a different distribution. Squared error is a Gaussian with fixed variance; binary cross-entropy is a Bernoulli through a sigmoid; a softmax output is a categorical. Nothing new is being introduced — the losses are being named.
  • The output coordinates are almost always taken to be conditionally independent given h, which is what makes the likelihood a cheap sum over pixels. That assumption is also, as §24 will show, the direct cause of blurry samples.
the loss is a negative log-likelihood — and always waspdecoder(x | h) = 𝒩( x ; g(h), σ²I ) ⟹ −log p = ‖x − g(h)‖² / (2σ²) + const ← squared error pdecoder(x | h) = ∏ⱼ Bern( xⱼ ; g(h)ⱼ ) ⟹ −log p = −∑ⱼ [ xⱼ log gⱼ + (1−xⱼ) log(1−gⱼ) ] ← cross-entropy

The encoder as a distribution

  • The more radical move is to make the encoder stochastic too: replace the function h = f(x) with a distribution pencoder(h | x). Sampling replaces evaluation, and the code becomes a cloud rather than a point.
  • Any latent-variable model pmodel(h, x) supplies both halves for free: the stochastic encoder is the posterior pmodel(h | x) and the stochastic decoder is the conditional pmodel(x | h). Read backwards, an autoencoder with stochastic parts is trying to be a latent-variable model.
  • They need not be consistent. Two arbitrarily chosen conditionals pencoder and pdecoder generally correspond to no joint distribution at all. Training denoising-style makes them asymptotically compatible given enough capacity and data; the variational autoencoder instead constructs a joint and derives a bound, which is why it comes with a likelihood guarantee and the deterministic models do not.
deterministic and stochastic, side by sidedeterministic: h = f(x) r = g(h) stochastic: h ~ pencoder(h | x) x ~ pdecoder(x | h) from a latent-variable model: pencoder(h | x) = pmodel(h | x) pdecoder(x | h) = pmodel(x | h)
This is the hinge. §16 onwards takes exactly this step and then asks the obvious follow-up: if the encoder is supposed to be the posterior pmodel(h | x), and that posterior is intractable, what happens if we train a network to approximate it and optimise a bound instead? The answer is the variational autoencoder.

14 Predictive sparse decomposition — learning to shortcut inference

A halfway house between sparse coding, where the code is solved for, and an autoencoder, where it is predicted. It is also the cleanest early example of the idea that dominates the second half of this page: train a network to imitate an expensive inference procedure.

  • Sparse coding infers a code by running an optimisation for every example: minimise ‖x − g(h)‖² + λ‖h‖₁ over h. Excellent codes, unusable latency.
  • PSD keeps that optimisation but adds a parametric encoder f(x) and a third term tying the two together. Training alternates between minimising over h and minimising over the parameters.
  • The optimisation over h becomes cheap because f(x) supplies a good starting point and the coupling term keeps h near it — around ten gradient steps is enough.
  • Note the subtlety: this is not "fit sparse coding, then fit a regressor to its outputs". The coupling term is present while the decoder is learned, so the decoder is pushed toward parameters for which a feed-forward encoder can predict good codes. The inference network shapes the generative model.
  • At deployment the iteration is dropped entirely and f alone computes the features. This is learned approximate inference, and it is the same trick the VAE uses: replace an intractable or expensive per-example inference with one forward pass of a trained network.
predictive sparse decompositionminimise ‖ x − g(h) ‖² + λ‖h‖₁ + γ ‖ h − f(x) ‖² term 1 reconstruct x from the code term 2 keep the code sparse term 3 and keep the code predictable by the encoder f train: alternate min over h / min over the parameters of f and g deploy: h = f(x), one forward pass, no optimisation
Why it is worth a section. PSD can be read as maximising a lower bound on the log-likelihood of a directed sparse-coding model — the same shape of argument as the ELBO in §17. The lineage runs directly from here to the variational autoencoder's inference network, and to every modern "amortised inference" method.

15 What deterministic autoencoders are actually used for

Before the probabilistic half, a stocktake: the plain autoencoder earns its keep in four places, and is a poor choice in several others that it is nonetheless routinely used for.

Where they work

use 1
Dimensionality reduction
The original application. A deep autoencoder with a 30-unit bottleneck beats 30-component PCA on reconstruction and produces a code whose classes fall into well-separated clusters. Compare against the PCA floor of §04 or the comparison is meaningless.
use 2
Information retrieval & semantic hashing
Reduce to a low-dimensional binary code and a database becomes a hash table: retrieve exact matches in O(1), near matches by flipping bits. The trick that produces genuinely binary codes is to inject noise before a sigmoid and grow it over training, forcing the units to saturate to 0 or 1 to survive.
use 3
Denoising and restoration
The one case where you actually want the decoder's output. §09's model, used for its intended purpose.
use 4
A learned compression front end
Encode once, do all subsequent work in the small space. §27 is the industrial-scale version: latent diffusion runs its entire generative process inside an autoencoder's latent space.

Where they disappoint

  • Anomaly detection by reconstruction error. The plausible story — "anomalies reconstruct badly" — fails often in practice, because a high-capacity autoencoder frequently reconstructs unseen inputs well (§06 is the reason), and because reconstruction error is dominated by high-variance regions rather than by anomalousness. It is a reasonable baseline and a bad final answer; always check what §06's probe test says about your model first.
  • General-purpose representations for classification. Reconstruction spends capacity on whatever carries the most variance, which is often exactly what you do not care about — lighting, background, texture. Contrastive and masked-prediction objectives generally produce stronger linear-probe features because they can be told what to ignore.
  • Generation. A deterministic autoencoder has no prior over its code, so there is nothing principled to sample. Feed it a random vector and you get an arbitrary point in a space whose occupied region you never characterised. This is precisely the gap the VAE fills.

16 The latent-variable model, and the two integrals that are impossible

Declare that the data was generated: draw a code from a simple prior, push it through a network, add observation noise. Everything difficult about the VAE follows from the fact that this model is easy to sample from and impossible to evaluate.

The generative story

  • Sample z ~ p(z), almost always 𝒩(0, I). Push it through a differentiable generator network gθ. Emit x from a simple distribution whose parameters that network produced: pθ(x | z) = 𝒩(x ; gθ(z), σ²I) for real data, or a product of Bernoullis for binary data.
  • The prior is deliberately trivial. All the structure comes from gθ, which acts as a nonlinear change of variables: it takes a boring isotropic Gaussian in ℝᵈ and drapes it over a complicated d-dimensional surface in ℝᴰ.
  • You have seen the trivial case already. To sample 𝒩(μ, Σ) you draw z ~ 𝒩(0, I) and compute x = μ + Lz with L the Cholesky factor. That is a one-layer generator network. Everything here is that idea with the affine map replaced by a deep one.
  • Two ways to use the generator, with different powers: have it emit a sample directly (continuous data only, but no need to write down a tractable output density), or have it emit the parameters of a conditional distribution (works for discrete data, but you have to pick a family a human can write down). VAEs take the second route; GANs take the first.

Why both of those lines are hopeless

  • The marginal is an integral over the whole latent space of a term involving a deep network. There is no closed form for anything but a linear g, and numerical quadrature dies in d dimensions. Monte-Carlo with samples from the prior is unbiased but catastrophically high-variance: nearly every z drawn from p(z) produces an x nothing like the one you are evaluating, so the estimate is dominated by a vanishing fraction of samples.
  • The posterior is worse, because it contains the marginal in its denominator. And even its shape is bad.   • Compare with the invertible route: if g were invertible with a cheap Jacobian determinant you could change variables and get p(x) exactly. That is a normalizing flow, and the price is an architecture built entirely out of invertible layers. VAEs decline to pay it and approximate instead.

The plan, stated before it is executed. Train a second network — an inference network or encoder — to output the parameters of a distribution qφ(z | x) that approximates the true posterior. Then optimise a quantity that (a) can be computed from q, p(z) and pθ(x|z) alone, and (b) is provably a lower bound on log pθ(x). Push the bound up and you push the log-likelihood up too. That quantity is the ELBO, and §17 is nothing but its two derivations and one measurement.

17 The evidence lower bound — two decompositions and one gap

One quantity, three equivalent ways to write it, and an exactly identified gap between it and the thing you actually wanted. Knowing all three forms is the difference between using the ELBO and understanding it.

The bound

  • Pick any distribution q(z | x) over the latent. The log marginal likelihood splits exactly into two pieces: the ELBO, and the KL divergence from q to the true posterior.
  • KL is non-negative — that is Jensen's inequality, and this page does not re-derive it. So the ELBO is a lower bound on log pθ(x), with equality exactly when q(z|x) = pθ(z|x).
  • The identity is the load-bearing fact. Maximising the ELBO over θ pushes the likelihood up; maximising it over φ — the encoder's parameters — squeezes the gap shut. One objective, two jobs.
the exact decomposition — everything else on this page follows from this linelog pθ(x) = 𝓛(θ, φ; x) + DKL( qφ(z|x) ‖ pθ(z|x) ) the first term is the ELBO — computable from q, p(z) and p(x|z) alone, and what you optimise the second term is the gap — non-negative, real, and never observed

form A — joint plus entropy. this is the one that shows why q spreads out𝓛 = Ez~q[ log pθ(z, x) ] + H( qφ(z|x) ) form B — reconstruction minus KL. this is the one you implement𝓛 = Ez~q[ log pθ(x | z) ] − DKL( qφ(z|x) ‖ p(z) ) first term reconstruction — how well the decoder rebuilds x from a sampled code second term regulariser — how far the encoder's distribution strays from the prior
  • Form A is the classical variational form. The first term is the joint log-likelihood under the approximate posterior — exactly the EM objective, with an approximate posterior in place of the exact one. The second is the entropy of q, and it explains the VAE's most distinctive behaviour: maximising entropy pushes the encoder's predicted noise up, so q covers many codes that could have produced x rather than collapsing to a single best guess. A deterministic autoencoder has no such term and does collapse to a point.
  • Form B is what you write in code. It reads as a regularised autoencoder — reconstruct the input, and keep the code's distribution near the prior — which is why the VAE looks like an autoencoder at all. The resemblance is a consequence of the algebra, not the design.
  • Both forms are the same number. The second follows from the first by expanding log p(z,x) = log p(x|z) + log p(z) and folding Eq[log p(z)] + H(q) into −DKL(q ‖ p(z)).

18 The reparameterisation trick — and the estimator it replaces

The ELBO is an expectation over a distribution whose parameters you are differentiating. There are two ways to get a gradient through that, one of them usable. The difference between them is not a matter of taste; it is measurable, and this section measures it.

The problem

  • The reconstruction term is Ez~qφ(z|x)[ log pθ(x|z) ]. Estimating it is easy — draw a z, evaluate. Differentiating it with respect to φ is not, because φ controls which z you draw, and a sampling operation has no derivative.
  • Backpropagation needs a deterministic computational graph. A node that "returns a different number every time you ask" is not one.

Fix 1: reparameterise — move the randomness out of the path

  • Write the sample as a deterministic function of the parameters and an independent noise draw. For a diagonal Gaussian, z = μ + σ ⊙ ε with ε ~ 𝒩(0, I). Now z is an ordinary differentiable node with two parameter inputs and one constant random input.
  • The crucial condition, and it is easy to violate: ε's distribution must not depend on φ, and φ must not depend on ε. Given that, backpropagation runs straight through the sampler as if it were an add and a multiply.
  • What the resulting gradient means: how would the output change if I nudged μ or σ and re-ran the sampler with the same ε? The noise is held fixed across the perturbation, which is exactly why the estimator has low variance — it is a pathwise derivative, not a difference of two independent random draws.
  • The generalisation: any z ~ p(z | ω) that can be written z = f(ε; ω) with f continuous and differentiable almost everywhere can be reparameterised. This requires z to be continuous, which is the whole reason §26's discrete latents need something else.
the trickbefore: z ~ 𝒩( μφ(x) , diag σφ(x)² ) ✗ no gradient path through the sample after: ε ~ 𝒩(0, I) ✓ randomness is now an INPUT z = μφ(x) + σφ(x) ⊙ ε ✓ a differentiable node ∇φ Eq[ h(z) ] = Eε[ ∇φ h( μφ + σφ ⊙ ε ) ] the PATHWISE estimator

Fix 2: the score-function estimator, which is unbiased and unusable

  • There is a second route that needs no reparameterisation at all, derived by differentiating the expectation directly and applying the identity ∂p/∂ω = p · ∂ log p/∂ω. It is known as REINFORCE, the score-function estimator, or the likelihood-ratio estimator.
  • It is fully general — it works for discrete z, for non-differentiable h, for anything you can sample and evaluate — and it is exactly unbiased.
  • And its variance is enormous, because it never looks inside h. It only correlates the scalar value h(z) with the direction ∇ log q(z), so it is effectively estimating a gradient from a random search. The pathwise estimator, by contrast, differentiates through h and gets the direction for free.
  • You can subtract any baseline b that does not depend on z without changing the expectation, since Eq[∇ log q(z)] = 0. That reduces variance substantially and still does not close the gap.

19 The variational autoencoder, end to end

Everything assembled: two networks, one sampling step, one closed-form KL, and a training loop that fits on a napkin.

The forward pass

  1. Encode. The encoder network reads x and emits two vectors: a mean μφ(x) and a log-variance log σφ²(x), both of length d. Predicting the log variance is not cosmetic — it keeps the variance positive without a constraint and keeps its gradient well-scaled.
  2. Sample. Draw ε ~ 𝒩(0, I) and set z = μ + σ ⊙ ε. One sample per data point per step is standard, and §18 is the reason that is enough.
  3. Decode. The decoder network reads z and emits the parameters of pθ(x | z) — a mean for a Gaussian, logits for Bernoullis, whatever §20 says the data calls for.
  4. Score. Add the reconstruction log-likelihood and the negative KL. Both terms are computed in closed form except the reconstruction expectation, which is the one Monte-Carlo sample.

Reading the KL term

  • Each dimension contributes independently, and each contribution is zero exactly when μⱼ = 0 and σⱼ = 1 — that is, when the encoder has said nothing about x in that dimension. This is the mechanism of posterior collapse in §22, visible in the formula.
  • The μⱼ² term keeps codes near the origin, so the aggregate of all codes resembles the prior and sampling from 𝒩(0, I) lands somewhere the decoder has seen. The σⱼ² − 1 − log σⱼ² term is a well with its minimum at σⱼ = 1, penalising both over-confidence and under-confidence.
  • Because the penalty is per-dimension and the reconstruction reward is shared, dimensions compete: a dimension is kept only if it earns more reconstruction than it costs in KL. §22 turns that sentence into an exact threshold.

The training step, in the order you would write it

  • Sum over dimensions, mean over the batch. Averaging the KL over latent dimensions instead of summing silently rescales β by 1/d and is one of the most common quiet bugs in VAE code.
  • To generate, discard the encoder: draw z ~ 𝒩(0, I), decode, and either take the mean or sample from pθ(x|z). Taking the mean gives a cleaner picture; sampling gives an honest one.
  • To encode, discard the sampling: use μφ(x) as the representation. The variance head is a training device, and at inference the mean is what downstream code wants.

The scale trap, stated as arithmetic

  • Fixing the decoder variance to σ² makes the reconstruction term ‖x − g(z)‖²/(2σ²). Relative to the KL, that is identical to a β-VAE with β = 2σ² and a plain squared-error reconstruction. There is no such thing as "no β" — there is only a β you chose implicitly.
  • So the widespread habit of writing MSE + KL is a specific and rarely-examined choice: σ² = 0.5. On data scaled to [0,1] that is an enormous observation noise, the KL dominates, and the model collapses. On data with unit variance per dimension it is merely arbitrary.
  • Worse, summing versus averaging over pixels rescales the same knob by the number of pixels. A "mean squared error" reconstruction on a 784-pixel image is 784× weaker relative to the KL than a summed one. Two codebases that look identical can sit at β values three orders of magnitude apart.

21 The reconstruction–KL trade-off, and what β actually buys

The ELBO's two terms pull in opposite directions, and the quantity they trade is information. Read the KL as a rate in nats and the whole thing becomes a rate–distortion problem, which is the framing that makes β stop looking arbitrary.

Rate and distortion

  • Rate R = Ex[ DKL( q(z|x) ‖ p(z) ) ], in nats: how many nats the encoder spends describing x beyond what the prior already said. It is an upper bound on the mutual information between x and z under the encoder.
  • Distortion D = −ExEq[ log pθ(x|z) ]: how badly the decoder reconstructs given that description. For a fixed-variance Gaussian decoder this is just the mean squared error, rescaled.
  • The ELBO is −(D + R). A β-VAE optimises −(D + βR), which traces out different points on the same rate–distortion frontier. Two models with the same ELBO can sit at wildly different (R, D) — one that describes nothing and reconstructs badly, one that describes a lot and reconstructs well.
  • This is why "the ELBO went down" is a weak sentence. Report R and D separately, always.
rate–distortion form of the objective−𝓛 = D + R R = Ex DKL( q(z|x) ‖ p(z) ) D = − Ex Eq log pθ(x|z) β-VAE: minimise D + βR β < 1 → high rate, low distortion (autoencoder-like) β = 1 → the plain ELBO β > 1 → low rate, high distortion (prior-like, disentanglement-seeking)

β > 1 and disentanglement

  • The β-VAE was introduced to encourage disentangled representations: single latent units that respond to single generative factors — object identity, position, scale, lighting — and stay flat with respect to the others. Raising β above 1 measurably improves standard disentanglement scores on synthetic 2-D shape datasets, at a visible cost in reconstruction quality.
  • The mechanism is bandwidth starvation. A tight rate budget forces the encoder to spend nats on the factors that explain the most and to spend them in the cheapest available basis — and a factorised prior makes an axis-aligned basis cheap. But the linear analysis above shows the limit of that argument: raising β is guaranteed to prune dimensions; it is not guaranteed to align the survivors with anything meaningful.
  • The honest caveat, which the follow-up literature made unavoidable: unsupervised disentanglement is not identifiable without inductive bias or supervision, because a rotation of the latent space leaves a factorised Gaussian prior invariant. High β reliably buys you fewer active dimensions; whether it buys you interpretable ones depends on the data and the architecture, and needs to be measured rather than assumed. Note how exactly this mirrors §04: a rotationally symmetric objective cannot pin down a basis.

22 Posterior collapse — when the latent variable stops existing

The encoder outputs μ = 0 and σ = 1 for every input, the KL term goes to zero, and the decoder learns to ignore z entirely. The ELBO looks fine. The model has become an unconditional density estimator with a very expensive random number generator attached.

The mechanism, read straight off the objective

  • Each latent dimension contributes ½(σⱼ² + μⱼ² − 1 − log σⱼ²) to the loss, minimised at exactly zero when μⱼ = 0, σⱼ = 1 — the setting that carries no information about x. Ignoring a dimension is not a degenerate accident; it is a local optimum the objective actively rewards.
  • A dimension survives only if the reconstruction it enables is worth more than the KL it costs. Anything that reduces the value of the reconstruction — a weak signal, a heavy KL weight, or a decoder powerful enough to do well without z — tips that comparison.
  • The classic trigger is a strong autoregressive decoder. If the decoder can predict each element of x from the earlier ones almost as well as it could with z's help, then z is nearly worthless and the model gladly pays zero KL for it. This is why collapse is far more common in text VAEs than in image ones.

23 Inside the latent space — traversal, interpolation, and the holes

The VAE's selling point over a plain autoencoder is that its code space is organised: a prior says where the codes should be, so you can walk around in it, interpolate, and sample. This section is about how far that promise actually goes.

Three things you can do with a latent space, and what each shows

  • Traversal. Fix all coordinates but one, sweep that one over a few standard deviations, and decode each point. If the model has found factors of variation, one coordinate moves one thing. This is the standard qualitative disentanglement check, and it is a check, not a proof.
  • Interpolation. Encode two examples, walk along the segment between their codes, and decode. A well-organised latent gives a plausible sequence of intermediates; a badly organised one gives a cross-fade — which is what interpolating in pixel space always gives, and is therefore the thing to beat.
  • Ancestral sampling. Draw z ~ 𝒩(0, I) and decode. This is the only one of the three that tests whether the aggregate posterior actually matches the prior, and it is the one that most often disappoints.
the aggregate posterior — the distribution your codes actually haveq(z) = Ex~pdata[ qφ(z | x) ] = (1/N) ∑ᵢ qφ( z | x⁽ⁱ⁾ ) the ELBO's KL term pushes each qφ(z|x) toward p(z) INDIVIDUALLY. It does NOT directly force the aggregate q(z) to equal p(z) — and it usually does not.

The prior hole, which is why samples are worse than reconstructions

  • Sampling is only valid where the decoder was trained, and the decoder was trained on codes drawn from q(z), not from p(z). Wherever p(z) has mass and q(z) does not, you are asking the decoder about a region it has never seen. Those regions are prior holes.
  • The symptom is unmistakable and universal: reconstructions look fine, samples look worse. If you have ever concluded a VAE "works" from a reconstruction grid, this is the reason to be suspicious.
  • The mismatch is a direct consequence of what the objective asks for. Pushing every individual posterior toward the prior is not the same as making their mixture match the prior — the mixture can be lumpy while every component is nicely centred.
  • The standard fixes all amount to fitting a better prior: learn p(z) after training (a mixture, a flow, an autoregressive model), or use a two-stage VAE that fits a second small VAE to the codes. Both work, and both quietly concede that 𝒩(0, I) was the wrong prior.

24 Why VAE samples are blurry — the honest reasons

Blurriness is the single most-cited complaint about VAEs, and it is usually explained badly. There are three distinct causes, only one of which is really about variational inference, and the fix that actually works in production addresses none of them directly.

Cause 1 — a squared-error decoder outputs a conditional mean, and means of sharp things are blurry

  • With a Gaussian decoder of fixed variance, the reconstruction term is squared error, and the value that minimises expected squared error is the conditional mean E[x | z]. If several genuinely different x share a code, the best possible output is their average — and the average of two sharp images with an edge in different places is one image with two faint edges.
  • This is not a failure of optimisation, or of the bound, or of the network. It is what the loss asks for. A perfect optimiser on a perfect architecture produces exactly this.
  • It also explains which details vanish: features occupying few pixels, or causing only small changes in brightness, contribute little to a squared error, so the model spends its capacity elsewhere. Squared error is a bad model of what people notice.
  • The effect is measurable and appears in the figure below. On the toy dataset of §23, whose signals all have peak height exactly 1.000, the reconstruction's mean peak height falls from 0.997 at β = 0.2 to 0.953 at β = 10 and 0.768 at β = 200. That last value is not arbitrary: it is exactly the peak of the dataset mean, because at that point the code carries nothing and the best reconstruction of everything is the average of everything. Meanwhile the number of training examples being averaged into each output climbs from 2.4 to 240 — the entire dataset.

Cause 2 — maximum likelihood is mode-covering

  • Maximising likelihood minimises DKL(pdata ‖ pmodel), which is infinite wherever the data has mass and the model has none. So the model is heavily punished for missing anything and only mildly punished for putting mass where there is no data. It spreads.
  • Some of the mass it spreads lands on things that are not images — including blurry ones. This is a property of the divergence, shared by every likelihood-trained generative model, not something specific to VAEs.
  • The contrast with a GAN is exactly here. An adversarial objective punishes generating anything the discriminator can call fake, and does not punish missing modes at all. That is why GANs are sharp and drop modes, and why VAEs cover the data and blur. It is one trade, seen from two sides.

Cause 3 — a factorised decoder cannot express what it is missing

  • The decoder emits conditionally independent outputs given z: every pixel is its own Gaussian or Bernoulli. So all correlation between pixels must be carried by z, and whatever z's limited capacity cannot carry is emitted as independent per-pixel noise.
  • Given the choice between independent speckle and a smooth average, squared error picks the average every time. Independence in the output distribution therefore turns directly into smoothness in the output image.
  • And note the interaction with §22: the tighter the rate budget, the more that z cannot carry, and the more the decoder must fall back on averaging. Blur and posterior collapse are the same phenomenon at two severities.
Blur, measured — how many examples is each output an average of? every signal in this dataset has peak height exactly 1.000, so the reconstruction's peak height is a direct sharpness meter

What actually fixes it in practice

  • Stop using a pixel-space likelihood. The autoencoders used inside modern generative systems are trained with a perceptual loss plus a patch-based adversarial loss on top of the reconstruction term, precisely — and explicitly — to keep reconstructions on the image manifold and to avoid the blurriness that comes from relying on pixel-space L¹ or L² objectives alone. The KL is kept, but as a mild regulariser on the latent rather than the dominant term.
  • Give the decoder a stronger output model. A discretised logistic or autoregressive decoder can express pixel correlations directly instead of pushing them all through z — at the cost of inviting posterior collapse (§22).
  • Hand generation to something else. Use the autoencoder only as a compressor and fit a separate, powerful prior over its latents: an autoregressive model over discrete codes (§26), or a diffusion model over continuous ones (§27). This is the arrangement that won, and it is worth noticing that it does not fix the VAE's blur so much as stop asking the VAE to generate.
The sentence to retire. "VAEs are blurry because they are variational." They are not: the bound's looseness is a separate issue (§17) and a deterministic autoencoder with the same squared-error decoder blurs in exactly the same way. They are blurry because a factorised, squared-error output distribution asked to cover the data will output a conditional mean. Change the output distribution and the blur goes with it — which is exactly what the systems in §27 did.

25 Tighter bounds, richer posteriors, and the rest of the family

Every weakness identified so far has a named fix, and each fix buys one thing at the cost of another. This is the map.

The importance-weighted bound

  • Draw k samples from q(z|x) instead of one, and average the importance ratios inside the logarithm rather than outside. The result is still a lower bound on log p(x), it reduces to the ordinary ELBO at k = 1, and it gets monotonically tighter as k grows.
  • The interpretation is exactly importance sampling: q is a proposal distribution for estimating p(x), and averaging k proposals before taking the log gives a better estimate of the evidence. Jensen's gap shrinks as the estimator's variance falls.
  • The cost is k decoder passes per data point. And the well-known catch: a tighter bound weakens the gradient signal for the encoder, so an IWAE can end up with a better bound and a worse inference network than a plain VAE. Tighter is not automatically better.

Those are the only three places the VAE can be wrong, so they are the only three places to look.

26 VQ-VAE — discrete latents, and a KL that cannot collapse

Replace the continuous code with the index of the nearest entry in a learned codebook. The posterior becomes a one-hot categorical, the KL becomes a constant, posterior collapse becomes impossible, and the price is a step with no gradient.

The construction

  • Keep a codebook e₁ … e_K, each a vector in ℝDe. The encoder produces a continuous field ze(x) — a 1-D sequence for audio, a 2-D grid for images, a 3-D volume for video — and each position is snapped to its nearest codebook entry.
  • The posterior is deterministic and one-hot: probability 1 on the nearest entry, 0 on everything else. With a uniform prior over the K entries, the KL term of the ELBO is exactly log K — a constant, independent of the encoder's parameters, so it can simply be dropped from training.
  • That single fact is why VQ-VAE does not collapse. There is no gradient pushing the rate toward zero, because the rate is fixed by construction at log K nats per position. Compare §22, where the entire failure mode was that gradient.

The gradient problem and the straight-through fix

  • argmin has no useful derivative: zero almost everywhere, undefined on the boundaries. Exactly the situation §18 said the reparameterisation trick cannot handle, and the reason the score-function estimator would otherwise be the only option.
  • The straight-through estimator sidesteps it: in the forward pass send zq to the decoder; in the backward pass copy the gradient at the decoder's input unchanged to the encoder's output. It is a deliberate lie about the derivative, justified by the fact that ze and zq live in the same space, so the direction that would improve the decoder is also a sensible direction to move the encoder.
  • Because that copied gradient bypasses the codebook, the codebook receives nothing from the reconstruction term and needs its own objective — which is where the second and third loss terms come from.
the three-term VQ-VAE loss; sg[·] is stop-gradient — identity forwards, zero derivativeL = log p( x | zq(x) ) + ‖ sg[ze(x)] − e ‖₂² + β ‖ ze(x) − sg[e] ‖₂² term 1 reconstruction trains the decoder, and the encoder via straight-through term 2 codebook loss moves each e toward the encoder outputs assigned to it — a k-means step term 3 commitment loss keeps the encoder near its chosen code, so the embedding volume cannot grow without bound
  • Each term trains exactly one part: the decoder optimises the first, the embeddings optimise the second, and the encoder optimises the first and the third.
  • β = 0.25 is the standard commitment weight, and results were reported to be insensitive across β from 0.1 to 2.0. The right value does depend on the scale of the reconstruction loss.
  • An alternative to the second term is to update the codebook by an exponential moving average of the encoder outputs assigned to each entry — the same k-means step, done without an optimiser, and usually more stable.
  • The dominant practical failure is codebook collapse: a large fraction of entries are never selected and therefore never updated. Standard remedies are EMA updates, re-initialising dead entries from live encoder outputs, L²-normalising the codes, and lowering the code dimension.

The two-stage arrangement, and the numbers

  • A VQ-VAE on its own is a compressor, not a generative model: it has no interesting prior over the code grid. Generation is a second stage — fit a powerful autoregressive model (originally a PixelCNN, later a transformer) over the grid of discrete indices, then sample indices from it and decode.
  • The reported image setting makes the compression concrete: 128 × 128 × 3 images encoded to a 32 × 32 grid of indices with K = 512, i.e. 9 bits per position. In bits that is 128·128·3·8 / (32·32·9) ≈ 42.6×, and the reconstructions were reported to be only slightly blurrier than the originals.
  • Why the split helps: the autoregressive model no longer has to spend its capacity on pixel-level texture, which the decoder already handles, and can spend it on global structure instead. Sampling is also far cheaper — 1 024 positions rather than 49 152 subpixels.
  • The reported likelihoods are honest about the cost: on one benchmark a VAE reached 4.51 bits per dimension and the VQ-VAE 4.67. Discretisation is not free — it buys stability and a tractable second stage, and pays in nats.
  • Later work stacked several resolutions of codes — a coarse grid for global structure and a finer one for detail, each with its own prior — which is the arrangement that produced high-fidelity samples at scale.
The idea that outlived the model. "Encode into a grid of discrete tokens, then let a sequence model handle the distribution over tokens" is now the standard recipe for images, audio and video inside vision-language models — the tokeniser is a VQ-VAE descendant, and the prior is a transformer. The autoencoder half of this page turned out to be the durable half.

27 Where this lands today — the latent space everything else runs in

The autoencoder lost the generative-modelling contest and won something larger: it became the coordinate system that the winning generative models operate in. This is why the diffusion page keeps pointing back here.

Latent diffusion, stage by stage

  • Stage one is an autoencoder — this page's subject — trained with a reconstruction term, a perceptual loss and a patch-based adversarial objective, explicitly to keep reconstructions on the image manifold and to avoid the blur that a pure pixel-space L¹ or L² loss produces (§24). It is regularised in one of two ways: a slight KL penalty toward a standard normal — a VAE with a very small β, deliberately mild so the latent does not lose information — or a vector-quantisation layer in the decoder, which is §26's construction absorbed into the architecture.
  • Stage two trains a diffusion model entirely inside that latent space, and decodes once at the end. Everything the diffusion page says about schedules, samplers and guidance happens to z, not to pixels.
  • The economics: attention cost grows quadratically in the number of spatial positions, and every one of the tens of denoising steps pays it. Shrinking the canvas by a factor f per axis discounts all of them. That is the whole reason high-resolution text-to-image fits on one consumer GPU — and the diffusion page's §10 is the same story told from the other end.

The same idea everywhere else

  • Audio and speech. Neural audio codecs are residual vector-quantised autoencoders; the tokens they emit are what audio and music language models actually model. Same two-stage split as §26.
  • Video. A spatio-temporal autoencoder compresses time as well as space, and a transformer diffuses over the resulting latents — otherwise the sequence length is hopeless.
  • Multimodal models. Image and audio tokenisers let a single sequence model consume and emit several modalities. The tokeniser is an autoencoder; the intelligence is the prior.
  • Interpretability. Sparse autoencoders (§08) trained on a language model's internal activations, used to pull out candidate features. A twenty-year-old objective pointed at a new kind of data.
  • The road not taken. JEPA-style models argue you should predict in representation space and drop the decoder entirely, precisely to avoid spending capacity on pixel detail. That is a direct rejection of the reconstruction objective — and worth reading against §24, because it targets the same problem from the opposite direction.

The diagnostics that are worth logging every run

  • Rate and distortion separately, never just the ELBO. Two models with equal ELBOs can sit at opposite ends of §21's frontier.
  • Per-dimension KL, and the count above ~0.01 nats. This is the collapse detector, and the total hides it completely (§22).
  • Held-out reconstruction error, against the PCA floor ∑i>d λᵢ at the same code size. If a deep autoencoder does not beat the floor, it has not earned its parameters (§04).
  • The off-manifold probe. Feed inputs the model should not recognise and measure how far it moves them. Little movement means g∘f is near the identity and the model has learned nothing about the distribution (§06). Costs one forward pass.
  • The active fraction of the codebook, for VQ models. Dead entries are the standard failure and they are invisible in the loss.
  • Samples and reconstructions, side by side. A large gap between them is the prior hole of §23, and it is diagnostic rather than cosmetic.

The traps, in the order people fall into them

trap 1
An accidental β
Fixing the decoder variance, or averaging rather than summing over pixels, silently sets the KL weight — and the two together can be off by three orders of magnitude. State β explicitly, or learn σ (§20).
trap 2
Averaging the KL over dimensions
mean instead of sum across the latent axis divides the effective β by d. Sum over dimensions, mean over the batch. Every time.
trap 3
Bernoulli likelihood on non-binary data
"BCE" on targets in [0,1] is not a density, and the missing normaliser changes the objective. Use a continuous Bernoulli, a Gaussian, or a discretised logistic (§20).
trap 4
Reading the weights as components
A linear autoencoder's matrices are defined only up to an invertible mixing. Ordering them or interpreting one column as "the first factor" is reading an arbitrary change of basis (§04).
trap 5
Anomaly detection by reconstruction error
High-capacity autoencoders often reconstruct unseen inputs well, and the error is dominated by high-variance regions rather than by anomalousness. Run the §06 probe before trusting it.
trap 6
Comparing models by ELBO
An ELBO is a bound whose deficit depends on the posterior family. A model with a better encoder can win while having the worse decoder (§17).
trap 7
Believing a traversal
A tidy-looking traversal is a hypothesis. Unsupervised disentanglement is not identifiable without inductive bias, and rotations of the latent leave a factorised Gaussian prior invariant (§21).
trap 8
Judging a VAE from reconstructions
Reconstructions test the encoder–decoder pair. Only ancestral samples test whether the aggregate posterior matches the prior — and that is the part that usually fails (§23).

A starting recipe that usually works

  1. Standardise the data, and pick the decoder likelihood that matches it (§20). Learn a single global σ rather than guessing one.
  2. Start with a latent size you expect to be too large, and let the per-dimension KL tell you how many dimensions the data actually supports. That number is far more informative than a guess.
  3. Anneal the KL weight from 0 to its target over the first 10–30% of training, or use free bits at roughly 0.1–0.5 nats per dimension. Do one or the other from the start; retrofitting them after a collapse means retraining anyway.
  4. Log per-dimension KL, rate, distortion, and held-out reconstruction from step one. Add sample grids next to reconstruction grids.
  5. If samples are blurry and you care, change the reconstruction loss before you change anything else — perceptual, then adversarial (§24, §27). Do not reach for a bigger decoder.
  6. If you need real generative quality, stop asking the autoencoder for it: freeze it and fit a strong prior over its latents — autoregressive over discrete codes, or diffusion over continuous ones (§26, §27).

What to remember

  • An autoencoder is a learned identity with an obstacle, and the obstacle is the model. Shape is not a bottleneck; the learned function is.
  • A linear autoencoder with squared loss spans the principal subspace and hits the PCA error floor exactly — and recovers no basis at all within it. Measured: principal angles under 3 × 10⁻⁵ degrees, decoder columns at |cos| ≈ 0.5 to every principal axis.
  • Denoising and contraction are the same instruction at two scales, and the denoiser's displacement field is exactly σ²∇log pσ — verified here to 10⁻¹⁶. That identity is the bridge to diffusion.
  • The ELBO is a lower bound with an exactly identified deficit, DKL(q ‖ p(z|x)), that you never get to observe. Verified on a toy model: ELBO −7.919220 plus gap 4.060922 equals log p(x) = −3.858298, to 10⁻⁹.
  • Reparameterisation is not elegance, it is variance. Measured at a 128-dimensional latent: 4 556× more samples needed for the score-function estimator to match.
  • Posterior collapse is not an optimisation bug — the collapsed solution is often the global optimum. In the linear case a dimension dies exactly when λᵢ ≤ βσ², confirmed against a trained model to four decimals.
  • Blur is what a factorised squared-error likelihood asks for: the optimal output is a conditional mean. Change the likelihood and the blur goes.
  • And the ending: the autoencoder is now the coordinate system that diffusion models and multimodal transformers run inside. It stopped being the generative model and became the space.
In one sentence: force a network to rebuild its input through something it cannot fit the input into, and the shape of what survives is a model of the data — a subspace if the network is linear, a manifold if it is not, and a probability distribution if the code is one too.
