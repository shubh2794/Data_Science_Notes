Neural Network Hardware

A neural network on paper is a sequence of real-valued multiply–accumulates followed by a nonlinearity. A neural network on silicon is something else: every number has a finite number of bits, every multiply costs area and picojoules, every weight has to be fetched from somewhere, and fetching it usually costs far more than using it. This page follows that gap from the bottom up. It starts by counting — MACs, bytes and joules for one forward pass — and turns the count into the roofline, the one-line model that says whether a layer is limited by arithmetic or by memory. It then goes through the choices that designers of neural hardware have argued about since the late 1980s: floating point or fixed point, how many bits, what happens on overflow, why training needs more precision than inference and how stochastic rounding narrows that gap; how to compute a sigmoid with no exponential unit; how to arrange thousands of multipliers so that each fetched value is used many times (the systolic array); and how an FPGA's lookup tables, DSP slices and block RAM trade precision against parallelism. It ends with the exotic arithmetics — bit-serial, stochastic bitstreams, logarithmic numbers, analog crossbars, spiking chips — and with the honest verdict of history: why general-purpose GPUs and one very large-volume ASIC family won the general case, and where FPGAs and small custom chips still win.

01 Why hardware matters

Every neural network, classical or modern, spends almost all of its time in one operation: the multiply–accumulate (MAC), acc ← acc + w·x. A perceptron is one inner product; a multilayer perceptron is a stack of matrix–vector products; a convolutional layer is a matrix product in disguise; a transformer is matrix products plus a softmax. Whoever makes MACs cheap — in time, area, energy and memory traffic — makes neural networks cheap. That has been true since the first analog neurochips of the late 1980s, and it is why the hardware story of this field is mostly a story about arithmetic and data movement, not about "neurons".

the neuron, as the hardware sees ity = φ( ∑ᵢ₌₁ⁿ wᵢ xᵢ + b ) n MACs, one bias add, one nonlinearity a layer of m neuronsy = φ(W x + b), W ∈ ℝᵐˣⁿ m·n MACs, m·n weights to read, m nonlinearities the same layer over a batch of B inputsY = φ(W X + b), X ∈ ℝⁿˣᴮ m·n·B MACs, still only m·n weights

Three resources are consumed, and a design is a choice about which to spend:

  • Compute — how many MACs per second the silicon can perform. It scales with the number of multipliers and the clock, and the size of a multiplier grows roughly with the square of its operand width, so precision and parallelism are directly traded against each other.
  • Memory capacity and bandwidth — where the weights and activations live and how fast they can be moved to the multipliers. The multipliers are useless if they are starved.
  • Energy — the joules per inference or per training step. On battery-powered devices and in data centres alike, this is the binding constraint, and as §02 shows it is dominated by moving data, not by arithmetic.

One number sits on top of all three: latency, the wall-clock time from input to output. A network used for control or for a trigger in a physics experiment may need an answer in microseconds for a single input, while a recommendation model is judged by throughput over millions of inputs. These two goals favour different hardware, and that difference is the reason FPGAs and small ASICs still exist beside GPUs (§16).

The classical connection. The networks in this series — perceptrons, Hopfield nets, SOMs, RBF networks — were among the first targets of dedicated neural hardware, because their computation is so regular: an inner product, a comparison or a distance, a simple nonlinearity, all repeated over many units in parallel. The same regularity is what modern accelerators exploit for CNNs and transformers.

  • Precision pays twice. Going from 32 to 8 bits shrinks the multiplier by roughly (32/8)² in area and ≈ 15× in energy, and it cuts every memory transfer by 4×. Sections 05–08 are about how far you can push this before accuracy breaks.
  • Reuse is the other lever. At batch 1 each weight is fetched to be used exactly once. Batch B inputs together and each fetched weight serves B MACs; tile a convolution and each fetched activation serves many filters. Sections 10–11 are about arranging the arithmetic so every fetched value is reused as much as possible.
  • Where the bytes live matters as much as how many there are. A register access is nearly free, a neighbour PE's register costs about twice that, an on-chip buffer about 6×, and DRAM about 200× (the normalised figures used in the design of the Eyeriss accelerator, Chen et al. 2016). The whole art of accelerator design is keeping data in the cheap levels.

03 Arithmetic intensity and the roofline

Arithmetic intensity is the number of operations performed per byte moved to or from main memory. The roofline model (Williams, Waterman & Patterson 2009) says that a kernel with intensity I on a machine with peak compute P and memory bandwidth β can run no faster than min(P, β·I). Everything left of the "ridge" is memory-bound; everything right is compute-bound.

definitionsI = FLOPs / bytes moved from DRAM attainable = min( P, β · I ) ridge I* = P / β dense layer d × d, batch B, 2-byte values (weights read once, inputs and outputs once)FLOPs = 2·B·d² bytes = 2·(d² + 2·B·d) I = B·d / (d + 2B) ≈ B for B ≪ d limitsB = 1: I ≈ 1 FLOP/byte B → ∞: I → d/2 square GEMM n³: I = n/3 worked: an H100-class GPU, P ≈ 989 TFLOP/s dense BF16, β ≈ 3.35 TB/sI* = 989 / 3.35 ≈ 295 FLOP/byte. At batch 1 a 4096-wide layer reaches 3.35 TFLOP/s — 0.34% of peak. Solving B·4096/(4096 + 2B) = 295 gives B ≈ 345: only then is the same layer compute-bound.
The roofline: where does your layer sit? drag anywhere on the chart to set the intensity, or use the batch slider for a 4096 × 4096 BF16 layer; switch devices to move the ridge

At the default (H100-class device, batch 1) the point sits at I ≈ 1 on the sloped line: the machine delivers a third of one percent of its peak, and buying a faster chip with the same memory would change nothing. Slide the batch up and the point climbs the slope until, near B ≈ 345, it hits the flat roof. Switch to the TPU v1: its 92 TOPS of 8-bit MACs were fed by only 34 GB/s of DDR3, which puts the ridge near 2 700 ops/byte — beyond the d/2 = 2 048 that any 4096-wide dense layer can ever reach. That was exactly the published finding (Jouppi et al. 2017): most of Google's production MLPs and LSTMs were memory-bound on the first TPU, and the second generation switched to high-bandwidth memory. The same geometry explains why single-stream LLM decoding (one token, every weight read once) is memory-bound on any device, why speculative decoding helps, and why weight-only quantization (§08) speeds decoding almost in proportion to the bytes saved.

How to read a roofline in practice. If your kernel is left of the ridge, reduce bytes: quantize weights, fuse elementwise ops so intermediates never touch DRAM, batch requests. If it is right of the ridge, reduce FLOPs or use lower-precision math units: tensor cores, int8, sparsity. Optimising the wrong side does nothing.

04 Where the parallelism is

"Neural networks are massively parallel" was the founding slogan of neural hardware. It is true, but the parallelism comes at several levels of very different size, and a design has to decide which ones to spend silicon on.

Two consequences shaped the history of the field. First, virtual parallelism is unavoidable, so every accelerator is really a scheduler: it decides which slice of which weight matrix is on which multiplier in which cycle — the dataflow of §10. Second, the neural-network part is rarely the whole job. Many dedicated neurocomputers of the late 1980s and 1990s were built with enormous arrays of simple PEs and nothing to handle the serial parts — preprocessing, control flow, I/O — so Amdahl's law quietly capped them. Designs that survived were the ones with a general-purpose processor alongside the array; today every accelerator pairs its matrix engine with scalar and vector units for exactly this reason.

05 Number representations: floating point vs fixed point

A floating-point number stores a sign, an exponent and a mantissa, so its relative precision is constant across a huge range. A fixed-point number is just an integer with an implied binary point, so its absolute precision is constant across a small range. Floating point is what software uses; fixed point is what small, fast, low-power hardware prefers, because a fixed-point adder is an integer adder and a fixed-point multiplier is an integer multiplier.

Fixed point: the Qm.n format

The integer bits m buy range, the fraction bits n buy resolution, and for a fixed word length b every bit moved from one to the other halves one and doubles the other. This is the core fixed-point design decision, and it is made separately for weights, activations, sums and gradients because their ranges differ by orders of magnitude.

  • bfloat16 is FP32 with the mantissa cut off. Same 8-bit exponent, so the same range — no overflow or underflow surprises when converting — and a mantissa multiplier of 8 × 8 bits (with the hidden bit) instead of 24 × 24: about one ninth of the area. Networks turned out to care far more about range than about the seventh decimal digit.
  • A floating-point adder is a fixed-point adder plus a great deal of alignment logic: compare exponents, shift the smaller mantissa, add, renormalise, round. That is why, on FPGAs and small ASICs, floating point costs so much more than fixed point of the same width. One careful FPGA study of backpropagation found a 16-bit fixed-point adder about 39× smaller than a 32-bit floating-point one, the multiplier 6.5× smaller, and a table-based fixed-point sigmoid 250× smaller than a floating-point sigmoid unit; the whole fixed-point network was 13× smaller and 12× faster, and it still learned the task.
  • Block floating point sits in between: a block of values (a row, a tile of 16 or 32) shares one exponent and each value keeps a short integer mantissa. Arithmetic inside the block is fixed point; the shared exponent supplies range. It is the idea behind the microscaling (MX) formats of §08.

06 Quantization error, overflow and saturation

Quantizing a real value to a grid of step Δ introduces two kinds of error. Values inside the range are moved by at most half a step — small, bounded, noise-like. Values outside the range overflow — and what the hardware does then decides whether the error is merely large or catastrophic.

At the default Q1.6 (8 bits, range [−2, 2), LSB 1/64) the weight RMS error is 5.1 × 10⁻³ against the Δ/√12 = 4.5 × 10⁻³ of pure rounding — the small excess is the two widest weights being clipped — and the network's output moves by about 2.6% of its own spread: the dashed curve sits almost on top of the solid one. Things to try:

  • Sweep b. Along the bottom panel both errors fall by a factor of two per bit (6 dB) while rounding dominates, then the weight error flattens above ≈ 10 bits: extra fraction bits cannot fix the two clipped weights, so the range error becomes the floor. Going down, 4 bits moves the output by about 60% of its spread and 3 bits by more than 100% — the network has become a different function.
  • Set m = 0 (range [−1, 1)). You gain a bit of resolution, but 17 weights now clip, and because they are the largest weights they matter most: even with saturate the output error jumps to about half the output's spread. Switch to wrap around and each clipped weight becomes a large weight of the opposite sign — output error over 100%. This is why every neural accelerator saturates, and why checking the dynamic range of every tensor is the first step of any fixed-point port.
  • Switch to truncate. The weight RMS error roughly doubles (toward Δ/√3 instead of Δ/√12), but the output error grows more than fivefold, to about 14%: every weight is pushed the same way, and a bias does not average out across 24 inputs the way zero-mean noise does. Rounding costs one adder; it is always worth it.
  • Set m = 4. Range [−16, 16) spends three more integer bits than Q1.6 on weights whose largest magnitude is about 2.04: the same word length now buys eight times less resolution. Choosing m is choosing a clipping threshold, and the best threshold is usually inside the data's extreme values, not at them.
Error propagation, informally. A perturbation δW of the weights changes a layer's pre-activation by δW·x, whose variance is about n·Δ²/12·E[x²] for n inputs; a tanh or sigmoid slope ≤ 1 then passes it on at most unchanged. So the output error grows with fan-in and depth but only like √n per layer — the reason networks tolerate low precision far better than, say, a matrix inversion does. Saturating nonlinearities help further: an input deep in the flat part of a sigmoid is insensitive to small errors.

07 Precision for training vs inference, and stochastic rounding

Inference only needs the forward pass to be close enough; training needs something harder — that very small weight updates, summed over thousands of steps, actually arrive. Round-to-nearest destroys any update smaller than half an LSB, so a fixed-point learner can stall even though each forward pass is perfectly accurate.

the swamping problemw ← Q( w + η·δ·x ) with round-to-nearest: |η δ x| < Δ/2 ⇒ w never changes worked: Q3.12 weights, learning rate 0.1Δ/2 = 2⁻¹³ ≈ 1.22 × 10⁻⁴. A late-training gradient δ·x ≈ 10⁻³ gives η δ x = 10⁻⁴ → rounded away, every step stochastic rounding (SR)SR(x) = ⌊x⌋Δ + Δ with probability (x − ⌊x⌋Δ) / Δ, else ⌊x⌋Δ E[ SR(x) ] = x exactly — unbiased, so T tiny updates of size u sum to T·u on average the price is variance: after T updates with fractional part f, std = Δ·√( T·f(1 − f) )
400 weight updates, each smaller than one LSB set the update size in LSB units; below 0.5 round-to-nearest never moves, truncation never moves below 1, stochastic rounding tracks the exact sum

At the default 0.3 LSB per update the exact sum reaches 120 LSB, round-to-nearest and truncation both stay at 0 — the learner is frozen — and the stochastic-rounding runs end within a few LSB of 120, their spread matching √(T·f(1−f)) ≈ 9 LSB. Push the update to 0.6 and round-to-nearest now rounds every update up to a full LSB, overshooting to 400: a different, equally wrong, answer. Only unbiased rounding, or keeping a wider copy, gets the sum right for every update size.

  • The classical answer: more bits for training. Early simulation studies of backpropagation in fixed point (Holt & Baker 1991) found about 16 bits — sign, 3 integer bits, 12 fraction bits, with inputs and targets in [0, 1] — to be the minimum for reliable learning, while forward-only use tolerated 8-bit activations and somewhat more for weights. That "16 bits for learning, 8 for recall" rule of thumb held for decades.
  • Stochastic rounding moves the line. Gupta et al. (2015) trained networks with 16-bit fixed-point weights and stochastic rounding to the same accuracy as FP32, where round-to-nearest failed. The random bits are cheap in hardware — a linear-feedback shift register per unit — and SR is now built into several training accelerators.
  • The modern answer: mixed precision. Keep an FP32 master copy of the weights (the violet line in the figure) and apply updates to it; run the forward and backward matrix products in 16 or 8 bits (Micikevicius et al. 2018). With FP16, gradients can underflow the 5-bit exponent, so the loss is multiplied by a scale factor before backpropagation and divided out afterwards (loss scaling); bfloat16's 8-bit exponent largely removes that need. FP8 training (2022 onward) uses E4M3 for the forward pass and E5M2 for gradients, each tensor with its own scale.
  • Accumulators always stay wide. Whatever the operand precision, sums are kept in FP32 or int32: the sum of thousands of products is where the error would otherwise pile up.
Inference vs training in one line. Inference needs the function to be preserved; that tolerates 8 bits almost everywhere, and 4 bits or less for weights with care. Training needs small differences to be preserved; that needs either wide accumulators and master weights, or unbiased rounding, or both.

08 Low precision today: bfloat16, FP8, int8, int4

What was an FPGA designer's hand-tuned trick in the 1990s is now standard practice at every scale. 09 Implementing activation functions in hardware

Multiplication and addition are easy in hardware; ex and division are not. The logistic sigmoid σ(x) = 1/(1 + e−x) and tanh need both, and a naive implementation can end up bigger than all the MACs it follows. Hardware designers therefore never compute them exactly — they approximate, and the only questions are how, at what error, and at what cost in memory, multipliers and latency.

free identities that halve every approachσ(−x) = 1 − σ(x) store only x ≥ 0, one subtractor handles the rest tanh(x) = 2σ(2x) − 1 one unit serves both functions (shifts do the ×2) σ′(x) = σ(x)(1 − σ(x)) the derivative for backprop costs one multiply, no second table saturationσ(8) = 0.99966, σ(−8) = 3.4 × 10⁻⁴ → outside ±R, output the constant 0 or 1; the floor on error is σ(−R)

The four families

  • Lookup table (LUT). Use the top k bits of x as an address into a 2ᵏ-entry ROM. One memory read, no arithmetic, trivially pipelined. The error is roughly slope × half a cell: for σ over [−8, 8) with N entries, about 0.25 × (16/N)/2 = 2/N, so each extra bit of accuracy doubles the table. Fine for 8-bit outputs; hopeless for 16.
  • Piecewise-linear (PWL) interpolation. Split the range into N segments (a power of two, so the top bits select the segment), store a slope and an intercept for each, compute c₂·x + c₁. One multiply and one add, 2N words. The error falls like 1/N² instead of 1/N. A further factor of two is free: instead of joining the endpoints of each segment (the chord), shift the line by half its maximum gap so that the error equioscillates — equal and opposite at the ends and at the interior extremum. Applied to relative error this minimax condition exactly halves the maximum error of the endpoint fit, with the same table size and hardware.
  • PLAN and other shift-only approximations. Choose segment slopes that are powers of two, and the multiply becomes a wire shift. PLAN (Amin, Curtis & Hayes-Gill 1997) uses four segments per side — slopes ¼, ⅛, 1/32 and 0 — and needs only comparators, shifts and adds; its maximum error is about 0.019, adequate for many classifiers. "Hard" variants (hard-sigmoid, hard-tanh, and ReLU itself) take this to its limit.
  • Polynomials and CORDIC. A minimax or least-squares polynomial of degree d evaluated by Horner's rule costs d multiply–adds in sequence; an odd polynomial in x for σ(x) − ½ halves that. High degrees are accurate but either slow or large, so hardware uses low-order polynomials per segment, the coefficients selected by the top bits — the combination of a small table with a low-order polynomial that remains the best general-purpose method. CORDIC (Volder 1959; hyperbolic mode, Walther 1971) computes sinh and cosh with nothing but shifts, adds and a small table of atanh(2⁻ⁱ), one bit of accuracy per iteration; but the sigmoid then still needs an exponential range reduction and a division, so it takes two or three CORDIC passes of b iterations each. Its virtue is that one datapath computes many functions; its vice is latency.
Five ways to build σ(x) without an exponential unit N sets the table entries / segments; the bottom panel shows |error| on a log scale; the table counts memory words and multipliers

At the default (N = 16, degree 5, R = 8) the table in the readout shows the ranking you should expect: the 16-entry LUT is worst (a staircase, error ≈ 0.1), PLAN is next with no memory at all (≈ 0.019), the chord PWL with 16 segments is ≈ 0.012, and the balanced PWL is exactly half of it, ≈ 0.006. The degree-5 polynomial over the whole ±8 range is poor — a single low-order polynomial cannot bend into both flat tails. Slide N to 256: the LUT reaches ≈ 8 × 10⁻³ (still coarser than 8-bit output resolution in the middle), while both PWL variants drop to the floor set by the input range itself, σ(−8) = 3.4 × 10⁻⁴ — with 256 segments the interpolation error is no longer what limits accuracy. Now drop R to 4 and watch every method hit the new, higher floor σ(−4) ≈ 0.018 — the input range is itself an approximation. Finally, quantize the coefficients to 8 fraction bits: the fancy methods lose their edge, because the answer cannot be more precise than the words that store it.

Rate matching, the hidden cost. A neuron with n inputs does n MACs and then one activation. In a custom chip that is easy to balance; on an FPGA, where arithmetic sits in fixed DSP columns and memory in fixed BRAM columns, routing every neuron's sum to a shared activation unit and keeping that unit busy — but not a bottleneck — is often harder than the approximation itself. Designs typically share one activation unit among many MAC chains and pipeline it.

10 Inner products and dataflow

With the arithmetic fixed, the remaining freedom is order: which products are computed where and when, and therefore which values have to be fetched how often. For a matrix product this is literally the order of three nested loops, and the choice changes the memory traffic by large factors without changing a single result.

Chains and trees for one inner product

The same thinking drives GPU kernel tiling today: a tile of W and a tile of Y are loaded into shared memory once and reused across the whole tile of U, which is how a matrix multiply is moved right of the ridge in §03.

11 Systolic arrays

A systolic array (Kung & Leiserson 1978; Kung 1982) is a grid of identical MAC cells, each connected only to its neighbours, through which data is pumped in lock-step like blood through the heart. Each value is read from memory once, enters at the edge, and is used by every cell it passes. Wires are short, control is trivial, and the array scales to tens of thousands of multipliers — which is why it sits at the heart of the TPU and of many edge NPUs.

output-stationary n × n array computing C = A · Brow i of A enters from the left, delayed i cycles column j of B enters from the top, delayed j cycles in cycle t, PE(i, j) computes C[i][j] += A[i][k] · B[k][j] with k = t − i − j, if 0 ≤ k < n costn² PEs, n³ MACs, 3n − 2 cycles until the last C[i][j] is complete every A and B element is fetched once and used n times one product alone: utilisation n / (3n − 2) → ⅓; products streamed back-to-back: → 100% weight-stationary variant (the TPU's choice)PE(k, j) holds B[k][j]; A[i][k] enters row k at cycle i + k the partial sum for C[i][j] flows down column j and leaves at cycle i + j + n − 1 same 3n − 2 cycles; the weights are loaded once and reused for every input streamed through the first TPU256 × 256 = 65 536 8-bit MACs × 700 MHz × 2 ops ≈ 92 TOPS

Step through the 3 × 3 case. At cycle 1 only the top-left PE works; the wavefront of green cells then sweeps diagonally across the array, is widest at cycle 4 (7 of the 9 PEs busy), and drains out at the bottom right after 3n − 2 = 7 cycles. The readout counts exactly 27 = n³ MACs, and C matches A·B. Switch to weight-stationary: the weights sit still, the A values march across the rows and the partial sums march down the columns, and the timing is identical — but now the weights are the data loaded once, which is what you want when the same layer is applied to a stream of inputs.

  • Why it scales. Every wire is between neighbours, so wire length and clock skew do not grow with the array; there is no shared bus and no global memory port per PE. Memory bandwidth grows with the array's perimeter (2n values per cycle) while compute grows with its area (n² MACs per cycle) — the systolic array is an arithmetic-intensity machine.
  • Why it is rigid. The array is fast only for dense, regular products whose dimensions are multiples of n. Small or ragged matrices, sparsity and irregular operations waste cells — one reason general-purpose GPUs, which pair smaller tensor-core tiles with flexible scheduling, handle a wider range of models well.
  • Backprop fits too. The backward pass multiplies by Wᵀ; a systolic array can compute W·x and Wᵀ·δ with the same stored weights just by feeding data along the other axis. Fully pipelined backpropagation on systolic arrays in FPGAs reached several GOPS in the early 2000s.

12 FPGA design: LUTs, DSP slices, block RAM

A field-programmable gate array is a sea of small configurable resources wired together by programmable routing, configured by a bitstream after manufacture. For a neural network it offers a middle path: close to custom-hardware efficiency for the specific network you load, while remaining re-programmable when the network changes.

  • Resource vs throughput vs precision. On a fixed device, halving word length roughly quadruples the number of LUT-based multipliers you can place, or doubles DSP throughput through packing. The design question is therefore not "how many bits is best" but "what is the lowest precision that keeps accuracy, so I can spend the rest on parallelism". This is why FPGA neural designs pioneered 16-, 8- and eventually 1-bit networks long before GPUs supported them.
  • Reconfigurability. The bitstream can be replaced: the same board can host a different network, a different precision per layer, or — with run-time or partial reconfiguration — swap the forward-pass circuit for the weight-update circuit mid-training. The catch is time: loading a bitstream takes milliseconds, and compiling one (synthesis, place and route) takes hours, so FPGAs track model changes far more slowly than a GPU running new software.
  • Routing is the real scarce resource. An FPGA is a 2-D grid with limited wiring; a fully connected layer is a complete bipartite graph. Directly mapping one neuron per PE with all-to-all wires fails beyond small networks, so designs time-multiplex a modest array of PEs, restrict connectivity (local or partially connected layers), or use bit-serial links that need one wire per connection instead of b.
  • Design flow. Classical designs were written in VHDL or Verilog by hand. Today high-level synthesis compiles C++ or a trained model into a circuit — frameworks such as FINN (for binarized and quantized networks) and hls4ml (for ultra-low-latency physics triggers) generate a fully pipelined, layer-per-block design from a network description.
A measured data point. In one careful study of backpropagation on an FPGA, a 16-bit fixed-point (Q3.12, range [−8, 8)) network learned XOR as reliably as a 32-bit floating-point one, while being 13× smaller and 12× faster; it did saturate occasionally, and still converged. The floating-point version followed the software simulation's gradient-descent path exactly; the fixed-point one followed a slightly different path because of its quantization error — and ended in the same place.

13 On-chip learning: backprop in hardware

Most neural hardware, then and now, only does inference: the network is trained in software and its weights are loaded. On-chip learning puts the training algorithm itself on the device — needed when the device must adapt in the field, or when training speed is the goal — and it is much harder, for reasons that are all visible in the backprop equations.

what the hardware must add for backpropagationforward: Hₖ = ∑ⱼ wₖⱼ oⱼ + θₖ, oₖ = σ(Hₖ) — keep every oₖ for the backward pass output: δₖ = (tₖ − oₖ) · oₖ(1 − oₖ) — σ′ from the stored output, one multiply hidden: δⱼ = oⱼ(1 − oⱼ) · ∑ₖ wₖⱼ δₖ — a second matrix–vector product, with Wᵀ update: wₖⱼ ← wₖⱼ + η δₖ oⱼ — an outer product; every weight is written cost relative to inference≈ 3× the MACs (forward, backward, update), storage for all activations, write bandwidth for every weight, higher precision (§07) the training metricCUPS = connection updates per second (vs CPS, connections per second, for inference)
  • Control: a two-state machine. The simplest design alternates a forward state, in which only the forward datapath is enabled, and a backward state, in which the error, delta and update circuitry runs; weights are committed on the transition back to forward. Correct and simple, but half the hardware is idle at any time.
  • Pipelining forward and backward passes. To keep all hardware busy, the next pattern's forward pass starts while the previous one's error propagates back. Then the weights a pattern sees in its forward pass are a few updates older than those used when its gradient is applied — delayed or pipelined backpropagation. With a small learning rate it converges nearly as well. The same staleness trade-off reappears in modern pipeline-parallel training across many GPUs; see Distributed Training.
  • Learning algorithms chosen for hardware, not for software. An algorithm that converges in fewer epochs in software may be a poor choice in silicon if it needs divisions, global information or high precision. Local rules — the perceptron and LMS rules, Hebbian updates in Hopfield networks, the winner-take-all update of self-organizing maps, weight perturbation, and spike-timing-dependent plasticity in neuromorphic chips — need only information available at the synapse, and so were the favourites of on-chip learning. SOMs in particular were widely mapped onto FPGAs, because their "find the nearest unit" step is a parallel distance computation followed by a comparator tree.
  • Benchmark honestly. CPS and CUPS are the neural equivalents of MIPS and MFLOPS: easy to inflate, hard to compare across networks, and not the thing users care about. The meaningful measure is time (or energy) to reach a fixed accuracy on a fixed task — the approach taken by the MLPerf benchmarks since 2018.

14 Arithmetic-based design: bit-serial, stochastic and logarithmic

When multipliers are the scarce resource, change the arithmetic. Three alternatives recur throughout the history of neural hardware, each trading something — time, accuracy, or the cost of addition — for tiny operators.

Bit-serial arithmetic

process one bit per cyclea b-bit add takes b cycles on a 1-bit full adder; a bit-serial × bit-parallel multiply takes b cycles on b AND gates + an adder area ∝ 1 (or b), time ∝ b → throughput per unit area roughly constant, but the wiring per connection is 1 wire, not b the payoff: time proportional to precisiona layer quantized to p bits instead of 16 runs 16/p times faster on the same bit-serial hardware (Stripes, Judd et al. 2016)

Early FPGA neurocomputers packed thousands of bit-serial processing elements onto chips that could not hold more than a few word-parallel multipliers, and the 1-wire-per-connection property also eases the routing problem of §12. The modern revival is precision-proportional accelerators: the same hardware runs an 8-bit layer twice as fast as a 16-bit one, so per-layer precision tuning pays off directly.

Stochastic computing

represent a number p ∈ [0, 1] as a random bitstream with P(bit = 1) = p (Gaines 1967)multiply: z = a AND b P(z = 1) = P(a = 1) · P(b = 1) = p₁ p₂ — if the streams are independent scaled add: z = MUX(a, b; select with P = ½) P(z = 1) = (p₁ + p₂)/2 bipolar code for x ∈ [−1, 1]: p = (x + 1)/2, multiply with XNOR the cost is time: the estimate after N bits is binomialRMS error = √( p(1 − p) / N ) halving the error costs 4× the cycles; b-bit accuracy needs N ~ 4ᵇ cycles

With the defaults (p₁ = 0.6, p₂ = 0.5, N = 256) the AND-gate estimate lands within a few hundredths of 0.3, and the green curve follows the dashed √(p(1−p)/N) law down the log-log plot: 4× more cycles for each halving of the error, crossing 8-bit binary accuracy only around N ≈ 1.6 × 10⁵. Now choose shared random sources: both streams are generated from the same random numbers, the 1s line up, and the AND gate computes min(p₁, p₂) = 0.5 instead of the product — and no amount of stream length fixes it. Decorrelation (independent random-number generators per input, or deterministic low-discrepancy sequences) is the central engineering problem of stochastic computing. Its virtues are real — tiny gates, graceful degradation under bit flips, natural fit to pulse-based and spiking signals — and it resurfaces whenever area or fault tolerance matters more than latency, but it has never been competitive for high-precision work.

Logarithmic and residue number systems

logarithmic number system (LNS): store L = log₂|x| and a signx · y ↔ Lₓ + L_y — a multiplier becomes an adder x + y ↔ max(Lₓ, L_y) + log₂(1 + 2^(−|Lₓ − L_y|)) — addition needs a function table: the price moves to the accumulator power-of-two weights, the degenerate casew = ±2^(−k) → w · x is a shift of x; networks quantized to powers of two lose surprisingly little accuracy (Miyashita et al. 2016) residue number system (RNS): represent x by its remainders modulo coprime m₁, m₂, …add and multiply digit-wise, carry-free and in parallel; converting back, comparing and dividing are expensive

Both exploit the fact that a neural network's arithmetic is mostly multiply and add, and that exact intermediate values rarely matter: a classifier only needs the final decision to be right, so an exotic representation need only be converted back at the very end — if at all.

15 Analog and neuromorphic hardware

The most literal answer to "a neuron is a weighted sum" is to let physics do the sum. In an analog crossbar the weights are conductances, the inputs are voltages, and Ohm's and Kirchhoff's laws compute a whole matrix–vector product in one step, in place, with no data movement at all.

an analog crossbar (in-memory computing)input voltages Vᵢ on the rows, conductances Gᵢⱼ at the crossings: column current Iⱼ = ∑ᵢ Gᵢⱼ Vᵢ the multiply is Ohm's law, the sum is Kirchhoff's current law, and the weights never move the catchdevice variation, noise, drift, and the DACs/ADCs at the edges → effective precision of roughly 4–8 bits, and converter energy that can dominate
  • Analog neurochips go back to the late 1980s — Mead's analog VLSI program and chips such as Intel's ETANN (1989), which stored weights as charge on floating gates. Modern versions use flash cells, phase-change memory or resistive memories (memristors) as the conductances. They are extremely efficient for inference on fixed weights, but writing weights precisely, training on chip and keeping calibration are hard.
  • Neuromorphic chips implement spiking neurons that communicate by discrete events, so energy is spent only when something happens. IBM's TrueNorth (2014) had a million spiking neurons and 256 million synapses on one chip and ran at tens of milliwatts; Intel's Loihi (2018) added on-chip learning rules; the SpiNNaker machine connects about a million ARM cores to simulate spiking networks in real time. They excel at sparse, event-driven sensory processing (event cameras, always-on audio) at very low power, but spiking networks remain harder to train to state-of-the-art accuracy than conventional ones.
  • The bridge to classical networks. Hopfield's 1984 continuous model was explicitly an analog circuit of amplifiers and resistors, and his energy-function analysis was partly motivated by building it; associative memories and Boltzmann-style samplers remain natural targets for analog and stochastic hardware.

16 Why GPUs and TPUs won the general case — and where FPGAs and ASICs live

For three decades, dedicated neurocomputers promised order-of-magnitude speed-ups, and almost none of them outperformed the best conventional computer of their own time. Then a device built for video games became the engine of deep learning. The reasons are economic and architectural in about equal measure.

Why the early neurocomputers lost

  • Volume beats specialisation. Mass-market processors improved much faster, generation over generation, than low-volume special-purpose chips; by the time a neurochip shipped, commodity hardware had closed the gap. Comparisons claiming big wins were often against an old PC running interpreted code.
  • Software lagged. A chip with a small user base never got the compilers, libraries and debuggers that make hardware usable.
  • Flexibility ended up re-inventing the FPGA. The variety of network types forced neurochips to be programmable, and a programmable array of configurable units is essentially an FPGA — without the FPGA's volume.
  • Amdahl and the serial parts (§04), and poor benchmarking (§13) did the rest.

Why GPUs and TPUs won

  • The workload converged on dense matrix products — exactly what a GPU's thousands of SIMD lanes do well. Deep learning's rise (the 2012 ImageNet result ran on two consumer GPUs) was partly a consequence of this fit.
  • Volume and a software ecosystem. Gaming paid for the silicon; CUDA (2007), cuDNN and then the major frameworks made the silicon usable by anyone writing Python.
  • Specialisation arrived inside the general-purpose chip. Tensor cores (2017 onward) are small matrix-multiply units, a systolic idea inside a GPU; FP16, BF16, FP8 and FP4 support brought the precision lessons of §05–§08 to the mainstream; high-bandwidth memory and fast interconnects moved the ridge of §03.
  • The TPU is the exception that proves the rule. It is an ASIC — a systolic array (§11) with a large on-chip buffer — and it succeeded because a single company's internal volume was large enough to amortise the design cost, and its workloads were stable matrix products. That is the condition under which custom silicon wins: a big, stable market.

The durable lesson. The hardware that wins is not the one that best mirrors the brain or the network diagram; it is the one that makes the dominant operation cheap per joule and per dollar, keeps data close to the arithmetic, and comes with software people can use. Everything on this page — fixed point, table-based sigmoids, systolic arrays, bit-serial PEs — survives in that form: as ideas inside mainstream accelerators, or as the right answer for a niche where latency, power or precision dominate. For how these ideas are applied when deploying models today, see Model Acceleration; for scaling training across many accelerators, see Distributed Training.

17 Takeaways and cheat sheet

  • Count first. MACs = ∑ nₗ₋₁nₗ for dense layers; energy is dominated by data movement (a DRAM read costs ~1000× an 8-bit MAC), so bytes and their location matter more than FLOPs.
  • Roofline: attainable = min(P, β·I). Batch-1 dense layers have I ≈ 1 FLOP/byte and are memory-bound everywhere; batching, tiling and quantizing weights move them right.
  • Fixed point Qm.n: m integer bits buy range, n fraction bits buy resolution; rounding error RMS = Δ/√12; each bit = 6 dB; always saturate, never wrap; always round, don't truncate; accumulate wide.
  • Training needs more than inference because updates below half an LSB vanish; fixes are wide master weights, stochastic rounding, loss scaling, and wide accumulators.
  • Activations: use symmetry; LUT error ∝ 1/N, PWL ∝ 1/N², balanced (minimax) PWL halves the chord error for free; low-order polynomial per segment is the general-purpose best; CORDIC is flexible but slow.
  • Dataflow: name the stationary operand; systolic arrays give n-fold reuse with neighbour-only wiring, 3n − 2 cycles for an n × n product.
  • FPGAs: DSPs × clock × packing sets the peak; LUT multipliers scale with b², so precision is parallelism; reconfigurable but slow to recompile; routing is the scarce resource.
  • Exotic arithmetic (bit-serial, stochastic, LNS, analog, spiking) trades time, precision or programmability for tiny, low-power operators; each lives on in a niche or inside mainstream designs.
  • History: volume, software and a convergent workload let GPUs and TPUs win the general case; FPGAs and small ASICs win on latency, power, custom precision and streaming data.
