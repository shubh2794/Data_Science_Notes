Convolutional Neural Networks

Images are grids where meaning is local and position-independent. A convolution bakes exactly those two facts into the architecture: a small filter, reused at every location. Everything else — depth, channels, pooling, residuals — is a way to turn that one operation into a hierarchy that reads edges at the bottom and objects at the top.

Deep Learning Vision Architectures Inductive bias

01 Why convolution for grids

A dense layer treats an image as an unordered bag of numbers. Convolution instead assumes three things about grid data — and those assumptions are what make vision learnable from limited data.

Three structural priors

  • Locality. A pixel is explained mostly by its neighbours — edges, corners and textures all live inside a few-pixel patch — so a unit needs only a small window, a sparse connection pattern instead of all-to-all.
  • Weight sharing. An edge detector useful in the top-left is useful in the bottom-right, so one kernel is reused at every position and the parameter count stops depending on image size.
  • Translation equivariance. Because the same filter runs everywhere, shifting the input shifts the output the same way: conv(shift(x)) = shift(conv(x)). Add pooling or global averaging on top and equivariance becomes approximate invariance — the classifier stops caring where the cat was.
equivariancef(Tδ x) = Tδ f(x) for any spatial shift Tδ

The parameter count that settles the argument

  • Flatten a 224×224×3 image and feed it to a dense layer of 1000 units: ≈150 million weights in a single layer, and none of them transfer between locations.
  • A 3×3 convolution mapping 3 input channels to 64 output channels: 1,792 weights, applied at all 50,176 positions. Five orders of magnitude fewer parameters, and each one is trained by every patch of every image.
  • The compute does not vanish, it moves: FLOPs stay proportional to H·W because the kernel runs at every pixel. CNNs are parameter-cheap and compute-hungry — the opposite profile to a big dense head.
dense vs conv on a 224×224×3 inputdense → 1000 units: 224·224·3 · 1000 ≈ 1.5 × 10⁸ weights conv 3×3, 3 → 64 ch: 3·3·3·64 + 64 = 1,792 weights
Takeaway: a convolution is a dense layer with two constraints imposed — most weights forced to zero (locality) and the rest tied together (sharing). Constraints are free knowledge: the network no longer has to learn that images are grids.

02 The convolution operation

Slide a small weight matrix over the input, take a dot product at every stop, write the result into a feature map. That is the whole primitive.

Cross-correlation, honestly

  • Textbook convolution flips the kernel before sliding: (x ∗ w)[m,n] = ∑ᵢ ∑ⱼ x[m−i, n−j] · w[i,j]. Every deep-learning library skips the flip and computes cross-correlation instead.
  • It makes no difference: the kernel is learned, so the network simply learns the flipped filter. The name stuck, the flip did not.
  • A layer with Cout filters produces Cout feature maps stacked along a new channel axis. Each filter spans all input channels — a 3×3 filter on a 64-channel input is really a 3×3×64 tensor.
one conv layer, stride sy[m, n, o] = b[o] + ∑c ∑i ∑j x[m·s + i, n·s + j, c] · w[i, j, c, o] shapesx : H × W × Cin w : k × k × Cin × Cout y : H′ × W′ × Cout
  • Read the index carefully: the sums over i, j are the patch, the sum over c mixes channels, and o selects which filter. Locality lives in the first two, and the third is an ordinary linear map.
  • In practice it runs as a matrix multiply — patches unrolled into columns (im2col) or fused kernels — which is why convolutions suit GPUs so well.

Takeaway: a feature map answers one question — "how strongly does this pattern appear here?" — at every location at once. Stacking filters asks many questions in parallel; stacking layers asks questions about the answers.

03 Shape arithmetic: stride, padding, dilation

Four hyperparameters decide the geometry of a conv layer — and getting shapes wrong is the single most common bug in vision code.

The output-size formula

  • Kernel size k — how wide the window is. Odd sizes (3, 5, 7) are preferred so the window has a centre pixel.
  • Stride s — how far the window jumps. s = 2 halves the resolution and is the standard way to downsample inside the network.
  • Padding p — rings of (usually zero) pixels around the border, so edge pixels are visited as often as interior ones and the size can be preserved. Reflect/replicate padding avoids the dark-border artifact zeros introduce.
  • Dilation d — insert d − 1 gaps between kernel taps. The filter covers a larger area with the same parameter count, which is how segmentation models keep resolution while still seeing context.
per spatial axiskeff = d·(k − 1) + 1 o = ⌊ (i + 2p − keff) / s ⌋ + 1 "same" padding (needs s = 1)p = (keff − 1) / 2 ⟹ o = i

Receptive field: what a unit can actually see

  • The receptive field of a unit is the region of the original image that can influence it. It starts at one pixel and grows with depth — this is the quantity that decides whether your network can even perceive a large object.
  • Track two numbers per layer: the receptive field r and the jump j (the input-pixel spacing between adjacent units, i.e. the product of all strides so far).
  • Two stacked 3×3 convolutions see 5×5; three see 7×7 — with 2·(3·3·C²) weights instead of 5·5·C², plus an extra non-linearity. That trade is the entire design of the VGG family.
  • Strides and dilation grow the receptive field far faster than kernel size does, because they multiply the jump rather than adding to the window.
receptive field growthr0 = 1, j0 = 1 rℓ = rℓ−1 + (keff,ℓ − 1) · jℓ−1 jℓ = jℓ−1 · sℓ

Takeaway: compute the receptive field before you debug the loss. If the theoretical receptive field of your last conv layer is smaller than the objects you care about, no amount of training will fix it.

04 Feature maps, channels, and 1×1 convolutions

Spatial size shrinks as you go deeper; channel count grows. The network is trading where for what.

The channel axis is the feature axis

  • Read a H × W × C tensor as: at each of H·W locations, a C-dimensional descriptor of what is there. Early layers have many locations and few generic features; late layers, few locations and many specific ones.
  • A typical backbone follows a doubling rule — each time stride halves the resolution, the channel count doubles, keeping the per-layer compute roughly constant.
  • Parameters and FLOPs both scale with the product of channel counts, so widening a layer is quadratically expensive.
cost of one conv layerparams = k² · Cin · Cout + Cout FLOPs ≈ 2 · k² · Cin · Cout · Hout · Wout

The 1×1 convolution

  • With k = 1 there is no spatial mixing at all — it is a learned linear map applied to the channel vector at every pixel independently, i.e. a shared dense layer over the feature axis.
  • Uses: bottlenecks (256 → 64 channels, do the expensive 3×3 there, expand back — the ResNet block); channel mixing after a depthwise conv; cheap projection to match shapes on a skip path.
  • It is astonishingly cheap relative to its effect: no spatial extent, so the k² factor disappears from both params and FLOPs.
1×1 convolutiony[m, n, o] = ∑c x[m, n, c] · w[c, o] + b[o] — a per-pixel matrix multiply
Takeaway: think of a conv layer as two jobs — spatial mixing (the k×k extent) and channel mixing (the Cin → Cout map). Nearly every efficiency trick in the field comes from separating them.

05 Cheaper convolutions: grouped, depthwise-separable, 1-D and 3-D

Once you see spatial and channel mixing as separable jobs, you can factorise the layer and pay a fraction of the cost for almost the same function.

Grouped convolution

  • Split the channels into g groups and convolve each group independently. Params and FLOPs both drop by a factor of g, at the cost of no cross-group communication (usually restored by a following 1×1).
  • Originally a workaround for splitting a model across two GPUs; later a deliberate knob — grouped 3×3 convs with many parallel paths are the core of the ResNeXt-style block.

Depthwise-separable convolution

  • Take grouping to its limit: g = Cin, one k×k filter per channel (the depthwise step), then a 1×1 pointwise conv to mix channels.
  • The factorisation cuts cost by roughly k² — about 8–9× for 3×3 kernels — for a small accuracy loss, which is why it underpins the mobile-oriented families.
  • Depthwise convs are bandwidth-bound rather than compute-bound, so the wall-clock speedup is smaller than the FLOP ratio suggests.
multiply–adds per layerstandard: k² · Cin · Cout · H · W depthwise + pointwise: k² · Cin · H · W + Cin · Cout · H · W ratio1/Cout + 1/k² ≈ 1/9 (k = 3, Cout large)

Other dimensionalities

  • 1-D convolutions slide over a single axis — raw audio, sensor streams, time series, and character/token sequences. Stacked dilated 1-D convs give an exponentially growing receptive field, the classic alternative to a recurrent model; causal padding (pad only on the left) keeps them autoregressive.
  • 3-D convolutions add a third axis for video (height, width, time) or volumetric scans. Cost grows with k³, so video models often factorise into a 2-D spatial conv followed by a 1-D temporal conv.
  • The maths is identical in every case; only the number of summed spatial indices changes.

Takeaway: a dense k×k conv couples every input channel to every output channel at every offset. Almost all of that coupling is redundant — factorising it is the cheapest accuracy-per-FLOP win in CNN design.

06 Downsampling: pooling, strided conv, global average pooling

Something has to shrink the spatial grid, or the network stays expensive and its receptive field stays small. There are three ways to do it, and they differ in what they throw away.

Max vs average pooling

  • Max pooling keeps the strongest response in each window: "was this feature present anywhere nearby?" It is parameter-free, gives small-shift tolerance, and routes gradient only to the winning cell.
  • Average pooling keeps the mean: smoother, retains overall intensity, spreads gradient over the whole window. Better when the aggregate matters more than the peak.
  • Strided convolution downsamples with learned weights and is what most modern backbones use instead of a pooling layer — one operation does feature extraction and subsampling together.
  • All three alias: subsampling without a low-pass filter makes predictions oddly sensitive to a one-pixel shift, which blur-then-subsample variants largely fix.
2×2 pooling windowmax: y[m,n] = maxi,j ∈ {0,1} x[2m+i, 2n+j] avg: y[m,n] = ¼ ∑i,j x[2m+i, 2n+j]
Max pool vs average pool vs strided conv same 6×6 input, same 2× downsample — three different answers

Global average pooling

  • At the very end, collapse each feature map to a single number: H × W × C → 1 × 1 × C. That vector goes straight into the classifier.
  • This replaced the huge flattened fully-connected head of early networks (the bulk of VGG's ~138M parameters), acts as a structural regulariser, and makes the network accept any input resolution.
  • Each channel then reads roughly as "is this feature present somewhere?" — the basis of class-activation maps.
global average poolingzc = (1 / H·W) ∑m ∑n x[m, n, c]
Takeaway: downsampling buys receptive field and compute at the price of spatial precision. Classification loves it; segmentation and detection have to claw the resolution back (§10).

07 The canonical block: conv → norm → activation

You almost never write a bare convolution. The unit of construction is a three-part block, repeated with mechanical regularity.

  • Conv produces the linear response; its bias is usually omitted because the normalisation layer immediately re-centres the output anyway.
  • Normalisation rescales activations to a stable distribution — larger learning rates, less sensitivity to initialisation, mild regularising noise from batch statistics.
  • Activation supplies the non-linearity — ReLU historically, GELU or SiLU in recent designs.
  • Batch normalization standardises each channel over the batch and spatial positions, then re-scales with learned γ, β. At inference it switches to running averages, so it becomes a fixed affine map that can be folded into the preceding conv for free.
  • Its weakness is the batch: with small or heterogeneous batches the statistics get noisy, which is why detection and segmentation models often swap in GroupNorm or LayerNorm (both batch-independent).
batch normalization, per channelx̂ = (x − μB) / √(σB² + ε) y = γ · x̂ + β statistics over batch and spaceμB = mean over (N, H, W) for each channel
Takeaway: the block, not the layer, is the design unit. Change the ordering (pre-activation), the norm, or the activation and you get most of the "new" CNN blocks of the last decade. More in Neural Network Training.

08 The architecture lineage

Each famous backbone contributed roughly one reusable idea. Read the list as a sequence of answers to "what is stopping us from going deeper or cheaper?"

The residual connection, in one line

  • A block computes y = x + F(x) instead of y = F(x). The identity path gives gradients an unobstructed route back to early layers, so depth stops degrading training.
  • Consequences: the block only has to learn a residual correction; the network behaves like an ensemble of many shorter paths; and the same trick reappears in every transformer. Full treatment in Residual / Skip Connections.
residual blocky = x + F(x; W) ∂y/∂x = I + ∂F/∂x — the identity term keeps the gradient alive
Takeaway: the lineage is not a list of models to memorise but a list of mechanisms — bottleneck, skip, separable, multi-scale, compound scaling — that you will recombine in any architecture you design. See also DL Architectures Compared.

09 What CNNs actually learn

The hierarchy is not wishful thinking — it is visible. Probe a trained network layer by layer and the same progression shows up across datasets and architectures.

  • Layer 1 learns oriented edges, colour blobs and frequency-selective filters that look strikingly like classical Gabor filters — and like the early stages of biological vision.
  • Early-middle layers combine edges into corners, curves and repeated textures.
  • Late-middle layers respond to object parts — wheels, eyes, text-like patterns.
  • Final layers respond to whole objects and configurations, and are the features you keep when transferring to a new task.
  • An important caveat: networks trained on standard image datasets lean more on texture than on shape. Augmentation choices can shift that bias, and it explains a chunk of the brittleness under distribution shift.

Ways to look inside

  • Filter visualisation — plot the first-layer kernels directly; only interpretable at layer 1, where the inputs are pixels.
  • Activation maximisation — optimise an input image to maximally excite one unit, regularised to stay image-like.
  • Dataset examples — collect the patches that most strongly activate a unit; cheapest, and often the most convincing.
  • Occlusion and gradient attribution — slide a grey square over the image, or backpropagate to the input, to see which pixels the prediction depends on. Class-activation maps give a coarse spatial explanation from the last feature maps.
Takeaway: the same hierarchy that makes CNNs work makes them transferable — early layers are nearly task-agnostic, which is exactly why fine-tuning a pretrained backbone beats training from scratch on small datasets.

10 Beyond classification: detection and segmentation heads

Classification collapses the grid to one label. Detection and segmentation must keep — or rebuild — spatial resolution, which changes what sits on top of the backbone.

Fully convolutional thinking

  • Replace the flattened dense head with 1×1 convs and the network outputs a map of predictions rather than one vector — a per-location classifier evaluated everywhere in a single pass, instead of a sliding window re-run per crop.
  • Detection heads predict a class score plus a box offset at every location of one or more feature maps. Two-stage designs propose regions then refine them; single-stage designs predict straight from the grid. Feature pyramids fuse coarse-deep with fine-shallow maps so small objects survive.
  • Semantic segmentation needs a full-resolution label map, so the decoder has to undo the downsampling.

Getting resolution back

  • Transposed convolution (sometimes called deconvolution, which it is not) spreads each input value over a k×k output patch with learned weights — the gradient of a strided convolution, run forwards.
  • Checkerboard artifacts appear when the kernel size is not divisible by the stride, so output pixels receive uneven numbers of contributions. Fixes: choose k divisible by s, or simply upsample then convolve (nearest/bilinear resize + 3×3 conv), which most modern decoders do.
  • Dilated convolutions offer the alternative: never downsample past a certain point, and grow the receptive field with dilation instead — expensive in memory, but no information is destroyed.
  • The U-Net pattern is the workhorse: a contracting encoder, an expanding decoder, and skip connections that concatenate each encoder feature map into the matching decoder stage. The decoder gets semantics from below and precise boundaries from the skip.
transposed conv output sizeo = (i − 1)·s − 2p + k (+ output padding) artifact-free rule of thumbk mod s = 0, or resize → conv
Takeaway: classification, detection and segmentation share the same backbone; they differ in how much spatial detail the head demands and therefore how the resolution is restored.

11 CNNs vs Vision Transformers, and practical notes

The honest summary: CNNs bring assumptions, transformers bring data. Which wins depends almost entirely on how much data you have.

AxisCNNVision Transformer
Inductive biasLocality, weight sharing, translation equivariance — built inAlmost none beyond patch splitting; must be learned
Small/medium dataStrong; trains well from scratchWeak unless heavily pretrained, augmented and regularised
Very large dataGood, saturates soonerScales better; benefits keep coming
Receptive fieldGrows layer by layer; local early onGlobal from the first block
Cost vs resolutionLinear in pixelsQuadratic in token count (self-attention)
Changing input sizeTrivial (with global pooling)Needs positional-embedding interpolation
Typical recipeShort schedules, light augmentationLong schedules, strong augmentation, pretraining
  • The convergence is real from both directions: transformers adopt convolutional stems, hierarchical stages and windowed (local) attention, while modernised convnets adopt large kernels, LayerNorm and inverted bottlenecks. At equal compute and data, the gap is small. See Vision Transformers.
  • CNNs remain the default when latency, memory or data are tight — edge deployment, medical imaging, industrial inspection — precisely because their priors substitute for data.

Practical tips and pitfalls

  • Augment aggressively. Random crops and flips exploit the very invariances the architecture assumes; colour jitter, RandAugment-style policies, mixup and cutmix supply the rest.
  • Start from a pretrained backbone. On a few thousand images, fine-tuning beats training from scratch by a wide margin — freeze early layers, use a lower learning rate for the backbone than the head. See Fine-Tuning & Transfer Learning.
  • Check the receptive field. Too small and the model literally cannot see the object; add stride, dilation or depth rather than more filters.
  • Watch batch norm. Tiny batches make its statistics unreliable — switch to GroupNorm.
  • Mind the borders and the aliasing. Zero padding teaches the network a dark frame it can use as a position cue; strided downsampling without blurring makes predictions jitter under one-pixel shifts.
  • Avoid checkerboards in any decoder — prefer resize-then-convolve upsampling.
  • Normalise inputs with the statistics the pretrained weights expect, and keep that preprocessing at inference — a silent mismatch is a classic accuracy leak.
Takeaway: convolution is not a legacy technique — it is the cheapest correct prior for grid data. Reach for a transformer when you have the data to replace that prior, and for a CNN when you do not.
