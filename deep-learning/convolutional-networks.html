Convolutional Networks

Part 1 built the function class and part 2 built the machinery that fits it. Both are architecture-neutral: they know nothing about what the input coordinates mean. This page is the first architecture, and it is the cleanest example in the whole series of a simple idea — put a hard constraint on the weight matrix and the constraint becomes knowledge. A convolution layer is a dense layer whose matrix is forced to be banded (each output sees a small window) and tied (the same weights are reused at every position). Nothing else changes: the same forward pass, the same loss, the same backward pass, the same optimiser. What changes is that the layer now assumes the input lives on a grid, and that assumption is worth several orders of magnitude of parameters and a great deal of sample efficiency — right up to the point where it is false.

Every number on this page was recomputed against an independent implementation before it was printed: every shape, every parameter and multiply-accumulate count, every receptive field (measured by perturbing one input pixel, not just by applying the formula), and the backward pass (audited against central differences). Where a common presentation gets an arithmetic detail wrong, the page teaches the discrepancy rather than repeating it.

01 What a convolution layer is, and the conventions this page never departs from

One sentence, and then the rest of the page is that sentence in detail: a convolution layer is an affine map, exactly like part 1's dense layer, whose weight matrix is constrained to be banded and tied. Banded means an output unit sees only a small contiguous window of the input. Tied means every output unit uses the same window of weights, just slid to a different place. Both constraints are hard — the forbidden weights are not penalised toward zero, they do not exist.

the layer, in the form part 1 would recognisedense layer Z = X W + b W is (dᵢₙ × dₒᵤₜ), dense and free conv layer Z = X W_c + b W_c is (dᵢₙ × dₒᵤₜ) too — but almost every entry is FORCED to zero, and the surviving entries are FORCED into groups that must be equal. what survives, for a single-channel f × f kernel on an H × W imagefree parameters f·f + 1 (the kernel and one bias) matrix entries (H′·W′) · (H·W) (the same layer written out dense) for f = 3, H = W = 224: 10 parameters, and 2 517 630 976 matrix entries.

That ratio — ten numbers standing in for two and a half billion — is the whole story, and §02 and §03 make it precise. Everything after that is bookkeeping: how the window is placed (§08), how channels stack (§10), what it costs (§12), how far each output can see (§14), what to do when the plain version is too expensive (§20–§22), and how the gradient flows back through it (§25).

The tensor layout, declared once

This is the exact place where a series forks its conventions and never notices. Part 1 declared the row convention for 2-D: a batch X is (N × d), one example per row, and a layer is X·W + b with W of shape (dᵢₙ × dₒᵤₜ). This page extends it in the only way that keeps the batch axis first and the feature axis next to it:

the layout law of this page — NCHWactivations (N, C, H, W) batch · channel · row · column kernels (Cₒᵤₜ, Cᵢₙ/g, fₕ, f_w) one 3-D filter per OUTPUT channel bias (Cₒᵤₜ) one scalar per output channel, shared over all positions why this one, and not the other oneRow convention says: batch first, then the features. NCHW is exactly that, with the single feature axis d expanded into the three axes (C, H, W), so d = C·H·W and the flatten at the end of a convnet is literally the identity map onto part 1's (N × d). Most teaching material — and this page's own source deck — quotes shapes the OTHER way round, as 6×6×3 or 28×28×192, which is HWC. Same tensor, axes written in the reverse order. Where this page quotes a shape in that style it says so; the ARITHMETIC is always NCHW. the one place the two layouts genuinely differA 1×1 convolution IS a dense layer applied at every pixel independently: reshape the activation to the (N·H·W × Cᵢₙ) matrix of pixel vectors, one pixel per ROW, and the layer is X·W with W of shape (Cᵢₙ × Cₒᵤₜ) — part 1's dense layer, unchanged. That reshape is FREE in NHWC and a transpose in NCHW. It is a memory fact, not a mathematical one, and §16 uses it.
Two more conventions, so no figure has to restate them.
  • Cost is counted in MACs — multiply–accumulates, one per multiply-and-add pair — matching DL.macs from part 1 §10 and part 2 §01. Papers that quote "FLOPs" usually mean MACs, and papers that mean literal floating-point operations quote twice this number. Both figures appear in the literature for the same network. Every count here is a MAC count and every figure says so.
  • Sizes are per example. The batch axis N multiplies every activation count and no parameter count. That asymmetry is the entire content of part 2 §26 and it does not change here.

Two habits that prevent most of the above

habit 1
Print the shape table, once, and read it
Every layer's input shape, output shape, parameter count and whether its division was exact. It takes ten seconds and catches traps 1, 3 and 4 immediately. §13's figure is that table; the point is to have the real one for your own model.
habit 2
Look at the first-layer filters after training
They should be oriented edges and colour blobs (§27). If they are noise, the learning rate or the initialisation is wrong; if many are uniformly grey, those units are dead (part 2 §11). A five-second visual check that catches problems a loss curve hides for hours.

36 What to remember

the one idea
A constrained dense layer
Banded (each output sees a window) and tied (the same weights everywhere). Nothing else about the layer changes — same forward pass, same loss, same optimiser. The constraint is the prior knowledge, expressed as a hard limit rather than a penalty.
the three motivations
Sparse, shared, equivariant
Sparsity takes m·n parameters to k·n. Sharing takes k·n to k and buys the sample efficiency. Equivariance is what makes sharing legitimate. They are three separate things.
the one formula
⌊(n + p₀ + p₁ − fₑ)/s⌋ + 1
With fₑ = d(f−1)+1. Every shape on this page comes from it, and every off-by-one bug in §09 is the floor or the padding split.
the three counts
They move differently
Parameters do not contain H or W. MACs are parameters × H′W′. Activations are N·Cₒᵤₜ·H′W′ and contain no parameters. Never reason about one from another.
the growth rule
Depth adds, downsampling multiplies
rₗ = rₗ₋₁ + (fₑ−1)·jₗ₋₁ with jₗ = jₗ₋₁·sₗ. Stride-1 stacking is far too slow; downsampling makes the growth geometric; dilation does the same without losing resolution.
and the caveat on it
Effective ≠ theoretical
The influence profile is Gaussian and its width grows like √L while the theoretical field grows like L. Quoting a 212-pixel receptive field says much less than it appears to.
the two complementary primitives
1×1 and depthwise
A 1×1 mixes channels and not space; a depthwise mixes space and not channels. Every efficient architecture alternates them, and the cost ratio 1/Cₒᵤₜ + 1/f² is why.
the distinction that matters most
Equivariance is not invariance
Equivariance preserves information; invariance destroys it. Convolution is equivariant, global pooling is invariant, strided max pooling is neither cleanly. Choose invariance once, at the end, and only if the task wants it.
the calculus
The flip is forced
Forward is a correlation. ∂L/∂K is a valid correlation of the input with the output gradient; ∂L/∂V is a full convolution of the output gradient with the kernel. Verified to 2.86e−09 against central differences across eight geometries.
the execution
It is one matrix product
im2col turns the layer into P·W — part 1's X·W with pixels as the batch — at the price of about f² memory. The MAC count falls straight out of the matrix shapes.
the critique to take seriously
Pooling discards arrangement
A 2×2 max pool throws away two bits of position per channel per window, at every stage. The prediction — right parts in the wrong places still classify as the object — is testable and largely holds. Modern practice has quietly conceded much of this.
the comparison
It is about the prior, not the operation
A patch embedding is a convolution and an MLP block is two 1×1 convolutions. The real difference is a strong fixed local prior against a weak dynamic global one, and which wins is a question about how much data you have.

The mistakes that cost the most

  • Not printing the shape table. Traps 1, 3 and 4 in §09 are all visible in it in ten seconds and invisible in a loss curve for days.
  • Reasoning about speed from a parameter count. Early layers are cheap in parameters and expensive in arithmetic; late layers are the reverse; and a depthwise layer is cheap in both and slow anyway (§12, §21).
  • Comparing a "GFLOPs" figure to a "MACs" figure. They differ by exactly two and both are called FLOPs in print (§12).
  • Believing max pooling gives translation invariance. A one-pixel shift changes over 90% of a stride-2 max pool's outputs on §18's test map. It gives a partial reduction in sensitivity, not invariance.
  • Leaving the bias on a convolution that is followed by a normalisation layer. Not harmful, but inert, and it makes the parameter count disagree with the reference implementation (§24).
  • Using a stride-2 transposed convolution with a 3×3 kernel and then wondering about the checkerboard. The overlap counts are 2, 1, 2, 1 and no amount of training fixes a geometric fact (§23).
  • Adding depth to fix a context problem. The effective field grows like √L; dilation or attention is the fix, not more 3×3 layers (§15, §22).
  • Assuming grouped or depthwise layers make the model faster in proportion to their MAC saving. Measure the wall clock (§20, §21).
  • Forgetting evaluation mode. Still the single most expensive one-line bug in the field (part 2 §29).
  • Taking the "edges, parts, objects" story literally. The first layer is reliable; the rest is partly a selection effect, and the network is more texture-driven than the story suggests (§27).
