29 Locally connected and tiled layers: when not to share

§06 argued for parameter sharing. The argument has a precondition — that the same feature is worth detecting everywhere — and when the precondition fails, so does the layer. Two architectures relax the sharing by different amounts.

layerparameterswhat it assumeswhere it is right
convolutionalkThe same feature is worth detecting at every position.Almost always, for natural images taken in an uncontrolled frame.

Combined with max pooling over the t variants, the pooled unit can become invariant to whatever transformation the t kernels differ by — which is how a pooling unit learns invariance to something other than translation.
locally connected
(unshared convolution)		k · nOnly that features are local. Every position gets its own weights.When the input is registered — cropped and aligned so that a given position always means the same thing. Aligned faces are the canonical case: the region that should look for eyebrows is always in the same place, so there is nothing to gain from sharing and something to gain from specialising.

Z[cₒ][p][q] = ∑ V[c][i][j] · W[cₒ][p][q][c][m][n] ↑↑↑↑ a 6-D tensor: the weight depends on WHERE the output is. Same connectivity. Same arithmetic, O(k·n) either way. H′W′ times the parameters, and no translation equivariance at all.

A dense layer, a locally connected layer and a convolution therefore form a ladder of decreasing freedom: all connections and all weights free, local connections and all weights free, local connections and weights tied. Each rung down is a stronger prior. Modern practice sits almost entirely on the bottom rung, with one notable exception: vision transformers reintroduce position-dependence through learned positional embeddings added to the input rather than through position-dependent weights — a much cheaper way to let the model know where it is looking. The figure in §05 already draws the ladder; this section names what each rung assumes.

The practical version of this section. If your data is registered — medical scans in a standard orientation, aligned faces, document images with a fixed layout, board positions in a game — then the translation-equivariance prior is partly wasted, and you have three options: add positional information to the input, relax to a locally connected layer, or use an architecture with a weaker positional prior. If your data is not registered, the convolutional prior is close to free accuracy and you should take it.

30 The critique: what pooling throws away, and the viewpoint problem

Everything up to here has been description. This section is the strongest sustained argument against the design, made from inside the field, and it is worth taking seriously whether or not you accept its proposed fix. The charge sheet has four counts.

What the critique concedes

local feature detectors — correct·replicated across the image — correct·receptive fields growing with depth — correctbutinterleaving them with pooling — wrong

Count 1 — pooling solves the wrong problem

This is the central charge, and §18 has already stated the distinction it turns on. Pooling is designed to produce invariance to small translations. But the invariance we ultimately want is only in the final label. Discarding position throughout the network, a little at a time, destroys the spatial relationships between parts that a later layer would need to check whether the parts are in a plausible configuration. The claim: what you want at every intermediate layer is equivariance — the representation should change in a predictable way with viewpoint, not be blind to it — and invariance should be applied once, at the end, if at all.

Note how much of modern practice has quietly conceded this: max-pooling layers have largely been replaced by strided convolutions and, in the most recent designs, by very few downsampling stages with a single global pool at the end. That is not the same argument arriving at the same conclusion, but it is not unrelated.

Count 2 — the network has no notion of pose

The framing is that vision is inverse graphics. A renderer takes a scene — objects, and a pose matrix for each — and produces pixels. Vision should recover the objects and their poses. In computer graphics the relationship between a whole and its part is a transformation matrix that is viewpoint invariant: the matrix relating a face to its nose is the same whichever way the face is turned. A convolutional network represents none of this. It has activations that say "a nose is present here, strongly", and no representation of the nose's orientation, scale or position relative to the face.

The practical consequence is the one everybody has met: a convnet extrapolates badly to unseen viewpoints, and the standard fix is to show it every viewpoint. That is what augmentation is (part 2 §35) and it is expensive in data. A representation that carried pose explicitly would generalise across viewpoints from far fewer examples.

Count 3 — the parts are detected but their arrangement is not checked

This is the sharpest and most testable count. A network built out of "is feature X present in this region?" detectors, aggregated by pooling, has weak machinery for asking "are these features in the right relative positions?". The prediction: an image with the right parts in the wrong places should still be classified confidently as the object. This is easy to test and it largely holds — scramble a face's features within the frame and a classifier's confidence often stays high. §17's figure already measured the mechanism: a 2×2 max pool discards two bits of within-window position per channel per window, and does it at every stage.

Count 4 — pooling is a crude routing decision

Read max pooling as a routing operation: of the k² units in a window, it decides that exactly one gets to send its value onward, and the choice is made by a fixed rule — take the largest. That is routing without any consideration of what the receiving unit needs. A better scheme would send each lower-level unit's output to whichever higher-level unit is best placed to make use of it, decided dynamically per input. §31 is that scheme.

The arrangement test: right parts, wrong places both images contain exactly the same parts in the same quantities; the two feature vectors are compared, and the similarity after global pooling is the number the critique predicts will be high

31 Capsule networks: routing by agreement, and the loss that goes with it

§30 was the diagnosis. This is the proposed cure, and it is worth a section because it is the most fully worked-out alternative to the convolution-plus-pooling design that anyone has built. It lives here, inside this page's critique, because that is what it is — a critique of the CNN's design, not an independent architecture family with a literature to match. Reading it after §30 is the only way it makes sense.

What a capsule is

the single structural changeA NEURON outputs a SCALAR: "this feature is present, with strength a". A CAPSULE outputs a VECTOR: "this entity is present with probability ‖v‖, and its POSE is the direction of v." The length carries EXISTENCE and the orientation carries INSTANTIATION PARAMETERS — position, scale, rotation, thickness, skew. So the same entity seen from a new viewpoint produces a vector of the SAME LENGTH pointing in a DIFFERENT DIRECTION. That is equivariance, built into the representation rather than hoped for. the squash, which enforces the "length is a probability" reading ‖s‖² s squash(s) = ─────── · ───── 1 + ‖s‖² ‖s‖ ‖s‖ → 0 ⇒ ‖v‖ ≈ ‖s‖² short vectors are crushed toward 0 ‖s‖ → ∞ ⇒ ‖v‖ → 1 long vectors are capped just below 1 The DIRECTION is untouched — squash is a radial rescaling and nothing else. It is the vector analogue of a sigmoid, applied to the length alone.

Routing by agreement

This is the replacement for pooling. Each lower-level capsule i makes a prediction for what each higher-level capsule j should be, by applying a learned transformation matrix: û_{j|i} = W_{ij} u_i. Those matrices are the pose relationships of §30 — "given a nose in this pose, here is the face pose it implies". Then the higher-level capsule's output is a weighted average of the predictions made about it, and the weights are set by how well each prediction agrees with the emerging consensus:

the routing algorithm, in fullgiven predictions ûⱼ|ᵢ = Wᵢⱼ uᵢ for every lower capsule i and upper capsule j bᵢⱼ ← 0 for all i, j repeat r times: cᵢ ← softmax(bᵢ) over j — capsule i's routing weights sum to 1 sⱼ ← ∑ᵢ cᵢⱼ ûⱼ|ᵢ the weighted consensus for capsule j vⱼ ← squash(sⱼ) bᵢⱼ ← bᵢⱼ + ûⱼ|ᵢ · vⱼ AGREEMENT: a dot product return vⱼ read the last line — it is the whole ideaA prediction that points the same way as the consensus gets a large positive dot product, so its logit rises and its weight grows on the next iteration. A prediction that disagrees gets a small or negative dot product and is routed away. After a few iterations the capsules that agree have dominated the average and the ones that do not have been suppressed. CONTRAST WITH MAX POOLING, which is also a routing decision (§30, count 4): max pooling picks the LARGEST value in a window. The choice ignores what the receiving unit needs, and it is made once, statically. routing picks by AGREEMENT with the receiver's current estimate. The choice depends on the input, and is refined over r iterations. Note the softmax is over j, not i: each LOWER capsule distributes its output across the upper capsules, so it must decide where to send itself. It is a competition between PARENTS for a child, not between children for a parent. And r is small — 3 is the value that works; more iterations tend to overfit the routing and make the coefficients collapse to one-hot too early.

The loss: margin, plus reconstruction

margin loss, one term per class capsule kLₖ = Tₖ · max(0, m⁺ − ‖vₖ‖)² + λ(1 − Tₖ) · max(0, ‖vₖ‖ − m⁻)² Tₖ = 1 if class k IS PRESENT in the image, 0 otherwise m⁺ = 0.9 m⁻ = 0.1 λ = 0.5 total loss = ∑ₖ Lₖ Read it as two hinges. If the class is present, push ‖vₖ‖ ABOVE 0.9 and stop. If it is absent, push ‖vₖ‖ BELOW 0.1 and stop. Between 0.1 and 0.9 the absent-class term is zero and the present-class term is zero, so there is no gradient — the deliberate flat region is what stops the model from wasting capacity driving lengths to the extremes. why a margin loss and not a softmax cross-entropyBecause ‖vₖ‖ is meant to be an INDEPENDENT probability of the entity existing, not a share of a normalised total. A softmax would force the class capsules to compete for one unit of probability mass, which contradicts the design's intent that several entities can be present at once. λ = 0.5 down-weights the absent classes, of which there are K − 1, so early training is not dominated by pushing nine lengths to zero. the reconstruction regulariserTake the 16-D output vector of the CORRECT class capsule, mask the others to zero, and feed it to a small fully connected decoder (16·K → 512 → 1024 → 784) that must reproduce the input image. Add the squared reconstruction error, SCALED BY 0.0005, to the margin loss. The scale matters and is easy to get wrong: the raw reconstruction error is over 784 pixels and would otherwise dwarf the margin loss entirely.

Three arithmetic and definitional errors that circulate in secondary presentations of this material — all three found while checking this section against the source. Stated so you do not inherit them.
  • T_k = 1 when the class is present, not when it is predicted. Several summaries write "T_k = 1 when the correct label is predicted". That would make the target depend on the model's own output and remove the gradient that pushes a wrong prediction toward the right answer. T_k is the label, full stop.
  • The reconstruction loss is scaled by 0.0005, not 0.00005. A factor of ten. At the smaller value the reconstruction term is essentially switched off and the regularisation it is supposed to provide does not happen — and the network still trains, so nothing tells you.
  • A reported 5% error rate is a re-implementation's number, not the method's. The original result is 0.25% test error on digits with three routing iterations and reconstruction. A 5% figure — twenty times worse — indicates a training problem, and quoting it as the method's performance mis-states the evidence in both directions.

32 Why capsules did not displace convolutional networks — an honest assessment

The critique in §30 is largely correct. The architecture in §31 is a genuine attempt to fix it. It did not take over, and understanding why is more instructive than either dismissing it or over-selling it.

reason 1
The cost is quadratic in capsule count
DigitCaps needs one transformation matrix per (lower, upper) pair: 1 152 × 10 × 8 × 16 = 1 474 560 parameters for a two-layer routing step on 28×28 digits. Scale the lower layer to a real image's worth of capsules and the pairwise matrices dominate everything. Convolution's answer to this — share the transformation across positions — is available and reintroduces exactly the weight-tying the design was trying to escape.
reason 2
Routing is an inner loop that does not vectorise well
Three routing iterations mean three sequential passes over the coupling coefficients, each with a softmax and a dot product per pair, inside every forward pass. Convolution is one dense matrix product (§26) that runs at close to peak throughput. Reported wall-clock costs were an order of magnitude worse for comparable accuracy — and the hardware has moved further toward dense matrix products since, not away.
reason 3
It never scaled past small images
The compelling results were on digits and on small, controlled datasets. Attempts to scale to ImageNet-sized problems did not produce competitive numbers, and the number of researchers who tried was large. That is real evidence, though it is evidence about this instantiation of the idea rather than about the idea.
reason 4
The comparison was against a moving target
Over the same period, ordinary convnets absorbed better normalisation, better optimisers, far better augmentation, and eventually transformer-style blocks (§28). A four-point accuracy gain from a training recipe alone is larger than most architectural claims of the era. Capsules needed to beat a rapidly improving baseline with a much smaller research community behind them.

What survived, and where

The ideas did not vanish; they were absorbed, mostly without the name.

dynamic, input-dependent routing→attention, whose weights are computed from the data exactly as routing coefficients are
vector-valued units carrying pose→the multi-dimensional tokens of a transformer, and equivariant architectures with explicit group structure
equivariance over invariance→the modern preference for few downsampling stages and one global pool at the end, and for dense-prediction backbones that never pool at all

The sharpest way to put it: routing by agreement and attention are the same move — replace a fixed aggregation rule with one computed from the data — and attention won because it is a single matrix product with no inner loop, is trivially parallel, and turned out to need no pose machinery to be useful. Attention and Transformers are where that thread continues.

Why this material has no node of its own. Capsule networks are a critique of the convolutional design before they are an architecture, and they are best understood immediately after §30's charge sheet, by a reader who has just been shown exactly what pooling discards and has watched it measured. Splitting them onto a page of their own would separate the answer from the question and would give a line of work that did not scale the same weight in the graph as convolution itself. The honest place for them is here.

33 Convolutional networks against vision transformers: which prior, and when

The comparison is usually framed as "convolution versus attention". That framing is wrong twice over: the two architectures are more similar than they look, and the thing that actually differs is the strength of the prior, which is a statement about how much data you have.

How similar they really are

a vision transformer, translated into this page's vocabularypatch embedding = a CONVOLUTION with kernel = stride = the patch size. A 16×16 patch embedding on a 224×224 image is exactly conv(f = 16, s = 16), giving a 14×14 map of D channels. Not "like" a convolution — it IS one (§08's formula: (224 − 16)/16 + 1 = 14). the MLP block = two 1×1 CONVOLUTIONS with a non-linearity between them (§16). Identical operation, different name. the attention = the genuinely new part: a mixing matrix over positions that is COMPUTED FROM THE DATA rather than learned as a fixed kernel, and that is dense over all positions rather than banded. so the real difference is exactly one layer, and it is thisCONVOLUTION fixed, banded, tied mixing: the weights do not depend on the input, each output sees a small window, and the same weights are used everywhere. ATTENTION dynamic, dense, untied mixing: the weights ARE a function of the input, every position can see every other, and there is no tying at all — position information must be ADDED explicitly because there is none in the operation.

The trade, stated as a prior

convolutional networkvision transformer
the priorStrong. Locality and translation equivariance are hard constraints (§03, §06).Weak. Permutation equivariance over tokens, plus whatever the positional embedding supplies. Locality must be learned.
small dataWins, decisively. The prior is true, so it is free accuracy that would otherwise have to be paid for in examples.Underperforms badly when trained from scratch on a mid-size dataset — the classic result is several points below a comparable convnet.

and the twistRedesigning a convnet with a transformer's block shape — a large depthwise kernel as the token mixer, LayerNorm, GELU, an inverted bottleneck, a patchifying stem, and the same training recipe — closes the gap and often reverses it, at matched parameters and matched arithmetic. That is strong evidence that much of the reported advantage was block design and training recipe rather than attention.
The prior against the data: measured sample efficiency of a strong and a weak inductive bias both models are fitted, on the same data, by the same routine — whether the curves cross at all, and where, is a measurement, and it depends entirely on how true the strong model's assumption is
The decision rule, which is not "which is better". Ask instead: how much data do I have, and is locality true of it? Under roughly a million labelled examples and with images of natural scenes, a convolutional backbone is the right default and will train faster and more reliably. With hundreds of millions of examples, or with a large pretrained model available to fine-tune, the weaker prior wins. And if you are fine-tuning someone else's pretrained model — which is the common case (Fine-tuning & Transfer Learning) — the question is not architectural at all: it is which pretrained model is closest to your data. See Vision Transformers for the other side of this comparison and DL Architectures Compared for the map.

34 Convolution beyond images: 1-D, 3-D, and variable size

Nothing in §04–§12 mentioned images. Convolution applies to any input with a known grid topology — a set of coordinates where "nearby" means something and where a pattern can occur at more than one location. That covers considerably more than pictures.

dimensionssingle channelmulti-channel
1-DAn audio waveform. One axis, time, sampled at a fixed rate. Convolving over it makes the model equivariant to shifts in time.Skeleton or sensor data. One channel per joint angle or per sensor; the sliding axis is time and the channel axis is contracted at every step exactly as in §10.
2-DA spectrogram. Rows are frequency and columns are time. Convolving over time gives shift-equivariance in time; convolving over frequency gives equivariance to transposition, so the same melody an octave up produces the same representation at a different height. Those are two genuinely different design decisions and it is worth knowing which one you are making.A colour image. The case this page has assumed throughout.
3-DVolumetric data — medical scans. The kernel is (Cᵢₙ, f, f, f) and slides over three spatial axes. Cost grows as f³, so 3×3×3 is essentially the only kernel anyone uses.Video. One axis is time and two are space. Note the standard cheap factorisation, which is §21's idea in another guise: a (1, f, f) spatial convolution followed by an (f, 1, 1) temporal one, instead of a full (f, f, f).

Variable input size, which is a real and under-used advantage

A dense layer's weight matrix has a fixed shape, so an MLP simply cannot accept an input of a different size. A convolution can: the kernel is applied as many times as it fits, and the output grows or shrinks accordingly. The only obstacle is the classifier at the end, which needs a fixed-size vector — and there are three standard answers, all of which appear elsewhere on this page:

global pooling (§17)—one number per channel regardless of the map size; the simplest and now the default
adaptive pooling to a fixed grid—vary the pooling region size with the input so the count of regions is fixed, e.g. always a 3×3 grid of summaries
no classifier at all—emit one feature map per class and let the output be as variable as the input; this is what a segmentation network does (§23)
And the boundary of the idea. Convolution makes sense when a variable-size input contains varying amounts of the same kind of observation — more seconds of audio, more pixels of scene. It makes no sense when the input varies because it contains different kinds of observation. Sliding one kernel over a feature vector whose first three entries are exam grades and whose next two are test scores is meaningless: those coordinates have no adjacency relation, so the prior of §03 is simply false. That is the same test as part 1 §24's shuffle: if permuting the coordinates would not destroy anything, there was no grid to exploit. For genuinely irregular relational structure, the right generalisation is a graph neural network, where the neighbourhood is given explicitly rather than implied by a grid.
