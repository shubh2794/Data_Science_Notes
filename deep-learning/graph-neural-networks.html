Graph Neural Networks

Deep learning where the data has no grid and no order — only nodes and the edges between them. Every architecture on this page is one answer to a single question: how should a node listen to its neighbours?

01 Graphs as data

A graph is a set of entities plus a set of relations. That's a far weaker assumption than a grid or a sequence — and the weakness is exactly what forces a new architecture.

The objects

  • A graph is G = (V, E) with N = |V| nodes. Connectivity lives in the adjacency matrix A ∈ ℝN×N, where Aᵢⱼ ≠ 0 means an edge i → j. Undirected graphs give a symmetric A; directed graphs do not.
  • The degree matrix D is diagonal with dᵢ = ∑ⱼ Aᵢⱼ — how many neighbours node i has. It is the normalizer that appears in almost every layer below.
  • Signals ride on the structure: a node feature matrix X ∈ ℝN×F (one row per node), optional edge features eᵥᵤ (bond type, transaction amount, relation label), and sometimes a graph-level vector u.
  • Heterogeneous graphs carry typed nodes and typed edges (user / item / review · bought, rated). Each type usually gets its own transform, then results are pooled across relations — the pattern behind R-GCN and most knowledge-graph models.
  • In practice you almost never materialize a dense A: graphs are stored as an edge list (2 × |E| index tensor) and aggregation is a scatter-add, so cost is O(|E|), not O(N²).
the ingredientsG = (V, E) A ∈ ℝN×N D = diag(d₁, …, dN), dᵢ = ∑ⱼ Aᵢⱼ X ∈ ℝN×F

Why CNN and RNN assumptions break

  • A convolution assumes a fixed, ordered neighbourhood: the pixel above-left is always the same slot in the kernel. On a graph there is no "above-left", and node degree varies from 1 to millions — a fixed-size weight patch cannot even be written down.
  • An RNN assumes a canonical order. Nodes have none: relabelling them must not change the answer.
  • So the layer must be permutation equivariant — permute the input nodes and the output permutes identically — and any whole-graph prediction must be permutation invariant.
  • The only cheap way to guarantee that is to build the layer out of set functions: sum, mean, or max over a neighbourhood, which have no notion of order by construction.
the symmetry constraintequivariance: f(PAPᵀ, PX) = P · f(A, X) invariance: ρ( f(PAPᵀ, PX) ) = ρ( f(A, X) ) for every permutation matrix P
Takeaway: a CNN is a GNN on a grid whose neighbourhoods happen to be ordered and identical everywhere. Drop those two luxuries and you are forced into order-free neighbourhood aggregation — which is the graph neural network.

02 The message-passing framework

Nearly every GNN is the same three-step loop repeated L times: message, aggregate, update. The variants differ only in what you plug into those three slots.

The loop

  • Message ψ: for each edge, compute what the neighbour sends — a function of the sender, the receiver, and the edge feature.
  • Aggregate ⊕: collapse the incoming multiset into one vector with a permutation-invariant operator (sum, mean, max, attention-weighted sum).
  • Update φ: combine the node's own state with the aggregate — typically a linear map plus a nonlinearity, sometimes an MLP or a GRU cell.
  • Initialize with hᵥ⁽⁰⁾ = xᵥ. All nodes update in parallel from layer l to layer l+1; weights are shared across every node, which is what makes the model size independent of N.
one message-passing layermᵥ⁽ˡ⁾ = ⊕u ∈ N(v) ψ⁽ˡ⁾( hᵥ⁽ˡ⁾, hᵤ⁽ˡ⁾, eᵥᵤ ) hᵥ⁽ˡ⁺¹⁾ = φ⁽ˡ⁾( hᵥ⁽ˡ⁾, mᵥ⁽ˡ⁾ ) hᵥ⁽⁰⁾ = xᵥ

Depth = radius

  • After one layer a node knows its own features and its 1-hop neighbours. After L layers its state is a function of everything within L hops — the receptive field is the L-hop ball around the node.
  • This is the single most useful mental model on the page: depth is not capacity, depth is radius. If the signal you need lives 3 hops away, you need at least 3 layers. If it lives 1 hop away, more layers mostly add noise.
  • The receptive field grows roughly like d̄L for average degree d̄, so on a social graph 3 layers can already touch a large fraction of the network — this is the root of both the sampling problem (§08) and over-squashing (§09).

Takeaway: message passing is a learnable, order-free convolution whose kernel is "the neighbourhood". Choose ψ, ⊕, φ and you have named a specific architecture.

03 GCN — the normalized average

The simplest useful layer: transform every node, average over the neighbourhood including yourself, with a degree normalization that keeps activations from exploding at hubs.

The layer

  • Add self-loops so a node keeps its own signal: Ã = A + I, with D̃ the degree matrix of Ã. This pair is the renormalization trick.
  • Normalize symmetrically on both ends of the edge. A neighbour with huge degree contributes less, and a high-degree receiver is damped too — the eigenvalues of D̃−½ Ã D̃−½ lie in (−1, 1], so stacking layers does not blow up.
  • Everything is one sparse matrix product per layer: cheap, batch-free on small graphs, and trivially parallel.

Where the formula comes from

  • Spectral graph theory defines convolution through the graph Laplacian L = I − D−½ A D−½: diagonalize it, multiply in the eigenbasis, transform back. Exact but O(N³) and not localized.
  • Approximating the spectral filter by a truncated Chebyshev polynomial makes it local — a degree-K polynomial in L only mixes K-hop neighbours. Keeping just K = 1, tying the two coefficients, and applying the renormalization trick collapses the whole construction into the one-line layer above.
  • So GCN is a first-order spectral filter that turned out to be a spatial rule. That is why it needs no eigendecomposition and why the same weights transfer to graphs of different size.
Takeaway: the aggregation weights 1/√(d̃ᵥ d̃ᵤ) are fixed by the graph — no feature ever influences how much a neighbour counts. That single limitation is what GAT removes.

04 GraphSAGE — sample and aggregate

Built for graphs too big to fit in memory and for nodes that did not exist at training time. Two changes to GCN do it: sample the neighbourhood, and keep the self-vector separate.

The layer

  • Sample a fixed-size set S(v) ⊂ N(v) (a "fanout", e.g. 25 at layer 1 and 10 at layer 2), so per-node cost is bounded no matter how many neighbours a hub has.
  • Aggregate the sample, then concatenate the result with the node's own previous state before the linear map — unlike GCN, self and neighbours are not averaged into the same pot, so the layer can tell them apart.
  • ℓ₂-normalize the output of each layer; it stabilizes training and makes dot-product similarity meaningful downstream.
  • Aggregator choices: mean (close to GCN), max-pool (an MLP per neighbour, then element-wise max — good at "does any neighbour have property X?"), and an LSTM over a randomly permuted neighbour list (more expressive, but only permutation-invariant in expectation).

Inductive by design

  • Because the model learns aggregator weights rather than a lookup table of node vectors, a brand-new node gets an embedding from its features and neighbours in a single forward pass — no retraining. That is the difference between learning embeddings and learning a function that produces embeddings (see Embeddings).
  • Unsupervised training needs no labels at all: push connected nodes together, push random nodes apart — a contrastive objective on the graph.

Takeaway: sampling turns an inherently global computation into a bounded, mini-batchable one — the reason GraphSAGE-style layers dominate industrial graphs.

05 GAT — learned neighbour weights

Replace the fixed 1/√(d̃ᵥ d̃ᵤ) with a learned, feature-dependent coefficient. It is attention masked by the adjacency matrix.

Attention over a neighbourhood

  • Score each edge with a shared linear map W and a shared attention vector a, squashed by a LeakyReLU (negative slope 0.2) so scores stay signed and non-saturating.
  • Softmax over the neighbourhood only (self-loop included), not over all nodes — so the coefficients form a convex combination per node and remain cheap: O(|E|), never O(N²).
  • Multi-head: run K independent attentions and concatenate; each head can specialize (one on structural hubs, one on feature similarity). At the final layer average the heads instead of concatenating, so the output dimension matches the label space.
  • Dropout is usually applied to the attention coefficients themselves, which randomly removes edges each step and acts as strong regularization on small citation graphs.
  • A known wrinkle: in the original formulation the ranking of neighbours is the same for every query node — "static" attention. GATv2 fixes it by moving the nonlinearity before the attention vector, e = aᵀ LeakyReLU(W[hᵥ ‖ hᵤ]), restoring genuinely dynamic attention at the same cost.

06 GIN, edge features & expressiveness

How powerful can a message-passing network be? The answer is a precise one, and it changes which aggregator you should pick.

The Weisfeiler-Lehman ceiling

  • The 1-WL colour-refinement test decides whether two graphs might be isomorphic: repeatedly replace each node's colour by a hash of (own colour, multiset of neighbour colours) and compare the colour histograms.
  • That is structurally identical to message passing. The consequence: no message-passing GNN can distinguish two graphs that 1-WL cannot. It cannot count triangles, cannot tell a 6-cycle from two disjoint triangles, and is blind to many regular graphs.
  • A GNN reaches that ceiling only if both its aggregate and its update are injective on multisets. Mean loses multiplicity ({a, a, b} ≡ {a, b}); max loses everything but the distinct set. Sum keeps both.
GIN layer — sum aggregation + MLPhᵥ⁽ˡ⁺¹⁾ = MLP⁽ˡ⁾( (1 + ε⁽ˡ⁾) · hᵥ⁽ˡ⁾ + ∑u ∈ N(v) hᵤ⁽ˡ⁾ ) graph readout — every depth, concatenatedhG = ‖l = 0..L SUM( { hᵥ⁽ˡ⁾ : v ∈ V } )
  • ε (learned or fixed at 0) lets the layer weight the self term differently from the neighbours; the MLP supplies the universal function needed for injectivity.
  • Reading out every layer, not just the last, keeps both fine-grained and coarse structure — a small change that reliably helps graph classification.
  • To go beyond 1-WL you must add information message passing cannot see: subgraph counts, distance encodings, random node identifiers, or higher-order (k-WL) tensors — all more expensive.

Edge features: the general MPNN

  • Molecules make edges first-class (single / double / aromatic bond). The general MPNN message function takes the edge as an argument, often by having a small network generate the weight matrix from the edge feature.
  • Update can be recurrent (a GRU over layers, sharing weights), and readout can be a learned set function rather than a plain sum.

Takeaway: pick the aggregator by the question. Counting-style graph properties want sum; "what is the typical neighbour" wants mean; "does any neighbour do X" wants max; "which neighbours matter" wants attention.

07 Tasks, heads & readouts

The stack of message-passing layers is shared; what changes per task is the head that reads the final node states.

Node level

  • Node classification / regression: a linear layer on hᵥ⁽ᴸ⁾. Loss is computed on labelled nodes only via a boolean mask, even though the forward pass touches the whole graph.

Edge level

  • Link prediction: encode nodes, then decode pairs. The cheapest decoder is a dot product; typed relations get a diagonal or full relation matrix; anything richer is an MLP on [zᵤ ‖ zᵥ].
  • Train with negative sampling: real edges are positives, random non-edges are negatives, binary cross-entropy on the score. Removing the target edges from the message-passing graph is essential or the model simply reads the answer off the adjacency.
pairwise decodersscore(u, v) = zᵤ · zᵥ scorer(u, v) = zᵤᵀ Rr zᵥ Â = σ( Z Zᵀ ) lossL = − ∑(u,v) ∈ E log σ(score) − ∑(u,v') ∉ E log(1 − σ(score))

Graph level

  • Readout / pooling collapses N node vectors into one graph vector — and must be permutation invariant. Sum keeps size information, mean is size-normalized, max is a feature detector; concatenating sum and max is a common cheap default.
  • Hierarchical pooling coarsens instead: learn a soft cluster assignment and pool nodes into super-nodes (DiffPool), or keep the top-k nodes by a learned score. Useful when the graph has real hierarchy (functional groups, communities).

Transductive vs inductive

  • Transductive: one fixed graph, all nodes present at training, only labels are hidden. Classic citation-network benchmarks work this way; models may even learn per-node embeddings.
  • Inductive: test on nodes — or entire graphs — never seen during training. This demands that everything be a function of features and structure, and it is what real deployments almost always need.
Takeaway: encoder once, decoder per task. Most GNN bugs in link prediction are leakage bugs: the edge you are predicting must not be in the graph you are passing messages over.

08 Training in practice

Mini-batching is the hard part. In a GNN, examples are not independent — each node's loss depends on a neighbourhood that spreads with depth.

Full batch vs sampling

  • Full batch: on graphs up to a few hundred thousand nodes, run the whole graph on GPU each step. Exact gradients, but one gradient step per epoch and memory scales with N × F × L.
  • Neighbour sampling: for a batch of target nodes, sample a fanout per layer and build the induced computation graph (a "block" per layer). Bounded memory, unbiased-ish gradients, some variance. Without it, the neighbour explosion — d̄L nodes per target — makes 3 layers intractable on a dense graph.
  • Subgraph sampling: partition the graph into clusters and use whole clusters as batches (Cluster-GCN), or sample node/edge-induced subgraphs with normalization to remove the bias (GraphSAINT). No exponential blow-up because messages stay inside the subgraph.

Regularization & stability

  • Normalization matters more than in an MLP because degrees vary: layer norm per node is the safest default; batch norm works for graph-level tasks; PairNorm-style schemes explicitly fight feature collapse.
  • Dropout on hidden features, attention dropout on coefficients, and DropEdge — randomly deleting a fraction of edges every epoch, which both regularizes and slows over-smoothing by thinning the propagation.
  • Small benchmark graphs overfit almost instantly: weight decay, early stopping on a validation mask, and 2 layers are usually the whole recipe. See Neural Network Training for the general optimizer/schedule story.
Takeaway: the batch in a GNN is not a set of rows, it is a subgraph. Choose the sampler before you tune the model — it determines memory, variance, and how deep you can afford to go.

09 Over-smoothing, over-squashing & heterophily

GNNs stubbornly refuse to get deeper. Three distinct pathologies explain why — and each has its own fix.

Over-smoothing

  • Repeated normalized averaging is a diffusion process. Iterate it enough and every node's representation converges toward the same point (up to a degree-dependent scaling): the dominant eigenvector of the propagation matrix. Node identity is erased and classes become inseparable.
  • Diagnostic: track the spread of node features — pairwise distance, or the Dirichlet energy E(H) = ∑(u,v) ∈ E ‖hᵤ − hᵥ‖². It decays geometrically with depth.
  • Remedies: residual / skip connections (see Residual Connections), initial residuals that re-inject h⁽⁰⁾ at every layer plus identity mapping (GCNII), jumping knowledge (concatenate or max-pool all layer outputs so each node picks its own effective depth), DropEdge, and normalization that preserves feature variance.

Over-squashing

  • A node's L-hop ball can hold exponentially many nodes, yet its state is a fixed-size vector. Information from far away is compressed through bottleneck edges until the gradient signal is effectively zero — long-range dependencies simply cannot be learned.
  • It is a topology problem, not a depth problem: it concentrates on edges with negative discrete curvature (bridges between densely connected regions).
  • Remedies: graph rewiring (add or reweight edges to relieve bottlenecks), a virtual global node, multi-hop propagation, or replacing local passing with global attention (§10).

Heterophily

  • Standard GNNs assume homophily — neighbours share labels. Averaging then acts as a denoiser. On heterophilous graphs (fraud rings hiding among normal accounts, dating networks) averaging destroys the signal, and a plain MLP on node features can beat a GCN.
  • Remedies: keep the ego embedding separate from the neighbour embedding, use higher-order neighbourhoods (2-hop neighbours may be homophilous even when 1-hop is not), allow signed / negative aggregation weights, and learn a per-layer combination coefficient that can turn propagation off.
Takeaway: before adding layers, ask which problem you actually have. Need a bigger radius but features collapse → residuals + jumping knowledge. Need long-range signal through a bottleneck → rewiring or global attention. Neighbours disagree with you → stop averaging.

10 Graph transformers & the attention connection

A transformer is a GNN on a complete graph. Say that out loud and both families snap into one picture.

  • Self-attention lets every token attend to every other — that is aggregation over a fully connected graph, with the sequence order supplied externally by positional encodings. A GNN is the same computation masked by the adjacency matrix, with structure supplied by the mask instead. See Attention and Transformers.
  • Going global removes over-squashing (everything is one hop away) but throws away the graph. So structure must be re-injected as features or as an attention bias.
  • Laplacian eigenvector positional encodings play the role of sinusoids — the graph's own Fourier basis, with a sign/basis ambiguity that needs handling. Random-walk structural encodings use return probabilities over k steps and are often simpler and stronger.
  • Attention biases: add a learned term per shortest-path distance, per edge type along that path, and a degree-based term — the recipe behind Graphormer-style models, strong on molecular property prediction.
  • Hybrids (local MPNN layer + global attention layer, alternating) are the pragmatic sweet spot: locality where it is cheap and correct, global reach where it is needed.
the same operation, two masksGNN: hᵥ' = ∑u Aᵥᵤ · αᵥᵤ · W hᵤ (structure = hard mask) Transformer: hᵥ' = ∑u softmax( qᵥᵀkᵤ/√dk + bᵥᵤ ) · W hᵤ (structure = bias bᵥᵤ)
Takeaway: cost decides. Message passing is O(|E|) and biased toward locality; graph attention is O(N²) and biased toward nothing. Sparse graphs with local signal → GNN. Small graphs with long-range interactions (molecules) → graph transformer.

11 Where they earn their keep — and how to not get burned

GNNs pay off exactly when the relations carry signal that the node features do not. If they don't, a gradient-boosted tree on tabular features will beat you.

Applications

  • Molecules & materials: atoms as nodes, bonds as edges — property prediction, force fields, and generative design. The canonical home turf, since a molecule is a graph.
  • Recommendation: the user-item bipartite graph; message passing propagates preference several hops, surfacing items no co-occurrence count would find.
  • Knowledge graphs: relation-aware layers for entity classification and link prediction — the structured grounding behind retrieval and reasoning systems (Knowledge Graphs).
  • Traffic & forecasting: road sensors as nodes; spatial GNN layers combined with temporal layers give spatio-temporal forecasting.
  • Physics simulation: particles as nodes and interactions as edges, learning the update rule for the next timestep.
  • Fraud & security: rings are visible in the topology long before they are visible per account — though these graphs are often heterophilous, so read §09 first.

Tooling

  • Two mature libraries dominate: PyTorch Geometric and DGL — both give sparse message-passing primitives, batched samplers, and the standard layers as one-liners.

Checklist & pitfalls

  1. Beat the no-graph baseline first. An MLP on node features, and a feature-free structural baseline (label propagation, node2vec). If the GNN doesn't beat both, the edges aren't helping.
  2. Measure homophily before choosing a layer. It decides whether averaging is a denoiser or a destroyer.
  3. Start at 2 layers. Add depth only with residuals or jumping knowledge, and only if the task genuinely needs a bigger radius.
  4. Check for leakage: target edges removed from the message graph, temporal splits by time, no test nodes in the training loss.
  5. Self-loops and normalization — forgetting either is the most common silent bug; activations drift and hubs dominate.
  6. Watch degree distribution. Heavy tails wreck memory during sampling; cap fanout, and consider dropping or splitting super-hubs.
  7. Log a smoothing metric (feature variance or Dirichlet energy) per layer. It turns "deeper didn't help" into a diagnosis.
Takeaway: the graph is a modelling choice, not a given. Deciding what a node is, what an edge means, and which features live where usually moves the metric more than swapping GCN for GAT.
