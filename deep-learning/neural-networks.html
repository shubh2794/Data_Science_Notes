Feedforward Networks (MLP)

The base model of deep learning: affine map → non-linearity → repeat. Everything else — convolutions, attention, diffusion nets — is this same skeleton with structure imposed on the weight matrices. This page builds it from a single neuron up to a fully worked backward pass with real numbers, so that the shape of the computation is never in doubt.

01 The neuron and the layer

A neuron is a weighted sum plus a bias, squashed by a non-linear function. A layer is many neurons computed at once — which is just a matrix product.

One unit

  • The unit holds a weight vector w ∈ ℝⁿ and a scalar bias b. It scores an input with a dot product, then bends the result: a = φ(w·x + b).
  • The pre-activation z = w·x + b is a hyperplane score: the set z = 0 is a plane in input space, w is its normal direction (the direction of steepest increase of the score), and b shifts it off the origin. Points on the w side get positive scores, points on the other side negative ones.
  • The magnitude |z| / ‖w‖ is literally the signed distance from x to that plane. A unit is therefore a soft, oriented ruler: "how far past this boundary, in this direction, is the input?"
  • A single unit with a sigmoid is logistic regression. A network is what you get when you stack thousands of these and let a later layer decide what to do with their answers.
  • The non-linearity φ is applied element-wise — it never mixes features. Mixing is the job of the weights; bending is the job of φ. That division of labour is the whole design, and it is what makes the layer expressible as one BLAS call.
worked example · one unitw = [0.5, −1.2, 0.3] b = 0.7 x = [2, 1, −4] z = (0.5)(2) + (−1.2)(1) + (0.3)(−4) + 0.7 = 1.0 − 1.2 − 1.2 + 0.7 = −0.7 ReLU: a = max(0, −0.7) = 0 sigmoid: a = 1/(1 + e0.7) = 1/3.0138 = 0.332

Stacking units into a layer

  • Stack m units side by side and their weight vectors become the rows of a matrix W ∈ ℝm×n, so the whole layer is a = φ(Wx + b) — one matrix-vector product plus one element-wise map.
  • "Fully connected", "dense" and "linear layer" all name this same object: every output touches every input. In code, only the trailing activation distinguishes a linear layer from a layer.
  • Layer ℓ takes the previous layer's activations as its input, so the net is a composition of these blocks. "Feedforward" means the computation graph is acyclic — data flows input → output with no loops back (contrast RNNs, which feed hidden state back into themselves).
  • Naming: a⁽⁰⁾ = x is the input, a⁽ᴸ⁾ the output, z⁽ˡ⁾ the pre-activation and a⁽ˡ⁾ the post-activation of layer ℓ. Backprop is written in terms of z, so keeping the two names separate pays off in §06.
  • The output layer usually has no hidden-style activation — it produces raw scores (logits) that the loss interprets. Mixing that up is one of the most common bugs (§05).

Why the non-linearity is not optional

  • Delete φ and compose two layers: W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂). The product of two matrices is one matrix. A hundred stacked linear layers collapse into a single affine map W̃x + b̃ — no more expressive than linear regression, just slower to evaluate and harder to fit.
  • So depth buys nothing without a non-linearity between the maps. φ is what stops the composition from telescoping, and it is why a deep net can carve input space into many pieces instead of one.
  • The collapse is exact, not approximate — you can compute the equivalent single matrix. Worked below: two layers, then the one affine map that reproduces them digit for digit.
  • A useful corollary: stacked linear layers are still meaningful as a factorization. A bottleneck W₂W₁ with inner dimension r is exactly a rank-r map — fewer parameters, restricted function class. This is the mechanism behind low-rank adapters and linear bottlenecks, and it changes the parameter count, not the family of functions (which is still linear).
worked example · two linear layers collapse to oneW₁ = [[1, 2], [0, 1]], b₁ = [1, 0] W₂ = [[1, −1], [2, 0]], b₂ = [0, 1] step by step, x = [1, 1]: W₁x + b₁ = [3, 1] + [1, 0] = [4, 1] → W₂[4, 1] + b₂ = [3, 8] + [0, 1] = [3, 9] collapsed: W̃ = W₂W₁ = [[1, 1], [2, 4]], b̃ = W₂b₁ + b₂ = [1, 2] + [0, 1] = [1, 3] check: W̃x + b̃ = [2, 6] + [1, 3] = [3, 9] ✓ identical
Takeaway: a network is alternating — linear mixing, element-wise bending, linear mixing, bending. Remove either half and the model degenerates: no W means no feature mixing, no φ means no depth.

02 Activation functions

The bend applied element-wise. The choice matters less for what the net can represent and far more for whether gradients survive the trip back.

The saturating pair: sigmoid and tanh

  • Sigmoid σ(z) = 1/(1 + e−z) maps ℝ to (0, 1). Its derivative is σ(z)(1 − σ(z)), which peaks at 0.25 when z = 0 and decays to ~0 in both tails.
  • That 0.25 ceiling is a hard fact with brutal consequences: every sigmoid layer multiplies the gradient by at most ¼. Ten stacked sigmoid layers attenuate by at most 0.25¹⁰ ≈ 9.5×10⁻⁷; twenty layers by ≈ 9×10⁻¹³. This is the classic recipe for vanishing gradients (§09).
  • Sigmoid is also not zero-centred: all its outputs are positive, so every weight feeding a downstream unit receives a gradient of the same sign on a given example, and the update direction is restricted to one orthant — updates zig-zag toward the optimum instead of heading straight there.
  • tanh fixes the centring (range (−1, 1), derivative 1 − tanh²z peaking at 1) but still saturates in both tails. Note tanh(z) = 2σ(2z) − 1 — it is a rescaled sigmoid, not a different idea.
  • Both survive today mainly as gates — inside LSTM/GRU cells, in gated FFN variants, or as a bounded output — rather than as general hidden activations.

The ReLU family

  • ReLU max(0, z) is the default that made deep nets trainable. Derivative is exactly 1 on the positive side, so gradient magnitude passes through unattenuated however deep the stack, and the forward cost is a single comparison.
  • It is also sparsifying: with typical initialization roughly half the units output exactly zero on any given input, which makes representations sparse and the effective network narrower per example.
  • The cost: the negative half has zero gradient. A unit whose pre-activation is negative for every training example receives no gradient ever again — a dead ReLU. It is not a temporary stall; nothing can revive it, because the gradient with respect to both its weights and its bias is exactly 0.
  • How units die: one oversized update pushes the bias far negative. If b = −5 and |w·x| < 5 for all inputs, then z < 0 always, ReLU(z) = 0 always, and φ′(z) = 0 always. Too large a learning rate can kill a large fraction of a layer in a single step.
  • Leaky ReLU (αz for z < 0, typically α ≈ 0.01) and PReLU (learned α) keep a trickle of gradient alive on the negative side so units can recover. ELU does the same with a smooth exponential tail and mean activations nearer zero.
  • ReLU is not differentiable at z = 0. In practice libraries define φ′(0) = 0 (occasionally 0.5); the choice never matters, because exact zeros have measure zero in floating point.

Smooth modern defaults: GELU and SiLU/Swish

  • GELU z·Φ(z), where Φ is the standard-normal CDF, weights the input by the probability that a standard normal falls below it — a soft, probabilistic gate rather than a hard cut. It is the standard hidden activation in transformer feed-forward blocks.
  • Because Φ needs an erf, implementations often use the tanh approximation 0.5z(1 + tanh(√(2/π)(z + 0.044715z³))), which agrees to about 3 decimal places.
  • SiLU / Swish z·σ(βz) is the same idea with a logistic gate (β = 1 in most uses). Both are smooth, both dip slightly negative around z ≈ −1 (GELU bottoms out near −0.17, SiLU near −0.28), and both approach ReLU for large |z|.
  • Why they help: no hard kink means a well-behaved curvature, and the small negative lobe means mildly-negative units still pass a little signal instead of dying outright. The gain over ReLU is real but modest — this is a tuning-level choice, not an architectural one.
  • Gated variants — GLU, SwiGLU, GeGLU — split the layer into two projections and multiply one by an activated copy of the other: (xW) ⊙ φ(xV). This costs a third matrix, so implementations shrink the hidden width (often to ⅔·4d) to keep the parameter count constant. Common in current large language models.

Output activations are a different question

  • Hidden activations are chosen for gradient flow; the output activation is chosen to match the shape of the target. Regression: none (raw real numbers). Binary: sigmoid. Multi-class, one label: softmax. Multi-label: independent sigmoids, one per label.
  • Softmax turns a vector of logits into a probability distribution: exponentiate, then normalize. It is shift-invariant — softmax(z + c·1) = softmax(z) — which is exactly what licenses the standard stability trick of subtracting the maximum logit before exponentiating.
  • Without that trick, softmax([1000, 1001, 1002]) overflows to inf/inf = NaN. With it, the same computation is softmax([−2, −1, 0]) and is perfectly stable.
  • A temperature T rescales the logits, softmax(z/T): T < 1 sharpens toward one-hot, T > 1 flattens toward uniform. This is the knob behind sampling temperature and the soft targets in knowledge distillation.

03 The forward pass in tensors

In code the net is not a graph of little circles — it is a short chain of matrix multiplies over a batch. Getting the shapes straight is most of the battle.

Batching turns vectors into matrices

  • Frameworks put the batch on the first axis: X ∈ ℝB×n, one example per row. A layer is then H = φ(XW + b) with W ∈ ℝn×m and b ∈ ℝm broadcast across rows.
  • Note this is the transpose of the textbook Wx convention used in §01 and §06. Both are the same computation — (XW)ᵀ = WᵀXᵀ — only the memory layout differs. Pick one and stay consistent, or you will fight shape errors forever.
  • Why row-major batching wins in practice: consecutive features of one example are contiguous in memory, which is what the matrix-multiply kernels want, and the batch axis maps cleanly onto parallel work.
  • The examples in a batch do not interact in an MLP — the batch axis is pure parallelism, and the result for row i is identical whether you run batch 1 or batch 1024. Batch normalization is the notable exception, since its statistics are computed across the batch; that is exactly why it behaves differently at inference time.
  • With more than two dimensions (tokens, pixels) a linear layer applies to the last axis and treats every leading axis as batch: ℝB×T×d → ℝB×T×d′. That is precisely how a transformer's per-token feed-forward block works — B·T independent vectors pushed through the same MLP.
  • Broadcasting the bias is the one silent shape trap: b of shape (m,) added to (B, m) is right; a stray (B, 1) or (m, 1) broadcasts into an (B, m)-shaped mistake without raising an error.

Worked example: a 784 → 256 → 128 → 10 classifier

  • Parameters, layer by layer: 784·256 + 256 = 200,960, then 256·128 + 128 = 32,896, then 128·10 + 10 = 1,290. Total 235,146 parameters ≈ 0.94 MB in fp32.
  • Notice the shape of the cost: the first layer holds 85% of the parameters, purely because its input is wide. Parameter count grows with the product of adjacent widths, so doubling a hidden width roughly quadruples the layers touching it.
  • Optimizer state multiplies that: Adam keeps two moments per parameter, so weights + gradients + 2 moments ≈ 4× the model size ≈ 3.8 MB here. On a billion-parameter model that factor is the difference between fitting on one GPU and not.
  • Compute: 2·(200,704 + 32,768 + 1,280) ≈ 0.47 MFLOPs per example forward. At batch 128 that is ~60 MFLOPs forward and ~180 MFLOPs for a full training step (forward + backward ≈ 3×).
  • Activation memory: storing x, a¹, a², ŷ for the backward pass costs (784 + 256 + 128 + 10)·B·4 bytes — 0.6 MB at B = 128, but 19 MB at B = 4096, at which point the activations dwarf the 0.94 MB of weights. This is why batch size drives memory almost linearly while parameters stay fixed.

04 Universal approximation, depth vs width

One hidden layer is enough in principle. Depth is what makes it affordable in practice.

What the universal approximation theorem says

  • A network with a single hidden layer, any non-polynomial activation, and enough units can approximate any continuous function on a compact domain to any accuracy ε you name. (The non-polynomial condition is essential: polynomials of fixed degree compose into polynomials of fixed degree, so they cannot be universal.)
  • Intuition for ReLU in one dimension: each unit contributes one kink — c·ReLU(x − t) is flat until t then rises with slope c. Summing K of them gives a piecewise-linear function with K breakpoints, and any continuous function on an interval can be traced by a fine enough polyline.
  • In n dimensions the same units become hinges along hyperplanes, and the sum is a piecewise-linear surface over a polyhedral partition of the input space.
  • There is a dual version: bounded width, unbounded depth is also universal (with width a small constant above the input dimension). Neither breadth nor depth is fundamentally privileged for expressiveness — only for cost.

What it does not promise

  • Not the size. The theorem is existential and says nothing about how many units are needed. For some target functions the required width is exponential in the input dimension. Existence is not efficiency.
  • Not learnability. Good weights exist; nothing says gradient descent will find them from your initialization, with your learning rate, on your finite data. Approximation theory and optimization are separate problems.
  • Not generalization. Approximation is guaranteed on the compact training domain. Outside it, extrapolation is unconstrained — a ReLU net is linear in every unbounded outer region, so it extends straight lines into territory it has never seen.
  • Not the data. Fitting the function requires enough samples to pin it down; the theorem assumes you know the target function everywhere.

Why depth wins on parameter efficiency

  • A depth-L, width-w ReLU net has about L·w² parameters, but the number of distinct linear regions it can carve grows roughly like wL — parameters grow linearly in depth while expressible complexity grows exponentially. The mechanism is folding: each layer can map many different input regions onto the same activation pattern, so the next layer's kinks are replicated across all of them.
  • The cleanest concrete case is the sawtooth. The triangle map g(x) = 2·ReLU(x) − 4·ReLU(x − 0.5) uses 2 ReLU units and folds [0,1] onto itself. Composing it L times gives a sawtooth with 2L linear pieces using only 2L units.
  • A single hidden layer needs one kink per breakpoint, so matching that same function takes about 2L units. At L = 10: 20 units deep vs ~1,000 wide. At L = 20: 40 units deep vs ~1,000,000 wide. That is the parameter-efficiency argument in one example.
  • The representational story matches: early layers learn generic parts, later layers compose them into larger structures. Composition is cheap; enumeration is expensive.
  • The practical trade: depth costs sequential latency (layer ℓ+1 cannot start until ℓ finishes) and makes optimization harder (§09), while width is embarrassingly parallel on a GPU and better at saturating tensor cores. Real designs land on moderate depth with wide layers.

05 Loss functions

The loss defines what "good" means. Almost every standard loss is the negative log-likelihood of some assumed output distribution — which is why the "right" loss is usually determined by the target, not chosen by taste.

The likelihood view

  • Assume the model outputs the parameters of a distribution over y. Maximum likelihood says: maximize ∏ᵢ pθ(yᵢ | xᵢ), equivalently minimize −∑ᵢ log pθ(yᵢ | xᵢ). Every loss below is that expression with a different assumed distribution.
  • Logs turn the product into a sum (numerically essential — a product of 10,000 probabilities underflows immediately) and turn "confidently wrong" into an unboundedly large penalty.
  • This view also explains the pairing rule: the output activation produces the distribution's parameters, and the loss reads them. Sigmoid → Bernoulli parameter; softmax → categorical parameters; linear → Gaussian mean.

Regression: mean squared error

  • MSE = (1/B)∑ ‖y − ŷ‖². Its gradient with respect to the prediction is 2(ŷ − y) — errors are penalized quadratically, so a single 10× outlier contributes 100× the loss and dominates the batch.
  • Likelihood reading: MSE is the negative log-likelihood of a Gaussian with fixed variance. MAE corresponds to a Laplace assumption — robust, but its gradient has constant magnitude ±1, so it never slows down near the optimum. Huber interpolates: quadratic within δ of zero, linear beyond it.
  • MSE is scale-sensitive: if targets live in the thousands, the loss and its gradients live in the millions. Standardizing targets is as important as standardizing inputs.

Classification: cross-entropy

  • Softmax over K logits, then L = −∑ₖ yₖ log ŷₖ. With a one-hot target this reduces to −log ŷtrue: the loss cares only about the probability assigned to the correct class, and is indifferent to how the remaining mass is split.
  • Useful sanity values: a K-class model that predicts uniformly scores log K — 2.30 for 10 classes, 6.91 for 1000. If your loss starts far above that, the initialization or the label alignment is wrong.
  • Equivalent form: L = log∑ₖ ezₖ − ztrue (log-sum-exp minus the true logit). When one wrong logit dominates, the loss is very nearly the logit gap — a handy mental check.
  • The reason cross-entropy beats MSE here: its gradient with respect to the logits is the strikingly clean ŷ − y (derived in full in §06), so a confidently wrong prediction produces a large gradient. MSE composed with a saturating output does the opposite — it produces a tiny gradient exactly when the model is most wrong.
  • Implementations fuse softmax and cross-entropy into a single log-sum-exp op — more stable and cheaper — which is why framework losses want raw logits, not softmaxed probabilities. Applying softmax twice is a classic silent bug: it trains, badly.
  • Variants: label smoothing replaces the one-hot target with 1 − ε on the true class and ε/(K−1) elsewhere, which caps the logit gap the model chases and improves calibration. Focal loss multiplies by (1 − ŷtrue)γ to down-weight easy examples under heavy class imbalance. Class weights rescale per-class terms directly.

Worked contrast: why MSE strangles a saturating output

  • Take a binary unit that is confidently wrong: target y = 1, output a = σ(z) = 0.001.
  • With MSE: ∂L/∂z = 2(a − y)·σ′(z) = 2(−0.999)(0.001·0.999) ≈ −0.0020. The σ′ factor is nearly zero precisely because the model is deep in the saturated tail, so the update is negligible.
  • With binary cross-entropy: ∂L/∂z = a − y = −0.999. The σ′ factor cancels analytically against the 1/a from the log, leaving a gradient ~500× larger.
  • That cancellation is the entire reason cross-entropy is the classification loss. It is not a heuristic preference — it is the loss whose gradient is immune to output saturation.

06 Backpropagation, derived

The chain rule, applied right to left and reusing intermediate results. It is not a neural-network algorithm — it is reverse-mode automatic differentiation, and it happens to be perfect for them.

The setup

  • Two-layer classifier, one example, column convention (W is out × in). Forward: z⁽¹⁾ = W⁽¹⁾x + b⁽¹⁾, a⁽¹⁾ = φ(z⁽¹⁾), z⁽²⁾ = W⁽²⁾a⁽¹⁾ + b⁽²⁾, ŷ = softmax(z⁽²⁾), L = −∑ₖ yₖ log ŷₖ.
  • Shapes: x ∈ ℝⁿ, W⁽¹⁾ ∈ ℝh×n, W⁽²⁾ ∈ ℝK×h. A gradient always has the same shape as the thing it differentiates, so ∂L/∂W⁽¹⁾ is h×n — a good running check.
  • The one object worth defining is δ⁽ˡ⁾ = ∂L/∂z⁽ˡ⁾, the error signal at the pre-activation of layer ℓ. Every gradient we want is a cheap product built from it.

Step 1 — differentiate the loss with respect to the outputs

  • L = −∑ₖ yₖ log ŷₖ, so ∂L/∂ŷₖ = −yₖ/ŷₖ. Note this blows up as ŷₖ → 0 — the reason you never compute it explicitly, and instead fuse the next two steps.

Step 2 — the softmax Jacobian

  • Softmax couples every output to every logit, so its derivative is a full K×K Jacobian, not an element-wise factor. Differentiating ŷₖ = ezₖ/∑ⱼezⱼ by the quotient rule gives ∂ŷₖ/∂zⱼ = ŷₖ(δₖⱼ − ŷⱼ), where δₖⱼ is the Kronecker delta.
  • Diagonal terms ŷₖ(1 − ŷₖ) are positive (raising a logit raises its own probability); off-diagonal terms −ŷₖŷⱼ are negative (it must come at everyone else's expense).

Step 3 — the two collapse into ŷ − y

  • Chain steps 1 and 2 and the mess cancels completely. This cancellation is the single most important line of algebra in supervised deep learning, so it is worth writing out in full — see the formula block below.
  • Reading the result: the error signal at the logits is simply "what you predicted minus what was true". Its entries sum to zero, its magnitude is bounded by 1, and it is largest exactly when the model is most wrong. No saturation, no vanishing.
step 3 · the cancellation, in full∂L/∂zⱼ = ∑ₖ (∂L/∂ŷₖ)(∂ŷₖ/∂zⱼ) = ∑ₖ (−yₖ/ŷₖ) · ŷₖ(δₖⱼ − ŷⱼ) = −∑ₖ yₖ(δₖⱼ − ŷⱼ) = −yⱼ + ŷⱼ ∑ₖ yₖ = ŷⱼ − yⱼ (since ∑ₖ yₖ = 1) ⟹ δ⁽²⁾ = ŷ − y

Step 4 — gradients of the top layer's parameters

  • Write the layer in indices: z⁽²⁾ⱼ = ∑ᵢ W⁽²⁾ⱼᵢ a⁽¹⁾ᵢ + b⁽²⁾ⱼ. Then ∂z⁽²⁾ⱼ/∂W⁽²⁾ⱼᵢ = a⁽¹⁾ᵢ and ∂z⁽²⁾ⱼ/∂b⁽²⁾ⱼ = 1.
  • So ∂L/∂W⁽²⁾ⱼᵢ = δ⁽²⁾ⱼ · a⁽¹⁾ᵢ — in matrix form, an outer product δ⁽²⁾(a⁽¹⁾)ᵀ of the outgoing error with the incoming activation, and ∂L/∂b⁽²⁾ = δ⁽²⁾.
  • Two consequences worth internalizing: a weight's gradient is zero if its input activation was zero (dead ReLUs upstream freeze the weights below them), and it is proportional to the input's magnitude (unscaled inputs produce wildly unequal gradients across features).

Step 5 — push the error down one layer

  • a⁽¹⁾ᵢ influences every output, so its gradient sums over them: ∂L/∂a⁽¹⁾ᵢ = ∑ⱼ δ⁽²⁾ⱼ W⁽²⁾ⱼᵢ, which in matrix form is (W⁽²⁾)ᵀδ⁽²⁾. The transpose routes the error backwards along the same wires the forward pass used.
  • Then cross the activation, which is element-wise, so its Jacobian is diagonal and the chain rule becomes a Hadamard product: δ⁽¹⁾ = ((W⁽²⁾)ᵀδ⁽²⁾) ⊙ φ′(z⁽¹⁾).
  • Finally the same outer-product rule as step 4: ∂L/∂W⁽¹⁾ = δ⁽¹⁾xᵀ, ∂L/∂b⁽¹⁾ = δ⁽¹⁾.
  • That is the entire algorithm. For deeper nets you just repeat step 5: transpose to route the error, ⊙ φ′ to gate it, outer product to bank it. Depth means doing it more times, nothing else.

The reverse-mode autodiff view

  • Every operation in the forward pass is a node in a computation graph. Forward mode propagates derivatives input → output and costs one pass per input; reverse mode propagates output → input and costs one pass per output.
  • Training has millions of inputs (the parameters) and one scalar output (the loss). Reverse mode is therefore the right choice by a factor of millions — that asymmetry is the entire reason deep learning is computationally feasible. Forward mode would need one pass per parameter.
  • Frameworks record the graph as you compute (a tape), then walk it backwards calling each op's vector-Jacobian product. You never materialize a Jacobian — for the layer above, the K×h Jacobian is never built, only applied as (W⁽²⁾)ᵀδ.
  • Nodes with several consumers accumulate: if a tensor is used twice, its gradient is the sum of the two incoming gradients (the multivariable chain rule). This is why frameworks add into .grad and why you must zero gradients between steps.
  • Backprop is exact to floating-point precision, not a finite-difference approximation. Which means you can gradient-check it: perturb one weight by ε = 10⁻⁵ and confirm ΔL ≈ ε · ∂L/∂w. Any custom layer deserves this test.

What it costs

  • Time: the backward pass is roughly 2× the forward pass. Each layer does two matrix multiplies of the same size as its forward one — a gradient with respect to its input (δ⁽ˡ⁾ for the layer below) and one with respect to its weights. So a training step ≈ 3× an inference pass, which is the origin of the familiar "6·N·D FLOPs" training estimate for a model with N parameters and D tokens.
  • Memory: every activation needed by a backward op must be retained from its forward computation until it is used, so peak memory scales with depth × batch × width. This — not the weights — is what usually caps batch size.
  • Gradient checkpointing trades that memory back for compute: store activations only at a few checkpoints and recompute the rest during the backward pass, typically cutting activation memory to O(√L) for about one extra forward pass.
  • Numerically the danger is that the recursion is a product of many terms — L transposed matrices and L slope vectors multiplied together. Whether that product survives is the subject of §09.
Takeaway: backprop is bookkeeping, not magic — it computes exactly the derivatives calculus already defines, but reuses shared sub-expressions so the total cost stays proportional to the forward pass instead of scaling with the parameter count.

08 Gradient descent, SGD, mini-batches

Backprop hands you a direction. The optimizer decides how far to step, and on how much data the direction was estimated.

The update rule

  • The update is one line: θ ← θ − η ∇θL. Everything else — momentum, Adam, schedules, second-order methods — is a smarter way to choose that step from the same gradient.
  • Why the negative gradient: ∇L points in the direction of steepest increase, and to first order L(θ − η∇L) ≈ L(θ) − η‖∇L‖², which decreases for small enough η. "Small enough" is the entire difficulty — the first-order approximation is only valid within a neighbourhood set by the curvature.
  • One epoch = one pass over the shuffled training set = ⌈N/B⌉ steps. With N = 50,000 and B = 128 that is 391 steps per epoch, so a 20-epoch run is 7,820 updates — the number that actually matters, not the epoch count.
  • Shuffling between epochs matters: a net fed class-sorted batches chases whichever class it saw last, and the loss curve develops a sawtooth locked to the data order.

Batch size: the bias-free, variance-heavy estimate

  • Full-batch gradient descent uses every example per step — an accurate direction at enormous cost, and one that heads straight into the nearest local basin.
  • Stochastic (one example) is cheap and extremely noisy. Mini-batch (32–1024) is the practical middle: the estimate is unbiased (𝔼[ĝ] = ∇L) with variance falling as 1/B, so the standard deviation falls only as 1/√B.
  • That square root is the key economics: going from B = 32 to B = 512 costs 16× the compute per step but reduces gradient noise only 4×. Beyond some critical batch size you are buying almost nothing.
  • The noise is not purely a nuisance: it perturbs the trajectory out of sharp minima and acts as a mild regularizer. Larger batches give smoother, less exploratory steps, which is why they typically want a proportionally larger learning rate (the linear-scaling heuristic) plus warm-up to survive the first few steps.

The learning rate

  • η is the single most consequential hyper-parameter, and its useful range spans orders of magnitude. Too small: crawling, and stuck in whatever basin you started near. Too large: the loss oscillates, diverges to NaN, or kills a swathe of ReLUs in one step.
  • Concretely: gradient component 0.4 with η = 0.1 moves that weight by 0.04. If typical weights are ~0.05 (He init at nin = 256), that single step nearly doubles the weight — clearly too big.
  • Standard practice is a short warm-up (ramp from ~0 over the first few hundred steps, so early noisy gradients cannot blow up the scale) followed by a decay (cosine or step) that anneals toward a fine-grained finish.
  • The cheapest diagnostic: a learning-rate range test — run a few hundred steps with η increasing exponentially and plot loss vs η. Pick roughly an order of magnitude below where the loss turns upward.

09 Initialization and the scale problem

Depth multiplies. Whatever factor each layer applies to the signal gets raised to the power L — so the scale of the initial weights decides whether a deep net trains at all.

Why not zeros, and why not "anything random"

  • All zeros (or any constant) is fatal: every unit in a layer computes the same function and receives the same gradient, so they remain identical forever and the layer has the effective width of one unit. Random initialization exists first and foremost to break symmetry.
  • But the scale is not free. For a layer with independent zero-mean weights, Var(z) = nin·Var(W)·Var(ain), so each layer multiplies the signal variance by the factor nin·Var(W).
  • Compounding is merciless. A factor of 1.2 over 50 layers gives 1.2⁵⁰ ≈ 9,100×; a factor of 0.8 gives 0.8⁵⁰ ≈ 1.4×10⁻⁵. Both destroy training — the first by saturating or overflowing, the second by starving the deeper layers of any signal at all.
  • So the design goal is a factor of ≈ 1: activation variance roughly constant on the way forward, and gradient variance roughly constant on the way back. The forward condition wants nin·Var(W) = 1, the backward condition wants nout·Var(W) = 1 — and the two disagree unless the layer is square.

Xavier/Glorot and He/Kaiming

  • Xavier/Glorot splits the difference between the two conditions with the harmonic-style compromise Var(W) = 2/(nin + nout), or uniform on ±√(6/(nin + nout)). It was derived assuming a symmetric activation that is roughly linear near zero — tanh, or sigmoid after rescaling.
  • He/Kaiming corrects for ReLU. ReLU zeroes half its inputs, so it halves the variance passing through, and the fix is to double the weight variance: Var(W) = 2/nin. The factor of 2 is exactly that compensation, nothing more.
  • Rule of thumb: He with the ReLU family, Xavier with tanh/sigmoid. Frameworks let you pass a gain for other activations (e.g. √2 for ReLU, 5/3 for tanh).
  • Concrete numbers for a 256 → 128 layer: He gives Var(W) = 2/256 = 0.0078, so sd ≈ 0.088. Xavier gives Var(W) = 2/384 = 0.0052, sd ≈ 0.072, or uniform on ±0.125. Small differences that compound over dozens of layers.
  • Biases start at zero — there is no symmetry for them to break, since the weights already differ. Modern nets add extra scale control on top: normalization layers, and tricks like initializing the last layer of each residual branch near zero so every block starts out as an identity map.

Vanishing and exploding gradients

  • The backward recursion of §06 is a product: δ⁽¹⁾ carries a factor of ∏ℓ(W⁽ˡ⁾)ᵀ and ∏ℓφ′(z⁽ˡ⁾). Products of terms below 1 vanish exponentially; products above 1 explode exponentially. There is no stable middle unless you engineer one.
  • Symptoms of vanishing: the loss plateaus early, early-layer weights barely move from their initial values, and the gradient norm at layer 1 is orders of magnitude below the norm at layer L. The model still trains — but effectively only its top few layers do.
  • Symptoms of exploding: the loss spikes to inf or NaN, often in a single step; gradient norms jump by orders of magnitude; weights blow up and every ReLU either saturates or dies.
  • The fixes are precisely the ingredients that define modern architectures:
    • Non-saturating activations — slope 1 instead of ≤ 0.25 removes the guaranteed decay factor.
    • Careful initialization — the variance argument above sets the weight factor to ≈ 1 at step 0.
    • Normalization (batch, layer, RMS) — re-centre and re-scale activations at every layer so the running product cannot drift away from 1 during training, not just at initialization.
    • Residual connections — a = x + F(x) has derivative I + ∂F/∂x, giving the gradient an identity path with factor 1 straight to the bottom of the network no matter how deep it is. This is what took networks from ~20 layers to hundreds. See Residual / Skip Connections.
    • Gradient clipping — rescale the gradient whenever its global norm exceeds a threshold. It cannot fix vanishing, but it makes explosion survivable, and is standard in recurrent and language models.
  • Diagnose before you treat: log per-layer gradient norms. A healthy net keeps them within an order of magnitude of each other across depth. The viz below shows what the unhealthy versions look like.

10 Regularization in nets

A net with millions of parameters can memorize the training set outright — it can even fit random labels. Regularization is anything that makes memorizing less attractive than generalizing.

The standard levers

  • Weight decay shrinks every weight toward zero on each step. As an L2 penalty (λ/2)‖θ‖² in plain SGD, the update becomes θ ← (1 − ηλ)θ − η∇L — a constant multiplicative pull toward the origin. In Adam the penalty interacts badly with the adaptive scaling, so AdamW decouples it into a direct subtraction.
  • How strong is it, really? With η = 0.1 and λ = 10⁻⁴, the per-step factor is 0.99999, but over 10,000 steps that compounds to e−0.1 ≈ 0.905 — a ~10% shrink from decay alone, on top of whatever the loss gradient does.
  • Dropout zeroes each hidden unit independently with probability p during training. Inverted dropout (the standard implementation) divides the survivors by 1 − p so the expected activation is unchanged and inference needs no rescaling at all.
  • Why it works: no unit can rely on any particular partner being present, so features become redundant and individually meaningful rather than co-adapted. A layer of h units defines 2h possible sub-networks that share weights, and dropout trains a random one each step — loosely, an implicit ensemble. It is disabled at inference, which is what the train/eval mode switch is for.
  • Early stopping monitors validation loss and keeps the checkpoint from just before it turns upward. It costs nothing, needs no hyper-parameter beyond patience, and is often the single strongest lever.
  • Batch/layer normalization regularize as a side effect — batch norm because each example's statistics depend on the random batch it landed in, which injects noise much like dropout.

Data beats penalties

  • Augmentation and simply more data beat every explicit penalty when available, because they change what the model must fit rather than how hard it is punished for fitting it.
  • Milder extras: label smoothing (§05), Gaussian noise on inputs or weights, and stochastic depth in very deep residual nets.
  • The knobs interact. Heavy dropout plus heavy weight decay plus a small model is over-regularized, and shows up as a training loss that never gets low enough — a diagnosis people often mistake for "needs more regularization" and make worse.
  • Sequence to follow: get the model to overfit first (proving capacity and a working pipeline), then add regularization until the validation curve turns. A model that cannot overfit a small subset has a bug, not a generalization problem.

Takeaway: diagnose before you regularize — high training and validation loss is underfitting (add capacity or train longer), low training with high validation is overfitting (add regularization or data). Full treatment on Regularization.

11 Where MLPs live inside modern models

Nobody ships a plain MLP on images or text — but nearly every modern model is mostly MLP by parameter count.

Inside every transformer

  • Each block alternates attention (where tokens mix with each other) with a per-token MLP (where a token's features mix with themselves): FFN(x) = W₂·φ(W₁x + b₁) + b₂, conventionally with dff = 4·dmodel.
  • Count the parameters per layer: attention has four d×d projections (Q, K, V, O) for 4d²; the FFN has d×4d up and 4d×d down for 8d². Total 12d², of which the FFN is two thirds. The MLP is where most of a language model's knowledge sits.
  • Concretely at d = 4096: 67M parameters of attention and 134M of FFN per layer; across 32 layers that is ~6.4B parameters, ~4.3B of them in plain feed-forward blocks.
  • Mixture of experts replaces that single FFN with many and routes each token to a few. The experts are MLPs — 8 experts means 64d² of parameters but only 8d² or 16d² active per token. The architecture changes which MLP runs, not what an MLP is. See Mixture of Experts and Transformers.

Everywhere else

  • Heads. Classification, regression and projection heads are one or two dense layers on top of a pooled representation. Fine-tuning frequently means exactly "freeze the encoder, train a small MLP head" — see Fine-Tuning & Transfer Learning.
  • Embedding projections that map one space into another, value and policy networks in reinforcement learning, the conditioning path of a diffusion model's score network, and the tiny per-node MLPs inside graph and point-cloud models.
  • Tabular data is the one domain where a bare MLP is still a reasonable end-to-end model — though gradient-boosted trees remain a very strong baseline on small, heterogeneous tables, where the inductive bias of axis-aligned splits fits the data better than smooth interpolation.
  • The pattern to internalize: specialized architectures add structure to the mixing step — weight sharing over space (CNNs), content-dependent mixing over positions (attention), message passing over edges (GNNs) — and then hand each element back to an MLP for per-element processing.
  • Which also means the MLP is where efficiency work concentrates: quantization, sparsity, low-rank adapters and expert routing all target these blocks first, because that is where the parameters and the FLOPs are.

Takeaway: "MLP" is not a legacy model. It is the default building block; new architectures mostly innovate on how information moves between positions, then hand each position back to an MLP.

12 What to remember & common pitfalls

The compressed version, plus the mistakes that cost the most debugging time.

The six sentences

  • A net is alternating affine maps and element-wise non-linearities; without φ the whole stack collapses to one linear map.
  • The forward pass is a chain of matrix products over a batch × features tensor; shapes chain through inner dimensions, and parameters grow with the product of adjacent widths.
  • Depth is parameter-efficient — the sawtooth needs 2L units deep and 2L wide — but universal approximation promises neither size, learnability, nor generalization.
  • The loss is a negative log-likelihood; softmax + cross-entropy collapses to the gradient ŷ − y, which is exactly why it doesn't saturate.
  • Backprop is reverse-mode autodiff: transpose to route the error, ⊙ φ′ to gate it, outer product to bank it — every gradient at ~2× the forward cost.
  • Depth is multiplicatively fragile; initialization, normalization and residual connections are what keep the product of layer factors near 1.

Pitfalls

  • Softmax applied twice — most frameworks' cross-entropy expects raw logits. Symptom: it trains, but weakly and to a worse optimum, with no error raised.
  • MSE on a classification problem — trains, converges slowly, calibrates badly, and saturates exactly when it is most wrong (§05).
  • Unscaled inputs. Feature magnitudes multiply directly into weight gradients (∇W = δxᵀ), so features on wildly different scales produce wildly different learning rates per weight. Standardize.
  • Learning rate too high — NaNs, or a wall of dead ReLUs that never recover. Always sanity-check by overfitting a batch of ten examples to near-zero loss before a real run; if that fails, the bug is in the pipeline, not the hyper-parameters.
  • Forgetting train/eval mode. Dropout and batch norm behave differently at inference; leaving the model in train mode quietly corrupts every validation number you report.
  • Forgetting to zero gradients — backward accumulates into .grad, so a missing reset silently sums gradients across steps.
  • Not shuffling, or leaking validation data through preprocessing statistics fitted on the full dataset before the split.
  • Loss that starts far from log K — for a 10-class problem the initial loss should be ≈ 2.30. Much higher means a broken initialization or misaligned labels; much lower means the labels have leaked into the inputs.
  • Blaming the architecture first. In practice the data pipeline, the learning rate, and the loss/target pairing explain the overwhelming majority of failures long before the layer count does.
Takeaway: if you can write the shape chain forward, the δ recursion backward, and name the distribution behind your loss, you understand the model well enough to debug it — and every architecture built on top of it.
