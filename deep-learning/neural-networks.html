Feedforward Networks (MLP)

A feedforward network is a chain of affine maps separated by element-wise non-linearities, and essentially every other architecture in this domain is that chain with structure imposed on the weight matrices — a convolution is a dense layer whose matrix is forced to be banded and tied, attention is a dense layer whose matrix is computed from the data, and a mixture of experts is a dense layer whose matrix is selected per token. This page owns the base object: what the function class is, what it can represent, and how it is shaped. It builds one neuron up to a batched forward pass with real numbers, works the XOR solution through by hand, derives every standard output unit from maximum likelihood, and then draws the hard line between what universal approximation actually promises and what people believe it promises.

01 What a feedforward network is

Three words in the name each carry a precise technical meaning, and every one of them is a design decision that later architectures revisit. Feedforward: information flows one way, the computation graph is acyclic. Network: the model is a composition of functions, drawn as a graph. Neural: a historical accident of naming that stopped being an engineering constraint decades ago.

The object, in one line

the modelf(x; θ) = f⁽ᴸ⁾ ∘ f⁽ᴸ⁻¹⁾ ∘ ⋯ ∘ f⁽²⁾ ∘ f⁽¹⁾ (x) each layer f⁽ˡ⁾(h) = g⁽ˡ⁾( h W⁽ˡ⁾ + b⁽ˡ⁾ ) g element-wise, W a matrix, b a vector the goalThere is some unknown f*. The data gives noisy samples (xᵢ, yᵢ) with yᵢ ≈ f*(xᵢ). Choose θ so that f(·; θ) is close to f*. That is the whole enterprise; the rest is how the family f(·; θ) is built and how θ is chosen.
feed · forward
The graph is acyclic
Information moves from x through intermediate computations to y and never back into the same unit. There is no state, no time index, no fixed point to solve. Add feedback edges and you have a recurrent network — a strictly larger family with a strictly harder training problem.
net · work
It is a composition, drawn as a DAG
The depth is the length of the chain; the width of a layer is the dimension of its output vector. "Deep learning" is named after that length and nothing else. The chain is the common case, not a requirement: skip connections add edges that jump layers, and the graph stays acyclic.
neur · al
A loose historical analogy
Each unit sums inputs and applies a threshold-like function, which is roughly what a 1940s model of a neuron did. Modern design is driven by optimisation and statistics, not neuroscience. Treat these as function-approximation machines that occasionally borrow an idea from biology, not as models of a brain.
hidden
The layers nobody supervises
The data specifies what the output layer must produce at each x. It says nothing about what any intermediate layer should compute. Those layers are called hidden for exactly that reason, and the fact that their targets are unspecified is what makes the training problem non-convex.

Why the composition view is the useful one

Writing the model as f⁽ᴸ⁾ ∘ ⋯ ∘ f⁽¹⁾ rather than as "a network of neurons" pays for itself three times over. It makes the chain rule the obvious tool for differentiating it — which is all backpropagation is. It makes clear that the layers are not independent modules that could be reordered; each one is defined on the output space of the one below it, so a layer's meaning is entirely determined by its position. And it exposes the actual design space: you get to choose the number of functions in the chain, the dimension of each intermediate space, and the form of each function. Everything else on this page is one of those three choices.

There is a second reading that becomes important later. A deep network can be read as a program with L sequential steps, each step consuming the previous step's output. Under this reading depth is not "more capacity" — it is more steps of computation, and a network that is too shallow is not under-parameterised so much as it is denied the ability to compute something in stages. §21 turns this intuition into an actual counting argument.

The chain: depth, width, and the shapes that flow through it every layer is one matrix; the shapes chain through the inner dimension, and the parameter count is the sum of the adjacent-width products
The tempting shortcut. "The input layer is the first layer, so a network with one hidden layer has three layers." Count the layers that have parameters. The input is data, not a function; it has no weights and computes nothing. A network with one hidden layer is a two-layer network and has depth 2, because there are exactly two affine maps in the chain. Library summaries that print an "InputLayer" row are describing a graph node, not a layer of the model. Every count on this page — parameters, depth, matrices — follows the parameterised-layer convention.

27 The historical arc: perceptron, objection, backprop, depth

Worth knowing because the same misconceptions recur, and because two of the three algorithmic changes that made deep networks work are things this page has already derived.

PeriodWhat happenedWhat it means here
17th–19th c.The chain rule is worked out; iterative gradient descent is introduced as a method for approximating the solution of an optimisation problem.Both ingredients of training predate the model by three centuries. A feedforward network is the culmination of a very long project on function approximation, not a break from it.
1940s–1950sThe threshold logic unit and the perceptron: a weighted sum with a step function, trained by a rule that strengthens the connections that would have produced the correct answer — "cells that fire together, wire together", corrected by the error. It provably converges when the data is linearly separable.A single perceptron is §02's neuron with a step activation. Note what it does not produce: a probability. That is one good reason to prefer logistic regression, and §16's derivation is what fixes it.
1969A formal monograph catalogues the perceptron's limits, XOR foremost among them. Funding and attention leave the field for over a decade.§06. The objection was correct about the model that existed — a single layer of linear threshold units — and wrong about the family. Stacking layers fixes it (§07); nobody could train the stack.
1960s–1970sEfficient applications of the chain rule by dynamic programming appear, mostly in control and sensitivity analysis, without being connected to neural networks.Backpropagation existed as a technique before it was applied to this problem. The bottleneck was never the mathematics.
1980sThe idea is proposed for training networks, independently rediscovered several times, and popularised by a body of work whose central claim goes well beyond the algorithm — distributed representation: that a concept is a pattern of activity across many units rather than the firing of one.The XOR objection is answered in practice. Distributed representation is why §03's "learn φ" strategy is possible at all, and why a hidden unit is generally not interpretable on its own.
1990sA peak of interest, then a decline as other methods with convexity guarantees become more attractive.The trade §03 named: strategy 3 is the only one that gives up convexity, and for a decade that looked like a bad bargain.
2006 onwardThe modern resurgence. Until roughly 2012 feedforward networks were still thought to need help from other models; after 2012 they were understood to work well on their own given the right resources and engineering.The reversal is total: it is now more common to use supervised learning to support unsupervised learning than the other way round.

What actually changed between 1986 and 2015

The core ideas did not. The same backpropagation, the same gradient descent. Most of the improvement came from larger datasets, which made generalisation less of a challenge, and larger models on faster machines with better software. On top of that, a small number of algorithmic changes mattered a great deal — and two of the three are on this page.

change 1
Squared error → cross-entropy
Squared error was the default into the 1990s and was gradually replaced by the cross-entropy family as the maximum-likelihood framing spread from statistics. The gain landed precisely where §17 predicts: models with sigmoid and softmax outputs, which had suffered from saturation and slow learning, started to train.
change 2
Sigmoid hidden units → rectifiers
Rectification appeared in early vision models in the 1970s, was displaced by sigmoids in the 1980s — plausibly because sigmoids do better when networks are very small — and was avoided into the 2000s on the somewhat superstitious ground that a non-differentiable point must be bad. Around 2009 this reversed decisively: rectification was found to be the single most important factor in improving a recognition system, and learning in deep rectified networks turned out to be far easier than in networks with two-sided saturation.
change 3
Optimisation machinery
Better initialisation, normalisation layers, adaptive optimisers, and residual connections — the things that make a hundred-layer network trainable at all. Not this page: Neural Network Training. This is the change that unlocked the depth that §21 says is worth having.
a footnote worth keeping
Random weights already work, a little
On small datasets, using a rectifying non-linearity was found to matter more than learning the hidden weights at all: random weights suffice to propagate useful information through a rectified network, and a classifier on top can learn to map the resulting features to labels. Learning the hidden layers only starts to pay once there is enough data. A useful corrective to the idea that all the value is in the learned features.
Neuroscience, in proportion. The rectifier is a case where a biological argument genuinely guided a design: biological neurons are completely inactive for many inputs, respond roughly proportionally to their input when active, and are inactive most of the time — three properties a half-rectifier captures and a sigmoid does not. That is a real contribution. It is also close to the last one: modern design is driven by optimisation and statistics, and the role of neuroscience as a guide has diminished steadily. Both halves of that sentence are true and the second is more often forgotten.

28 What to remember, and the mistakes that cost the most

The compressed version of the function class, then the errors that are worth recognising on sight.

Ten sentences

  1. A feedforward network is alternating affine maps and element-wise non-linearities, composed in an acyclic chain. Depth is the number of parameterised layers; width is the dimension of a hidden vector.
  2. Without the non-linearity the whole stack collapses to a single affine map W* = W₁W₂⋯W_L. That one fact is why g exists, and a deliberately linear layer is a low-rank factorisation rather than a mistake.
  3. A hidden layer is a new space to be linear in, not extra capacity bolted onto a linear model. XOR is solved because one clipped number stops four points being collinear.
  4. A rectified unit folds the input space. Units add regions; layers multiply them. Everything about depth follows from that distinction.
  5. The forward pass is a chain of matrix products over a batch × features tensor; shapes chain through the inner dimension, the batch axis is a spectator, and parameters grow with the sum of adjacent-width products.
  6. The output unit and the loss are one decision. Pick a distribution for the target, output its parameters, take the negative log-likelihood. Linear + Gaussian gives squared error; sigmoid + Bernoulli gives cross-entropy; softmax + multinoulli gives categorical cross-entropy.
  7. Every maximum-likelihood pairing gives ∂L/∂z = ŷ − y at the logits, with no derivative of the output non-linearity in it — which is exactly why cross-entropy does not saturate and squared error on a sigmoid does, by a factor of 2 + eᶻ + e⁻ᶻ.
  8. Universal approximation promises existence and nothing else: no width bound, no guarantee that training finds it, no claim about generalisation, and nothing at all outside the compact set.
  9. Depth is exponentially more efficient than width for functions with compositional structure — the sawtooth needs 2L units deep and 2ᴸ wide — but that is a statement about representability, and whether your target has that structure is an empirical question.
  10. An MLP is permutation-equivariant over its input coordinates, so it assumes nothing. Every other architecture in this domain is this one with a constraint imposed on W, and the constraint is the prior knowledge.

Pitfalls, in rough order of how much time they cost

  • Softmax applied twice. Most frameworks' cross-entropy expects logits and applies the softmax internally. Passing probabilities squashes twice. Nothing raises an error; the model trains weakly to a worse optimum. Look for …_with_logits in the function name and believe it.
  • Squared error on a classification problem. It trains, converges slowly, calibrates badly, and delivers essentially no gradient from the examples it is most wrong about (§17).
  • Softmax for a multi-label problem. The outputs are forced to sum to 1, so the model is structurally prevented from saying "both". Use K independent sigmoids (§19).
  • A silent broadcast. Predictions of shape (N, 1) against targets of shape (N,) broadcast to (N, N). The loss is finite and nearly meaningless. Print the shape once.
  • The naive log-sigmoid. −log(σ(z)) returns infinity for z below about −710 in float64 and about −104 in float32, where the true answer is a perfectly ordinary number. One infinite loss is one destroyed run (§16).
  • An accidental bottleneck. A hidden layer narrower than the output dimension caps the rank of the whole network, and no capacity above it recovers what was discarded (§23).
  • Mixing the row and column conventions mid-derivation. A transposed weight matrix produces a shape error if you are lucky and a wrong gradient if you are not (§09).
  • Unscaled inputs. Feature magnitudes multiply directly into the weight gradients, so features on wildly different scales get wildly different effective learning rates. Standardise.
  • A loss that does not start near log K. For a balanced K-class problem the initial loss should be about log K — 2.303 for ten classes, 0.693 for two. Much higher means broken initialisation or misaligned labels; much lower means the labels have leaked into the inputs.
  • Reaching for a different activation first. It is almost never the activation. It is the data pipeline, the learning rate, or the output-unit-and-loss pairing (§13).
  • Blaming the architecture at all. Universal approximation says the family can express it. Before touching the shape, overfit ten examples to near-zero loss; if that fails the bug is upstream of everything on this page.
