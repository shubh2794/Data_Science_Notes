20 Universal approximation: what it promises, and what it does not

The most quoted and most misread result about neural networks. It is a genuine theorem with a precise statement, and almost every practical conclusion drawn from it is unsupported by it.

The statement

universal approximation, stated carefullyLet f be a continuous function on a CLOSED AND BOUNDED subset K ⊂ ℝⁿ. Let ε > 0 be any positive tolerance. THEN there EXISTS a feedforward network with a LINEAR OUTPUT LAYER and ONE hidden layer using a suitable non-polynomial activation, having FINITELY many hidden units, such that sup_{x ∈ K} | f(x) − net(x) | < ε The original results assumed a "squashing" activation that saturates at both ends; they were later extended to a much wider class of non-polynomial activations, including the rectified linear unit. The DERIVATIVES of the network can be made to approximate the derivatives of f arbitrarily well too.

Every clause is doing work. Continuous and closed and bounded: nothing is claimed outside a compact set, which is why the theorem says nothing about extrapolation. There exists: it is an existence result about the function class, with no procedure attached. Finitely many: a finite number, with no bound on how large.

it does promise
Representability
For any continuous target on a bounded region and any tolerance, some setting of the weights of a large enough one-hidden-layer network is that close. The architecture is not the obstacle. Whatever your model is failing to do, "the family cannot express it" is almost never the reason.
it does not promise
A size
No bound on the width. In the worst case the number of hidden units required is exponential in the input dimension — in the binary case, distinguishing every one of 2ⁿ input configurations needs O(2ⁿ) degrees of freedom, because there are 2^(2ⁿ) Boolean functions on n bits and selecting one costs 2ⁿ bits. "Finitely many" can mean more units than there are atoms available.
it does not promise
That training finds it
The theorem is about the existence of a point in parameter space. The loss surface is non-convex and gradient descent has no guarantee of reaching that point, or any point near it. Representability and learnability are separate questions and the theorem addresses only the first.
it does not promise
Generalisation
It says a function fitting your training points exists in the family. It says nothing about behaviour at points you have not seen. A network large enough to represent anything is also large enough to represent the wrong thing — there is no universal procedure that examines a training set and returns a function that generalises.
How to use the theorem, in one sentence. Treat it as a licence to stop asking "is my architecture expressive enough?" and start asking the three questions that actually bite: how large must it be, will optimisation find a good setting, and will that setting generalise. §21 answers the first for depth. The second is the training page. The third is bias and variance and §25.
Approximation in practice: sup-error against width, and what happens outside the interval the error really does go to zero on the interval — and the extrapolation really is worthless, which the theorem never denied
The classic misreading. "A one-hidden-layer network can approximate any function, so depth is unnecessary." The theorem gives no bound on the width, and §21 shows the required width can be exponential in the depth you refused to use. "Can be done" and "can be done at a feasible size, found by gradient descent, generalising to new data" are four different claims and the theorem establishes only the first.

21 Depth against width, counted

§08 said units add regions and layers multiply them. Here is the arithmetic, with exact numbers — and with the two bounds correctly labelled, because the direction of the inequality is the whole meaning of the result.

What a "linear region" is, and why counting them is the right measure

A rectified network is piecewise linear: the input space splits into maximal regions on each of which the whole network is a single affine map. Which region a point is in is determined by the on/off pattern of every hidden unit, so counting regions counts distinguishable behaviours. It is the natural complexity measure for this function class, and unlike parameter count it is sensitive to how the parameters are arranged.

The caveat that keeps this honest

Two of them, and both matter. First, this counts what a deep network can do at some parameter setting, not what gradient descent finds — a randomly initialised or trained network achieves far fewer regions than the bound (toggle the fold figure in §08 to random weights and watch the count collapse). Second, and more fundamentally: there is no guarantee that the functions worth learning are the ones with many linear regions. The counting argument shows depth is efficient for functions with repeated, compositional structure. The empirical claim that real-world functions have that structure is a separate, empirical claim — supported by the fact that depth reliably helps, but not proved by any of this.

Depth as a prior. Choosing a deep model is stating a belief about the target: that it decomposes into a composition of simpler functions, or that it is a program with sequentially dependent steps. That is a real assumption and it can be wrong — on tabular data with no compositional structure, gradient-boosted trees routinely beat deep networks, and the reason is that the prior does not fit. Depth is not free capacity; it is a shaped prior over functions.

Controlled evidence that it is depth and not size

The obvious objection to "deeper is better" is that deeper networks are also bigger. The controlled version of the experiment fixes that: hold the parameter count constant and vary how those parameters are distributed. Measured on a multi-digit transcription task, test accuracy rises consistently and monotonically with depth from 3 to 11 layers; and in the control, adding parameters to a shallow network without adding depth is far less effective — the shallow models begin to overfit around 20 million parameters while the deep ones keep improving past 60 million. Same budget, different arrangement, different outcome. That is the empirical form of everything above.

Counting bounds are abstract. Here is a specific function, with an explicit construction, where a deep network needs 2L units and a shallow one provably needs 2ᴸ.

What the sawtooth is and is not evidence for. It is a proof that some functions are exponentially cheaper to represent with depth — the separation is real, explicit and tight. It is not evidence that the functions you care about are like this. The honest position: depth provably helps on functions with self-similar, repeated structure; empirically it helps on images, audio and language; there is no theorem connecting those two sentences.

23 Designing the shape: how many layers, how wide

The theory above says depth is efficient and says nothing about how much of it to use. In practice the shape is found by experiment, but the search space has a known structure and a few positions in it are known to be bad.

What is determined and what is chosen

fixed by the problem, not by youd₀ = the input dimension: 784 for a 28 × 28 grey image, 13 for 13 features d_L = the output dimension: 1 for a scalar regression, 1 logit for binary, K logits for K classes, |V| logits for a language model's vocabulary chosen by youL the number of layers d₁ … d_{L−1} the hidden widths g the hidden activation (§11–§13) the output unit (§14–§19)

Depth: start at one or two, raise it until it overfits

  • For many problems one or two hidden layers is enough, and it is the right place to start. A single hidden layer of a few hundred units reaches above 97% on handwritten digits; two hidden layers with the same total number of units reach above 98%, in about the same training time. That is the depth effect at its smallest, and it is still a real one.
  • For harder problems, raise the depth until the training set starts being overfitted, then stop and add regularisation. Depth is the more effective of the two knobs: in general you get more from adding layers than from adding units per layer.
  • Genuinely hard perception tasks use tens or hundreds of layers — but not fully connected ones, and not trained from scratch. At that scale the layers are convolutional or attentional and the model is almost always adapted from a pre-trained one.
  • Deeper is harder to optimise. That is the real cost, and it is the reason residual connections and normalisation layers exist. Every depth record was unlocked by an optimisation fix, not by a representational discovery.

Width: uniform beats the funnel, and a bottleneck is unrecoverable

It used to be standard to taper the widths into a pyramid — 300, then 200, then 100 — on the theory that many low-level features coalesce into fewer high-level ones. That practice has been largely abandoned: the same width in every hidden layer performs as well or better in most cases, and it leaves one hyperparameter to tune instead of one per layer. Making only the first hidden layer larger than the rest sometimes helps, depending on the data.

The bottleneck argument, and it is the one hard constraint. A layer of width q can output only q numbers. Whatever information the layers below it extracted, only a q-dimensional summary passes through — a layer of two units emits a 2-D representation, so if it is handed something genuinely 3-D, one dimension is destroyed. No amount of capacity above the bottleneck recovers it. This is why over-wide is a much safer error than over-narrow, and why the practical advice is to build slightly larger than needed and control the excess with early stopping and regularisation rather than to hunt for the exactly-right width. Buy the stretchy trousers.
Four shapes under one parameter budget, and what a bottleneck costs the rank readout is the bottleneck argument as a number: information that leaves at layer 3 is not in layer 4

A short, honest procedure

  1. Overfit a tiny subset first. Ten examples, no regularisation, until the loss is near zero. If that fails, the bug is in the pipeline, not the architecture, and no amount of shape-tuning will help.
  2. Start at one or two hidden layers of uniform width, sized in the low hundreds for tabular data.
  3. Add depth until the training loss and validation loss separate. That separation is the signal that capacity is now sufficient.
  4. Then stop growing and start regularising — early stopping, weight decay, dropout, more data.
  5. Do not tune the shape before the learning rate. The learning rate is the single most important hyperparameter and a badly chosen one will make every architecture look equally bad. That comparison, and the schedules that go with it, are the training page's.

24 The inductive bias of an MLP: it has essentially none

This is the section that motivates every later part of this series. A fully connected network makes no assumption about the structure of its input — and that neutrality, which sounds like a virtue, is the reason a convolutional network beats it on images by an enormous margin at a fraction of the parameter count.

The precise statement, and its proof in two lines

permutation equivariance of the input coordinates — row convention throughout (§09)Let P be any permutation matrix on the d input coordinates, so that xP is x with its coordinates permuted. For any MLP with first-layer weights W₁, define a second MLP identical except that W₁′ = PᵀW₁. Then for every x: net′(xP) = net(x) why(xP)·W₁′ = (xP)·(PᵀW₁) = x·(PPᵀ)·W₁ = x·W₁ since P is orthogonal, PPᵀ = I. The first pre-activation is unchanged, so everything after it is unchanged. Shapes, so the argument typechecks: x is (1 × d), P is (d × d), W₁ is (d × h), and W₁′ = PᵀW₁ is (d × h) — the same shape as W₁, with its ROWS permuted. Rows of W₁ are indexed by INPUT COORDINATE, which is why permuting the input is undone by permuting the rows and by nothing else. In the column convention — x a column, z = W₁ᵀx — the same statement reads net′(Px) = net(x) with W₁′ = PW₁, since (PW₁)ᵀ(Px) = W₁ᵀPᵀPx = W₁ᵀx. Both are correct; this page uses the first throughout, as §09 declared. CONSEQUENCE: shuffle the pixels of every image in your dataset by the SAME fixed random permutation, and an MLP's achievable accuracy is EXACTLY UNCHANGED — the optimum simply moves to the permuted weights, with the same loss value. It never knew the pixels were arranged in a grid, so destroying the grid costs it nothing.

Run the same experiment on a convolutional network and its accuracy collapses, because a convolution's entire premise — that nearby coordinates are related and that the same pattern can occur anywhere — has been destroyed. The CNN's loss is exactly the measure of how much prior knowledge it was carrying. Being hurt by the shuffle is the evidence that the architecture knew something true about the data.

The way to read the whole table. Every architecture in this domain is a constrained MLP: the same affine-then-non-linear skeleton, with a restriction imposed on which weights may be non-zero and which must be equal. The restriction is the prior knowledge, expressed as a hard constraint rather than as a soft penalty. A convolution is not a different kind of computation — it is a dense layer whose matrix is banded and tied, which is why every later part of this series can assume this page and build on it rather than starting again.
The scaling-era misreading. "Priors are a crutch; with enough data the unbiased model wins, so use the MLP." The first half is closer to true than it used to be, and the conclusion still does not follow. Weak priors do win at scale — that is the transformer's story against the CNN in vision. But "at scale" means hundreds of millions of examples and a compute budget to match. Below that regime the strong prior is worth more than the flexibility, and the correct question is never "which architecture is better" but "which assumption is true of my data, and do I have enough data to afford to discard it".

25 Over-parameterisation, interpolation, and double descent

Modern networks have far more parameters than training examples, fit the training set exactly, and generalise anyway. That is not what the classical picture predicts, and the resolution changes how the capacity of this function class should be thought about.

The observation

the regimeP ≫ N parameters far exceed training examples training loss → 0 the model INTERPOLATES: it fits every point, including deliberately mislabelled ones test error → small anyway which the classical U-curve does not predict A network with enough capacity to memorise a training set of random labels — which it demonstrably has — nonetheless generalises when trained on real labels. Capacity measured as PARAMETER COUNT therefore does not determine generalisation.

The first half of that claim is directly checkable, and the figure below checks it: take a small classifier, flip a fraction of its training labels at random, and train it. It reaches essentially perfect training accuracy on the corrupted labels every time. Its capacity to memorise is not the binding constraint, at any corruption level — and yet, trained on uncorrupted labels, the very same network generalises.

The classical account of what happens as capacity grows says test error falls, reaches a minimum, and then rises once the model begins fitting noise. Measured across model sizes that U really is there — and then, past the point where the model has just enough capacity to interpolate the training data, the test error falls again, often to below the classical minimum. The peak sits at the interpolation threshold, roughly where the number of parameters equals the number of training points. That curve, and the conditions under which the second descent does and does not appear, are owned by Bias–Variance Tradeoff §08; what matters here is the conclusion it forces about this function class.

Memorisation: the same network fits true labels and randomised labels equally well every number here is measured from a network trained in your browser — the training accuracy barely moves, the held-out accuracy collapses

How to think about it

  • Parameter count is the wrong capacity measure. What matters is the effective complexity of the function the training procedure actually selects, which depends on the optimiser and the initialisation as much as on the architecture.
  • Over-parameterisation changes the space of interpolating solutions. Past the threshold there are many parameter settings that fit the training data exactly, and gradient descent does not choose among them at random — it is biased toward low-norm, "simple" solutions. More parameters means more interpolating solutions to choose from, and therefore a better chance that a simple one is available.
  • The spike at the threshold is a conditioning failure. At exactly the threshold there is essentially one interpolating solution and it is forced to be wild. Either side of it there is slack, and adding even a little regularisation smooths the peak away — which is also why the effect is delicate to reproduce and why its size depends heavily on the feature geometry.
  • The practical rule that follows: do not shrink a model because it has more parameters than data points. Make it comfortably large and control it with early stopping and regularisation — the same conclusion §23 reached from the bottleneck argument, by a different route.
Where this is taught in full. The decomposition of test error into bias and variance, the classical U-curve, learning curves, and the modern double-descent revision are owned by Bias–Variance Tradeoff and specifically its §08. This section covers only what it means for this function class: that the parameter count of an MLP does not bound its generalisation, so "how many parameters" is not the design question §23 makes it look like.

26 Where MLPs actually live in modern models

The fully connected network is not a historical stepping stone that got replaced. It is a component — and in the largest models in use today it holds the clear majority of the parameters.

The position-wise feedforward network inside a transformer

Every transformer block is two sub-layers: attention, which moves information between positions, and a feedforward network, which processes each position independently. That second sub-layer is exactly this page's object — a two-layer MLP with one hidden layer, applied to each of the N·T positions as if they were a batch (§09).

The gated variant, and the 2/3 factor that comes with it. Many recent models replace the FFN with a gated one: FFN(x) = (g(xW₁) ⊙ xV) W₂, with a third matrix V of the same shape as W₁. Three matrices instead of two means 1.5× the parameters at the same d_ff, so implementations shrink the hidden width by 2/3 — d_ff = 8d/3 rather than 4d — to keep the parameter count matched at 8d². When a configuration file reports a hidden size of 11008 for d = 4096, that is 8d/3 rounded to a convenient multiple, and the comparison against a 4d model is parameter-matched by construction.

The pattern, stated once. New architectures almost always innovate on how information moves between positions — convolution, recurrence, attention, message passing, routing — and then hand each position to an MLP for the actual transformation. "MLP" is not a legacy model. It is the default per-element computation of the entire field, and it is where most of the parameters and most of the arithmetic live.
