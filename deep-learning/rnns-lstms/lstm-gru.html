24 The LSTM: a second state whose update is additive

Here is the whole idea in one sentence, before any equations. Add a second state vector whose only update is "multiply by a number near one, then add something", and never pass it through a matrix or a squashing function. Everything else in the LSTM exists to control the two numbers in that sentence.

the LSTM cell, complete — six linesfₜ = σ( hₜ₋₁Wf + xₜUf + bf ) FORGET gate ∈ (0,1)ᵈʰ iₜ = σ( hₜ₋₁Wi + xₜUi + bi ) INPUT gate ∈ (0,1)ᵈʰ gₜ = tanh( hₜ₋₁Wg + xₜUg + bg ) CANDIDATE ∈ (−1,1)ᵈʰ oₜ = σ( hₜ₋₁Wo + xₜUo + bo ) OUTPUT gate ∈ (0,1)ᵈʰ cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ gₜ the CELL STATE hₜ = oₜ ⊙ tanh( cₜ ) the OUTPUT / hidden state the line that matters, isolatedcₜ = fₜ ⊙ cₜ₋₁ + (something) · NO matrix multiplies cₜ₋₁. The operation is ELEMENTWISE. · NO squashing function is applied to cₜ₋₁. It passes through raw. · The multiplier fₜ is in (0, 1) and is PRODUCED BY THE MODEL, per unit, at every step, from the current input and the current output. Compare the vanilla cell, where hₜ₋₁ is multiplied by a matrix AND put through a tanh, both of which are exactly what §17 and §18 objected to.

Two states, and what each is for

StateRangeWho sees itIts job
cₜunboundedOnly the cell itself. It is never passed to the read-out or the next layer directly.Memory. A private accumulator with a linear, gated self-loop. It is allowed to be large, and it often is — values of tens are normal in a trained model.
hₜ(−1, 1)The read-out, the next layer, and all four gates at the next step.Exposure. A bounded, gated view of the memory. The output gate decides how much of the accumulator to reveal, which lets the cell hold something without acting on it yet.

That separation is the second idea in the design and it is easy to miss. The model can carry a fact for two hundred steps in cₜ while hₜ stays near zero the whole time, because oₜ is closed — so nothing downstream is disturbed by the fact being held, and nothing about holding it interferes with the model's ordinary step-to-step behaviour. Then oₜ opens and the fact is available. A vanilla cell has one state that must simultaneously be the memory and the output, and those two jobs have contradictory requirements.

25 Each gate, derived from the job it has to do

The four are not interchangeable and the design is not arbitrary. Each answers a question the previous section's accumulator raises, and the order below is the order in which the questions arise.

gate 1 · the one that matters most
Forget — fₜ ⊙ cₜ₋₁
A leaky unit (§23) has a fixed α. It can hold and it can never clear. The question "when should this accumulator be reset?" has an input-dependent answer — a full stop, a new speaker, a scene change — so make the coefficient a function of the input: fₜ = σ(…). Ablation studies across many architectural variants agree that this is the single most important component; remove it and performance collapses on most tasks.
gate 2
Input — iₜ ⊙ gₜ
Without it the accumulator absorbs every step's candidate, and a hundred steps of irrelevant input drown whatever was being held. The input gate makes writing conditional: iₜ ≈ 0 means "nothing here is worth recording". Note that the candidate gₜ is tanh, not σ — it is a value to be written and can be negative, whereas a gate is a proportion and cannot.
gate 3
Output — oₜ ⊙ tanh(cₜ)
Answers "should the thing I am holding affect my behaviour right now?". Separating holding from acting is what lets a unit carry a fact silently. The tanh around cₜ is a squashing step whose job is to bound what leaves the cell — cₜ itself is unbounded, and feeding an unbounded value into the next layer's affine map is how a network diverges.
not a gate
The candidate gₜ
This is the ordinary recurrent cell — exactly the vanilla tanh(hₜ₋₁W + xₜU + b) of §04, unchanged. Everything the LSTM adds is plumbing around that computation. Seeing this makes the parameter count obvious: four affine maps of the same shape rather than one.

Why sigmoids for the gates and tanh for the values

a gate is a proportion; a value is a quantitygate σ(z) ∈ (0, 1) "keep this fraction" multiplicative value tanh(z) ∈ (−1, 1) "write this amount" additive, signed Swap them and the model breaks in specific ways: · a tanh forget gate can be NEGATIVE, so the accumulator flips sign every step — an oscillator, not a memory. · a σ candidate can never write a negative value, so the cell can only ever count upwards. and the reason the sigmoid's small derivative is not a problem HEREPart 2's table notes max σ′ = 0.25 and calls the sigmoid a bad hidden unit for exactly that reason. A gate is not a hidden unit. Its output is MULTIPLIED into a path rather than passed along one, and the long-range gradient travels through the value fₜ itself, not through σ′. A saturated gate — fₜ ≈ 1 with σ′ ≈ 0 — is a gate that has DECIDED, and it passes the memory gradient perfectly while receiving almost none itself. That is a feature: it makes the decision stable.
The intuition that misleads. "The gates learn to open and close like switches, so I can read the model by looking at them." Some units do that; most do not. In a trained LSTM a minority of units have forget gates that genuinely saturate near 0 or 1 and behave like latches, and those are interpretable and often correspond to something nameable. The majority sit at intermediate values and act as leaky integrators with learned, mildly input-dependent time constants — much closer to §23's leaky unit than to a switch. Both behaviours are useful and only the first is the story usually told.

26 The constant error carousel, derived — and then measured, with an unwelcome result

The standard argument for the LSTM is one line: ∂cₜ/∂cₜ₋₁ = fₜ, so with fₜ ≈ 1 the gradient passes unchanged, and there is no matrix and no exponential. The argument is correct and incomplete, and the incompleteness is worth more than the argument.

The derivation, done properly

the direct path along the cell statecₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ gₜ Holding the gates fixed for a moment, the Jacobian of that map is ∂cₜ/∂cₜ₋₁ = diag( fₜ ) ← DIAGONAL and over d steps the composition is still diagonal: ∂cₜ/∂cₜ₋ᵈ = diag( fₜ ⊙ fₜ₋₁ ⊙ … ⊙ fₜ₋ᵈ₊₁ ) and THAT is the structural difference, stated properlyA DIAGONAL matrix has eigenvalues equal to its own entries. So: · There is no matrix POWER. There is no spectral radius. There is no eigenvector to align with, no non-normality, no transient. · Each unit gets its OWN product of scalars — its own time constant — and they do not interact. One unit can hold something for 500 steps while its neighbour resets every step. A vanilla cell cannot do this: one ρ(W) governs every unit at once. · The product is a product of numbers in (0, 1), so it is MONOTONE and cannot oscillate, cannot explode, and decays only as fast as the MODEL CHOOSES. That last clause is the whole design. The vanilla cell's decay rate is a property of its weights. The LSTM's is an OUTPUT of the model, produced fresh at every step from the data.

The gates are not really fixed, of course, and the exact one-step Jacobian has a second term, because cₜ₋₁ reaches the gates at step t through hₜ₋₁ = oₜ₋₁ ⊙ tanh(cₜ₋₁):

the exact one-step Jacobian of the cell state∂cₜ ∂cₜ ∂hₜ₋₁ ────── = diag(fₜ) + ────── · ────── ∂cₜ₋₁ ∂hₜ₋₁ ∂cₜ₋₁ └───┬───┘ └──────────┬──────────┘ the CAROUSEL everything else: through the four — diagonal gates, and therefore through the four weight matrices. NOT diagonal. with ∂hₜ₋₁/∂cₜ₋₁ = diag( oₜ₋₁ ⊙ (1 − tanh²(cₜ₋₁)) ), which is small whenever the output gate is closed or the cell state is large.

The claim that does not survive the measurement. "An LSTM does not have the vanishing-gradient problem." An LSTM whose forget gate is initialised at zero bias has a WORSE long-range gradient than a vanilla RNN. Read row 7 against row 1: at a distance of sixty steps the LSTM at b_f = 0 delivers 3.5 × 10⁻¹³ and the vanilla cell at ρ = 0.9 delivers 9.8 × 10⁻⁷ — the LSTM is 2.8 million times worse. 27 The forget-gate bias: one line of initialisation, and the whole benefit

§26's table says the LSTM's advantage is entirely conditional on the forget gate being open. So open it — at initialisation, before any data is seen. This is a one-line change that has been standard advice since shortly after the forget gate was introduced, and the measurement above is the reason.

the whole interventionbf ← 1 (instead of 0) so fₜ starts at σ(1) = 0.731 and the per-step memory factor at initialisation goes from σ(0) = 0.500 → half the memory gone every step to σ(1) = 0.731 → a time constant of 1/ln(1/0.731) = 3.2 steps which is still short, but the MEASURED effect is much larger than that suggests, because it is the gradient that matters and the gradient is what lets the model learn to raise the gate further. what each bias buys, at a distance of 60 steps (from §26)bf = 0 3.47e−13 the additive path is off bf = 1 1.53e−06 4.4 million times more gradient than bf = 0 bf = 2 2.67e−02 bf = 3 4.52e−01 essentially no decay at all over 60 steps bf = 5 2.59e+00 GROWING — and now clipping matters again

Why 1 and not 5

Because a forget gate at σ(5) = 0.993 is a cell that cannot clear, and §25 argued that clearing is the forget gate's actual job. A large bias buys gradient flow at initialisation and costs the model the thing it was for; it also puts the cell back in the exploding regime, as the last row shows. The conventional choice of 1 is a compromise that has held up: enough to switch the additive path on, small enough that a modest weight update can close the gate when the task calls for it. Bias values of 1 to 2 are all defensible and the difference between them is small next to the difference between either and 0.

Where this bites in practice. Framework defaults differ, and the difference is invisible. Some initialise the forget-gate bias to one automatically; some initialise every bias to zero; and some carry two bias vectors per gate (§28) and add one to each, which doubles whatever you set. If you are reproducing a result and your LSTM will not learn a dependency the paper says it learned, print σ(b_f) at initialisation before changing anything else. It is a one-line check and §26's table is what is at stake.

29 Peephole connections, and the variants that were tried

The LSTM as it is used today is not the LSTM as it was first published: the forget gate was added three years later, and the peephole connections a year after that. A great many further variants have been proposed and systematically compared, and the result of those comparisons is worth stating plainly because it saves a lot of time.

Peephole connections

The three gates decide what to do with the cell state, and in the plain cell they cannot see it — they read only hₜ₋₁, which is the cell state after the output gate has filtered it. If the output gate is closed, hₜ₋₁ ≈ 0 and the gates are deciding blind. A peephole adds a direct connection from the cell state to each sigmoid gate:

peephole LSTM — the three sigmoid gates gain one term eachfₜ = σ( hₜ₋₁Wf + xₜUf + cₜ₋₁Zf + bf ) iₜ = σ( hₜ₋₁Wi + xₜUi + cₜ₋₁Zi + bi ) oₜ = σ( hₜ₋₁Wo + xₜUo + cₜ Zo + bo ) ← note cₜ, not cₜ₋₁ The candidate gₜ gets NO peephole: it is a value, not a decision. the ordering detail that is easy to get wrongfₜ and iₜ are needed BEFORE cₜ exists, so they peep at cₜ₋₁. oₜ is needed AFTER, so it peeps at the FRESH cₜ — which is the whole point, since the output gate's job is to decide how much of the state it is about to expose, and it should see the state it is exposing. the cost, and the two forms of ZZ DIAGONAL (the original) 3m parameters each unit peeps only at ITSELF. This is the form that is normally meant. Z FULL (m × m) 3m² parameters rarely used. At m = 128 that is 384 extra parameters against 219 648 — under 0.2%. The intervention is essentially free, which is why it was worth trying.

Peepholes were introduced to let the cell learn precise timing — counting a fixed number of steps, measuring an interval — which needs the gates to react to the state's actual value rather than to a gated view of it. On tasks with that character they help clearly. On language and most sequence labelling they do not, and modern implementations mostly omit them.

The honest summary of a decade of variants. Large systematic studies — thousands of architectural mutations evaluated across several task families — did not find a variant that clearly beats both the LSTM and the GRU across the board. What they did find is that (a) the forget gate is essential, (b) initialising its bias to one closes most of the gap between the vanilla LSTM and anything more elaborate, and (c) the remaining differences between reasonable gated cells are smaller than the differences caused by hyperparameter tuning. That is a genuinely useful negative result: if a gated cell is not working, the answer is almost never a different gate topology.

30 The GRU: the same idea with one state and two gates

The gated recurrent unit asks which parts of the LSTM are load-bearing and removes the rest. It drops the separate cell state, couples the input and forget gates into one, and drops the output gate, leaving two gates and three matrix pairs instead of four.

the GRU, completezₜ = σ( hₜ₋₁Wz + xₜUz + bz ) UPDATE gate rₜ = σ( hₜ₋₁Wr + xₜUr + br ) RESET gate cₜ = tanh( (rₜ ⊙ hₜ₋₁)Wc + xₜUc + bc ) CANDIDATE └─────┬─────┘ the reset gate acts on the state BEFORE the matrix, not on the result — this is the one place the GRU is not just a simplified LSTM hₜ = zₜ ⊙ cₜ + (1 − zₜ) ⊙ hₜ₋₁ a CONVEX COMBINATION the carousel, for the GRU∂hₜ/∂hₜ₋₁ = diag( 1 − zₜ ) + (everything through cₜ and the gates) └─────┬─────┘ the additive path. Same structure as the LSTM's diag(fₜ), with the SAME consequence: diagonal, so no matrix power, and per-unit time constants. So the GRU's "forget gate" is 1 − zₜ, and holding a value means zₜ → 0.
A polarity trap that costs an afternoon. Two opposite conventions for zₜ are both in wide use. Above, zₜ is how much new, so carrying the old state means zₜ → 0. Several standard references and most framework implementations write hₜ = zₜ ⊙ hₜ₋₁ + (1 − zₜ) ⊙ cₜ instead, in which zₜ is how much old and carrying means zₜ → 1. The two describe the same model — the gate simply learns the opposite sign — but every statement about gate values, every initialisation bias and every interpretability plot flips. This page uses the first convention throughout and says so at every point where a gate value is printed. Check which one your code uses before you set a bias.

What the GRU drops, and what it costs

LSTM hasGRU insteadWhat is actually lost

Independent fₜ and iₜCoupled: keep 1 − zₜ, write zₜThe ability to erase without writing, or write without erasing. In practice the two decisions are usually correlated and this costs little.
An output gate oₜnoneThe state is exposed raw. Note it is also not squashed — the LSTM's tanh(cₜ) disappears, but the GRU's state is a convex combination of a previous state and a tanh, so it stays in (−1, 1) by induction. Bounded for free.
Four matrix pairsThree25% fewer parameters and 25% less arithmetic at the same width — and, in the measurements of §31, faster convergence too.
The reset gate is the GRU's one genuinely distinct idea. It applies inside the candidate's affine map: (rₜ ⊙ hₜ₋₁)Wc, not rₜ ⊙ (hₜ₋₁Wc). That means the reset gate controls which parts of the past are allowed to participate in computing the new candidate, rather than scaling the result. With rₜ = 0 the candidate is tanh(xₜUc + bc) — the cell reads the current input as though the sequence had just started, which is exactly the operation a model needs at a sentence boundary. There is no LSTM gate that does this; the LSTM's gates all act on completed quantities.

31 Vanilla against GRU against LSTM, on a task where the difference is visible

Every claim so far about gates has been about the gradient. This section closes the loop and asks whether the gradient difference turns into a learning difference, on a task built so that nothing else can explain the result.

The task

the adding problem, in fullTwo input channels, T steps. channel 0 a fresh U(0,1) value at every step — pure distraction channel 1 zero everywhere except at TWO marked steps, one drawn from the first tenth of the sequence and one from anywhere target read out at the LAST step only: the SUM of the two marked values from channel 0. Everything about the task is designed to remove alternative explanations: · the two marked values are typically far apart, so the model MUST carry the first one across many steps; · the distractors are the SAME distribution as the signal, so the model cannot separate them by magnitude, only by the marker; · there is one loss, at the end, so the ONLY gradient path to the first marker is the recurrence — exactly the object §26 measured; · the trivial predictor "always answer 1.0" has an MSE of exactly 2 · Var[U(0,1)] = 2/12 = 0.16667, which is the line to beat.

The result, at equal parameter count

Comparing cells at equal hidden width gives the LSTM four times the parameters (§28), which is not a comparison of architectures. The failure is not a capacity failure.
vanilla
Fails from T = 20, and more budget does not help
Solves T = 10. At T = 20 and beyond it never beats the trivial predictor at any of the budgets tried, and at T = 30 with 600 steps and at T = 50 with 1500 it is worse than the trivial predictor — the run diverged rather than plateaued. The classic reported failure point for vanilla recurrent networks is dependencies of ten to twenty steps, and that is exactly where this reproduces it.
GRU
Solves every length, and fastest
Below 0.0022 at every length at 600 steps, including T = 80, with the smallest hidden width of the three. On this task the GRU is not "comparable to the LSTM"; it is better, and it converges in less than half the steps.
LSTM
Solves every length — but needs more than twice the budget at long ones
At 600 steps it matches the GRU up to T = 30 and then fails outright at T = 50 and T = 80, sitting at the trivial predictor's error. At 1500 steps it solves both. The gate advantage is real; the LSTM simply has four matrix pairs to fit with the same budget and takes longer to fit them.
The reporting failure this table is designed to prevent. Run the same experiment at 600 steps only, and you would write "the LSTM fails on long sequences". The LSTM solves both lengths; it needs 2.5 times the optimisation budget to do so. An architecture comparison at a single fixed step count is a comparison of convergence speed wearing the costume of a comparison of capability, and it is the most common way sequence-model benchmarks mislead. Every row here is reported at two budgets for exactly that reason.
What this does and does not license you to conclude. It shows that on a task engineered to isolate long-range credit assignment, the gated cells succeed where the vanilla cell fails, at matched parameters, and that the failure is not one of capacity. It does not show that the GRU beats the LSTM in general — one synthetic task, one hyperparameter setting, one seed family. The published systematic comparisons (§29) find no consistent winner between the two across task families, and the differences they do find are smaller than the differences caused by tuning. The safe reading is: use either gated cell, do not use a vanilla cell for anything that must remember, and tune before you conclude.
