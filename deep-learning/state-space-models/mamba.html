Mamba: Linear-Time Sequence Modeling with Selective State Spaces

A linear state space model that lets its step size Δ and its read/write matrices B, C depend on the current token. That one change lets a recurrence decide what to keep and what to ignore, which time-invariant SSMs cannot do. It also rules out the convolution trick those models train with, so the paper pairs it with a fused, hardware-aware scan. This page works through the motivation and the zero-order-hold discretization, then shows why Δ is a generalised RNN gate. After that come the kernel, the block, the results on text, DNA and audio, the ablations, and the limits the paper states.

01 The motivation: compress the context, but choose what goes in

The paper frames sequence modelling as compressing the context into a state. How well a model does depends on how well that state summarises the past. How fast it runs depends on how small the state is.

attention
Does not compress at all
It keeps every past key and value, the KV cache. That makes it effective, since any token can be looked up exactly. It is also expensive: per-step inference cost and memory grow with the context, and training is quadratic in length (the hub's cost chart).
recurrences & LTI SSMs
Compress, but blindly
A fixed-size state means constant-time steps and linear-time training. But a time-invariant model applies the same dynamics to every token. It cannot decide, based on what a token is, to store it or to skip it.
selective SSM
Compress, selectively
Make the dynamics a function of the input. The state can then ignore filler, latch onto relevant tokens, and reset when the context changes. It stays fixed-size and linear in length.

The paper's central claim follows from this framing. Efficiency vs effectiveness is a question of state size, and the way to get a small but good state is selection. Selection means input-dependent control over how information enters and leaves the state. Everything else on this page either implements selection (§04–§05) or pays for what it costs (§07).

02 Background: continuous SSM → discretization → recurrence ≡ convolution

The hub's recurrence starts already discrete. Selection only makes sense if you know where the discrete matrices come from: a continuous system sampled with a step Δ.

continuous-time state space model (per input channel)h′(t) = A h(t) + B x(t) h(t) ∈ ℝᴺ, x(t), y(t) ∈ ℝ y(t) = C h(t) A ∈ ℝᴺˣᴺ, B ∈ ℝᴺˣ¹, C ∈ ℝ¹ˣᴺ zero-order hold (input held constant over each step of length Δ)Ā = exp(ΔA) B̄ = (ΔA)⁻¹ (exp(ΔA) − I) · ΔB the discrete recurrence that is actually computedhₜ = Ā hₜ₋₁ + B̄ xₜ yₜ = C hₜ

Where the ZOH formulas come from: hold x fixed over one step and solve the linear ODE exactly. You get h(t+Δ) = e^(ΔA) h(t) + (∫₀^Δ e^(sA) ds) B x, and the integral evaluates to A⁻¹(e^(ΔA) − I). For diagonal A (what S4-style models and Mamba use) everything is elementwise. Each state coordinate n has its own decay Āₙ = exp(Δ aₙ), and aₙ < 0 keeps Āₙ ∈ (0, 1), so the recurrence is stable.

A simplification you will meet in code (general knowledge, not from the paper's text). The reference implementation keeps Ā = exp(ΔA) but replaces B̄ with the first-order B̄ ≈ ΔB. For small ΔA the two agree, because (e^z − 1)/z ≈ 1. The worked derivation in §05 uses the exact ZOH form, which is what makes the gate come out exactly.

Linear time invariance: the convolution view

When Δ, A, B, C are the same at every step, which is the linear time-invariant (LTI) case, the recurrence can be unrolled from h₀ = 0:

unrolling an LTI SSM gives one long, fixed convolution kernelyₜ = C B̄ xₜ + C Ā B̄ xₜ₋₁ + C Ā² B̄ xₜ₋₂ + … = ∑ₖ C Āᵏ B̄ · xₜ₋ₖ y = x ∗ K̄ K̄ = (CB̄, CĀB̄, CĀ²B̄, …, CĀᵏB̄, …)
  • Two ways to compute the same model. In training the whole sequence is known, so you build K̄ once and apply it as a parallel (FFT-able) convolution. In generation you step the recurrence and keep only hₜ. This duality is how S4-family models train in parallel and still decode in constant time per token.
  • The catch is in the name. The weight on xₜ₋ₖ is CĀᵏB̄. It depends only on the lag k, never on what xₜ₋ₖ or xₜ is. An LTI model can learn where to look, at fixed offsets, but never what to look at.
  • S4 in one line. S4 is a structured LTI SSM: a carefully initialised (HiPPO-style) A, applied independently to each of D channels, trained through K̄. Mamba keeps the SSM skeleton and the per-channel structure and drops the time invariance.

03 Two synthetic tasks that time invariance cannot solve

The paper uses two toy tasks to show exactly what a fixed kernel lacks.

copying vs selective copying
Remember the tokens, not the positions
In standard Copying, the tokens to memorise sit at a fixed spacing, so a time-aware model only needs the right lags. An LTI convolution with the right kernel solves it. In Selective Copying, the same tokens are scattered among filler tokens at random positions. To output them in order, the model must pass over filler and store the content tokens, wherever they fall. That decision depends on content, and no fixed K̄ can make it.
induction heads
Recall what followed a cue
After a special token appears, the model must later output the token that followed it, as in "Harry Potter … Harry → Potter". This is associative recall, the mechanism behind much of in-context learning in language models. The model must recognise the cue by its content and store the next token, at whatever distance.

Both tasks need the same capability: let the token decide what happens to the state. Filler should leave the state alone. A relevant token should be written in, overwriting older content if needed. The figure in §05 makes this concrete with a one-dimensional state, and §09 gives the numbers: on Selective Copying an LTI S4 layer reaches 18.3% while the selective version reaches 97.0%.

04 The selection mechanism: S4 vs S6, shape by shape

The whole change is to give three parameters a length dimension: B, C and Δ become functions of the input x. The paper calls the result S6, an S4 model with selection, computed with a scan.

  • Shared vs per-channel. B and C have shape (B, L, N), so at a given token they are shared across all D channels. Δ has shape (B, L, D) and varies per channel. In the appendix the Linear_1 generalises to a low-rank projection Linear_D(Linear_R(x)) with R a small fraction of D. The ablation in §11 shows that widening it helps.
  • Why A stays fixed. A only ever acts through Ā = exp(ΔA). Once Δ is selective, Ā is already input-dependent, so making A selective too would add little. The paper notes it could be, and expects similar performance.
  • Why Δ matters most. Δ is the only parameter that controls both how much old state survives (Ā) and how much of the new input is written (B̄). §05 makes that exact, and §11 confirms it: Δ alone is the single most useful thing to make selective.
  • The price. Ā, B̄ are now (B, L, D, N): N times larger than the input and different at every step. There is no single kernel K̄ to build, so the convolution mode is gone. That is the problem §07 solves.

05 Δ is a generalised RNN gate (Theorem 1, worked out)

Strip the selective SSM to its smallest case and it becomes a classic gated recurrence. This is the cleanest way to see what selection does.

set N = 1, A = −1, B = 1, s_Δ = Linear(x), softplus for the Δ mapΔₜ = softplus(zₜ) zₜ = Linear(xₜ) Āₜ = exp(−Δₜ) B̄ₜ = (ΔA)⁻¹(exp(ΔA) − 1)·ΔB = (−Δₜ)⁻¹(e^(−Δₜ) − 1)·Δₜ = 1 − e^(−Δₜ) the identity that closes it: exp(−softplus(z)) = 1 / (1 + eᶻ) = 1 − sigmoid(z)gₜ = σ(zₜ) = σ(Linear(xₜ)) Āₜ = 1 − gₜ B̄ₜ = gₜ hₜ = (1 − gₜ) · hₜ₋₁ + gₜ · xₜ

That is the gated update from the GRU, with a single gate playing both the forget role and the input role. Read it in terms of Δ:

  • Large Δ (g → 1): reset and focus. Ā → 0 wipes the old state and B̄ → 1 writes the current token in. The model "spends a long time" on this input.
  • Small Δ (g → 0): hold and ignore. Ā → 1 keeps the state untouched and B̄ → 0 lets the token through without effect. The input is treated as a negligible blip in continuous time.
  • The general case is richer than one gate. With N > 1, each state coordinate has its own aₙ, so one Δ produces a whole spectrum of decay rates. B and C separately choose which coordinates a token writes to and is read from. The paper's interpretation: Δ is a discretization step, and selecting it means choosing per token whether to persist the state or to attend to the input.
Selection playground: a scalar SSM that should hold the most recent signal token with one fixed Δ, filler either washes the state out or dilutes it; let Δ depend on the token and the state latches
  • What the figure computes. It runs exactly the Theorem 1 recurrence: Āₜ = e^(−Δₜ), B̄ₜ = 1 − e^(−Δₜ), hₜ = Āₜhₜ₋₁ + B̄ₜxₜ. Signal tokens carry values in ±[0.3, 1]; filler tokens carry noise of the chosen amplitude. In selective mode Δ is a stand-in for softplus(p + s_Δ(xₜ)) with a learned projection that recognises signal tokens. The two sliders are the values that projection would output.
  • The LTI dilemma is visible in the "best fixed Δ" readout. A large Δ copies every token, filler included. A small one averages everything into mush. Every intermediate value trades one failure for the other. Turn filler noise to zero and the problem remains: filler with value 0 still pulls the state toward zero unless Δ can be zero on filler alone.
  • This is a 1-D toy. Selective copying needs several tokens held at once. A real layer gets that from N state coordinates per channel, across D = E·d_model channels, with B and C choosing where each token is written and read.

06 What selection buys: three behaviours a fixed kernel cannot have

variable spacing
Filter out filler
Skip noise tokens between the relevant ones, such as "um"s in speech or padding and filler in text. In the playground this is Δ ≈ 0 on filler.
filtering context
Longer context stops hurting
Many sequence models fail to improve with more context, because irrelevant history pollutes the state. A selective model can drop it at any time. The paper reports performance improving monotonically with context length, on DNA and audio up to sequences of a million (§09).
boundary resetting
Wipe state at document breaks
When independent sequences are packed together for training, an LTI model bleeds information across the boundary. A selective model can fire a large Δ at the boundary (Ā → 0) and start clean.

The paper also gives each parameter a role. B decides whether a token enters the state, and C decides whether state content reaches the output. Both work on content, the way a token's representation picks what it interacts with. Δ controls the balance between remembering and focusing on the present, as §05 showed.

07 The hardware-aware algorithm: never write the big state to HBM

Selection removes the convolution mode, so training must run the recurrence over the time-varying (B, L, D, N) tensors. Done naively, that means storing a state N times larger than the activations. The fix: keep the expanded state in on-chip SRAM, fuse discretize + scan + readout into one kernel, use a parallel scan, and recompute states in the backward pass.

Where the cost really is

A GPU has a large but slow off-chip memory (HBM) and a small, fast on-chip SRAM (GPU architecture). Apart from matrix multiplies, most deep-learning operations are bound by memory bandwidth, not FLOPs. The scan does only O(BLDN) FLOPs, linear in L. The danger is the bytes. Computing Ā, B̄ in one op, writing them to HBM, and reading them back for the scan moves (B, L, D, N) tensors through HBM several times.

the fused selective-scan kernel1. read Δ, A, B, C (and x) from HBM → SRAM O(BLD + BLN + DN) bytes 2. in SRAM: discretize Ā = exp(ΔA), B̄ = f(Δ, B) (B, L, D, N) — never leaves the chip 3. in SRAM: parallel scan hₜ = Āₜ hₜ₋₁ + B̄ₜ xₜ 4. in SRAM: yₜ = Cₜ hₜ 5. write y (B, L, D) back to HBM effect, as reportedmemory IO reduced by a factor ≈ N → 20–40× faster than a standard (PyTorch) scan faster than FlashAttention-2 beyond sequence length 2K; up to 7× faster than attention at 32K (N = 16, A100)

A parallel scan for a recurrence that is not a convolution

A recurrence looks inherently sequential. But each step h ↦ aₜh + bₜ (with aₜ = Āₜ and bₜ = B̄ₜxₜ) is an affine map, and composing affine maps is associative. So the prefix compositions, which are exactly the states hₜ, can be computed by a parallel prefix scan in O(log L) depth. The paper uses a work-efficient variant. The general algorithm is on the parallel scan page.

the associative operator (apply the earlier step first, then the later one)(a₂, b₂) ∘ (a₁, b₁) = (a₂a₁, a₂b₁ + b₂) check: a₂(a₁h + b₁) + b₂ = (a₂a₁)h + (a₂b₁ + b₂) identity element (1, 0) prefix (aₜ,bₜ) ∘ … ∘ (a₁,b₁) applied to h₀ = 0 gives hₜ = its b-component
Parallel scan over the affine steps (aₜ, bₜ) of an 8-token selective recurrence step through the stages; every algorithm ends with the same hₜ, they differ in depth and total work

Recomputation instead of storage

Backpropagation normally needs the intermediate states. Storing the (B, L, D, N) states would bring back exactly the memory the fusion avoided. Instead the backward pass recomputes them: it reloads Δ, A, B, C from HBM and reruns the scan in SRAM. Recomputing is cheaper than reading a tensor N times larger. The same trade is used for the activations around the scan, so the whole selective SSM layer has the same memory requirement as an optimised Transformer with FlashAttention. The appendix measurement at 125M scale gives 4.6 GB for the Transformer (FlashAttention-2) vs 4.8 GB for Mamba at batch size 1, and 34.5 GB vs 38.2 GB at batch 32. This is the same IO-aware reasoning as FlashAttention; the general technique is kernel fusion.

08 The Mamba block: H3 and a gated MLP merged into one

The paper simplifies the usual pattern of an SSM layer followed by an MLP block. It merges the H3 block (an SSM wrapped with a short convolution and multiplicative gating) and the gated MLP into a single homogeneous block. That block is repeated, with residual connections and normalization, like a Transformer's blocks.

So a Mamba LM with twice as many layers as a Transformer has about the same parameter count. That is why Mamba models at a given width and size have twice the layer count. For example, the 130M model is 24 layers at width 768, where a GPT-3-style 125M Transformer has 12 (layer counts are general knowledge of the released configurations). The selective part (Δ, B, C projections and A) is a few percent of the block, so selection is cheap in parameters. Its cost is in compute and memory traffic, which is what §07 handles. The skip term D·x (+ D·xₜ in the hub's recurrence) is part of the reference implementation.

Induction heads: length extrapolation

  • Trained at sequence length 256, Mamba solves the task perfectly up to length 1,048,576 (2²⁰), about 4000× its training length.
  • No other method tested generalises beyond 2× its training length. H3 and Hyena degrade, and attention variants run out of memory at long lengths (they were tested to 16384).
  • This is what Δ buys. The state is written on the cue and on the token after it and is held through everything else, so the distance between them does not matter.

Language modelling on the Pile

Under a Chinchilla-style protocol from about 125M to 1.3B parameters, Mamba is the first attention-free model to match a strong Transformer++ recipe. That baseline, in general-knowledge terms, is a Transformer with rotary embeddings, SwiGLU MLPs, RMSNorm, no biases and a higher learning rate. 10 Speed and memory: training and inference

training kernel
20–40× over a naive scan
The fused scan vs a standard PyTorch scan implementation. It is faster than FlashAttention-2 beyond length 2K and up to 7× faster than attention at 32K (N = 16, A100). FLOPs are O(BLDN), linear in L.
inference throughput
~5× a same-size Transformer
With no KV cache the per-sequence state is small, so many more sequences fit in a batch. That is where most of the throughput gain comes from. Each generation step takes constant time, whatever the context length.
training memory
Comparable, not lower
Thanks to fusion and recomputation, memory is on par with a FlashAttention-2 Transformer: 4.6 GB (Transformer) vs 4.8 GB (Mamba) at 125M, batch 1, and slightly more than the Transformer at every batch size reported.

The asymmetry is worth stating plainly. In training, Mamba's win is asymptotic in L: at short lengths a tuned attention kernel is competitive. In inference the win is structural. The KV cache grows with every generated token, while the Mamba state is fixed at D·N (plus a few conv taps) per layer. The calculator in §07 shows the gap.

12 Limitations the paper states, and one it does not

no free lunch
Continuous vs discrete
Selection helps discrete, information-dense data (text, DNA), but it can hurt where LTI SSMs excel. On raw audio waveforms the paper finds that selection hampers performance. Time-invariant dynamics are a good inductive bias for smooth signals.
affordances
Downstream use untested
Whether Mamba LMs support the same downstream affordances as Transformers, such as fine-tuning, adaptation, prompting, in-context learning and RLHF, is left open.
scale
Below ~3B parameters
All language experiments are below about 3B parameters. Behaviour at larger scale, and the engineering needed to get there, are unknown.
post-paper, general knowledge
Weaker exact recall
Later work, not this paper, found that fixed-state models lag attention on tasks that need exact retrieval of arbitrary earlier tokens. Examples are long-context copying and multi-query associative recall. A finite state cannot hold everything. This is why later designs interleave attention layers with SSM layers (the hub's comparison).

13 Common misreadings

"Mamba is a long convolution, like S4." No. Selection breaks the convolution. With Δ, B, C varying per token there is no single kernel K̄. Mamba trains with a parallel scan over the recurrence (§07). Its short causal conv1d (§08) is a separate, tiny local filter, not the SSM.
"A, B and C are all input-dependent." A is a fixed parameter. Δ, B and C are selective. The effective transition Ā = exp(ΔA) does vary per token, but only through Δ (§04).
"Selection is free: strictly better than LTI." Not in compute and not on every modality. It costs the convolution mode and needs a custom fused kernel to be practical. It is also a worse inductive bias for raw audio, where the paper finds LTI layers do better (§12).
"Recurrent, so it trains sequentially like an RNN." The recurrence is linear in h, so it is a scan. Affine steps compose associatively, so training runs in O(log L) depth on parallel hardware (the scan figure in §07). Only generation is step by step, and there each step costs a constant amount.
"No KV cache means no inference memory." There is still a state, but its size is fixed. It is D·N numbers per layer (plus conv taps), independent of context length. Compare it with the cache in the §07 calculator.
"Linear time means it is always faster than attention." The reported crossover is around length 2K. Below that, FlashAttention-2 is competitive. The large training wins come at long sequences, and the large inference win comes from batch size, not from per-token FLOPs (§10).

14 Takeaways

  • Sequence modelling is compressing context into a state. Attention does not compress. LTI SSMs compress but cannot choose by content. Selection is the missing piece.
  • S6 makes Δ, B, C functions of the token: B, C are (B, L, N), Δ is (B, L, D), and A stays a parameter. Time invariance, and with it the convolution mode, is gone.
  • Δ is a gate. With N = 1, A = −1, B = 1 and ZOH, hₜ = (1 − gₜ)hₜ₋₁ + gₜxₜ with gₜ = σ(Linear(xₜ)). Large Δ resets and writes; small Δ holds and ignores.
  • The hardware-aware scan keeps the (B, L, D, N) state in SRAM, fuses discretization, scan and readout, uses a work-efficient parallel scan, and recomputes in the backward pass. The result is 20–40× over a naive scan and memory on par with FlashAttention-2.
  • The Mamba block merges H3 and the gated MLP: about 3ED² parameters, so two blocks ≈ one Transformer block.
  • Results: it solves Selective Copying, extrapolates induction heads to 2²⁰, matches Transformer++ on the Pile, and Mamba-2.8B matches Transformers twice its size. It is better with longer context on DNA and audio, and gives about 5× inference throughput.
  • Limits: selection can hurt continuous signals; it is untested beyond about 3B parameters and for downstream affordances; exact recall over long contexts is a later-identified weakness.
