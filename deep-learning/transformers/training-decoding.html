24 The training recipe (1): teacher forcing with the causal mask — one forward pass, every position's loss

A decoder is trained to predict the next token, and the mask is what lets it be trained on all next tokens of a sequence in one pass. The recipe is the shift by one, the mask, and the mean over positions; the cost is the exposure bias the RNN page's teacher-forcing section named, which a decoder inherits unchanged.

the shift, the mask, the losssequence t₀ t₁ t₂ … t_{n−1} one document, or a chunk of one input rows X = [t₀, t₁, …, t_{n−2}] positions 0 … n−2 targets y = [t₁, t₂, …, t_{n−1}] the SAME tokens, shifted by one mask causal: position i reads 0 … i, so its prediction of yᵢ = tᵢ₊₁ cannot see tᵢ₊₁ loss L = (1/n′) ∑ᵢ −log p(yᵢ | t₀ … tᵢ) n′ = the positions that carry a target ONE forward pass produces every p(yᵢ | ·) at once — n′ supervised predictions from n tokens — because the mask makes each row's computation exactly what it would have been had the model been run on the prefix alone. DL.tfLoss(m, idx, tgt) is this line, with tgt[i] = −1 for the positions that carry no target (a prompt, padding). the equivalence that makes it legitimate, and the bias it leavescausal masking ⇒ logitsᵢ( t₀ … t_{n−1} ) = logitsᵢ( t₀ … tᵢ ) exactly, at every layer (§18) so training on the full sequence with the mask IS training on every prefix separately, at about 2/n of the cost (n tokens pushed through once, instead of 1 + 2 + … + n). but every prefix is the TRUE prefix. At inference the prefix is the model's own output, and a model that has only ever conditioned on correct prefixes has never learned to recover from an incorrect one — exposure bias. The figure measures it on the trained model: accuracy when teacher-forced against accuracy when fed its own predictions — no gap once a task is solved (the model's own outputs ARE the true tokens); a gap on a partly trained model (at 60 steps: 40% teacher-forced against 35% free-running).

Two details in the recipe are transformer-specific. Documents are packed: to keep every row of the batch at the trained context, several documents are concatenated with a separator, and the causal mask is either left as it is (a token may read the previous document — cheap, and at scale found to cost little) or blocked at document boundaries (a block-diagonal causal mask, built from the same additive machinery). The loss is a mean over positions, not over sequences, so a long document contributes more than a short one, and the per-position losses are not equal: the first positions of a document have little context and high loss, later positions less. The figure plots the per-position loss of the trained copy model, and it is the shape every language-model loss curve has along the sequence — high where there is nothing to condition on, low where the answer is determined.

25 The training recipe (2): label smoothing — the target it really trains on, and the loss floor it creates

The 2017 recipe trained against a target that put 0.9 on the correct token and spread 0.1 over the rest. That changes what "perfect" means: the loss can no longer reach zero, the optimal logit gap is finite, and the reported training loss must be read against a floor that this section derives.

the smoothed target and the loss against itone-hot q = e_k L = −log p_k smoothed q_ε = (1 − ε)·e_k + ε/V · 1 L_ε = −∑ⱼ q_ε[j] log pⱼ = (1 − ε)(−log p_k) + (ε/V) ∑ⱼ (−log pⱼ) i.e. the usual loss, damped by (1 − ε), PLUS a penalty on making ANY token improbable the floor — the loss when p = q_ε exactlyL_ε(p = q_ε) = H(q_ε) = −(1 − ε + ε/V)·log(1 − ε + ε/V) − (V − 1)·(ε/V)·log(ε/V) ε = 0.1, V = 50 257: H = 0.0948 + 1.3127 = 1.408 nats ← the loss cannot go below this ε = 0.1, V = 32 000: 1.363 nats ε = 0.1, V = 8: 0.467 nats ε = 0: 0 and the optimal logit gap between the correct token and any other is FINITE: z_k − z_j = log( (1 − ε + ε/V) / (ε/V) ) = log(1 + (1 − ε)·V/ε) = 13.02 at ε = 0.1, V = 50 257 against +∞ for a one-hot target — the smoothing is a cap on confidence, and that is the point. by hand — V = 4, ε = 0.1, correct token k = 2 (0-based)q_ε = 0.9·e₂ + 0.1/4 · 1 = [ 0.025 0.025 0.925 0.025 ] sums to 1 floor H(q_ε) = −0.925·ln 0.925 − 3·0.025·ln 0.025 = 0.0721 + 0.2767 = 0.349 nats optimal gap ln( 0.925 / 0.025 ) = ln 37 = 3.61 (against ∞ for a one-hot target) a model that puts p = [ 0.05 0.05 0.85 0.05 ]: one-hot loss −ln 0.85 = 0.163 smoothed loss −∑ⱼ q_ε[j]·ln pⱼ = 0.925·0.163 + 3·0.025·(−ln 0.05) = 0.150 + 0.225 = 0.375 gradient on the logits p − q_ε = [ 0.025 0.025 −0.075 0.025 ] — still pushing 2 up, the rest down; the same model with p₂ = 0.99 would have a gap of ln(0.99/0.0033) = 5.7 > 3.61, and the sign of ∂L/∂z₂ flips.

Two consequences for reading a training run. First, a loss of 1.4 on a smoothed 50k-vocabulary objective is a perfect model, and the comparable one-hot cross-entropy has to be computed separately (the work that introduced the recipe noted that smoothing "hurts perplexity" while improving accuracy — the two numbers are not the same objective). Second, the gradient with respect to the logits is p − q_ε rather than p − e_k, so it does not vanish at a confident correct prediction — once the model is more confident than the target, it pushes the correct logit down and the others up until the gap is back at 13.02, which is a mild, permanent regulariser on the head. Encoder–decoder translation models keep it; most decoder-only language models drop it (ε = 0), because on a next-token objective at scale the calibration it buys is not needed and the floor obscures the number everyone compares. The figure evaluates the floor and the gap for any (ε, V) and shows the gradient at the optimum.

26 The training recipe (3): the warmup-then-decay schedule, derived from the 2017 rule and plotted from the library

The original recipe tied the learning rate to the width and the step count in one formula. Written out, it is a linear warmup to a peak that depends on d and the warmup length, followed by an inverse-square-root decay; the modern recipe keeps the warmup and swaps the tail for a cosine. Both come out of DL.lrAt with the right arguments, and §12 said why the warmup is there.

the 2017 rule, and what each piece isη(step) = d^(−½) · min( step^(−½) , step · warmup^(−3/2) ) step = 1, 2, … for step ≤ warmup: the second term wins: η = d^(−½) · warmup^(−3/2) · step LINEAR in step for step ≥ warmup: the first wins: η = d^(−½) · step^(−½) ∝ 1/√step at step = warmup: both equal η_peak = (d · warmup)^(−½) d = 512, warmup = 4000: η_peak = (512 · 4000)^(−½) = 6.99e−4 d = 512, warmup = 8000: 4.94e−4 d = 1024, warmup = 4000: 4.94e−4 so the peak FALLS with both width and warmup length, and the decay after the peak is slow: at step = 100 000 with warmup 4000 the rate is √(4000/100000) = 0.2 of the peak. by hand, d = 512, warmup = 4 000 (d^(−½) = 0.04419, warmup^(−3/2) = 3.953e−6): step 1 000: 0.04419 · min( 1000^(−½) = 0.0316 , 1000 · 3.953e−6 = 0.00395 ) = 0.04419 · 0.00395 = 1.75e−4 step 4 000: 0.04419 · min( 0.0158 , 0.0158 ) = 6.99e−4 ← the peak step 16 000: 0.04419 · min( 16000^(−½) = 0.00791 , 0.0632 ) = 3.49e−4 = peak / 2 step 100 000: 0.04419 · 100000^(−½) = 1.40e−4 = 0.2 · peak (DL.noamLR returns 1.747e−4, 6.988e−4, 3.494e−4, 1.398e−4 for the same four steps) the same object in the library, and the modern replacementDL.noamLR(step, d, warmup) ≡ DL.lrAt("invsqrt", step, {peak: (d·warmup)^(−½), warm: warmup}) to round-off modern: DL.lrAt("cosine", step, {peak: η_max, warm: W, total: T, floor: η_min}) linear warmup over W steps — a fraction of a percent of the run in the two recipes of §27: 375M of 300B tokens, and 2 000 of roughly 500 000 steps — then cosine from η_max to η_min ≈ η_max/10 over the remaining steps. η_max is set by hand — 6e−4 for a 125M-class model, 3e−4 at 350M, 2e−4 at 1.3B, 1.2e−4 at 6.7B, 6e−5 at 175B in the published 2020 family; 3e−4 at 7B and 1.5e−4 at 70B in the 2023 family — smaller with width, as the 2017 rule's d^(−½) already said (the 2020 family's peaks fall as d^(−0.77) over that range).

Three things the plot makes visible. The warmup is a straight line from zero and is the part of the schedule §12 explained: the gradient scales at initialisation are not the scales the optimiser will see later, and a post-norm stack in particular cannot take a full-size step at step one. The inverse-square-root tail never reaches a floor and decays slowly — it was designed for training runs whose length was not fixed in advance. The cosine tail reaches a chosen floor at a chosen step, which is what a run with a fixed token budget wants, and it spends more of the run near the peak; the two tails differ by a factor of about two over most of a long run, which is one reason the modern recipe's peak rates can sit at or below what the 2017 rule would give at the same width — at d = 4096 with a 2 000-step warmup the rule gives (4096·2000)^(−½) = 3.5e−4, and the 2023 recipe's 7B peak is 3.0e−4. The figure also draws the constant-then-drop schedule some recent recipes prefer (a "warmup–stable–decay" shape), because it makes the same point from the other side: what the decay buys is the last few percent of loss, and when it is taken is a choice.

The 2017 rule against warmup + cosine and warmup–stable–decay, from DL.lrAt and DL.noamLR change d and the warmup and watch the 2017 peak move exactly as (d·warmup)^(−½) says; the cosine curve's peak is a free choice, so it is set to match at the defaults

27 The training recipe (4): AdamW as it is actually set — β₂, decoupled decay, clipping, and where the dropout goes

The training page owns AdamW as an algorithm. This section owns the four numbers a transformer recipe sets differently from the textbook defaults, and measures the one that matters most: the second-moment constant.

Read across the columns and the recipe's constants are the same in both families three years apart: β₂ = 0.95, decay 0.1, clipping at 1.0, warmup then cosine to a tenth. What moved is the peak rate (down with width, as §26's rule says) and the batch (up with size and up over the course of a run — the batch ramp is a second warmup, on the noise scale rather than the step size). The ε difference is plausibly a bf16 accommodation — the 2023 recipe does not say — since with coarser gradients a larger ε keeps the denominator from being dominated by rounding; it is also a floor on how large a step a near-zero second moment can produce.

Dropout: where, and how much

The 2017 recipe applied dropout of 0.1 in three places: to the output of every sub-layer before it is added to the residual stream (so the stream itself is never dropped), to the attention weights after the softmax (which zeros individual entries of A, so a row no longer sums to one; the survivors are rescaled by 1/(1 − p) like any dropout and nothing renormalises the row — the paper's text names the first and third placements, its reference implementation had the second as well), and to the sum of embedding and position before the first block. Encoders of the 2018 generation kept all three at 0.1. Most large decoders since 2020 use none (a few 2022 families kept 0.1): at their data scale each token is seen about once and there is little to overfit to, and the regularisation costs real capacity. The rule is therefore a function of the data-to-parameter ratio rather than of the architecture, and the training page owns the mechanism. What the architecture fixes is only the placement: on the sub-layer output, never on the residual path, and never after the final norm.

Adam's step size through a gradient spike at two values of β₂, and global-norm clipping on the same stream the gradient stream is steady noise with one spike at step 3000; with β₂ = 0.999 the step overshoots at the spike and then stays too small for hundreds of steps, with 0.95 it is absorbed — clipping the gradient norm caps the spike before Adam sees it
The decay applied everywhere. Weight decay of 0.1 applied to the LayerNorm gains and to the biases. Nothing crashes; the norms' γ are pulled toward zero every step, and the model fights its own regulariser. The recipe decays the matrices (the things with a scale to control) and excludes the one-dimensional parameters; most frameworks require the two groups to be listed explicitly, and the default of decaying everything is the bug.

28 The training recipe (5): mixed precision — bf16 against fp16, and what the loss scale was for

The training page owns mixed precision as a topic. What this section owns is the transformer-specific fact that decided the format: a 16-bit float with fp32's exponent range and a coarse mantissa (bf16) trains a transformer without the loss-scaling machinery that a 16-bit float with a fine mantissa and a small range (fp16) needs, and the reason is where the small numbers are.

the two 16-bit formats, exactly sign exponent mantissa largest smallest normal smallest subnormal unit round-off (½ step) fp16 1 5 10 65 504 6.10e−5 5.96e−8 2^(−11) = 4.9e−4 bf16 1 8 7 3.39e38 1.18e−38 9.18e−41 2^(−8) = 3.9e−3 fp32 1 8 23 3.40e38 1.18e−38 1.40e−45 2^(−24) = 6.0e−8 bf16 is fp32 with the low 16 mantissa bits cut off: SAME range, 8× coarser steps than fp16. where the trouble is — activations and gradients in a transformeractivations in a large model can exceed 65 504 — a few outlier coordinates of the residual stream, and in some models the attention logits before the softmax → fp16 overflow → inf, then NaN gradients of early layers and of embeddings are routinely 1e−8 … 1e−5 → fp16 UNDERFLOW → zero the loss-scale fix: multiply the loss by S (say 2¹⁶), so every gradient is S× larger and lands in fp16's range; divide by S in fp32 before the update; if a gradient overflows, skip the step and halve S; grow S every N clean steps (dynamic loss scaling) bf16 needs none of it: a 1e−8 gradient is representable, a 1e5 score is representable. what bf16 costs: 3.9e−3 relative rounding on every stored value — which is why the MASTER copy of the weights and the optimiser state stay in fp32 and only the matmuls run in 16 bits.

The figure makes the two failure modes literal. It draws a histogram of gradient magnitudes of the shape a transformer produces — log-normal across many decades — and rounds every value to each format: the fraction that becomes exactly zero in fp16 is printed, and it is not small; in bf16 it is zero. Then it applies a loss scale and shows the fp16 fraction fall to zero, and it applies too large a scale and shows the top of the distribution overflow instead. The other panel rounds a single number to both formats and prints the relative error, which for bf16 is up to eight times larger than fp16's (the steps are eight times coarser; on a single value the ratio depends on where it falls between steps): that is the price, and it is paid in the forward pass, where a matmul of thousands of terms averages it away, rather than in the weights, which are never stored in 16 bits. The same choice again at load time

Training settles the format; inference has to respect it. A checkpoint trained and saved in bf16 carries nothing in an fp32 copy — the extra mantissa bits are zeros — so loading it in fp32 doubles the memory and, because decode time is weight bytes divided by bandwidth (§47), roughly halves the decode speed, for essentially the same predictions — the weights are identical, and only the precision of the arithmetic on the activations changes. Loading it in fp16 on hardware without bf16 support brings back this section's other failure: the few activation coordinates that exceed 65 504 overflow to ∞ and then to NaN. The default in current implementations is to load in the dtype the configuration records; §38 walks through it, and the mask constant −1e9 that is finite in fp32 and −∞ in fp16 is §36's example of a single number whose meaning depends on this choice.

29 Decoding (1): what temperature, top-k and top-p do to one distribution

The model produces a distribution over the vocabulary at every step; decoding is the rule that turns it into a token. Greedy takes the mode, sampling draws from it, and the three knobs in every generation API are three ways of reshaping the distribution before drawing. Each has a closed form, and each does something the others cannot.

the four rules, on one logit vector zgreedy t = argmaxⱼ zⱼ deterministic; the mode, every step temperature p_T = softmax(z / T) T → 0: greedy; T = 1: the model; T → ∞: uniform changes every probability; log-odds between two tokens scale by 1/T top-k keep the k largest pⱼ, renormalise a HARD cap on the candidate set, blind to how peaked p is top-p keep the smallest set whose mass ≥ p, renormalise ADAPTIVE: one token when the model (nucleus) is sure, many when it is not the order that frameworks apply them: temperature → top-k → top-p → sample two numbers that summarise the reshaped distributionentropy H(p) = −∑ pⱼ log pⱼ (nats) and perplexity e^H = the effective number of candidates temperature moves H continuously; top-k and top-p move it by removing mass from the tail, and the figure prints H and e^H for every setting so that "T = 0.7" and "top-p = 0.9" can be compared on one scale.

Two facts that the closed forms make clear. First, temperature is not truncation: at T = 0.7 the tail is still there, only lighter, and a long generation will eventually draw from it; top-p removes it. Second, top-k is the wrong shape for a language model: the number of plausible next tokens varies by orders of magnitude between positions (one after "the United States of", hundreds after "I think"), and a fixed k is too many in the first case and too few in the second. Nucleus sampling was proposed for exactly this reason. In practice the two are combined — a top-k of 50 as a safety cap and a top-p of 0.9 to 0.95 doing the work — with a temperature slightly below one. Repetition penalties, length normalisation and the beam search of §30 are further rules on top; the KV cache that makes any of this affordable is the attention page's KV-cache section's.

Where these knobs sit in a real generate loop

In an implementation, temperature, top-k and top-p are the last stages of a pipeline of logits processors that runs at every step (followed only by rarer warpers and, when one is configured, a watermark), and the stages before them — repetition penalties, n-gram bans, a minimum length that suppresses end-of-sequence, banned words — have already changed the distribution these three see. The order is fixed (penalties and constraints first, then temperature → top-k → top-p), and it matters: a repetition penalty applied after a temperature of 0.7 would act on logits already divided by 0.7. §46 steps through the whole pipeline on a six-word vocabulary with every intermediate number, and shows a property of the repetition penalty that the closed forms above do not have — it is not invariant to adding a constant to the logits.

30 Decoding (2): greedy, beam search and sampling, run live on the trained model

§29 reshaped one distribution. Decoding a sequence applies a rule at every step and feeds the result back, and the rules differ in what they optimise: greedy the next token, beam search the whole sequence's probability, sampling nothing at all. Run all three on the page's trained model and watch them agree where the model is sure and diverge where it is not.

the three rules, and what each one is looking forgreedy tₖ = argmax p(· | prefix, t₁ … tₖ₋₁) one forward per step maximises each step's probability; NOT the sequence's — a locally best first token can lead to a poor continuation beam (B) keep the B highest-scoring partial sequences, score = ∑ log p(tₖ | …) at each step extend every one of the B by every token, keep the best B of the B·V B forward passes per step (batched); B = 1 is greedy; B = V^n is exhaustive finds a sequence with HIGHER total log-probability than greedy, not the highest length bias: longer sequences accumulate more negative log-probability, so the score is often divided by length^α, α ≈ 0.6 … 1 sampling tₖ ~ p_T,k,p(· | …) from §29's reshaped distribution one forward per step stochastic; the only rule that produces DIFFERENT outputs from the same prefix the cost, with the KV cache of the attention pageper generated token, per layer: one new row of Q, K, V (3·d² MACs) and its output projection (d²), scores against the cached n keys (n·d), the blend (n·d), the FFN (8d²): O(d² + n·d) — no re-encoding of the prefix. beam search multiplies every term by B and keeps B caches; sampling and greedy keep one.

On the copy task the three rules produce the same answer once the model is trained: the distributions are one-hot to three decimals, the beam's alternatives have vanishing scores and sampling with any sane temperature never leaves the mode. That is the honest picture for a solved deterministic task and it is worth seeing. On a partly trained model — 60 steps instead of 300 — the three separate: greedy commits to a wrong token and carries it forward, the beam recovers a higher-scoring sequence, and repeated samples disagree with each other. What beam search costs in a real cache, and the rules that go beyond these three

With a KV cache, beam search is more than B forward rows per step. After each step the B surviving hypotheses may descend from different parents — two children of one beam, none of another — so every layer's cache must be reordered along the batch axis to follow them: a gather of B caches per step, and B times the cache memory of greedy decoding for the whole generation. On §36's model with a 2 000-token context and B = 4 that is 4 × 250 MiB = 1 000 MiB of cache instead of 250 MiB (§45). The rules that change which candidates survive rather than how many — contrastive search, contrasting layers, diverse and constrained beams — are §48, each worked by hand; the processor pipeline that feeds every rule is §46.
