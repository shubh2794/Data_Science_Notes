Recurrences & the Master Theorem

Solving the recurrences that recursive algorithms produce: setting T(n) up from the code, proving a guess by substitution, reading the sum off a recursion tree, the Master theorem's three cases for T(n) = a·T(n/b) + f(n), and the gaps, regularity condition and shapes it cannot handle.

13 Recurrences: what they are and where they come from

A recurrence is an equation that defines a function in terms of its own value on smaller inputs. A recursive algorithm's running time satisfies one automatically: the time on an input of size n is the time to split, plus the time of the recursive calls, plus the time to combine. Solving the recurrence — turning it into a closed form or an asymptotic bound — is the entire cost analysis of a recursive algorithm.

the divide-and-conquer templateT(n) = { Θ(1) if n ≤ n₀ (base case: solve directly) { D(n) + a·T(n/b) + C(n) otherwise wherea = how many subproblems n/b = how big each one is D(n) = cost of dividing C(n) = cost of combining usually written, with f(n) = D(n) + C(n)T(n) = a·T(n/b) + f(n)

Deriving mergesort's recurrence, carefully

  • Divide. Compute the midpoint. One arithmetic operation: D(n) = Θ(1).
  • Conquer. Two subproblems, each of half the size: 2·T(n/2).
  • Combine. Merge two sorted halves into one sorted array. Each step of the merge writes exactly one element and advances one input pointer, so the merge does Θ(n) work: C(n) = Θ(n).
  • Assemble. D(n) + C(n) = Θ(1) + Θ(n) = Θ(n), giving T(n) = 2·T(n/2) + Θ(n), whose solution is Θ(n log n) — by recursion tree in §15, by Master theorem in §16, and provable by substitution in §14.

Three conventions that look like cheating and are not

  • The base case is usually omitted. Writing T(n) = 2T(n/2) + Θ(n) without saying T(1) = Θ(1) is standard, because every recurrence in this subject has a constant base case and stating it adds nothing. It matters only when you do a formal induction (§14), where the base case of the proof is a separate thing from the base case of the recurrence.
  • Floors and ceilings are dropped. The honest recurrence for mergesort is T(n) = T(floor(n/2)) + T(ceil(n/2)) + Θ(n), since n/2 need not be an integer. Replacing both by n/2 does not change the asymptotic solution — a fact that is proved once, in the proof of the Master theorem, and then used silently forever.
  • The recursion is assumed to reach the base case. Which requires the subproblem to shrink strictly, and the base case to be reachable. Both are termination obligations, and both are where real recursive bugs live.

  • Subtracting from n versus dividing n is the whole difference. T(n−1)-style recurrences have n levels; T(n/b)-style ones have log_b n. That is why the naive Fibonacci recursion is catastrophic and mergesort is not — they are not different amounts of cleverness, they are different arithmetic on the subproblem size.
  • The number of subproblems is an exponent, not a factor. Going from 2T(n/2) to 3T(n/2) does not make the algorithm 1.5× slower; it moves it from Θ(n log n) to Θ(n^1.585), because the leaf count is a^(log_b n) = n^(log_b a). Karatsuba's entire trick is turning four half-size multiplications into three.

Three methods solve these, and they are complementary: substitution (§14) proves a bound you have already guessed, recursion trees (§15) generate the guess, and the Master theorem (§16) is a lookup table for the common case. The usual workflow is tree → guess → substitution → proof, with the Master theorem short-circuiting the whole thing when it applies.

14 The substitution method

Two steps: guess the form of the solution, then prove it by induction, substituting the inductive hypothesis for the recursive terms. It is the only one of the three methods that produces an actual proof, and the only one that works on recurrences of any shape. Its weakness is that you must already have the guess.

A proof carried all the way through

Take T(n) = 2·T(floor(n/2)) + n, and guess T(n) = O(n log n). By the definition in §07 that means proving T(n) ≤ c·n·log₂ n for some constant c > 0 and all n past some threshold. Assume it holds for all positive m < n — in particular for m = floor(n/2) — and substitute:

inductive stepT(n) ≤ 2·( c·floor(n/2)·log₂(floor(n/2)) ) + n ≤ c·n·log₂(n/2) + n (drop the floor, which only shrinks both factors) = c·n·log₂ n − c·n·log₂ 2 + n = c·n·log₂ n − c·n + n ≤ c·n·log₂ n whenever c ≥ 1

The inductive step is done, and it told us how large c has to be: any c ≥ 1.

The base case is where it nearly falls over

  • Suppose the recurrence's base case is T(1) = 1. Then the claim at n = 1 reads T(1) ≤ c·1·log₂ 1 = 0, which is false. The induction has no base.
  • The repair uses the definition, not a bigger constant. Asymptotic notation only requires the bound for n ≥ n₀, and we get to choose n₀. For n > 3 the recurrence never refers to T(1) directly, so take n₀ = 2 and use n = 2 and n = 3 as the base cases of the proof. From T(1) = 1 the recurrence gives T(2) = 2·T(1) + 2 = 4 and T(3) = 2·T(1) + 3 = 5. Both are satisfied by T(2) ≤ 2c·log₂ 2 = 2c and T(3) ≤ 3c·log₂ 3 ≈ 4.75c as soon as c ≥ 2.
  • Combining the two constraints, c = 2 and n₀ = 2 is a complete witness and the proof is finished. Note the distinction that trips people: the base case of the recurrence (n = 1) and the base cases of the induction (n = 2, 3) are different objects, and you are free to move the second.

The subtlety: a hypothesis that is too weak

Consider T(n) = T(floor(n/2)) + T(ceil(n/2)) + 1. The answer is O(n). Guess T(n) ≤ c·n and substitute:

the attemptT(n) ≤ c·floor(n/2) + c·ceil(n/2) + 1 = c·n + 1 — and c·n + 1 is NOT ≤ c·n, for any c. The proof fails. the counterintuitive fix: guess something SMALLERT(n) ≤ c·n − d, with d ≥ 0 a second constant T(n) ≤ (c·floor(n/2) − d) + (c·ceil(n/2) − d) + 1 = c·n − 2d + 1 ≤ c·n − d whenever d ≥ 1
  • Why strengthening the claim makes it provable. In an induction you must use your own hypothesis on the subproblems. A weaker hypothesis gives you weaker material to work with, so it can genuinely be harder to prove a weaker bound. Here the recurrence has two recursive terms, so subtracting d once in the statement buys you 2d back in the step — a surplus of d, which absorbs the stray +1.
  • Do not respond by guessing bigger. O(n²) would go through easily and would be a weaker, correct, useless theorem. When the algebra misses by a lower-order term, subtract a lower-order term.
  • The same trick on a different recurrence. For T(n) = 4T(n/3) + n the true answer is Θ(n^(log₃ 4)), and the naive hypothesis T(n) ≤ c·n^(log₃ 4) also fails by a lower-order term; T(n) ≤ c·n^(log₃ 4) − d·n repairs it.

The pitfall: proving O(n) for something that is not

A famously seductive wrong proof for T(n) = 2T(floor(n/2)) + n: guess T(n) ≤ c·n, then write T(n) ≤ 2·c·floor(n/2) + n ≤ c·n + n = O(n) — and declare victory. It is wrong. The inductive hypothesis to be re-established is the exact statement T(n) ≤ c·n, and c·n + n is not ≤ c·n. Writing O(n) at the end of the chain hides a constant that grows by one at every level of the recursion, and n levels of that is exactly the missing log n factor. In substitution you must re-derive the hypothesis with its own constants, symbol for symbol.

Two more tools

  • Change of variables. T(n) = 2·T(√n) + log₂ n looks unlike anything. Set m = log₂ n, so √n = 2^(m/2), and define S(m) = T(2^m). The recurrence becomes S(m) = 2·S(m/2) + m — the mergesort recurrence — with solution S(m) = O(m log m). Substituting back, T(n) = O(log n · log log n).
  • Bracketing to find the guess. Prove a loose lower bound and a loose upper bound, then squeeze. For T(n) = 2T(n/2) + n, Ω(n) is immediate from the + n term and O(n²) is easy; tighten from both ends until they meet at Θ(n log n). And if the recurrence resembles one you know — T(n) = 2T(floor(n/2) + 17) + n, say — guess the same answer. The +17 cannot matter once n is large, and substitution confirms it.
When to reach for substitution. When the Master theorem does not apply — unequal splits, subtractive recurrences, a variable number of subproblems — or when you need an actual proof rather than a bound to quote. It is the general method; the other two are shortcuts.

15 The recursion-tree method

Draw the recursion as a tree: each node is one subproblem, labelled with the non-recursive work it does. Sum across each level, then sum the levels. Drawn carefully it is a proof; drawn quickly it is the fastest way to manufacture the guess that substitution then verifies.

The three quantities to write down

for T(n) = a·T(n/b) + f(n)subproblem size at depth i: n / bⁱ number of nodes at depth i: aⁱ work at depth i: aⁱ · f(n / bⁱ) the tree bottoms out when n/bⁱ = 1depth = log_b n, so there are log_b n + 1 levels number of leavesa^(log_b n) = n^(log_b a) ← the identity that makes n^(log_b a) the number to beat totalT(n) = ∑ᵢ₌₀^(log_b n − 1) aⁱ·f(n/bⁱ) + Θ(n^(log_b a))

That leaf-count identity is worth a moment: a^(log_b n) = n^(log_b a) because taking log_b of both sides gives log_b n · log_b a either way. It is why the quantity n^(log_b a) — the cost of the bottom of the tree — is the yardstick the Master theorem compares everything against.

A tree summed by hand: T(n) = 3T(n/4) + c·n²

  • Each level has 3× more nodes than the one above, and each node is 1/4 the size, so its n² work is 1/16 as large. Level i therefore costs 3ⁱ·c·(n/4ⁱ)² = (3/16)ⁱ·c·n².
  • The per-level costs form a geometric series with ratio 3/16 < 1 — decreasing fast. Bounding the finite sum by the infinite one (§09) gives ∑(3/16)ⁱ·cn² < cn²/(1 − 3/16) = (16/13)·cn².
  • The bottom level has 3^(log₄ n) = n^(log₄ 3) ≈ n^0.79 leaves, each costing Θ(1), so the leaves contribute Θ(n^0.79) — asymptotically negligible against n².
  • Conclusion: T(n) = O(n²), dominated by the root. The guess is then confirmed by substitution: assume T(m) ≤ d·m² for m < n, substitute to get T(n) ≤ 3·d·(n/4)² + cn² = (3/16)·d·n² + cn² ≤ d·n² whenever d ≥ (16/13)c.
Recursion tree for T(n) = a·T(n/b) + n^k — per-level work, summed watch which level dominates as a/b^k crosses 1

At the defaults a = 3, b = 4, k = 2 the per-level ratio is a/b^k = 3/16 = 0.1875, the bars shrink by a factor of more than five each level, and the readout reports the root alone as over 80% of the total with the leaves at a tenth of a percent: the work is top-heavy, and T(n) = Θ(f(n)). Now move the sliders and watch the ratio do all the work:

  • a = 2, b = 2, k = 1 (mergesort) gives a/b^k = 1 exactly. Every bar is the same length — each level costs n — and with log_b n + 1 levels the total is Θ(n log n). The equal-bar picture is case 2 of the Master theorem.
  • a = 4, b = 2, k = 1 gives a/b^k = 2 > 1: the bars grow downward, the bottom level swamps everything, and the total is Θ of the leaf count n^(log_b a) = n².
  • Set k = 0 with a = 1 and you get binary search: one node per level, constant work, log_b n + 1 levels, total Θ(log n).
The one thing to remember. The per-level ratio is a/b^k. Less than 1 → geometric decay → the root dominates. Equal to 1 → flat → multiply by the number of levels. Greater than 1 → geometric growth → the leaves dominate. Those three sentences are the Master theorem, and §16 adds the fine print — which, as §17 shows, is exactly where a good many real recurrences fall.

16 The Master theorem

A cookbook for the recurrence that divide-and-conquer produces — also called the master method, and you will meet both names for the same result. It answers one question — does the root, the leaves, or every level equally, dominate the tree? — by comparing f(n) against n^(log_b a), and it converts §15's three geometric outcomes into three memorisable cases. It is a sufficient condition in each case, never a necessary one: when no case applies the theorem says nothing at all, which is not the same as saying the recurrence has no solution (§17).

Master theoremLet a ≥ 1 and b > 1 be CONSTANTS, f(n) an asymptotically non-negative function, and T(n) = a·T(n/b) + f(n) (n/b read as floor(n/b) or ceil(n/b) — it makes no difference) 1. If f(n) = O(n^(log_b a − ε)) for some constant ε > 0, then T(n) = Θ(n^(log_b a)). ← the LEAVES dominate 2. If f(n) = Θ(n^(log_b a)), then T(n) = Θ(n^(log_b a) · log n). ← EVERY LEVEL costs the same 3. If f(n) = Ω(n^(log_b a + ε)) for some constant ε > 0, AND a·f(n/b) ≤ c·f(n) for some constant c < 1 and all large n, (the REGULARITY condition) then T(n) = Θ(f(n)). ← the ROOT dominates

Why n^(log_b a) is the thing to compare against

It is the number of leaves. Each level multiplies the node count by a, there are log_b n levels, so the bottom has a^(log_b n) nodes — and by the identity of §15, a^(log_b n) = n^(log_b a). So n^(log_b a) is exactly what the recursion costs if the combine step were free. The theorem asks whether the real combine cost f(n) beats that, ties with it, or loses to it.

Three cases worked with actual numbers

  • Case 1 — Strassen's matrix multiplication: T(n) = 7T(n/2) + Θ(n²). Here a = 7, b = 2, so log₂ 7 ≈ 2.807 and the yardstick is n^2.807. Is f(n) = n² polynomially smaller? Take ε = 0.8: n^(2.807 − 0.8) = n^2.007, and n² = O(n^2.007). Yes. So T(n) = Θ(n^2.807) — the recursion, not the combine, is the whole cost, and Strassen's contribution was to reduce a from 8 to 7.
  • Case 2 — mergesort: T(n) = 2T(n/2) + Θ(n). log₂ 2 = 1, the yardstick is n¹ = n, and f(n) = Θ(n) matches it exactly. So T(n) = Θ(n log n). In the tree picture every level costs n and there are log₂ n + 1 of them — the flat-bar picture from §15.
  • Case 3 — with the regularity check done properly: T(n) = 3T(n/4) + n log n. log₄ 3 ≈ 0.7925. Is n log n polynomially larger? Take ε = 0.2, so the bar is n^0.9925, and n log n ≥ n ≥ n^0.9925 for n ≥ 1. Yes. Now regularity: a·f(n/b) = 3·(n/4)·log(n/4) ≤ (3/4)·n log n = c·f(n) with c = 3/4 < 1. Satisfied. So T(n) = Θ(n log n).

What the regularity condition is for

  • It says the work really does shrink as you descend. a·f(n/b) ≤ c·f(n) with c < 1 means one level down costs a constant fraction of the level above — which is exactly what makes the per-level series geometric and therefore summable to Θ of its first term.
  • For a pure power f(n) = n^k it is automatic when case 3's polynomial condition holds: a·f(n/b) = a·(n/b)^k = (a/b^k)·f(n) exactly, so c = a/b^k, which is below 1 precisely when b^k > a, i.e. when k > log_b a. So for every pure polynomial f you will meet, regularity is free and you may check it in one line. The one-line check needs a footnote when f carries a log factor. For f(n) = n^k·log^p n with p ≥ 0, log(n/b) ≤ log n and c = a/b^k still works. For p < 0 the log factor moves the wrong way and a/b^k itself may fail at every finite n — but a·f(n/b)/f(n) → a/b^k, so any constant strictly between a/b^k and 1 is a valid c for all large n, and regularity holds anyway.
  • It can fail for pathological f. An f that oscillates — dipping low at n and spiking at n/b — can be polynomially larger than n^(log_b a) and still violate a·f(n/b) ≤ c·f(n). Then case 3 does not apply even though its first condition does, and the theorem is silent. This is the trichotomy failure of §08 reappearing in applied form.
Master-theorem case classifier — f(n) = n^k·log^p n against n^(log_b a) the last two presets are the recurrences the theorem cannot solve

At the default preset the two curves lie on top of each other — f(n) = n and n^(log₂ 2) = n are the same function — and the classifier reports case 2 with T(n) = Θ(n log n). Step the a slider up one at a time with b = 2, k = 1 held: at a = 1 the root wins (case 3, Θ(n)), at a = 2 they tie (case 2), and from a = 3 onward the leaves win (case 1, Θ(n^(log₂ a))) — the entire theorem traversed with one control. The classic-recurrence table is produced by the same classifier the sliders drive, so the two cannot disagree with each other.

Read the case label carefully — the classifier knows more than the theorem above it. The p slider puts a factor of log^p n into f, and when p ≠ 0 with k = log_b a the classifier reports "case 2 (extended — NOT the basic theorem)". That is deliberate. The three cases stated above do not cover 2T(n/2) + n log n; the standard p > −1 extension does, and the figure implements the extension. So the preset labelled gap of the basic theorem is reported as solvable, with T(n) = Θ(n log² n) — solvable by the extension, a genuine gap for the three cases. §17 derives both, and the second gap preset — p = −1, where even the extension fails — is reported as no case applies.
A decision procedure you can run in your head. Compute log_b a. Compare it with the exponent of n in f. Smaller exponent in f → leaves win, answer n^(log_b a). Equal → tie, multiply by log n. Larger → root wins, answer f(n). Only then worry about whether the gap is polynomial and whether regularity holds — which, for a pure power f(n) = n^k, it automatically does.

17 What the Master theorem cannot solve

The three cases do not tile the space of possibilities. There are gaps between them, a condition in case 3 that can fail, and whole families of recurrences that are not of the required shape at all. Knowing where the cookbook ends is as useful as knowing what is in it, because the failure mode is quietly applying a case that does not hold.

Gap 1 — smaller, but not polynomially smaller

Case 1 needs f(n) = O(n^(log_b a − ε)) for a constant ε > 0. A function can be asymptotically below n^(log_b a) and still fail that, if the gap is only logarithmic.

the standard witnessT(n) = 2·T(n/2) + n / log n the comparisonn^(log₂ 2) = n, and f(n)/n = 1/log n → 0, so f is smaller but n/log n is NOT O(n^(1−ε)) for any constant ε > 0 — 1/log n beats no power of n no case applies; the true answer, by summing the tree directlyT(n) = Θ(n · log log n)

The tree argument: every level costs 2ⁱ·(n/2ⁱ)/log(n/2ⁱ) = n/(log n − i), so the total is n·∑ᵢ₌₀^(log n − 1) 1/(log n − i) = n·H_(log n) = Θ(n log log n) — a harmonic sum in disguise, which the cookbook has no way to notice.

Gap 2 — larger, but not polynomially larger

the other standard witnessT(n) = 2·T(n/2) + n log n the comparisonn^(log₂ 2) = n, f(n)/n = log n → ∞, so f is larger but log n is NOT Ω(n^ε) for any constant ε > 0 — §09: every polynomial beats every polylog the basic theorem is silent; the standard EXTENSION covers itif f(n) = Θ(n^(log_b a) · log^p n) with p > −1, then T(n) = Θ(n^(log_b a) · log^(p+1) n) so hereT(n) = Θ(n · log² n)
  • The extension subsumes case 2, which is just p = 0. It is worth memorising in the general form, because n log n and n log² n combine steps are common.
  • It has its own boundary. At p = −1 the extension fails too — and p = −1 is precisely the n / log n case above, whose answer Θ(n log log n) is not of the form n log^q n at all. The classifier's last two presets are exactly these two frontiers.

The more general tool: Akra–Bazzi

For recurrences with several unequal splits, T(n) = ∑ᵢ₌₁ᵏ aᵢ·T(bᵢ·n) + f(n), there is a genuine generalisation. The hypotheses are worth stating rather than waving at, because they are what makes the p below exist and be unique: the aᵢ are positive constants, each bᵢ is a constant with 0 < bᵢ < 1, the argument may be perturbed by a floor, a ceil or anything else of size O(n / log² n) without changing the answer, and f must satisfy a polynomial-growth condition — informally, f(n) and f(bᵢ·n) stay within constant factors of each other, which every n^k·log^p n does and an oscillating f need not. Then find p from the balance equation and integrate:

Akra–Bazzifind p such that ∑ᵢ aᵢ·bᵢ^p = 1 then T(n) = Θ( n^p · ( 1 + ∫₁ⁿ f(u)/u^(p+1) du ) ) applied to the median-of-medians recurrence T(n) = T(n/5) + T(7n/10) + n(1/5)^p + (7/10)^p = 1 ⇒ p ≈ 0.8398 ∫₁ⁿ u / u^(p+1) du = ∫₁ⁿ u^(−p) du = (n^(1−p) − 1)/(1 − p) = Θ(n^(1−p)) T(n) = Θ( n^p · n^(1−p) ) = Θ(n) sanity check on the balance equation1/5 + 7/10 = 0.9 < 1, so the subproblems together are smaller than the whole ⇒ linear time is possible
  • Why p exists and is unique. Define g(p) = ∑ᵢ aᵢ·bᵢ^p. Since every bᵢ < 1, each term aᵢ·bᵢ^p is a strictly decreasing function of p; the sum is therefore strictly decreasing, runs to +∞ as p → −∞ and to 0 as p → +∞, and so crosses 1 exactly once. No search heuristics, no case analysis — one root, found numerically. For the median-of-medians equation, g(0) = 2 > 1 and g(1) = 0.9 < 1, so the root sits in (0, 1): it is p ≈ 0.8398.
  • The intuition behind the balance equation. ∑aᵢbᵢ = 0.9 < 1 means each level of recursion handles only 90% as much total data as the level above, so the per-level work decays geometrically and the root dominates — linear time. If the sum were exactly 1 you would get Θ(n log n), and above 1 the leaves would take over. It is the Master theorem's three cases again, in a form that tolerates unequal splits.
  • It is why median-of-medians works. Choosing the pivot costs a recursive call on n/5, and the partition leaves at most 7n/10; the two fractions must sum to less than 1 for the whole construction to be linear, and 0.9 is the margin the constant 5 buys.
Practical order of attack. Try the Master theorem; it settles most divide-and-conquer recurrences in seconds. If a gap or the wrong shape blocks it, draw the recursion tree — the tree always works, it just takes longer — and confirm the guess by substitution. Reach for Akra–Bazzi only when the splits are genuinely unequal.
