23 DP on DAGs, and the hand-off to Bellman-Ford and Floyd-Warshall

On a directed acyclic graph, shortest paths, longest paths and path counts from a source are all computed by one pass over the vertices in topological order, relaxing each edge exactly once: Θ(V + E), with no priority queue and no restriction on edge weights. The reason is that a DAG's topological order is a dynamic-programming evaluation order — every vertex's predecessors come before it — and the converse is the deeper fact: every dynamic program on this page is a shortest- or longest-path computation on the DAG of its subproblems. Bellman-Ford and Floyd-Warshall are what the same recursion becomes when the graph is allowed to have cycles and the state must be enlarged to keep the recursion well-founded.

state · recurrence · base · order · costSTATE d[v] = the shortest distance from s to v (or the longest, or the number of distinct s → v paths) RECURRENCE d[v] = min over edges (u, v) of [ d[u] + w(u, v) ] shortest (max for longest; ∑ d[u] for counting) BASE d[s] = 0 (1 for counting); d[v] = +∞ (−∞ for longest, 0 for counting) for every other v ORDER topological order of the DAG (Graphs, §20): when v is processed, every u with an edge into v is already final — implemented as "for u in order: for each edge (u, v): relax" (push) or "for v in order: look at in-edges" (pull); the push form is the usual one ANSWER d[t]; the path by predecessor pointers, set at the relaxation that last improved d[v] COST each edge relaxed once ⇒ Θ(V + E) after the Θ(V + E) topological sort; Θ(V) space no priority queue (Dijkstra's Θ((V + E) log V) is for graphs with cycles), no sign restriction on weights, and LONGEST path is as easy as shortest — on a DAG

Why it is correct, and why the DAG is essential

Shortest paths have optimal substructure (§02): a shortest s → v path's last edge is some (u, v), and the part before it is a shortest s → u path, else splice a shorter one in. So d[v] = min over in-edges of d[u] + w(u, v) — provided every d[u] is final when d[v] is computed, which the topological order guarantees since u precedes v. Longest paths need the same argument plus one thing more: the cut-and-paste step splices a longer s → u path onto the edge (u, v), and in a graph with cycles the spliced path might revisit a vertex and stop being simple — that was the failure of §02. In a DAG no path revisits anything, "simple" is automatic, and the argument goes through. Path counting is the same recurrence with ∑ in place of min: every s → v path ends in exactly one in-edge, and the paths ending in (u, v) are in bijection with s → u paths. Acyclicity is essential there too — in a graph with a cycle there are infinitely many walks.

Every DP table is a DAG, and every DAG problem is a DP

Turn the perspective round. The subproblem graph of §05 — a vertex per state, an edge from each state to the states its recurrence reads — is a DAG by construction, and the recurrence is a shortest- or longest-path computation on it. Rod cutting: vertices 0 … n, an edge j → j − i of weight pᵢ for every piece length i; the best cutting is the longest path from n to 0. Edit distance: the (m + 1) × (n + 1) grid with right, down and diagonal edges weighted 1, 1 and [xᵢ ≠ yⱼ]; the distance is the shortest path from the top-left corner to the bottom-right, and an alignment is a path. 0/1 knapsack: vertices (i, c), an edge to (i + 1, c) of weight 0 (skip item i) and, when it fits, to (i + 1, c − wᵢ) of weight vᵢ (take it); the answer is the longest path from (0, W) to any (n, ·). Longest increasing subsequence: an edge i → j whenever i < j and aᵢ < aⱼ, unit weights, longest path. In every case the table's fill order is a topological order of that DAG, the "relaxation" is the recurrence's inner step, and the running time is (vertices + edges) of the subproblem DAG — which is the "(states) × (choices)" of §01 said in graph language. The reason to know this is practical: when a DP is unclear, drawing its DAG often makes the state and the order obvious, and when a graph problem lives on a DAG (scheduling with precedence, critical paths, counting lattice paths), a one-pass DP is the whole algorithm.

The hand-off: cycles, and two ways to enlarge the state

With cycles the topological order does not exist, and d[v] = min (d[u] + w) has no well-founded evaluation order — a vertex on a cycle depends on itself. The dynamic-programming cure is the one §07 prescribes for every recurrence that is not well-founded: add a parameter that strictly decreases. Two choices of parameter give the two classical algorithms.

Bellman-Ford — the parameter is the number of edges alloweddistₖ(v) = the shortest s → v walk using AT MOST k edges dist₀(s) = 0, dist₀(v) = ∞ otherwise distₖ(v) = min( distₖ₋₁(v), min over edges (u, v) of [ distₖ₋₁(u) + w(u, v) ] ) answer: dist_{V−1}(v) — a shortest path with no negative cycle reachable is simple, hence has at most V − 1 edges cost: V − 1 rounds × E relaxations = O(V·E) time; Θ(V) space with two rows (only k − 1 is read), or Θ(V) in place (which can only be better) correctness in one line: a shortest walk of ≤ k edges is either a walk of ≤ k − 1 edges, or a shortest walk of ≤ k − 1 edges to some u followed by (u, v) — cut and paste on its last edge on the six-vertex DAG, run as a graph algorithm without using the order: 45 relaxations = (V − 1)·E, the rows stabilise after round 4, same distances (measured in the figure) and a V-th round that still improves something is the negative-cycle test Floyd-Warshall — the parameter is the set of intermediate vertices alloweddₖ(i, j) = the shortest i → j path whose intermediate vertices all lie in {1, …, k} (all pairs at once) d₀(i, j) = w(i, j) if the edge exists, 0 if i = j, ∞ otherwise dₖ(i, j) = min( dₖ₋₁(i, j), dₖ₋₁(i, k) + dₖ₋₁(k, j) ) answer: d_V(i, j) for every pair; cost: V rounds × V² pairs = Θ(V³) time, Θ(V²) space (the k index rolls away, and even a single matrix updated in place is correct) correctness in one line: a shortest path with intermediates in {1..k} either avoids k — so it is a dₖ₋₁(i, j) path — or passes through k exactly once (no negative cycles), splitting into an i → k and a k → j path with intermediates in {1..k − 1} on the same graph: 216 = V³ triples examined, and row 0 of the result equals the single-source distances (measured in the figure)

Both are dynamic programs in the strict sense of §01: a state ((k, v) or (k, i, j)), a recurrence over choices, base cases, an order (increasing k) that makes the recurrence well-founded, and a cost equal to states times choices. The added parameter is exactly what restores acyclicity to the subproblem graph — (k, v) depends only on (k − 1, ·) — and it is what the DAG version could do without. Both are built in full, with negative cycles, predecessor reconstruction and the Johnson reweighting that lets Dijkstra serve all pairs, at Shortest Paths, MST & Flow; Graphs, §28 states where each algorithm applies. Here the point is only that they are the same recursion on a bigger state space, and that Dijkstra — usually classified as greedy rather than DP: it commits to one vertex per step, licensed by non-negative weights (the Greedy Algorithms page's §20 takes the same view) — is what replaces both when weights are non-negative and the graph is not a DAG.

24 DP over subsets: Held–Karp for the travelling salesman, and bitmask states

When the natural state must record which elements have been used — not how many — the state is a subset, there are 2ⁿ of them, and a dynamic program over subsets is exponential but still far better than the factorial enumeration it replaces. The travelling-salesman problem is the canonical case: the shortest tour that visits every one of n cities once and returns home. Brute force tries (n − 1)! orders; the Held–Karp recurrence tries Θ(n²·2ⁿ) (subset, last city, previous city) triples, and the gap between those two counts — a factor of about 2.9·10⁸ at n = 20, or 5.8·10⁹ once each tour is charged its n additions, which is the n! column of the table below — is the whole point of the section. The subset is stored as an integer bitmask, which makes "the state" a table index like any other.

Why the state has to be a set

A partial tour that starts at city 1, has visited some cities, and now stands at city j needs two things to be extended optimally: where it is (j, because the next distance depends on it) and which cities it has already visited (so none is repeated). The count of visited cities is not enough — two partial tours with the same count and the same endpoint may have visited different sets, and their best completions differ. So the smallest state that makes the recurrence correct is (S, j) with S the set visited so far and j ∈ S the current city. This is the enlargement §02 predicted for problems whose pieces compete for a shared resource (the cities), and the reason §22's independent-set DP is linear on trees and exponential on graphs. The cut-and-paste argument is then standard: if the optimal path through S ending at j arrived from i, its prefix is an optimal path through S ∖ {j} ending at i — a better prefix, followed by the same edge (i, j), would still visit exactly S and would be shorter.

state · recurrence · base · order · cost (cities 1 … n, home = 1; d(i, j) the distance matrix)STATE C(S, j) = the length of the shortest path that starts at 1, visits every city in S exactly once, and ends at j, for 1 ∈ S, j ∈ S ∖ {1} RECURRENCE C(S, j) = min over i ∈ S ∖ {1, j} of [ C(S ∖ {j}, i) + d(i, j) ] for |S| ≥ 3 BASE C({1, j}, j) = d(1, j) (the path 1 → j) ORDER by |S| = 2, 3, …, n: S ∖ {j} is one smaller, so every value on the right is already filled ANSWER tour* = min over j ≠ 1 of [ C({1..n}, j) + d(j, 1) ] (close the cycle); reconstruct through the predecessor table P(S, j) = the i that won COST states: (n − 1) choices of j × 2ⁿ⁻² subsets S of the other cities = (n − 1)·2ⁿ⁻² = Θ(n·2ⁿ) — that is the SPACE work: each state tries |S| − 2 predecessors ⇒ ∑ₛ₌₃ⁿ (n−1 choose s−1)·(s − 1)·(s − 2) + (n − 1) = Θ(n²·2ⁿ) triples — that is the TIME n = 5: 32 states, 4 + 6·2·1 + 4·3·2 + 1·4·3 = 52 triples, then 4 closing candidates (measured by the figure) versus brute force: (n − 1)! tours = 24 at n = 5, each costing n additions

The count of triples deserves the care, because loose statements ("n²·2ⁿ") hide a factor of four or more. For |S| = s there are (n−1 choose s−1) subsets containing city 1, each with s − 1 choices of the last city j and s − 2 choices of the predecessor i; the base |S| = 2 contributes one look-up per j. The checking script for this page evaluated that sum and the counter on the routine for n = 3 … 8: 4, 15, 52, 165, 486, 1 351 triples, matching exactly. Asymptotically the sum is Θ(n²·2ⁿ), and the space, (n − 1)·2ⁿ⁻² entries plus the same for predecessors, is what actually limits n: at n = 20 the table has 19·2¹⁸ ≈ 5·10⁶ entries and the time is about 4.5·10⁷ (S, j, i) triples — the sum above evaluates to 44 826 643, against n²·2ⁿ ≈ 4.2·10⁸ for the loose form — which is a few hundred million machine operations once each triple's look-ups and adds are counted, and a laptop does that in seconds; at n = 30 the table is 29·2²⁸ ≈ 7.8·10⁹ entries and memory is what stops it first — 7.8·10⁹ values are about 31 GB at four bytes each, before predecessors — with the ≈ 1.1·10¹¹ triples not far behind.

The same state serves a whole family. Hamiltonian path (does a path visit every vertex once?) is the boolean version: H(S, j) is true iff some i ∈ S ∖ {j} adjacent to j has H(S ∖ {j}, i), in O(n²·2ⁿ). 25 Digit DP: counting the numbers up to N with a property of their digits

Digit dynamic programming counts (or optimises over) the integers in [0, N] whose decimal digits satisfy some property, by walking the digits of N from the most significant one and keeping as state the position, a single bit that records whether the number built so far is still equal to N's prefix (and therefore still constrained by N's next digit), and whatever summary of the digits placed so far the property needs. The count is exponential in the number of digits — there are N + 1 candidates — but the state space is tiny: (number of digits) × 2 × (size of the property summary), and the answer is read off a memo over it. It is the last state space in this page's catalogue and the one that looks least like the others, until the tight bit is recognised as just another state variable that makes the recursion well-founded.

The problem and the state

Take the property "the digits sum to k" and N = 253, k = 7. A number in [0, 253] is a string of three digits d₀d₁d₂ (leading zeros allowed, so 7 is 007) that is lexicographically at most 253. Building the string left to right, the constraint ≤ 253 bites only while the prefix built so far equals the prefix of N: if the first digit is 0 or 1, every completion is below 253 and the remaining digits are free (0 … 9); if it is 2, the next digit is limited to 0 … 5, and only if it is exactly 5 does the last digit stay limited, to 0 … 3. So the state needs the position, the tight flag ("prefix still equal to N's"), and — for this property — the digit sum so far. Nothing else about the prefix matters: two prefixes at the same position, with the same tightness and the same sum, have identical sets of valid completions.

state · recurrence · base · order · cost (digits of N are n₀ n₁ … n_{L−1}, most significant first)STATE f(pos, tight, s) = the number of ways to fill positions pos … L−1 so that the whole number is ≤ N (given the prefix's tightness) and the final digit sum is k, when the prefix has sum s RECURRENCE f(pos, tight, s) = ∑ over d = 0 … lim of f(pos + 1, tight AND d = lim, s + d) where lim = n_pos if tight else 9 — the next position is tight only if it was tight and the digit chosen is the largest allowed BASE f(L, ·, s) = 1 if s = k else 0; and prune: f(·, ·, s) = 0 whenever s > k (the sum cannot decrease) ORDER top-down with a memo over (pos, tight, s) — the recursion is well-founded because pos increases; the start is f(0, true, 0) ANSWER f(0, true, 0) = the count in [0, N]; for a range [A, B] answer B minus answer (A − 1) COST at most L × 2 × (k + 1) states, 10 choices each ⇒ O(10 · L · k) time and O(L · k) space — for N = 253, k = 7: 48 possible states, 13 actually visited (measured) "tight" is true in at most one state per position (the prefix equal to N's), so the tight half of the lattice is a single path of L states

The trace shows the three regimes a digit walk passes through. Tight states are the spine: at most one per position (the prefix equal to N's own digits), each with a limited range. Loose states are where the counting happens: once the prefix has dropped below N's, the remaining positions are unconstrained and the answer depends only on how many positions remain and on the summary — which is why f(2, F, s) is the same function of s regardless of how the prefix reached it, and why the memo pays: f(2, F, 2) is requested from f(1, F, 0) with d = 2, from f(1, F, 1) with d = 1, and from f(1, T, 2) with d = 0, and computed once. The third regime is pruning: a summary that can never recover (sum already above k) returns 0 immediately, which the counter shows as calls that are neither computations nor hits.

Other properties, other summaries

The summary is whatever the property needs to be checked one digit at a time; the position and tight bit never change. "No two adjacent digits equal" needs the previous digit (10 values) and — because leading zeros are not real digits — a started flag, so that 007 is not rejected for its two zeros; the state is (pos, tight, started, prev), at most L × 2 × 2 × 10. On N = 253 that property holds for 212 of the 254 integers (the 42 exceptions are 11, 22, …, 99, 100, 110–119, 122, 133, …, 200, 211, 220–229, 233, 244), computed from 16 memo states and confirmed by brute force. "Divisible by m" needs the remainder so far (m values, updated as (10·r + d) mod m). "Contains the digit 4" needs one bit. "Number of digits equal to 1" (the classic "count the 1s written from 1 to N") needs the count so far, or better, is computed as a plain sum of per-position counts. "Digits non-decreasing" needs the previous digit. The general recipe is: identify the smallest summary of a prefix that determines which completions are valid, and the memo is over (position, tight, summary). When the summary is Θ(L)-sized — the sum, the count — the state space is O(L²); when it is a bitmask of the digits used, it is O(L·2¹⁰); in every case it is polynomial in L = log₁₀ N, hence polylogarithmic in N.

Where it fits

Digit DP is a prefix DP in disguise. The "string" is the decimal expansion of N, the state is a prefix of it plus a summary, and the tight bit is exactly the device that turns the inequality x ≤ N — a global constraint on the whole number — into a local one that each position can check on its own. The same device appears wherever a global bound must be enforced digit by digit or character by character: counting strings lexicographically below a given string with a pattern constraint, counting binary numbers with a bit property (the base is 2 and the tight bit works unchanged), and the "minimum number ≥ N with a property" questions, which reverse the sum into a min and add a reconstruction. What makes it worth its own section is the habit it teaches: when a problem's natural search space is the integers up to N, and N is far too large to enumerate, the right question is "what does a position-by-position walk need to remember" — and the answer is almost always a state of size polynomial in log N.
