26 Space optimisation, and reconstruction after rolling

A table entry may be discarded the moment no later entry will read it, so the memory a bottom-up dynamic program needs is not the size of its table but the size of the window of entries still to be read — one row when the recurrence looks back one row, two rows when it also reads the current row, k rows for a look-back of depth k, and a constant when the state is one-dimensional. Every table on this page was drawn in full because the figures step through it, but the value alone never needed it: Fibonacci keeps two numbers, the knapsack keeps one row of W + 1, LCS and edit distance keep two rows of the shorter string. The price of rolling is the walk-back. Reconstruction reads cells that a rolled program has already overwritten, and this section is about that trade — what the window rule gives, what it takes, and the three ways to get the solution back without paying for the whole table: Hirschberg's split, checkpointing, and storing the choices instead of the values.

the window rule — how many rows must be alivea recurrence that reads dp[i − 1][·] only → ONE row, overwritten in place, if the in-row reads are ordered so that each cell is read before it is overwritten (knapsack 0/1: w downward, §12) dp[i − 1][·] and dp[i][·] → TWO rows (LCS §14, edit distance §15: up, left and up-left; the "left" read is the current row) dp[i − 1][·] … dp[i − k][·] → k rows, a circular buffer indexed by i mod k (a k-step staircase; Bellman-Ford's distₖ reads only distₖ₋₁, so it is the one-row case, §23) dp[i − 1], dp[i − 2] (1-D) → two scalars (Fibonacci, stairs, house robber); Kadane keeps one plus the running best interval DP, by length: an ENDPOINT recurrence reads lengths l − 1 and l − 2 only → two diagonals of n words (palindromic subsequence, §21) a SPLIT recurrence reads EVERY shorter length → does not roll: the whole triangle stays (matrix chain §19, optimal BST §20, burst §21) the general statement: space = the maximum, over the evaluation order, of the number of entries written but not yet finished with; a topological order of §05's graph that keeps that number small is a "narrow" order what rolling does NOT changetime — the same cells are computed, once each; correctness — each read still sees the value the recurrence names, PROVIDED the in-row order respects the loop-direction rule of §12; the answer's location — dp[n][W] is still the last cell written, L[m][n] is still the bottom-right of the last row

Why the window is what it is

The rule follows from §05: the working set is the set of states written but still to be read, and a row-major order over a two-index recurrence that reads only the previous row leaves exactly one row pending at any moment. LCS reads three neighbours, two of them in the previous row and one in the current, so the current row must exist alongside the previous one — two rows — and by making the shorter string index the columns the two rows are as short as possible: 2·(min(m, n) + 1) words, which the §14 figure measures as 14 on the worked pair against 8 × 7 = 56 table entries. The knapsack recurrence reads only row i − 1, and the two reads it makes — dp[i − 1][w] and dp[i − 1][w − wᵢ] — are both at columns ≤ w, so a single row overwritten from the right never destroys a value before it is read; that is the downward loop of §12, and the same row swept upward is a different program (the unbounded knapsack), not a faster one. For a one-dimensional state the window is the look-back depth: two scalars for a recurrence in i − 1 and i − 2. And for the interval family the window is decided by the transition's shape rather than the state's: the palindromic-subsequence recurrence reads L[i + 1][j − 1], L[i + 1][j] and L[i][j − 1], all of length l − 1 or l − 2, so filling by length keeps two diagonals — 2n words against the n(n + 1)/2 = 45 cells of the n = 9 figure — whereas matrix chains read m[i][k] + m[k + 1][j] for every split k, which touches every shorter length, and nothing can be discarded until the top entry is done.

What is lost: the walk-back

Every reconstruction on this page walks the finished table backwards — s[j] for rod cutting, the keep test dp[i][w] ≠ dp[i − 1][w] for knapsack, the three-way case test at (i, j) for LCS and edit distance, root[i][j] for search trees — and each step reads a cell chosen by the previous step, anywhere in the table. A rolled program has overwritten all but the last row, so the first step of the walk-back succeeds and the second reads garbage. The value is intact; the solution is gone. This is not a small loss: for alignment, diff, parsing and scheduling the solution is the output and the value is a by-product, and §07's checklist item 6 ("decide before writing the loop whether the solution is wanted") exists because rolling and reconstruction pull in opposite directions. There are three ways to have both, in increasing order of generality and decreasing order of elegance.

Way one: Hirschberg — recompute the split, recurse

§16 is the full treatment. The forward pass in two rows gives the middle row's scores; the same pass on the reversed strings gives the scores from the middle row to the end; their sum's minimum locates a column through which some optimal path crosses the middle row; recurse on the two sub-rectangles. Space O(m + n), time under n·∑ₖ⌈m/2ᵏ⌉ ≈ 2mn, measured on kitten → sitting at 80 cells against the plain table's 42. Its hypothesis is the one stated there — a grid DAG in which every path crosses every row, a recurrence local to adjacent rows, an additive objective — which LCS, edit distance and linear-gap alignment satisfy and interval DPs and weighted interval scheduling do not. When it applies it is the answer: linear space, a constant-factor time penalty, and an exact solution.

Way two: checkpointing — keep every r-th row, rebuild the gaps

Checkpointing is the general tool: it needs nothing from the recurrence except that a row is a function of the previous few, so it applies to knapsack, to weighted interval scheduling (checkpoint OPT every r indices; the block rebuild is O(r)), to the Bellman-Ford rounds of §23 and to any DP whose table is a sequence of rows. Its guarantee is weaker than Hirschberg's — √m rows rather than one — but its cost is a fixed factor of two and the code is the forward loop plus a bookkeeping wrapper. The routine behind the numbers above, lcsCheckpoint, is exercised by the load-time audit of §31 on random pairs against the full-table traceback; on this page's tiny instances it is a demonstration, not a saving, and the honest statement of when it pays is "when m is in the thousands and the full table would not fit".

Way three: store the choice, not the value

A walk-back does not need the numbers; it needs, at each cell, which case won. That is a small integer — one of two cases for knapsack and weighted intervals, one of three for LCS and edit distance, one of n for a split table — and it fits in one or two bits per cell where the value needed a word. The knapsack routine already keeps such a table: keep[i][w], one boolean per cell, 44 bits on the worked instance beside the 44 computed values; roll the values to one row and keep the bit table, and the walk-back works unchanged, because the test "dp[i][w] ≠ dp[i − 1][w]" has been replaced by the stored answer to that test. LCS's arrow table dirs[i][j] ∈ {↖, ↑, ←} is two bits per cell — 42 × 2 = 84 bits on the worked pair against 42 integers of the value table. The space is still Θ(mn) in cells, so this is a constant-factor saving (a factor of 16 to 32 in bytes), not an asymptotic one; it is the right tool when the table is large but not enormous, when the walk-back must be exact and cheap, and when Hirschberg's hypothesis fails — the split tables of §19–§20 are the case in point, where s[i][j] and root[i][j] already are the choice tables and the value tables can be discarded once the top entry is known. A bitset over mn cells at one bit each is what production diff and alignment tools keep when they keep anything.

When the full table is cheap anyway

Rolling is an engineering decision, and on most of this page it would be the wrong one. A table of a few thousand entries is nothing; a table of 10⁶ entries is a few megabytes; the trouble starts at 10⁸–10⁹ entries, which for a prefix-pair DP means strings of tens of thousands of characters and for knapsack means n·W in the hundreds of millions. Below that, keep the table: the walk-back is free, the code is the recurrence and nothing else, and every cell can be inspected when the answer looks wrong, which is the debugging tool §30 will recommend. Two further remarks. Memoized programs do not roll at all — the memo holds every reached state until the top call returns (§06), and when memory is the constraint that is a reason to convert to a loop. And rolling interacts with parallelism in the opposite direction from what one might expect: the anti-diagonal order that lets a prefix-pair table be filled in wavefronts (§15) needs three diagonals alive rather than two rows, so the narrowest order and the most parallel order are different topological orders of the same graph, and a program picks one.

The rule and its price. Alive = written but not yet read; the window is the look-back depth of the recurrence in the chosen order; rolling costs nothing in time and everything in reconstruction. Get the solution back by Hirschberg's split when the recurrence is local and the objective additive (linear space, twice the time), by checkpointing when it is not (√m rows, twice the time, any row-by-row DP), or by keeping the choices as bits when a factor of sixteen in bytes is enough. And before doing any of it, ask whether the table fits — usually it does.

27 The named optimisations and their hypotheses

A dynamic-programming optimisation is a theorem of the form "if the cost function has property P, then the inner minimisation over choices can be answered in less than linear time", and each of the named ones trades one factor of n for one hypothesis on the costs. None of them changes the state space or the recurrence; they change how the min (or max, or ∑) over candidates is evaluated, by exploiting an order among the candidates that the hypothesis guarantees. That is also why every one of them is dangerous: applied to a recurrence whose costs lack the property, the narrowed search silently returns a suboptimal table, with no error and often a plausible number. This section states six of them — the monotone deque, Knuth's optimisation, the divide-and-conquer optimisation, the convex hull trick with its Li Chao generalisation, the sum-over-subsets transform, and bitset acceleration — each with its exact hypothesis, its cost before and after, and a two-line reason it works. Two are measured on this page: the monotone deque in the figure below, and Knuth's window in §20's figure, where it examined 28 candidate roots instead of 35 and returned the same 2.75. The other four are stated, not measured.

1. The sliding window and the monotone deque — measured

the recurrence shapedp[i] = c(i) + min over j ∈ [i − k, i) of dp[j] (reach position i by a jump of at most k from some j, paying c(i) on landing; dp[0] = c(0)) naive: examine every j in the window → ∑ᵢ min(i, k) ≈ nk candidate examinations = Θ(nk) HYPOTHESISthe candidate set is a WINDOW whose two ends only move forward as i grows, and the quantity minimised is a function of j alone (dp[j], or dp[j] + g(j)) — nothing in the candidate depends on i the deque, and why it is O(n)keep a deque of indices from the window with dp INCREASING from front to back. At step i: expire the front if it has left the window (index < i − k); the front is now the window minimum → dp[i] = c(i) + dp[front] pop from the back every j with dp[j] ≥ dp[i], then push i (such a j is older than i AND no better: it leaves the window before i does and is never the minimum again — DOMINATED) each index is pushed once and popped or expired at most once ⇒ ≤ 2n deque operations in all, whatever k is ⇒ O(n), amortised O(1) per step measured at k = 3 on the figure's 12 costs: naive 30 examinations = ∑ min(i, 3); deque 16 comparisons, 12 pushes, 5 pops + 4 expiries; both return 18; brute force over all 504 jump sequences: 18

The dominance argument is the whole proof. An index j at the back with dp[j] ≥ dp[i] can never again be the minimum of any future window, because every future window that contains j also contains the newer, no-worse i; so j may be forgotten, and after the pops the deque is increasing in dp from front to back, which is exactly the invariant that makes the front the minimum. Expiry handles the other end: the front is the oldest survivor, so it is the only index that can fall out of the window at step i, and one comparison per step keeps the window honest. The same structure answers "minimum of every window of width k over an array" in O(n), and it is what turns the bounded knapsack of §12 into Θ(nW) without the logarithm: for item i with multiplicity kᵢ, the recurrence over capacity w reads f[w − t·wᵢ] + t·vᵢ for t = 0..kᵢ, which, after grouping capacities by their residue modulo wᵢ and subtracting the linear term, is a sliding-window maximum over each residue class. The deque itself is the Linked Stacks & Queues page's deque used as an algorithm rather than a container.

2. Knuth's optimisation — measured in §20

the recurrence shapedp[i][j] = w(i, j) + min over r = i … j of ( dp[i][r − 1] + dp[r + 1][j] ) (an interval recurrence whose split cost depends only on the interval, not on r) naive: Θ(n²) intervals × O(n) roots = O(n³) HYPOTHESIS (on w alone)quadrangle inequality w(a, c) + w(b, d) ≤ w(a, d) + w(b, c) for all a ≤ b ≤ c ≤ d monotonicity w(b, c) ≤ w(a, d) whenever [b, c] ⊆ [a, d] then dp inherits the quadrangle inequality, and the smallest optimal root satisfies opt(i, j − 1) ≤ opt(i, j) ≤ opt(i + 1, j) the narrowed loop and its costr ranges over [opt(i, j − 1), opt(i + 1, j)] instead of [i, j]; for a fixed length l the ranges telescope: ∑ᵢ (opt(i + 1, j) − opt(i, j − 1) + 1) ≤ n + (n − l + 1) ≤ 2n ⇒ O(n) per length, O(n²) in all. §20 measured 28 candidates against 35 for the plain loop, and verified the monotonicity on all 10 pairs of the finished table

Why the hypothesis is needed is visible in the one interval problem on this page where it fails: matrix chains. There the split cost pᵢ₋₁·pₖ·pⱼ depends on the split point k, so it is not a w(i, j) at all, and the roots are not monotone — a narrowed loop would examine the wrong k range and return a table whose top entry is merely the best among the splits it tried. For the optimal search tree w(i, j) is a sum of probabilities over the interval, which satisfies the quadrangle inequality with equality and is monotone on inclusion, so the theorem applies. The same test — is the split cost a function of the interval only, and does it satisfy the inequality? — settles the other classical instances: merging adjacent piles with cost equal to their total weight (yes), and most cases where the cost is a sum over the merged range; the general result is Yao's quadrangle-inequality theorem — at bottom a monotonicity lemma about the argmin of a function with the quadrangle property, the same lemma that licenses the divide-and-conquer optimisation below — and the practical rule is that the hypothesis must be checked on the cost function, not assumed because the recurrence has the right shape.

3. The divide-and-conquer optimisation — hand-worked, not measured

the recurrence shapedp[i][j] = min over k < j of ( dp[i − 1][k] + C(k, j) ) (split the prefix of length j into i groups; the last group is (k, j]; i = 1 … K) naive: K rows × n cells × O(n) candidates = O(K·n²) HYPOTHESISthe argmin is MONOTONE along a row: opt(i, j) ≤ opt(i, j + 1) (guaranteed when C satisfies the quadrangle inequality, as a cost that is a sum over the group, or a "square of the sum", does) the algorithm, one row at a timeSOLVE(row i, cells [lo, hi], candidates [klo, khi]): j = ⌊(lo + hi)/2⌋; scan k ∈ [klo, khi] for the best; then SOLVE(i, [lo, j − 1], [klo, opt(j)]) and SOLVE(i, [j + 1, hi], [opt(j), khi]) — each recursion level scans O(n + number of cells) candidates in total ⇒ O(n log n) per row, O(K·n log n) overall

The two-line reason: computing the middle cell's argmin by a full scan tells you that every cell to its left has its argmin at or before that point and every cell to its right at or after it, so the two halves search disjoint-ish candidate ranges whose total length is about n per level of recursion, and there are log n levels. It is the optimisation of choice for "partition into K contiguous groups" problems — segmenting a sequence into K pieces at minimum total cost, placing K facilities — where Knuth's interval form does not apply because the state is (groups, prefix) rather than (interval). Its hypothesis is weaker than Knuth's (monotone argmin only), and it fails, silently, on costs that reward long groups more than proportionally in a non-convex way.

Two things the trace shows that the statement does not. The middle cell's argmin is found by a scan over the whole candidate range, so the correctness of the top level does not depend on the hypothesis at all; the hypothesis is used only to restrict the ranges handed to the two halves, and if it is false the restricted scans can miss the true argmin without any sign of it — which is why "check the cost function" is the rule. And the ranges are not disjoint: the left half keeps [klo, opt(j)] and the right half [opt(j), khi], sharing the endpoint, which is where the "n plus the number of cells" per level comes from.

4. The convex hull trick, and the Li Chao tree — stated, not measured

the recurrence shapedp[i] = min over j < i of ( mⱼ · xᵢ + bⱼ ) where the slope mⱼ and intercept bⱼ depend on j (typically bⱼ = dp[j] + something), and xᵢ on i — every earlier state contributes a LINE in the query variable x, and dp[i] is the lower envelope of those lines evaluated at xᵢ. naive: O(n²) HYPOTHESIS, three strengths(a) slopes mⱼ arrive in monotone order AND queries xᵢ are monotone → keep the lower envelope in a deque; a line that is never below the envelope (cross-product test on three consecutive lines) is discarded; queries walk a pointer forward: amortised O(1) per state, O(n) in all (b) slopes monotone, queries arbitrary → the same envelope, binary search per query: O(log n) per state (c) neither monotone → a LI CHAO TREE over the query range: a segment tree in which each node keeps the line that wins at its midpoint; insert by descending and swapping the loser down; query by descending and taking the min: O(log C) per insert and per query over a coordinate range of size C (O(log n) after compressing the n query points)

The two-line reason for (a): with slopes sorted, the lower envelope of the lines is a convex chain whose pieces appear in slope order, so a new line either extends the chain at the end or makes some trailing pieces redundant — a stack discipline — and monotone queries sweep the chain once, exactly as the deque of optimisation 1 sweeps a window. For (c): at each node of a segment tree exactly one line can be the best at the node's midpoint, and any other line beats it on at most one side of the midpoint, so it is pushed into one child; a query descends one root-to-leaf path and one of the lines it meets is the minimum at that point. The trick appears whenever a cost has the form "a rate times a distance plus a state-dependent constant" — a batch that starts at time xᵢ and pays mⱼ per unit, a segment whose cost is a product of an aggregate of each side — and it is how O(n²) recurrences of that form become O(n) or O(n log n). The hypothesis to check before reaching for it is that the candidate really is linear in a query variable; a quadratic term in xᵢ that also multiplies j's data breaks the envelope structure.

5. Sum over subsets — hand-worked, not measured

the problemgiven f(T) for every subset T of an n-element set, compute F(S) = ∑ over T ⊆ S of f(T) for EVERY S (the zeta transform; ∑ may be max, OR, or any commutative associative combine) naive: enumerate the submasks of each S: ∑ₛ 2^{|S|} = 3ⁿ terms in all HYPOTHESISthe aggregate is over SUBSETS (or supersets) of the state, one bit at a time, with a combine that is associative and commutative the transform, one dimension at a timeF₀(S) = f(S); for bit b = 0 … n − 1: F_b(S) = F_{b−1}(S) + [ bit b ∈ S ] · F_{b−1}(S ∖ {b}) n passes over 2ⁿ masks ⇒ O(n · 2ⁿ) after pass b, F_b(S) sums f over all T that agree with S on the bits above b and are ⊆ S on the bits ≤ b — an n-dimensional prefix sum, one axis per pass

The two-line reason: a subset relation is a product of n one-bit relations ("bit b of T ≤ bit b of S"), and a prefix sum over a product of orders can be taken one coordinate at a time, exactly as a 2-D prefix-sum table is built by summing along rows and then along columns. It is the tool that makes the set-partition and set-cover recurrences of §24 — "f(S) = min over compatible T ⊆ S" — tractable when the inner aggregate is a sum or a count rather than a min over structured subsets, and its inverse (the Möbius transform, the same loop with a subtraction) recovers f from F. Its hypothesis is exactly the shape of the aggregate; a min over subsets with a per-T cost that is not decomposable across bits is back at 3ⁿ.

6. Bitset acceleration — stated, not measured

the recurrence shapea BOOLEAN table whose row update is an OR of shifted copies of the previous row: subset sum (§12): reach′ = reach OR (reach << aᵢ) — one shift and one OR over a bitset of T + 1 bits: ⌈(T + 1)/w⌉ word operations per item, w = 64 ⇒ O(n · T / w) instead of O(n · T); the same idea gives LCS in O(m · ⌈n/w⌉) with a bit-parallel formulation of the three-way recurrence HYPOTHESISthe state's value is one bit (or a small enumeration), and the transition is a bitwise operation on whole rows — shift, OR, AND, addition with carries — so that a machine word processes w cells at once

The two-line reason: the recurrence for subset sum is "s is reachable after item i if it was reachable before or if s − aᵢ was", which is a word-parallel OR of a shifted row, and the loop-direction rule of §12 is satisfied automatically because the shift reads the old row. This is a constant-factor optimisation (a factor of w), not an asymptotic one, but the factor is 64 on a 64-bit machine: a subset sum with n = 1 000 and T = 10⁶ is 10⁹ cell updates as a loop and about 1.6·10⁷ word operations as a bitset, and it is the version to use when the table is boolean and wide. The hypothesis is the boolean-ness: the moment the cells hold values that must be maximised, the shift-and-OR is gone and the ordinary row update returns.

28 The Bellman equation, Viterbi, CTC — and why beam search is not DP

The Bellman optimality equation, V*(s) = max over actions a of [ r(s, a) + γ·∑ over s′ of P(s′ | s, a)·V*(s′) ], is a dynamic-programming recurrence over a state space that may contain cycles, and value iteration is its tabulation — a sweep of Bellman backups repeated until the table stops changing, with convergence guaranteed not by acyclicity but by the discount γ < 1, which makes each sweep a contraction. Viterbi decoding is the same recursion on a trellis of hidden states against time, with a product in place of the sum and a maximum over predecessors; the forward algorithm is the sum-product version on the same trellis; and CTC is the forward or Viterbi recursion on a trellis extended with blank states. All four are exact, because each keeps one value per state and the optimal-substructure argument goes through; beam search, which keeps the k best partial hypotheses and discards the rest, is not dynamic programming and has no such guarantee — which the figures below demonstrate with a width-1 beam that returns the wrong path on the default instance.

Why it is dynamic programming, and what replaces the evaluation order

Every ingredient of §01's template is present: a state, a recurrence over choices, a base case, a table and a reconstruction (the greedy policy). What is missing is a well-founded order, because the subproblem graph has cycles — from a cell of the gridworld an action can lead back to the same cell, and V(s) then depends on itself. §23 handled cycles in shortest paths by indexing the state with an edge count, so that distₖ(v) reads only distₖ₋₁; value iteration is exactly that move — Vₖ reads only Vₖ₋₁ — with one difference. Bellman-Ford's index is bounded by V − 1 because a shortest path is simple; an infinite-horizon return has no such bound, and the iteration would run forever were it not for the discount. The contraction is what the acyclicity was for: it guarantees that the sequence Vₖ settles, geometrically, at the unique fixed point, so the "table" is infinite in k but effectively finite, and it gives the stopping rule that turns the infinite recursion into a finite loop. The hand-off is the whole of model-based reinforcement learning: Reinforcement Learning, §03 derives the equation from the definition of return, and its §04 builds policy iteration and value iteration as the planning algorithms; the model-free methods that follow there are sampled approximations of the same backup. Here the point is narrower: it is §23's DP with the DAG condition replaced by a contraction, and the figure measures the contraction rather than assuming it.

Worked on the gridworld of the figure

The instance is a 4 × 4 grid with the goal (reward +1) in the top-right cell, a pit (reward −1) directly below it, one wall, a step reward of −0.04 on every non-terminal move, four actions, and a slip: the intended move happens with probability 0.8 and each perpendicular move with probability 0.1; a move into a wall or off the grid leaves the agent where it is. With γ = 0.9 the first sweep gives every non-terminal cell the step reward −0.04 except the cell left of the goal, which becomes 0.8·1 + 0.1·(−0.04) + 0.1·(−0.04) = 0.792 (right with probability 0.8 into the goal; up stays put and down moves, each costing the step reward) and that 0.792 is the first residual r₁ the readout prints. The residuals then fall — 0.563, 0.399, 0.281, … — each at most 0.9 times the last (the measured ratios are between 0.44 and 0.79), and after 24 sweeps the largest change is below 10⁻⁶: 1 248 backups in all, which is 24 × 13 non-terminal, non-wall states × 4 actions. The finished value at the cell left of the goal is 0.9282, and it is a fixed point of its own backup: 0.8·1 + 0.1·(−0.04 + 0.9·0.9282) + 0.1·(−0.04 + 0.9·0.5849) = 0.9282 to four places, where 0.5849 is the value of the cell below it. The bottom-left start cell is worth 0.2750. The policy read off the table goes right along the top row and up the left column, and — the interesting part — the two cells directly below the pit are told to move left rather than up, away from the pit's slip risk and round the long way, which is what the expectation inside the max buys over a shortest-path rule. Policy iteration on the same model, run by the figure as the independent check, reaches the same values after 4 evaluate-improve rounds and the same greedy action in every state.

CTC: Viterbi and forward on an extended trellis — hand-worked, not measured

the extended-alphabet tricka network emits, at each of T frames, a distribution yₜ over an alphabet plus a BLANK symbol ∅. A frame sequence is COLLAPSED to a label by merging repeats, then deleting blanks: "∅ c ∅ a a ∅ t t ∅" → "cat" the probability of a label l is the sum over every frame sequence that collapses to it — exponentially many, so a DP: l′ = ∅ l₁ ∅ l₂ ∅ … ∅ l_L ∅ the label with a blank inserted around every symbol: 2L + 1 trellis states STATE (t, s) — αₜ(s) = the total probability of the frame prefixes of length t that collapse to a prefix of l ending in state s of l′ RECURRENCE αₜ(s) = [ αₜ₋₁(s) + αₜ₋₁(s − 1) + αₜ₋₁(s − 2)·[l′ₛ ≠ ∅ and l′ₛ ≠ l′ₛ₋₂] ] · yₜ(l′ₛ) (stay; advance one; skip the blank between two DIFFERENT symbols — the skip is forbidden across a blank between equal symbols, which is how "aa" stays distinct from "a") BASE α₁(1) = y₁(∅), α₁(2) = y₁(l₁), else 0; ANSWER P(l | x) = α_T(2L + 1) + α_T(2L) COST T · (2L + 1) states × 3 predecessors = O(T · L) per label; the Viterbi version (max in place of ∑) gives the single best alignment

CTC is the forward algorithm on a trellis whose states are the positions in l′ and whose allowed transitions encode the collapsing rule — no new idea, but a state space chosen so that "every frame sequence that collapses to l" is exactly "every path through the trellis", which is §07's checklist applied to a sequence-labelling problem. The ∑ is what training needs (the loss is −log P(l | x), differentiable through the recursion); the max is what greedy decoding approximates by taking the argmax frame by frame. The Speech Processing page names CTC as the alignment-free training objective of end-to-end recognisers, and the Hidden Markov Models & CRFs page is where Viterbi and forward live as the decoding and evaluation problems of an HMM; this page's contribution is that both are the trellis instance of the template, with the cost T·S² measured on the figure above and the CTC cost O(T·(2L + 1)) following from the same count with three predecessors per state.

Why beam search is not dynamic programming

Beam search over the same trellis keeps, at each time step, the k partial state sequences of highest probability so far, extends each by every state, and keeps the best k of the results; at k = 1 it is greedy decoding. It looks like Viterbi with a smaller table, and the difference is where the values live. Viterbi keeps one value per state — δₜ(j) for every j, S values per column — and the optimal-substructure argument guarantees that the best full path passes through some (t, j) and that its prefix is the best path to that (t, j), so nothing is lost by keeping only the best path to each state. Beam search keeps k hypotheses, ranked by their own probability, and a prefix that ranks below the k-th at time t is gone, even if it is the prefix of the eventual optimum. On the figure's default observations the width-1 beam stays in S₁ for all six steps and returns a path of probability 1.543·10⁻⁴, while Viterbi finds S₁ S₂ S₂ S₂ S₃ S₃ at 4.593·10⁻⁴, three times as likely; the width-2 beam happens to recover it on this instance. Over all 64 observation strings of length 6 on this model, the checking script found width 1 wrong on 33 and width 2 wrong on 23 — and the load-time audit of §31 counts the same failure on random models. Beam search earns its place where DP cannot be run: when the "state" a hypothesis carries is its whole prefix — a neural decoder's hidden state depends on every token before it — no two hypotheses share a state, the trellis is a tree with Vᵀ leaves, and pruning to k is the only option. That is the greedy page's territory (Greedy Algorithms, §25), and the honest description of beam search is a k-wide greedy heuristic with no optimality guarantee, not an approximate DP. The test is the one this section keeps returning to: if the values are indexed by state and every state is kept, it is dynamic programming and it is exact; if hypotheses are ranked and discarded, it is search, and its answer is a lower bound.

One recursion, four costumes. Value iteration: max over actions of an expectation, on a cyclic state graph, converging by contraction. Viterbi: max over predecessors of a product, on a trellis, exact in one pass. Forward: the same with a sum, giving a total instead of a best. CTC: forward or Viterbi on a trellis whose states are the positions of a blank-padded label. In each the table has one entry per state, the entry is computed from its predecessors' entries, and the answer is exact because of §02's cut-and-paste argument — which is precisely what beam search gives up when it ranks hypotheses instead of indexing states.
