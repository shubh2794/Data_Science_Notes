14 Longest common subsequence

A subsequence of a string is the string with zero or more characters deleted (the rest keep their order); the longest common subsequence (LCS) of X = x₁…xₘ and Y = y₁…yₙ is a longest string that is a subsequence of both. The state is a prefix pair (i, j) — the LCS length of x₁…xᵢ and y₁…yⱼ — and the recurrence has three cases: if the last characters match, extend the LCS of both prefixes shortened by one; otherwise drop the last character of one string or the other and take the better. The table has (m + 1)(n + 1) entries, mn of them computed, in Θ(mn) time; the LCS itself is read back by a traceback of O(m + n) steps, and it is in general not unique. LCS is the archetype of the two-string state space that edit distance (§15), Hirschberg (§16) and sequence alignment all share.

the template instantiatedSTATE (i, j), 0 ≤ i ≤ m, 0 ≤ j ≤ n — L[i][j] = length of an LCS of the prefixes x₁…xᵢ and y₁…yⱼ RECURRENCE L[i][j] = L[i−1][j−1] + 1 if xᵢ = yⱼ (the match is the last character of an LCS) L[i][j] = max( L[i−1][j], L[i][j−1] ) if xᵢ ≠ yⱼ (at least one of xᵢ, yⱼ is not used: drop it) BASE L[0][j] = L[i][0] = 0 (an empty prefix has only the empty subsequence) ORDER row by row (i = 1..m, j = 1..n) — each cell reads the cell above, to the left, and diagonally up-left; any order that fills those first works (column-major, anti-diagonals) ANSWER L[m][n]; the string by traceback from (m, n): on a match emit xᵢ and go diagonally; otherwise go to whichever of L[i−1][j], L[i][j−1] equals L[i][j] COST mn cells × O(1) = Θ(mn) time; Θ(mn) space for traceback, O(min(m, n)) for the length alone

Correctness: the three-case argument

THEOREM (optimal substructure of an LCS). Let Z = z₁…zₖ be any LCS of X = x₁…xₘ and Y = y₁…yₙ.1. if xₘ = yₙ, then zₖ = xₘ = yₙ and z₁…zₖ₋₁ is an LCS of x₁…xₘ₋₁ and y₁…yₙ₋₁ 2. if xₘ ≠ yₙ and zₖ ≠ xₘ, then Z is an LCS of x₁…xₘ₋₁ and Y 3. if xₘ ≠ yₙ and zₖ ≠ yₙ, then Z is an LCS of X and y₁…yₙ₋₁ proof of 1 (cut and paste, twice)if zₖ ≠ xₘ, append xₘ (= yₙ) to Z: the result is a common subsequence of length k + 1 — contradiction. So zₖ = xₘ = yₙ. now z₁…zₖ₋₁ is a common subsequence of x₁…xₘ₋₁ and y₁…yₙ₋₁ of length k − 1; if a longer one W existed (length ≥ k), W followed by xₘ would be a common subsequence of X and Y of length ≥ k + 1 — contradiction. proof of 2 (3 is symmetric)zₖ ≠ xₘ means Z never uses xₘ, so Z is a common subsequence of x₁…xₘ₋₁ and Y; a longer one would also be a common subsequence of X and Y, longer than the LCS Z — contradiction. why the recurrence followscase 1 gives L[m][n] = L[m−1][n−1] + 1 when xₘ = yₙ. When xₘ ≠ yₙ, zₖ cannot equal both, so case 2 or case 3 applies, and L[m][n] = max(L[m−1][n], L[m][n−1]); both are achievable (any common subsequence of a prefix pair is one of the whole), so the max is exact. The subproblem space — all prefix pairs — is closed under all three cases.

The naive recursion on this recurrence is exponential in the worst case — when the last characters never match it makes two calls per level, and there are m + n levels — while the number of distinct prefix pairs is only (m + 1)(n + 1). On the worked pair the naive routine makes 152 calls for a table of 42 computed cells (the matches short-circuit many branches; on two strings with no character in common it would make far more); the figure prints both counts. The overlap is the whole reason for the table: L[i][j] is asked for once for each way of reaching (i, j) by deleting characters from the ends of the two strings, and there are exponentially many such ways.

Brute force — every one of the 2⁶ = 64 subsequences of the shorter string BDCABA, each tested for being a subsequence of ABCBDAB — reports length 4 and returns BDAB as the first longest it meets. Three lessons from one table: the length is unique; the string is not, and which one a program returns is a tie-breaking convention, not a property of the problem; and the traceback needs the table (or the arrows) but not the strings' future — it reads only cells already filled, which is why it costs O(m + n) steps and no more, one row or column consumed per step.

Traceback without the arrows, and the length in linear space

The direction table is a convenience, not a necessity: at (i, j) the traceback can recompute which case applied from L alone — a match if xᵢ = yⱼ, otherwise compare L[i − 1][j] with L[i][j − 1] — at the cost of one extra comparison per step, which saves the mn arrows but not the mn numbers. The numbers, in turn, are needed only for the traceback. If only the length is wanted, row i depends on row i − 1 and on itself, so two rows suffice, and by making the shorter string index the columns the working set is 2·(min(m, n) + 1) integers — 14 on the worked pair, against 8 × 7 = 56 for the full table — with the same Θ(mn) time (the figure's readout confirms the two-row routine returns 4 with the same 42 cell updates). A single row plus one saved diagonal value also works. But the rolling version cannot trace back, because the rows it would need to revisit are gone; recovering the alignment in linear space is a genuine problem, and its solution — recursing on a split point found by a forward and a backward half-pass — is Hirschberg's algorithm, §16. LCS also lives one substitution away from edit distance: with insertions and deletions allowed but no substitutions, the distance between X and Y is m + n − 2·LCS(X, Y), which on the worked pair is 7 + 6 − 8 = 5 — a value the edit-distance routine of §15 reproduces when substitution is priced at 2 (or above). The diff utilities that show two files' differences as lines kept, inserted and deleted are, in essence, LCS on lines under this cost model (with heuristics on top), which is why a diff is an LCS traceback and why it is not unique either.

15 Edit distance and its DAG

The edit distance (Levenshtein distance) between strings a = a₁…aₘ and b = b₁…bₙ is the minimum number of single-character insertions, deletions and substitutions that turn a into b. The state is again a prefix pair, D[i][j] = the cost of turning a₁…aᵢ into b₁…bⱼ; the recurrence is a three-way minimum — delete aᵢ, insert bⱼ, or line aᵢ up with bⱼ (free if they match, one substitution if not) — and the table costs Θ(mn). Each operation can carry its own price, the table is then a shortest path through a grid-shaped DAG with one vertex per cell, and the sequence of operations — the alignment — is read off by walking the path back. kitten → sitting is 3 under unit costs and 5 when a substitution costs 3; both are worked below and re-derived by the figure.

the template instantiated (costs cᵢₙₛ, c𝒹ₑₗ, cₛᵤ𝒷 — all 1 for the Levenshtein distance)STATE (i, j), 0 ≤ i ≤ m, 0 ≤ j ≤ n — D[i][j] = least cost to turn a₁…aᵢ into b₁…bⱼ RECURRENCE D[i][j] = min( D[i−1][j−1] + [aᵢ ≠ bⱼ]·cₛᵤ𝒷, align aᵢ with bⱼ: a match (cost 0) or a substitution D[i−1][j] + c𝒹ₑₗ, delete aᵢ D[i][j−1] + cᵢₙₛ ) insert bⱼ BASE D[0][j] = j·cᵢₙₛ (build b₁…bⱼ from nothing); D[i][0] = i·c𝒹ₑₗ (erase a₁…aᵢ) ORDER row-major — each cell reads up, left and up-left; ANSWER D[m][n]; the alignment by walking back along the winning case at each cell COST mn cells × O(1) = Θ(mn) time; Θ(mn) space with the alignment, O(min(m, n)) for the distance alone (two rows)

Weighted operations

Prices change the answer and the alignment, not the algorithm. With cₛᵤ𝒷 = 3 and insertions and deletions at 1, a substitution is dearer than a deletion followed by an insertion, so the recurrence never chooses it: kitten → sitting becomes 5 — insert s, delete k, keep itt, insert i, delete e, keep n, insert g, in the column order the routine's walk-back produces — and the naive recursion, re-run with the same prices, also returns 5. With insertions and deletions at 2 and substitutions at 1 the unit-cost alignment survives and the cost is 1 + 1 + 2 = 4. The general rule is the triangle inequality on the prices: whenever cₛᵤ𝒷 ≥ cᵢₙₛ + c𝒹ₑₗ substitution is dominated and the distance collapses to the insert/delete distance c𝒹ₑₗ·(m − LCS) + cᵢₙₛ·(n − LCS) of §14 — which is c·(m + n − 2·LCS) when the two gap costs are equal (the worked pair gives 7 + 6 − 2·4 = 5 for the LCS strings, and 6 + 7 − 2·4 = 5 here, since LCS(kitten, sitting) = ittn has length 4). Costs may also depend on the characters — a substitution matrix in sequence alignment, keyboard distance in spelling correction — and the recurrence is unchanged as long as every cost is non-negative. (Negative costs still give a well-defined minimum over the DAG below, but the result is no longer a distance — a path could profit from inserting a character and deleting it again — which is why sequence alignment in biology is phrased as a score to maximise, with a substitution matrix and gap penalties; affine gap penalties then need two extra states per cell — a gap open in either string, three values per cell in the standard formulation — an extension rather than a new idea.)

The named variants: Wagner–Fischer, Needleman–Wunsch, Smith–Waterman, Damerau–Levenshtein

The table above carries several names, each attached to a different reading of the costs. Wagner–Fischer is the edit-distance table itself: the three-way minimum over prefix pairs with per-operation costs, exactly as the formula block at the top of the section states it. Needleman–Wunsch is the same recurrence turned into global alignment: a maximisation with a substitution matrix s(aᵢ, bⱼ) in place of [aᵢ ≠ bⱼ]·cₛᵤ𝒷 and a gap penalty −g in place of the insert and delete costs, the whole of both strings aligned end to end, and the answer at (m, n) as before. Smith–Waterman is local alignment — the best-scoring pair of substrings, one from each string — and it changes two things only: every cell takes a max with 0, so that an alignment may start afresh anywhere, and the answer is the largest entry anywhere in the table rather than H[m][n], with the alignment traced back from that cell until a 0 is reached. That second change is the same trap as Kadane's maximum subarray in §08: the recurrence computes "best alignment ending here", and the answer is a maximum over all states, not the value at the last one. Damerau–Levenshtein adds a fourth operation, the transposition of two adjacent characters, as one more candidate in the minimum — D[i−2][j−2] + 1 when aᵢ₋₁ = bⱼ and aᵢ = bⱼ₋₁ — so that ca → ac costs 1 (one transposition) instead of 2 (two substitutions, or a deletion and an insertion). That is the restricted form, in which a transposed pair is not edited again; the unrestricted distance, where it may be, needs a table indexed also by the last row and column at which each character occurred, and is the form that is a metric.

the four recurrences side by side (the base rows and columns differ; the interior is one line each)WAGNER–FISCHER D[i][j] = min( D[i−1][j−1] + [aᵢ ≠ bⱼ]·cₛᵤ𝒷, D[i−1][j] + c𝒹ₑₗ, D[i][j−1] + cᵢₙₛ ) answer D[m][n] NEEDLEMAN–WUNSCH S[i][j] = max( S[i−1][j−1] + s(aᵢ, bⱼ), S[i−1][j] − g, S[i][j−1] − g ); S[i][0] = −i·g, S[0][j] = −j·g answer S[m][n] SMITH–WATERMAN H[i][j] = max( 0, H[i−1][j−1] + s(aᵢ, bⱼ), H[i−1][j] − g, H[i][j−1] − g ); H[i][0] = H[0][j] = 0 answer max over ALL (i, j); trace back to the first 0 DAMERAU–LEVENSHTEIN D[i][j] = min( the three Wagner–Fischer candidates, D[i−2][j−2] + 1 if aᵢ₋₁ = bⱼ and aᵢ = bⱼ₋₁ ) answer D[m][n] (restricted form) affine gaps three tables — M (aᵢ aligned with bⱼ), X (gap in b: open cost o, extend cost e), Y (gap in a) — so a run of k gaps costs o + (k − 1)·e rather than k·g

The table is a DAG, and the distance is a shortest path

the edit graphvertices (i, j) for 0 ≤ i ≤ m, 0 ≤ j ≤ n — one per cell edges (i−1, j) → (i, j) weight c𝒹ₑₗ (down: delete aᵢ) (i, j−1) → (i, j) weight cᵢₙₛ (right: insert bⱼ) (i−1, j−1) → (i, j) weight [aᵢ ≠ bⱼ]·cₛᵤ𝒷 (diagonal: match or substitute) D[i][j] = the length of a shortest path from (0, 0) to (i, j); an optimal alignment = a shortest (0, 0) → (m, n) path, one edge per column the graph is acyclic (every edge increases i + j), row-major order is a topological order, and the DP is exactly the single-source shortest-path relaxation over a DAG in that order — §23 makes that the general statement

Seeing the table as a graph explains several things at once. The DP's Θ(mn) is the O(V + E) of DAG shortest paths with V = (m + 1)(n + 1) and E < 3V. Any topological order works — anti-diagonals i + j = const are one, which is the order that lets the table be filled in parallel wavefronts. Dijkstra's algorithm would also solve it, the weights being non-negative, and with a heap that is the basis of the "only explore cells with D ≤ d" trick: if the distance is small, only the cells within a band of width about d around the diagonal can lie on a shortest path, and the table can be restricted to O(d·min(m, n)) cells. The DAG view also shows why the alignment is not unique — distinct shortest paths — and why the walk-back is O(m + n): every edge advances i or j or both. §23 takes the general case: any DP whose recurrence reads "min over incoming edges" is a shortest path on the subproblem DAG, and the choice of algorithm is the choice of how to traverse it.

16 Hirschberg: the alignment in linear space

Hirschberg's algorithm recovers an optimal alignment — not just its cost — in O(m + n) space and still Θ(mn) time, by finding the column where an optimal path crosses the middle row of the edit-distance table using one forward and one backward linear-space pass, and then recursing on the two sub-rectangles that split creates. The two-row trick of §14–§15 computes the value in linear space but destroys the rows a walk-back would need; Hirschberg keeps the value's economy and replaces the walk-back by divide and conquer. Its cost is a geometric sum: the top level touches mn cells, the next level about half, and the total stays below roughly 2mn — on the worked pair 80 cells against a full table of 42. Everything here is stated for edit distance; the same construction works for LCS and for any prefix-pair DP whose recurrence looks only at adjacent cells.

the two linear-space passes (D is the edit-distance table of §15; mid = ⌊m/2⌋)FORWARD F[j] = D(a₁…a_mid, b₁…bⱼ) for j = 0..n — the middle row of the table for a's first half, computed with two rows of length n + 1 BACKWARD R[j] = D(a_mid+1…aₘ, bⱼ₊₁…bₙ) for j = 0..n — the cost of aligning a's second half with b's SUFFIX after column j; computed as the forward pass on the REVERSED strings (reverse(a_mid+1…aₘ), reverse(b)) and read backwards the splitCLAIM. D(a, b) = min over j = 0..n of [ F[j] + R[j] ], and any j attaining the minimum is a column through which SOME optimal alignment passes row mid. PROOF. ≥: an optimal path from (0, 0) to (m, n) in the edit graph must visit row mid (every edge raises i by 0 or 1); let (mid, j) be a vertex it visits there. its prefix up to (mid, j) costs ≥ F[j] and its suffix from (mid, j) costs ≥ R[j], so D(a, b) ≥ F[j] + R[j] ≥ min. ≤: for any j, an optimal prefix path realising F[j] followed by an optimal suffix path realising R[j] is a legal path costing F[j] + R[j], so D(a, b) ≤ min. ∎ THEN recurse: align (a₁…a_mid, b₁…b_q) and (a_mid+1…aₘ, b_q+1…bₙ) where q = argmin; concatenate. Base: m ≤ 1 (one row — solve directly), or an empty string (all insertions / all deletions).

The cost: a geometric sum, and its exact form

The "at most twice the full table" slogan is the power-of-two case of the sum; with rounding the honest bound is n·∑ₖ ⌈m/2ᵏ⌉, and a throwaway run over 3 000 random pairs of lengths up to 14 never exceeded it, while 241 of those pairs — thin ones, with m much larger than n, where the +1s of the ceilings matter — did exceed the bare 2mn. The figure prints all three numbers for whichever pair it shows. Time is therefore Θ(mn) with a constant about twice the plain table's. Space is O(m + n): the two passes need two rows of length n + 1; the recursion has depth ⌈log₂ m⌉ and, if sub-strings are passed as index ranges rather than copies, each frame holds O(1) words; the alignment being built has O(m + n) columns. That is the trade the algorithm offers — double the arithmetic, memory down from mn to m + n — and it is decisive when the strings are long enough that the table does not fit: two sequences of length 10⁵ need a 10¹⁰-cell table but only a few hundred thousand words of rows.

What the argument needs, and where it generalises

Three properties made the split legitimate: the DP is a shortest path on a grid DAG whose every edge goes down, right or diagonally, so every path crosses every row; the recurrence at a cell reads only the previous row and the current one, so a forward pass in two rows and a backward pass on the reversed inputs are both available; and the objective is additive along the path, so prefix cost plus suffix cost is path cost. LCS has all three with max in place of min (and F[j] + R[j] maximised), as does global sequence alignment with a substitution matrix and linear gap penalties; affine gap penalties need the split to record whether the path enters row mid in a gap state, which is a bookkeeping extension rather than a new idea. What it does not extend to are DPs whose recurrence reaches arbitrarily far back — weighted interval scheduling's OPT(p(j)), the interval DPs of §19–§21 — because there is no "middle row" that every solution path must cross with local information on either side. §26 collects the general question of reconstruction after rolling and the cheaper trick (store every k-th row, recompute the gaps) that suffices when memory is merely tight rather than absent.

17 Dynamic time warping: aligning sequences that run at different speeds

Two recordings of the same word, the same gesture or the same heartbeat rarely line up sample for sample: one speaker is slower, one pause is longer. Dynamic time warping (DTW) compares them by the cheapest warping path — a monotone matching of the samples of one sequence to the samples of the other in which a sample may be matched to several consecutive samples — and finds it with the same grid DP as edit distance. The state is again a prefix pair, the recurrence a three-way minimum, the cost Θ(nm); what changes is what a move costs.

the template instantiated (x = x₁…xₙ, y = y₁…yₘ, a local cost such as cost(i, j) = |xᵢ − yⱼ|)STATE (i, j) — D(i, j) = the least total cost of a warping path that aligns x₁…xᵢ with y₁…yⱼ and ends by matching xᵢ with yⱼ RECURRENCE D(i, j) = cost(i, j) + min( D(i − 1, j), D(i, j − 1), D(i − 1, j − 1) ) BASE D(0, 0) = 0; D(i, 0) = D(0, j) = ∞ for i, j ≥ 1 (every path starts by matching x₁ with y₁) ORDER row-major; ANSWER D(n, m); the path by walking back along the winning minimum COST Θ(nm) time; Θ(nm) space with the path, Θ(min(n, m)) for the value alone (two rows, §26) what a warping path isa sequence of cells (1, 1) = p₁, p₂, …, p_L = (n, m) with each step one of (+1, 0), (0, +1), (+1, +1) BOUNDARY both sequences are used from start to end MONOTONE time never runs backwards in either sequence CONTINUOUS no sample is skipped — every xᵢ and every yⱼ is matched to at least one sample of the other max(n, m) ≤ L ≤ n + m − 1; the number of such paths is a Delannoy number — 48 639 for 8 × 8, far too many to enumerate at real lengths

Correctness, and the relation to edit distance

The argument is §15's last-column argument. An optimal warping path ending at (i, j) arrived from (i − 1, j), (i, j − 1) or (i − 1, j − 1); its prefix up to that cell is a warping path for the smaller prefix pair, and cut and paste makes it an optimal one; so D(i, j) is the local cost plus the best of the three. The grid DAG is literally the edit graph of §15, with a different price list. Edit distance charges each edge: a diagonal step costs 0 or a substitution, a horizontal or vertical step costs an insertion or a deletion, and a character met by such a step is left unmatched. DTW charges each cell the path visits: a horizontal step means xᵢ is matched to one more sample of y — the local time is stretched — and it pays cost(i, j) for that match, with no separate gap penalty. Nothing is ever deleted. That difference has a consequence worth knowing: DTW is not a metric. Repeating a sample costs nothing if it matches, so DTW(x, x′) = 0 for distinct sequences that differ only by repetitions, and the triangle inequality fails — for a = (2, 2, 0), b = (2, 1), c = (1), DTW(a, b) = DTW(b, c) = 1 but DTW(a, c) = 3. Indexing structures that rely on the triangle inequality therefore do not apply directly, and fast DTW search relies instead on cheap lower bounds (an envelope around the query, or the distance between first and last samples) that discard most candidates before the Θ(nm) table is filled. A run over 3 000 random pairs of lengths up to 6 checked the table against brute force over every warping path, with no disagreement.

The Sakoe–Chiba band

Unconstrained, the optimal path may match one sample to half of the other sequence — a "pathological warp" that makes two genuinely different signals look alike. The Sakoe–Chiba band forbids it by filling only the cells within radius r of the diagonal (rescaled when n ≠ m):

the bandfill (i, j) only if | (j − 1) − (i − 1)·(m − 1)/(n − 1) | ≤ r; every other cell is ∞ cells ≈ n·(2r + 1), so time Θ(n·r) instead of Θ(nm); DTWᵣ ≥ DTW (a smaller set of paths can only raise the minimum), with equality iff some optimal path stays inside r = 0 with n = m is the lock-step distance ∑ |xᵢ − yᵢ|; r ≥ max(n, m) is the full table

The band does two jobs at once: it is a modelling constraint (a warp of more than r samples is declared implausible) and a speed-up (the table shrinks from nm cells to about n(2r + 1)). It is the same restriction as the banded edit distance of §15, where only cells near the diagonal can lie on a cheap path. A parallelogram-shaped constraint that limits the path's slope instead of its distance from the diagonal is the common alternative; both are special cases of "fill only an admissible region of the DAG".

At the default — one bump, the second copy centred later — the lock-step distance is 48 and DTW is 7, from all 144 cells: the path runs along a row while one sequence waits for the other's bump, then returns to the diagonal. Narrow the band to r = 3 and the table shrinks to 72 cells but the distance rises to 10, because the optimal path needs a lag of more than three samples; at r = 1 (34 cells) it is 40, most of the way back to lock-step. The two-sampling-rates pair is the opposite case: its optimal path hugs the rescaled diagonal, so at r = 2 the band fills 46 of 216 cells and the distance is still 6. On different shapes DTW falls from the lock-step 50 to 20 and no further — stretching time can align one bump with either of two, but not with both.

Where it is used

DTW was the recogniser of the first practical isolated-word speech systems — store one template per word, and label an utterance by its nearest template under DTW — before statistical models over the same kind of trellis took over; the alignment view it introduced survives in the forced alignment of transcripts to audio and in the CTC and HMM decoders of Speech Processing, whose Viterbi recursion is §28's. Elsewhere it aligns gestures, handwriting strokes, sensor traces and music performances to scores, and one-nearest-neighbour classification under banded DTW remains a strong baseline for time-series classification. A smoothed variant that replaces the min by a soft minimum is differentiable, and is used as a training loss for sequence models whose outputs need not be time-aligned with their targets.

18 Longest increasing subsequence, two ways

The longest increasing subsequence (LIS) of a sequence a₁…aₙ is a longest subsequence — indices i₁ < i₂ < … < iₖ, not necessarily adjacent — whose values are strictly increasing. Two algorithms are standard and worth knowing together. The Θ(n²) dynamic program uses the state "the LIS that ends at position i" and the recurrence dp[i] = 1 + max{dp[j] : j < i, aⱼ < aᵢ}; the O(n log n) method keeps, for each length, the smallest value that can end an increasing subsequence of that length — the tails array — and places each element by binary search. Both are worked on [10, 9, 2, 5, 3, 7, 101, 18], whose LIS has length 4; the two return different LISs of that length, and the tails array, despite appearances, is not in general one of them.

method 1 — the template instantiatedSTATE i, 1 ≤ i ≤ n — dp[i] = the length of the longest increasing subsequence that ENDS at aᵢ (aᵢ is its last element) RECURRENCE dp[i] = 1 + max{ dp[j] : j < i and aⱼ < aᵢ }, with max ∅ = 0 (extend the best subsequence that can precede aᵢ, or start fresh) BASE dp[1] = 1 ORDER i = 1..n; ANSWER max over i of dp[i] — the LIS can end anywhere; reconstruct by prev[i] = the j that won COST ∑ᵢ (i − 1) = n(n − 1)/2 comparisons = Θ(n²) time, Θ(n) space correctness (cut and paste)let S be a longest increasing subsequence ending at aᵢ and let aⱼ be its second-to-last element (j < i, aⱼ < aᵢ). S minus aᵢ is an increasing subsequence ending at aⱼ; if a longer one ending at aⱼ existed, appending aᵢ (legal, since aⱼ < aᵢ) would beat S. So |S| = 1 + dp[j] for that j, and dp[i] = 1 + max over all admissible j. "ends at aᵢ" is the state that makes the argument work: "LIS of the prefix a₁…aᵢ" would not, because knowing its length says nothing about whether aᵢ₊₁ can extend it.

Why tails is not the LIS, and why reconstruction needs the links

On this instance the final tails array [2, 3, 7, 18] is itself an increasing subsequence of the input — a coincidence that misleads. Run the same routine on [2, 6, 3, 4, 1]: the trace is [2] → [2, 6] → [2, 3] → [2, 3, 4] → [1, 3, 4], and the final array [1, 3, 4] is not a subsequence of the input, because the 1 that sits in front arrived after the 3 and the 4. The LIS has length 3 ([2, 3, 4]), which is what the length of tails reports correctly; the contents of tails are the smallest-known endpoints for each length, drawn from different subsequences, and they lose the order in which they were placed. That is why tails[k] ← aᵢ alone cannot reconstruct anything: it overwrites the evidence. The fix is the pred link recorded at placement time — the index holding tails[k − 1] at that moment is a genuine predecessor of aᵢ in a length-(k + 1) subsequence, and those links are never overwritten. With them, reconstruction is a walk of L steps, and the whole method is O(n log n) time and Θ(n) space for the links. The picture behind the name "patience sorting" is a row of piles: each card goes on the leftmost pile whose top card is at least as large (or starts a new pile at the right), the tops of the piles are the tails array, and the number of piles is the LIS length — with the same caveat that the tops are not a subsequence.

The reduction to LCS, and the variants

When the values are distinct, an increasing subsequence of a is exactly a common subsequence of a and sorted(a) — any common subsequence appears in sorted order, hence increasing; any increasing subsequence is a subsequence of the sorted list — so LIS(a) = LCS(a, sorted(a)), a Θ(n²) algorithm by §14 that the figure runs as a third check (64 cells on the worked sequence; it returns 4). With duplicates the reduction computes the longest non-decreasing subsequence instead — on [3, 3, 3] it answers 3 where the strict LIS is 1 — and the repair is to sort and remove duplicates before taking the LCS. The same distinction governs the binary search in method 2: a lower-bound search (first tail ≥ aᵢ) gives the strictly increasing version, an upper-bound search (first tail > aᵢ) the non-decreasing one, and using the wrong boundary is the commonest bug in an otherwise correct implementation — Sorting & Searching, §29 is the reference for the two searches. Longest decreasing is LIS on the negated values. The Θ(n²) method is the one to generalise — to weighted versions (maximise the sum of the chosen values rather than their count), to two-dimensional dominance (box stacking, envelope nesting: sort by one coordinate, LIS on the other), to "longest chain" problems — because its state is explicit; the tails method is the one to use when only an increasing sequence of scalars is wanted and n is large.
