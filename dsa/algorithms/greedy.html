Greedy Algorithms

A greedy algorithm builds a solution one irrevocable choice at a time, each choice the best-looking one available at that moment, and never looks back. That is the fastest possible shape an optimisation algorithm can have — usually one sort and one scan — and it is also the shape most likely to be confidently wrong. This page is about the difference. It states the two properties (the greedy-choice property and optimal substructure) that make a greedy algorithm correct and the three proof templates (greedy stays ahead, the exchange argument, and the matroid theorem) that establish them; it traces the classical greedy algorithms — activity selection, interval partitioning, minimum lateness, coin change, fractional knapsack, Huffman codes, the weighted-matroid greedy, the cut property behind every minimum-spanning-tree algorithm — with every step measured on the real routine and every answer checked against brute force; and it spends as much care on the problems where greedy fails (0/1 knapsack, non-canonical coins, set cover, the travelling salesman) as on the ones where it succeeds, because knowing which side of that line a problem is on is the whole skill.

01 What a greedy algorithm is

A greedy algorithm solves an optimisation problem by a sequence of choices, each made by a fixed local rule that looks only at the current state, each irrevocable, and each followed by a strictly smaller instance of the same problem. Three words in that sentence carry the definition. Local: the rule ranks the options available now — the interval that finishes first, the largest coin that fits, the two lightest symbols, the cheapest edge leaving the tree — without solving any subproblem to find out what the choice leads to. Irrevocable: a choice is never undone; there is no backtracking, no table of alternatives, no second pass. Smaller instance: after the choice, exactly one subproblem remains, and it is the same kind of problem on fewer elements, so the algorithm is a loop, not a tree of recursive calls.

Why the shape is so attractive, and why it is dangerous

The template's cost is the cost of the ordering plus one feasibility test per candidate. When the test is O(1) — "does this interval start after the last one I kept finished?" — the whole algorithm is Θ(n log n) for the sort and Θ(n) for the scan, and if the input arrives already ordered it is linear. When the test needs a structure — the union-find behind Kruskal's algorithm, the priority queue behind Huffman's — the algorithm is still Θ(n log n) for the sort plus a near-linear O(m α(n)) or O(n log n) for the tests, tiny next to the exponential space of solutions it is choosing among. That is the attraction: an n log n algorithm for a problem whose solution space has 2ⁿ or n! members. The danger is the same fact viewed from the other side. The algorithm inspects one path through that exponential space and commits to it; if the local rule ever picks an element that no optimal solution contains, the answer is wrong and nothing downstream can repair it. A greedy algorithm without a proof is a heuristic, and §26 shows a heuristic (nearest-neighbour tours) whose answer can be made as bad as you like.

What makes a greedy algorithm correct: two properties, three proofs

A greedy algorithm is correct when the problem has two properties (§02). The greedy-choice property: the locally best choice is contained in some globally optimal solution — so committing to it loses nothing. Optimal substructure: after committing, an optimal solution to the remaining subproblem, glued to the choice, is an optimal solution to the whole. Together they give a one-line induction: the first choice is safe, the rest is a smaller instance of the same problem, so by induction the whole answer is optimal. The work is always in the first property, and it is proved in one of three ways (§03). Greedy stays ahead: define a measure of progress and show by induction that after every step the greedy partial solution is at least as far along as any other solution's corresponding prefix. The exchange argument: take any optimal solution, find where it first differs from the greedy one, swap the greedy choice in, and show the objective does not get worse — repeat until the optimal solution has been transformed into the greedy one without ever losing value. The matroid theorem: if the feasible sets form a matroid, the greedy algorithm is optimal for every nonnegative weight function, and no problem-specific argument is needed at all.

02 The two properties, and how greedy differs from dynamic programming

Greedy algorithms and dynamic programming both rest on optimal substructure. They part company on one question: can the choice be made before the subproblems are solved? If a locally-ranked choice is always safe, the problem has the greedy-choice property and one subproblem remains; if the right choice can only be known by comparing the solutions of several subproblems, the problem needs dynamic programming and the subproblems overlap.

The same problem seen both ways

Activity selection (§04) is the clean demonstration because its dynamic-programming formulation is natural and its greedy one is a strict simplification of it. In the DP view, the subproblem S(i, j) is "the activities that start after aᵢ finishes and finish before aⱼ starts", and its optimal size satisfies c[i, j] = max over aₖ in S(i, j) of c[i, k] + c[k, j] + 1: every activity is tried as the middle of a solution, and each trial spawns two subproblems. That is Θ(n²) subproblems and Θ(n³) work. The greedy observation is that one of the candidates — the one that finishes first — is always safe to choose, and that choosing it leaves nothing on its left side: the left subproblem is empty, the recurrence collapses to c[k] = 1 + c[next compatible], and the table is not needed because there is only one path through it. The two views are not rivals; the greedy algorithm is what the DP becomes once the greedy-choice property is proved. That is the general pattern: beneath almost every greedy algorithm there is a more expensive dynamic program that would also work, and the greedy algorithm is the reward for proving the extra property.

The canonical pair: fractional versus 0/1 knapsack

The two knapsack problems (§10–§11) are the textbook boundary because they share everything — the same items, the same capacity, the same objective, the same optimal substructure — and differ only in whether an item can be split. Both have optimal substructure: remove any item (or any fraction of one) from an optimal load and what remains is an optimal load for the reduced capacity. Only the fractional version has the greedy-choice property. Taking as much as possible of the highest value-per-unit-weight item is always safe when items can be split, because any load that uses less of it could swap in more at no loss (§10 proves this by exchange). The moment items become indivisible, the best-density item can leave a gap that no other item fills efficiently, and the choice that looked best locally is contained in no optimal solution: on the four-item instance of §11 the greedy load is worth 160 and the optimum 220, and the greedy load does not contain the optimal one. The 0/1 problem keeps optimal substructure — that is exactly why dynamic programming solves it — and loses only the one property greedy needs.

03 The three proof templates: greedy stays ahead, exchange, matroid

Every greedy correctness proof on this page is one of three templates. They prove the same thing — the greedy-choice property, and hence optimality — from different angles, and choosing the right one is most of the work. Greedy stays ahead compares greedy's partial solution to an arbitrary solution's prefix, step by step. The exchange argument takes an arbitrary optimal solution and edits it toward the greedy one without loss. The matroid argument checks two axioms of the feasible sets and then invokes one theorem that covers every weight function at once.

template 1 — greedy stays aheadlet g₁, g₂, …, gₖ be greedy's choices in order, and o₁, o₂, …, oₘ any feasible solution's elements in the same order choose a MEASURE μ that captures "how far along" a partial solution is claim (induction on r): μ(g₁..gᵣ) is at least as good as μ(o₁..oᵣ) for every r ≤ min(k, m) base: g₁ is the best single choice by the rule, so μ(g₁) ≥ μ(o₁) step: oᵣ₊₁ was feasible after o₁..oᵣ; because greedy was ahead, it is feasible after g₁..gᵣ too; greedy chose gᵣ₊₁ as the BEST such element, so μ(g₁..gᵣ₊₁) ≥ μ(o₁..oᵣ₊₁) conclude: if m > k then oₖ₊₁ would have been feasible for greedy after gₖ — contradiction with greedy stopping. Which template fits which problem

Greedy stays ahead is the natural template when the objective is a count — the number of activities scheduled, the number of fuel stops, the number of jumps — and the greedy rule is "take the option that leaves the most room". The measure is the room left: the finish time of the last chosen interval (§06), the position reached after r stops (§21). The induction shows greedy is never behind, and the contradiction at the end converts "never behind" into "at least as many". Its subtlety is that the measure is not the objective: the proof establishes an inequality about finish times and only then deduces the inequality about counts. A proof that compares counts directly at each step usually does not go through.

The exchange argument is the template for sums — total weight, total lateness, total cost — and for problems whose solutions are orderings. Its heart is one inequality: replacing the optimal solution's element by greedy's does not decrease the value. For orderings that inequality is about swapping two adjacent elements that are in the wrong order relative to the greedy key (an inversion), and the whole proof is "every inversion can be removed at no cost, and a solution with no inversions is the greedy one" (§08). For subsets it is "swap the first differing element" (§10 for fractional knapsack, §14 for Huffman's lemma, §20 for the cut property). The exchange argument is the most general of the three and the one to reach for first.

The matroid theorem is the template when the feasible sets have enough structure that no problem-specific inequality is needed. It applies to forests in a graph (so to minimum spanning trees), to linearly independent sets of vectors, to "at most k elements", to "at most one element from each block of a partition", and to sets of unit-time tasks that can all meet their deadlines (§19). It does not apply to activity selection (compatible sets of intervals fail the exchange axiom, §17) or to Huffman codes, which is why those need the other two templates. When it applies, it gives more than correctness: it tells you the greedy algorithm is optimal for every weight function, and the converse (§18) says that if greedy is optimal for every weight function, the structure must be a matroid.

The obligation the templates share: induction, and the base case

All three are inductions and all three need the base case checked explicitly, because that is where the edge cases hide. Greedy stays ahead on an empty instance chooses nothing and the claim is vacuous; on a single interval it chooses it, and the measure comparison is trivial. The exchange argument needs an optimal solution to exist — guaranteed for finite instances — and needs the "first difference" to exist, which it does whenever greedy and the optimum differ. The matroid axioms include the empty set being independent, which is what makes the first greedy step well-defined. The formal discipline of writing an induction so that it actually proves the claim (statement, base, step, conclusion) is the subject of Recursion, Divide & Conquer, §03; this page assumes it and concentrates on the problem-specific inequality that each template turns on.

A proof template is not a proof. Each template has one line that carries the problem: the measure and why greedy's next element is feasible (template 1); the value inequality after the swap (template 2); the exchange axiom (template 3). §05 shows three plausible greedy rules for activity selection for which that line is false — each has a small instance where the swap does lose value — and they are wrong even though they look exactly like the correct rule. The template tells you what to prove; it never tells you it is true.

05 Four plausible rules, three of them wrong — with counterexamples and measured failure rates

"Earliest finish time" is not the only rule that sounds right. Earliest start ("start using the resource as soon as possible"), shortest duration ("small activities leave more room"), and fewest conflicts ("take the activity that blocks the least") are each locally reasonable, each correct on many instances — all three happen to find a maximum set on the eleven-activity instance above except earliest start — and each provably wrong. Why each wrong rule is wrong, in the language of §03

Each failure is a failure of the exchange step. The theorem's exchange worked because the earliest-finishing activity aₘ can replace the earliest-finishing member aⱼ of any optimum: everything else in the optimum starts after fⱼ ≥ fₘ. Try the same swap for earliest start: the earliest-starting activity may finish late, and the other members of the optimum may start before it finishes, so the swapped set is not compatible — the inequality the template needs is simply false, and the first counterexample above is exactly the instance where it fails. Shortest duration: the shortest activity can sit astride the boundary between two optimum activities, so swapping it in for one of them leaves it overlapping the other. Fewest conflicts: the count is a global property that says nothing about which activities are blocked; the middle activity blocks two, but they are two members of the only optimum. The pattern is worth internalising: a wrong greedy rule is not "usually wrong" — on random instances all three are right most of the time, as the figure below measures — it is wrong on a specific structure, and the structure can be found by asking where the exchange inequality breaks.

The same theorem by greedy-stays-ahead

The exchange proof of §04 is the shortest, but activity selection is also the canonical example of template 1, and seeing both on one problem shows what each is really proving. Let greedy's choices in order be g₁, …, gₖ and let o₁, …, oₘ be any compatible set, also ordered by finish time. The measure is the finish time of the r-th chosen activity.

CLAIM. Then oₖ₊₁ exists, and s(oₖ₊₁) ≥ f(oₖ) ≥ f(gₖ): it was available after greedy's last choice. but greedy stopped, meaning nothing was available — contradiction. Notice what the induction proves: an inequality between finish times, not between counts. The count inequality comes only at the end, from the contradiction. A proof that tried to show "greedy has chosen at least as many activities as any other set after r steps" has nothing to induct on, because both sides are r; the measure has to be the thing greedy is actually optimising locally. This is the general lesson of template 1 and the reason its proofs sometimes feel indirect: greedy stays ahead on a measure, and the objective follows from the measure.

What the problem becomes when the objective changes

Change the objective from "most activities" to "most total weight" — each activity has a value and the aim is a maximum-weight compatible set — and every greedy rule fails, including earliest finish: a single long heavy activity can be worth more than the many short ones it blocks, and no local rule sees that. The problem is weighted interval scheduling, and it is dynamic programming: sort by finish time, define OPT(j) as the best value using only the first j activities, and take the better of skipping aⱼ or keeping it plus OPT(p(j)) where p(j) is the last activity compatible with aⱼ, found by binary search. That recurrence is the unweighted DP of §04 with the greedy simplification removed; the boundary between the two problems is exactly the greedy-choice property, and §17 explains in matroid terms why it is lost: compatible interval sets are not a matroid, so no weight-independent greedy exists for them.

The one-line version. Sort by finish time, keep every activity that starts at or after the last kept finish: Θ(n log n), proved by a one-element exchange or by stays-ahead on finish times, correct for the unweighted count and for nothing else.

07 Interval partitioning: schedule everything, using the fewest resources — the depth lower bound

Turn activity selection around: every interval must be scheduled, and the question is how many resources (rooms, machines, registers) are needed so that no two overlapping intervals share one. The greedy answer processes intervals in order of start time and puts each into any resource that is free, opening a new one only when none is. It is optimal, and the proof is not an exchange but a lower bound that the greedy algorithm meets: no schedule can use fewer resources than the largest number of intervals alive at one instant, and greedy never opens a resource unless that many are alive.

Why start order, and what goes wrong with finish order

The proof's key step is "each existing resource holds an interval that started at or before s(I)" — that is what makes all d intervals share the point s(I), and it is true only because intervals are processed in start order. This is the same lesson as §05 in a different costume: the greedy key is not a matter of taste, it is the thing the proof turns on.

What the theorem does not say — read the objective

  • It minimises the maximum lateness, not the total. Two words first: scheduling calls the signed quantity fⱼ − dⱼ the lateness and its positive part max(0, fⱼ − dⱼ) the tardiness; this page's Lⱼ is the tardiness, and earliest-deadline minimises the maximum of either. Total signed lateness is trivial — ∑(fⱼ − dⱼ) = ∑fⱼ − ∑dⱼ, minimised by shortest-processing-time-first in O(n log n). Total tardiness is the hard one, and for it earliest-deadline is not optimal: with jobs (t, d) = (1, 9), (3, 5), (5, 3), (3, 2) the deadline order D, C, B, A has total tardiness 1 + 5 + 6 + 3 = 15 and the order D, B, A, C has 1 + 1 + 0 + 9 = 11, the best of all 24 orders (checked by enumeration in the load-time audit). Minimising total tardiness on one machine is NP-hard in the ordinary sense (a pseudo-polynomial DP exists) and the weighted version is strongly NP-hard; the greedy rule's proof works for the maximum because a single swap can only change two latenesses and the new one is dominated by an old one — a max survives that, a sum does not.
  • The rule ignores processing times, which feels wrong and is right: the exchange never mentions tᵢ. Shortest-processing-time-first minimises the sum of completion times, a different objective with its own exchange proof.
  • All deadlines equal: every order is inversion-free, every order is greedy, and all have the same maximum lateness (max(0, the makespan minus the common deadline)). Ties in general are safe for the same reason — the fact 2 argument.
  • Release times (a job cannot start before rⱼ) break the theorem: with release times the problem is NP-hard, and the exchange fails because swapping can create idle time.

Why greedy works on {1, 5, 10, 25} — a bounding argument, then an exchange

The proof for a specific system bounds what an optimal solution can contain, then concludes it must be the greedy one. In any optimal solution for {1, 5, 10, 25}: at most four 1s (five 1s would be exchanged for a 5, saving four coins); at most one 5 (two 5s → one 10); and if there is a 5 then at most one 10 (a 5 and two 10s → one 25), while with no 5 at most two 10s (three 10s → a 25 and a 5). So the coins smaller than 25 total at most 4 + 5 + 10 = 19 with a 5 present, or 4 + 20 = 24 without — in every case less than 25. An optimal solution therefore uses at least floor(x / 25) quarters (otherwise the small coins would have to cover 25 or more), and cannot use more; so it uses exactly the greedy number, and the same bounds applied to the remainder x mod 25 force exactly floor((x mod 25)/10) dimes, then the 5, then the 1s. The optimal solution is the greedy one. Run the same argument on {1, 3, 4}: an optimal solution has at most two 1s, but it may have at most three 3s (four 3s → three 4s saves a coin), so the coins below 4 can total 3 · 3 + 2 · 1 = 11 ≥ 4 — the "small coins total less than the largest coin" bound that the {1, 5, 10, 25} argument rested on is exactly what fails, so the "at least floor(x/4) 4s" step has nothing to rest on, and 6 = 3 + 3 is the first amount where it bites.

Deciding canonicity: what is known

  • There is a polynomial-time test. Whether a system of m denominations is canonical can be decided in O(m³) time, by an algorithm that examines a specific polynomial-size family of candidate amounts; the test's existence is the fact to remember, its details are outside this page.
  • Where the smallest counterexample lives. If a system is not canonical, the smallest amount on which greedy fails lies strictly between c₃ + 1 and cₘ₋₁ + cₘ. For {1, 3, 4} that is 5 < x < 7, i.e. x = 6; for {1, 5, 10, 20, 25} it is 11 < x < 45, and the first failure is at 40. This also gives a brute-force test: compare greedy with the DP on every amount below cₘ₋₁ + cₘ.
  • Small cases have closed forms. Every two-coin system {1, c} is canonical. For three coins {1, a, b}, write b = q·a + r with 0 ≤ r < a: the system is canonical if and only if r = 0 or r ≥ a − q, and when it is not, the amount (q + 1)·a is a counterexample — greedy pays one b plus a − r ones, 1 + a − r coins, against q + 1 coins of a. For {1, 3, 4}: q = 1, r = 1, and 1 < 3 − 1, so it is non-canonical at 6. (The load-time audit checks this characterisation against greedy-versus-DP on every {1, a, b} with a < b ≤ 80.)
  • Real currencies. The coin systems in wide use — 1, 2, 5, 10, 20, 50 in cents and their multiples; 1, 5, 10, 25 — are canonical, which is why till-greedy works; it is a design choice, not a law. Systems with a 20 and a 25 are the classic non-canonical shape.
  • Without a 1-coin the problem may have no solution at all: {3, 5} cannot make 7, and greedy on 6 takes a 5 and is then stranded with 1 (the optimum is 3 + 3; it must be allowed to backtrack, or the DP used, to find it); the general question of which amounts are representable is a different problem.

10 Fractional knapsack: greedy by value density, proved by exchange

n items with weights wᵢ > 0 and values vᵢ ≥ 0, a capacity W; take any fraction xᵢ ∈ [0, 1] of each item so that ∑ xᵢ wᵢ ≤ W and ∑ xᵢ vᵢ is maximum. The greedy rule sorts by value density vᵢ / wᵢ, takes whole items in that order while they fit, and then takes the fraction of the next item that fills the remaining capacity exactly. What the proof needs and what it does not

The exchange moves value from a low-density item to a high-density one and the inequality vᵢ/wᵢ ≥ vⱼ/wⱼ is the whole argument — so the proof needs items to be divisible (so that δ can be any amount) and it needs densities to be well defined (weights positive). It does not need integer weights or values, it does not need the items to fit, and it does not care about ties: two items of equal density can be taken in either order and the value is the same. Zero-value items are simply never reached; negative values (a penalty for carrying an item) should be dropped before sorting, since taking any fraction of them can only hurt. The cost is the sort, Θ(n log n), plus a linear scan; a weighted-median selection (the linear-time selection of Recursion, Divide & Conquer, §28) finds the break item k in Θ(n) without sorting at all, which is worth knowing and rarely worth doing.

The fractional problem is also the linear-programming relaxation of the 0/1 problem — relax xᵢ ∈ {0, 1} to xᵢ ∈ [0, 1] — and its optimum is therefore an upper bound on the 0/1 optimum: no integer selection can beat 240 on the instance above. That bound is what makes the greedy 0/1 approximation of §11 provable, and it is the bound a branch-and-bound search for the exact 0/1 answer uses to prune (Recursion, Divide & Conquer, §26). One greedy algorithm, three roles: exact solution of the fractional problem, upper bound for the integer one, pruning rule in the search for it.

Why the fix works and why it is tight

The unfixed rule's failure is always the same shape: the first item that does not fit is worth a lot, and the greedy prefix's value is small compared with it. The fractional bound says the greedy prefix plus that one item is worth at least the optimum; so whichever of the two is larger is worth at least half. The single most valuable item is at least as good as the item that did not fit, so it can stand in for it. Factor 2 is tight for the fixed rule. Take three items (w, v) = (1, 2), (W/2, W/2), (W/2, W/2) with capacity W: greedy by density takes the first (density 2), then one of the halves, and the other no longer fits (1 + W/2 + W/2 > W), so G = 2 + W/2 and M = W/2, while the optimum takes the two halves for W. Where the exact answer lives

The 0/1 problem keeps optimal substructure — remove any item from an optimal load and the rest is optimal for the reduced capacity — so it has a correct recurrence, OPT(i, c) = max(OPT(i − 1, c), vᵢ + OPT(i − 1, c − wᵢ)), and a table of (n + 1)(W + 1) cells solves it exactly in Θ(nW) time. That is pseudo-polynomial (polynomial in the value of W, exponential in its bit length), which is consistent with the problem being NP-hard, and it is the subject of Dynamic Programming. The point for this page is the contrast: the recurrence compares two subproblems at every item, and the greedy algorithm is the attempt to skip the comparison. When items are divisible the comparison always comes out the same way (density decides) and skipping it is safe; when they are not, it can come out either way, and skipping it is the 160-versus-220 error above.

12 Prefix codes: variable-length codewords, the binary trie, and the cost of a tree

A binary character code assigns each symbol of an alphabet a string of bits, its codeword; a message is coded by concatenating codewords. A fixed-length code uses ceil(log₂ |C|) bits for every symbol. A variable-length code can do better by giving frequent symbols short codewords — provided the receiver can still tell where one codeword ends and the next begins. A prefix code (better: prefix-free) is one in which no codeword is a prefix of another; that single property makes decoding unambiguous and left-to-right, and it is the class within which Huffman's algorithm is optimal.

Why prefix codes lose nothing

Restricting to prefix codes looks like a sacrifice — perhaps some cleverer uniquely-decodable code, one that needs lookahead to parse, could be shorter. It cannot. Every uniquely-decodable code with codeword lengths ℓ₁, …, ℓₙ satisfies the Kraft inequality ∑ 2^(−ℓᵢ) ≤ 1, and conversely for any lengths satisfying it there is a prefix code with exactly those lengths — build the trie by assigning the shortest codewords first, and the inequality guarantees room. So the set of achievable length profiles is the same for both classes, and since the cost depends only on the lengths, the best prefix code is as short as the best uniquely-decodable code. This is the "no loss of generality" that lets §13 search only over trees. (The inequality for prefix codes is a one-line argument: each codeword of length ℓ "owns" a fraction 2^(−ℓ) of the infinite binary strings — those beginning with it — and prefix-freeness makes those fractions disjoint.)

Where the trie lives

The code tree is a binary trie — the structure of Balanced Trees, §23, with the bit alphabet {0, 1} and the symbols stored only at leaves. Encoding is a table lookup (symbol → codeword string, built once by a walk of the tree); decoding is a trie walk, one node per bit. In practice the tree is not stored at all: a canonical Huffman code (§16) is determined by the codeword lengths alone, so a compressor transmits the lengths and the receiver rebuilds the same trie. The tree's role is in the construction and the proof, where the fact that merging two subtrees under a new root adds 1 to every depth below it is what makes the cost recurrence (§14) work.

13 Huffman's algorithm: merge the two lightest, with a priority queue

Start with each symbol as a one-node tree weighted by its frequency; repeatedly remove the two lightest trees, join them under a new root whose weight is their sum, and put the new tree back; after |C| − 1 merges one tree remains, and it is an optimal prefix code. The greedy choice is "the two lightest", the data structure that finds them is a min-priority queue, and the cost is |C| − 1 rounds of two extractMins and one insert, after the |C| inserts that fill the queue.

Reading the trace

Three things in the trace are the algorithm. First, the weights only ever go up: each merged node weighs at least as much as either child, so the two lightest trees at any moment are found at the front of the queue and a merged node never needs to be reconsidered. Second, the sum of the merge weights is the cost of the tree: a symbol of frequency f at depth d takes part in exactly d merges (one per ancestor), contributing f to each, so ∑ merges = ∑ f · d = B(T). The proof is the two-property pattern of §02 made exact. Lemma 1 (greedy choice): there is an optimal tree in which the two least frequent symbols are sibling leaves at maximum depth — so merging them first is safe. Lemma 2 (optimal substructure): an optimal tree for the alphabet with those two symbols replaced by their merged node, expanded back, is optimal for the original alphabet — so what remains after the merge is the same problem, smaller. What the proof says about the "cost of a merge"

Lemma 2's identity B(T) = B(T') + freq(x) + freq(y) is the reason Huffman's algorithm can be described as "greedy on merge cost". Every full tree on C can be built by a sequence of |C| − 1 merges, and its cost is the sum of the merge weights, whatever order the merges are done in (the trace in §13 shows the sum coming to 224). The algorithm chooses, at each step, the cheapest possible merge. That is exactly the shape of §01's template, and it is exactly the shape that is usually wrong — minimising each step's cost does not in general minimise the sum — so it is worth seeing where the proof does the real work: Lemma 1 says the cheapest merge is compatible with some optimum, not merely cheap, and that is what the two-swap exchange establishes. The lemma is the greedy-choice property; the identity is optimal substructure; the theorem is the induction that needs both.

The proof also shows what Huffman's algorithm does not claim. It is optimal among prefix codes that assign one codeword per symbol for a known, fixed frequency table. It says nothing about codes over blocks of symbols (which can approach the entropy more closely, §15), about adaptive codes that change as the message is read, about arithmetic coding (which is not a symbol-by-symbol prefix code and can beat Huffman's per-symbol overhead), or about what happens when the frequencies used to build the code differ from the message's actual frequencies. Each of those is a different problem, and "Huffman is optimal" is a true sentence only with its hypotheses attached.

Ties, and what is unique

  • The cost B(T) is unique; the tree is not. Whenever two candidate merges tie in weight, either choice leads to an optimal tree, and the trees can have different shapes with different individual codeword lengths. Frequencies 1, 1, 2, 2: merging the 1s gives node 2; the queue is then {2, 2, 2} and the next merge may pair the new node with a leaf (depths 3, 3, 2, 1, cost 3 + 3 + 4 + 2 = 12) or the two leaves (depths 2, 2, 2, 2, cost 2 + 2 + 4 + 4 = 12). Same cost, different lengths, different trees. The multiset of lengths is not unique either — {3, 3, 2, 1} versus {2, 2, 2, 2} — only the average is.
  • Equal frequencies give a fixed-length code when |C| is a power of two and an almost-fixed one otherwise: four equal symbols get lengths 2, 2, 2, 2 (L = 2 = H); five equal symbols get 2, 2, 2, 3, 3 (L = 2.4, H = log₂ 5 = 2.32).
  • One symbol: the algorithm returns a single leaf, depth 0 — codeword length 0, L = 0 = H. That is the mathematically correct answer (a message over one symbol carries no information) and a practical nuisance: a decoder needs to know the message length. Implementations assign the lone symbol a 1-bit codeword, which is not optimal but is decodable; the figure shows the length-0 answer and says so.
  • Two symbols: always lengths 1, 1, L = 1 regardless of the probabilities — the source of the H + 1 slack: a symbol with p = 0.99 "deserves" log₂(1/0.99) = 0.0145 bits and gets a whole one. Coding pairs of symbols (an alphabet of four, with probabilities .9801, .0099, .0099, .0001) brings the per-symbol average down toward H; coding blocks of k independent symbols gives H ≤ Lₖ / k < H + 1/k, which is how block codes approach the entropy.

16 Huffman codes in practice: canonical codes, transmitting the table, and what real compressors actually do

A textbook Huffman coder is a component, not a compressor. Real systems answer three questions the algorithm leaves open — how does the decoder learn the code?, where do the frequencies come from?, and what redundancy is the code blind to? — and the answers explain both why Huffman coding is everywhere and why it is almost never the whole story.

Canonical Huffman codes: send the lengths, not the tree

Since the cost depends only on the length assigned to each symbol — B = ∑ freq(c) · ℓ(c) (§15) — every tree realising the same per-symbol lengths costs the same, and a compressor can throw the tree away and keep only the lengths. A canonical code assigns codewords from the lengths by a fixed rule: sort symbols by (length, symbol order); give the first symbol the all-zeros codeword of its length; each subsequent codeword is the previous one plus 1, shifted left when the length increases. Decoder and encoder run the same rule on the same lengths and agree on every codeword, so the transmitted "table" is one small integer per symbol, and decoding can use length-indexed arithmetic instead of a trie walk. This is the form in which Huffman codes appear in the DEFLATE format (the code lengths are themselves compressed by a second, small Huffman code) and in JPEG's baseline entropy coder (a table of counts per length plus the symbol order).

Static, two-pass, and adaptive

The frequencies must come from somewhere. A static code uses a fixed table agreed in advance (an English-text table, say) — no header, but suboptimal for anything else. A two-pass (semi-static) coder scans the input to count, builds the code, transmits the lengths, then encodes: optimal for the input's own distribution, at the cost of the header and a second pass. An adaptive coder starts from a flat code and updates the tree as symbols arrive, encoder and decoder making identical updates, so no table is sent and the code tracks a drifting distribution; the price is per-symbol tree maintenance. Which one a format uses is a design choice about latency, header cost and the stationarity of the data, not about the algorithm.

What Huffman coding is blind to, and what real formats pair it with

  • It sees single symbols only. A file of ABABAB… has two equally frequent symbols and Huffman gives it 1 bit per symbol — no compression at all — although it is perfectly predictable. Repetition and context are captured by a modelling stage: run-length encoding for long runs (a run of k identical bytes stored as the byte and the count), dictionary matching (LZ77-style back-references "copy 12 bytes from 340 bytes back"), or a context model. Huffman coding then codes the output of that stage — literals, match lengths, distances — where it is doing what it is good at: turning a skewed symbol distribution into near-entropy bits.
  • DEFLATE (the format inside zip, gzip and PNG) is exactly that pairing: LZ77 matching followed by Huffman coding of literals/lengths and of distances, with canonical codes described by transmitted lengths. Baseline JPEG Huffman-codes the quantised transform coefficients (a Huffman symbol per (zero-run, magnitude-category) pair, with the magnitude bits appended raw); the standard also defines an arithmetic-coding option that is rarely used for compatibility reasons.
  • Its per-symbol overhead is real — the < 1 bit of §15 — and for very skewed distributions it dominates. Arithmetic coding and its table-driven descendants (asymmetric numeral systems, ANS) code a whole message as one number and reach the entropy to within a constant per message rather than per symbol. Modern general-purpose compressors mix the two: one widely used format uses a finite-state ANS coder for its main streams and a Huffman coder for literals, choosing each for speed; modern image and video codecs generally use arithmetic or ANS coders. The general statement that is safe: Huffman coding remains the fast, simple entropy coder in many formats, usually behind a modelling stage, and is increasingly replaced by ANS/arithmetic coding where the last few percent of size matter more than the last few percent of speed.
  • Any lossless compressor makes some inputs longer. A pigeonhole count: there are fewer short strings than long ones, so a scheme that shortens some inputs must lengthen others. Huffman coding on data whose symbols are already uniform (encrypted, already-compressed) gains nothing and pays the header.
The one-line version. Huffman's algorithm is the optimal symbol-by-symbol prefix code for a known distribution, built greedily in O(|C| log |C|) with a priority queue; in practice it is transmitted as canonical lengths, placed after a modelling stage that captures repetition, and competes with arithmetic/ANS coders that avoid its up-to-one-bit-per-symbol overhead.

17 Matroids: the definition, the exchange axiom, and the examples that are (and are not) matroids

A matroid is the abstract structure that makes greedy work for every weight function. It is a finite ground set S together with a family I of "independent" subsets satisfying two axioms: hereditary — a subset of an independent set is independent — and exchange — a smaller independent set can always be grown by an element of a larger one. The name comes from matrices (columns that are linearly independent), the motivating example is forests in a graph, and the payoff is §18's theorem: on a matroid, sort by weight and take what fits.

What is not a matroid — and why that matters

Compatible sets of intervals (activity selection) are hereditary but fail exchange: A = {[0, 10)} and B = {[0, 4), [5, 9)} are both compatible, |A| < |B|, and neither member of B can be added to A — both overlap [0, 10). So interval compatibility is not a matroid, and the matroid theorem does not apply to activity selection; earliest-finish needs its own proof (§04), and weighted activity selection has no greedy algorithm at all (§06, §18). Matchings in a graph are hereditary but not a matroid (a path on four vertices: the middle edge alone is a maximal matching of size 1, the two outer edges form one of size 2 — bases of different sizes), which is why maximum matching needs augmenting paths, not greed. The lesson is the one §03 gave: the matroid template is powerful exactly where it applies and silent everywhere else, and checking (M2) on a small example is the fastest way to find out which.

Three consequences worth stating exactly

  • Maximum weight versus maximum-weight basis. With all weights strictly positive, an optimal set is automatically a basis (adding any extension helps), so the theorem finds the maximum-weight basis. With zero weights present, greedy as written still adds every weight-0 element that keeps independence, so it returns a basis; a variant that stops at the first zero weight returns a maximum-weight independent set that may not be a basis — the same weight either way. With negative weights present, greedy should skip them: the theorem as stated needs w ≥ 0, and negative-weight elements can never help a maximum-weight set. (For a maximum-weight basis with negative weights allowed, add a constant to every weight — bases all have the same size, so the order of bases is unchanged.)
  • Minimum weight. A minimum-weight basis is found by negating: sort by increasing weight and add what stays independent. Equivalently use w'(x) = w₀ − w(x) with w₀ larger than every weight, which is positive, and maximise. That is Kruskal's algorithm on the graphic matroid: sort edges by increasing weight, add each edge that does not close a cycle, and the result is a minimum spanning tree — the matroid theorem is one of its two standard proofs, the cut property (§20) is the other.
  • The converse: greedy-for-all-weights characterises matroids. Let (S, I) be hereditary (M1). If the greedy algorithm returns a maximum-weight member of I for every nonnegative weight function, then (S, I) satisfies (M2) and is a matroid. Sketch: suppose (M2) fails for some A, B with |A| < |B|; give the elements of A weight 1 + ε, those of B − A weight 1, everything else 0. Greedy takes all of A first (heaviest, independent), then can add nothing from B − A (that is what failing (M2) means), so its value is |A|(1 + ε); but B has value at least |B| ≥ |A| + 1, which is larger for small ε. So greedy fails for that weight function. This is why weighted activity selection has no greedy algorithm: interval compatibility is not a matroid (§17), so some weight function defeats the weight-sorted greedy — and the weight function in the sketch is a recipe for building it.

Beyond matroids, briefly

The matroid theorem covers greedy algorithms whose feasible sets are closed under subsets. Some correct greedy algorithms live on structures that are not hereditary — a partial solution must be built up in a particular order, and a subset of a feasible set need not be feasible. Prim's algorithm, whose partial solutions must stay connected trees grown from the root, is the standard example, and the structure that captures it is the greedoid: the hereditary axiom is weakened to accessibility (every nonempty feasible set has an element whose removal leaves a feasible set) and the exchange axiom is kept. Greedy is optimal on a general greedoid only for a narrower class of objectives than on a matroid (it is optimal for every linear weight exactly when the greedoid has a strong exchange property — which Prim's greedoid has, and that is why §20 could prove Prim's without any restriction), and the details are beyond this page; what is worth keeping is the shape of the idea — the two axioms of §03's template 3 are exactly what a greedy proof consumes, and weakening one of them weakens the class of objectives for which greedy is guaranteed.

20 Greedy on graphs: the cut property, and why Kruskal, Prim and Dijkstra are greedy algorithms

The three most-used graph algorithms after the traversals are greedy. Dijkstra's algorithm is greedy too, with a different invariant and a hypothesis

Dijkstra's algorithm maintains a set of settled vertices whose shortest distances from the source are final and repeatedly settles the unsettled vertex with the smallest tentative distance — the locally best choice — then relaxes its outgoing edges. The greedy-choice lemma is: the unsettled vertex u with the smallest tentative distance has that distance as its true shortest distance. The proof is by contradiction — a shorter path to u would have to leave the settled set somewhere, and its first unsettled vertex would already have a tentative distance no larger than u's, and no path can get shorter by continuing — and that last step needs nonnegative edge weights. With a negative edge, continuing a path can shorten it, the lemma fails, and Dijkstra's algorithm returns wrong distances; the Bellman–Ford algorithm, which is not greedy, takes over. This is failure shape (i) of the greedy family: an algorithm that is correct under a hypothesis and is routinely quoted without it.

Two cautions on the framing. First, Prim's and Dijkstra's algorithms look identical in code — a priority queue of vertices, extract the minimum, relax the neighbours — and differ only in the key: Prim keys a vertex by the lightest single edge into the tree, Dijkstra by the total path length from the source. They solve different problems, and a minimum spanning tree is not a shortest-path tree. Second, the cut property is a statement about undirected graphs; directed minimum spanning arborescences are not found by either algorithm and are not greedy in this simple sense.

What the three problems have in common, and where each one's proof lives

Each problem's greedy rule maximises the measure the proof inducts on — the position after r stops, the farthest index after r jumps, the right endpoint of the r-th interval — and each rule is safe for the same reason: any other solution's (r + 1)-th choice was available to greedy at step r + 1, because greedy was already at least as far along. The unit-interval version is activity selection turned inside out: sort the points, place the first interval with its left end at the leftmost uncovered point (so it reaches as far right as possible), discard the points it covers, repeat; the measure is the right end of the last interval placed. The fuel-stop version is also the recipe for "minimum number of refuellings", "fewest taxi rides with a range limit" and "fewest checkpoints", which is why it is worth having the proof in one's head rather than re-deriving it each time.

A fourth member of the family is worth naming because it is activity selection seen from the other side: stabbing intervals — given n closed intervals, choose the fewest points so that every interval contains at least one point. Sort by right endpoint; place a point at the right endpoint of the first unstabbed interval; discard every interval containing it; repeat. The measure is the position of the last point placed, the stays-ahead claim is that greedy's r-th point is no further left than any solution's r-th point, and the number of points equals the size of the largest set of pairwise disjoint intervals — which is exactly the maximum set that earliest-finish activity selection finds. The two problems are a min–max pair (a lower bound for one is an upper bound for the other), and the same sorted scan solves both: the activities it keeps are a maximum disjoint family, and their right endpoints are a minimum stabbing set.

The rule also has a clean infeasibility case: if at some point no station is within R, then no strategy can cross that gap either — the gap is a property of the instance, not of the strategy — so greedy detects impossibility exactly when it exists. And it has a clean tie case: two stations at the same position are the same choice. What it does not extend to unchanged is a price per station (minimise the total cost of fuel, with a tank capacity): "farthest reachable" is the wrong key there — a cheap station just inside the range is worth stopping at early — and the objective is no longer determined by the measure "distance reached", so this proof has nothing to induct on. That problem has its own greedy rule (buy just enough, net of what is in the tank, to reach the first cheaper station if one lies within a tank's range; otherwise fill the tank and drive to the cheapest station within range) with its own exchange argument; the point is that the rule and the proof change together with the objective.

Reading the guarantee correctly

  • It is a bound on the ratio, for every instance. Greedy may be optimal on most instances (it is on many random ones); the theorem says the worst case is H(n), and the tight family shows the worst case is not a proof artefact — the ratio really grows like log n.
  • The bound is in terms of n, and the sharper form is H(d) with d the size of the largest set — for instances whose sets are small — sets of at most three elements give H(3) = 11/6. Vertex cover seen as set cover (universe = edges, one set per vertex holding its incident edges) has d = Δ, the maximum degree, so greedy is only an H(Δ)-approximation there — the max-degree greedy for vertex cover is a known Θ(log n) worst case, not a constant. (The system in which every set has two elements is edge cover, solvable exactly via maximum matching.) Do not quote a better ratio than H(d) for the plain greedy rule; it does not have one.
  • "Essentially tight" is a theorem, not a hunch. No polynomial-time algorithm achieves ratio (1 − ε) ln n unless P = NP. What sorting first buys, and what it does not

List scheduling is online: it assigns each job as it arrives, without knowing the rest, and the bound above holds for every arrival order — that is the theorem's real content. If the jobs are known in advance, sorting them longest-first (LPT) and then list-scheduling improves the guarantee to 4/3 − 1/(3m), because the job that determines the makespan is then no larger than a third of the optimum (if it were larger, only two jobs per machine could be optimal, and LPT is optimal in that case). LPT is still not optimal; exact solutions need dynamic programming over load vectors or branch and bound, and a polynomial-time approximation scheme exists that gets within 1 + ε for any fixed ε. The greedy rule's honest summary: never worse than twice optimal in any order, never worse than 4/3 with the best order, exact only by luck.

The proof's shape is worth recognising because it recurs. It does not compare greedy to the optimum directly (the optimum is unknown and hard); it compares both to lower bounds that are easy to compute — the longest job and the average load — and shows greedy is within a factor of those bounds. Every approximation proof on this page and in the approximation part of the series has this shape: find something the optimum cannot beat, show greedy is not far from it. The set-cover proof used "the optimum's k sets cover the remainder"; the knapsack proof used the LP relaxation. The bounds are the argument; the greedy rule is just what the bounds happen to certify.

Why "stingy" is the right greedy rule, and what it computes

The algorithm is greedy in the sense of §01 — one irrevocable choice at a time, made by a local rule — but the rule is "do the least you are forced to", which is why the invariant is so clean. Setting a variable true can only help implications (their conclusions may become forced) and only hurt negative clauses; since the implications force a unique minimal set, the algorithm computes the least model of the implications, and the negative clauses are satisfied by that model if by any. The result is exactly the greedy-choice property: the forced variable is in every solution, so choosing it is safe, and after choosing it the remaining problem is the same problem with one more fact. Horn clauses are the logical core of rule-based systems and of logic programming: a program of rules "if these facts then that fact" is a set of implications, a query is a negative clause, and the forward-chaining evaluation that derives all consequences is this algorithm. That is why a large useful fragment of an NP-complete problem is polynomial — it is the fragment in which a greedy rule can never be wrong.

What the fragment excludes matters as much: a clause with two positive literals, (¬x ∨ y ∨ z), offers a choice (make y true or z true) that no local rule can settle, and the stingy invariant fails — neither y nor z is forced. Two-literal clauses (2-SAT) have their own polynomial algorithm, via implications and strongly connected components (Graphs, §22); three-literal clauses (3-SAT) are NP-complete. The boundary between "greedy works" and "search is unavoidable" runs exactly through the clause forms, and the Horn case is the largest natural fragment on the greedy side.

25 Greedy in machine learning: trees, feature selection, boosting, beam search — greedy because the exact problem is intractable

Machine learning is full of greedy algorithms, and almost none of them come with the guarantees of §04–§21. They are greedy for the opposite reason: the exact optimisation is NP-hard or the search space is astronomically large, so a locally-best sequence of choices is the only feasible procedure, and its quality is assessed empirically rather than proved. Knowing which kind of greedy you are looking at — provably optimal, provably approximate, or heuristic — is the whole of what this page adds to those methods.

Decision-tree induction is greedy, and the exact problem is NP-complete

A decision tree is grown top-down: at each node, choose the split (feature and threshold) that most reduces the impurity of the node's data — information gain, Gini decrease, variance reduction — split, and recurse on the children. That is §01's template with "impurity reduction" as the greedy key and no backtracking: a split chosen at the root is never revisited even if a different root split would allow a much smaller tree below it. The reason is not laziness: constructing a minimum-size decision tree consistent with a training set is NP-complete, so the greedy top-down construction is the standard compromise, and pruning afterwards is the (also heuristic) repair. The mechanics — impurity measures, the splitting loop, pruning — are in Decision Trees; what this page adds is the label: it is a greedy heuristic with no optimality claim, and its known failure mode (a split that is locally uninformative but globally essential, as in XOR-shaped data) is exactly the failure shape of §05's wrong rules.

Forward feature selection, boosting as stagewise fitting, and greedy pursuit

  • Forward stepwise selection starts from no features and at each step adds the one feature that most improves the fit; backward elimination removes the least useful one. Both are greedy on a subset-selection problem whose exact version (best subset of size k) is NP-hard in general. Forward selection can miss a pair of features that are useless alone and decisive together — the same interaction failure as the tree's XOR — and the fix, when affordable, is a search (branch and bound over subsets) or a convex relaxation (an L1 penalty, whose path is followed by a related greedy procedure). Regularization covers the relaxation.
  • Boosting fits an additive model one term at a time: at stage t, keep everything fitted so far fixed and choose the next weak learner and its weight to most reduce the loss. That is forward stagewise additive modelling — greedy coordinate-wise optimisation in function space — and gradient boosting makes the greedy step explicit as a step along the negative gradient of the loss. Nothing is ever refitted, which is what makes boosting fast and what makes early terms suboptimal relative to a joint fit. Decision Trees, in its boosting section, has the algorithm.
  • Matching pursuit and its orthogonal variant choose, one at a time, the dictionary atom most correlated with the current residual — greedy sparse approximation, with guarantees only under restrictive conditions on the dictionary (incoherence), which is the pattern of a greedy rule that is provable under a hypothesis and heuristic without it.
  • Greedy layer-wise pretraining of deep networks — train one layer at a time on the previous layer's output, then fine-tune — was the practical route to deep models before end-to-end training became reliable; it is a greedy decomposition of a joint optimisation, useful because the joint problem was hard to optimise, and abandoned as soon as the joint problem became tractable.

Greedy and beam search in decoding

A language model or sequence-to-sequence model defines a probability over output sequences one token at a time, and finding the most probable sequence is a search over an exponential tree. Greedy decoding takes the most probable next token at every step — §01's template exactly, with a locally-maximal probability as the key — and is not optimal: a slightly less likely first token can lead to a far more likely completion. Beam search keeps the k best partial sequences at every step instead of one; it is "greedy with a wider front", still not exact (it can drop the prefix of the true best sequence), and its practical behaviour — beams that are too wide return degenerate high-probability outputs — is an empirical matter. Language Models and Large Language Models cover decoding strategies, including the sampling methods that abandon maximisation altogether. In §03's terms, greedy decoding has no stays-ahead measure, no exchange argument, and no matroid; it is a heuristic whose failure cases are the norm, which is why it is rarely the final choice.

Where greedy in ML does have a guarantee

Two places. Greedy maximisation of a monotone submodular function under a cardinality constraint — choosing k sensors, k summary sentences, k seed nodes for influence spread — is within 1 − 1/e of optimal, by the same calculation as §22's maximum coverage; submodularity ("diminishing returns") is the hypothesis, and it is checkable. And the k-means++ seeding rule — choose each new centre with probability proportional to its squared distance from the nearest existing centre — is a randomised greedy initialisation with an expected O(log k) approximation guarantee for the k-means objective (Clustering), which the plain greedy "farthest point" rule lacks. The pattern is the page's: greedy is provably good where a structure (submodularity, a matroid, a cut) can be named, and empirical everywhere else.

26 Greedy heuristics that are only heuristics: the nearest-neighbour tour, and how bad "locally best" can be

The travelling-salesman problem — visit every city once and return, minimising the total distance — has the most famous greedy heuristic of all: from the current city, go to the nearest unvisited one. It is fast (Θ(n²)), it is natural, and it has no constant-factor guarantee: on metric instances its ratio to the optimum can grow like log n, and on non-metric instances it can be made as large as you like with four cities.

What separates a heuristic from an algorithm

Nearest-neighbour fails §03's every test. There is no stays-ahead measure: being at the "nearest" city after r steps says nothing about the cost of finishing. There is no exchange argument: swapping the optimal tour's next city for the nearest one can lengthen the tour by any amount, as the four-city instance shows. There is no matroid: tours are not a hereditary set system in any useful sense. The rule is a heuristic because its only justification is that it is cheap and often not terrible, and "often" is measured, not proved — on the random Euclidean instances the figure draws, its ratio is typically within 30% of optimal, which for many purposes is fine and for a proof is nothing. The honest way to use such a rule is as a starting point for local improvement (2-opt, which repeatedly removes a crossing pair of edges), or as one of many restarts, and never to report its answer as the optimum.

The same distinction sorts every greedy rule in engineering practice. Greedy register allocation, greedy packing of files onto disks (first-fit decreasing bin packing, an 11/9 · OPT + 6/9 guarantee, tight — 11/9 · OPT + 1 is the older, looser form), greedy graph colouring (no polynomial ordering rule is guaranteed; Δ + 1 colours always, and a bad order can use n/2 colours on a 2-colourable graph), greedy interval-graph colouring by start time (optimal — that is §07), greedy scheduling of tasks by priority (§08, §19, §23 as the objective varies). The rules look alike; their status ranges from exact to unbounded; and the only way to know which is to find the proof or the counterexample. That is the skill this page has been practising.

27 When greedy fails, and what to do instead: dynamic programming, branch and bound, relaxation

Every failure on this page has the same anatomy: the problem keeps optimal substructure but loses the greedy-choice property, so the right choice at a step can only be found by comparing the outcomes of several choices. The three replacements differ in how they do the comparing. Dynamic programming compares all choices exactly, with a table to avoid recomputation. Branch and bound compares them by search, pruned by bounds — often bounds that a greedy relaxation supplies. Relaxation changes the problem to one greedy (or linear programming) solves exactly, then rounds, with a provable loss.

The decision procedure

  1. Write the recurrence first. Identify the subproblem and the choices at each step; check optimal substructure by cut-and-paste. If there is no recurrence, there is neither a greedy algorithm nor a DP, and the problem is a search.
  2. Guess the greedy key — the quantity that "leaves the most room": earliest finish, largest coin, highest density, lightest edge, most uncovered elements. Ask whether the element that is best by that key is contained in some optimal solution.
  3. Try to prove it by a template (§03): find a measure for stays-ahead, or the swap for an exchange, or check the matroid axioms. If the proof goes through, the DP collapses to a scan (§04) and you are done in n log n.
  4. Try to break it. Hunt for an instance where the swap loses value — two elements the key ranks in the "wrong" order for the objective (§05, §09, §11 each needed only a handful of elements). Random instances rarely find it (§05's fewest-conflicts rule survived 300 of them); the structure has to be aimed at.
  5. If it breaks: is the recurrence polynomial? Count the distinct subproblems. Polynomially many → dynamic programming, read Dynamic Programming. Exponentially many (subsets, tours) → the problem is likely NP-hard; take the greedy rule as a heuristic or an approximation, prove a ratio if you can (§22, §23), and use branch and bound (Recursion, Divide & Conquer, §26) with the greedy relaxation as the bound when an exact answer is needed on small instances.

Relaxation, in one paragraph

A relaxation replaces a hard constraint by an easier one — integers by reals, "each item whole" by "any fraction", "one machine per job" by "jobs may be split" — producing a problem whose optimum is a bound on the original's (an upper bound for maximisation, lower for minimisation), and often one that greedy or linear programming solves exactly. Fractional knapsack is the relaxation of 0/1 knapsack (§10–§11); the "any schedule may be preempted" relaxation gives the ∑pⱼ/m bound of §23; the linear-programming relaxation of set cover is what the sharper analyses of §22 are built on. Rounding the relaxed solution back to a feasible one — take the whole items, assign each split job to one machine — and bounding the loss is the standard route to an approximation ratio, and the greedy algorithm is usually the rounding step's first move. So the greedy rule's failure is rarely the end of the story: the same rule reappears as a bound, a relaxation solver, or a rounding heuristic inside the algorithm that replaces it.

The two-sentence test

State the greedy key in one sentence: "take the element with the smallest/largest X that keeps the solution feasible." Then state the safety claim in one sentence: "the element with the best X is contained in some optimal solution because Y." If you cannot fill in Y with a measure that greedy maximises step by step, a swap that provably loses nothing, or a pair of axioms, you do not have a greedy algorithm — you have a guess, and §27's decision flow says what to do with it. The most common way to fill in Y wrongly is to argue about the objective directly ("greedy has picked at least as many so far") when the induction has to be about the measure ("greedy's last pick finishes no later"); §06 shows the difference on the simplest possible case.

A note on cost

The template's cost is the ordering plus the feasibility tests, and both are worth naming precisely. The ordering is a sort, Θ(n log n), unless the keys are small integers (a counting sort makes it linear, Sorting & Searching, §20) or the choice is made repeatedly from a changing set (a priority queue, O(log n) per choice — Huffman, Prim, Dijkstra). The feasibility test ranges from O(1) (compare against last) through a hash-set membership check (Hash Tables, §02) to a union-find FIND (near-constant amortised) or a linear count (§19's Nₜ). "Greedy is fast" is true only because these two ingredients are usually cheap; a greedy rule whose feasibility test is itself expensive — checking a matroid independence oracle that costs a linear-algebra rank computation, say — is as slow as its test, and no faster for being greedy.

29 Pitfalls

  • Quoting a theorem without its hypothesis. "Greedy solves activity selection" is true for earliest finish and false for three equally plausible rules (§05). "Greedy solves coin change" is true for canonical systems only (§09). "Greedy solves knapsack" is true for the fractional version only (§10–§11). "Huffman is optimal" is true among symbol-by-symbol prefix codes for a known distribution (§14). "Dijkstra is greedy and correct" needs nonnegative weights (§20). "Earliest deadline minimises lateness" means maximum lateness (§08). Each hypothesis is where the proof's one inequality lives.
  • Proving the objective instead of the measure. A stays-ahead induction on "greedy has chosen at least as many" has nothing to induct on; the induction is on finish times, positions, right endpoints, and the count follows at the end (§06, §21).
  • Trusting random tests. The fewest-conflicts rule passed 300 random instances at every setting the figure offers and is wrong (§05). Counterexamples to greedy rules have structure that random instances almost never contain; a proof or an aimed counterexample is the only evidence that counts.
  • Sorting by the wrong key. Interval partitioning needs start order (§07); activity selection needs finish order (§04). Both are "sort then scan"; swapping the keys breaks the proof and, measurably, the answer.
  • Confusing "some optimum contains the greedy choice" with "every optimum does". The greedy-choice property is existential. Activity selection has four optima and only two contain a₁; Huffman has several optimal trees when frequencies tie (§15). An exchange proof produces an optimum containing the choice, and that is all the induction needs.
  • Forgetting the base and the edge cases. Empty input, one element, all elements identical, ties in the key, a coin system without a 1, a single-symbol alphabet (§06, §09, §15). The proofs are inductions and they start somewhere.
  • Assuming greedy is fast because it is greedy. It is fast because the sort and the feasibility test are cheap (§28). With an expensive independence test or a priority queue it is Θ(n log n) or worse, and the matroid greedy with an O(n) test is quadratic (§19).
  • Reporting a heuristic's answer as the optimum. Nearest-neighbour, greedy colouring, greedy decoding, greedy tree induction return a solution; none of them returns the solution, and their ratios range from bounded to unbounded (§25–§26). Say which.
  • Misreading the approximation ratio. Greedy set cover is H(n), not a constant, and that is essentially tight (§22); list scheduling is 2 − 1/m in any order and 4/3 − 1/(3m) sorted (§23); the knapsack greedy is 1/2 only with the single-item fix (§11). The ratio belongs to a specific rule on a specific problem.
  • Boundary conventions. Half-open intervals make "start ≥ last finish" the compatibility test and let an activity begin exactly when another ends; closed intervals need a strict inequality. The stabbing dual of §21 needs closed intervals for "the right endpoint stabs it" to be true. A greedy algorithm's correctness proof is written for one convention, and a silent change of ≥ to > is a different problem.
  • Tie-breaking is part of the specification. Two Huffman implementations with different priority-queue tie rules produce different trees of the same cost (§15); a decoder built from the wrong tree decodes garbage. That is why formats transmit canonical lengths rather than trust both sides to break ties the same way (§16), and why a greedy algorithm whose output must be reproduced elsewhere should fix its tie order explicitly.
  • Systems folklore. "zip uses Huffman" — DEFLATE uses LZ77 and Huffman; JPEG has an arithmetic-coding option; modern compressors increasingly use ANS (§16). "Real coin systems are canonical" — most are, as a consequence of the 1-2-5 pattern rather than a stated design goal, and a 20-and-25 system is not (§09). Check the format specification, not the memory of a lecture.
