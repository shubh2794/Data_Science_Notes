22 Greedy set cover: not optimal, but within H(n) ≈ ln n of optimal — and that is essentially the best possible

A universe U of n elements and a family of subsets S₁, …, Sₘ whose union is U; pick the fewest subsets whose union is still U. The greedy rule — repeatedly pick the set that covers the most still-uncovered elements — is not optimal, and the gap can grow like log n. But it is never worse than H(n) = 1 + 1/2 + … + 1/n ≈ ln n + 0.58 times the optimum, and under the assumption P ≠ NP no polynomial-time algorithm has a guarantee of (1 − ε) ln n for any fixed ε > 0. This is the first approximation guarantee on the page and a preview of NP-Completeness & Approximation, §23, which proves the H(d) bound and the matching hardness result.

Reading the guarantee correctly

  • It is a bound on the ratio, for every instance. Greedy may be optimal on most instances (it is on many random ones); the theorem says the worst case is H(n), and the tight family shows the worst case is not a proof artefact — the ratio really grows like log n.
  • The bound is in terms of n, and the sharper form is H(d) with d the size of the largest set — for instances whose sets are small — sets of at most three elements give H(3) = 11/6. Vertex cover seen as set cover (universe = edges, one set per vertex holding its incident edges) has d = Δ, the maximum degree, so greedy is only an H(Δ)-approximation there — the max-degree greedy for vertex cover is a known Θ(log n) worst case, not a constant. (The system in which every set has two elements is edge cover, solvable exactly via maximum matching.) Do not quote a better ratio than H(d) for the plain greedy rule; it does not have one.
  • "Essentially tight" is a theorem, not a hunch. No polynomial-time algorithm achieves ratio (1 − ε) ln n unless P = NP. Greedy is, up to lower-order terms, the best possible polynomial-time approximation for set cover, which is unusual: for most problems where greedy gives a ratio, something else gives a better one.
  • The weighted version (each set has a cost, minimise total cost) uses the rule "pick the set minimising cost per newly covered element" and has the same H(n) guarantee by the same charging argument.
  • Maximum coverage (pick k sets to cover the most elements) has the same greedy rule and a different guarantee, 1 − 1/e ≈ 0.632 of the optimum, from the same (1 − 1/k)ᵏ calculation; that bound is the general one for greedy maximisation of a monotone submodular function, which is the modern home of this whole argument.

23 Load balancing: list scheduling on identical machines is a (2 − 1/m)-approximation, proved

n jobs with processing times pⱼ, m identical machines, each job on one machine; minimise the makespan — the time the last machine finishes. The greedy rule (list scheduling): take the jobs in the given order and assign each to the machine that is currently least loaded. It is not optimal — the problem is NP-hard for m ≥ 2 — but its makespan is never more than 2 − 1/m times the optimum, and the proof is four lines built on two lower bounds that any schedule must obey.

What sorting first buys, and what it does not

List scheduling is online: it assigns each job as it arrives, without knowing the rest, and the bound above holds for every arrival order — that is the theorem's real content. If the jobs are known in advance, sorting them longest-first (LPT) and then list-scheduling improves the guarantee to 4/3 − 1/(3m), because the job that determines the makespan is then no larger than a third of the optimum (if it were larger, only two jobs per machine could be optimal, and LPT is optimal in that case). LPT is still not optimal; exact solutions need dynamic programming over load vectors or branch and bound, and a polynomial-time approximation scheme exists that gets within 1 + ε for any fixed ε. The greedy rule's honest summary: never worse than twice optimal in any order, never worse than 4/3 with the best order, exact only by luck.

The proof's shape is worth recognising because it recurs. It does not compare greedy to the optimum directly (the optimum is unknown and hard); it compares both to lower bounds that are easy to compute — the longest job and the average load — and shows greedy is within a factor of those bounds. Every approximation proof on this page and in the approximation part of the series has this shape: find something the optimum cannot beat, show greedy is not far from it. The set-cover proof used "the optimum's k sets cover the remainder"; the knapsack proof used the LP relaxation. The bounds are the argument; the greedy rule is just what the bounds happen to certify.

24 Horn-formula satisfiability: a greedy algorithm that is exact for a fragment of an NP-complete problem

Boolean satisfiability is NP-complete, but its Horn fragment — clauses that are either implications (x₁ ∧ … ∧ xₖ) ⇒ y or purely negative (¬x₁ ∨ … ∨ ¬xₖ) — is decided by a greedy (better: stingy) algorithm in linear time: start with everything false, set a variable true only when an implication forces it, and check the negative clauses at the end. Its correctness argument is a stays-ahead invariant in disguise: every variable the algorithm sets true is true in every satisfying assignment.

Why "stingy" is the right greedy rule, and what it computes

The algorithm is greedy in the sense of §01 — one irrevocable choice at a time, made by a local rule — but the rule is "do the least you are forced to", which is why the invariant is so clean. Setting a variable true can only help implications (their conclusions may become forced) and only hurt negative clauses; since the implications force a unique minimal set, the algorithm computes the least model of the implications, and the negative clauses are satisfied by that model if by any. The result is exactly the greedy-choice property: the forced variable is in every solution, so choosing it is safe, and after choosing it the remaining problem is the same problem with one more fact. Horn clauses are the logical core of rule-based systems and of logic programming: a program of rules "if these facts then that fact" is a set of implications, a query is a negative clause, and the forward-chaining evaluation that derives all consequences is this algorithm. That is why a large useful fragment of an NP-complete problem is polynomial — it is the fragment in which a greedy rule can never be wrong.

What the fragment excludes matters as much: a clause with two positive literals, (¬x ∨ y ∨ z), offers a choice (make y true or z true) that no local rule can settle, and the stingy invariant fails — neither y nor z is forced. Two-literal clauses (2-SAT) have their own polynomial algorithm, via implications and strongly connected components (Graphs, §22); three-literal clauses (3-SAT) are NP-complete. The boundary between "greedy works" and "search is unavoidable" runs exactly through the clause forms, and the Horn case is the largest natural fragment on the greedy side.

25 Greedy in machine learning: trees, feature selection, boosting, beam search — greedy because the exact problem is intractable

Machine learning is full of greedy algorithms, and almost none of them come with the guarantees of §04–§21. They are greedy for the opposite reason: the exact optimisation is NP-hard or the search space is astronomically large, so a locally-best sequence of choices is the only feasible procedure, and its quality is assessed empirically rather than proved. Knowing which kind of greedy you are looking at — provably optimal, provably approximate, or heuristic — is the whole of what this page adds to those methods.

Decision-tree induction is greedy, and the exact problem is NP-complete

A decision tree is grown top-down: at each node, choose the split (feature and threshold) that most reduces the impurity of the node's data — information gain, Gini decrease, variance reduction — split, and recurse on the children. That is §01's template with "impurity reduction" as the greedy key and no backtracking: a split chosen at the root is never revisited even if a different root split would allow a much smaller tree below it. The reason is not laziness: constructing a minimum-size decision tree consistent with a training set is NP-complete, so the greedy top-down construction is the standard compromise, and pruning afterwards is the (also heuristic) repair. The mechanics — impurity measures, the splitting loop, pruning — are in Decision Trees; what this page adds is the label: it is a greedy heuristic with no optimality claim, and its known failure mode (a split that is locally uninformative but globally essential, as in XOR-shaped data) is exactly the failure shape of §05's wrong rules.

Forward feature selection, boosting as stagewise fitting, and greedy pursuit

  • Forward stepwise selection starts from no features and at each step adds the one feature that most improves the fit; backward elimination removes the least useful one. Both are greedy on a subset-selection problem whose exact version (best subset of size k) is NP-hard in general. Forward selection can miss a pair of features that are useless alone and decisive together — the same interaction failure as the tree's XOR — and the fix, when affordable, is a search (branch and bound over subsets) or a convex relaxation (an L1 penalty, whose path is followed by a related greedy procedure). Regularization covers the relaxation.
  • Boosting fits an additive model one term at a time: at stage t, keep everything fitted so far fixed and choose the next weak learner and its weight to most reduce the loss. That is forward stagewise additive modelling — greedy coordinate-wise optimisation in function space — and gradient boosting makes the greedy step explicit as a step along the negative gradient of the loss. Nothing is ever refitted, which is what makes boosting fast and what makes early terms suboptimal relative to a joint fit. Decision Trees, in its boosting section, has the algorithm.
  • Matching pursuit and its orthogonal variant choose, one at a time, the dictionary atom most correlated with the current residual — greedy sparse approximation, with guarantees only under restrictive conditions on the dictionary (incoherence), which is the pattern of a greedy rule that is provable under a hypothesis and heuristic without it.
  • Greedy layer-wise pretraining of deep networks — train one layer at a time on the previous layer's output, then fine-tune — was the practical route to deep models before end-to-end training became reliable; it is a greedy decomposition of a joint optimisation, useful because the joint problem was hard to optimise, and abandoned as soon as the joint problem became tractable.

Greedy and beam search in decoding

A language model or sequence-to-sequence model defines a probability over output sequences one token at a time, and finding the most probable sequence is a search over an exponential tree. Greedy decoding takes the most probable next token at every step — §01's template exactly, with a locally-maximal probability as the key — and is not optimal: a slightly less likely first token can lead to a far more likely completion. Beam search keeps the k best partial sequences at every step instead of one; it is "greedy with a wider front", still not exact (it can drop the prefix of the true best sequence), and its practical behaviour — beams that are too wide return degenerate high-probability outputs — is an empirical matter. Language Models and Large Language Models cover decoding strategies, including the sampling methods that abandon maximisation altogether. In §03's terms, greedy decoding has no stays-ahead measure, no exchange argument, and no matroid; it is a heuristic whose failure cases are the norm, which is why it is rarely the final choice.

Where greedy in ML does have a guarantee

Two places. Greedy maximisation of a monotone submodular function under a cardinality constraint — choosing k sensors, k summary sentences, k seed nodes for influence spread — is within 1 − 1/e of optimal, by the same calculation as §22's maximum coverage; submodularity ("diminishing returns") is the hypothesis, and it is checkable. And the k-means++ seeding rule — choose each new centre with probability proportional to its squared distance from the nearest existing centre — is a randomised greedy initialisation with an expected O(log k) approximation guarantee for the k-means objective (Clustering), which the plain greedy "farthest point" rule lacks. The pattern is the page's: greedy is provably good where a structure (submodularity, a matroid, a cut) can be named, and empirical everywhere else.

26 Greedy heuristics that are only heuristics: the nearest-neighbour tour, and how bad "locally best" can be

The travelling-salesman problem — visit every city once and return, minimising the total distance — has the most famous greedy heuristic of all: from the current city, go to the nearest unvisited one. It is fast (Θ(n²)), it is natural, and it has no constant-factor guarantee: on metric instances its ratio to the optimum can grow like log n, and on non-metric instances it can be made as large as you like with four cities.

What separates a heuristic from an algorithm

Nearest-neighbour fails §03's every test. There is no stays-ahead measure: being at the "nearest" city after r steps says nothing about the cost of finishing. There is no exchange argument: swapping the optimal tour's next city for the nearest one can lengthen the tour by any amount, as the four-city instance shows. There is no matroid: tours are not a hereditary set system in any useful sense. The rule is a heuristic because its only justification is that it is cheap and often not terrible, and "often" is measured, not proved — on the random Euclidean instances the figure draws, its ratio is typically within 30% of optimal, which for many purposes is fine and for a proof is nothing. The honest way to use such a rule is as a starting point for local improvement (2-opt, which repeatedly removes a crossing pair of edges), or as one of many restarts, and never to report its answer as the optimum.

The same distinction sorts every greedy rule in engineering practice. Greedy register allocation, greedy packing of files onto disks (first-fit decreasing bin packing, an 11/9 · OPT + 6/9 guarantee, tight — 11/9 · OPT + 1 is the older, looser form), greedy graph colouring (no polynomial ordering rule is guaranteed; Δ + 1 colours always, and a bad order can use n/2 colours on a 2-colourable graph), greedy interval-graph colouring by start time (optimal — that is §07), greedy scheduling of tasks by priority (§08, §19, §23 as the objective varies). The rules look alike; their status ranges from exact to unbounded; and the only way to know which is to find the proof or the counterexample. That is the skill this page has been practising.
