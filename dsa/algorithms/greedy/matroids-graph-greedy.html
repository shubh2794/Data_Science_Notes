17 Matroids: the definition, the exchange axiom, and the examples that are (and are not) matroids

A matroid is the abstract structure that makes greedy work for every weight function. It is a finite ground set S together with a family I of "independent" subsets satisfying two axioms: hereditary — a subset of an independent set is independent — and exchange — a smaller independent set can always be grown by an element of a larger one. The name comes from matrices (columns that are linearly independent), the motivating example is forests in a graph, and the payoff is §18's theorem: on a matroid, sort by weight and take what fits.

What is not a matroid — and why that matters

Compatible sets of intervals (activity selection) are hereditary but fail exchange: A = {[0, 10)} and B = {[0, 4), [5, 9)} are both compatible, |A| < |B|, and neither member of B can be added to A — both overlap [0, 10). So interval compatibility is not a matroid, and the matroid theorem does not apply to activity selection; earliest-finish needs its own proof (§04), and weighted activity selection has no greedy algorithm at all (§06, §18). Matchings in a graph are hereditary but not a matroid (a path on four vertices: the middle edge alone is a maximal matching of size 1, the two outer edges form one of size 2 — bases of different sizes), which is why maximum matching needs augmenting paths, not greed. Independent sets of vertices (no two adjacent) fail for the same reason. Huffman trees are not a set system of this kind at all. The lesson is the one §03 gave: the matroid template is powerful exactly where it applies and silent everywhere else, and checking (M2) on a small example is the fastest way to find out which.

18 The greedy algorithm on a weighted matroid: the theorem, its proof, the min-weight variant, and the converse

On a matroid with nonnegative weights, the greedy algorithm — sort the elements by decreasing weight, add each one that keeps the set independent — returns a maximum-weight independent set. The proof is the two-property pattern once more, with the exchange axiom doing the work that a problem-specific inequality did in §04 and §10. It explains Kruskal's algorithm (a graphic matroid with negated weights), the unit-task scheduler of §19, and every "take the best that still fits" algorithm on a structure that passes (M1) and (M2).

Three consequences worth stating exactly

  • Maximum weight versus maximum-weight basis. With all weights strictly positive, an optimal set is automatically a basis (adding any extension helps), so the theorem finds the maximum-weight basis. With zero weights present, greedy as written still adds every weight-0 element that keeps independence, so it returns a basis; a variant that stops at the first zero weight returns a maximum-weight independent set that may not be a basis — the same weight either way. With negative weights present, greedy should skip them: the theorem as stated needs w ≥ 0, and negative-weight elements can never help a maximum-weight set. (For a maximum-weight basis with negative weights allowed, add a constant to every weight — bases all have the same size, so the order of bases is unchanged.)
  • Minimum weight. A minimum-weight basis is found by negating: sort by increasing weight and add what stays independent. Equivalently use w'(x) = w₀ − w(x) with w₀ larger than every weight, which is positive, and maximise. That is Kruskal's algorithm on the graphic matroid: sort edges by increasing weight, add each edge that does not close a cycle, and the result is a minimum spanning tree — the matroid theorem is one of its two standard proofs, the cut property (§20) is the other.
  • The converse: greedy-for-all-weights characterises matroids. Let (S, I) be hereditary (M1). If the greedy algorithm returns a maximum-weight member of I for every nonnegative weight function, then (S, I) satisfies (M2) and is a matroid. Sketch: suppose (M2) fails for some A, B with |A| < |B|; give the elements of A weight 1 + ε, those of B − A weight 1, everything else 0. Greedy takes all of A first (heaviest, independent), then can add nothing from B − A (that is what failing (M2) means), so its value is |A|(1 + ε); but B has value at least |B| ≥ |A| + 1, which is larger for small ε. So greedy fails for that weight function. This is why weighted activity selection has no greedy algorithm: interval compatibility is not a matroid (§17), so some weight function defeats the weight-sorted greedy — and the weight function in the sketch is a recipe for building it.

Beyond matroids, briefly

The matroid theorem covers greedy algorithms whose feasible sets are closed under subsets. Some correct greedy algorithms live on structures that are not hereditary — a partial solution must be built up in a particular order, and a subset of a feasible set need not be feasible. Prim's algorithm, whose partial solutions must stay connected trees grown from the root, is the standard example, and the structure that captures it is the greedoid: the hereditary axiom is weakened to accessibility (every nonempty feasible set has an element whose removal leaves a feasible set) and the exchange axiom is kept. Greedy is optimal on a general greedoid only for a narrower class of objectives than on a matroid (it is optimal for every linear weight exactly when the greedoid has a strong exchange property — which Prim's greedoid has, and that is why §20 could prove Prim's without any restriction), and the details are beyond this page; what is worth keeping is the shape of the idea — the two axioms of §03's template 3 are exactly what a greedy proof consumes, and weakening one of them weakens the class of objectives for which greedy is guaranteed.

19 Scheduling unit-time tasks with deadlines and penalties: a matroid in disguise

n tasks each taking one time unit, task i with an integer deadline dᵢ (1 ≤ dᵢ ≤ n) and a penalty wᵢ ≥ 0 paid if it finishes after dᵢ; run them one per slot from time 1; minimise the total penalty. This looks like a sequencing problem, but it is a set problem: the schedule is determined by which tasks are on time, and the on-time sets form a matroid, so the greedy algorithm of §18 solves it exactly.

Cost, and the shape of the argument

The test "is A ∪ {x} independent?" by criterion (2) costs O(n) — count deadlines with a bucket array — so the greedy run is O(n²) after an O(n log n) sort; a union-find over time slots ("find the latest free slot at or before dₓ") brings the test down to near-constant amortised time, the same structure Kruskal's algorithm uses. What makes this problem instructive is that the greedy rule is not obviously about sets — one would naturally think about orders — and that once the reduction to a set problem is seen, no problem-specific exchange is needed: the matroid axioms are checked once (the theorem above), and §18 does the rest for every penalty function. The exchange proof of §08 (maximum lateness) and this proof solve superficially similar scheduling problems by completely different routes, because §08's objective is a maximum over an order while this one is a sum over a set; recognising which of the two shapes a scheduling problem has is the first step of solving it.

20 Greedy on graphs: the cut property, and why Kruskal, Prim and Dijkstra are greedy algorithms

The three most-used graph algorithms after the traversals are greedy. Kruskal's and Prim's build a minimum spanning tree by repeatedly adding the cheapest safe edge; Dijkstra's builds a shortest-path tree by repeatedly settling the closest unsettled vertex. This page states the one lemma that makes the spanning-tree algorithms correct — the cut property — proves it, and names the algorithms; the algorithms themselves, with their data structures, traces and costs, are the subject of Shortest Paths, MST & Flow, and Graphs, §28 and §27 are the data-structure hand-offs.

definitionsG = (V, E) connected, undirected, with edge weights w. A SPANNING TREE is an acyclic connected subgraph on all of V — it has exactly |V| − 1 edges. a MINIMUM spanning tree (MST) minimises the total weight. A CUT (S, V − S) is a partition of the vertices; an edge CROSSES it if its endpoints are on different sides. an edge set X RESPECTS a cut if no edge of X crosses it. A LIGHT edge across a cut has minimum weight among the crossing edges. THEOREM (the cut property = the greedy-choice lemma for MSTs). Hypothesis: X ⊆ some MST T; (S, V − S) a cut that X respects; e a light edge across it.X ∪ {e} is contained in some MST. proof — the exchangeif e ∈ T, done. Otherwise T ∪ {e} contains exactly one cycle (T is a tree: the tree path between e's endpoints plus e). that cycle crosses the cut an even number of times — it leaves S and must return — so besides e it contains another crossing edge e'. e' ∈ T, and e' ∉ X since X respects the cut. T' = T ∪ {e} − {e'} is a spanning tree: removing e' from the cycle leaves it connected, and it has |V| − 1 edges. w(T') = w(T) + w(e) − w(e') ≤ w(T) because e is LIGHT across the cut and e' also crosses it. T is minimum, so w(T') = w(T): T' is an MST, and X ∪ {e} ⊆ T'. ∎ the two MST algorithms are two ways of choosing the cutKRUSKAL X = a forest; the next edge (cheapest overall that joins two different trees of X) is light across the cut (its tree, everything else), which X respects. sort edges Θ(m log m); each test "different trees?" is a union-find FIND — O(m α(n)) for all of them. Dijkstra's algorithm is greedy too, with a different invariant and a hypothesis

Dijkstra's algorithm maintains a set of settled vertices whose shortest distances from the source are final and repeatedly settles the unsettled vertex with the smallest tentative distance — the locally best choice — then relaxes its outgoing edges. The greedy-choice lemma is: the unsettled vertex u with the smallest tentative distance has that distance as its true shortest distance. The proof is by contradiction — a shorter path to u would have to leave the settled set somewhere, and its first unsettled vertex would already have a tentative distance no larger than u's, and no path can get shorter by continuing — and that last step needs nonnegative edge weights. With a negative edge, continuing a path can shorten it, the lemma fails, and Dijkstra's algorithm returns wrong distances; the Bellman–Ford algorithm, which is not greedy, takes over. This is failure shape (i) of the greedy family: an algorithm that is correct under a hypothesis and is routinely quoted without it.

Two cautions on the framing. First, Prim's and Dijkstra's algorithms look identical in code — a priority queue of vertices, extract the minimum, relax the neighbours — and differ only in the key: Prim keys a vertex by the lightest single edge into the tree, Dijkstra by the total path length from the source. They solve different problems, and a minimum spanning tree is not a shortest-path tree. Second, the cut property is a statement about undirected graphs; directed minimum spanning arborescences are not found by either algorithm and are not greedy in this simple sense.

21 Greedy along a line: fuel stops, jumps, and unit intervals — three stays-ahead proofs from one template

A family of problems shares one greedy rule — go as far as you can before committing — and one proof, the stays-ahead induction of §03 with "distance reached" as the measure. Fuel stops: a road of length D with stations at known positions and a tank that covers distance R; minimise the stops. Jumps: an array where a[i] is the farthest you may jump from i; minimise the jumps to the end. Unit intervals: cover a set of points on a line with the fewest intervals of length 1. In each, the greedy choice is the farthest reachable option, and any solution that commits earlier is never ahead.

What the three problems have in common, and where each one's proof lives

Each problem's greedy rule maximises the measure the proof inducts on — the position after r stops, the farthest index after r jumps, the right endpoint of the r-th interval — and each rule is safe for the same reason: any other solution's (r + 1)-th choice was available to greedy at step r + 1, because greedy was already at least as far along. The unit-interval version is activity selection turned inside out: sort the points, place the first interval with its left end at the leftmost uncovered point (so it reaches as far right as possible), discard the points it covers, repeat; the measure is the right end of the last interval placed. The fuel-stop version is also the recipe for "minimum number of refuellings", "fewest taxi rides with a range limit" and "fewest checkpoints", which is why it is worth having the proof in one's head rather than re-deriving it each time.

A fourth member of the family is worth naming because it is activity selection seen from the other side: stabbing intervals — given n closed intervals, choose the fewest points so that every interval contains at least one point. Sort by right endpoint; place a point at the right endpoint of the first unstabbed interval; discard every interval containing it; repeat. The measure is the position of the last point placed, the stays-ahead claim is that greedy's r-th point is no further left than any solution's r-th point, and the number of points equals the size of the largest set of pairwise disjoint intervals — which is exactly the maximum set that earliest-finish activity selection finds. The two problems are a min–max pair (a lower bound for one is an upper bound for the other), and the same sorted scan solves both: the activities it keeps are a maximum disjoint family, and their right endpoints are a minimum stabbing set.

The rule also has a clean infeasibility case: if at some point no station is within R, then no strategy can cross that gap either — the gap is a property of the instance, not of the strategy — so greedy detects impossibility exactly when it exists. And it has a clean tie case: two stations at the same position are the same choice. What it does not extend to unchanged is a price per station (minimise the total cost of fuel, with a tank capacity): "farthest reachable" is the wrong key there — a cheap station just inside the range is worth stopping at early — and the objective is no longer determined by the measure "distance reached", so this proof has nothing to induct on. That problem has its own greedy rule (buy just enough, net of what is in the tank, to reach the first cheaper station if one lies within a tank's range; otherwise fill the tank and drive to the cheapest station within range) with its own exchange argument; the point is that the rule and the proof change together with the objective.
