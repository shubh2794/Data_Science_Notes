07 Interval partitioning: schedule everything, using the fewest resources — the depth lower bound

Turn activity selection around: every interval must be scheduled, and the question is how many resources (rooms, machines, registers) are needed so that no two overlapping intervals share one. The greedy answer processes intervals in order of start time and puts each into any resource that is free, opening a new one only when none is. It is optimal, and the proof is not an exchange but a lower bound that the greedy algorithm meets: no schedule can use fewer resources than the largest number of intervals alive at one instant, and greedy never opens a resource unless that many are alive.

definitionsa PARTITION assigns each interval a resource so that intervals on the same resource are pairwise compatible the DEPTH of a set of intervals = the maximum number of intervals containing a common point (= the largest clique of overlaps) for half-open intervals the maximum is attained at some interval's start time, so depth is computed by testing those n points: Θ(n²) naively the algorithm — sort by START time, not finish timesort intervals by start time for each interval I in that order: if some resource's last interval finished at or before s(I): put I there ← a resource is free iff its last finish ≤ s(I) else: open a new resource (with a min-heap on "last finish time" the free test is one peek: Θ(n log n) total; the figure scans the resources, Θ(n · rooms)) THEOREM. Hypothesis: intervals processed in nondecreasing start order.the greedy algorithm uses exactly depth(I) resources, and every partition uses at least depth(I). prooflower bound: d intervals sharing a point must be on d different resources. So every partition uses ≥ depth. greedy ≤ depth: suppose greedy opens resource number d while placing interval I. The d − 1 existing resources are all busy: each holds an interval that started at or before s(I) (start order) and finishes after s(I) (busy). Those d − 1 intervals and I all contain the point s(I). So depth ≥ d. Greedy opens resource d only when d intervals overlap; it never exceeds the depth, and it cannot go below it. ∎

Worked: ten lectures, four rooms

Ten lectures with start and end times on a day: a [9, 10.5), b [9, 12.5), c [9, 10.5), d [11, 12.5), e [11, 14), f [13, 14.5), g [13, 14.5), h [13, 16.5), i [15, 16.5), j [15, 16.5). The depth is 4: at time 13 the lectures e, f, g, h are all in progress, and no time has five. The greedy pass (start order; ties broken by end time, then name, so a, c precede b) assigns a→1, c→2, b→3 (three rooms opened at 9), d→1 (room 1 freed at 10.5), e→2 (room 2 freed at 10.5), f→1 (freed at 12.5), g→3, h→4 (rooms 1–3 all busy at 13: a new room), i→1, j→2. Four rooms, equal to the depth — as the theorem says it must be. Run under the counter, the room scan makes 16 "is this room free?" tests, and the figure recomputes the depth independently by testing every start time.

Why start order, and what goes wrong with finish order

The proof's key step is "each existing resource holds an interval that started at or before s(I)" — that is what makes all d intervals share the point s(I), and it is true only because intervals are processed in start order. Process them by finish time instead and the busy resources may hold intervals that started after s(I), sharing no common point with it; greedy can then open a room the depth does not justify. On the ten lectures finish-order processing also happens to use four rooms, but the guarantee is gone: on the figure's random instance of twelve intervals the depth is 3, start order uses 3 rooms, and finish order opens a fourth — and across 500 random instances of that kind finish order exceeded the depth on 52 (a load-time measurement, reported in the cheat sheet). This is the same lesson as §05 in a different costume: the greedy key is not a matter of taste, it is the thing the proof turns on.

08 Scheduling to minimise maximum lateness: the exchange argument on inversions, traced

n jobs, each with a processing time tⱼ and a deadline dⱼ, run one after another on one machine from time 0; a job finishing at fⱼ is late by Lⱼ = max(0, fⱼ − dⱼ); minimise the maximum lateness. The greedy rule is earliest deadline first: ignore the processing times entirely and run the jobs in deadline order. The proof is the cleanest exchange argument on this page — it shows that any schedule can be turned into the greedy one by swapping adjacent out-of-order pairs without ever increasing the maximum lateness.

the instance used below — six jobsjob A B C D E F tⱼ 3 2 1 4 3 2 dⱼ 6 8 9 9 14 15 the algorithmsort by deadline (ties any order); run back to back with no idle time. Θ(n log n) for the sort, Θ(n) to lay out the schedule two facts about optimal schedules1. there is an optimal schedule with NO IDLE TIME — closing a gap moves later jobs earlier and can only reduce lateness 2. an INVERSION is a pair (i, j) with i scheduled before j and dᵢ > dⱼ. A schedule with no idle time and no inversions is an earliest-deadline schedule (all such schedules differ only in the order of equal-deadline jobs, and those all have the same maximum lateness — jobs with equal deadline run back to back, and only the last of them can be the latest, finishing at the same time in every order) LEMMA (the exchange). Hypothesis: jobs i, j adjacent, i before j, dᵢ > dⱼ (an inversion). Swap them.no other job's finish time changes. j finishes earlier, so its lateness falls. i now finishes when j used to, at time f = fⱼ(old): new Lᵢ = f − dᵢ < f − dⱼ = old Lⱼ (because dᵢ > dⱼ) so i's new lateness is below j's old lateness, which was ≤ the old maximum. The maximum lateness does not increase. ∎ THEOREM. Earliest-deadline-first minimises the maximum lateness.take any optimal schedule; remove idle time (fact 1); while it has an inversion, it has an ADJACENT one (consecutive jobs with dᵢ > dⱼ — otherwise deadlines would be nondecreasing along the whole sequence); swap it (lemma) — the maximum lateness does not rise and the number of inversions falls by exactly one. after at most n(n − 1)/2 swaps the schedule has no inversions, is an earliest-deadline schedule, and is still optimal. ∎

Worked: from the worst order to the greedy one

Run the six jobs in the order F, E, D, C, B, A — reverse deadline order — and the finish times are 2, 5, 9, 10, 12, 15, latenesses 0, 0, 0, 1, 4, 9, maximum lateness 9 (job A, due at 6, finishing at 15). This order has 14 inversions (every pair is inverted except D, C, whose deadlines tie at 9). The earliest-deadline order A, B, C, D, E, F has finish times 3, 5, 6, 10, 13, 15, latenesses 0, 0, 0, 1, 0, 0, maximum lateness 1, and exhaustive search over all 6! = 720 orders confirms that no order does better. The figure walks from the reverse order to an earliest-deadline order swap by swap — it ends with D before C, because their deadlines tie at 9 and a tie is not an inversion, and that order has the same maximum lateness 1; the measured maximum lateness after each swap never rises above the value before it, exactly as the lemma promises — and it usually falls, which the lemma does not promise.

One swap is worth tracing by hand. In the order A, B, C, E, D, F — the greedy order with one adjacent inversion, E (d = 14) before D (d = 9) — the finish times are 3, 5, 6, 9, 13, 15 and D is late by 13 − 9 = 4, the maximum. Swap the pair: D now finishes at 10 (lateness 1), E finishes at 13 (lateness 0). The job that moved later, E, took over D's old finish time 13 but has the later deadline 14, so its lateness 13 − 14 < 0 is below D's old lateness 4 — that inequality, f − dᵢ < f − dⱼ, is the whole proof.

What the theorem does not say — read the objective

  • It minimises the maximum lateness, not the total. Two words first: scheduling calls the signed quantity fⱼ − dⱼ the lateness and its positive part max(0, fⱼ − dⱼ) the tardiness; this page's Lⱼ is the tardiness, and earliest-deadline minimises the maximum of either. Total signed lateness is trivial — ∑(fⱼ − dⱼ) = ∑fⱼ − ∑dⱼ, minimised by shortest-processing-time-first in O(n log n). Total tardiness is the hard one, and for it earliest-deadline is not optimal: with jobs (t, d) = (1, 9), (3, 5), (5, 3), (3, 2) the deadline order D, C, B, A has total tardiness 1 + 5 + 6 + 3 = 15 and the order D, B, A, C has 1 + 1 + 0 + 9 = 11, the best of all 24 orders (checked by enumeration in the load-time audit). Minimising total tardiness on one machine is NP-hard in the ordinary sense (a pseudo-polynomial DP exists) and the weighted version is strongly NP-hard; the greedy rule's proof works for the maximum because a single swap can only change two latenesses and the new one is dominated by an old one — a max survives that, a sum does not.
  • The rule ignores processing times, which feels wrong and is right: the exchange never mentions tᵢ. Shortest-processing-time-first minimises the sum of completion times, a different objective with its own exchange proof.
  • All deadlines equal: every order is inversion-free, every order is greedy, and all have the same maximum lateness (max(0, the makespan minus the common deadline)). Ties in general are safe for the same reason — the fact 2 argument.
  • Release times (a job cannot start before rⱼ) break the theorem: with release times the problem is NP-hard, and the exchange fails because swapping can create idle time.

09 Coin change: when the largest-coin-first rule is optimal, and when it is not

Make an amount x with the fewest coins from denominations c₁ = 1 < c₂ < … < cₘ, unlimited supply. The greedy rule everyone uses at a till — take the largest coin that fits, repeat — is optimal for the coin systems of most real currencies and wrong for others, and there is no way to tell which from the rule itself. A coin system for which greedy is optimal for every amount is called canonical. "Greedy solves coin change" is false; "greedy solves coin change on a canonical system" is true by definition, and the content is in deciding which systems are canonical.

Why greedy works on {1, 5, 10, 25} — a bounding argument, then an exchange

The proof for a specific system bounds what an optimal solution can contain, then concludes it must be the greedy one. In any optimal solution for {1, 5, 10, 25}: at most four 1s (five 1s would be exchanged for a 5, saving four coins); at most one 5 (two 5s → one 10); and if there is a 5 then at most one 10 (a 5 and two 10s → one 25), while with no 5 at most two 10s (three 10s → a 25 and a 5). So the coins smaller than 25 total at most 4 + 5 + 10 = 19 with a 5 present, or 4 + 20 = 24 without — in every case less than 25. An optimal solution therefore uses at least floor(x / 25) quarters (otherwise the small coins would have to cover 25 or more), and cannot use more; so it uses exactly the greedy number, and the same bounds applied to the remainder x mod 25 force exactly floor((x mod 25)/10) dimes, then the 5, then the 1s. The optimal solution is the greedy one. Run the same argument on {1, 3, 4}: an optimal solution has at most two 1s, but it may have at most three 3s (four 3s → three 4s saves a coin), so the coins below 4 can total 3 · 3 + 2 · 1 = 11 ≥ 4 — the "small coins total less than the largest coin" bound that the {1, 5, 10, 25} argument rested on is exactly what fails, so the "at least floor(x/4) 4s" step has nothing to rest on, and 6 = 3 + 3 is the first amount where it bites.

Deciding canonicity: what is known

  • There is a polynomial-time test. Whether a system of m denominations is canonical can be decided in O(m³) time, by an algorithm that examines a specific polynomial-size family of candidate amounts; the test's existence is the fact to remember, its details are outside this page.
  • Where the smallest counterexample lives. If a system is not canonical, the smallest amount on which greedy fails lies strictly between c₃ + 1 and cₘ₋₁ + cₘ. For {1, 3, 4} that is 5 < x < 7, i.e. x = 6; for {1, 5, 10, 20, 25} it is 11 < x < 45, and the first failure is at 40. This also gives a brute-force test: compare greedy with the DP on every amount below cₘ₋₁ + cₘ.
  • Small cases have closed forms. Every two-coin system {1, c} is canonical. For three coins {1, a, b}, write b = q·a + r with 0 ≤ r < a: the system is canonical if and only if r = 0 or r ≥ a − q, and when it is not, the amount (q + 1)·a is a counterexample — greedy pays one b plus a − r ones, 1 + a − r coins, against q + 1 coins of a. For {1, 3, 4}: q = 1, r = 1, and 1 < 3 − 1, so it is non-canonical at 6. (The load-time audit checks this characterisation against greedy-versus-DP on every {1, a, b} with a < b ≤ 80.)
  • Real currencies. The coin systems in wide use — 1, 2, 5, 10, 20, 50 in cents and their multiples; 1, 5, 10, 25 — are canonical, which is why till-greedy works; it is a design choice, not a law. Systems with a 20 and a 25 are the classic non-canonical shape.
  • Without a 1-coin the problem may have no solution at all: {3, 5} cannot make 7, and greedy on 6 takes a 5 and is then stranded with 1 (the optimum is 3 + 3; it must be allowed to backtrack, or the DP used, to find it); the general question of which amounts are representable is a different problem.

10 Fractional knapsack: greedy by value density, proved by exchange

n items with weights wᵢ > 0 and values vᵢ ≥ 0, a capacity W; take any fraction xᵢ ∈ [0, 1] of each item so that ∑ xᵢ wᵢ ≤ W and ∑ xᵢ vᵢ is maximum. The greedy rule sorts by value density vᵢ / wᵢ, takes whole items in that order while they fit, and then takes the fraction of the next item that fills the remaining capacity exactly. It is optimal, and the exchange proof is short because the "swap" is continuous: move weight from a lower-density item to a higher-density one.

(D untouched) fractional optimum = 240 — 3 items examined, one fraction THEOREM. Hypothesis: items sorted so that v₁/w₁ ≥ v₂/w₂ ≥ … ≥ vₙ/wₙ; greedy's solution is x = (1, …, 1, θ, 0, …, 0) with the fraction θ on item k.any feasible y has ∑ yᵢ vᵢ ≤ ∑ xᵢ vᵢ. proof — the exchange, continuousWLOG y fills the knapsack (if not, adding more of anything with v > 0 helps). Both x and y have total weight W. let i ≤ k be the first item with yᵢ < xᵢ (for i = k this means yₖ < θ; if no such i exists then y = x). Since ∑ wⱼ yⱼ = ∑ wⱼ xⱼ and y has less of item i, y has MORE of some item j > i (an item x takes less of): yⱼ > xⱼ. move weight δ = min( wᵢ(1 − yᵢ), wⱼ(yⱼ − xⱼ) ) from item j to item i: y' has yᵢ' = yᵢ + δ/wᵢ, yⱼ' = yⱼ − δ/wⱼ, same total weight, feasible. value change = δ · (vᵢ/wᵢ) − δ · (vⱼ/wⱼ) ≥ 0 because i < j in density order. repeat: each move makes y agree with x on one more item and never lowers the value. When they agree, value(y) ≤ value(x). ∎

What the proof needs and what it does not

The exchange moves value from a low-density item to a high-density one and the inequality vᵢ/wᵢ ≥ vⱼ/wⱼ is the whole argument — so the proof needs items to be divisible (so that δ can be any amount) and it needs densities to be well defined (weights positive). It does not need integer weights or values, it does not need the items to fit, and it does not care about ties: two items of equal density can be taken in either order and the value is the same. Zero-value items are simply never reached; negative values (a penalty for carrying an item) should be dropped before sorting, since taking any fraction of them can only hurt. The cost is the sort, Θ(n log n), plus a linear scan; a weighted-median selection (the linear-time selection of Recursion, Divide & Conquer, §30) finds the break item k in Θ(n) without sorting at all, which is worth knowing and rarely worth doing.

The fractional problem is also the linear-programming relaxation of the 0/1 problem — relax xᵢ ∈ {0, 1} to xᵢ ∈ [0, 1] — and its optimum is therefore an upper bound on the 0/1 optimum: no integer selection can beat 240 on the instance above. That bound is what makes the greedy 0/1 approximation of §11 provable, and it is the bound a branch-and-bound search for the exact 0/1 answer uses to prune (Recursion, Divide & Conquer, §26). One greedy algorithm, three roles: exact solution of the fractional problem, upper bound for the integer one, pruning rule in the search for it.

11 0/1 knapsack: the same rule fails, the single-item fix gives a 1/2-approximation, and DP takes over

Forbid fractions — each item is taken whole or not at all — and the density rule fails: on the four items of §10 it takes A and B (value 160, capacity 20 left, nothing else fits) while the optimum takes B and C (value 220). Worse, plain density-greedy is not even a constant-factor approximation: one tiny high-density item can crowd out a huge one. The fix is one line — also consider the single most valuable item, and return the better of the two — and that fixed rule is provably within a factor 2 of the optimum. The exact answer needs dynamic programming.

Why the fix works and why it is tight

The unfixed rule's failure is always the same shape: the first item that does not fit is worth a lot, and the greedy prefix's value is small compared with it. The fractional bound says the greedy prefix plus that one item is worth at least the optimum; so whichever of the two is larger is worth at least half. The single most valuable item is at least as good as the item that did not fit, so it can stand in for it. Factor 2 is tight for the fixed rule. Take three items (w, v) = (1, 2), (W/2, W/2), (W/2, W/2) with capacity W: greedy by density takes the first (density 2), then one of the halves, and the other no longer fits (1 + W/2 + W/2 > W), so G = 2 + W/2 and M = W/2, while the optimum takes the two halves for W. The ratio (2 + W/2)/W approaches 1/2 as W grows; the figure's "tight family" instance measures it at W = 40. Better ratios exist — a fully polynomial-time approximation scheme gets within 1 − ε for any ε in time polynomial in n and 1/ε — and one is built at NP-Completeness & Approximation, §25.

Where the exact answer lives

The 0/1 problem keeps optimal substructure — remove any item from an optimal load and the rest is optimal for the reduced capacity — so it has a correct recurrence, OPT(i, c) = max(OPT(i − 1, c), vᵢ + OPT(i − 1, c − wᵢ)), and a table of (n + 1)(W + 1) cells solves it exactly in Θ(nW) time. That is pseudo-polynomial (polynomial in the value of W, exponential in its bit length), which is consistent with the problem being NP-hard, and it is the subject of Dynamic Programming. The point for this page is the contrast: the recurrence compares two subproblems at every item, and the greedy algorithm is the attempt to skip the comparison. When items are divisible the comparison always comes out the same way (density decides) and skipping it is safe; when they are not, it can come out either way, and skipping it is the 160-versus-220 error above.
