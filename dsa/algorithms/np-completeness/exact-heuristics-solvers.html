26 Exact exponential algorithms: branch and bound, DP over subsets

Giving up the polynomial bound is a design decision, not a surrender: an algorithm that is exponential in a small base, or that prunes most of the tree it could build, solves instances that brute force cannot look at — and it returns a provably optimal answer, which no approximation or heuristic on this page does. Three techniques carry almost all of the load. Backtracking walks the tree of partial solutions depth-first and abandons a branch the moment a partial solution is already infeasible. Branch and bound adds a computable lower bound on the cost of completing a partial solution and abandons the branch when that bound already reaches the best complete solution found so far. Dynamic programming over subsets replaces the n! orders of a permutation problem with the 2ⁿ subsets of a set, which is an enormous saving and also the standard illustration of the trade this section is about: Held–Karp turns the travelling salesman's Θ(n!) into Θ(n²·2ⁿ), and is still exponential. Backtracking: depth-first search over partial solutions

A backtracking algorithm needs three components: a way to extend a partial solution by one decision, a test that looks at a partial solution and returns one of three verdicts — failure (no completion exists), success (this is already a solution), or uncertain — and a traversal order. The traversal is a depth-first search of the tree whose root is the empty partial solution and whose leaves are complete ones; the test is what makes it more than brute force, because a failure verdict at a node of depth d removes the entire subtree below it, and for 3-SAT that subtree contains 2^(n − d) assignments. All the intelligence lives in the test and in which decision to branch on next.

That trace is the algorithm behind every SAT solver in production; §30 is the same procedure with twenty-five years of engineering bolted on. Two of its habits generalise immediately. First, propagate before you branch: any decision that is forced costs one step and never costs a factor of two. Second, branch where the constraint is tightest — in the shortest clause, on the most-constrained variable, at the vertex of highest degree — because that is where a failure verdict arrives soonest. The dual habit, branching where you are most confident of success, is the right one for a search that only needs one solution and knows a good heuristic, which is why solvers use both and switch.

Branch and bound: backtracking for optimisation

Backtracking's test is binary: a partial solution either can or cannot be completed. For an optimisation problem the corresponding question is quantitative — what is the cheapest completion? — and its exact answer is as hard as the original problem. So we replace it by a quantity that is cheap to compute and provably no larger: a lower bound on the cost of any completion. If cost(partial) + lowerbound(partial) ≥ the best complete solution already found, then no completion of this partial solution can beat the incumbent, and the whole subtree can go. Nothing else about the algorithm changes.

BRANCH-AND-BOUND, for a minimisation problemS ← {P₀}; best ← +∞; bestsol ← none while S ≠ ∅: choose P ∈ S and remove it expand P into subproblems P₁ … P_k for each Pᵢ: if Pᵢ is COMPLETE: if cost(Pᵢ) < best: best ← cost(Pᵢ); bestsol ← Pᵢ else if cost(Pᵢ) + lowerbound(Pᵢ) < best: add Pᵢ to S else: DISCARD ← the pruning return bestsol three knobs, and each one is worth more than the others in a different regime: the BOUND — tighter prunes more but costs more per node; the product is what matters the ORDER — depth-first keeps memory O(depth); best-first expands fewest nodes but stores them all the INCUMBENT — start from a good heuristic solution (§22's Christofides, §28's 2-opt) and the pruning bites from the first node instead of after the first leaf the CORRECTNESS condition — the only thing that must be proved lowerbound(P) ≤ cost of EVERY completion of P for every partial solution P That single inequality is what makes the discard safe. It is NOT a statement about the bound being good, or tight, or fast. A bound that violates it on even ONE partial solution can discard the branch containing the optimum — and the search then returns a suboptimal answer with no indication at all that anything went wrong. There is no run-time symptom. The output is simply wrong.

A lower bound for the travelling salesman, derived by counting edges

Fix the start city 0. A partial solution is a simple path 0 ⇝ cur that has visited a set of cities; write rem for the ones it has not. Its completion is a path cur → v₁ → … → v_k → 0 through exactly the cities of rem. The derivation is pure counting: that path uses exactly |rem| + 1 edges — one leaving cur, and one leaving each v ∈ rem (the last of them being the edge into 0). Bound each of those edges below by the cheapest edge that its tail vertex has available, and the sum is a lower bound.

the bound, and the edge count it rests onthe completion leaves cur exactly once, into rem: cost ≥ min { d(cur, u) : u ∈ rem } ≥ min { d(cur, u) : u ∈ rem ∪ {0} } the completion leaves each v ∈ rem exactly once, into another remaining city or into 0: cost ≥ min { d(v, u) : u ∈ (rem ∪ {0}) ∖ {v} } LB(cur, rem) = min_{u ∈ rem ∪ {0}} d(cur, u) + ∑_{v ∈ rem} min_{u ∈ (rem ∪ {0}) ∖ {v}} d(v, u) └────── 1 edge ──────┘ └──────────── |rem| edges ────────────┘ = |rem| + 1 ✓ each term is ≤ the edge the true completion actually uses at that vertex, and the terms are indexed by DISTINCT tail vertices, so no edge is double counted: LB ≤ cost(any completion). ∎ the first term takes its minimum over rem ∪ {0}, not rem, so that the same formula covers the last step (rem = ∅, where the only edge left is cur → 0); this is the bound the figure's code evaluates, and every count below comes from it. Dynamic programming over subsets: Held–Karp

Branch and bound attacks the constant in front of the exponential. Dynamic programming over subsets attacks the exponential itself, by noticing that a partial tour's future depends on the set of cities already visited and on the current endpoint, but not on the order in which the set was visited. That collapses (n−1)! partial paths into (n−1)·2ⁿ⁻¹ states, and is the oldest non-trivial exact exponential algorithm there is (Bellman 1962; Held and Karp 1962).

Two more patterns, briefly, because they come up

  • Inclusion–exclusion. Counting Hamiltonian cycles, or deciding whether one exists, can be done in O*(2ⁿ) time and polynomial space. Fix a vertex v and let w(S) be the number of closed walks of length n from v to v that use only vertices outside S. Then ∑_{S ⊆ V} (−1)^|S| · w(S) counts exactly the closed walks that use every vertex — the Hamiltonian cycles, each counted a fixed number of times — because a walk missing a vertex u is counted once with each sign as S ranges over the subsets that do and do not contain u, and cancels. Each w(S) is an entry of an n-th matrix power, computable in polynomial time and polynomial space, so the algorithm stores nothing exponential — it only iterates over 2ⁿ subsets. That is the point of the technique: it trades Held–Karp's Θ(n·2ⁿ) memory for the same order of time, and memory is the binding constraint. The same idea counts proper colourings, set covers and perfect matchings.
  • Measure and conquer. Branching algorithms are analysed by a recurrence on a measure of instance size — and choosing a cleverer measure than "number of vertices" proves a better bound for the same algorithm. If a branching rule removes a vertex of degree d in one branch and d + 1 vertices in the other, the naive measure gives T(n) ≤ T(n−1) + T(n−d−1); weighting vertices by degree so that high-degree vertices count for more makes each branch reduce the measure by more, and the same code gets a smaller base. The technique's headline result is maximum independent set: a simple branching algorithm whose standard analysis — measure = number of vertices — gives O(1.3247ⁿ) was shown, by measure and conquer and without any change to the algorithm, to run in O(2^(0.288n)) ⊆ O(1.2210ⁿ) (for scale, 3^(n/3) ≈ 1.4423ⁿ is the number of maximal independent sets a graph can have, so it is the cost of enumerating them all); subsequent work combining better branching rules with the same style of analysis has brought the exponent below 1.2ⁿ. It is the clearest example in the field of a bound being a property of a proof rather than of a program — and the corresponding warning is that a published exponent tells you what someone has managed to prove, not what the code does.
  • Knapsack, with the fractional relaxation as the bound. Knapsack is a maximisation, so the roles flip and what the search needs at each node is an upper bound on the best completion; the natural one is the fractional knapsack's optimum on the remaining items, computed greedily by value density in O(n log n) once and O(n) per node (Greedy Algorithms). This is exactly the linear-programming relaxation of §30, and it is the reason knapsack instances with hundreds of thousands of items are solved exactly. Measured on the five-item instance of §25: the root fractional bound is 92.6667 against a true optimum of 85; the search visits 26 nodes and prunes 3 subtrees, against 2⁵ = 32 subsets for brute force — a modest saving at n = 5, and the same code at n = 60 is the difference between a second and a millennium.

Where this leaves you

  • Exact exponential search is the response of choice when n is genuinely small, when optimality is contractual, or when you need a certificate. It is the only one of §19's responses that produces a proof that the answer is optimal: the pruning argument, run to completion, certifies that no unexplored branch can do better. An approximation algorithm gives a ratio; a heuristic gives nothing; branch and bound gives the answer and the proof.
  • It composes with everything else on the page. Warm-start the incumbent from §22's Christofides tour or §28's 2-opt tour and the pruning bites immediately; use §27's kernelisation to shrink the instance before the search starts; use §30's LP relaxation as the bound. A production solver is all of these at once.
  • The bound is the algorithm. Everything else — the traversal order, the data structures, the incumbent — moves the running time by constant factors. The bound moves it by orders of magnitude, and it is also the only component that can make the answer wrong. Spend the effort there, and test it there.
  • Do not confuse "exponential" with "impossible". §19's framing is the right one: the hardness proof forbids a polynomial worst case, not a fast algorithm on your instances. §30's SAT and integer-programming solvers are exact exponential algorithms with enormous engineering inside the constant, and they solve instances that dwarf anything in this section.

27 Parameterised complexity: FPT, kernels, bounded search trees

Parameterised complexity refuses to measure an instance by a single number. It measures it by two — the size n and a parameter k that captures whatever is small in practice — and asks for a running time of the shape f(k)·poly(n), where f may be as monstrous as it likes but the dependence on n is polynomial with an exponent that does not involve k. A problem with such an algorithm is fixed-parameter tractable, FPT. The distinction this draws is not cosmetic: vertex cover is FPT with parameter "size of the cover", solvable in O(1.2738ᵏ + k·n) time, which is linear in n for every fixed k; clique with parameter "size of the clique" is not believed to be FPT — it is W[1]-hard, and the best known algorithms are n^O(k), where the parameter sits in the exponent of n. Both problems are NP-complete, both are mutually reducible in polynomial time (§11, §12), and they behave completely differently once a parameter is fixed. That is the whole subject: NP-completeness is a single equivalence class; parameterised complexity is a finer instrument applied inside it.

The two shapes, and the difference between them

FPT against XP — the placement of k decides everything FPT time f(k) · n^c c a CONSTANT independent of k e.g. 2ᵏ·n, 1.2738ᵏ + k·n, 2^(2^k)·n XP time n^f(k) the parameter is in the EXPONENT e.g. n^k, n^(k/2), n^(O(k)) at k = 10, n = 10⁶: 2ᵏ·n = 1.02 × 10⁹ finishes n^k = 10⁶⁰ does not, and never will at k = 30, n = 10⁶: 2ᵏ·n = 1.07 × 10¹⁵ a large cluster job n^k = 10¹⁸⁰ beyond the number of atoms in the universe FPT ⊆ XP, and the inclusion is PROVED STRICT — unlike almost every other separation on this page. Note where the reductions of §10–§15 fail here. The polynomial-time reduction from clique to vertex cover is a one-line complementation: a graph G has a clique of size k if and only if its complement has a vertex cover of size n − k (§12). That is a perfectly good polynomial-time reduction, and it is useless as an FPT reduction, because it sends the parameter k to n − k, which is not bounded by any function of k. This is exactly why parameterised complexity needs its own reductions and its own catalogue: the standard Karp reductions do not preserve parameters. A hardness proof that transfers in one theory need not transfer in the other, and §33 lists the temptation to reuse it as a pitfall.

The bounded search tree: vertex cover in O(2ᵏ·E)

The algorithm is three lines and rests on one observation. Take any edge (u, v) that the current partial cover does not cover. Every vertex cover must contain u or v — that is what "cover" means. So branch on those two possibilities, and each branch spends one unit of the budget k. The recursion depth is at most k, the branching factor is 2, and each node does O(E) work to find an uncovered edge.

Kernelisation: shrink the instance until only the hard core is left

The second FPT technique is more surprising than the first, and it is the one with practical consequences. A kernelisation is a polynomial-time preprocessing that maps an instance (I, k) to an equivalent instance (I′, k′) with k′ ≤ k and |I′| ≤ g(k) for some function g of the parameter alone. The size of the reduced instance does not depend on n at all. A ten-million-vertex graph with a cover of size 40 is reduced, in linear time, to a graph of at most a few thousand edges, and whatever exponential algorithm you like then runs on that. It is a theorem that a decidable problem is FPT if and only if it has a kernel, so kernelisation is not one technique among several — it is an equivalent characterisation.

Where it sits among the other responses

  • Against approximation (§20–§25). FPT keeps exactness and pays in generality; approximation keeps generality and pays in exactness. They are not rivals, and they even combine: a parameterised approximation algorithm relaxes both, and for some problems that are both W[1]-hard and hard to approximate, relaxing both is the only thing that works.
  • Against exact exponential search (§26). The bounded search tree is a branch-and-bound search — its "bound" is the budget k — so the two sections describe one family of algorithms from two directions. The difference is what the exponent is measured against: §26 counts 2ⁿ in the input size, §27 counts 2ᵏ in the parameter, and kernelisation is the step that makes the second honest by removing n from the exponential term entirely.
  • Against special cases (§16). A structural restriction — planar, bipartite, interval, chordal — is the extreme case of a parameter: the parameter is zero. Bounded treewidth is the graded version, and the reason it is the single most productive parameter in the literature is that "small treewidth" holds approximately for a great many real graphs while "is a tree" holds for almost none.
  • Where it touches the rest of these notes. The tree-decomposition dynamic programme is the same table-filling discipline as Dynamic Programming's tree DP, with the bag of a decomposition node in place of a vertex's children; the k-path algorithm's colour coding is a randomised technique — like §24's coin flip — but it is derandomised differently: not by conditional expectations but by a k-perfect family of hash functions, an explicit, small set of colourings under at least one of which every k-subset of vertices gets k distinct colours; and the half-integrality that gives vertex cover its 2k kernel is the LP relaxation §30 uses as a branch-and-bound bound.

28 Local search, 2-opt and simulated annealing

Local search abandons the guarantee altogether: start from any solution, define a neighbourhood of small modifications, and keep moving to a neighbour that is better until none is. What it returns is a local optimum — a solution superior to everything within one move — and there is in general no theorem relating that to the global optimum at all. The design decision that matters is the neighbourhood, and it is a trade with two sides: a larger neighbourhood has fewer bad local optima and costs more to search, a smaller one is cheap per step and gets stuck more often. Local search has no place in a taxonomy of guarantees, and it is nevertheless the top performer on a broad range of optimisation problems, routinely landing within one or two per cent of optimal on travelling-salesman instances with millions of cities. This section defines the mechanism precisely, measures it, and is careful to distinguish what was observed on one instance from what is proved — because for local search those two sets barely overlap.

Escaping local optima: randomisation, restarts, annealing

Three devices, in increasing order of sophistication and of the effort needed to tune them.

  • Randomise the start, and restart. If a single run reaches a good local optimum with probability p, then O(1/p) independent runs find one with high probability; with r restarts the failure probability is (1 − p)^r. Measured above: p ≈ 0.585 on this instance, so three restarts fail with probability about 0.07 and five with about 0.012. Restarts are embarrassingly parallel, need no tuning, and are the first thing to try. They stop working when p itself shrinks exponentially with instance size, which is the usual situation on large instances.
  • Randomise the move. When several improving moves are available, pick among them at random rather than by a fixed rule. This alone changes which basin the trajectory falls into and turns a deterministic algorithm with one outcome into a distribution over outcomes, which restarts can then exploit.
  • Accept worsening moves: simulated annealing. Instead of only descending, propose a random neighbour and accept it even if it is worse, with a probability that falls as the damage rises and as the search proceeds.

Local search for satisfiability: GSAT and WalkSAT

The same machinery applies verbatim to SAT, with a different neighbourhood. A solution is a complete truth assignment; the neighbourhood is "flip one variable" (so |N| = n); the objective is the number of unsatisfied clauses, to be driven to zero. GSAT flips the variable that reduces the unsatisfied count the most. WalkSAT improves on it with a targeted random walk: pick a currently violated clause, and flip one of its three variables — with probability p a random one, otherwise the one that breaks fewest other clauses. Restricting attention to a violated clause is the key idea: flipping a variable outside every violated clause cannot help, so the neighbourhood is pruned to the moves that could possibly matter.

  • These solvers are incomplete. They find satisfying assignments; they never prove unsatisfiability. Running WalkSAT for a million flips and failing tells you nothing — the formula may be satisfiable and unlucky. A complete solver (§30's DPLL/CDCL) can answer both ways. This is the sharpest instance on the page of "what guarantee does this algorithm carry?", and the answer for a local-search SAT solver is: a yes-answer is certified by the assignment it returns; a no-answer is not an answer at all.
  • They win on the instances CDCL loses. Randomly generated satisfiable instances near the §30 threshold, and large structured instances with many solutions, often fall to WalkSAT in seconds where a systematic search flounders; industrial instances with deep implication structure go the other way. Portfolio solvers run both.
  • The connection to §24. A uniformly random assignment already satisfies 7m/8 clauses of a 3-CNF in expectation. WalkSAT starts from exactly that and walks. So the local search begins with a proved 7/8-approximation for MAX-3-SAT and discards the guarantee the moment it takes its first flip.

What carries over, and to where

  • The continuous cousin. Gradient descent is local search with an infinitesimal neighbourhood and a derivative to pick the direction; local minima, plateaux (saddle points and flat regions), restarts (random initialisation), and annealing (noise injection, learning-rate schedules) all have exact counterparts. Optimization develops the continuous theory, including the convexity condition under which every local minimum is global — which is precisely the condition that makes local search exact and which combinatorial problems almost never satisfy.
  • When local search is exact. It sometimes is, and the cases are worth knowing because they mark the boundary. The simplex method is local search over the vertices of a polytope with the edge neighbourhood, and it is exact because the feasible region is convex. Local search on spanning trees with the single-edge-swap neighbourhood is exact, and the reason is the matroid exchange property that Greedy Algorithms proves. Where an exchange argument exists, local search is an algorithm with a theorem; where it does not, local search is a heuristic. §22's discussion of greedy rules that look like approximation algorithms is the same distinction.
  • Graph partitioning, the other standard example. Split V into two halves minimising the weight crossing the cut; the neighbourhood is "swap a pair, one from each side", of size Θ(n²), which keeps the halves balanced. This is minimum bisection, which is NP-hard — although minimum cut without the balance constraint is in P by max-flow (Shortest Paths, MST & Flow), so the balance requirement is exactly the kind of one-constraint change that crosses §16's boundary — and the Kernighan–Lin heuristic — a variable-depth local search over exactly this neighbourhood — is still the workhorse in circuit layout and sparse-matrix ordering.
  • Measure, do not assume. The single most useful property of local search is that its quality is measurable on your own instances: run it against an exact solver on small cases, against a bound (the MST bound for TSP, the LP relaxation for an ILP) on large ones, and you obtain an empirical gap that is worth more than a worst-case ratio you will never meet. What you must not do is publish that gap as a guarantee. §33.

29 Population heuristics: genetic algorithms

A genetic algorithm keeps a population of candidate solutions rather than one, scores each by a fitness function, and produces the next population by selecting fitter candidates, recombining pairs of them, and perturbing the results at random. It carries no guarantee of any kind — not optimality, not an approximation ratio, not a bound on running time, not even a proof that it converges — and it is the last thing on this page one should reach for. It earns a section because it earns its keep in one specific situation, which is common enough to matter: when the objective can be evaluated but not analysed — a simulation, a physical measurement, a trained model's score — so that no gradient, no relaxation, no lower bound and no exchange argument is available, and the only thing the algorithm is allowed to do is ask "how good is this one?". In that setting the competition is not Christofides or branch and bound; it is random search, and a population method beats random search. Everywhere else, the sections above are better, and §32 routes accordingly.

Selection: four rules, and what each one is for

  • Roulette-wheel (fitness-proportional) selection. Give each chromosome a slice of a wheel proportional to its fitness and spin once per parent: P(i) = fᵢ / ∑ⱼ fⱼ. Simple, and awkward in three ways. It needs non-negative fitness, so a minimisation objective such as tour length has to be transformed — f = C − cost or f = 1/cost — and the choice of transformation silently changes the selection pressure. It is dominated by outliers early on, when one lucky chromosome can take a large share of the wheel and flood the population. And it stops discriminating late on, when all fitnesses are nearly equal and the wheel is nearly uniform. Fitness scaling patches these, and adds parameters.
  • Rank selection. Sort the population and assign selection probabilities by rank rather than by raw fitness. Immune to the scale of the objective and to outliers, and it keeps a usable pressure when the fitnesses have converged. The cost is a sort per generation and the loss of the information in the fitness gaps.
  • Tournament selection. Draw t chromosomes uniformly at random and take the best. The selection pressure is set by t alone — t = 1 is no pressure at all, t = 2 is mild, t = 5 is strong — it needs no sorting, no scaling and no non-negativity, and it works unchanged on a minimisation objective. This is the practical default and the one the figure uses.
  • Elitism. Copy the best e chromosomes into the next generation unchanged. Not a selection rule but a replacement rule, and it removes a real failure mode: without it, the best solution found so far can be destroyed by crossover or mutation and never recovered. With it, the best fitness is monotone non-increasing across generations — the only monotonicity a GA has, and it is there by construction rather than by any property of the search.
  • Stochastic universal sampling. Roulette with N equally spaced pointers on one spin instead of N independent spins: the same expected counts with far less variance, so a chromosome with expected share 2.4 is selected 2 or 3 times rather than possibly 0 or 6 times. A cheap variance reduction on top of proportional selection.

Generational or steady-state, and the schema story

Generational replacement builds an entire new population and discards the old one (with elitism as the escape hatch). Steady-state replacement produces one or two children per step and inserts them by displacing the worst members, so the population changes continuously; it converges faster and loses diversity faster. The choice is another tuning parameter with no theory.

The traditional explanation of why any of this works is the schema theorem and its corollary, the building-block hypothesis. A schema is a pattern over the alphabet extended with a wildcard — 1**0* matches every chromosome with a 1 first and a 0 fourth — and the theorem gives a lower bound on the expected number of copies of a schema in the next generation: short, low-order schemata whose average fitness exceeds the population average receive exponentially increasing trials, provided crossover and mutation do not disrupt them too often. The building-block hypothesis then asserts that a GA works by assembling such short, low-order, above-average "building blocks" into better and better solutions.

Read that as intuition, not as a theorem about performance. The schema theorem is a correct statement about expected counts over one generation of a specific selection scheme; it does not say that the GA finds good solutions, and it cannot, because it says nothing about the generations after the first. The building-block hypothesis is a hypothesis, and the literature contains explicit counterexamples: schemata whose average fitness is high because of a few outstanding members that the GA will never see, and schemata whose average is dragged below the population average by a few poor members although they contain the optimum. Competing explanations of the same empirical successes exist and fit the evidence about as well — that crossover acts as a macromutation operator (replace a contiguous block by a random one), under which a population is not needed at all and a "macromutational hill-climber" matches the GA on problems without clean building blocks; and that crossover is an adaptive mutation whose step size shrinks automatically as the population converges. The honest position is that genetic algorithms are an empirical technique with a suggestive biological metaphor and no performance theory, and this page will not pretend otherwise.

When to use one, and when not

  • Use one when the objective is a black box. If fitness comes from a simulation, a physical experiment, a rendering, or the validation score of a trained model, then there is no gradient, no relaxation to bound with, no exchange argument and no structure to exploit — the only permitted operation is evaluation. Everything else on this page needs structure; a population method needs only a fitness function and an encoding. This is also the honest description of most reported GA successes.
  • Use one when the search space is a strange object. Mixed discrete/continuous parameters, variable-length structures, programs, network topologies, designs. Writing a neighbourhood for local search is often as much work as writing crossover and mutation, and if the space is that irregular, neither has a theory, so take the one that is easier to implement correctly.
  • Do not use one when a guarantee is available. If the problem is vertex cover, take the 2-approximation (§21) — it is three lines and it is a theorem. If it is metric TSP, take Christofides (§22). If it is knapsack with a stated accuracy, take the FPTAS (§25). If n is small or a parameter is small, take §26 or §27 and get the exact answer. A GA that lands near a solution you could have proved near is strictly worse than the proof.
  • Do not use one as a first resort on a problem with an obvious local move. Restarted local search (§28) is simpler, has fewer parameters, is easier to instrument, parallelises trivially, and on combinatorial problems with a natural neighbourhood it is usually at least as good. The measurement above is one data point in that direction and the literature has many more. If a GA is chosen over local search, the comparison should have been run.
  • Beware the comparison that was never made. A GA is almost always reported against random search or against no baseline at all. The baselines that matter are: a good constructive heuristic, local search from that heuristic, local search with restarts, and — if the instance is small enough — an exact solver, so the gap is a measured gap rather than a relative one. §33.
  • Where this touches the rest of these notes. Evolutionary and population search appears in machine learning as one of the black-box strategies for hyperparameter tuning, alongside random search and Bayesian optimisation, and the case for it there is exactly the case made above: the validation score is a black box. Its continuous relatives — evolution strategies, CMA-ES, and the finite-difference gradient estimators — are derivative-free optimisation, next to the gradient methods of Optimization; the trade is the same one, an exact gradient where one exists against a sampled estimate where none does.

30 SAT solvers, ILP, and the phase transition

NP-complete problems are solved to optimality, routinely, at industrial scale — satisfiability instances with millions of variables, integer programmes with hundreds of thousands of binary variables — and nothing in §07 is violated, because NP-completeness is a statement about the worst case over all instances and the instances people actually have are not the worst case. Two technologies do most of this work: conflict-driven clause-learning SAT solvers, which are §26's backtracking search with four decades of engineering around the conflict; and integer-programming solvers, which are §26's branch and bound with the linear-programming relaxation as the bound and cutting planes to tighten it. The third thing this section owes the reader is an explanation of why random instances are usually easy: the satisfiable fraction of random 3-CNF formulas falls sharply as the clause/variable ratio crosses a threshold, and instances are hard only in a narrow band around the crossing. From DPLL to CDCL: what each mechanism buys

The search of §26 — assign a variable, simplify, recurse, backtrack on an empty clause — is the Davis–Putnam–Logemann–Loveland procedure, DPLL, and on its own it is a competent exponential search. A modern solver is DPLL plus five mechanisms, each of which addresses a specific waste.

  • Unit propagation (Boolean constraint propagation). When simplification leaves a clause with a single unassigned literal, that literal is forced: assign it and simplify again, to a fixed point. This costs one step and saves a branching factor of two per forced variable, and in practice 90% or more of all assignments in a solver run are propagated rather than decided. The implementation trick that makes it fast is two watched literals per clause: a clause can only become unit when one of its two watched literals is falsified, so an assignment only has to visit the clauses watching it, and — crucially — nothing has to be undone on backtrack.
  • Conflict analysis and clause learning. When a clause becomes empty, plain DPLL flips the last decision and forgets what happened. A CDCL solver instead walks the implication graph back from the conflict to a cut (the first unique implication point) and derives a new clause that is logically entailed by the formula and that excludes the assignment pattern that caused this conflict. That clause is added to the formula permanently. The effect is that the same conflict cannot recur anywhere else in the tree: the solver converts one dead end into a constraint that prunes the whole remaining search. This is the single mechanism that separates modern solvers from 1990s ones.
  • Non-chronological backtracking (backjumping). The learned clause says which decision levels were actually responsible for the conflict. If the culprits are levels 3 and 17, the solver jumps straight back to level 3 rather than undoing level 40, level 39, and so on. Whole regions of the tree are skipped without ever being visited — which is why a CDCL solver's trace is not a depth-first traversal of anything.
  • Activity-based branching (VSIDS). Every variable carries an activity score; variables appearing in recently learned clauses get bumped, all scores decay geometrically, and the solver branches on the highest score. The effect is that branching follows the part of the formula where conflicts are currently happening, so the search concentrates on the region that is actually constrained. It is a cheap, self-tuning heuristic with no theory behind it and an enormous measured effect.
  • Restarts. Periodically abandon the current assignment trail and start again from the top — keeping every learned clause. Search-cost distributions for these solvers are heavy-tailed: a run has a substantial chance of dropping into a region that costs orders of magnitude more than typical, and restarting cuts that tail off while the learned clauses ensure that nothing is really lost. Modern schedules (Luby, or glue-based) restart very frequently.
  • Preprocessing and inprocessing. Before and during the search: eliminate variables by resolution, subsume clauses that imply others, strengthen clauses by self-subsuming resolution, detect equivalent literals. These are §27's kernelisation applied to formulas, and they routinely cut industrial instances by large factors before any search happens.

The phase transition: why random instances are usually easy

Generate a random 3-CNF formula by drawing m clauses independently, each on three distinct variables with independent uniform signs, and ask how the probability of satisfiability depends on the ratio α = m/n. With few clauses almost every formula is satisfiable and almost any assignment works; with many clauses almost none is, and a solver proves unsatisfiability quickly because contradictions appear near the top of the tree. Between those regimes the satisfiable fraction falls, and the instances that sit in the fall are the hard ones: the formula is almost satisfiable, so the search must look everywhere before concluding anything.

Why industrial instances are not random instances

The phase transition explains why random formulas are easy away from the threshold; it does not explain why industrial formulas with millions of variables are easy, because those sit nowhere near the random model. The observed explanation is structure: real formulas have highly non-uniform variable degrees, a community structure that partitions them into loosely coupled clusters, and a small "backdoor" set of variables whose assignment makes the rest collapse under unit propagation. Clause learning exploits all three — it discovers the couplings between clusters and records them, and once the backdoor variables are set the remaining formula falls over. Random formulas at the threshold have none of this structure, which is why a few hundred random variables at α ≈ 4.27 can defeat a solver that dispatches a hardware verification instance with ten million.

  • The practical consequence is a workflow. Model the problem as SAT, MaxSAT, SMT or ILP and hand it to a solver; do not write a bespoke search unless the solver has been tried and has failed. The encoding matters far more than anything else — a good encoding of cardinality constraints, or of an all-different constraint, can change the running time by orders of magnitude — and encoding skill is the real expertise in this area.
  • Know which tool answers which question. SAT answers satisfiability. MaxSAT optimises the number of satisfied (soft) clauses and is the direct home of §24's problem. SMT adds theories — arithmetic, arrays, bit-vectors — so you need not encode integers into bits by hand. ILP optimises a linear objective over linear constraints. Constraint programming offers rich global constraints with specialised propagators. They overlap heavily and their relative performance is problem-specific.
  • The guarantee, stated precisely. A complete SAT solver that returns SAT hands you an assignment — a certificate anyone can check in linear time (§05). A complete solver that returns UNSAT can, if asked, emit a resolution proof, which is a certificate of the co-NP fact (§17) and can be enormous. An ILP solver returns an incumbent and a bound, so its answer is always accompanied by a proved optimality gap. Local-search solvers (§28's WalkSAT) return only the first kind and never the second.
  • None of this weakens §07. Every one of these solvers has a worst case that is exponential, and adversarial instances of very modest size — pigeonhole formulas, random parity constraints, crafted combinatorial benchmarks — defeat all of them. The theorem says such instances exist; the engineering says yours probably are not among them; and the only way to find out which is true for your problem is to run it.
