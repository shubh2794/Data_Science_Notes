02 Problems, encodings and the size of an input

A concrete problem is a set of binary strings — the encodings of its yes-instances — and "polynomial time" means polynomial in the number of bits of that string, never in the numeric value of anything written on it. That single sentence carries more weight on this page than any other, because it is what makes O(nW) knapsack not a polynomial algorithm, what makes trial-division primality an exponential one, and what makes the whole theory encoding-independent in the first place — provided the encodings you allow are reasonable. Get it wrong and half the catalogue collapses: subset sum looks polynomial, partition looks polynomial, and NP-completeness looks like a mistake. Get it right and the theory has a stable foundation on which every later claim can be stated exactly.

the three-step formalisationABSTRACT PROBLEM a relation between a set I of instances and a set S of solutions e.g. SHORTEST-PATH relates ⟨G, u, v⟩ to a lightest u ⇝ v path DECISION PROBLEM an abstract problem whose solution set is {0, 1}: a function Q : I → {0, 1} e.g. PATH(⟨G, u, v, k⟩) = 1 iff some u ⇝ v path uses at most k edges ENCODING a map e : I → {0,1}* turning each instance into a bit string CONCRETE PROBLEM the induced set of strings. An accepter must output 1 on every x ∈ L (and may run forever on x ∉ L); a decider must halt on every input with the right answer. For polynomial time the two coincide — simulate the accepter for its own c·nᵏ step bound and output 0 if it has not accepted by then.

Why the encoding is not a technicality

Take an algorithm whose only input is a positive integer k and whose running time is Θ(k) — a loop that counts down. Written in unary, k is a string of k ones, so the input length is n = k and the algorithm runs in Θ(n): linear, polynomial, tractable. Written in binary, k is n = ⌊log₂ k⌋ + 1 bits, so the same loop runs in Θ(k) = Θ(2ⁿ): exponential. Nothing about the algorithm changed. The problem changed, because the problem is a set of strings and the strings are different. Unary is a pathological encoding precisely because it is exponentially longer than it needs to be: it buys the algorithm a budget proportional to the value it is reading, which is the whole of its apparent efficiency.

Rule out that pathology and the definition becomes stable. Two encodings e₁, e₂ of the same instance set are polynomially related when polynomial-time computable functions translate each into the other. The lemma is then one paragraph: if e₁(Q) ∈ P and |e₁(i)| is computable from e₂(i) in time O(nᶜ), then on input e₂(i) convert (cost O(nᶜ), so the converted string has length O(nᶜ) — an algorithm cannot write more than it has time for) and run the O(mᵏ) decider on it, for a total of O(nᶜ) + O(nᶜᵏ) = O(nᶜᵏ). Polynomially related encodings therefore agree about membership in P. Base 2, base 3, base 10, ASCII decimal, an adjacency matrix against an adjacency list, a list of edges against a list of neighbours — all polynomially related, all interchangeable for this purpose. Unary against binary is not, and that is the only common encoding that is not.

Pseudo-polynomial, stated exactly

An algorithm is pseudo-polynomial when its running time is polynomial in the input size and in the largest numeric value appearing in the input — equivalently, when it would be polynomial if the numbers were written in unary. The knapsack table of Dynamic Programming, §11 has (n + 1)(W + 1) entries, of which the n(W + 1) outside the initial row are each computed in constant time. On this page's five-item instance of §25, with n = 5 and W = 15, that is 6 × 16 = 96 entries and 80 computed cells — the same 96 / 80 split that §25's value-indexed table shows at ε = 1, where the scaled values also total 15 — and W = 15 occupies four bits. Double the capacity to W = 31: the input grows by one bit, and the table doubles to 6 × 32 = 192 entries, 160 of them computed. At W = 1023, ten bits, it is 6 144 entries and 5 120 computed cells. The work is proportional to 2^(bits of W), which is the definition of exponential in the input size. The algorithm is genuinely useful — when W is small it is the best thing available, and §25 turns it into an approximation scheme by making the numbers small on purpose — but it is not a polynomial-time algorithm and its existence does not put knapsack in P.

The contrast that makes the notion precise is strong NP-hardness (§14): a problem is strongly NP-hard when it remains NP-hard even if all the numbers in the instance are bounded by a polynomial in the instance size — that is, even under unary encoding. Subset sum, partition and knapsack are not strongly NP-hard, which is exactly why they have pseudo-polynomial algorithms and why knapsack has a fully polynomial-time approximation scheme (§25). The travelling salesman with arbitrary distances, graph colouring, 3-SAT and clique are strongly NP-hard: their difficulty has nothing to do with the magnitude of any number, so no pseudo-polynomial algorithm can exist for them unless P = NP — and, for an optimisation problem whose optimum is bounded by a polynomial in the instance size and the largest number in it, no FPTAS either, since an FPTAS run with ε small enough would be exactly such an algorithm (§20).

Where "the size of the input" bites in graph problems

A graph on n vertices and m edges has input size Θ(n²) if you hand it over as an adjacency matrix and Θ(n + m) — up to a log n per identifier — if you hand it over as adjacency lists, as Graph Representations & Traversal, §08 tabulates. For dense graphs the two agree to within a constant. For sparse ones they differ by a factor of n, and an algorithm that is linear in one may be sub-linear in the other: reading a graph out of a matrix takes Θ(n²) whatever m is, which is why the dense/sparse distinction of that page matters even here. None of this changes membership in P — the representations are polynomially related — but it changes what the word "linear" refers to, and a claimed "linear-time" algorithm should always be read with its representation attached. The same caution applies to the weighted problems of Shortest Paths, MST & Flow: Dijkstra's O((n + m) log n) is polynomial in n + m and says nothing about the magnitude of the weights, while Dial's bucket queue on that page's §11 is O(m + n·C) for integer weights bounded by C — a pseudo-polynomial bound of exactly the knapsack shape, fast when C is small and exponential in the bits of C.

Unary against binary: the length of the input, and the measured cost of a loop that is linear in the value both axes are logarithmic; the slider picks a value k and the readout reports the measured step counts. The loop's cost tracks the unary length exactly and the binary length exponentially — that gap is the whole content of "polynomial in the size of the input"

Decision problems as languages, and why that is convenient

Once a decision problem is a set of strings, the whole vocabulary of formal languages is available for free and costs nothing. An alphabet Σ is a finite symbol set; a language over Σ is any subset of Σ*; complement, union, intersection, concatenation and Kleene star are set operations; and a complexity class is a set of languages singled out by a resource bound on a machine that decides them. P is one such set. NP (§05) is another. co-NP (§17) is the set of complements of NP languages, and the fact that P is closed under complement while NP is not known to be is a statement that only makes sense once problems are languages. The framework also makes the convention about malformed inputs harmless: some bit strings encode no instance at all, and by fiat they are mapped to 0, so L is a perfectly well-defined subset of {0,1}* and a decider is required to reject the garbage as well as the no-instances.

The one place this abstraction must be handled carefully is in reading an algorithm's time bound. Θ(n²) for an algorithm on a graph normally means n = |V|, not n = the length of the encoding; O(nW) for knapsack means n = the number of items; O(2ⁿ) for SAT means n = the number of variables. These are all legitimate and all standard, and none of them is the bit length. Translating into bit length is a step you must do explicitly, and it is exactly where the pseudo-polynomial algorithms reveal themselves: n items and a capacity of W take Θ(n log W) bits, so O(nW) is O(n·2^(bits of W)). For graph problems the translation is benign — n vertices take at least n bits to name, so anything polynomial in n + m is polynomial in the bit length and conversely — which is why the graph chapters of this series can be sloppy about it and this page cannot.

The rule to carry forward. Whenever a running time mentions a number from the input rather than a count of items in the input — W, T, C, N, the largest weight, the target sum, the maximum value — the bound is pseudo-polynomial until proved otherwise, and to check it you write that number in binary and ask what the time is as a function of its bit length. Whenever a running time mentions only counts — n items, m edges, L literals, k sets — a polynomial in those counts is a polynomial in the input size, because the input must at minimum name each of them. §14 returns to this with subset sum's table drawn twice, once against T and once against log T, and §25 turns the weakness into a technique.

03 Decision, search and optimisation — and self-reducibility

Every optimisation problem on this page comes in three forms — decide whether a solution of a given quality exists, find one, and find the best one — and the three are polynomially equivalent for all of the classic problems, so complexity theory may work exclusively with the yes/no form without giving anything up. The equivalence is not a definition; it is a pair of constructions. Optimisation reduces to decision by binary search over the objective value. Search reduces to decision by self-reducibility: a decision oracle, asked n carefully chosen questions, hands back an actual satisfying assignment or an actual clique. Because those constructions add only a polynomial overhead, the sentence "SAT is NP-complete" carries the full practical content "if you could decide satisfiability quickly you could also produce the assignment quickly", which is what anyone building on the result actually wants.

Why theory chooses the decision form

Three reasons, all structural. First, a decision problem is a language (§02), so the entire apparatus of formal-language theory — complement, closure, classes defined by machines — applies without adaptation, whereas an optimisation problem is a relation and has no complement in any useful sense. Second, the certificate definition of NP (§05) only makes sense for yes/no questions: a certificate is evidence for a yes, and there is nothing for it to be evidence of in "the maximum clique has size 3". Third, the decision form is never harder than the optimisation form, so a hardness proof for the decision form is the stronger statement — and it is hardness we are usually proving. Saying "TSP-DECISION is NP-complete" already implies that nobody will solve TSP-OPT in polynomial time unless P = NP, because the decision version reduces to the optimisation version in one call.

The price is a vocabulary trap this page takes care over. The optimisation problem is NP-hard and is normally not NP-complete, because NP-completeness requires membership in NP and an optimisation problem is not a decision problem at all. Written correctly: TSP-DECISION is NP-complete; TSP-OPT is NP-hard. The same holds for maximum clique, minimum vertex cover, minimum colouring, maximum cut, and every other optimisation problem in the catalogue. Loose usage — "TSP is NP-complete" — is everywhere in the literature and is harmless shorthand among people who know what they mean, but it is exactly the confusion §07 is written to prevent, so this page always names which version it means.

Self-reducibility, made concrete: a SAT oracle that hands back an assignment

Suppose a black box answers, in one step, "is this CNF formula satisfiable?" — and nothing else. It never shows an assignment. Here is how to extract one with n queries for n variables. Ask the box about φ itself; if the answer is no, stop and report unsatisfiable. Otherwise ask about φ|x₁ = TRUE, the formula with x₁ substituted (clauses containing the literal x₁ are deleted, occurrences of ¬x₁ are struck out of their clauses). If the answer is yes, fix x₁ = TRUE; if no, then because φ was satisfiable every satisfying assignment must have x₁ = FALSE, so fix that instead. Repeat for x₂ under the value now fixed for x₁, and so on. After n rounds every variable has a value, and the invariant maintained throughout — the formula restricted to the values fixed so far is satisfiable — is true at the end, when no free variables remain, which means the fixed assignment satisfies φ.

On the page's running formula φ = (x₁ ∨ ¬x₂ ∨ ¬x₃) ∧ (¬x₁ ∨ x₂ ∨ x₃) ∧ (x₁ ∨ x₂ ∨ x₃) — which has exactly 5 satisfying assignments out of 8, namely 001, 010, 101, 110 and 111 in the bit order x₁x₂x₃ — the procedure runs like this. A preliminary query establishes that φ is satisfiable at all — yes. Then, one query per variable: is φ|x₁=T satisfiable? Yes (101, 110, 111 survive), so x₁ = TRUE. Is φ|x₁=T, x₂=T satisfiable? Yes (110, 111), so x₂ = TRUE. Is φ|x₁=T, x₂=T, x₃=T satisfiable? Yes (111), so x₃ = TRUE. Four queries in all — one preliminary plus n = 3 — and the assignment 111 comes out; substituting it gives (1∨0∨0) ∧ (0∨1∨1) ∧ (1∨1∨1) = TRUE, which the figure re-checks against the exhaustive list of satisfying assignments. Note what the greedy "try TRUE first" rule does: it always lands on the lexicographically largest satisfying assignment under that ordering, and the oracle's three answers are exactly the branch decisions that a backtracking search would make without ever having to backtrack — which is the whole point. The decision oracle removes the search.

The same trick for clique, and why it is not universal

For clique the natural self-reduction deletes vertices instead of fixing bits. First find the optimum size k = ω(G) by binary search on the decision oracle (or, since k ≤ n, by n queries). Then walk the vertices in any fixed order and, for each v, ask the oracle whether G − v still has a clique of size k: if yes, delete v permanently, because some k-clique avoids it; if no, keep v, because every k-clique uses it. The invariant is the current graph still contains a clique of size k, and when the walk ends the surviving vertex set cannot be shrunk further, so it is exactly a k-clique. On the seven-vertex demonstration graph of §12 the maximum clique has size 3 and there are exactly 2 triangles, {c, d, e} and {d, e, f}; the deletion walk in alphabetical order deletes a, b and c — each time a triangle survives without it — and then keeps d, e and f, returning {d, e, f} after exactly 7 further queries, one per vertex, on top of whatever the search for k cost. Which triangle you get depends on the vertex order, and the figure lets you change it.

Self-reducibility is a property of a problem, not a theorem about NP. It holds for every NP-complete problem in the standard catalogue, because for each of them there is an obvious "fix one bit / delete one element and ask again" step whose sub-instance is an instance of the same problem. It is not known to hold for every problem in NP — that is a genuine open question, tangled with whether P = NP — and there are artificial NP languages for which no such procedure is known. The honest statement is: for every problem this page names, a polynomial-time decision algorithm would yield a polynomial-time search algorithm, by the explicit construction above; so nothing is lost by studying only the decision versions.

Binary search on the objective, with the one condition it needs

The reduction from optimisation to decision is binary search, and it is worth stating its condition because it is the only thing that can go wrong. If the objective takes integer values in [0, V], then ⌈log₂(V + 1)⌉ decision queries locate the optimum exactly. That is polynomial in the input size provided V ≤ 2^poly(n) — provided, in other words, that the optimum is not astronomically larger than anything written on the input. It never is: for clique and vertex cover the optimum is at most n, so ⌈log₂(n+1)⌉ queries suffice; for TSP it is at most the sum of all the edge costs, whose binary length is at most the length of the input, so the number of queries is at most the number of input bits. If the objective is not integral — a Euclidean tour length, say — the search returns an interval rather than a value, and one falls back on the self-reduction to produce the tour and then evaluates it, which is what the figures of §22 do. The pattern "decide, then binary-search, then self-reduce" is the standard way a theoretical result about a decision problem is cashed out as a program that prints an answer, and it costs a factor of O(n + log V) oracle calls in total.

A fourth face: counting, which is harder than all three

There is one more version of every problem on this page, and it does not join the equivalence. Counting asks not whether a solution exists but how many there are: how many satisfying assignments does φ have (5, out of 8, for the page's running formula), how many 3-cliques does a graph contain (2 in the seven-vertex graph of §12, and 12 in the nine-vertex graph the reduction of §11 builds from φ), how many subsets of {3, 7, 11, 14, 19, 23} total 37 (exactly 3). Those numbers are what the figures on this page use for cross-checking, and computing them is a strictly different problem: the counting versions live in the class #P, and #SAT is #P-complete just as SAT is NP-complete.

The reason counting deserves a separate paragraph rather than a footnote is that it is hard even when the decision problem is easy. Deciding whether a bipartite graph has a perfect matching is in P — it is a flow problem, solved on Shortest Paths, MST & Flow, §25 — but counting its perfect matchings is #P-complete, which is Valiant's 1979 theorem about the permanent. So the easy/hard boundary of §16 is drawn for decision problems and does not transfer to counting; a self-reduction that produces one solution says nothing about how many there are. Toda's theorem (1991) makes the gap precise in the other direction: the whole polynomial hierarchy (§18) reduces to #P with a single query, so a #P oracle is at least as useful as an oracle for any fixed number of alternating quantifiers. When a problem on this page is described as solved by "sampling solutions" or "estimating how many" — which is what several machine-learning applications in §31 actually need — the relevant hardness is #P's, not NP's, and the approximation theory is a different one (approximate counting, and the Markov-chain methods that support it).

The phrase to get right. "X is NP-complete" is a statement about a decision problem. "X is NP-hard" is a statement about any problem — decision, search, optimisation, function, even undecidable ones — that is at least as hard as everything in NP. The optimisation versions of clique, vertex cover, TSP, colouring, set cover, subset sum and knapsack in this page's catalogue are NP-hard; their decision versions are NP-complete; and the two facts are linked by exactly the constructions above. §07 gives the formal definitions and §33 lists the ways the pair is misquoted.

04 P: polynomial time, and why the class is robust

P is the set of decision problems some algorithm decides in O(nᵏ) steps for a fixed k, with n the input length in bits — and the reason this coarse, constant-blind, exponent-blind definition has survived sixty years is that it is the smallest natural class that is invariant under everything an engineer would consider an implementation detail. Change the machine model, change the encoding, change the programming language, pipe one algorithm's output into another's input, call a subroutine a constant number of times: the class does not move. That invariance is what lets a theorem proved about Turing machines in 1971 say something about a Python program in 2026. The identification of P with "tractable" — the Cobham–Edmonds thesis — is a separate and much weaker claim, and this section is careful to state where it holds and where it visibly does not.

Why "polynomial" and not something tighter

The honest answer is that no tighter class is robust. "Linear time" depends on the machine model — what is linear on a random-access machine is quadratic on a single-tape Turing machine. "O(n log n)" is not closed under composition. "O(n³)" is not closed under composition either; feed one cubic algorithm's output into another and you get O(n⁹). The polynomials are the smallest family of growth rates closed under addition, multiplication and composition, which is precisely the algebra of "build a program out of parts", so they are the smallest family in which the phrase "and then call the subroutine" is free. Everything else in the definition follows from wanting that one closure property. Edmonds in 1965 and Cobham in 1964 arrived at the class from opposite directions — Edmonds wanting a name for what his matching algorithm achieved and brute force did not, Cobham wanting a machine-independent characterisation of feasible functions — and the coincidence is the usual sign that a definition is the right one.

The complement of the argument is also worth stating. The reason "exponential" is the other side of the line is not that 2ⁿ is a magic function but that exponentials are closed under the same operations in the wrong direction: compose two exponentials and you leave the class entirely, and multiply an exponential by a polynomial and you are still exponential, so the constant factors and the exponent tuning that dominate practical performance inside P are invisible at that scale. A 1 000-fold faster machine multiplies the largest tractable n by 1 000 for a linear algorithm and by 10 for a cubic one, but adds about log₂ 1000 ≈ 10 to it for a 2ⁿ algorithm: measured against the same budget the figure uses, a cubic routine's reach goes from n = 1 000 to n = 10 000 while a 2ⁿ routine's goes from n = 29 to n = 39. That asymmetry — hardware multiplies polynomial reach and merely adds to exponential reach — is the practical content of the distinction, and §26 returns to it when a 1.3ⁿ algorithm turns out to be worth building.

The caveats, stated plainly

  • n¹⁰⁰ is in P and is useless. The definition puts no bound on k, and an algorithm running in n¹⁰⁰ steps is unusable at n = 2. The empirical defence is that this almost never happens: the polynomial-time algorithms that arise in practice have small exponents, and once any polynomial algorithm is known for a problem, better ones have historically followed quickly. That is an observation about the history of the field, not a theorem, and it should be quoted as such.
  • Galactic algorithms. Some polynomial algorithms have constants so large that no instance in this universe is big enough for them to win. The graph-minor theorem yields O(n³) — later O(n²) — recognition algorithms for every minor-closed graph property, with constants that depend on the excluded minors and are beyond astronomical, and the proof is non-constructive: it shows the algorithm exists without exhibiting its obstruction set. The fast matrix-multiplication exponents below 2.372 are similar: the improvements over Strassen's n^2.807 are real theorems with constants that rule out use. A membership proof in P is a statement about asymptotics and nothing else.
  • The constant factor is where real engineering lives. Two O(n log n) sorts can differ tenfold on cache behaviour alone, as Algorithm Analysis, §11 shows and Sorting & Searching, §19 measures. None of that is visible at this page's resolution, and none of it is the point here; the distinction this page draws is between nᵏ and cⁿ, which dwarfs every constant.
  • Polynomial in P does not mean "known to be polynomial". Linear programming was suspected polynomial for decades before the ellipsoid method (1979) proved it, while the simplex method in practice was and is far faster than either polynomial algorithm on real instances and still has exponential worst-case behaviour on Klee–Minty cubes. Primality testing entered P only in 2002, by an algorithm whose original bound was about Õ(b¹²) in the number of bits b, later improved to about Õ(b⁶) — and in practice probabilistic tests are used instead. Membership in P is a mathematical fact with an uneven relationship to what anyone runs.
  • Space is bounded by time. An algorithm that runs in O(nᵏ) steps touches at most O(nᵏ) cells, so P ⊆ PSPACE (§18) with no further argument. The converse is not known, and §18 explains what PSPACE contains that NP is not known to.

What P measures, and the neighbouring resources it does not

P fixes one resource — deterministic time — and holds everything else free. Vary the resource and you get the neighbouring classes, each of which stands in an interesting and mostly unresolved relation to P, and §18 returns to the ones that matter.

  • Space. L is logarithmic work space, PSPACE polynomial space. L ⊆ P ⊆ NP ⊆ PSPACE, and all four could conceivably be equal — the only separation known in that chain is L ≠ PSPACE, which follows from the space hierarchy theorem. A polynomial-time algorithm uses at most polynomial space for free, since it cannot touch more cells than it has steps; the converse is exactly what is open.
  • Randomness. BPP is what a polynomial-time algorithm with coin flips decides with error probability at most 1/3 on every input (and 1/3 can be driven to 2^−n by repetition and majority vote). P ⊆ BPP trivially. Randomised primality tests, randomised quicksort's pivot choice in Sorting & Searching, §16, and the MAX-3-SAT coin flip of §24 all live here. The modern expectation is that P = BPP — that randomness buys no asymptotic power for decision problems — on the strength of derandomisation results conditional on circuit lower bounds, and the historical trend supports it: primality was famously the flagship BPP problem until 2002 put it in P.
  • Quantum. BQP is polynomial time on a quantum machine. P ⊆ BQP, and factoring is in BQP by Shor's algorithm while not known to be in P — which is why "quantum computers break RSA" is a true sentence and "quantum computers solve NP-complete problems" is not one. BQP is not believed to contain NP: the best general quantum speed-up for unstructured search is Grover's, which turns 2ⁿ into 2^(n/2) — a square root, not a polynomial — and that is provably optimal for a black-box search. §18 says where BQP is thought to sit.
  • Parallelism. NC is what polylogarithmic time on polynomially many processors decides. NC ⊆ P, and whether the inclusion is strict is the "is everything parallelisable?" question; the P-complete problems, of which circuit evaluation is the canonical one, are the ones believed not to be.

None of these changes anything about this page's subject. An NP-complete problem is not put into P by randomising, by parallelising with polynomially many processors, or (as far as anyone knows) by going quantum; each of those buys a polynomial factor or a square root, and the gap this page is about is exponential.

Where this page uses P. Every "easy" problem named from §16 onward is a member of P by an algorithm built earlier in this series: BFS and DFS reachability, bipartiteness and 2-colouring, topological order and strongly connected components (Graph Representations & Traversal, §11–§23); shortest paths, minimum spanning trees, maximum flow, minimum cut and bipartite matching (Shortest Paths, MST & Flow); sorting, selection and binary search (Sorting & Searching); every dynamic program whose state space is polynomial (Dynamic Programming, §07); 2-SAT and Horn satisfiability (§09, §16). The catalogue of P is exactly the rest of this series, and this page is what is left over.

05 NP: certificates and verification

A problem is in NP when every yes-instance has a short piece of evidence — a certificate — that a polynomial-time algorithm can check; the algorithm never has to find the evidence, only to be convinced by it when handed one, and it must refuse to be convinced by anything when the answer is no. That is the whole definition, and it is strikingly weak: it asks for nothing more than that solutions be recognisable. Nearly every combinatorial problem anyone poses has this property, which is why NP is enormous and why "is it in NP?" is almost never the interesting question. The interesting question is the gap between recognising a solution and producing one, and NP is the class in which that gap is exactly the thing being measured.

the certificate definitionA two-argument algorithm V VERIFIES a language L if L = { x ∈ {0,1}* : ∃ y ∈ {0,1}* with |y| = O(|x|ᶜ) and V(x, y) = 1 } read both halves, because both are needed: COMPLETENESS x ∈ L ⟹ SOME certificate y makes V accept ("the evidence exists") SOUNDNESS x ∉ L ⟹ NO certificate y makes V accept ("the evidence cannot be forged") NP = { L : some V verifies L in time polynomial in |x| } the length bound on y is not decoration: without it, "guess the whole run of an exponential search" would be a certificate and NP would swallow EXPTIME. Since V runs in poly(|x|) time it cannot read more than poly(|x|) bits of y anyway, so |y| = O(|x|ᶜ) is the natural bound and is equivalent to imposing none at all beyond V's own running time. the equivalent nondeterministic definition — and where the letters come fromNP = the languages decided in polynomial time by a NONDETERMINISTIC machine: one allowed to branch, accepting x iff SOME branch of its (exponentially large) computation tree accepts within poly(|x|) steps. the two definitions are the same class, and the translation is mechanical: certificate → nondeterminism the machine nondeterministically writes y bit by bit, then runs V nondeterminism → certificate the certificate is the list of branch choices; V replays them deterministically NP abbreviates NONDETERMINISTIC POLYNOMIAL. It does NOT abbreviate "non-polynomial"; P ⊆ NP, so NP contains every problem with a fast algorithm. "Guess and check" is the right mental model; "not solvable quickly" is not.

Notice what the verifier is not doing in any row. It is not searching. It is not clever. It performs the same work a referee does reading a proof: local, mechanical, linear in the size of what it is shown. The exponential in each right-hand column is the cost of playing the role of prover instead, and NP is the class of problems where that asymmetry is all there is.

Soundness is the half that is usually forgotten

It is easy to write a "verifier" that accepts the right certificates and misses the fact that it also accepts wrong ones. A verifier for CLIQUE that checks only that |S| = k and that some pair in S is an edge satisfies completeness — every real clique passes — and fails soundness, since a non-clique passes too, and the language it verifies is not CLIQUE but something much larger. The two conditions must be checked separately, and the second is a statement about all strings y, not about the intended one. Put the other way round: a verifier defines a language, namely {x : ∃y V(x,y) = 1}, and the obligation is to show that this language is the one you meant. Every membership proof "X ∈ NP" on this page is that two-line argument, and §17's co-NP is precisely the observation that for some problems the no-answers are the ones with short evidence and the yes-answers are not.

P ⊆ NP, and what would have to be true for the inclusion to be strict

If L ∈ P then L ∈ NP: take the verifier that ignores its certificate and runs the decider on x. Completeness holds because the decider accepts every x ∈ L whatever y is (the empty string will do); soundness holds because it accepts no x ∉ L whatever y is. So P ⊆ NP, with a one-line proof and no hidden content. The reverse inclusion is the open problem. To prove P ≠ NP one must exhibit a problem in NP and prove that no polynomial algorithm whatsoever decides it — a statement quantified over all possible algorithms, which is the kind of statement complexity theory is worst at proving. Sixty years have produced exactly one class of such results for natural problems, the hierarchy theorems (§18), which separate classes only when one is given strictly more of the same resource; §07 collects the three barriers that explain why nothing else has worked. Sorting & Searching, §10 contains the only unconditional lower bound in this series, Ω(n log n) comparisons, and it is instructive about why: it holds in a restricted model where the algorithm may only compare, and counting leaves of a decision tree bounds its depth. No such restriction is available for SAT, where the algorithm may do anything at all.

The certificate length bound, and why it costs nothing

The definition requires |y| = O(|x|ᶜ), and it is worth seeing that this is not an extra assumption but a consequence of the time bound. A verifier running in p(|x|) steps cannot read more than p(|x|) bits of its certificate, so any certificate longer than that has a prefix that works just as well; truncating loses nothing. Dropping the bound entirely would be a different and much larger class — a certificate allowed to be exponentially long could simply be the transcript of an exponential-time computation, and "NP" would swallow EXPTIME. Keeping it gives the class its other important property for free: NP ⊆ EXPTIME. Enumerate all 2^O(nᶜ) candidate certificates, run the polynomial verifier on each, and accept if any accepts; that is 2^O(nᶜ) · poly(n) = 2^O(nᶜ) time, so every NP problem is solvable in exponential time by brute force, and the entire content of this page is whether anything better is possible. §26 is about making that brute force as fast as brute force can be made.

A certificate can also be surprisingly clever, and the classic case is worth knowing because it is the one place where "obviously in NP" is wrong. COMPOSITE — is N composite? — is in NP by an obvious certificate, a non-trivial factor. PRIMES — is N prime? — has no obvious certificate at all: the natural evidence for primality is the absence of a factor, which is a universal statement and therefore a co-NP-flavoured one. It was not obvious that PRIMES ∈ NP until Pratt exhibited, in 1975, a recursive certificate of primality: a generator of the multiplicative group modulo N together with the factorisation of N − 1 and, recursively, primality certificates for each of those factors, all checkable in polynomial time. So PRIMES sits in NP ∩ co-NP — which was already strong evidence that it was not NP-complete, since an NP-complete problem in co-NP would force NP = co-NP (§17) — and in 2002 it was shown to be in P outright. Factoring's decision version occupies the same NP ∩ co-NP position today, and is the standard example of a problem widely believed to be neither in P nor NP-complete (§07).

What NP is closed under

NP is closed under union and intersection (run both verifiers on a pair of certificates), under concatenation and Kleene star (the certificate names the split points as well), and under polynomial-time many-one reductions in the sense that A ≤ₚ B and B ∈ NP give A ∈ NP. It is not known to be closed under complement — that is precisely the NP versus co-NP question of §17 — and this single missing closure is what separates NP from P, which is closed under complement trivially. It is the reason the definition is asymmetric in the first place: a certificate is evidence for a yes, and nothing in the definition offers evidence for a no.

What the certificate view buys later on

  • It makes NP-hardness provable at all. The Cook–Levin theorem (§08) reduces an arbitrary language in NP to circuit satisfiability by taking the verifier V, which the certificate definition guarantees exists, and compiling its computation into a circuit whose free inputs are the certificate's bits. Without a uniform object to compile — a polynomial-time machine, given by the definition — there would be nothing to reduce from.
  • It explains the shape of every gadget. Each reduction in §11–§15 arranges its output instance so that its solutions are in correspondence with the certificates of the input instance: a satisfying assignment becomes a clique, becomes a cover, becomes a subset, becomes a colouring. Reductions map certificates to certificates, and checking a reduction is checking that correspondence in both directions.
  • It draws the line at co-NP. "This formula is satisfiable" has a one-line certificate; "this formula is unsatisfiable" appears not to, and no short certificate for unsatisfiability is known. That asymmetry is not an artefact of how the question is phrased — it is the difference between NP and co-NP (§17), and whether the two classes coincide is open and is implied by, but not known to imply, P = NP.
  • It is the definition the approximation lower bounds are stated against. The PCP theorem, which §20 and §24 use to state the inapproximability results, is a re-characterisation of NP: every NP language has a proof format such that a verifier reading a constant number of randomly chosen bits of the certificate accepts correct proofs always and incorrect proofs with probability at most ½. It is a statement about certificates from beginning to end.
The misreading to avoid. "NP" names a class that contains P. A problem being in NP says nothing about it being hard — sorting is in NP, shortest paths are in NP, every problem in this series is in NP. The hardness claims on this page are always of the form "NP-hard" or "NP-complete", never "in NP". And a problem in NP is guaranteed only that the yes-answers are short-certifiable; a problem whose no-answers are short-certifiable is in co-NP, and the two need not coincide (§17).
