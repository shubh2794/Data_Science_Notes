25 Maximum bipartite matching as a flow; König and Hall

A matching in a graph is a set of edges no two of which share a vertex; in a bipartite graph — vertices split into L and R with every edge between the sides — a maximum matching is found by one maximum-flow computation on the network that joins a source to every vertex of L, every vertex of R to a sink, and directs every edge from L to R, all with capacity 1. The integrality theorem is what makes the reduction a theorem rather than a relaxation: an integral flow of value k in that network is a matching of size k, and conversely, so the maximum flow is the maximum matching. Ford-Fulkerson on the network needs at most V/2 augmentations of O(V + E) each, O(VE) in all; Hopcroft-Karp augments along many shortest paths per phase and needs only O(√V) phases, O(E√V). The minimum cut of the same network is a minimum vertex cover, which is König's theorem, and König's theorem in turn gives Hall's condition for when every vertex of L can be matched: never more vertices on the left than they have neighbours on the right.

Augmenting paths in matching language

An augmenting path in G′_f starts s → l for an unmatched l (the edge s → l still has capacity), alternates between unmatched edges l → r traversed forward and matched edges traversed backward along their reverse arcs r → l (the cancellation of §21 — undoing a matching edge), and ends r → t at an unmatched r. Dropping s and t gives an M-augmenting path in G: an odd-length path from an unmatched L-vertex to an unmatched R-vertex whose edges alternate not-in-M, in-M, …, not-in-M. Augmenting along it — flipping every edge's membership — adds one more edge than it removes, and the max-flow min-cut theorem's (2) ⇒ (1) becomes the statement that a matching with no augmenting path is maximum (this is usually credited as a separate theorem about matchings, and it holds in general graphs too, where the flow reduction does not apply). The routine on this page runs directly on G: for each unmatched l it breadth-first searches alternating paths, and when it reaches an unmatched r it flips the path. That is Ford-Fulkerson on G′ with the source and sink edges made implicit — same augmentations, same result, and the figure confirms the count and the size against the explicit flow network.

König from max-flow min-cut

Give the middle edges l → r capacity ∞ instead of 1; the maximum flow is unchanged (each l receives at most 1 from s, so no middle edge ever carries more than 1), and now every finite cut has a clean shape. Let (S, T) be a minimum cut, necessarily finite since S = {s} has capacity |L|. No ∞ edge crosses it, so there is no edge (l, r) with l ∈ S and r ∈ T. Define C = (L ∩ T) ∪ (R ∩ S). C is a vertex cover: an edge (l, r) with l ∉ C has l ∈ S, hence r ∉ T, hence r ∈ S, hence r ∈ C. Its size is the cut's capacity: the crossing edges are s → l for l ∈ L ∩ T (one each) and r → t for r ∈ R ∩ S (one each), so c(S, T) = |L ∩ T| + |R ∩ S| = |C|. Conversely any vertex cover C defines the cut S = {s} ∪ (L ∖ C) ∪ (R ∩ C) of capacity exactly |C| — the crossing edges are s → l for l ∈ L ∩ C and r → t for r ∈ R ∩ C, and no middle edge crosses because an edge from l ∉ C goes to some r ∈ C ⊆ S. So minimum cut capacity = minimum vertex cover size; with maximum flow = maximum matching and the max-flow min-cut theorem in between, max |M| = min |C|. The reachable set of §22 gives the cover explicitly: S = {s} ∪ Z where Z is what s reaches in the residual network, which is precisely the set of vertices reachable from unmatched L-vertices by alternating paths; the formula C = (L ∖ Z) ∪ (R ∩ Z) is (L ∩ T) ∪ (R ∩ S) read off that S. The easy direction, |M| ≤ |C| for any matching and any cover, needs no flow: each vertex of C touches at most one edge of M, and every edge of M must be touched. König's theorem says the bound is tight in bipartite graphs; in general graphs it fails (a triangle has maximum matching 1 and minimum cover 2), which is why the flow reduction needs the two sides.

Hall from König

Necessity is immediate: if every vertex of L is matched, the matching sends S to |S| distinct neighbours, so |N(S)| ≥ |S|. Sufficiency: suppose no matching covers L, so the maximum matching has size < |L| and by König there is a vertex cover C with |C| < |L|. Let S = L ∖ C. Every edge leaving S must be covered by its R-endpoint, so N(S) ⊆ R ∩ C and |N(S)| ≤ |C| − |L ∩ C| < |L| − |L ∩ C| = |S|: Hall's condition fails at S. The proof is constructive in the same way König's is: the violating set is L minus the cover, and the cover is read off the final residual network — which is how the figure lights the violator without searching. A direct flow proof exists too (bound the capacity of any cut in G′ below by |L| using the condition, so the maximum flow is |L|), and the condition generalises: the largest number of L-vertices that can be matched is |L| − max over S ⊆ L of (|S| − |N(S)|), the deficiency version, which the brute-force routine computes and the figure prints.

Hopcroft-Karp, and the weighted problem

Hopcroft-Karp runs phases. A phase does one BFS from all unmatched L-vertices at once, alternating unmatched and matched edges, to layer the graph by shortest alternating distance; then a DFS restricted to the layers finds a maximal set of vertex-disjoint shortest augmenting paths and flips them all. This is Dinic's algorithm on the matching network (§23), and the phase bound is the unit-network argument: after √V phases every remaining augmenting path has length > √V; the symmetric difference of the current matching M with a maximum one M* contains |M*| − |M| vertex-disjoint augmenting paths, each using more than √V vertices, so |M*| − |M| < V/√V = √V, and since each phase adds at least one edge, fewer than √V further phases remain. Each phase is O(E), so the total is O(E√V). On the 4 × 4 instance it takes 2 phases (measured), against the 4 augmentations of the one-path-at-a-time routine. For the weighted problem — the assignment problem, a perfect matching of minimum total weight — the reduction is to min-cost flow on G′ with the weights as costs on the middle edges (§26), solved by successive shortest paths; the Hungarian method is the same successive-shortest-path idea with dual variables (vertex potentials) maintained so that Dijkstra can replace Bellman-Ford, and runs in O(V³). Both are pointers here.

26 What flow solves: disjoint paths, project selection, image segmentation, circulations

A problem is solved by maximum flow when it can be rewritten as "how much can be routed" and by minimum cut when it can be rewritten as "what is the cheapest way to separate" — and because the two are equal, a reduction to either gives both the optimum and its certificate. This section states the standard reductions precisely: the network built, what a flow or cut in it means in the original problem, and why the correspondence is exact. Disjoint paths and Menger's theorem

Give every edge capacity 1. An integral flow of value k decomposes into k paths from s to t (walk from s along edges carrying flow, removing each edge used; conservation guarantees the walk reaches t, and a cycle in the flow can be discarded without changing the value), and with unit capacities no edge is on two of them: they are edge-disjoint. That is the unit-capacity case of the flow decomposition theorem: every flow is a sum of at most E pieces, each a path flow (along one s ⇝ t path) or a cycle flow, found by peeling — take any path or cycle of edges carrying positive flow, subtract its minimum edge flow, which zeroes at least one edge, and repeat, so at most E pieces — and only the path flows contribute to |f|. It is also why maximum flows are not unique (§21): two maximum flows can differ by a cycle flow, or by which of two paths carries a unit, without differing in value, so "the" maximum flow is a value with many witnesses, exactly as "the" shortest path is a distance with possibly many paths. Conversely k edge-disjoint paths are a flow of value k. So the maximum flow is the maximum number of edge-disjoint paths, and the minimum cut — a set of edges leaving S of total capacity c(S, T), i.e. that many edges — is a smallest set of edges whose removal leaves t unreachable from s. The equality of the two is Menger's theorem (edge form). For vertex-disjoint paths, split each internal vertex v into v_in and v_out joined by a single edge of capacity 1, route every edge into v to v_in and every edge out of v from v_out; a flow can pass through v at most once, so integral flows are sets of vertex-disjoint paths, and the minimum cut counts the fewest vertices whose deletion separates s from t (Menger, vertex form; cutting a split edge is deleting the vertex, and cutting an original edge is never cheaper than cutting one of its endpoints' split edges). Undirected graphs reduce by replacing each edge with two antiparallel unit arcs — a maximum flow can be assumed to use at most one direction of each pair, by cancelling. On the six-vertex network the answer is 2 both ways (the source has out-degree 2, so it cannot be more, and s→v₁→v₃→t with s→v₂→v₄→t are vertex-disjoint); the figure's brute force enumerates all 5 simple s ⇝ t paths and checks every subset of them for disjointness.

Project selection: a closure problem as a minimum cut

Projects i have profits p_i, positive for revenue and negative for pure costs, and a prerequisite relation "i requires j"; a feasible selection is a set A closed under prerequisites, and the goal is to maximise Σ_{i ∈ A} p_i. Build the network as in the block: s → i with capacity p_i for each profitable project, i → t with capacity −p_i for each costly one, and an edge i → j of capacity ∞ for each requirement. A cut of finite capacity cannot cut an ∞ edge, so if i ∈ S and i requires j then j ∈ S: the set A = S − {s} is closed. Its capacity is the sum of p_i over profitable projects not in A (their s → i edges cross) plus the costs of the costly projects in A (their i → t edges cross), which is P − profit(A) where P is the sum of all positive profits. Minimising the cut therefore maximises the profit, and the best closed set is the source side of any minimum cut — the reachable set that Ford-Fulkerson returns for free.

Worked. Four projects A = +9, B = +6, C = −4, D = −5; A requires C, B requires C and D. P = 15. The eight closed sets and their profits: ∅: 0, {C}: −4, {D}: −5, {C, D}: −9, {A, C}: 5, {A, C, D}: 0, {B, C, D}: −3, {A, B, C, D}: 6. The best is to do everything, profit 6, even though B alone with its prerequisites loses 3 — because C is paid for once and shared. The network has 6 vertices and 7 edges; Edmonds-Karp finds |f*| = 9 in 2 augmentations, and 15 − 9 = 6 with the reachable set {A, B, C, D}. The cut for {A, C}, for comparison, has capacity 6 (B left out) + 4 (C taken) = 10 = 15 − 5. The same construction solves any "choose a closed set to maximise a sum of vertex weights" problem: open-pit mining (a block requires the blocks above it), module selection with dependencies, and the segmentation below is its cousin with a symmetric penalty in place of ∞.

Image segmentation: a binary labelling energy as a minimum cut

Each pixel p gets a label x_p ∈ {0, 1} (background, foreground); a data term D_p(x_p) says how badly p's intensity fits the region it is assigned to, and a smoothness term charges λ for every pair of 4-neighbours with different labels. The energy is E(x) = Σ_p D_p(x_p) + λ · #{p ~ q : x_p ≠ x_q}, and the minimum-energy labelling is a minimum cut in the network of the block: s → p with capacity D_p(0), p → t with capacity D_p(1), and p → q, q → p both with capacity λ. Put p on the source side when x_p = 1. Then the cut severs s → p exactly for the pixels labelled 0 (paying D_p(0)), severs p → t exactly for the pixels labelled 1 (paying D_p(1)), and severs one of the two arcs between each differently-labelled pair (paying λ once, since only the arc from the source side to the sink side counts); so c(S, T) = E(x) for every labelling, and the minimum cut is the global minimum of the energy. The condition that makes the construction work is that disagreement costs more than agreement — the smoothness term must be non-negative (more generally, submodular) — because a capacity cannot be negative; Image Segmentation, §23 states that condition in full, with the contrast-sensitive weights used in practice and the multi-label extensions that are no longer exact. Baseball elimination, sketched

Teams have current wins w_i and remaining games g_{ij} against each other; is team z already unable to finish with the most wins? Suppose z wins all its remaining games, ending with W = w_z + g_z. Build a network with a node per remaining pairing {i, j} among the other teams and a node per other team: s → {i, j} with capacity g_{ij}, {i, j} → i and {i, j} → j with capacity ∞, and i → t with capacity W − w_i (the wins team i may still collect without passing z; if some w_i > W the answer is already no). A flow assigns each remaining game's wins to its two teams; every game can be played out without anyone overtaking z iff the maximum flow saturates all the s → {i, j} edges, i.e. equals the total number of remaining games among the others. When it does not, the minimum cut names a set of teams T* whose current wins plus the games among themselves exceed W · |T*| — a certificate anyone can check by arithmetic: those teams cannot all stay at or below W. The reduction is a template for "can these demands all be met" questions: sources of supply on the left, sinks of capacity on the right, and a check that the flow saturates the supply.

Circulations with demands and lower bounds

A circulation has no source or sink; instead each vertex has a demand d(v) (negative for a supplier), the demands sum to zero, and the flow must satisfy capacity on every edge and in(v) − out(v) = d(v) at every vertex. Feasibility reduces to maximum flow: add s* with an edge s* → v of capacity −d(v) to each supplier and t* with an edge v → t* of capacity d(v) from each demander; a circulation exists iff the maximum s* ⇝ t* flow saturates every new edge, i.e. has value D = Σ_{d(v) > 0} d(v), and then the flow restricted to the original edges is the circulation. If the answer is no, the minimum cut gives the reason: a set of vertices whose net demand exceeds the capacity of the edges into it. With lower bounds ℓ(e) ≤ f(e) ≤ c(e), pre-send ℓ(e) on every edge: that consumes ℓ(e) of the capacity, leaving c(e) − ℓ(e), and it changes each vertex's balance by ℓ_in(v) − ℓ_out(v), so the residual demand is d′(v) = d(v) − ℓ_in(v) + ℓ_out(v); solve the lower-bound-free problem with capacities c − ℓ and demands d′, and add the ℓ(e) back. Both transformations are exact — they are bijections between feasible solutions — and together they cover survey design, scheduling with minimum staffing, and flows that must use certain edges.

Pointers: minimum-cost flow, b-matching, scheduling

Minimum-cost flow adds a cost per unit on each edge and asks for the cheapest flow of a given value (or the cheapest maximum flow). The residual network gets costs too — the reverse arc of an edge with cost k costs −k, since it refunds — and the successive shortest paths algorithm augments along a cheapest augmenting path each time, found by Bellman-Ford (§07) because of the negative reverse costs, or by Dijkstra after Johnson-style reweighting with vertex potentials (§14), which is the practical version; the correctness invariant is that a flow is minimum-cost for its value iff the residual network has no negative-cost cycle, which is also the basis of the alternative cycle-cancelling algorithm. The assignment problem of §25 is its special case. b-matching gives each vertex a capacity b(v) on how many matching edges may touch it — jobs to machines that can run several, students to courses with quotas — and is the matching network with s → l of capacity b(l) and r → t of capacity b(r). Scheduling problems with "each of n tasks needs one of its allowed slots, each slot holds at most k" are the same network; with time windows and machine capacities they are circulations with demands. In each case the reduction is the whole algorithm, and the two things to state precisely are what the capacities mean and what an integral flow of maximum value corresponds to in the original problem.

27 Weighted-graph algorithms in machine learning

A weighted-graph algorithm enters machine learning in one of four roles: as an exact solver for a combinatorial subproblem (a minimum cut that is the global optimum of a labelling energy, an assignment that is a maximum-weight matching, a transport plan that is a minimum-cost flow); as an exact inference engine whose recurrence is literally a shortest path on a DAG (Viterbi, and every trellis decoder built like it); as a geometric primitive that turns a point cloud into distances or clusters (geodesics on a nearest-neighbour graph, single-linkage trees); and as the shape that other graph computations are mistaken for — PageRank, message passing, greedy routing in a vector index — which are iterations on a graph but not shortest paths, and whose guarantees are of a different kind. Each correspondence below is stated exactly: which graph is built, which algorithm on this page runs on it, under which hypothesis of that algorithm, and at what cost; every claim of exactness is a theorem from §02–§26 applied to a particular network, and every claim of "not this" says what the computation is instead. The links go to the page in these notes where the learning side is treated.

Geodesics on a neighbourhood graph: manifold learning

The linear methods on the Dimensionality Reduction page flatten a point cloud by a rotation, and the table there of nonlinear and neighbour-embedding alternatives begins with the observation that a curved manifold — a spiral, a Swiss roll — is not flat in Euclidean distance but is flat in distance measured along it. Isomap makes that distance computable with two objects from this page. First a k-nearest-neighbour graph: each point is joined to its k nearest points (or to every point within radius ε), each edge weighted by the straight-line length, giving an undirected graph with n vertices and about nk edges whose weights are all non-negative. Second, all-pairs shortest paths on that graph (§12–§14): with weights ≥ 0 the choice is n runs of Dijkstra, O(n · nk log n) = O(n² k log n) with a binary heap, against Floyd-Warshall's Θ(n³), and the sparse choice wins by a factor of n / (k log n) — the decision procedure of §28 applied verbatim. The resulting n × n matrix of graph distances approximates the geodesic distances on the manifold, and classical multidimensional scaling — the eigendecomposition of the double-centred squared-distance matrix, the same computation as PCA on a Gram matrix — recovers coordinates in which those distances are Euclidean. Three facts from this page govern when it works. The graph must be connected: a component unreachable from another has δ = ∞ (the no-path property, §02), and an implementation must either raise k, keep the largest component, or embed components separately. The weights must not short-circuit: an edge that cuts across a fold makes the graph distance shorter than the geodesic, and no amount of shortest-path computation notices, because the algorithm answers exactly the question asked of the graph it is given. And the cost is dominated by the shortest paths, not the top-d eigendecomposition (computed iteratively; a full Θ(n³) eigendecomposition would dominate), for the sizes where k log n ≪ n. Spectral embeddings, t-SNE and UMAP begin from the same neighbourhood graph and never compute a shortest path: they work from the graph's Laplacian or from local affinities, which is why they preserve neighbourhoods rather than geodesic distances.

Minimum spanning trees: single linkage, spacing, and the tree that factorises a distribution

§20 proved that the k clusters produced by single-linkage agglomeration — merge the two closest clusters, distance between clusters being the minimum over cross pairs — are exactly the components left when Kruskal's algorithm stops after n − k acceptances on the complete distance graph, and that this partition maximises the spacing (the minimum inter-cluster distance) over all k-partitions. The Clustering page presents the dendrogram and the linkage choices; the fact recorded here is what it costs and what it cannot do. The complete graph has n(n − 1)/2 edges, so Kruskal costs Θ(n² log n) for the sort and Prim's array version (§19) costs Θ(n²) — either is the O(n³) naive agglomerative loop with a log factor or more removed, and both compute the entire dendrogram at once, since the merge sequence is the acceptance sequence. The audit at the foot of this page re-checks the equivalence on 120 random graphs: cutting the k − 1 heaviest tree edges gives k clusters whose spacing is the lightest cut edge. What single linkage cannot do is resist chaining: the MST is willing to connect two dense groups through a thin bridge of points, because the tree minimises total edge weight and never asks how far apart the endpoints of a path are — the MST-against-SPT contrast of §20 (a path of 13 for a distance of 10 on six vertices, a factor approaching V − 1 in general) is the same phenomenon. Complete and average linkage do not reduce to a spanning-tree computation for that reason: their inter-cluster distance depends on all pairs, not the closest, and the cut property's exchange argument no longer applies. Two more uses of the tree are exact. The maximum spanning tree (§20, by negation) of the complete graph whose edge weights are pairwise mutual informations is the tree-structured joint distribution closest in KL divergence to the data — the Chow–Liu construction — because the log-likelihood of a tree factorisation decomposes into a sum of edge mutual informations plus a constant, so maximising it is a maximum-weight spanning tree, solved by Kruskal on −I(X; Y). And the minimum-bottleneck property (§16) makes the MST path between two points the minimax path — the route whose largest jump is smallest — which is the distance density-based methods want and the reason single-linkage clusters coincide with the connected components of the ε-neighbourhood graph at every threshold ε at once. Spectral clustering, which the clustering page lists among the density- and model-based methods, is often described as "a graph cut", and it is worth being precise: the normalised and ratio cuts it approximates are balanced partitions with no designated source and sink, which are NP-hard, and the eigenvector computation is a relaxation of them; the s–t minimum cut of §22 is a different problem, solvable exactly, and it is the next item.

Minimum cut as exact MAP inference: graph cuts

§26 built the network whose minimum cut is the global minimum of a binary labelling energy E(x) = Σ_p D_p(x_p) + λ · #{p ~ q : x_p ≠ x_q}, and checked it against all 512 labellings of a 3 × 3 grid. The Image Segmentation page states the general condition and its consequences; the algorithmic content is this. A pairwise term V_pq(x_p, x_q) can be represented by capacities if and only if it is submodular, V_pq(0, 0) + V_pq(1, 1) ≤ V_pq(0, 1) + V_pq(1, 0), because after the standard rearrangement the smoothness capacity between p and q is V_pq(0, 1) + V_pq(1, 0) − V_pq(0, 0) − V_pq(1, 1) and a capacity cannot be negative (§21); the Potts term λ·[x_p ≠ x_q] with λ ≥ 0 is the simplest submodular term, and contrast-sensitive weights λ_pq = λ · exp(−(I_p − I_q)²/2σ²) are submodular for the same reason. Under that condition the minimum cut is the exact MAP labelling of the corresponding Markov random field — the pairwise energy is −log of an Ising-type prior, the data term −log of a likelihood — and the max-flow min-cut theorem (§22) is the certificate: the flow value proves no labelling is cheaper. For more than two labels the reduction is no longer exact; α-expansion solves a sequence of binary problems, each a minimum cut that asks "which pixels should switch to label α", and is guaranteed only to reach a local minimum, within a known constant factor of the optimum when the smoothness term is a metric. The solvers matter because the networks are large and structured — a megapixel image is a grid of a million vertices and four million neighbour arcs — and §24 named the choice: push-relabel with the gap and global-relabelling heuristics, or the augmenting-path algorithm that reuses its search trees between augmentations, which on grids with short augmenting paths beats the general-purpose bounds; Edmonds-Karp's O(VE²) (§23) is the wrong tool at that scale and the right one on the page's 3 × 3 instance, where it makes 13 augmentations. Conditional random fields with the same binary submodular structure — foreground/background, in/out of a region, before/after a boundary — are solved the same way, and the segmentation page's λ sweep is a picture of the regularisation path: energies non-decreasing in λ, boundary length non-increasing, individual pixels not monotone (pixel 5 flips 1 → 0 → 1 → 0 on this page's grid).

Viterbi is the DAG algorithm, and beam search is not

The Viterbi decoder finds the most probable state sequence of a hidden Markov model or a linear-chain CRF; Dynamic Programming, §28 derives it as a table. Here it is a graph: the trellis has a vertex for every (state, time) pair plus a source and a sink, an arc from (i, t − 1) to (j, t) of weight −log a_ij − log b_j(o_t), and the most probable sequence is the shortest source-to-sink path, because a product of probabilities is a sum of negative log-probabilities. The trellis is a DAG — every arc advances time — so §09 applies with no condition on the weights: one pass in topological order (time-major), each of the (T − 1)·S² + 2S arcs relaxed once, Θ(T·S²) — the DP page's count of (T − 1)·S² + T·S = 63 multiplications for S = 3, T = 6 is the 45 inter-layer arcs relaxed once each plus one emission factor per (state, time). The weights happen to be non-negative, so Dijkstra (§04) would also be correct — and would be slower, because it pays a log per queue operation for an order the topological sort gives for free; the typical situation in which Dijkstra is the better decoder is a lattice that is not a trellis, such as a word graph with arcs of varying length, where the goal is reached long before most of the graph has been expanded and A* with an admissible completion estimate (§15) expands fewer vertices still. Beam search is neither: it keeps the B best partial paths at each time and discards the rest, so it is a heuristic pruning of the DAG pass that can discard the prefix of the optimal path — the DP page counted a width-1 beam missing the optimum on 33 of the 64 observation strings of its model — and it has no counterpart on this page because nothing on this page discards a vertex before its estimate is final. CTC's forward recursion, the forward algorithm, and the sum-product versions of all of these are the same trellis with (min, +) replaced by (+, ×), the semiring change of §12, and they compute a marginal rather than a path.

Planning: value iteration is Bellman-Ford, and Dijkstra is its priority order

The Bellman optimality equation of Reinforcement Learning, V*(s) = min_a [c(s, a) + Σ_s′ P(s′ | s, a) V*(s′)] for costs, becomes a shortest-path problem exactly when the transitions are deterministic and undiscounted: then V*(s) = min_a [c(s, a) + V*(next(s, a))] is the triangle-inequality fixed point of §02 read backwards, V*(s) = δ(s, goal), and the value-iteration sweep "update every state from its successors" is one round of Bellman-Ford on the reversed graph — the DP view of §08, in which round k is exact for every state whose optimal path has at most k steps. That correspondence gives value iteration its convergence count on such problems (at most V − 1 sweeps from the initialisation "0 at the goal, ∞ elsewhere", not the log(1/ε)/log(1/γ) of the discounted case) and explains why negative step costs are dangerous there and harmless here: a negative cycle is an unbounded reward, and the test round of §07 is the detector. When step costs are non-negative, Dijkstra's order — settle the state with the smallest current value, never revisit it — is exactly the priority that prioritised sweeping and Dijkstra-style planners use, and §05 says what it needs: w ≥ 0, no more and no less. With stochastic transitions the problem is a stochastic shortest path, the expectation replaces the single successor, the greedy order is no longer valid in general, and value iteration's rounds remain the safe algorithm — the same relationship, one level up, as Bellman-Ford's to Dijkstra's on this page. Temporal-difference learning is the same backup sampled from experience, and A* with a learned heuristic is Dijkstra with a potential (§15), which is why an inconsistent learned heuristic must be run with reopening or accepted as approximate.

Optimal transport and assignment: minimum-cost flow and maximum-weight matching

The earth-mover distance between two discrete distributions — the minimum total work, mass times distance, to reshape one histogram into the other — is a transportation problem: a bipartite network with a vertex per bin on each side, supplies equal to the source masses, demands equal to the target masses, an arc from every source bin to every target bin with cost equal to the ground distance and unbounded capacity, and the answer is a minimum-cost flow of value equal to the total mass — the pointer at the end of §26, solved by successive shortest paths with Bellman-Ford or, with Johnson-style potentials (§14) keeping the reduced costs non-negative, with Dijkstra. That is the Wasserstein-1 distance the Wasserstein GAN page introduces through the same dirt-moving picture; the GAN uses its dual form (a supremum over 1-Lipschitz critics) rather than solving the flow, because the distributions are continuous and represented by samples. In one dimension the flow has a closed form — sort both samples and pair them in order, which is the reason the drift-monitoring distances can be computed per feature in O(n log n) — and the entropically regularised version solved by Sinkhorn iterations is a matrix-scaling relaxation, not a flow algorithm, which trades exactness for parallelism. Two special cases collapse further. When both sides have n points of equal mass, the transport plan can be taken to be a permutation (the integrality of §22 applied to the transportation network), and the problem is the assignment problem: a minimum-cost perfect matching in a complete bipartite graph, §25's matching with costs, solved by the Hungarian method in O(n³) or as a min-cost flow of value n. That is the data-association step of multi-object tracking — detections on one side, tracks on the other, cost a distance between predicted and observed positions, with a dummy vertex per side so that unmatched detections can start tracks and unmatched tracks can end — for which these notes have no page; the nearest treatment is the feature-matching strategies of the vision notes, where the mutual-nearest-neighbour rule with a ratio test is a greedy approximation to the same assignment, fast and without the optimality guarantee a matching gives. And when the costs are 0/1 — "compatible or not" — the assignment is the unweighted maximum bipartite matching of §25 with Hall's condition as the feasibility test, which is how the audit at the foot of this page checks it.

What is not a shortest path, and what it is instead

Three graph computations that machine learning uses constantly resemble the algorithms of this page and are not them. PageRank, and its sentence-graph form TextRank in extractive summarisation, is the stationary distribution of a random walk with restarts: the dominant eigenvector of a stochastic matrix, computed by power iteration in O(E) per iteration, converging geometrically at the damping rate. Nothing is minimised along a path; the quantity is a fixed point of averaging, and the relevant theory is spectral (the Perron–Frobenius eigenvector), not relaxation. Message passing in graph neural networks repeats L rounds of "aggregate the neighbours' vectors, update your own", and its L-hop receptive field has exactly the shape of Bellman-Ford's rounds (§08), in which round k reaches every vertex within k edges; the difference is that the aggregation and update are learned functions rather than min and +. The correspondence is more than a metaphor in one direction: a message-passing layer whose message is d[u] + w(u, v) and whose aggregation is min is one round of Bellman-Ford, so a network with that inductive bias can represent shortest paths exactly, and the observation that architectures aligned with a target algorithm's recurrence learn it from fewer examples is the reason "neural algorithmic reasoning" benchmarks use Bellman-Ford, Dijkstra, Prim and the like as targets; a network with sum or mean aggregation cannot represent the min and only approximates. Greedy search in a vector index such as HNSW, in the vector-database notes, hops from a vertex to whichever neighbour is closest to the query and stops when none is closer: it is a descent on a navigable graph with no optimality guarantee, tuned by the beam width ef, and it answers "an approximate nearest neighbour" rather than "the shortest path"; the theory behind it is about the graph's construction (long-range links that make greedy routing succeed), not about relaxation. Knowing which of the four roles a graph computation plays is the practical skill: an exact solver can be trusted to the last unit and checked by its certificate (a cut, a cover, a dual), an inference engine is exact for its model and only as good as the model, a geometric primitive is exact for the graph it is given and only as good as the graph, and an iteration that resembles a shortest path should not be given a shortest path's guarantees.
