21 Flow networks, residual graphs, augmenting paths and cuts

A flow network is a directed graph with a non-negative capacity c(u, v) on every edge, a source s and a sink t; a flow is an assignment f(u, v) to every edge that never exceeds the capacity and is conserved at every vertex other than s and t; its value |f| is the net amount leaving s; and the maximum-flow problem asks for a flow of largest value. Four objects built on that definition are the whole vocabulary of the next five sections. The residual network G_f records, for the current flow, how much more can be sent along each edge and how much already sent can be taken back. An augmenting path is an s → t path in G_f, and pushing its bottleneck amount along it produces a flow of larger value. A cut (S, T) is a partition of the vertices with s ∈ S and t ∈ T, its capacity is the total capacity of edges leaving S, and the net flow across it equals |f| for every cut — which gives the one inequality, |f| ≤ c(S, T), that every algorithm on these pages turns into a certificate.

What the definition allows and forbids, and the two fixes

The flow is defined on all pairs of vertices, with f(u, v) = 0 wherever there is no edge; this makes the conservation sums clean. The convention that a network has no antiparallel edges exists for the residual network: if both (u, v) and (v, u) were present, "the residual capacity of (u, v)" would be two numbers — the room on the forward edge and the cancellable flow on the reverse edge — and the definition above, which reads c_f(u, v) off whichever edge exists, would be ambiguous. The fix is to subdivide one of the pair: replace (v, u) by v → v′ → u through a new vertex v′, both edges with the old capacity. The subdivided network has the same maximum flow (a flow through v′ is exactly a flow on the old edge), one more vertex and one more edge. An implementation does not need to do this: the routine on this page stores each input edge as a pair of arcs, a forward arc with the capacity and a reverse arc with capacity zero, and the two carry opposite flows; each input edge then owns its own reverse arc, and an antiparallel input pair is simply two pairs. The definition's convention and the implementation's pairing are two ways to say the same thing — every unit of residual capacity belongs to exactly one edge.

Several sources and sinks are handled with a supersource and supersink: add a vertex s with an edge of capacity ∞ to each original source and a vertex t with an edge of capacity ∞ from each original sink. Any flow in the multi-source network is a flow in the augmented one of the same value, and conversely, so the two problems have the same optimum. (When each source can supply at most some amount, that amount is the capacity of its edge from s instead of ∞; that is the supply-and-demand form, which §26 uses for circulations.)

The residual network: room left, and flow that can be taken back

Two things can be done to the flow on an edge (u, v) carrying f(u, v) of c(u, v): add up to c(u, v) − f(u, v) more, or remove up to f(u, v) of what is there. The residual network records both as arcs with positive capacity: a forward arc u → v of capacity c − f if any room is left, and a reverse arc v → u of capacity f if any flow is present. Pushing on a reverse arc is cancellation: sending 3 units back along v → u means the edge now carries f − 3, which is why c_f(v, u) = f(u, v) and not c(v, u). Cancellation is not a convenience but the mechanism that lets a greedy sequence of augmentations reach the optimum: an early augmentation may route flow through an edge a better solution needs empty, and the only way to undo that choice without starting over is to push against it. §22's pathological instance, where the worst path rule cancels the same unit 200 times, and §24's push-relabel, which sends excess back towards the source along reverse arcs, both live on this one definition.

Formally, if f is a flow in G and f′ a flow in G_f, their augmentation (f ↑ f′)(u, v) = f(u, v) + f′(u, v) − f′(v, u) on edges of E (and 0 elsewhere) is a flow in G with |f ↑ f′| = |f| + |f′|. The capacity constraint holds because f′(u, v) ≤ c_f(u, v) = c(u, v) − f(u, v) bounds the sum above and f′(v, u) ≤ c_f(v, u) = f(u, v) bounds it below zero; conservation holds because both f and f′ are conserved and the definition is linear; the value adds because the terms at s add. An augmenting path p defines the simplest such f′ — c_f(p) on the arcs of p, zero elsewhere — so augmenting along p increases |f| by exactly c_f(p) > 0. That is the step every augmenting-path algorithm repeats, and the residual network is where it looks for the path.

Cuts, and why the net flow across every cut is |f|

Take any cut (S, T). Start from the value |f| = f(s, V) − f(V, s), where f(X, Y) abbreviates ∑_{x ∈ X} ∑_{y ∈ Y} f(x, y). For each u ∈ S − {s}, conservation says f(u, V) − f(V, u) = 0; add those zero terms to the value to get |f| = f(S, V) − f(V, S). Now split V = S ∪ T in both terms: f(S, V) = f(S, S) + f(S, T) and f(V, S) = f(S, S) + f(T, S). The f(S, S) terms cancel, leaving |f| = f(S, T) − f(T, S), which is the definition of the net flow across the cut. Nothing about the cut was used except that s ∈ S and t ∉ S (so t's non-conservation never entered), so the identity holds for every cut. Weak duality follows in one line: |f| = f(S, T) − f(T, S) ≤ f(S, T) ≤ c(S, T), the first inequality because flows are non-negative and the second by the capacity constraint on each S → T edge. Every cut is therefore an upper bound on every flow, and a flow that equals some cut's capacity is maximum, with that cut as its certificate. Whether such a pair always exists is the content of §22.

Vocabulary that will recur

An edge with f(u, v) = c(u, v) is saturated; its forward residual arc is absent. A flow is maximum if no flow has larger value; maximum flows are not unique (the flow of value 23 obtained above and the one Edmonds-Karp finds in §23 differ on three edges — their difference is a circulation — a sum of cycle flows, in the language of the flow-decomposition theorem §26 states), but the value is. A cut is minimum if no cut has smaller capacity; it need not be unique either, though on this instance it is. The bottleneck of a path is its residual capacity. A flow with |f| = c(S, T) for some cut (S, T) is both maximum and a proof of its own maximality, and every algorithm on this page ends by exhibiting that pair. Linear-programming language says the same thing: maximum flow is a linear program, minimum cut is (the integral solution of) its dual, and the identity f(S, T) = |f| together with weak duality is the LP weak-duality inequality written by hand; the connection is stated here and not pursued (the Lagrangian view of constrained optimisation is Optimization).

22 Ford-Fulkerson and the max-flow min-cut theorem

The Ford-Fulkerson method starts from the zero flow and repeats one step — find an augmenting path in the residual network, push its bottleneck along it — until no augmenting path exists; the max-flow min-cut theorem says that at that moment the flow is maximum, and that its value equals the capacity of the cut whose source side is the set of vertices still reachable from s in the residual network. "Method" rather than "algorithm" because the path is not specified: any rule for choosing it gives a correct maximum flow when the method terminates, and with integer capacities it terminates in at most |f*| augmentations of O(E) each, for O(E·|f*|) in total. That bound is tight and bad: a four-vertex network with capacities M and a perverse path rule takes 2M augmentations to move 2M units, one at a time, and with irrational capacities the method can fail to terminate at all. Choosing the path well is the subject of §23 and §24; this section proves that any path works.

the methodFORD-FULKERSON(G, s, t): f(u, v) = 0 for every edge while there is an augmenting path p in G_f: — any s ⇝ t path with every arc of positive residual capacity c_f(p) = min over arcs of p of c_f(u, v) for each arc (u, v) of p: if (u, v) ∈ E: f(u, v) += c_f(p) else: f(v, u) −= c_f(p) — forward: add; reverse: cancel return f — and the cut S = { v : s ⇝ v in G_f }, which certifies it the max-flow min-cut theorem — for a flow f in G, the following are equivalent(1) f is a maximum flow (2) the residual network G_f has no augmenting path (3) |f| = c(S, T) for some cut (S, T) and therefore max over flows |f| = min over cuts c(S, T) integrality, and the cost with integer capacitiesif every c(u, v) is an integer, the method keeps every f(u, v) an integer, ends with an integer maximum flow, and each augmentation adds ≥ 1 to |f| so augmentations ≤ |f*|, each a search of G_f costing O(V + E_f) = O(E) (E ≥ V − 1, E_f ≤ 2E) ⇒ O(E · |f*|) total this is a function of the capacities, not of V and E alone — pseudo-polynomial; on the pathological instance below it is attained capacity scaling — a Ford-Fulkerson rule that is weakly polynomialΔ ← 2^⌊log₂ U⌋ with U = max c(u, v) (integer capacities); while Δ ≥ 1: { augment along any s ⇝ t path of G_f whose arcs all have c_f ≥ Δ, until none exists; Δ ← Δ/2 } when the Δ-phase ends, the vertices reachable by arcs with c_f ≥ Δ form a cut every crossing residual arc of which has c_f < Δ ⇒ the remaining flow is < E·Δ the next phase (Δ/2) adds ≥ Δ/2 per augmentation ⇒ < 2E augmentations per phase; ⌊log₂ U⌋ + 1 phases, O(E) per search ⇒ O(E² log U) WEAKLY polynomial: polynomial in V, E and the bit length of the capacities, log U — not in V and E alone (that is STRONGLY polynomial: Edmonds-Karp's O(VE²), §23)

Proof of the theorem

(1) ⇒ (2). If f is maximum but G_f has an augmenting path p, then augmenting along p (§21) gives a flow of value |f| + c_f(p) > |f|, contradicting maximality. (2) ⇒ (3). Suppose G_f has no s ⇝ t path. Let S be the set of vertices reachable from s in G_f and T = V − S; s ∈ S by definition and t ∈ T by assumption, so (S, T) is a cut. Take any u ∈ S, v ∈ T. If (u, v) ∈ E, then f(u, v) = c(u, v): otherwise c_f(u, v) = c − f > 0 would make v reachable from u, hence from s, putting v in S. If (v, u) ∈ E, then f(v, u) = 0: otherwise c_f(u, v) = f(v, u) > 0 would again make v reachable. (If neither edge exists both flows are 0 anyway.) So every edge leaving S is saturated and every edge entering S is empty, and the net flow across the cut is f(S, T) = ∑ c(u, v) − 0 = c(S, T). By §21's identity, |f| = f(S, T) = c(S, T). (3) ⇒ (1). By weak duality, |f′| ≤ c(S, T) for every flow f′; if |f| = c(S, T) then no flow exceeds f. The three implications close the cycle. The equality of the maximum flow value and the minimum cut capacity follows: a maximum flow exists (the method finds one for integer capacities; for real capacities compactness supplies one), it satisfies (3) for some cut, and that cut cannot exceed the minimum cut while the minimum cut cannot be below any flow.

The step to notice is (2) ⇒ (3): it is constructive. The set S it names is exactly what a breadth-first or depth-first search from s in the final residual network returns, so the method ends with the minimum cut in hand for one extra O(E) traversal — on the six-vertex network, S = {s, v₁, v₂, v₄}, the unique minimum cut of §21. Every application in §25–§26 that asks for a cut rather than a flow (a vertex cover, a project set, a pixel labelling) reads it off this set.

Integrality, termination, and what irrational capacities break

The integrality theorem: if all capacities are integers, the maximum flow value is an integer and there is a maximum flow in which every f(u, v) is an integer. The proof is the method itself — the zero flow is integral, the residual capacities of an integral flow are integers, so every bottleneck c_f(p) is a positive integer, and every augmentation keeps the flow integral and raises its value by at least 1. Hence the method terminates after at most |f*| augmentations, and the flow it stops with is integral and, by the theorem, maximum. Rational capacities reduce to this case by scaling by the common denominator. §25 depends on integrality entirely: with unit capacities an integral flow is a set of edges, which is what makes "maximum flow = maximum matching" a statement about matchings and not about fractional ones.

With irrational capacities the guarantee is gone. A network with six vertices and irrational capacities is known on which a particular sequence of augmenting-path choices never terminates: the bottlenecks form a geometric series, the flow values converge, and the limit is strictly less than the maximum flow. Its status on this page is evidential only — the construction is a specific, checkable instance in the literature, not something the figures reproduce, because they compute with integers throughout (the pathology they can show is the integer one below). The practical reading is that "Ford-Fulkerson terminates" is a theorem about integer (or rational) capacities, and "Ford-Fulkerson is O(E·|f*|)" is a theorem about integer capacities; neither is a statement about the method in general. Edmonds-Karp (§23) removes the dependence on both the capacities and the path choice.

A second cure keeps the capacities in the bound but tames them. Capacity scaling is the Ford-Fulkerson method with the rule "only augment along paths whose every arc has residual capacity at least Δ", starting with Δ the largest power of two not above the largest capacity U and halving Δ each time no such path remains. When a Δ-phase ends, the set of vertices reachable from s through arcs of residual capacity ≥ Δ is a cut whose crossing residual arcs each carry less than Δ, so at most E·Δ more flow can ever be added; every augmentation of the following phase adds at least Δ/2, so that phase has fewer than 2E augmentations, and there are ⌊log₂ U⌋ + 1 phases: O(E² log U) in total, against the plain method's O(E·|f*|). The bound is weakly polynomial — it depends on the capacities through their bit length log U — where Edmonds-Karp's O(VE²) is strongly polynomial, with no capacity in it at all; the two names mark exactly that distinction, and §28 lists scaling as the rule to reach for when capacities are integers with a wide range and E is small relative to V. On the four-vertex pathology below, scaling with U = 100 starts at Δ = 64, saturates the two capacity-100 paths in that first phase, and finds nothing to do in the six phases that follow — the capacity-1 middle edge is never used: 2 augmentations instead of the 200 the "worst" rule performs (checked by running the rule on the page's residual structure; on the six-vertex network it takes 3 augmentations, one at Δ = 8 and two at Δ = 4).

The pathological instance: 2M augmentations on four vertices

Vertices s, u, v, t; edges s→u, s→v, u→t, v→t of capacity M and one middle edge u→v of capacity 1. The maximum flow is 2M: M along s→u→t and M along s→v→t, never touching the middle edge; a cut of capacity 2M is S = {s}. Now choose paths perversely. Path 1: s → u → v → t, bottleneck 1 (the middle edge). The residual network gains the reverse arc v → u of capacity 1. Path 2: s → v → u → t, bottleneck 1 again — it uses that reverse arc and cancels the unit on the middle edge, restoring c_f(u, v) = 1. Path 3 is path 1 again, and so on: every augmentation moves exactly one unit and flips the middle edge, so 2M augmentations are needed, each an O(E) search, for Θ(E·M) total on a graph with V = 4 and E = 5. With M = 10⁶ that is two million augmentations of a five-edge graph; the figure uses M = 100 and the "worst" rule and measures 200 augmentations and 2 402 arc scans, against 4 augmentations for depth-first (its first path also takes the middle edge for one unit, its second pushes 99 along s→u→t, its third cancels the middle unit along s→v→u→t, and its fourth pushes 99 along s→v→t) and 2 for BFS (the two length-2 paths are shortest, and after them the middle edge is useless). The lesson is precise: the bound O(E·|f*|) is not pessimism about an unlucky constant; it is the actual running time of a legitimate implementation of the method on a legitimate input, and the cure is a rule for the path.

23 Edmonds-Karp: the O(VE²) bound, proved and measured

Edmonds-Karp is the Ford-Fulkerson method with one rule added: the augmenting path is a shortest s ⇝ t path in the residual network, counted in edges, found by breadth-first search. The rule costs nothing — a BFS is what the search was going to be anyway — and it changes the bound from a function of the capacities to a function of the graph: at most VE augmentations regardless of the capacities, each an O(E) search, so O(VE²) in total, with no assumption of integrality and no dependence on the path being lucky. The proof has two steps that are worth knowing on their own: shortest-path distances from s in the residual network never decrease as the flow grows, and each residual arc can be the bottleneck of an augmentation only V/2 times because its endpoint's distance grows by two between bottleneck events. Dinic's algorithm keeps the same idea and augments along all shortest paths at once, which improves the bound to O(V²E) and, on unit-capacity networks, to far less.

Why the distances never decrease

Suppose an augmentation takes the flow from f to f′ and, for some vertex, δ_{f′}(s, v) < δ_f(s, v). Among all such vertices choose v with the smallest δ_{f′}(s, v). Let p′ be a shortest s ⇝ v path in G_{f′} and (u, v) its last arc, so δ_{f′}(s, u) = δ_{f′}(s, v) − 1; by the choice of v, the distance to u did not decrease: δ_{f′}(s, u) ≥ δ_f(s, u). Two cases. If (u, v) was already a residual arc in G_f, then δ_f(s, v) ≤ δ_f(s, u) + 1 ≤ δ_{f′}(s, u) + 1 = δ_{f′}(s, v), contradicting the assumed decrease. If it was not — (u, v) ∉ E_f but (u, v) ∈ E_{f′} — then the augmentation created it, which means it pushed flow from v to u: the augmenting path contained the arc (v, u). That path was a shortest path in G_f, so along it δ_f(s, u) = δ_f(s, v) + 1, giving δ_f(s, v) = δ_f(s, u) − 1 ≤ δ_{f′}(s, u) − 1 = δ_{f′}(s, v) − 2, again contradicting the decrease. The shortest-path rule is used exactly once, in the second case: an arbitrary augmenting path could push flow along (v, u) while v was further from s than u, creating a residual arc (u, v) that shortens the way to v, and then distances could fall; the shortest-path rule guarantees that the arcs an augmentation creates always point backwards, from a vertex to one closer to s, and a backward arc can shorten nothing.

Why each arc is critical at most V/2 times, and the O(VE) count

Let (u, v) be critical on the augmenting path p under flow f. Since p is shortest, δ_f(s, v) = δ_f(s, u) + 1. After the augmentation the arc is gone from the residual network, and it can reappear only when some later augmentation pushes flow from v to u — that is, when (v, u) lies on a later shortest augmenting path under a flow f′, at which moment δ_{f′}(s, u) = δ_{f′}(s, v) + 1. By the lemma δ_{f′}(s, v) ≥ δ_f(s, v), so δ_{f′}(s, u) ≥ δ_f(s, v) + 1 = δ_f(s, u) + 2. Between two critical events of the same arc, the distance to its tail rises by at least 2. That distance is 0 at least (it is 0 when u = s) and, while the arc still lies on an s ⇝ t path, at most V − 2 (the path continues through v to t); a quantity that starts at ≥ 0, rises by ≥ 2 each time and stays ≤ V − 2 can take at most V/2 values, so (u, v) is critical at most V/2 times. The arcs that can ever be residual are the 2E forward and reverse arcs of the edges, so the total number of critical events is at most 2E · V/2 = VE, and since every augmentation makes at least one arc critical, there are at most VE augmentations. Each is a BFS over at most 2E arcs — O(V + E) = O(E) because every vertex lies on an s ⇝ t path — for O(VE²) in all. Nothing in the argument mentions the capacities: they may be irrational, and the bound stands.

The bound's slack, measured

VE augmentations is a worst case, and on small instances the algorithm is nowhere near it: 3 against 54 here. The figure's random mode generates seeded networks with 8 vertices and 16 edges (capacities 1–9, every vertex on an s ⇝ t path) and reports the same counts; over 300 such seeds the checking script found at most 8 augmentations against the bound VE = 128, and no arc critical more than once. Families that force the bound exist — layered constructions on which Edmonds-Karp genuinely performs Θ(VE) augmentations — but they are not random-looking, and in practice the augmentation count tends to grow far more slowly than VE. Two remarks follow. First, the theoretical improvements — Dinic's O(V²E), push-relabel's O(V²E) generic bound and O(V³) or O(V²√E) with an order (§24), and the more recent almost-linear bounds — matter when the graphs are large and structured (grids of pixels in §26, dense bipartite graphs in §25), not on toy networks. Second, the cross-check that matters is not the count but the value: the figure confirms Edmonds-Karp's |f| against Dinic's, and both against the brute-force minimum cut over all 2^{V−2} cuts, with a flag that would say DISAGREE if they ever differed.

Dinic in a little more detail

A phase runs one BFS from s to get δ_f, keeps only the arcs that advance one level (the level graph), and then finds a blocking flow in it — a flow in the level graph such that every s ⇝ t path of the level graph has a saturated arc. That is not a maximum flow of the level graph, only a maximal one, and it is found by repeated DFS from s that advances along level-graph arcs with residual capacity, retreats (and deletes the arc from further consideration) when stuck, and augments along each s ⇝ t path found; a current-arc pointer per vertex, which never moves backwards within a phase, makes each phase O(VE): each augmentation is O(V) and there are O(E) of them because each saturates a level-graph arc, and the pointer advances total O(E). After a blocking flow every shortest path is destroyed, so the next BFS finds δ(s, t) larger by at least one; δ(s, t) ≤ V − 1 gives at most V − 1 phases and O(V²E) overall. On unit-capacity networks the blocking flow is O(E) per phase (every augmentation saturates every arc on its path, so the DFS never revisits an arc), and the number of phases collapses: after k phases every remaining augmenting path has length > k, and in a unit network (in-degree 1 or out-degree 1 at every internal vertex) the remaining flow is at most V/k, so the phases number at most about 2√V — the O(E√V) that §25 states for Hopcroft-Karp, which is Dinic specialised to a bipartite matching network. 24 Push-relabel: preflows, heights, and the O(V²E) generic bound

Push-relabel algorithms compute a maximum flow without ever looking for a path: they work with a preflow, in which a vertex may temporarily hold more flow than it sends on (its excess), and move excess one edge at a time "downhill" according to a height label, raising a vertex's height when it has excess and nowhere lower to send it. The source starts at height V with every outgoing edge saturated, the sink stays at height 0, and the two local operations — PUSH along a residual edge from a vertex to one exactly one unit lower, RELABEL a stuck vertex to one more than its lowest residual neighbour — are repeated in any order until no vertex other than s and t has excess. At that point the preflow is a flow, and it is maximum because the height labels certify that no augmenting path can exist. The analysis counts the three kinds of operation: fewer than 2V² relabels, fewer than 2VE saturating pushes, and O(V²E) non-saturating pushes by a potential argument, giving O(V²E) for any order; specific orders bring it to O(V³) and O(V²√E), and with two heuristics the method is the practical winner on dense and structured networks.

Why the operations keep h a height function, and why that forbids augmenting paths

RELABEL(u) changes only h(u), and raises it: its precondition says every residual arc out of u had h(u) ≤ h(v), so the new value 1 + min h(v) is larger than the old. For arcs out of u the new height is at most h(v) + 1 by construction (it equals h(v) + 1 for the lowest neighbour, which becomes admissible). For arcs into u, (w, u) with h(w) ≤ h(u) + 1 before, raising h(u) only loosens the constraint. PUSH(u, v) changes no height but may change the residual arcs: it may delete (u, v) (deleting an arc removes a constraint) and may create (v, u), for which the constraint h(v) ≤ h(u) + 1 holds because h(v) = h(u) − 1. So the height property is an invariant. Now suppose G_f had an s ⇝ t path s = v₀, v₁, …, v_k = t; it can be taken simple, so k ≤ V − 1. Applying the property along it, h(s) ≤ h(v₁) + 1 ≤ h(v₂) + 2 ≤ … ≤ h(t) + k = k ≤ V − 1, but h(s) = V. So there is never an augmenting path, at any point of the run — not only at the end. The algorithm is, in this sense, Ford-Fulkerson run backwards: instead of maintaining a flow and working towards "no augmenting path", it maintains "no augmenting path" and works towards a flow.

Termination needs one more fact: an overflowing vertex can always be pushed or relabelled. If some residual arc out of u is admissible, push along it. Otherwise every residual arc out of u has h(u) ≤ h(v) (strict h(u) < h(v) + 1 with integers), which is exactly RELABEL's precondition, and the set of residual arcs out of u is non-empty because u is overflowing — flow arrived at u along some edge, and the reverse of that edge is a residual arc. So the loop never stalls, and the counts below show it ends.

The bounds, with the potential argument spelled out

Heights are bounded. If u is overflowing, there is a simple path from u to s in G_f: let U be the set of vertices reachable from u in G_f; if s ∉ U, then no flow enters U from outside (an edge (w, x) with x ∈ U, w ∉ U carrying flow would give a residual arc (x, w), putting w in U), so the total excess in U is −(flow leaving U) ≤ 0; but excess is non-negative off s and positive at u, a contradiction. Along that path of at most V − 1 arcs, h(u) ≤ h(s) + (V − 1) = 2V − 1. Since RELABEL is only applied to overflowing vertices, no height ever exceeds 2V − 1. Relabels. Each raises a height by at least 1 from 0 to at most 2V − 1, and only the V − 2 internal vertices are ever relabelled: at most (2V − 1)(V − 2) < 2V² relabels. Saturating pushes. Fix a pair {u, v} joined by an edge in either direction. A saturating push u → v needs h(u) = h(v) + 1; before the next push u → v the arc must be recreated by a push v → u, which needs h(v) = h(u) + 1, so h(v) has risen by at least 2 in between; symmetrically for the other direction. Heights rise at most 2V − 1 in total, so each pair sees fewer than 2V saturating pushes, and there are at most E pairs: fewer than 2VE. Non-saturating pushes. Let Φ be the sum of h(u) over overflowing u; Φ = 0 at the start and end and never negative. A non-saturating push u → v empties u (removing h(u) from the sum) and may make v overflowing (adding h(v) = h(u) − 1): Φ falls by at least 1. A relabel raises Φ by the height increase, less than 2V² over the whole run; a saturating push may add a newly overflowing v with h(v) ≤ 2V − 1, less than 2VE(2V − 1) over the run. The total decrease cannot exceed the total increase, so the non-saturating pushes number fewer than 2V² + 2VE(2V − 1) < 4V²(V + E), which is O(V²E) because E ≥ V − 1. Every bound holds for any order of applicable operations, which is what "generic" means; the figure measures all three counts and prints them beside these bounds, and the slack is large on small instances.

Orders, heuristics, and where push-relabel wins

The generic algorithm leaves the order open, and the order determines the bound. Relabel-to-front keeps the internal vertices in a list and repeatedly discharges the current vertex — pushes and relabels until its excess is 0 — moving a relabelled vertex to the front of the list; the list stays topologically sorted with respect to admissible arcs, each pass over the list is O(V) plus the operations it triggers, and a pass that relabels nothing is the last (the list is then fully discharged), so with fewer than 2V² relabels in total there are at most 2V² + 1 passes: O(V³). FIFO selection — discharge active vertices in queue order, as the figure's routine does — is also O(V³). Highest-label first — always discharge the highest active vertex, keeping buckets by height — is O(V²√E), the best of the three in theory and usually in practice. Two heuristics change practical behaviour more than the order: the gap heuristic notices that if no vertex has height k then every vertex with height between k and V can be lifted straight to V + 1 (it can never reach t again), and global relabelling periodically recomputes every height as the exact BFS distance to t in the residual graph, which is the tightest valid labelling. With those two, push-relabel is the algorithm behind most maximum-flow libraries for dense graphs and the graph-cut solvers of §26 (where the competing choice is a specialised augmenting-path algorithm with search-tree reuse), while for sparse graphs with small integer capacities Dinic-style level-graph algorithms remain competitive. The counts on this page are of the generic algorithm with FIFO selection and no heuristics; the bounds quoted for the named orders are stated, not measured.
