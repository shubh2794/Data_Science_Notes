Big-O Complexity

Asymptotic notation describes how an algorithm's operation count grows with input size n — ignoring constants and lower-order terms. It lets us compare algorithms independent of hardware: a fast algorithm performs few operations; one whose count grows faster is, eventually, slower.

  • Time vs space: time complexity counts basic operations as a function of n; space complexity counts the extra memory used. Both are reported in the same notation.
  • Three bounds: Big-O is an asymptotic upper bound (cost grows at most this fast, ≤); Big-Omega Ω is a lower bound (≥); Big-Theta Θ is a tight bound (both at once). We also distinguish worst-, average-, and best-case inputs.
  • Only the dominant term survives: a single loop that does a few steps per element costs 3n+2 operations, but the coefficient 3 and the constant 2 vanish asymptotically ⇒ O(n). Constants and lower-order terms drop.
  • Halving work stays in the same class: an all-pairs nested loop runs n(n−1)/2 ≈ n²/2 times ⇒ still O(n²). Cutting the constant in half does not change the class. To drop a class you must divide by something that grows with n.
  • Logarithms come from repeated halving: when each step halves the remaining problem, after k steps the size is n/2ᵏ; setting n/2ᵏ = 1 gives k = log₂ n ⇒ O(log n). This is exactly why binary search is logarithmic.
  • Where it shows up: the cost of tree and graph traversals, sorting, array operations, and the savings from Dynamic Programming are all stated in this language. Reducing complexity is also the goal of Model Acceleration and of model optimization more broadly.
