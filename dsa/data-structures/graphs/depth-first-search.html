15 Depth-first search: recursive and explicit-stack versions, discovery and finishing times, and a traced example

Depth-first search follows one edge from the current vertex to an undiscovered neighbour, and keeps doing so — going deeper — until it reaches a vertex with no undiscovered neighbours; then it backtracks one step and tries the next edge. It is breadth-first search with the queue replaced by a stack, and on a tree it is exactly the preorder traversal. What makes it more than "the other traversal" is the bookkeeping: each vertex receives a discovery time d[v] when it is first reached and a finishing time f[v] when everything reachable through it has been explored, and those 2V timestamps carry a nesting structure (§16) from which cycle detection, topological order, strongly connected components and articulation points are all read off. The BFS of §11 is the search for distance; DFS is the search for structure.

Recursive or explicit stack — which, and when it matters

The recursive version is the definition and the one every proof is written against; its stack is the call stack, one frame per grey vertex holding the position in that vertex's adjacency list. The explicit-stack version keeps that position in an array of iterators and is otherwise identical — the figure runs both and reports that they agree on every timestamp — and it exists because the call stack is small: a few thousand to a few hundred thousand frames depending on the runtime, while a DFS on a path-shaped graph of 10⁶ vertices needs a depth of 10⁶. §26 takes this up. What must not be done is the shortcut that replaces "iterate lazily" by "push every white neighbour now": it is a correct traversal (it visits everything reachable) but the vertex order, the tree and the timestamps differ from true DFS, a vertex may be pushed once per incoming edge, and none of the theorems of §16–§24 apply to its output.

DFS against BFS on the same graph

  • Same work, different order. Both scan every adjacency entry once; both are Θ(V + E). BFS's order is by distance; DFS's is by nesting. BFS from a on G1 discovers b c d e f h g; DFS discovers b d c e f g h and goes eight deep where BFS never went past a layer of two.
  • Different trees. The BFS tree of G1 has g at depth 4; the DFS tree has it at depth 6. Only the BFS tree's depths mean anything (they are distances); the DFS tree's depths are an artefact of list order.
  • Different non-tree edges. BFS's non-tree edges join adjacent or equal layers and are otherwise structureless; DFS's non-tree edges are classified (§17) and each class says something.
  • Different memory profile. BFS holds a layer; DFS holds a path. Which is worse depends on the graph's shape, measured in §25.
DFS on a tree is preorder; on a graph it is preorder plus a memory. The visited set is the only addition, and it is what turns the non-tree edges — which a tree does not have — into the classified edges the rest of this page is built on. The traversals themselves are the tree page's; what is new here is what the rejected edges tell you.

16 The parenthesis theorem and the white-path theorem: what the timestamps guarantee

Write (u at time d[u] and u) at time f[u]. The claim is that the resulting string of 2V symbols is a properly nested parenthesisation — for G2, (a (b (c c) (e (d d) e) b) a) (f (g (h h) g) f) — and that the nesting is the ancestor relation of the DFS forest. That single fact, plus a characterisation of which vertices become descendants of which, is the entire theoretical content of DFS; everything in §17–§24 is a corollary.

Intervals never partially overlap: d[u] < d[v] < f[u] < f[v] is IMPOSSIBLE. proofassume d[u] < d[v] (else swap names). Case d[v] < f[u]: v was discovered while u was grey, i.e. during VISIT(u), so v is a descendant of u; and VISIT(v) is a call nested inside VISIT(u), which cannot return before VISIT(v) does, so f[v] < f[u] — case (iii). Case d[v] > f[u]: since d[u] < f[u] < d[v] < f[v] the intervals are disjoint, and neither vertex was discovered while the other was grey, so neither is a descendant of the other — case (i). (Times are distinct, so d[v] = f[u] cannot occur.) corollary — nesting of descendants' intervalsv is a PROPER descendant of u ⇔ d[u] < d[v] < f[v] < f[u]. Why the theorems matter more than the algorithm

The DFS procedure is six lines; its value is that those six lines produce timestamps with a provable structure, and that structure is what later algorithms consume. Topological sort (§20) needs only "for every edge (u, v) of a DAG, f[v] < f[u]", which the parenthesis theorem and the edge classification deliver. The two-pass SCC algorithm (§22) needs "the component containing the vertex with the largest f is a source component of the condensation", which the white-path theorem delivers. Articulation points (§24) need "every non-tree edge goes to an ancestor", the undirected special case of §17. None of these consult the DFS tree's parent pointers directly; all consult the timestamps, because the timestamps encode the tree and more. That is also why the naive stack variant of §15 is not DFS: it produces a visit order without the nesting, and none of the corollaries survive.

The four cases at a leaf. A vertex c with no white neighbours at discovery has f[c] = d[c] + 1 (G2: 3/4); its interval contains nothing, so it is nobody's ancestor; it is nested in every ancestor's interval and disjoint from everyone else's. The theorem's trichotomy holds with the "descendant" cases empty — the edge case is not an exception, it is the base of the induction that the recursion embodies.

17 Edge classification: four classes for a directed graph, two for an undirected one

When DFS examines an edge (u, v) from the grey vertex u, the colour of v at that moment sorts the edge into one of four classes, and the classes are exactly the relationships the parenthesis theorem allows between u and v. The four-way classification is a directed-graph statement. In an undirected graph two of the classes cannot occur, and the reason is a two-line theorem that the figures verify on every undirected DFS they run.

the four classes (directed graph), defined by the DFS forestTREE edge (u, v): v was discovered by exploring (u, v) — parent[v] = u. The tree edges are the forest. BACK edge (u, v): v is an ANCESTOR of u (or v = u: a self-loop). Closes a cycle with the tree path v ⇝ u. FORWARD edge (u, v): a non-tree edge to a proper DESCENDANT of u. A shortcut down the tree. CROSS edge (u, v): everything else — v is neither ancestor nor descendant: another branch of the same tree, or another tree entirely. the classification at the moment of examination — by colour, then by timecolour[v] = WHITE → TREE (v is discovered right now, from u) colour[v] = GREY → BACK (the grey vertices are exactly the stack, a path of ancestors of u — so a grey v is an ancestor) colour[v] = BLACK → FORWARD if d[u] < d[v] (v discovered after u yet already finished: it lies inside u's interval, hence is a descendant) CROSS if d[u] > d[v] (v discovered and finished before u was discovered: disjoint intervals) G2 (§15): a→d is examined at t = 9 with d black and d[a] = 1 < d[d] = 6 → forward; g→d at t = 14 with d black and d[g] = 12 > d[d] = 6 → cross; c→a, d→e, h→f find a grey target → back theorem — an undirected DFS has only tree and back edgeslet {u, v} be an edge and, without loss of generality, d[u] < d[v]. What each class tells you

  • Tree edges are the DFS forest. Their number is V minus the number of trees, which for an undirected graph is the number of connected components (§19). Everything the forest "knows" — ancestry, depth, the recursion structure — is in these edges.
  • Back edges are cycles. Each one closes a cycle with a tree path, and — the converse, proved in §18 — a graph has a cycle only if DFS finds a back edge. For a DAG the class is empty; for an undirected graph it is the set of edges you could delete to leave a spanning forest, and its size is the cyclomatic number E − V + c.
  • Forward edges are redundant for reachability (a tree path already goes there) but not for distance: a forward edge is a shortcut, and BFS would have used it. Their presence distinguishes "reachable" from "reachable in the tree's number of steps".
  • Cross edges connect what the DFS explored separately, and they always point from later-discovered to earlier-discovered (d[u] > d[v]). They are the class that can join two different DFS trees. Note that an edge between strongly connected components may be a tree, forward or cross edge — never a back edge, since a back edge closes a cycle with the tree path and so lies inside one component — G2's a→d is a forward edge from {a, b, c} to {d, e}, and g→d a cross edge from {f, g, h} — and it is the decreasing-finish-time order of §22, not the classification, that keeps the second pass from following them.

Why direction changes the count from four to two

In a directed graph an edge (u, v) is examined once, from u, and v's colour at that instant is unconstrained by u's: v may have been finished long before u was discovered (cross), or discovered after u and finished through another route (forward). In an undirected graph the edge is available from both ends, and that symmetry forces the earlier-discovered endpoint to still be grey when the later one is discovered — the later one is on its list and must be dealt with before it finishes. So the later endpoint is always a descendant of the earlier, and "descendant" leaves only tree (discovered through this edge) or back (discovered through another route, this edge examined from below). The two "impossible" classes are impossible because an undirected graph cannot have a vertex finished before its neighbour is discovered. The practical consequence is the one that bites in §18: an undirected cycle detector needs only to look for grey neighbours, but it must not count the arrival edge as one.

Classification depends on the DFS, not only on the graph. Change the adjacency order or the starting vertex and an edge that was forward may become cross or tree. What is invariant is the existence of a back edge (it is equivalent to the existence of a cycle, §18) and the counts derived from the forest size; the labels on individual edges are properties of one particular search.

18 Cycle detection: a directed graph is acyclic iff DFS finds no back edge — and the undirected version's one trap

"Does this graph contain a cycle" is the first structural question a DFS answers, and it answers it with the edge classification alone: a cycle exists if and only if some edge examined during the search points at a grey vertex. The statement is the same for both kinds of graph, the proof is the same, and the implementation differs in one line — the undirected search must not mistake the edge it arrived by for a cycle. Getting that line wrong by excluding the parent vertex rather than the arrival edge makes the detector blind to a doubled edge, which the figure demonstrates.

Why the directed proof needs the white-path theorem and the undirected one needs the exclusion

In the directed case the danger is a cycle whose edges are examined in an unhelpful order — could DFS traverse a cycle's vertices in separate subtrees and classify the closing edge as cross? The white-path theorem says no: the first vertex of the cycle to be discovered sees the whole rest of the cycle as a white path and swallows it into its subtree, so the closing edge lands on an ancestor. That is the argument, and it identifies which edge is the witness: the cycle's edge into its first-discovered vertex is always classified back. The cycle's other edges may be tree, forward or even cross edges — r→p tree, p→q cross (if q's subtree was explored from r first), q→r back is a three-cycle in which the cross edge is on the cycle — so "no cycle through this cross edge" is not a valid inference; only "no back edge anywhere, hence no cycle anywhere" is. In the undirected case the theorem of §17 already says every non-tree edge is a back edge, so any non-tree edge is a cycle and the only work is to recognise the tree edge to the parent when it is seen a second time from the child — which is what the exclusion does. Exclude by edge identity, not by parent vertex, and the detector is correct on multigraphs too; on a simple graph the two exclusions coincide, which is why the bug hides until a multigraph arrives.

Three cycle questions, three different answers. "Is there a cycle" is this section (any back edge). "Is there an odd cycle" is §14 (a same-colour edge in the BFS parity colouring). "Is there a cycle through vertex v" is neither: it is whether v lies in a strongly connected component of size ≥ 2 or has a self-loop (§22, directed), or whether v has two incident edges in the same biconnected block (§24, undirected).

19 Connected components of an undirected graph: the outer loop counts them, and union-find agrees

The connected components of an undirected graph are the equivalence classes of the relation "there is a path from u to v": maximal sets of mutually reachable vertices. One traversal from any vertex reaches exactly its component, so the outer loop of §10 — start a new search at each vertex not yet visited — labels every vertex with a component number in Θ(V + E), one number per search started. The same question has a second algorithm with a different shape, union-find, which processes edges one at a time and is the right tool when the graph grows while you ask; it is named here and built where it belongs.

Three notions of connectivity, and which this section is about

This section is the undirected case, where one traversal from s settles the matter because paths run both ways. For a directed graph the same outer loop still produces a forest, but its trees are not components of anything meaningful: a DFS from a on G2 reaches a b c d e, which is not a strongly connected set (d cannot reach a) and not a weak component either — it is weakly connected, but not maximal, since the whole of G2 is weakly connected. The directed analogues are two different questions with two different algorithms: weak components — the components of the graph with arrows erased — by exactly this section's algorithm on the undirected version; and strong components — maximal sets in which every vertex reaches every other — by the two-pass or low-link algorithms of §22–§23. The word "connected" without a qualifier means the undirected notion, and it is a mistake to apply it to a digraph without saying which of the other two is meant.

When to use which. A static graph, one question: traverse (this section), Θ(V + E), no extra structure. Edges arriving over time with "are these connected yet?" queries between arrivals: union-find, near-linear total, and it is also the inner loop of Kruskal's algorithm — which is why the structure is built on the MST part rather than here (§27). Edges also leaving: neither; that is dynamic connectivity, a harder problem with its own structures.
