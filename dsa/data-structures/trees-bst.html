01 Vertices, edges, and the tree special case

A graph G = (V, E) is a set of vertices joined by edges — a bare model of "these things are related". A tree is the well-behaved special case: connected and acyclic. Road maps, dependency chains, file systems and computation graphs are all one of these two shapes.

Graph vocabulary

  • Write n = |V|, m = |E|. Edges may be directed or undirected, weighted or not. A directed graph with no cycles is a DAG — the shape of every dependency problem.
  • Degree counts incident edges; a path visits distinct vertices along edges, a cycle returns to its start, a connected component is a maximal mutually-reachable set.
  • Density decides every bound. Sparse means m = O(n); dense means m ≈ n². Since m ≤ n(n−1)/2, a bound of O(n + m) is never worse than O(n²) — and on sparse graphs it is far better.

What makes a tree special

  • A tree on n vertices has exactly n − 1 edges and a unique path between any two vertices. Add any edge and you create exactly one cycle; remove any edge and it splits.
  • A rooted tree orients everything away from a chosen top: parent, children, depth (edges from root), height (longest downward path). A binary tree caps children at two.
  • Height is the currency. Balanced gives h = Θ(log n), degenerate gives h = Θ(n). Nearly every result below is an argument for keeping h logarithmic.
Structural identitiestree: |E| = |V| − 1 · exactly one path between any two vertices handshake lemma: ∑v∈V deg(v) = 2·|E| perfect binary tree: n = 2^(h+1) − 1 ⇒ h = log₂(n+1) − 1 = Θ(log n) simple undirected graph: 0 ≤ |E| ≤ n(n−1)/2
Takeaway: any two of connected, acyclic, |E| = n − 1 imply the third — the cheapest test for "is this a tree?".

02 Representations: list, matrix, edge list

Before any algorithm runs you choose how edges are stored — and that choice, not the algorithm, usually decides the running time.

  • Adjacency list: per vertex, its neighbours. Iterating them costs Θ(deg v), so one full sweep touches each edge once (twice, undirected) — the origin of the ubiquitous O(V + E).
  • Adjacency matrix: an n × n table of weights or flags. O(1) edge lookup, Θ(n²) space however few edges exist. Matrix powers count walks: (Aᵏ)[u][v] is the number of length-k walks.
  • Edge list: plain (u, v, w) triples — useless for neighbour queries, ideal for algorithms that sweep all edges, like Kruskal and Bellman-Ford.

03 Tree traversals and how to write them

Four orders, one shape of recursion. All that changes is when you visit the node relative to its children — and that timing is what makes each order useful.

  • Pre-order (node, left, right) emits the node before its subtrees, so the output rebuilds the tree top-down — copying, serializing, prefix expressions.
  • In-order (left, node, right) emits a BST's keys in sorted order. The proof is the invariant: the left subtree is smaller and the right larger, so by induction the concatenation is sorted.
  • Post-order (left, right, node) finishes children first, letting a node combine results computed beneath it — freeing memory, evaluating expression trees, and the backward pass in neural-network training.
  • Level-order (BFS) sweeps depth 0, then 1, driven by a queue rather than recursion — the order for "shallowest match" and row-by-row printing.
  • Recursive vs iterative: recursion is the honest version, an explicit stack the safe one. Depth is O(h), fine at log n but stack-overflowing on a skewed tree. Morris traversal threads temporary links through empty right pointers for in-order in O(1) extra space.
Traversal costevery order visits each node once: time Θ(n) DFS orders: extra space O(h) — call stack, h = height level order: extra space O(w) — w = max width, up to ⌈n/2⌉ at the leaf row
Takeaway: DFS is cheap in space on deep, narrow trees; BFS on shallow, wide ones. A perfect binary tree keeps half its nodes in the last row, so level-order peaks at ⌈n/2⌉ queued nodes while DFS never exceeds log₂ n frames.

04 Binary search trees and staying balanced

The BST invariant is one line and it buys ordered search. Keeping it and a logarithmic height is the whole engineering problem.

The invariant and its cost

  • Invariant: every key left of a node is smaller, every key right is larger. One comparison therefore discards a whole subtree — the tree version of binary search.
  • Search, insert and delete each walk one root-to-leaf path, so all cost O(h). Deletion's awkward case — two children — is settled by swapping in the in-order successor, the leftmost node of the right subtree.
  • The catch: nothing in the invariant bounds the height. Sorted inserts build a right spine, h = n − 1, a linked list in a tree costume. Random insertion order gives expected height ≈ 1.39·log₂ n — but you rarely control input order.

Self-balancing variants

  • AVL requires |height(left) − height(right)| ≤ 1 per node, repairing violations with rotations: O(1) pointer rewirings that change height while preserving the in-order sequence. Strictest balance ⇒ fastest lookups.
  • Red-black trees colour nodes so no red node has a red child and every root-to-leaf path holds the same black count. Looser height, but only O(1) amortized rotations per update — hence their use in standard-library ordered maps.
  • B-trees push fan-out high: many keys per node, so height is tiny and each node fills a disk page or cache block. Database and filesystem indexes are B-trees because the bottleneck is block fetches, not comparisons.
BSTinvariant: keys(left subtree) < key(node) < keys(right subtree) search / insert / delete: Θ(h) h = Θ(log n) balanced · h = Θ(n) skewed AVL: h < 1.44·log₂ n · red-black: h ≤ 2·log₂(n+1)
Takeaway: quote BST costs as O(h), not O(log n). The logarithm is a consequence of a balancing scheme, not of the invariant — naming which scheme you assume is what makes the answer precise. Related in shape only: the recursive splits of decision trees partition data for prediction, not for lookup.

05 Heaps, priority queues, and tries

Two more tree-shaped structures that appear constantly: the heap answers "what is the smallest?", the trie answers "what starts with this prefix?".

Binary heap

  • Invariant: every parent is ≤ (min-heap) both children. Far weaker than BST ordering — it pins only the extremum, which is exactly why it is cheap to restore.
  • A complete binary tree needs no pointers: embed it in an array. Completeness forces height ⌊log₂ n⌋, so sift-up after an insert and sift-down after an extract both cost O(log n); peeking is O(1).
  • Building in linear time: sift down every internal node bottom-up. At height h there are at most ⌈n/2^(h+1)⌉ nodes costing O(h) each, and ∑ h/2^h converges to 2 — so build-heap is O(n), not O(n log n).
  • The priority queue is the heap's interface: it drives Dijkstra, A*, Huffman coding, heapsort, and top-k selection over a stream in O(n log k).

Trie (prefix tree)

  • Edges carry characters, so a node is the prefix spelled along the path to it. Lookup and insert of a length-L word cost O(L), independent of how many words are stored; the price is many sparse child pointers, which compressed variants merge away. Prefix structures underlie autocomplete, routing tables, and vocabulary lookup in tokenization.
Array-embedded heapchildren(i) = 2i+1, 2i+2 · parent(i) = ⌊(i−1)/2⌋ peek O(1) · push / pop O(log n) · build-heap O(n) derivation: ∑h≥0 ⌈n/2^(h+1)⌉ · O(h) ≤ n · ∑h≥0 h/2^h = 2n = O(n)
Takeaway: a heap deliberately does less than a BST — it orders root-to-leaf, never left-to-right. Use it when you need a repeated extremum and never need sorted iteration.

06 Graph search: BFS and DFS

One algorithm, two containers. Hold discovered vertices in a queue and you sweep outward in layers; hold them in a stack and you plunge to the frontier. Everything else follows from that swap.

  • BFS invariant: when a vertex is dequeued its recorded distance is the true minimum hop count, and the queue always holds at most two consecutive levels with non-decreasing distances. That is precisely why BFS solves unweighted shortest paths.
  • DFS structure: mark vertices white (undiscovered), grey (on the current path), black (finished). An edge into a grey vertex is a back edge — a cycle. Reversed finishing times give a topological order.
  • Cost, derived: each vertex is discovered once and each adjacency entry examined once — twice per undirected edge — giving O(V + E), plus O(V) for the visited set and frontier.
  • Visit once, not enqueue once. Marking visited only on dequeue lets the same vertex be pushed many times and the frontier blow up. Mark on push (BFS) or check on pop (DFS), consistently.

07 DAGs and topological sort

Given "A must come before B" constraints, produce a linear order respecting all of them. One exists if and only if the dependency graph is acyclic.

  • Kahn's algorithm: compute in-degrees, queue the zero-in-degree vertices, then repeatedly output one and decrement its successors, enqueuing any that reach zero. Each vertex and edge is handled once ⇒ O(V + E).
  • Cycle detection comes free: if the output is shorter than V, the leftover vertices form a cycle and no valid order exists.
  • DFS variant: append each vertex when it finishes, then reverse — a vertex finishes only after all its descendants, so reversal puts prerequisites first.
  • The order is usually not unique: every tie among zero-in-degree vertices is a free choice. It powers build systems, schedulers, spreadsheet recalculation, and ordering operations in a computation graph before gradients flow back.
Topological orderfor every edge (u → v): position(u) < position(v) exists ⇔ the graph is a DAG · cost O(V + E) Kahn termination: |output| < |V| ⇒ a cycle remains
Takeaway: "order these under constraints" and "is there a circular dependency?" are the same question, answered in one pass.

08 Shortest paths: pick the right tool

Every shortest-path algorithm is built from one operation — edge relaxation. They differ only in the order they relax, and in what that order assumes about the weights.

  • Unweighted: plain BFS in O(V + E). Never reach for Dijkstra when all weights are equal.
  • Dijkstra extracts the unfinalized vertex with the smallest tentative distance and relaxes its edges. Invariant: an extracted vertex's distance is final — true only because no detour can be cheaper when weights are non-negative. Binary heap: O((V + E)·log V).
  • Bellman-Ford assumes no ordering: relax every edge V − 1 times, since a shortest path uses at most V − 1 edges. If a V-th pass still improves anything, a reachable negative cycle exists and no shortest path is defined.
  • Floyd-Warshall does all pairs by DP over allowed intermediate vertices — see Dynamic Programming. A* is Dijkstra with a heuristic added to the key, still optimal when the heuristic never overestimates.

09 Union-find and minimum spanning trees

Disjoint-set union answers "are these two in the same component?" in near-constant amortized time, and it is the engine that makes Kruskal's MST practical.

Disjoint-set union

  • Each set is a tree whose root is its representative: find(x) climbs to the root, union(a, b) links one root under another. Done naively those trees grow tall and find degrades to O(n).
  • Union by rank/size always hangs the shorter tree under the taller, capping height at O(log n). Path compression re-points every node visited during a find straight at the root, flattening the path just walked.
  • Together, m operations on n elements cost O(m·α(n)) with α the inverse Ackermann function — below 5 for any realistic input. This is amortized: one find can still be slow, but it pays for the cheap ones after it.

Minimum spanning trees

  • An MST connects all vertices using V − 1 edges of minimum total weight. Both classic algorithms are greedy and both are justified by the cut property: for any vertex partition, the lightest crossing edge belongs to some MST. Kruskal sorts edges and adds each one joining two different components (a union-find query); Prim grows a single tree, always absorbing the cheapest leaving edge via a priority queue — Dijkstra's skeleton with a different key.
Union-find & MSTunion by rank + path compression: m operations in O(m · α(n)), α(n) ≤ 5 in practice cut property: the lightest edge crossing any cut lies in some MST Kruskal O(E log E) · Prim (binary heap) O(E log V) · MST has V−1 edges
Takeaway: union-find handles incremental connectivity only — merges and membership, never edge deletion. That restriction is exactly what buys the near-constant amortized cost.

10 Pitfalls and interview checklist

Most graph bugs are not algorithmic — they are a missing visited set, an unstated weight assumption, or a bound quoted for the wrong representation.

Common mistakes

  • No visited set on a cyclic graph ⇒ infinite loop. Tree code survives without one; graph code never does.
  • Quoting O(log n) for an unbalanced BST — the honest bound is O(h).
  • Dijkstra with negative weights: wrong answers, not crashes. Also, the lazy-deletion heap variant needs a stale-entry check on pop.
  • Recursion depth on a skewed tree or long path graph — use an explicit stack when depth approaches n.
  • Directed vs undirected: adding one direction to an undirected list halves the graph; adding both to a directed one invents edges.
  • Disconnected graphs: one BFS misses other components — loop over all unvisited vertices for global tasks.

Questions to answer before you code

  • Directed or undirected? Weighted? Can weights be negative? Disconnected? Self-loops or parallel edges?
  • What are V and E? Sometimes the graph is implicit — grid cells, board states, word transformations — and never built at all.
  • Which representation, and does that make traversal O(V + E) or O(V²)? Can you state the invariant and the assumption it rests on?
