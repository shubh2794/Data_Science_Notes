Sorting & Searching

Sorting puts data into order; searching locates an element. The two are deeply linked: sorting once turns every later lookup from a linear scan into a logarithmic search.

  • Properties that classify a sort: stable — equal keys keep their original relative order; in-place — uses only O(1) auxiliary memory; and its best / average / worst time. The right trade-off depends on whether you care about memory, stability, or guaranteed worst case.
  • The comparison-sort floor: any algorithm that only compares pairs of keys needs at least Ω(n log n) comparisons in the worst case — you cannot do better than n log n by comparing alone. Non-comparison sorts dodge this by using the keys' structure.
  • Simple O(n²) sorts: bubble, insertion, and selection sort are easy to reason about and fine for tiny or nearly-sorted inputs, but their nested passes cost O(n²).
  • Merge sort: divide-and-conquer — split the array in half, sort each half recursively, then merge the two sorted halves in one linear pass. The recurrence T(n) = 2T(n/2) + Θ(n) solves to Θ(n log n) in every case; it is stable but needs O(n) extra space.
  • Quicksort: pick a pivot, partition so smaller keys go left and larger go right (Lomuto or Hoare schemes), then recurse on each side. Average O(n log n) and in-place, but a bad pivot on already-sorted data degrades to O(n²).
  • Heap sort & counting sort: heap sort builds a heap then repeatedly extracts the max — O(n log n), in-place, not stable. Counting sort is non-comparison: it tallies occurrences over a key range of size k for O(n+k), sidestepping the Ω(n log n) floor.
  • Searching: linear search scans until it finds the target — Θ(n) average and worst, O(1) best. Binary search needs sorted data and halves the search space each step ⇒ O(log n), the same n/2ᵏ = 1 ⇒ k = log₂ n derivation from Big-O Complexity. Sorting itself rides on Arrays & Strings layout.

Database indexes are essentially persistent sorted-and-searchable structures, and approximate nearest-neighbor methods such as HNSW in Vector Databases are search algorithms over a graph of sorted candidates.
