Context-Length Extension

A model trained at 4K tokens breaks if you feed it 32K — it has never seen those positions. Context-length extension is the set of tricks that let a pretrained model handle far longer inputs than it was trained on.

LLMs & Generative AI Long context Positional encoding

01 Two problems with going long

  • Positions: the model only learned position patterns up to its training length; positions beyond that are out-of-distribution and degrade quality.
  • Cost: attention is O(n²) in sequence length — 8× the context is ~64× the attention compute and a much bigger KV cache.
  • Extension techniques tackle both: remap positions into a familiar range, and make long attention affordable.
One sentence: teach (or trick) a model into treating long positions like the short ones it was trained on — cheaply.

02 Why RoPE extrapolation fails

Rotary position embeddings rotate query/key vectors by an angle proportional to position.

  • RoPE encodes position as a rotation; relative position falls out of the dot product of two rotated vectors.
  • It's smooth, but the model never saw rotation angles beyond its training length — so naive extrapolation past that length produces unfamiliar angles and the model falls apart.
  • The fix is to keep angles inside the trained range, even for longer sequences.

03 Position interpolation

Instead of extrapolating to new positions, squeeze the longer sequence back into the trained range. Stretch the target length and watch the positions compress.

Extrapolation vs interpolation of positions Trained range is fixed; interpolation rescales long positions to fit inside it

Linear position interpolation divides every position index by the scale factor, so position 8000 in a 2×-extended model is treated like position 4000 — inside the trained range. A short fine-tune adapts the model to the squeezed positions.

04 The methods

05 Making long attention affordable

  • Efficient kernels: FlashAttention removes the memory blow-up of the n×n matrix (same result, far less memory traffic).
  • Sparse / sliding-window attention: attend locally, recover global reach through depth (see Attention).
  • KV-cache compression: GQA/MQA/MLA shrink the cache that dominates long-context memory.

06 Does it actually work?

  • Needle-in-a-haystack: hide a fact at a random depth in a long context and test retrieval — a stress test for true long-context use.
  • Lost in the middle: usable context length is often shorter than the advertised window; accuracy sags for mid-context information.
  • So a big context window is necessary but not sufficient — context engineering still matters.

07 Takeaways

  • Two barriers to long context: unseen positions and quadratic cost.
  • Position interpolation (PI → NTK → YaRN) squeezes long positions into the trained range instead of extrapolating, plus a short fine-tune.
  • Efficient attention + KV-cache compression make the length affordable.
  • Validate with needle-in-a-haystack — advertised ≠ usable length, and "lost in the middle" persists.
  • Builds on Transformers/RoPE and Attention.
