LoRA: Low-Rank Adaptation

Freeze the pretrained weight W₀ and learn only a low-rank update ΔW = BA beside it. This page goes past the parameter count: why the update should be low-rank at all, what the zero-initialised B and the α/r scale actually do, what gradient descent on a factorised update converges to, which attention matrices to adapt, why rank 1 is often enough, what the learned ΔW amplifies inside W₀, and where the method stops working.

01 Why another adaptation method: the three costs it was built to avoid

Full fine-tuning stores a whole model per task; adapter layers add sequential depth and therefore latency; prefix tuning is hard to optimise and eats context. LoRA is designed to avoid all three at once — small per-task storage, no added inference latency, and no change to the input sequence.

  • Storage and deployment. Fully fine-tuning a 175B-parameter model produces another 175B-parameter model per task. Holding many independent instances of that in memory, or swapping them in, is prohibitive. (The general trade-offs of updating everything are on the fine-tuning & transfer learning page.)
  • Adapters cost latency, worst exactly where serving lives. Adapter layers are extra modules executed in series with the existing ones. Large models already saturate hardware through parallelism, so the extra depth cannot be hidden — and it hurts most at small batch sizes, which is the online-inference regime.
  • Prefix tuning is hard to optimise and costs sequence length. Its quality changes non-monotonically with the number of trainable parameters, and every position reserved for the learned prefix is a position the task input cannot use. In the reported large-model experiments, quality dropped beyond about 256 special tokens for prefix-embedding tuning and beyond about 32 for prefix-layer tuning.

02 The bet: the update has low intrinsic rank

Earlier work on intrinsic dimension showed that over-parameterised pretrained models can still be fine-tuned effectively after a random projection of the trainable parameters into a surprisingly small subspace. LoRA makes the analogous bet about the weight update: the change a task needs, ΔW, has low "intrinsic rank", even though W₀ itself is full-rank.

two different claims, often blurredintrinsic DIMENSION (prior work): the fine-tuning trajectory can be confined to a random d_int-dimensional subspace of ALL params with d_int ≪ total, and still work. intrinsic RANK (the LoRA bet): each adapted matrix's update ΔW ∈ ℝ^(d×k) is well approximated by rank r ≪ min(d, k).

The second is a structural assumption per matrix, and it is cheaper to exploit: a rank-r matrix factors as a product of a d×r and an r×k matrix, so it costs r(d + k) numbers instead of dk. Whether the bet is true is an empirical question; §08 and §09 are the evidence, and §11 records where it is expected to fail.

The intuition. Pretraining has already built the features. Adapting to a task mostly means re-weighting a few directions the model already represents — a low-dimensional steer, not a rebuild. The SVD page is the background for "rank" and "directions" used throughout.

03 The parameterisation, the initialisation and the scale

Every detail of the forward pass below is there for a reason: the zero B makes training start exactly at the pretrained model, and the α/r factor decouples the step size from the rank.

forward pass of one adapted linear layerh = W₀x + ΔWx = W₀x + (α / r) · B A x W₀ ∈ ℝ^(d×k) frozen, full-rank, receives no gradient B ∈ ℝ^(d×r) trainable, initialised to 0 A ∈ ℝ^(r×k) trainable, initialised random Gaussian r ≪ min(d, k) trainable numbers per adapted matrixr · (d + k) instead of d · k d = k = 12288 (a 175B-scale model width), r = 4: 98 304 vs 150 994 944 → 0.065% of the matrix

Why B = 0 and A random — and not both zero

gradients, with g = ∂L/∂h and scale s = alpha / r∂L/∂B = s · g (A x)ᵀ ∂L/∂A = s · Bᵀ g xᵀ at step 0: B = 0 ⇒ ΔW = BA = 0 the model IS the pretrained model ∂L/∂A = 0 A does not move on the first step ∂L/∂B ≠ 0 (A is random) B starts learning immediately if both were 0: both gradients vanish forever — the adapter never trains.

So the symmetry is broken by A and the "no-op at start" property is supplied by B. After the first step B ≠ 0 and both factors train. The choice could be flipped (random B, zero A) with the same effect; what matters is that exactly one factor is zero.

What α/r is for

  • In the reported experiments α was set to the first r tried and then not tuned. With Adam, scaling the update by a constant is roughly equivalent to scaling the learning rate (given a suitably scaled initialisation), so tuning α and tuning the learning rate are nearly the same knob.
  • Dividing by r is the useful part: it keeps the size of the update from growing with the rank, which reduces the need to retune hyperparameters when r changes. (A later refinement argues the right divisor is √r; see §12.)

A generalisation of full fine-tuning, not an approximation of the model

Adapt every weight matrix with r equal to its full rank and LoRA can express any update full fine-tuning can — it roughly recovers full fine-tuning's expressiveness. As the trainable budget grows, LoRA converges to training the original model. The alternatives do not have this property: adapter-based methods converge to training an extra MLP, and prefix-based methods to a model that cannot take long inputs.

04 Fitting a low-rank update: what gradient descent on BA finds

No rank-r matrix can be closer to a target ΔW* than its truncated SVD, and the error is exactly the discarded singular values (Eckart–Young). LoRA never computes an SVD — it runs gradient descent on B and A — but from B = 0 it typically lands on that floor, learning the target's directions largest-first.

the floor any rank-r adapter is bounded byΔW* = ∑ᵢ σᵢ uᵢ vᵢᵀ (SVD of the update the task "wants") min over rank(BA) ≤ r of ‖BA − ΔW*‖_F = √( ∑_(i>r) σᵢ² ) relative floor(r) = √( ∑_(i>r) σᵢ² ) / ‖ΔW*‖_F

A LoRA adapter of rank r is trained on ½‖BA − ΔW*‖²_F by plain gradient descent from LoRA's own initialisation (B = 0, A Gaussian), with α = r so the scale is 1. The bars show, for each of the target's singular directions, how much of it the adapter has learned so far: uᵢᵀ(BA)vᵢ against σᵢ. The full statement and proof of Eckart–Young is on the SVD page.

A rank-r adapter learning a target update, against the Eckart–Young floor set r below the intrinsic rank and the loss stalls on the floor; set it at or above and the floor drops to the noise
  • Largest-first is a property of the dynamics, not of LoRA's definition. From a small or zero start, factorised gradient descent grows each direction at a rate proportional to its singular value, so the plateaus in the loss curve appear in order. That is one reason a too-large r mostly wastes capacity on small, noisy directions rather than harming the large ones — the same picture the subspace analysis of §09 finds in real adapters.
  • The toy knows the target; real fine-tuning does not. In a real model there is no ΔW* to fit — the loss is the task loss through the whole network. The toy isolates one question: given an update of some intrinsic rank, how much a rank-r factorisation can capture, and what training does to approach that.

05 Merge for zero latency, switch tasks cheaply — and the mixed-batch catch

Because the update is additive and linear, it can be folded into the weight once: W = W₀ + BA. The deployed model is then an ordinary dense model of the original shape, with exactly the original inference cost.

merge, switch, unmergedeploy task 1: W ← W₀ + B₁A₁ once; no extra latency afterwards switch to task 2: W ← W − B₁A₁ + B₂A₂ two rank-r products per matrix — cheap, and little extra memory kept UNMERGED, per request i with adapter t(i): hᵢ = W₀xᵢ + B_t(i) A_t(i) xᵢ extra MACs per token: r(d + k) vs the base's d·k

The catch is in the last line. A merged weight is one task. A batch that mixes requests for different tasks cannot share a single merged forward pass — you either serialise by task (re-merging between groups) or keep the adapters unmerged and pick the adapter per sample, paying a small extra cost for every token. The latter is how multi-adapter serving systems run many fine-tunes on one copy of the base; batching and scheduling for that setting are on the LLM serving page.

One batch, several tasks: merged weights vs unmerged adapters with one task, merging is free; add a second task to the batch and count what each strategy costs
Combining several adapters into one is a different operation from switching between them: it is weight-space merging, and the rule there is to merge the products BᵢAᵢ, never the factors separately. Model merging owns that, including why averaging As and Bs produces meaningless cross terms.

07 Which weight matrices to adapt, at a fixed budget

The original study adapted only the attention projections — Wq, Wk, Wv and Wo, each treated as a single d_model × d_model matrix — and froze the MLP blocks. Holding the trainable budget at about 18M parameters on the 175B model, it asked where those parameters should go.

  • Breadth beats depth. Spreading the same budget over more matrices at lower rank beats putting it all into one matrix at higher rank — consistent with the update having low rank per matrix: extra rank in one place buys little.
  • Wq alone or Wk alone is clearly worse (about 3 points on WikiSQL). Adapting the value or output path matters more than adapting only how attention scores are computed.
  • Wq + Wv is the strong default the rest of the study uses; all four at r = 2 is as good or slightly better.

08 How small can r be? Flat from 1 to 64

With Wq and Wv both adapted, rank 1 is already competitive, and going to rank 64 — 64× the parameters — buys essentially nothing. Wq alone benefits from a little more rank, which hints that its update is less low-rank (§09).

Reported accuracy against LoRA rank on the 175B model — and the fixed-budget comparison note how zoomed the vertical axis has to be before any rank dependence becomes visible
Reading this correctly. "Rank 1 suffices" is a statement about these tasks on a very large pretrained model, with two or more matrices adapted per layer. It is evidence for the low-intrinsic-rank bet, not a universal setting — §11 notes tasks far from the pretraining distribution, and §12 how practice moved to larger ranks once all linear layers were adapted.

09 Inside the learned ΔW: shared directions, noise, and amplification

Two questions the accuracy tables cannot answer: do adapters of different rank learn the same thing? and how does ΔW relate to the W₀ it is added to?

Rank 8 and rank 64 agree on the top direction

normalised subspace similarity between two learned A matricesφ(A₁, A₂, i, j) = ‖ U₁⁽ⁱ⁾ᵀ U₂⁽ʲ⁾ ‖²_F / min(i, j) ∈ [0, 1] U⁽ⁱ⁾ = the top-i right-singular vectors of A 1 = one subspace contains the other 0 = orthogonal
  • Comparing A learned at r = 8 with A learned at r = 64: the top singular directions overlap significantly; for both ΔWq and ΔWv the two runs share a one-dimensional subspace with similarity above 0.5. That is the direct explanation for §08's flat curve — rank 1 already holds the direction that matters.
  • The remaining directions of the rank-64 adapter overlap little with the rank-8 one: they look like noise accumulated during training rather than additional structure.
  • Across random seeds, ΔWq appears to have a higher intrinsic rank than ΔWv — more shared directions between runs — matching the observation that Wq alone benefits from more rank.

ΔW amplifies what W₀ under-weights

Take the SVD of ΔW, keep its top-r left and right singular vectors U and V, and project the pretrained W onto that subspace: ‖UᵀWVᵀ‖_F. If ΔW just repeated W's dominant directions, this would be large; if it were unrelated, it would be as small as for a random subspace.

layer 48 of the 175B model, Wq, r = 4subspace U, V taken from ‖UᵀWqVᵀ‖_F ΔWq (the learned update) 0.32 Wq itself (its own top-4) 21.67 a random matrix 0.02 ‖Wq‖_F = 61.95 ‖ΔWq‖_F = 6.91 amplification factor = ‖ΔWq‖_F / ‖UᵀWqVᵀ‖_F ≈ 21.5 (the reported figure; the two-decimal norms above give 6.91 / 0.32 ≈ 21.6)
  • Correlated, but not with the top. 0.32 is far above random (0.02), so ΔW lives in directions related to W; but it is far below 21.67, so those are not W's dominant directions.
  • It amplifies features already present but weak. Along its own directions W has norm about 0.32; the update adds about 6.91 there — roughly a 21× boost of directions the pretrained weights under-emphasise. The reading is that adaptation turns up task-relevant features the general model learned but did not prioritise.
  • At r = 64 the amplification factor is much smaller, consistent with the extra directions being mostly noise rather than additional amplified features.

11 Limitations the original study states

serving
Merged means single-task
Once BA is folded into W, inputs for different tasks cannot share one forward pass. Keeping adapters unmerged and choosing per sample works where latency is less critical (§05).
design
No principled choice of matrices
Which matrices to adapt was settled by heuristics and ablation (§07). Adapting the MLP, LayerNorm or biases was left unexplored.
rank
Small r is not universal
A task far from pretraining — for example, a downstream language very different from the pretraining data — may need a much larger rank.
composition
Orthogonal to other methods
LoRA can be combined with other approaches, such as prefix tuning; it changes weights, not the input sequence.

Well-known successors, one line each

  • rsLoRA — scales the update by α/√r instead of α/r, so that large ranks keep learning instead of having their updates shrink; this makes higher r actually useful.
  • DoRA — decomposes each weight into a magnitude vector and a direction, trains the magnitude directly and applies a LoRA update to the direction.
  • LoRA+ — uses a larger learning rate for B than for A, motivated by the asymmetry of the two factors' roles.

13 Common misconceptions

"LoRA approximates the weight matrix with a low-rank one." No — W₀ stays full-rank and untouched. Only the update ΔW is constrained to rank r. The adapted weight W₀ + BA is full-rank. Compressing W itself with a truncated SVD is a different technique (low-rank compression) with very different quality costs.
"LoRA makes inference cheaper." No — merged, it costs exactly the same as the base model; unmerged, slightly more. What LoRA reduces is training memory (no optimiser state for frozen weights), training time, and per-task storage (§06).
"Higher rank is always better, it is just more expensive." Not in the reported results. Accuracy is flat from r = 1 to r = 64 when two or more matrices are adapted (§08), and the extra directions of a high-rank adapter look like noise (§09). Where more rank does help — distant domains, many adapted modules — it is a property of the task, not of the method.
"You can average two LoRA adapters by averaging their A and B matrices." No — merge BᵢAᵢ, not the factors. Averaging factors creates cross terms B₁A₂ + B₂A₁ that never trained together (model merging §07).
"Initialising both A and B to zero would be safer." It would never train. With both zero, both gradients are zero (§03). Exactly one factor must be zero for the no-op start, and the other must be random to break the symmetry.

14 Takeaways

  • Freeze W₀, learn ΔW = (α/r)·BA with r ≪ min(d, k): r(d + k) trainable numbers per matrix instead of dk.
  • B = 0, A random: training starts exactly at the pretrained model, and the symmetry is still broken.
  • α/r decouples the update size from the rank; with Adam, α is nearly a learning-rate knob.
  • Merge W₀ + BA for zero added latency; switch tasks by subtracting one product and adding another; keep adapters unmerged to batch mixed tasks.
  • Spread the budget across matrices at low rank; Wq + Wv at r = 1–4 is already competitive on a 175B model.
  • The learned ΔW concentrates in a very few directions that runs of different rank agree on, and it amplifies features W₀ has but under-weights — by about 21× at r = 4 in the measured layer.
  • Limits: merged adapters are single-task, matrix choice is heuristic, and distant tasks may need large rank.
