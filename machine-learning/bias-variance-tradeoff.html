Bias-Variance Tradeoff

A model can be wrong in two opposite ways: too rigid to represent the truth (bias), or too sensitive to the particular sample it was trained on (variance). Under squared loss those two errors, plus irreducible noise, add up exactly — which turns a vague intuition about over- and underfitting into an equation you can measure. Plus the modern twist where the classic U-curve is only half the story.

Machine Learning Generalization Fundamentals

01 Two sources of error

Expected test error at a point splits into bias, variance, and irreducible noise — three quantities with three different cures.

The whole idea rests on a thought experiment. Fix one input x₀. Now imagine drawing many different training sets of the same size from the same distribution, refitting your model on each one, and recording what each fit predicts at x₀. You get a cloud of predictions, not a single number. Two things make that cloud miss the truth: its centre can sit away from the true value (bias), and it can be wide (variance). On top of that, the label you are trying to match is itself noisy, and no model can predict noise.

the decomposition, under squared lossE[(y − f̂(x₀))²] = ( E[f̂(x₀)] − f(x₀) )² + E[( f̂(x₀) − E[f̂(x₀)] )²] + σ² └──── bias² ────┘ └──────── variance ────────┘ └ noise ┘ too simple too sensitive unavoidable
  • Bias — error from wrong assumptions. The model class simply cannot express the true function, so even with infinite data it stays off. A straight line fitted to a sine wave has bias no amount of data will fix. Symptom: underfitting.
  • Variance — error from sensitivity to which particular rows you happened to sample. The model chases the noise, so a fresh training set produces a visibly different fit. Symptom: overfitting.
  • Irreducible noise σ² — the part of y that x does not determine (measurement error, missing features, genuine stochasticity). It is the floor of achievable test error, sometimes called the Bayes error.
  • Bias and variance are properties of the learning procedure on a data distribution, not of one fitted model. You cannot read them off a single training run — which is why we estimate them via resampling.
Takeaway: a single trained model is one draw from a distribution of models. Generalization error asks about that whole distribution — where it is centred (bias) and how much it wobbles (variance).

02 Deriving the decomposition

Three lines of algebra, both cross-terms vanish, and the identity is exact — not an approximation.

Setup and notation

Assume the data-generating process y = f(x) + ε with E[ε] = 0 and Var[ε] = σ², and that ε at test time is independent of the training set D. Write f̂ = f̂_D(x₀) for the prediction of the model trained on D, and f̄ = E_D[f̂] for the average prediction over training sets — the centre of the cloud. All expectations below run over both D and the fresh noise ε.

step 1 — peel off the noiseE[(y − f̂)²] = E[((f + ε) − f̂)²] = E[(f − f̂)²] + 2·E[ε·(f − f̂)] + E[ε²] E[ε·(f − f̂)] = E[ε]·E[f − f̂] = 0 (ε is independent of D and has mean 0) ⟹ E[(y − f̂)²] = E[(f − f̂)²] + σ² step 2 — add and subtract the average prediction f̄E[(f − f̂)²] = E[( (f − f̄) + (f̄ − f̂) )²] = (f − f̄)² + E[(f̄ − f̂)²] + 2·(f − f̄)·E[f̄ − f̂] E[f̄ − f̂] = f̄ − E[f̂] = 0 (that is the definition of f̄) step 3 — name the piecesE[(y − f̂)²] = (f̄ − f)² + E[(f̂ − f̄)²] + σ² = Bias² + Variance + Noise

A worked numeric example

Suppose the truth at x₀ is f(x₀) = 2.5, the noise variance is σ² = 0.25, and refitting on three different training sets gives predictions 2.0, 3.0, 4.0.

plugging inf̄ = (2.0 + 3.0 + 4.0)/3 = 3.0 bias = f̄ − f = 3.0 − 2.5 = 0.5 bias² = 0.25 variance = [(2.0−3.0)² + (3.0−3.0)² + (4.0−3.0)²]/3 = 2/3 ≈ 0.667 expected squared error = 0.25 + 0.667 + 0.25 = 1.167 ← variance dominates: this learner is unstable, not biased

Fine print worth knowing

  • The identity is pointwise. Overall test error is the average of the three terms over the input distribution, so a model can be bias-dominated in one region and variance-dominated in another.
  • It is specific to squared loss. For 0-1 classification loss there is no clean additive split — the analogues are non-additive, and variance can even reduce error when it flips a systematically wrong prediction back across the boundary. Treat "bias/variance" for classifiers as a useful metaphor, not an equation.
  • σ² never appears in training error, which is why training error can reach zero while test error cannot go below σ².
  • Bias and variance are not independently dialable. Nearly every knob you have moves both, in opposite directions — hence "tradeoff".
Takeaway: the cross-terms die because E[ε] = 0 and E[f̂] = f̄ by construction. Everything else in this page is about which design choices push on which of the three surviving terms.

03 The tradeoff curve

As capacity grows, bias falls monotonically and variance rises — so the sum is U-shaped. Slide complexity to find the sweet spot.

Adding capacity strictly enlarges the set of functions your model can express, so the best achievable approximation gets closer to f and bias falls. But a richer class also has more freedom to interpolate whatever noise happens to be in the sample, so refits differ more from each other and variance rises. Because the total is a sum of a decreasing and an increasing term, its minimum sits strictly inside the range — you should be neither as simple as possible nor as flexible as possible. The minimum is also flat-bottomed in practice: near the optimum a lot of complexity settings perform within noise of each other, which is why tuning gets diminishing returns fast (see Hyperparameter Tuning).

the shape, schematicallyErr(c) = bias²(c) + var(c) + σ² bias²(c) ↓ in c, var(c) ↑ in c at the optimum c*: d(bias²)/dc = − d(var)/dc ← marginal bias reduction exactly pays for marginal variance
Error vs model complexity Toggle "double descent" to see the modern twist
Takeaway: "more complexity is better until it isn't" is not a rule of thumb — it is a consequence of adding a falling curve to a rising one. Your job is to find c* honestly, on held-out data.

04 Seeing variance directly

Resample the training set a dozen times, refit, and the cloud of fits becomes visible. Bias is where the average fit sits; variance is how much the individual fits wobble around it.

This is the thought experiment from §01, actually run. Twelve training sets are drawn from the same true curve with the same noise level, a polynomial of the chosen degree is fitted to each by least squares, and all twelve fits are drawn together. At degree 0 or 1 the fits sit almost on top of each other — tiny variance — but the bundle clearly misses the shape of the truth: that gap is bias. Crank the degree up and the bundle fans out into a spray of wildly different curves that each honour their own noise; the average fit tracks the truth well (bias ≈ 0) while any single fit is unreliable. The readout computes the empirical bias² and variance exactly as defined above, averaged over the plotted input range.

Twelve fits, twelve training sets thin blue = individual fits · green = average fit · dashed = truth
  • Watch the green average fit: it is nearly truth-tracking from about degree 3 onward, long before any single fit is trustworthy. That is exactly why averaging many high-variance models works — it is the mechanism behind bagging and random forests.
  • Raise σ and every term moves: noise adds a constant floor, and it also amplifies variance, because there is more noise for a flexible model to chase.
  • The fits fan out most at the edges of the input range. Extrapolation is where variance is worst — a general fact, not an artefact of this demo.
Takeaway: bias is a property of the average model; variance is a property of the spread. Once you can see both, "bagging cuts variance, boosting cuts bias" stops being a slogan.

05 Underfitting vs overfitting

Two diagnoses, two very different prescriptions — and the train/validation gap tells them apart.

The diagnostic table

Underfit (high bias)Overfit (high variance)
SymptomHigh train and high validation error, small gapLow train error, high validation error, large gap
CauseModel class too restrictive; over-regularized; under-trained; features too weakCapacity large relative to sample size; noisy labels; leakage of sample-specific quirks
Effect of more dataAlmost none — the plateau is set by the model classLarge — variance shrinks roughly like 1/n
FixRicher features, bigger model, weaker regularization, train longerRegularize, more data, simplify, ensemble, early stopping
Failure mode of the fixSwings you into overfittingSwings you into underfitting

Reading the gap correctly

The train/validation gap is the variance signal and the level of the training error is the bias signal — you need both. A model at 2% train / 12% validation is variance-limited; a model at 11% train / 12% validation is bias-limited even though the validation numbers match. Compare the training error to an estimate of the achievable floor (human performance, a strong reference model, or known label noise) rather than to zero; that comparison is the "avoidable bias" framing used in ML Strategy. And keep the split honest — a validation set you have tuned against fifty times is no longer an unbiased estimate, which is why Model Evaluation insists on an untouched test set.

Takeaway: never prescribe before you diagnose. "Get more data" is the right answer for high variance and a waste of money for high bias.

06 Learning curves

Plot train and validation error against training-set size, not epochs. The shape tells you whether more data will help before you go and buy it.

Why the two curves move the way they do

With a tiny training set the model can fit it almost perfectly, so training error starts near zero and rises as n grows and the sample becomes harder to memorize. Validation error starts terrible and falls, because variance shrinks as the estimate stabilizes. The two curves therefore converge from opposite directions, and they converge to bias² + σ² — the part of the error that more data cannot touch. The vertical gap between them at any n is essentially the variance term.

asymptoticsErr_val(n) ≈ σ² + bias² + Var(n) Var(n) ~ C/n (roughly, for a fixed model class) Err_train(n) ↗ σ² + bias² from below gap(n) = Err_val(n) − Err_train(n) ≈ 2·Var(n) → 0

What each shape means

What you seeDiagnosisDo this
Curves already met, at a high plateauHigh bias, low varianceMore capacity / better features / less regularization. More data is wasted spend.
Curves met at a low plateauNear the noise floorNothing left in this framing — improve labels or add informative features.
Wide gap, validation still falling at the right edgeHigh variance, data-limitedMore data will help; meanwhile regularize or ensemble.
Wide gap, validation flat at the right edgeHigh variance, not data-limitedSimplify, regularize, remove leaky/noisy features.
Validation below training errorSuspiciousUsually a split bug, an easier validation set, or regularization active only at train time (e.g. dropout).

Compute the points with cross-validation at each sample size — a single split at n = 200 is far too noisy to read a trend from. Log-spaced sizes (100, 300, 1000, 3000, …) are the practical choice, since the interesting behaviour is in the order of magnitude.

Takeaway: a learning curve answers the single most expensive question in an ML project — "will more data help?" — for the price of a few extra fits.

07 Knobs & levers

Every hyperparameter is really a bias-variance dial. Here is which way each one turns.

The general levers

  • More data reduces variance without adding bias — the only lever that is free of the tradeoff, and usually the best one when you can afford it.
  • Regularization (L2/ridge, L1/lasso, dropout, weight decay, early stopping, data augmentation) deliberately buys a little bias to remove a lot of variance. It shifts you left along the complexity axis without changing the model class.
  • Ensembling. Bagging averages many high-variance, low-bias models — variance falls, bias barely moves. Boosting stacks many high-bias weak learners so that each corrects the last — bias falls, and variance eventually rises if you boost too long. See Decision Trees & Ensembles.
  • Feature engineering cuts bias (better features let a simple model express the truth) but adding many weak features raises variance.
why averaging B models cuts variance (ρ = pairwise correlation between fits)Var[ (1/B)·∑ᵢ f̂ᵢ ] = ρ·σ² + (1 − ρ)·σ²/B B → ∞ ⟹ Var → ρ·σ² ← averaging only removes the uncorrelated part so: decorrelate the trees (random feature subsets, bootstrap samples) to push ρ down

Two knobs, worked out exactly

For k-nearest-neighbour regression the decomposition is closed-form: the prediction averages k noisy labels, so the noise variance divides by k, while the bias grows because far-away neighbours are being pulled in.

kNN regression at x₀, with neighbours x₍₁₎ … x₍ₖ₎f̂(x₀) = (1/k)·∑ⱼ₌₁..ₖ y₍ⱼ₎ E[(y − f̂(x₀))²] = σ² + [ f(x₀) − (1/k)·∑ⱼ f(x₍ⱼ₎) ]² + σ²/k noise bias² variance k = 1 ⟹ variance = σ² (maximal), bias ≈ 0. k = n ⟹ variance ≈ 0, model = the global mean.

For ridge regression with an orthonormal design, the penalty shrinks every coefficient by the same factor, which makes the tradeoff arithmetic:

ridge, orthonormal design (XᵀX = I)β̂ᵣᵢ𝒹ᵍₑ = β̂ₒₗₛ / (1 + λ) bias(β̂ⱼ) = −λ·βⱼ / (1 + λ) Var(β̂ⱼ) = σ² / (1 + λ)² λ = 0 → unbiased, full variance. λ → ∞ → zero variance, bias = −βⱼ (predicts nothing). example: βⱼ = 2, σ² = 1, λ = 1 ⟹ bias² = 1, Var = 0.25, sum = 1.25 vs 0 + 1 = 1 at λ = 0 λ = 0.2 ⟹ bias² = 0.111, Var = 0.694, sum = 0.805 ← a real improvement

08 Double descent

Past the point where a model can fit the training data exactly, test error stops rising and starts falling again. The classic U-curve is the first half of a longer story.

The interpolation threshold

Track test error as capacity grows past the classic optimum and it does rise — as advertised — but it peaks at the interpolation threshold, roughly where the number of effective parameters equals the number of training examples (p ≈ n). There, exactly one solution fits the data, and it is forced to be a wild one: with no slack, the model must contort itself through every noisy point. Push capacity further and something changes qualitatively — now many solutions fit the training data perfectly, and the optimizer gets to choose among them.

the regime variableratio = p / n (effective parameters per training example) ratio ≪ 1 : classic regime — U-curve, bias falls then variance wins ratio ≈ 1 : interpolation threshold — a single, badly-conditioned exact fit; test error peaks ratio ≫ 1 : over-parameterized — many exact fits; the optimizer picks a smooth, low-norm one; error falls again

Why the second descent happens

  • Gradient descent from small initialization tends to converge to the minimum-norm interpolating solution — an implicit regularizer nobody asked for. Among all the ways to fit the noise, it picks a smooth one.
  • Extra capacity therefore does not buy extra wiggliness in the direction that hurts; it buys more room to satisfy the data while staying flat.
  • The same non-monotone shape shows up along other axes: epoch-wise (train longer and test error can dip, rise, and dip again) and sample-wise (more data can transiently hurt if it drags you toward p ≈ n).
  • Explicit regularization at the right strength largely flattens the peak — double descent is most visible when the model is under-regularized.

What it does and doesn't change

It does not repeal the decomposition — bias, variance and noise still add up. What it repeals is the assumption that variance rises monotonically with parameter count. Practically: do not choose a model by parameter count alone, do not stop scaling because the validation curve ticked upward once, and do not read "more parameters than data" as automatic overfitting. On small tabular problems with a modest model you are almost certainly still in the classic regime and the U-curve advice applies unchanged.

Takeaway: capacity is not the same thing as effective complexity. What generalizes is the norm of the solution the optimizer lands on, not the number of slots it had available.

09 Pitfalls & what to remember

Pitfalls

  • Diagnosing from one number. Validation error alone cannot distinguish bias from variance — you need the training error too, and ideally a learning curve.
  • Comparing training error to zero. Compare it to the achievable floor. If labels are 8% noisy, 8% training error is perfect, not underfit.
  • Tuning against the test set. Every decision made by looking at held-out data leaks a little; after enough looks the estimate is optimistic. Use a validation set for choices and reserve the test set for one final number.
  • Treating the split as an afterthought. Random splits on grouped, temporal, or duplicated data massively understate variance. Group- and time-aware splits are part of the diagnosis.
  • Assuming ensembles fix everything. Bagging cuts variance only to the extent the members are decorrelated; averaging ten copies of the same biased model changes nothing.
  • Over-reading the classifier metaphor. The exact identity is a squared-loss result; for accuracy it is a heuristic.

What to remember

  • Err = bias² + variance + σ², exactly, under squared loss. Bias = wrong on average; variance = unstable across samples; σ² = unbeatable.
  • Complexity trades one for the other, so total error is U-shaped and the optimum is interior.
  • Diagnose with the train/validation gap and a learning curve; fix with data, regularization, ensembling, or capacity — matched to the diagnosis.
  • Double descent means "past the interpolation threshold, bigger can be better again" — capacity ≠ effective complexity.
