Decision Trees & Ensembles

SupervisedTree-based Recursively split the feature space to lower impurity — then combine many trees (bagging, boosting) to beat any single one.

Overview

A decision tree recursively partitions the data by feature values, forming a flowchart of yes/no questions. It's non-parametric (no distribution assumptions), strongly non-linear (axis-aligned rectangular regions), and handles both classification and regression.

  • Root node — the whole dataset; the first split.
  • Decision (internal) nodes — where data is split on a feature threshold.
  • Leaf nodes — terminal nodes holding the final prediction.
  • Branches — the outcomes connecting them.
No scaling needed. Splits depend only on a feature's rank/order (is x > 40?), not its magnitude — so unlike kNN/SVM, trees are invariant to feature scaling and robust to outliers.

Splitting criteria — how a node chooses its question

At each node, the tree evaluates candidate splits and picks the one that most reduces impurity (classification) or variance (regression).

Gini impurity (0 = pure) · weighted impurity after a splitGini = 1 − Σᵢ pᵢ² Gini_split = (N_L/N)·Gini_L + (N_R/N)·Gini_R
entropy & information gain (classification)Entropy = − Σᵢ pᵢ · log₂(pᵢ) Information Gain = Entropy_parent − Σ (Nₖ/N)·Entropy_child
variance reduction (regression)Reduction = Var_parent − (N_L/N)·Var_L − (N_R/N)·Var_R
Gini worked example. A node with 6 A and 4 B: Gini = 1 − (0.6² + 0.4²) = 0.48. Split into Left {3A,1B} → 0.375 and Right {3A,3B} → 0.5. Weighted: (4/10)·0.375 + (6/10)·0.5 = 0.45. Impurity dropped 0.48 → 0.45, so the split is worthwhile.

Building the tree & making predictions

  1. Select the best split — evaluate features with the impurity criterion, keep the one with the biggest gain.
  2. Partition the data into child subsets on that threshold.
  3. Recurse on each child.
  4. Stop when a node is pure, no features remain, max_depth is hit, or a node has too few samples.

Prediction: a new point traverses from the root, following branches by its feature values until it lands in a leaf, which gives the class (majority) or value (mean).

Overfitting, pruning & regularization

An unconstrained tree grows until every leaf is pure — memorizing noise. Two ways to rein it in:

  • Pre-pruning (early stopping) — cap growth up front: max_depth, min_samples_leaf, min_samples_split, min_impurity_decrease.
  • Post-pruning — grow the full tree, then trim weak branches. Cost-complexity pruning (ccp_alpha) removes splits whose accuracy gain doesn't justify their complexity.
  • Other tree weaknesses: instability (small data changes → very different trees), a bias toward high-cardinality features, and an inability to extrapolate beyond the training range. These motivate ensembles.

Why ensembles?

A single deep tree has low bias but high variance — accurate on training data, unstable on new data. Ensembles combine many models so that errors cancel out, beating any single tree. Two dominant strategies:

  • Bagging attacks variance — train many trees independently and average.
  • Boosting attacks bias — train trees sequentially, each fixing the last one's mistakes.

Bagging & Random Forests

Bagging (bootstrap aggregating)

  1. Bootstrap — draw many size-N samples with replacement from the data.
  2. Train a tree on each sample, independently and in parallel.
  3. Aggregate — majority vote (classification) or average (regression).

Averaging M independent models cuts variance by roughly 1/M while leaving bias unchanged — exactly what high-variance trees need.

Random Forests = bagging + feature randomness

At each split, a random forest considers only a random subset of features, which de-correlates the trees (stopping one dominant feature from controlling them all) — the key to better variance reduction.

features sampled per splitclassification: √p regression: p / 3 (p = total features)
  • Out-of-bag (OOB) error: each bootstrap omits ~37% of points; predicting those gives a free validation estimate without a holdout set.
  • Feature importance: rank features by the total impurity (Gini) decrease they produce across the forest.

Boosting & gradient-boosted trees

Boosting trains weak learners sequentially, each focused on what the ensemble so far gets wrong — reducing bias step by step.

AdaBoost

Re-weights samples: misclassified points get heavier so the next stump (depth-1 tree) focuses on them. Each learner's vote is weighted by its accuracy.

Gradient-Boosted Decision Trees (GBDTs)

Instead of re-weighting, each new tree is fit to the residuals (negative gradient of the loss) of the current model — gradient descent in function space. A small learning rate η shrinks each tree's contribution for better generalization.

residual · additive update (η = learning rate / shrinkage)rᵢ = yᵢ − ŷₜ₋₁(xᵢ) ŷₜ(x) = ŷₜ₋₁(x) + η · fₜ(x)

Base trees are kept shallow (depth 3–8). GBDTs are state-of-the-art for tabular data. Major implementations:

Overfitting watch. Because boosting chases hard samples, it can over-emphasize noise/outliers and increase variance. Tame it with a low learning rate, shallow trees, subsampling, and early stopping on a validation set.

Bagging vs. Boosting vs. Stacking

Stacking is a third strategy: train diverse heterogeneous models, then a meta-learner learns the best combination of their (out-of-fold) predictions.

Bias–variance, in one line. Bagging averages independent models → cuts variance, leaves bias. Boosting corrects errors sequentially → cuts bias (and some variance) but can overfit. So: high-variance problem → bagging; high-bias problem or max accuracy → boosting.

Pros, cons & takeaways

Single trees

  • Pros: highly interpretable, non-parametric, no scaling needed, capture non-linear interactions.
  • Cons: overfit easily, unstable, biased toward high-cardinality features, can't extrapolate.

Takeaways

  • Single trees are rarely used alone — ensembles fix their instability and accuracy.
  • Random Forests: robust, parallel, low-tuning default.
  • GBDTs (XGBoost/LightGBM/CatBoost): best accuracy on tabular data, with more tuning.
  • All are non-parametric, non-linear, scale-invariant, and provide feature importances.
