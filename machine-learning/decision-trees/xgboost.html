XGBoost: Scalable Tree Boosting

The hub page describes gradient boosting as fitting each new tree to the residuals of the current model. XGBoost keeps that additive model but changes two things. Each tree is fitted to a second-order expansion of a regularised objective, which gives closed-form leaf weights and a split gain that works for any twice-differentiable loss. And the engineering around split finding (weighted quantile candidates, learned directions for missing values, pre-sorted column blocks, cache-aware access, compressed and sharded out-of-core storage) lets the same algorithm run on billions of rows. This page derives the objective, works one split by hand, and then covers each piece of the system and the results reported for it.

01 The problem: accuracy and scale at once

By 2015 gradient-boosted trees were already among the most accurate tabular learners. The common implementations were either exact but single-machine and slow, or fast but limited to approximate splits. The 2016 study set out to build a single system that keeps exact-greedy quality where data fits in memory, degrades gracefully to approximate splits where it does not, and also runs out-of-core and distributed.

  • Accuracy. A regularised objective (§02) and a second-order fitting step (§03) give principled leaf values and a split criterion for any twice-differentiable loss, covering regression, classification and ranking.
  • Real data is sparse and dirty. Missing values, frequent zeros and one-hot columns are the norm. Rather than requiring imputation, the system learns where missing values should go (§09).
  • Scale. Split finding is the hot loop of tree learning. The study's main systems contribution is to sort each column once, keep the result in blocks, read gradient statistics cache-efficiently, and stream compressed blocks from several disks (§10).
Adoption at the time. The study reports that of 29 challenge-winning solutions published on a machine-learning-competition blog during 2015, 17 used XGBoost (8 of them used it alone; most of the others combined it with neural nets in ensembles), compared with 11 that used deep neural nets. In KDDCup 2015 every one of the top-10 teams used it.

02 The model and the regularised objective

The ensemble is a sum of K regression trees. What is new compared with classic gradient boosting is a complexity penalty on each tree, charged both on its number of leaves and on the size of its leaf weights.

tree ensembleŷᵢ = φ(xᵢ) = Σₖ fₖ(xᵢ), fₖ ∈ F F = { f(x) = w_q(x) } q : ℝᵐ → {1, …, T} the tree STRUCTURE (which leaf x falls in) w ∈ ℝᵀ the LEAF WEIGHTS (one score per leaf) regularised objectiveL(φ) = Σᵢ l(ŷᵢ, yᵢ) + Σₖ Ω(fₖ) Ω(f) = γ·T + ½·λ·‖w‖² T = number of leaves, ‖w‖² = Σⱼ wⱼ²
  • l is any differentiable convex loss: squared error, logistic, a ranking loss. Nothing below depends on which one, as long as its first and second derivatives exist.
  • γ prices a leaf. Adding a leaf must buy at least γ of loss reduction (§05).
  • λ is an L2 penalty on leaf scores. It is the same idea as ridge regression on the regularisation page, applied to the outputs of the leaves instead of to coefficients. It smooths the final learned weights.
  • Set Ω = 0 and you recover traditional gradient tree boosting. So the regularisation is an addition to the model, not a different model.

Each f is a CART-style regression tree with a real-valued score in every leaf, even for classification, where the scores are summed in log-odds space. The structural vocabulary (nodes, leaves, thresholds) is the one on the hub.

03 Additive training with a second-order step: the Newton view

The objective cannot be optimised over all trees at once, so it is optimised greedily, one tree per round. The study expands the loss to second order around the current prediction. That turns "fit tree t" into minimising a sum of per-example quadratics.

round t: add the tree that most improves the objectiveL⁽ᵗ⁾ = Σᵢ l( yᵢ, ŷᵢ⁽ᵗ⁻¹⁾ + fₜ(xᵢ) ) + Ω(fₜ) second-order Taylor expansion around ŷ⁽ᵗ⁻¹⁾ (constant terms dropped)L̃⁽ᵗ⁾ = Σᵢ [ gᵢ·fₜ(xᵢ) + ½·hᵢ·fₜ²(xᵢ) ] + Ω(fₜ) gᵢ = ∂l(yᵢ, ŷ⁽ᵗ⁻¹⁾) / ∂ŷ⁽ᵗ⁻¹⁾ first derivative (gradient) hᵢ = ∂²l(yᵢ, ŷ⁽ᵗ⁻¹⁾) / ∂(ŷ⁽ᵗ⁻¹⁾)² second derivative (hessian)

Two consequences. First, a single implementation handles every loss: the tree learner only ever sees the pairs (gᵢ, hᵢ), and a new loss needs just these two derivatives. Second, the step is a Newton step, not a gradient step. In one dimension, minimising g·w + ½·h·w² gives w = −g/h, which is gradient divided by curvature. The first-order and second-order methods are compared on the optimisation page.

How this differs from the hub's residual fitting

first-order gradient boosting (hub §boosting)fit fₜ by least squares to the pseudo-residuals rᵢ = −gᵢ leaf value = mean of rᵢ in the leaf (curvature ignored) second-order, regularised (this page)choose the structure q and the weights w that minimise Σᵢ[gᵢf + ½hᵢf²] + γT + ½λ‖w‖² leaf value = −Σgᵢ / (Σhᵢ + λ) (curvature + shrinkage)

The curvature hᵢ appears in the leaf values and also in the split criterion (§04). So the tree's shape is chosen for the Newton objective, not for a least-squares fit to gradients.

Two losses worked out

squared loss l = ½(y − ŷ)² (derivation on this page)gᵢ = ŷᵢ − yᵢ = −rᵢ hᵢ = 1 wⱼ* = Σ_{i∈Iⱼ} rᵢ / (nⱼ + λ) = [ nⱼ / (nⱼ + λ) ] · r̄ⱼ → the mean residual of the leaf, shrunk toward 0 by the factor nⱼ/(nⱼ + λ). With λ = 0 this is exactly the hub's residual-fitting leaf; small leaves are shrunk most. logistic loss on log-odds ŷ, p = σ(ŷ) (standard result)l = −[ y·ln p + (1 − y)·ln(1 − p) ] gᵢ = pᵢ − yᵢ hᵢ = pᵢ(1 − pᵢ) ∈ (0, ¼] wⱼ* = Σ (yᵢ − pᵢ) / ( Σ pᵢ(1 − pᵢ) + λ ) — a damped Newton step in log-odds

The logistic case shows why hᵢ matters. A point the model already classifies confidently (p near 0 or 1) has hᵢ ≈ 0 and contributes almost nothing to H. Uncertain points with p ≈ ½ dominate it. The gradient p − y is the same one that drives logistic regression. This uneven weighting is what the quantile sketch of §08 is built around.

04 Optimal leaf weights, the structure score, and the split gain

Group the sum by leaf. For a fixed structure the objective separates into T independent one-variable quadratics, each with a closed-form minimum. Substituting the minima back in gives a score for the structure itself, and the difference in scores before and after a split is the gain.

group by leaf: Iⱼ = { i : q(xᵢ) = j }, Gⱼ = Σ_{i∈Iⱼ} gᵢ, Hⱼ = Σ_{i∈Iⱼ} hᵢL̃⁽ᵗ⁾ = Σⱼ [ Gⱼ·wⱼ + ½·(Hⱼ + λ)·wⱼ² ] + γT set ∂/∂wⱼ = 0Gⱼ + (Hⱼ + λ)·wⱼ = 0 ⇒ wⱼ* = − Gⱼ / (Hⱼ + λ) structure score: plug w* back in (lower is better)L̃⁽ᵗ⁾(q) = − ½ · Σⱼ Gⱼ² / (Hⱼ + λ) + γT gain of splitting one leaf into L and R (G = G_L + G_R, H = H_L + H_R)L_split = ½ · [ G_L²/(H_L + λ) + G_R²/(H_R + λ) − G²/(H + λ) ] − γ

The structure score plays the role that Gini or variance plays for a single tree, but it is derived from the loss being optimised, so it works for any l. With squared loss and λ = γ = 0 it reduces to the familiar criterion. Then Gⱼ²/Hⱼ = nⱼ·r̄ⱼ², and the bracket equals the drop in residual sum of squares, i.e. n× the hub's variance reduction. (This reduction is our own derivation, not one stated in the study.) The −γ is subtracted once because a split adds exactly one leaf.

05 γ prunes, λ shrinks: the split-gain explorer

The two penalties are often confused, but they act on different things. γ is a fixed toll per leaf, subtracted from every gain, so a split happens only if its bracket exceeds γ. This is pruning built into the criterion. λ sits inside every denominator. It shrinks each leaf weight toward zero, and it lowers the bracket most for splits that create leaves with small H.

The figure fits one depth-1 tree (a stump) per round to 26 points in one dimension. Each round it recomputes gᵢ and hᵢ from the current prediction, evaluates the bracket of §04 at every threshold, and applies the best split, scaled by η (§06). Under squared loss every hᵢ = 1. Switch to logistic loss and every hᵢ starts at ¼, because the model begins at p = ½. Set γ = 0 and η = 1, then boost about ten rounds. The hessian bars become uneven: in this toy they fall to under 0.1 for the points the model now predicts most confidently, so those points count for less in every H. With the default γ = 1, the logistic run stops splitting after a few rounds, because no remaining gain clears the toll.

Split gain from gᵢ and hᵢ, threshold by threshold raise γ above the curve's peak and the round becomes a single leaf; raise λ and both leaf weights shrink and small edge splits lose most of their gain
γ — per-leaf toll
Decides whether to split
Subtracted once per split, independent of the data. A negative gain means no split. Leaf values are unaffected: γ appears nowhere in w*. Same idea as the complexity term in cost-complexity pruning, but charged while the tree is being grown.
λ — L2 on leaf weights
Decides how much each leaf says
Shrinks w* = −G/(H+λ) toward 0, most for leaves with small H. It also lowers the gain, so it discourages splits that isolate a few points. It never makes a gain negative by itself; only γ does that.
implementation note (general knowledge)
Grow, then prune back
The library grows each tree to max_depth and then removes, bottom-up, splits whose gain falls below γ. So a weak split can survive when a strong split below it depends on it. A separate floor on H per leaf (min_child_weight) also refuses leaves whose hessian sum is too small.

06 Two more guards against overfitting: shrinkage and column subsampling

Besides Ω, the study uses two further techniques. Shrinkage scales each new tree by η after it is fitted. Column (feature) subsampling, borrowed from random forests, lets each tree see only a random subset of features.

shrinkage: η applied to the newly added treeŷ⁽ᵗ⁾ = ŷ⁽ᵗ⁻¹⁾ + η · fₜ(x) the study's experiments use η = 0.1
  • Why it helps. Shrinkage reduces the influence of each individual tree and leaves room for future trees to improve the model. It is the same η as on the hub, and a smaller η needs more rounds. Setting the number of rounds by early stopping on a validation set is the usual companion (see hyperparameter tuning).
  • η and λ are not interchangeable. η scales the whole tree uniformly after its structure is chosen. λ changes which structure is chosen, and it shrinks small leaves more than large ones.
  • Column subsampling. According to user feedback reported in the study, it prevents overfitting even more than row subsampling does. Because each tree touches fewer columns, it also speeds up the column-parallel split search of §10. In the experiments it hurt slightly on Higgs (the study suggests there are few important features there). On the ranking task it was slightly better, which the study attributes to reduced overfitting (§11). The hub explains why de-correlating trees helps for random forests.

07 Finding the split: exact greedy vs the approximate algorithm

The gain formula says how to score a split. Finding the best one requires trying every threshold of every feature. With pre-sorted data that is a single linear scan per feature. The approximate algorithm cuts it down to a few candidates per feature.

exact greedy, for one nodefor each feature k: sort the node's instances by xₖ G_L ← 0, H_L ← 0 for each instance j in sorted order: G_L += gⱼ, H_L += hⱼ G_R = G − G_L, H_R = H − H_L score = max(score, G_L²/(H_L+λ) + G_R²/(H_R+λ) − G²/(H+λ)) output the split with the maximum score approximatefor each feature k: propose candidates Sₖ = {sₖ₁, …, sₖₗ} by percentiles of xₖ bucket each instance's (gᵢ, hᵢ) into the interval it falls in then: find the best split among the l bucket boundaries only
  • Exact greedy enumerates every distinct value. It is what scikit-learn, R's gbm and single-machine XGBoost supported. It breaks down when the data does not fit in memory, and in a distributed setting.
  • Global proposal picks candidates once per tree and reuses them at every depth. Proposal is cheaper, but it needs more candidates, because after a few splits each node only covers a small part of a feature's range.
  • Local proposal re-proposes after each split, using only the instances in that node. It needs fewer candidates and suits deeper trees.

08 Which percentiles? The weighted quantile sketch

Ordinary percentiles give every row equal weight. The second-order objective does not. Rewriting it shows that every row is a squared-error example weighted by its hessian hᵢ. So candidates should be spaced evenly in accumulated hessian, not in row count.

the objective is a weighted least-squares problem (completing the square)Σᵢ [ gᵢ·f(xᵢ) + ½hᵢ·f²(xᵢ) ] = Σᵢ ½·hᵢ·( f(xᵢ) + gᵢ/hᵢ )² − Σᵢ gᵢ²/(2hᵢ) weight hᵢ, target −gᵢ/hᵢ, last term constant in f rank function over Dₖ = {(x₁ₖ, h₁), (x₂ₖ, h₂), …}rₖ(z) = ( 1 / Σ_{(x,h)∈Dₖ} h ) · Σ_{(x,h)∈Dₖ, x<z} h the share of total hessian below z candidate condition (ε = approximation factor)| rₖ(sₖ,ⱼ) − rₖ(sₖ,ⱼ₊₁) | < ε, sₖ₁ = min xᵢₖ, sₖₗ = max xᵢₖ → roughly 1/ε candidates

On the sign: the study prints the weighted-squares form as (fₜ(xᵢ) − gᵢ/hᵢ)². Expanding the square gives the + form above, i.e. target −gᵢ/hᵢ, the Newton step. Either way the weights are hᵢ, and the weights are what the sketch needs.

Computing exact quantiles requires sorting all of the data, which is not possible when the data is streamed or spread across machines. Earlier quantile sketches (summaries that can be merged and pruned while keeping error bounds) handled only unweighted data. The study introduces a new mergeable, prunable sketch for weighted data with a provable guarantee, with details in its appendix. Why sample quantiles are statistically well behaved in the first place is covered on Sample Quantiles & Extreme Values.

Candidate splits by row count vs by hessian, under logistic loss raise the model's confidence k: far-away rows lose their hessian, and the h-weighted candidates crowd into the region where the next split is actually found
  • What the toy shows. The labels are soft: each yᵢ is the true probability from a decision boundary at x = 1.9. The current model puts the boundary at 1.5, so the useful next split lies in the right tail. Count quantiles spend most of their budget near x = 0, where the model is already confidently right and gᵢ ≈ 0. Hessian-weighted quantiles spend it where gradient signal is left. At the default settings (k = 4, ε = 0.12), the best h-weighted candidate recovers about 98% of the exact-greedy gain, against about 45% for count quantiles (figures from the toy, not from the study). Lower k and the hessians become more uniform, so the two candidate sets move closer together. At large ε with low k, both sets are too sparse to reach the tail.
  • Why soft labels. With random 0/1 labels, a single rare positive deep in the confident region has |gᵢ| ≈ 1 but hᵢ ≈ 0. The exact search can then chase that one point, which is noise. Down-weighting such points is part of what the weighting does.
  • Squared loss is the unweighted special case. When every hᵢ = 1, the weighted sketch is an ordinary quantile sketch.

09 Sparsity-aware split finding: learn where missing values go

Each tree node stores a default direction. A row whose feature is missing (or, in sparse storage, absent) follows that branch. The direction is learned from the data at training time, by trying both and keeping the better one.

sparsity-aware split finding, one node, one feature kI = all instances in the node G = Σ_{i∈I} gᵢ, H = Σ_{i∈I} hᵢ Iₖ = instances whose xₖ is PRESENT (enumerate only these) pass 1 — missing go RIGHT: scan Iₖ ascending, accumulate G_L, H_L over present rows only; G_R = G − G_L (the missing block lands on the right) pass 2 — missing go LEFT: scan Iₖ descending, accumulate G_R, H_R over present rows only; G_L = G − G_R (the missing block lands on the left) keep the better (threshold, direction) pair; cost is linear in |Iₖ|, the non-missing entries
  • Where sparsity comes from: genuinely missing values, frequent zero entries, and artefacts of feature engineering such as one-hot encoding. Absent entries are never visited. They enter only through the totals G and H.
  • It pays off a lot. On Allstate-10K, a one-hot-heavy dataset, the sparsity-aware algorithm ran more than 50× faster than the naive version that visits every entry.
  • It is a learned imputation, per node. Unlike mean or median filling (see missing values in preprocessing), the direction is chosen to reduce the loss, and it can differ for every node and every feature. When missingness is itself informative, the tree can use that information.
Missing → left, missing → right, or impute the mean first? with informative missingness, one default direction wins clearly; mean imputation drops those rows into the middle of the range, where they may land on the wrong side

10 System design: column blocks, cache-aware access, out-of-core

Most of the study's speed-up comes from data layout rather than from the algorithm. Sorting is the expensive part of split finding, so the system sorts each column once, stores it, and reuses that order for every node of every tree.

Column blocks

Data is stored in in-memory blocks in compressed sparse column (CSC) format. Each column is sorted by feature value and keeps, for each entry, a pointer back to its row's gradient statistics. The layout is computed once before training. A linear scan of a block's column then finds the best split for all leaves at the current depth at once, and different columns can be scanned in parallel. Blocks can also be spread across machines or kept on disk, and column subsampling simply means picking a subset of columns from a block.

time complexity (K trees, d max depth, ‖x‖₀ non-missing entries, n rows, q candidates, B rows per block)exact greedy original: O( K · d · ‖x‖₀ · log n ) sort at every level with blocks: O( K · d · ‖x‖₀ + ‖x‖₀ · log n ) sort once, then linear scans approximate original: O( K · d · ‖x‖₀ · log q ) binary search into q candidates with blocks: O( K · d · ‖x‖₀ + ‖x‖₀ · log B ) q is typically 32–100

The log factor moves out of the per-tree term into a one-time cost. Over hundreds of trees, that is the difference between paying for a sort at every level of every tree and paying for one sort in total.

cache-aware access
Prefetch the gradients
The sorted column order is not the row order, so reading (gᵢ, hᵢ) by row pointer jumps around memory and misses the CPU cache. For exact greedy, each thread gathers the statistics into a small contiguous buffer and then accumulates. This made exact greedy about 2× faster on large (10M-row) data. For the approximate algorithm the fix is the block size: 2¹⁶ examples per block balanced cache behaviour against parallelism.
out-of-core: compression
Trade CPU for disk bandwidth
Blocks are compressed by column and decompressed on the fly by an independent thread. Row indices are stored as 16-bit offsets from the start of the block. Compression ratios of about 26% to 29% were reported.
out-of-core: sharding
Read several disks at once
The data is split across multiple disks, with one prefetch thread per disk filling an in-memory buffer. The training thread alternately reads from each buffer, so disk throughput adds up.

14 Common misconceptions

"XGBoost is a different algorithm from gradient boosting." It is regularised, second-order gradient tree boosting. The model is still an additive ensemble of regression trees trained one round at a time. Setting Ω = 0 recovers the traditional objective (§02). What is new is the Newton-style fitting step, the penalty, and above all the system (§07–§10).
"λ and γ do the same thing — both are regularisation." They act on different quantities. γ is a per-leaf toll that decides whether to split and never changes a leaf's value. λ shrinks leaf values, and it lowers gains in a data-dependent way, most for low-H leaves (§05). Only γ can make a gain negative.
"Missing values must be imputed before training." Not for this learner. Each node learns a default direction for missing entries by trying both sides (§09). Imputing first can throw away the information in the missingness itself, and on sparse one-hot data it is also far slower.
"Approximate split finding is always worse than exact." Not with good candidates. Local proposals at ε = 0.3 and global proposals at ε = 0.05 both came close to exact-greedy AUC on Higgs-10M (§07). Weighting candidates by hessian puts them where the objective is sensitive (§08).
"min_child_weight is the minimum number of samples in a leaf." It is a minimum hessian sum. It equals the row count only under squared loss, where every hᵢ = 1. Under logistic loss, a leaf of 1000 confidently classified rows can have a tiny H and be refused.
"Its speed comes from cutting corners on the model." At equal settings it matched the exact-greedy reference. On Higgs-1M, XGBoost's exact greedy reached essentially the same AUC as scikit-learn (0.8304 vs 0.8302) and was more than 10× faster per tree (§11). The speed comes from data layout, the cache and the disks.

15 Takeaways

  • Objective: Σ l(ŷᵢ, yᵢ) + Σₖ (γT + ½λ‖w‖²); with the penalty set to zero it is plain gradient tree boosting.
  • Second-order step: each round sees only (gᵢ, hᵢ), so one tree learner serves every twice-differentiable loss. The leaf weight w* = −G/(H+λ) is a damped Newton step.
  • Split gain: ½[G_L²/(H_L+λ) + G_R²/(H_R+λ) − G²/(H+λ)] − γ. A non-positive gain means no split, so γ is built-in pruning and λ is leaf shrinkage.
  • Shrinkage (η, 0.1 in the experiments) and column subsampling are the other two guards against overfitting.
  • Approximate splits use about 1/ε candidates per feature, re-proposed per node (local) or once per tree (global, which needs more). Candidates are hessian-weighted quantiles, because the objective is least squares weighted by hᵢ.
  • Missing values: a learned default direction per node, at a cost linear in the non-missing entries; over 50× faster on one-hot-heavy data.
  • System: pre-sorted CSC column blocks take the log n out of the per-tree cost. Gradient prefetching (about 2×), block compression (about 3×) and disk sharding (about 2× more) took one machine to 1.7B rows.
