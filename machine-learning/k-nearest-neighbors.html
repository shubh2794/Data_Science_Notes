k-Nearest Neighbors

SupervisedLazy learner No training, no parameters to learn — just store the data and, at query time, vote among the k closest neighbors.

Overview

kNN is a non-parametric, supervised algorithm built on one assumption: similar points sit close together in feature space. So the label (or value) of a new point can be inferred from the labels of its nearest neighbors.

  • Classification — predict the majority class among the neighbors.
  • Regression — predict the average of the neighbors' values.
  • Non-parametric — it makes no assumption about the shape of the data and learns no fixed set of weights; the "model" is the training set.

How kNN works

Training phase — a lazy learner

There is essentially no training. The algorithm just memorizes the dataset D = {(xᵢ, yᵢ)} and defers all computation to prediction time — hence "lazy."

Prediction phase

For a query point xₜ:

  1. Compute distances d(xₜ, xᵢ) to every training point using the chosen metric.
  2. Sort the training points by ascending distance.
  3. Select the k closest neighbors.
  4. Predict from those neighbors:
classification — majority vote · regression — neighbor meanŷₜ = mode{ yᵢ : xᵢ ∈ Nₖ(xₜ) } ŷₜ = (1/k) Σ_(xᵢ ∈ Nₖ(xₜ)) yᵢ

Distance metrics

The notion of "nearest" depends entirely on the distance metric. The choice should match the data type.

Euclidean (L2) — continuous data on similar scalesd(x, y) = √( Σᵢ (xᵢ − yᵢ)² )
Manhattan (L1) — grid-like / when component-wise differences matterd(x, y) = Σᵢ |xᵢ − yᵢ|
Minkowski (Lp) — generalizes both: p=1 → Manhattan, p=2 → Euclideand(x, y) = ( Σᵢ |xᵢ − yᵢ|ᵖ )^(1/p)
Hamming — categorical features (count of mismatches)d(x, y) = Σᵢ 𝟙(xᵢ ≠ yᵢ)
Cosine distance — direction over magnitude (text / embeddings)d(x, y) = 1 − (x · y) / (‖x‖ ‖y‖)
  • Numerical data → Euclidean; categorical → Hamming; mixed → a hybrid metric.
  • Text and high-dimensional embeddings often use cosine, which ignores vector length.

Choosing k & the bias–variance trade-off

k is the one knob that matters most — it directly controls model complexity.

  • Small k (e.g. 1) → very flexible, jagged boundaries; low bias, high variance; sensitive to noise and outliers — risk of overfitting.
  • Large k → smoother boundaries; high bias, low variance; dilutes the influence of the truly closest points — risk of underfitting.
  • Pick k by cross-validation, scanning a range of values and keeping the one with the best validation score. A common heuristic starts near k ≈ √n, and odd k avoids ties in binary classification.

Feature scaling & the curse of dimensionality

Scaling is not optional

Because everything rides on distance, a feature with a large numeric range will dominate the metric. A salary in the thousands swamps an age in the tens unless features are put on a common scale.

standardize (z-score) · or min–max normalize to [0,1]x' = (x − μ) / σ x' = (x − min) / (max − min)

The curse of dimensionality

  • As dimensions grow, points spread out and distances concentrate — the nearest and farthest neighbors become almost equidistant, so "nearest" loses meaning.
  • Irrelevant/noisy features add distance in directions that don't matter, further degrading neighbor quality.
  • Mitigate with feature selection or dimensionality reduction (PCA) before applying kNN.

Computational cost & speedups

kNN front-loads nothing and back-loads everything: training is O(1) but each prediction is expensive.

  • Brute force: a single query scans all n points in d dimensions → O(n·d) per prediction. Painful on large datasets.
  • KD-trees: space-partitioning tree; build O(n log n), query close to O(log n) in low dimensions but degrades badly past ~20 dims.
  • Ball trees: partition into nested hyperspheres; hold up better in higher dimensions and with non-Euclidean metrics.
  • Approximate nearest neighbors (LSH, HNSW) trade a little accuracy for huge speedups at scale — the basis of modern vector search.

Beyond a fixed k

Several variants soften or remove the hard "pick exactly k neighbors" rule.

distance-weighted vote — closer neighbors count morewᵢ = 1 / d(xₜ, xᵢ)² wᵢ = e^(− dᵢ² / σ²) (Gaussian)
  • Distance-weighted kNN — weight each neighbor by closeness (inverse-distance or Gaussian), removing the abrupt cutoff at the k-th neighbor and adapting to local density.
  • Radius-based neighbors — use every point within a radius r instead of a fixed count; adapts to density but choosing r is hard in high dimensions.
  • Adaptive / dynamic k — grow k per query until the prediction stabilizes or a confidence threshold is met; good for heterogeneous or noisy data.
  • Local Outlier Factor (LOF) — compares a point's local density to its neighbors'; robust to outliers, used for anomaly detection.
  • Ensemble kNN — aggregate several models with different k to reduce sensitivity to the choice (at extra cost).
  • Data-driven selection — cross-validation, grid search, or Bayesian optimization to pick k principled-ly.

kNN vs. k-Means — don't confuse them

Both use k and distances, but they solve opposite problems.

Pros & cons

Advantages

  • Intuitive and simple — minimal math, easy to implement.
  • No training cost; new data can be added without retraining.
  • Naturally handles multi-class problems and both numerical and categorical data.

Disadvantages

  • Expensive predictions — every query touches the whole dataset.
  • Highly sensitive to feature scaling and to irrelevant/noisy features.
  • Performance hinges on a good k and distance metric.
  • Suffers in high dimensions (curse of dimensionality).
