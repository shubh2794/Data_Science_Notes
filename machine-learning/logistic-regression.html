Logistic Regression

A linear score pushed through a sigmoid and read as a probability. The sigmoid is derived, not assumed; cross-entropy is the loss that makes the problem convex; the decision boundary is a hyperplane; softmax and one-vs-rest extend it past two classes.

Logistic regression & the sigmoid

For classification, plain linear regression is wrong: its output is unbounded and can exceed the [0, 1] range, so it can't be read as a probability. Logistic regression fixes this by passing the linear score z through a sigmoid.

probability of the positive classP(y = 1 | x) = σ(z) = 1 / (1 + e⁻ᶻ) z = β̂₀ + β̂₁x₁ + β̂₂x₂ + … + β̂ₖxₖ

The sigmoid is not assumed — it is derived

The actual modelling assumption is about the log-odds: assume the log-odds of the positive class are a linear function of the features. The sigmoid is what you get when you solve that assumption for p:

from the log-odds assumption to the sigmoidassume ln( p / (1 − p) ) = z p / (1 − p) = eᶻ p = eᶻ − p·eᶻ ⟹ p (1 + eᶻ) = eᶻ p = eᶻ / (1 + eᶻ) = 1 / (1 + e⁻ᶻ) = σ(z)

The last step divides numerator and denominator by eᶻ. So "sigmoid of a linear score" and "linear model of the log-odds" are the same statement — the sigmoid is exactly the inverse of the logit. That is the real answer to "why the sigmoid": it is the unique function that turns a linear log-odds model into a probability.

  • It squashes (−∞, +∞) into (0, 1) — an honest probability, never 0 or 1 exactly.
  • It is smooth and differentiable, with a derivative that is a tidy function of its own output: σ′(z) = σ(z)(1 − σ(z)). That identity is what makes the training gradient so clean.
  • It is symmetric: σ(−z) = 1 − σ(z), so swapping the class labels just flips the sign of every coefficient.
  • Example: predicting sunny vs. rainy from temperature — a line could output 1.3 or −0.2 (nonsense as a probability), but the sigmoid keeps it a valid probability and yields a clean threshold.

Why not something else?

  • Step function — the "obvious" choice, but it is flat everywhere and non-differentiable at the jump, so gradient-based optimization has nothing to follow.
  • tanh — outputs (−1, 1), so it isn't a probability. (It is just a rescaled sigmoid: tanh(z) = 2σ(2z) − 1.)
  • The probit link, the Gaussian CDF, is a legitimate alternative and gives nearly identical fits. The logit wins on convenience: it has a closed form, and its coefficients read directly as log-odds.

The decision boundary is a hyperplane

Because σ is strictly increasing, thresholding the probability is the same as thresholding the linear score:

a probability threshold t is a threshold on zσ(z) > t ⇔ z > ln( t / (1 − t) ) = logit(t) t = 0.5 ⇒ logit(t) = 0 ⇒ boundary: β₀ + βᵀx = 0 general t ⇒ boundary: β₀ + βᵀx = logit(t)
  • The boundary is a hyperplane — a point in 1-D, a line in 2-D, a plane in 3-D. Moving the threshold does not bend it; it only slides it parallel to itself, because only the constant term changes.
  • This is the model's core limitation. Logistic regression cannot separate classes that aren't linearly separable in the given feature space — XOR is the canonical failure, and no amount of data fixes it.
  • The fix is the same as for linear regression: engineer the features. Add x₁², x₂², x₁x₂ and the boundary becomes a conic section in the original space while staying a hyperplane in the expanded one. Kernel methods (SVMs) and neural nets automate that trick.
  • ‖β‖ controls how fast the probability swings across the boundary: large coefficients give a near-step function (confident), small ones a gentle ramp (hedged). The boundary location is unchanged.

Training: why cross-entropy, not MSE

Logistic regression is fit by minimizing log-loss (binary cross-entropy), equivalently by maximum likelihood. Each label is a Bernoulli draw with parameter pᵢ = σ(zᵢ), so the likelihood and its negative log are:

Bernoulli likelihood ⟹ log-lossL(β) = ∏ᵢ pᵢ^yᵢ · (1 − pᵢ)^(1 − yᵢ) −(1/n) ln L(β) = − (1/n) Σᵢ [ yᵢ · ln(pᵢ) + (1 − yᵢ) · ln(1 − pᵢ) ]

The exponents act as a switch: for y = 1 only the first term survives, for y = 0 only the second. Minimizing log-loss is maximum-likelihood estimation of a Bernoulli model — the same relationship MSE has to Gaussian noise.

So why not just reuse MSE on the sigmoid's output? It looks reasonable, and it is a real disaster. There are four separate reasons.

1 · MSE composed with the sigmoid is non-convex

MSE is convex in ŷ, but σ is not affine, and composing a convex function with a nonlinear one does not preserve convexity. The result has humps, plateaus, and more than one basin — gradient descent's answer then depends on where you started. Log-loss with a sigmoid is convex in β — its Hessian is (1/n)·XᵀSX with S = diag(pᵢ(1 − pᵢ)), and since every pᵢ(1 − pᵢ) > 0 that matrix is positive semi-definite — so every local optimum is the global one. The landscape below shows both, on the same data.

2 · MSE's gradient vanishes exactly when you're confidently wrong

Differentiate both losses with respect to a coefficient. The sigmoid derivative σ′(z) = σ(z)(1 − σ(z)) shows up in one and cancels in the other:

MSE on top of a sigmoid · the σ′ factor survives∂/∂βⱼ (1/n) Σᵢ (σ(zᵢ) − yᵢ)² = (2/n) Σᵢ (σ(zᵢ) − yᵢ) · σ′(zᵢ) · xᵢⱼ
log-loss · the σ′ factor cancels∂L/∂pᵢ = (pᵢ − yᵢ) / [ pᵢ(1 − pᵢ) ] ∂pᵢ/∂zᵢ = pᵢ(1 − pᵢ) ⟹ ∂L/∂zᵢ = pᵢ − yᵢ ∇_β L = (1/n) · Xᵀ ( σ(Xβ) − y ) ∂L/∂βⱼ = (1/n) Σᵢ ( σ(zᵢ) − yᵢ ) · xᵢⱼ

Now consider a point the model gets badly wrong: true label 1, predicted p = 0.01. That means z ≈ −4.6, deep in the sigmoid's flat tail, so σ′(z) ≈ 0.0099. Under MSE the error (p − y) = −0.99 is multiplied by that near-zero factor and the update all but disappears — the more confidently wrong the model is, the less it learns. Under log-loss the gradient is just (p − y) = −0.99: the update is proportional to the mistake, exactly as it should be.

The elegant part. Compare ∇_β L = (1/n)·Xᵀ(σ(Xβ) − y) with the linear-regression gradient ∇_β MSE = (2/n)·Xᵀ(Xβ − y). Identical shape — "design matrix transpose, times the prediction error" — with only the link function differing. That is not a coincidence: both are generalized linear models fit by maximum likelihood, and the whole GLM family shares this gradient. It is also why the same optimizer code drops straight onto both.

3 · Log-loss is the right penalty for a probability

  • It is unbounded: predicting 0.999 for a true 0 costs −ln(0.001) ≈ 6.9, while MSE caps that same catastrophe at ≈ 1. Confident wrongness should hurt without limit.
  • It is a strictly proper scoring rule: its expected value is uniquely minimized by reporting your true belief. A model has no incentive to shade its probabilities, which is a large part of why logistic regression comes out well calibrated.
  • MSE on probabilities (the Brier score) is also proper and is a perfectly good evaluation metric — it is specifically as a training objective under a sigmoid that it fails.

4 · There is no closed form — but the problem is easy

  • Setting Xᵀ(σ(Xβ) − y) = 0 gives a nonlinear system with no algebraic solution, so fitting is always iterative: β := β − α·∇_β L.
  • Because the loss is convex and smooth, second-order methods work very well. Newton's method on this loss is IRLS (iteratively reweighted least squares) — each step is a weighted OLS solve with weights pᵢ(1 − pᵢ), and it typically converges in under ten iterations for modest p. Libraries use L-BFGS or Newton by default and fall back to SGD only when the data is huge.

Perfect separation: when the MLE doesn't exist

A real pathology. If some hyperplane separates the two classes with no errors, then scaling β up by any factor pushes every pᵢ closer to its label and the log-loss strictly decreases — forever. The likelihood has no finite maximum: coefficients run off to ±∞, standard errors explode, and the optimizer just hits its iteration cap at some huge, arbitrary value. Quasi-separation (a single feature or level that perfectly predicts the outcome) causes the same thing for that one coefficient. Any L2 penalty — equivalently, a Gaussian prior on β — restores a finite optimum by making the objective strictly convex and coercive. This is precisely why a typical LogisticRegression implementation applies L2 by default rather than fitting the raw MLE. See regularization.

Reading the coefficients: odds & logit

odds = p / (1 − p) logit(p) = ln( p / (1 − p) ) = z odds ratio for a unit change in xⱼ = e^βⱼ
  • A coefficient βⱼ is the change in log-odds per one-unit increase in xⱼ, holding the others fixed.
  • Exponentiate for an odds multiplier: β̂ⱼ = 0.7 → e^0.7 ≈ 2, so a one-unit increase roughly doubles the odds. β̂ⱼ = 0 → e⁰ = 1, no effect. Negative β̂ⱼ → a multiplier below 1.
  • The effect is multiplicative on the odds, not on the probability. Doubling the odds moves p from 0.10 to 0.18 (+8 points) but from 0.50 to only 0.67 (+17 points), and from 0.90 to 0.947 (+4.7 points). The same coefficient produces a different probability change depending on where you start on the curve — which is exactly the S-shape at work. Never report "e^β = 2 means the probability doubles".
  • The intercept is the log-odds when every feature is 0, so σ(β₀) is the baseline probability at x = 0. If x = 0 is impossible or far outside the data, that number is meaningless; centre the features and β₀ becomes the log-odds at the average input.
  • Coefficient magnitudes are only comparable across features after standardization, exactly as in linear regression.

Calibration

Because it is fit by maximum likelihood on a proper scoring rule, logistic regression's outputs are usable as probabilities out of the box — among the points it scores at 0.7, roughly 70% really are positive. That is a genuine advantage over SVMs (whose decision values are unnormalized margins) and over shallow trees or naive Bayes (which push predictions toward the extremes and need Platt scaling or isotonic regression to be trusted). Heavy regularization degrades calibration by shrinking probabilities toward the base rate, so check a reliability curve if the probability values themselves matter.   • The vertical amber line is x* = (logit(t) − β₀) / β₁ — the input value where the fitted probability equals the threshold. The shaded side is the predicted-positive region (to the right of x* when β₁ > 0). In one dimension the "hyperplane" boundary is just this single point.
  • Lower the threshold and x* slides left: you catch more true positives (recall ↑) at the cost of more false positives (precision ↓). Raise it and the trade reverses. Sweeping t from 1 to 0 and plotting the resulting (FPR, TPR) pairs is precisely how an ROC curve is drawn — this viz is one point on that curve at a time.
  • 0.5 is a default, not a law. It is optimal only when false positives and false negatives cost the same and the classes are balanced. Cancer screening wants a low threshold; a spam filter that deletes mail wants a high one.
  • Push separation up and |β₁| grows sharply: the model becomes more confident, the curve steepens toward a step, and the training log-loss falls toward zero. Push it far enough and the classes separate perfectly, at which point the unregularized MLE would diverge — this fit carries a tiny L2 penalty so the coefficients stay finite. That is the separation pathology from the previous section, live.
  • Note the coefficients don't move when you drag the threshold. Fitting and thresholding are separate decisions: train once, then choose the operating point from the business cost of each error type.

More than two classes

Binary logistic regression generalizes to K classes in two quite different ways.

Softmax (multinomial logistic regression)

One score vector per class, normalized into a distribution in a single joint fit:

softmax · one model, K score functionsz_k = β₀ₖ + βₖᵀ x P(y = k | x) = e^(z_k) / Σⱼ e^(z_j) categorical cross-entropy: L = − (1/n) Σᵢ Σₖ yᵢₖ · ln P(y = k | xᵢ)
  • Probabilities sum to 1 by construction, so the output is a genuine distribution over classes — no post-hoc normalization.
  • With K = 2 softmax reduces exactly to the sigmoid, so this is a strict generalization.
  • It is over-parameterized: adding the same constant c to every z_k leaves all probabilities unchanged, because e^(z_k + c)/Σⱼe^(z_j + c) = e^(z_k)/Σⱼe^(z_j). Only K − 1 coefficient vectors are identified. Statistics packages fix one class as the reference (set β_K = 0) so the coefficients are unique and read as log-odds versus that reference class; ML libraries usually keep all K and let the L2 penalty pin down a unique symmetric solution.
  • The loss is still convex, and the gradient keeps the same familiar shape: ∇_βₖ L = (1/n) Xᵀ (p_k − y_k).
  • Assumes classes are mutually exclusive. One label per example — softmax cannot express multi-label output.

One-vs-rest (OvR / one-vs-all)

  • Train K independent binary classifiers, each answering "class k, or not?". Predict with argmax_k of their scores.
  • Probabilities do not sum to 1 — the models never saw each other — so you must normalize by Σₖ p_k if you want a distribution, and that normalization has no probabilistic justification.
  • Cheap and trivially parallel; works with any binary learner, not just logistic. Adding a new class means training one more model instead of refitting everything.
  • Each sub-problem is artificially imbalanced (1 class vs. K − 1), which gets worse as K grows, and the K models can be miscalibrated relative to each other so the argmax is not always trustworthy.
  • It does handle multi-label problems, since each classifier fires independently.
Which to use. Prefer softmax when the classes are mutually exclusive and you want calibrated, coherent probabilities — it optimizes the thing you actually care about and is the default in most libraries for a reason. Prefer OvR when labels can co-occur, when K is large and you need to parallelize or add classes incrementally, or when you're wrapping a base learner that has no native multiclass form. A third option, one-vs-one, trains K(K−1)/2 pairwise models and votes: more models but each is small and balanced, which is why SVM implementations favour it.
