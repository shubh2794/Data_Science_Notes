ML Algorithms Compared

A decision page, not a survey. Every classical algorithm is a different bet about the shape of the truth — and that bet, plus your data size, your latency budget, and how much you need to explain, determines the choice far more than any leaderboard does. Below: the assumptions each one makes, the boundaries it can draw, what it costs, how it fails, and a prose flowchart for picking.

Machine Learning Overview Selection

01 No free lunch

Averaged over all possible target functions, every learner performs identically. Performance comes entirely from assumptions that happen to match reality.

The no-free-lunch result is easy to misread as nihilism. What it actually says is that a learning algorithm has no magic: it works because its inductive bias — the preference it holds over hypotheses before seeing any data — lines up with the problem. A linear model prefers smooth global trends. A decision tree prefers piecewise-constant regions with axis-aligned edges. kNN prefers "nearby inputs have nearby outputs". Naive Bayes prefers features that carry independent evidence. None of these is right in general; each is right for some data. Choosing an algorithm is choosing a prior.

what a learner actually doesdata alone under-determines f ⟹ need a preference over hypotheses f̂ = argmin_{f ∈ ℋ} [ L_train(f) + Ω(f) ] ℋ = which functions are expressible (bet #1: the model family) Ω = which of them we prefer (bet #2: the regularizer) generalization = (bet #1 + bet #2) matching the real f
  • Three questions decide almost everything: is the relationship roughly linear in your features? how many rows do you have relative to columns? and do you have to explain a prediction to somebody?
  • The workflow beats the choice. Start with a fast honest baseline (regularized linear, or a small gradient-boosted model), fix your evaluation and splits, then iterate. A well-validated simple model is worth more than an untrusted complex one.
  • Representation dominates. Feature engineering usually moves the score more than swapping algorithms — you are changing ℋ, which is the bigger lever.
  • Everything here still obeys the bias-variance tradeoff. "Which algorithm" is largely "which point on the complexity axis, reached by which route".
Takeaway: there is no best algorithm, only a best-matched assumption. Name the assumption you are making before you name the model.

04 Decision boundaries

Each family draws a characteristic shape. Recognizing the shape your data needs is most of the choice.

The geometry, family by family

A linear model draws a single hyperplane wᵀx + b = 0: one flat cut, oriented by the weights, no matter how many classes or dimensions. kNN draws the boundary of a union of Voronoi cells — jagged at k = 1, progressively smoother as k grows, and entirely local. A kernel SVM draws a level set of a weighted sum of kernel bumps centred on the support vectors, which is smooth and shaped by γ. A tree draws axis-aligned rectangles, so a genuinely diagonal boundary comes out as a staircase that needs many splits to approximate. Forests and boosting average or add many such staircases, which softens them into something surprisingly close to smooth. Naive Bayes with a shared variance gives a linear boundary; with per-class variances it gives a quadratic one.

the boundary each family can expresslinear / logistic: { x : wᵀx + b = 0 } one hyperplane kNN: boundary of ∪ Voronoi cells of the majority class piecewise linear, local kernel SVM: { x : ∑ᵢ αᵢ yᵢ K(xᵢ, x) + b = 0 } smooth level set tree: ∏ⱼ 1[ aⱼ < xⱼ ≤ bⱼ ] — axis-aligned boxes staircase boosting: F(x) = ∑ₘ η · hₘ(x), hₘ a shallow tree sum of staircases Gaussian NB: quadratic in x (linear if Σ is shared across classes)

Where these bite in production

  • kNN is the odd one out: zero training cost, but every prediction touches the whole dataset and the whole dataset must be resident. That is fine offline and usually fatal behind a low-latency API.
  • Kernel SVMs hit a wall around 10⁵ rows because of the quadratic kernel matrix. Beyond that, use a linear SVM with explicit features, or approximate the kernel.
  • Boosting trains sequentially, so it does not benefit from more machines the way a forest does — but inference is a few hundred cheap comparisons and is very fast.
  • Model size matters for deployment: a linear model is a vector; a forest can be a large binary blob; a kNN "model" is your dataset.

Takeaway: pick the algorithm whose expensive phase you can afford. Batch scoring forgives slow inference; a 20 ms API does not.

06 Which one when

A flowchart in prose. Read top to bottom and stop at the first branch that matches.

  1. Is the input perceptual — images, audio, long text, graphs? Then classical ML is the wrong shelf; you want a learned representation. Go to a convolutional, transformer, or graph model and come back here only for the small tabular side-features.
  2. Is the data tabular with mixed types, missing values, and interactions? This is the sweet spot of gradient-boosted trees. Start with a random forest at defaults for a trustworthy number in five minutes, then boost and tune if the number matters.
  3. Is d huge and sparse (bag-of-words, hashed IDs, one-hot everything)? Use a regularized linear model or Naive Bayes. Sparse linear models are extremely fast, scale to millions of features, and are usually within a hair of anything fancier.
  4. Do you have very few rows (tens to low hundreds)? Prefer high-bias, low-variance models: linear with strong regularization, Naive Bayes, or a shallow tree. Complex models here mostly fit noise.
  5. Must a human accept or contest each prediction? Use a linear model (signed weights) or a single shallow tree (a readable rule). Accept the accuracy cost knowingly; do not bolt a post-hoc explainer onto a black box and call it interpretable.
  6. Do you need well-calibrated probabilities? Logistic regression is calibrated by construction. Trees, forests and SVMs are not — calibrate them explicitly and check with a reliability curve.
  7. Is n a few thousand with a clean margin and continuous, comparable features? A kernel SVM is genuinely competitive — just budget for tuning C and γ together.
  8. Is the boundary local and irregular, with few dimensions and no latency constraint? kNN, after scaling and after pruning irrelevant features.
  9. Does the target drift, or must the model update continuously? Prefer incremental learners: SGD-fitted linear models and Naive Bayes update online; kernel SVMs and boosted ensembles need a retrain.
  10. Still unsure? Run three: a regularized linear model, a random forest, and a boosted model, all under the same cross-validation. The comparison takes minutes and settles the argument with evidence.
Takeaway: most real decisions are settled by branches 1–3. The rest of the list exists for the constraints — latency, interpretability, calibration, drift — that a leaderboard never shows you.

07 How each family fails

Knowing the failure mode is more useful than knowing the strength — it tells you what to check when the number disappoints.

Linear and logistic

Fails silently when the truth is non-linear: the fit converges, the coefficients look reasonable, and the model is simply biased. Multicollinearity makes coefficients huge, unstable, and uninterpretable — the predictions can still be fine, which is why people miss it. Squared loss is dominated by outliers. On perfectly separable data the logistic likelihood has no finite maximum and the weights diverge, so regularization is mandatory. And a linear model extrapolates confidently forever, which is a feature outside the training range and a hazard inside a business process.

kNN

Fails by dimension and by scale. Add a handful of irrelevant features and the distance becomes mostly noise; forget to standardize and one large-unit column silently becomes the only feature. It is also biased toward the majority class in imbalanced data (the neighbourhood fills up with common labels), stores the entire dataset, and has no parameters to inspect when something goes wrong.

Naive Bayes

The independence assumption is usually false, and the visible symptom is overconfidence: correlated features each contribute their evidence again and again, so the posterior saturates at 0 or 1. Ranking and argmax often survive this, so it stays a good classifier and a bad probability estimator. Unseen feature-class combinations give zero likelihood unless you smooth, and continuous features force a distributional assumption that may not hold.

SVM

Fails on size (super-linear training, quadratic memory) and on overlap — with heavily overlapping classes, nearly every point becomes a support vector and the "sparse in the data" advantage evaporates. Performance is very sensitive to the joint choice of C and γ, outputs are uncalibrated decision values rather than probabilities, and multiclass has to be assembled from binary problems.

Trees and tree ensembles

A single tree is high-variance: change a few rows and the top split changes, and with it the whole structure. Splits are axis-aligned, so a diagonal boundary becomes a staircase. Impurity-based importances are biased toward high-cardinality and continuous features. Crucially, no tree model can extrapolate — predictions are constant beyond the range of the training data, so trends in time series or prices are flattened. Forests fix the variance but grow large and lose the rule-level readability. Boosting fixes the bias but will happily fit noisy labels and outliers if you let it run, so early stopping is not optional.

Neural nets on tabular data

Hungry for rows, sensitive to input scaling and initialization, expensive to tune, and on small-to-medium heterogeneous tables they usually land behind gradient boosting. They earn their place when the input has structure worth learning — sequences, images, graphs, or very high-cardinality categoricals that benefit from embeddings.

Takeaway: when a model underperforms, check its known failure mode before reaching for a different family. Half the time the fix is a scaler, a smoothing constant, or an early-stopping round.

09 Pitfalls & what to remember

Pitfalls

  • Comparing algorithms under different pipelines. If one got scaled features and tuned hyperparameters and the other did not, you compared pipelines, not algorithms.
  • Comparing on a single split. The gap between two good models is usually smaller than split-to-split noise. Use repeated cross-validation and report a spread.
  • Forgetting the scaler for distance- and gradient-based models. kNN, SVMs, penalized linear models and neural nets all need it; trees never do.
  • Expecting tree models to extrapolate. They cannot, by construction. Model trends explicitly or use a linear component.
  • Treating feature importances as causal. They describe what the model used, on this data, with these correlations.
  • Choosing by accuracy alone. Latency, memory, retraining cost, calibration and explainability are all real constraints that show up after the model ships.

What to remember

  • Every algorithm is an assumption. Performance is how well that assumption matches your data — nothing more mystical than that.
  • Boundary shape is the fastest mental model: flat (linear), local (kNN), smooth (kernel SVM), boxy (trees), arbitrary (neural nets).
  • Boosted trees own tabular; sparse linear and Naive Bayes own high-dimensional text; deep models own perceptual data.
  • Cost lives in different places — kNN pays at inference, SVMs at training, forests in memory, boosting in tuning.
  • Each family has its own page; this is the map between them, with Bias-Variance underneath and Model Evaluation keeping the comparisons honest.
