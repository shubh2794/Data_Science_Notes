Model Interpretability

Explaining what a fitted model is doing. An explanation is itself a model: a simpler object (a ranking of features, a curve, a heatmap, a short list of additive contributions) that stands in for the real function. The whole subject therefore turns on one question that is easy to skip: does the stand-in describe the model, or does it only describe what a human expected the model to do? This page builds the main tools from their definitions, shows where each one quietly lies, and ends on how to tell a faithful explanation from a merely plausible one.

01 Overview: what an explanation is for, and the map of methods

You explain a model for one of four reasons: to debug it (is it using a leaked or spurious feature?), to justify an individual decision (a declined loan needs reasons), to audit it (does it lean on a protected attribute or a proxy for one?), or to learn about the world (which variables carry signal). Each reason wants a different kind of answer.

Three axes classify every method. Intrinsic vs post-hoc: is the model readable by construction (a short tree, a sparse linear model), or do you probe an opaque model after training? Global vs local: does the answer describe the model's behaviour everywhere, or one prediction? Model-agnostic vs model-specific: does the method treat f as a black box it may only query, or does it use internals such as gradients, tree paths or attention weights?

Takeaway: before choosing a tool, write down the question. "Which features matter?" has at least three non-equivalent answers — importance to the loss, influence on the prediction, and dependence of the world's outcome — and the methods below each answer exactly one of them.

02 Intrinsically interpretable models

The most faithful explanation is the model itself. A model is intrinsically interpretable when a person can simulate it by hand and when each parameter has a stable meaning.

  • Linear models. In ŷ = β₀ + ∑ⱼ βⱼxⱼ, βⱼ is the change in ŷ per unit change of xⱼ holding the other features fixed. That clause carries the whole interpretation: under strong collinearity "holding the others fixed" describes data that never occurs, the standard errors balloon and individual signs can flip between bootstrap samples. Coefficients are only comparable after standardising features (or reporting βⱼ·sd(xⱼ)), and regularisation shrinks them toward zero, so a penalised coefficient is not an unbiased effect size.
  • Logistic regression. βⱼ is additive on the log-odds scale, so exp(βⱼ) is an odds ratio: the multiplicative change in odds per unit of xⱼ. It is not a change in probability; that depends on where you start on the sigmoid.
  • Decision trees. A depth-4 tree is a readable rule list. A 500-tree forest is not: ensembles trade the intrinsic explanation for accuracy, which is exactly why TreeSHAP (§08) exists.
  • Generalized additive models. g(E[y]) = β₀ + ∑ⱼ sⱼ(xⱼ) keeps additivity but lets each sⱼ be a smooth curve you can plot; a few chosen pairwise terms sⱼₖ(xⱼ, xₖ) can be added and shown as heatmaps. See Splines & GAMs. On tabular data, boosted GAMs are often within a point or two of a full gradient-boosted ensemble.
the additive family: every intrinsic explanation is a sum of readable partslinear: ŷ = β₀ + β₁x₁ + … + βₚxₚ logistic: log(p / (1 − p)) = β₀ + ∑ⱼ βⱼxⱼ odds ratio = exp(βⱼ) GAM: g(E[y]) = β₀ + ∑ⱼ sⱼ(xⱼ) + ∑₍ⱼ,ₖ₎ sⱼₖ(xⱼ, xₖ)

The Rashomon argument. For many tabular problems there is a large set of models with near-identical test error. If that set contains a simple one, you do not have to choose between accuracy and interpretability, and a post-hoc explanation of the complex model is strictly worse than the simple model's self-description. Try the sparse or additive model first; reach for post-hoc tools when it genuinely loses.

Takeaway: an intrinsic model is faithful by definition, but its interpretation is still conditional — on the feature scaling, on the other features included, and on the absence of severe collinearity.

03 Permutation importance and the correlated-feature trap

The model-agnostic way to rank features globally: break the link between one column and the target, and measure how much the model's score drops. If the model relied on the column, scrambling it hurts.

permutation importance of feature j, K shuffles, on held-out datas = score(f, X, y) sₖ,ⱼ = score(f, X with column j permuted, y) PIⱼ = s − (1/K)·∑ₖ sₖ,ⱼ (for a loss, use loss after − loss before)
  • Use held-out data. On training data, PI rewards features the model memorised; a random ID column can look important. On validation data it measures what generalises.
  • It explains the model, not the world. A feature the model ignores scores 0 even if it is causally important; a leaked feature scores huge. That is a feature for debugging and a bug for science.
  • Compared with impurity importance. Tree "mean decrease in impurity" is computed on training data and is biased toward high-cardinality and continuous features, which offer more candidate splits. Permutation importance does not have that bias, which is why it is the safer default for forests.

The correlated-feature trap

Suppose x₂ ≈ x₁ + small noise (say, height in cm and height in inches with rounding). Two things go wrong, in opposite directions.

  • Extrapolation inflates or distorts. Permuting x₁ alone creates rows like "190 cm but 60 inches" that never occur in the data. The model's output there is arbitrary — it was never trained on that region — so the score drop measures behaviour off the data manifold rather than reliance on the feature.
  • Credit-splitting deflates. If the model spreads its reliance across both copies, permuting either one leaves the other to carry the signal, and both can look only moderately important even though the pair is essential. Drop-column importance (retrain without the feature) shows the same effect more strongly: retrain without x₁ and x₂ compensates, so x₁ scores near zero.

Practical fixes: cluster features by correlation (for example by Spearman rank correlation) and permute whole clusters together; use conditional permutation, which shuffles xⱼ only within strata of its correlated partners; and report the spread over the K shuffles, because a single shuffle is noisy. For the statistics of shuffling itself, see Resampling.

Takeaway: low permutation importance does not mean "irrelevant" and high importance does not mean "causal". It means "this fitted model's score depends on being able to see this column, given how the other columns were left intact".

04 Partial dependence, ICE curves and ALE

Importance says how much; a dependence plot says in what shape. Split the features into the ones of interest S (usually one or two) and the complement C. Fix x_S at a grid value, leave every row's x_C as observed, and average.

partial dependence: average the model over the marginal distribution of the other featuresPD_S(x_S) = E_X_C[ f(x_S, X_C) ] ≈ (1/n)·∑ᵢ f(x_S, x_C⁽ⁱ⁾) individual conditional expectation: one curve per row, no averagingICE⁽ⁱ⁾(x_S) = f(x_S, x_C⁽ⁱ⁾) PD_S = mean of the ICE curves centred ICE: anchor every curve at a reference point x*c-ICE⁽ⁱ⁾(x_S) = f(x_S, x_C⁽ⁱ⁾) − f(x*, x_C⁽ⁱ⁾)
  • PDP hides interactions. Take f = x₁·x₂ with x₂ symmetric around 0. Half the ICE curves slope up, half slope down, and the PDP is flat. The PDP says "x₁ does nothing"; the ICE plot shows that x₁ does a lot, in opposite directions for different rows. When ICE curves cross or fan out, the additive summary is lying by averaging.
  • PDP extrapolates under correlation. The average uses the marginal of X_C, so for each grid value of x₁ it pairs every observed x₂ with it, including combinations that never occur. This is the same off-manifold problem as permutation importance.
  • For a purely additive model f = g(x_S) + h(x_C), all ICE curves are vertical shifts of each other, c-ICE curves coincide, and the PDP recovers g up to a constant. Parallel ICE curves are therefore a visual test of additivity in x_S.

Accumulated local effects

ALE replaces "set x_S to a value for everyone" with "nudge x_S a little, only for rows that already live near that value". Bin x_S, compute the average finite difference of the prediction across each bin using only the rows in the bin, and accumulate.

ALE, with bin edges z₀ < z₁ < … and Nₖ the rows falling in bin kALE(x) = ∑ₖ₌₁..ₖ₍ₓ₎ (1/|Nₖ|)·∑ᵢ∈Nₖ [ f(zₖ, x_C⁽ⁱ⁾) − f(zₖ₋₁, x_C⁽ⁱ⁾) ] − constant continuous limit: ALE(x) = ∫ E[ ∂f/∂x_S | X_S = z ] dz

Because each difference is evaluated only on rows whose x_S already lies in the bin, ALE never asks the model about impossible combinations. The price is that it answers a different question: it reports the effect of x_S as it co-occurs with its correlated partners.

Takeaway: plot ICE under every PDP. The PDP is a mean; the ICE spread is its variance, and a flat mean with a wide spread is the signature of an interaction.

Two things to notice. At β = 0 the model is additive, the ICE curves are parallel and the centred view collapses them onto the PDP. At high correlation and high β, the PDP and ALE disagree, and neither is "wrong": the PDP answers "what if I set x₁ for everyone, keeping their x₂", which includes counterfactual rows the model has never seen; ALE answers "how does the prediction change locally along the data".

06 Shapley values: fair division of a prediction

Treat the features as players in a cooperative game whose payout is the prediction. The question "how much of f(x) is due to feature i?" becomes "how should a coalition's payout be split among its members?" — a problem with a unique answer once you insist on four reasonable rules.

The game

Let N = {1, …, M} be the features and, for each coalition S ⊆ N, let v(S) be the prediction when only the features in S are "known". A common choice is the interventional value function, which fills the unknown features from a background distribution (or a single baseline point b):

value functions — what "feature i is absent" means is a modelling choiceinterventional: v(S) = E_X_S̄[ f(x_S, X_S̄) ] single baseline: v(S) = f(x_S, b_S̄) observational: v(S) = E[ f(X) | X_S = x_S ] v(∅) = E[f(X)] (the base value φ₀) v(N) = f(x)

The Shapley value

Average feature i's marginal contribution v(S ∪ {i}) − v(S) over all orders in which the features could be added. Counting orderings gives the weight for each coalition: S's members arrive first in any of |S|! orders, then i, then the rest in (M − |S| − 1)! orders, out of M! total.

Shapley value of feature iφᵢ = ∑_S⊆N∖{i} [ |S|! · (M − |S| − 1)! / M! ] · [ v(S ∪ {i}) − v(S) ] equivalently, the average over all M! orderings π of the featuresφᵢ = (1/M!) · ∑_π [ v(Pᵢ(π) ∪ {i}) − v(Pᵢ(π)) ] Pᵢ(π) = features before i in π

The four axioms — and why they pin the answer down

AxiomStatementMeaning for attributions
Efficiency∑ᵢ φᵢ = v(N) − v(∅)The contributions add up exactly to f(x) − E[f(X)]. Nothing is left over or double-counted.
SymmetryIf v(S ∪ {i}) = v(S ∪ {j}) for every S containing neither, then φᵢ = φⱼTwo features that the model treats identically get identical credit.
Dummy (null player)If v(S ∪ {i}) = v(S) for every S, then φᵢ = 0A feature that never changes the prediction gets zero credit.
Additivityφᵢ(v + w) = φᵢ(v) + φᵢ(w)For a sum of models (a boosted ensemble, a bagged average), attributions are the sum of per-model attributions.

Shapley's theorem: the formula above is the only allocation satisfying all four. That uniqueness is the method's main selling point — any other attribution must break at least one of these properties. (Some presentations replace additivity with a monotonicity axiom; the same unique solution results.)

Worked example: a three-feature model with an interaction

Let f(x) = 2x₁ + x₂ + 0·x₃ + x₁x₂, explain x = (1, 2, 5) against baseline b = (0, 0, 0), using v(S) = f(x_S, b_S̄).

the eight coalition valuesv(∅) = 0 v{1} = 2 v{2} = 2 v{3} = 0 v{1,2} = 2 + 2 + 2 = 6 v{1,3} = 2 v{2,3} = 2 v{1,2,3} = 6 weights for M = 3: |S| = 0 → 1/3, |S| = 1 → 1/6, |S| = 2 → 1/3φ₁ = ⅓(2 − 0) + ⅙(6 − 2) + ⅙(2 − 0) + ⅓(6 − 2) = 0.667 + 0.667 + 0.333 + 1.333 = 3 φ₂ = ⅓(2 − 0) + ⅙(6 − 2) + ⅙(2 − 0) + ⅓(6 − 2) = 3 φ₃ = 0 (null player) efficiency: φ₁ + φ₂ + φ₃ = 6 = f(x) − f(b)

Read the result: x₁'s own term contributes 2, x₂'s contributes 2, and the interaction term x₁x₂ = 2 is split equally, 1 to each. In general, for this model with baseline b,

closed form for a linear model with one pairwise interactionφ₁ = w₁(x₁ − b₁) + ½·w₁₂·(x₁ − b₁)(x₂ + b₂) φ₂ = w₂(x₂ − b₂) + ½·w₁₂·(x₂ − b₂)(x₁ + b₁) φ₃ = w₃(x₃ − b₃) a purely linear model with independent features reduces toφᵢ = wᵢ · (xᵢ − E[xᵢ])
Takeaway: Shapley values do not discover interactions — they divide them. An interaction's payout is split among its participants, so a large φᵢ can come from feature i alone or from i's partnership with others. SHAP interaction values (a separate M × M decomposition) are needed to tell the two apart.

08 SHAP in practice: KernelSHAP, TreeSHAP and their caveats

Exact Shapley values need v(S) for all 2ᴹ coalitions, each of which is itself an expectation over background data. Practical SHAP is a set of ways to avoid that cost. All of them produce the same additive explanation model:

additive feature attribution: z′ ∈ {0,1}ᴹ marks which features are presentg(z′) = φ₀ + ∑ᵢ φᵢ·z′ᵢ g(1, …, 1) = φ₀ + ∑ᵢ φᵢ = f(x) φ₀ = E[f(X)]

KernelSHAP (model-agnostic)

Sample coalitions z′, evaluate v on each, and fit the linear model g by weighted least squares. With the right weight per coalition size, the regression solution is exactly the Shapley value — the link between LIME-style surrogates and game theory.

the Shapley kernel; |z′| = number of present featuresπ(z′) = (M − 1) / [ C(M, |z′|) · |z′| · (M − |z′|) ] weights are infinite at |z′| = 0 and |z′| = M → enforced as constraints: g(0) = φ₀, g(1) = f(x)

The kernel is largest for very small and very large coalitions, because those reveal a feature's effect most directly (alone, or as the last one added). Cost scales with the number of sampled coalitions times the background size; a background set of 50–200 rows (often k-means centroids) is typical, and results vary with that choice.

TreeSHAP (model-specific, exact)

For tree ensembles, a recursive algorithm pushes all coalitions down each tree simultaneously, tracking what fraction of orderings reach each leaf. It computes exact Shapley values in O(T · L · D²) time — T trees, L leaves, depth D — instead of exponential in M. Two variants matter: path-dependent TreeSHAP uses the training-sample counts stored in the nodes to approximate the conditional distribution and needs no background data; interventional TreeSHAP uses a background set and matches the interventional value function. Their answers differ when features are correlated.

Reading SHAP output

  • Local: a waterfall or force plot for one row, from φ₀ to f(x). Note the units: for a classifier these are usually log-odds, not probabilities, because additivity holds on the model's raw output.
  • Global: mean |φᵢ| over rows gives an importance ranking of influence on the prediction (not on the loss — compare with §03). A beeswarm (one dot per row, coloured by feature value) shows direction and spread together.
  • Dependence: φᵢ plotted against xᵢ is SHAP's answer to the PDP; vertical spread at fixed xᵢ signals interactions.

Caveats

  • Interventional vs observational is not a technicality. Interventional SHAP explains the model (it gives zero to a feature the model ignores, even if it is correlated with one it uses), but it evaluates off-manifold points. Observational SHAP stays on the data but spreads credit onto correlated features the model never reads. Pick deliberately and state which.
  • Not causal. φᵢ says how the model's output decomposes, not what would happen to the outcome if you intervened on xᵢ in the world.
  • Adversarial models. Because perturbation-based explainers query off-manifold points, a model can be built to behave innocently on those queries and discriminate on real data, fooling both KernelSHAP and LIME. This is a concrete reason to treat explanations as evidence, not proof.

09 Local surrogates and counterfactuals

LIME explains one prediction by fitting an interpretable model g (sparse linear, short tree) to the black box f on perturbed samples around x, weighting each sample by its proximity to x.

the LIME objective — local fidelity plus a complexity penaltyξ(x) = argmin_g∈G L(f, g, πₓ) + Ω(g) L(f, g, πₓ) = ∑_z πₓ(z) · ( f(z) − g(z′) )² πₓ(z) = exp( −D(x, z)² / σ² ) Ω(g) = complexity, e.g. ∞ if g uses more than K features
  • The kernel width σ is the hidden hyperparameter. Too narrow and the fit rests on a handful of samples (noisy); too wide and "local" becomes global, so the explanation describes a different region. Different σ can flip the sign of a coefficient for the same row.
  • Instability. Because samples are random, re-running LIME on the same point can return different top features. Run it several times and check that the explanation is stable before showing it to anyone.
  • Representation matters. For text, z′ toggles words; for images, z′ toggles superpixels. The segmentation algorithm is part of the explanation.
  • Global surrogates fit a single interpretable model to f's predictions over the whole dataset. Always report its fidelity — the R² or agreement rate between surrogate and model on held-out rows. A surrogate with 70% agreement explains 70% of a model.

Counterfactual explanations

Instead of "why", answer "what would have to change": the smallest edit to x that flips the decision.

x′ = argmin_x′ d(x, x′) subject to f(x′) = y_target, x′ feasible relaxed: argmin_x′ λ·( f(x′) − y_target )² + d(x, x′)

Counterfactuals are actionable ("income 4,000 higher would have approved the loan") and need no baseline, but there are usually many valid ones, they must respect immutable features (age cannot decrease) and plausibility constraints, and like everything else here they describe the model, not a causal lever in the world.

10 Gradient attributions for deep networks: saliency, integrated gradients, Grad-CAM

For a differentiable model there is a cheaper signal than queries: the gradient of the class score y_c (taken before the softmax, so other classes do not leak in) with respect to the input. These methods dominate in image classification; see CNNs for the architecture they probe and Calculus for the gradient machinery.

vanilla saliency and its noise-averaged versionSᶜ(x) = | ∂y_c / ∂x | gradient × input: xᵢ · ∂y_c/∂xᵢ SmoothGrad: Ŝᶜ(x) = (1/n)·∑ₖ ∂y_c(x + εₖ)/∂x, εₖ ~ N(0, σ²I)

Raw gradients are noisy and suffer from saturation: if a feature has already pushed a ReLU or sigmoid into its flat region, its local gradient is near zero even though it is responsible for the output.

Integrated gradients

Fix saturation by integrating the gradient along a straight path from a baseline x′ (a black image, an all-padding sequence) to the input.

integrated gradients for input dimension i, and its Riemann approximation with m stepsIGᵢ(x) = (xᵢ − x′ᵢ) · ∫₀¹ ∂f( x′ + α(x − x′) ) / ∂xᵢ dα IGᵢ(x) ≈ (xᵢ − x′ᵢ) · (1/m) · ∑ₖ₌₁..ₘ ∂f( x′ + (k/m)(x − x′) ) / ∂xᵢ completeness — the gradient-world analogue of Shapley efficiency∑ᵢ IGᵢ(x) = f(x) − f(x′)

Completeness follows from the fundamental theorem of calculus for path integrals. IG also satisfies sensitivity (a feature that changes the output gets non-zero attribution) and implementation invariance (two networks computing the same function get the same attributions), and it coincides with the Aumann–Shapley value, the continuous-game version of §06. Check completeness numerically: if the sum is far from f(x) − f(x′), increase m (20–300 steps is typical). The baseline is the method's main free choice — a black baseline cannot attribute anything to black pixels.

CAM and Grad-CAM

Pixel-level maps are fine-grained but noisy. Class-activation maps work at the last convolutional layer instead, where each channel Aᵏ is a spatial map of a high-level feature.

CAM — needs a global-average-pooling head with class weights w_k^cM_c(i, j) = ∑ₖ wₖᶜ · Aᵏᵢⱼ Grad-CAM — any CNN: channel weights from spatially averaged gradientsαₖᶜ = (1/Z) · ∑ᵢ ∑ⱼ ∂y_c / ∂Aᵏᵢⱼ L_Grad-CAMᶜ = ReLU( ∑ₖ αₖᶜ · Aᵏ ) Z = number of spatial positions

The ReLU keeps only regions that push the class score up. The map has the coarse resolution of the last conv layer (7 × 7 for a 224 × 224 ResNet input) and is upsampled onto the image; multiplying it by a fine-grained gradient map ("guided Grad-CAM") recovers detail. For object detection the same idea is applied per box score.

Sanity checks

A widely replicated test: randomise the model's weights layer by layer, or train on shuffled labels, and recompute the map. A faithful method must produce a very different map, because the model has changed. Several popular methods — notably guided backpropagation — produce nearly the same image-like map regardless, which shows they behave largely like edge detectors on the input rather than explanations of the model. Plain gradients and Grad-CAM pass these tests.

Takeaway: a saliency map that looks like a clean outline of the object is not evidence of faithfulness. The question is whether it changes when the model changes.

11 Attention as an explanation, and why that is contested

An attention layer computes weights a_ij = softmax_j(qᵢ·kⱼ / √d) that visibly say "token i looked at token j". It is tempting to read them as the model's reasons. The evidence says to be careful.

  • Weights are not contributions. The output is ∑ⱼ a_ij·vⱼ, so what reaches the next layer is the weight times the value vector. A large weight on a token with a tiny value vector (often a separator or punctuation token acting as a "no-op" sink) contributes little. Norm-based analyses of ‖a_ij·vⱼ‖ give a different and usually more sensible picture than raw weights.
  • Alternative attention, same output. In several text classifiers, attention weights were permuted or adversarially replaced with very different distributions while the prediction barely changed, and they correlated weakly with gradient-based importance. If many attention patterns yield the same answer, any one of them is a weak explanation.
  • The counter-argument. Whether an alternative distribution exists does not settle whether the learned one is meaningful; when the model is retrained with attention constrained to match an adversarial pattern, performance often drops, so attention can carry real signal. The defensible position: attention can be an explanation in specific settings, but it is not the explanation by default.
  • Depth mixes everything. After a few layers every position is a blend of all tokens, and the residual stream carries information around attention entirely. Per-layer weights therefore describe mixing of already-mixed representations. Attention rollout and attention flow propagate weights through layers (including the identity path) as a partial fix.
  • Probing and mechanistic analysis. A linear probe trained on hidden states shows that information is decodable, not that the model uses it; a high-accuracy probe can learn the task itself. Intervention-based methods — activation patching, causal ablation, reading the residual stream through the unembedding — test use directly. See Residual Stream, Norms & FFN, Depth, Width & the Logit Lens, and the attention and probing analyses on BERT: Fine-Tuning, Probing & Results.
Takeaway: attention tells you where information was routed, not why the output is what it is. To claim the latter, intervene: remove or patch the attended information and measure the change in the output.

12 Faithful vs plausible: evaluating explanations

A plausible explanation convinces a human. A faithful explanation accurately reflects the computation the model performed. They are independent: an explanation can be plausible and unfaithful (a neat outline produced by an edge detector) or faithful and implausible (a model that really does key on a watermark). Human-preference studies measure the first; only interventions measure the second.

Faithfulness tests

  • Deletion and insertion curves. Remove features in order of attributed importance and track the score; a faithful ranking makes it fall fastest. Insertion runs the reverse, starting from the baseline. Area under each curve is a summary.
  • Remove and retrain. Deleting pixels creates off-distribution inputs, so a score drop may reflect the artefact rather than the information. Retraining on the modified data and measuring the accuracy drop separates the two, at the cost of many retrains.
  • Model and data randomisation (§10): the explanation must change when the model does.
  • Planted ground truth. Train on data with a known spurious feature (a coloured patch that perfectly predicts the label) and check whether the method finds it. This is the closest thing to a unit test.
  • Completeness and stability. Do attributions sum to what they claim (Shapley efficiency, IG completeness)? Do they stay stable under tiny, prediction-preserving input perturbations and across random seeds?
