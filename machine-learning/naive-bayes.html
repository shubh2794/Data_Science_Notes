Naive Bayes

SupervisedProbabilistic Apply Bayes' rule with one brazen "naive" assumption — every feature is conditionally independent given the class — and you get a classifier that's fast, tiny, and shockingly good at text.

Overview

Naive Bayes is a family of probabilistic classifiers built on Bayes' theorem. Each predicts the class with the highest posterior probability given the observed features. Despite an assumption that's almost always false, it's remarkably robust — and a long-standing favorite for spam filtering, text classification, and medical diagnostics.

From Bayes' theorem to "naive"

Bayes' theorem inverts a conditional probability — turning the likelihood of the evidence into the posterior of the class:

Bayes' theoremP(C | X) = P(X | C) · P(C) / P(X)
  • P(C | X) — posterior: probability of class C after seeing the data.
  • P(X | C) — likelihood: probability of the data under class C.
  • P(C) — prior: how common class C is overall.
  • P(X) — evidence: a normalizing constant (same for every class).

The hard part is the joint likelihood P(x₁,…,xₙ | C). The naive assumption is that features are conditionally independent given the class, which factorizes it into a simple product:

conditional-independence (the "naive" part)P(x₁, x₂, …, xₙ | C) = ∏ᵢ P(xᵢ | C)

The decision rule (MAP / argmax)

Since P(X) is identical across classes, we can drop it and just compare numerators — the maximum a posteriori (MAP) rule:

predict the class with the largest posteriorĉ = argmax_c P(c) · ∏ᵢ P(xᵢ | c)

Multiplying many small probabilities underflows to zero, so in practice we work in log-space — products become sums, and the argmax is unchanged:

numerically stable log formĉ = argmax_c [ log P(c) + Σᵢ log P(xᵢ | c) ]

The priors and likelihoods are estimated from training-data frequencies by maximum likelihood. Equivalently, training minimizes the negative log-likelihood, NLL = −Σ log P(Cᵢ | Xᵢ).

Three variants — pick by your feature type

The variants differ only in how they model the per-feature likelihood P(xᵢ | c):

VariantFeature typeLikelihood model
GaussianContinuousNormal distribution per class
MultinomialDiscrete counts (word frequencies)Count proportions
BernoulliBinary (presence/absence)Per-feature probability of being 1
Gaussian — fit μ, σ² per feature per classP(xᵢ | c) = (1 / √(2π σ²_c)) · exp( − (xᵢ − μ_c)² / (2 σ²_c) )
Multinomial — smoothed count proportions (V = vocab size)P(xᵢ | c) = ( count(xᵢ, c) + α ) / ( Σₓ count(x, c) + α·V )
Bernoulli — explicitly models absence tooP(xᵢ | c) = p_(ic)^(xᵢ) · (1 − p_(ic))^((1 − xᵢ))

Laplace smoothing & log-probabilities

The zero-frequency trap. If a word never appeared in spam during training, its likelihood is 0 — and because the rule multiplies likelihoods, that single zero annihilates the whole product, no matter how spammy everything else looks.

Laplace (additive) smoothing fixes this by adding a pseudo-count α (usually 1) to every count, so no probability is ever exactly zero:

additive smoothing · K = number of possible valuesP̂(xᵢ | c) = ( count(xᵢ, c) + α ) / ( N_c + α·K )
  • Log-probabilities (from the decision-rule section) are the second numerical-stability safeguard: summing logs avoids the underflow of multiplying thousands of tiny probabilities.

Worked example — spam from one word

Suppose P(Spam)=0.2, P(¬Spam)=0.8, and for the word "offer": P(offer|Spam)=0.9, P(offer|¬Spam)=0.1. An email contains "offer".

evidence (normalizer)P(X) = P(X|S)·P(S) + P(X|¬S)·P(¬S) = (0.9·0.2) + (0.1·0.8) = 0.18 + 0.08 = 0.26
posteriorsP(Spam | X) = 0.18 / 0.26 ≈ 0.692 P(¬Spam | X) = 0.08 / 0.26 ≈ 0.308

Spam wins (0.692 > 0.308) → classified as spam. With more words, you'd multiply each one's likelihood into the product (or add its log).

Pros, cons & where it's used

Strengths

  • Simple, fast, and trains in a single pass — no iterative optimization.
  • Scales effortlessly to very high-dimensional data (e.g. bag-of-words text).
  • Works well with little training data and is a strong baseline.

Limitations

  • The conditional-independence assumption rarely holds, so correlated features can hurt it.
  • Limited expressiveness for complex feature interactions; sensitive to class imbalance.
  • Its probability estimates are often poorly calibrated (the ranking/argmax is usually fine).

Why it's great for text

Even though words clearly aren't independent, the argmax tends to land on the right class anyway — and with thousands of sparse word features, the cheap factorized model is exactly what scales. Hence its staying power in spam filtering, sentiment analysis, and document classification.
