Reinforcement Learning

Learning from Feedback Sequential Decisions No labels, only consequences. An agent acts, the world responds with a scalar reward and a new state, and the agent must work out — from delayed, noisy, self-generated experience — which of its past decisions were responsible.

01 Overview: what makes RL hard

Supervised learning is told the right answer. RL is only told how well things went, eventually, for a whole sequence of choices.

That difference creates four problems at once, and every algorithm on this page is an attack on one of them.

  • Evaluative, not instructive feedback. A reward of +1 says the action was good; it does not say which action would have been better. Without a gradient toward the right answer you have to search.
  • Delayed reward and credit assignment. The move that won the game may have been forty steps before the reward arrived. Discounted returns and bootstrapping exist to propagate credit backwards.
  • Non-i.i.d., non-stationary data. The agent generates its own training distribution, and that distribution changes as the policy improves. Standard supervised guarantees simply do not apply.
  • Exploration. You can only learn about actions you take, so an agent that always exploits its current best guess may never discover that a better option exists.
Takeaway: RL is optimisation over behaviour rather than over predictions. The objective is expected cumulative reward, and everything else — value functions, Bellman equations, policy gradients — is machinery for estimating or improving that one quantity.

02 The MDP formalism

Almost all of RL is stated on a Markov Decision Process, the tuple (S, A, P, R, γ). The Markov property is the key assumption: the current state summarises everything from the past that matters for the future, so P(sₜ₊₁ | sₜ, aₜ) does not improve if you also condition on the earlier history.

the five ingredients S — state space A — action space (possibly A(s), state-dependent) P(s′ | s, a) — transition kernel, ∑_{s′} P(s′ | s, a) = 1 R(s, a, s′) — reward function (often written as the expected reward r(s, a)) γ ∈ [0, 1) — discount factor a policy maps states to action distributionsπ(a | s) = P(Aₜ = a | Sₜ = s) deterministic case: a = π(s)

Returns and the role of γ

The agent maximises the return, the discounted sum of future rewards from time t onward. The recursive form on the right is the seed of every Bellman equation on this page.

discounted return Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + … = ∑_{k=0}^{∞} γᵏ Rₜ₊ₖ₊₁ Gₜ = Rₜ₊₁ + γ·Gₜ₊₁ why γ < 1 matters|Gₜ| ≤ R_max / (1 − γ) effective horizon ≈ 1/(1 − γ) γ = 0.99 ⟹ ≈ 100 steps

Discounting does three jobs. Mathematically it keeps the return finite in infinite-horizon tasks and makes the Bellman operator a contraction, which is what guarantees convergence. Practically it is a horizon knob: a small γ makes a myopic agent that learns fast and stably, a large γ makes a far-sighted one that is slower and higher-variance. Setting γ too low is a common silent failure — the agent is not stupid, it is being told the future does not matter.

Modelling choices that decide everything

The reward function is the specification, and agents optimise it literally. Reward that is too sparse ("+1 at the goal, 0 otherwise") gives almost no learning signal; reward that is shaped too eagerly invites reward hacking, where the agent finds a loophole that scores well and misses the intent entirely. Potential-based shaping — adding γΦ(s′) − Φ(s) for any function Φ — is the one form provably guaranteed to leave the optimal policy unchanged. Likewise, if the agent cannot observe the true state you have a POMDP, and the standard repair is to feed it a history: stacked frames, or a recurrent state.

Takeaway: writing down S, A, R and γ is most of the work. A badly specified reward or a state that violates the Markov property cannot be fixed by a better algorithm.

03 Value functions and the Bellman equations

A value function scores situations rather than moments: how much total reward should I expect from here on, if I follow policy π?

state value and action value Vπ(s) = 𝔼π[ Gₜ | Sₜ = s ] Qπ(s, a) = 𝔼π[ Gₜ | Sₜ = s, Aₜ = a ] they determine each otherVπ(s) = ∑ₐ π(a | s)·Qπ(s, a) Aπ(s, a) = Qπ(s, a) − Vπ(s) ← the advantage

The advantage is the quantity policy-gradient methods actually want: not "is this state good" but "is this action better than what I usually do here". By construction ∑ₐ π(a|s)·Aπ(s,a) = 0, so it has mean zero and much smaller variance than the raw return.

Bellman expectation: value is self-consistent

Substituting Gₜ = Rₜ₊₁ + γGₜ₊₁ into the definition and taking expectations turns a sum over an infinite future into a one-step relation. This is the whole trick.

Bellman expectation equations for a fixed π Vπ(s) = ∑ₐ π(a|s) ∑_{s′} P(s′|s,a)·[ R(s,a,s′) + γ·Vπ(s′) ] Qπ(s,a) = ∑_{s′} P(s′|s,a)·[ R(s,a,s′) + γ·∑_{a′} π(a′|s′)·Qπ(s′,a′) ]

Bellman optimality: value under the best possible behaviour

Replace "average over what π does" with "take the best action". The result is a nonlinear system (because of the max) whose unique solution is the optimal value function, from which an optimal policy is read off greedily.

Bellman optimality equations V*(s) = max_a ∑_{s′} P(s′|s,a)·[ R(s,a,s′) + γ·V*(s′) ] Q*(s,a) = ∑_{s′} P(s′|s,a)·[ R(s,a,s′) + γ·max_{a′} Q*(s′,a′) ] and the optimal policy needs no model at all if you have Q*π*(s) = argmax_a Q*(s, a) V*(s) = max_a Q*(s, a)

The final line explains why Q is the more useful object in practice. To act greedily on V* you must look one step ahead through P — which means you need a model of the environment. To act greedily on Q* you just compare numbers you already stored.

Takeaway: every RL algorithm is either solving a Bellman equation (dynamic programming, with a known model) or sampling one (temporal-difference learning, from experience).

04 Planning with a known model: policy and value iteration

If P and R are known, the Bellman equations become a system you can simply solve. Turning each into an assignment gives an operator, and iterating that operator converges.

Policy iteration

Alternate two steps until nothing changes. Policy evaluation computes Vπ by sweeping the Bellman expectation update to convergence (or just a few sweeps — "modified" policy iteration). Policy improvement then makes the policy greedy with respect to that value. The policy improvement theorem guarantees the new policy is at least as good everywhere, and since there are finitely many deterministic policies and each round strictly improves until it cannot, the loop terminates at an optimum.

policy iteration evaluate: V(s) ← ∑ₐ π(a|s) ∑_{s′} P(s′|s,a)·[ R + γV(s′) ] (repeat until stable) improve: π(s) ← argmax_a ∑_{s′} P(s′|s,a)·[ R + γV(s′) ] value iteration — fold the max into the sweep, no explicit policyV_{k+1}(s) ← max_a ∑_{s′} P(s′|s,a)·[ R + γ·V_k(s′) ] then once, at the end: π(s) = argmax_a ∑_{s′} P(s′|s,a)·[ R + γV(s′) ]

Why it converges: contraction

Write the update as an operator T. In the max-norm, T shrinks distances by a factor γ, so by the Banach fixed-point theorem it has a unique fixed point (which is V*) and iterates approach it geometrically. This is the formal reason γ < 1 is required, and it also gives a stopping rule.

γ-contraction in the max norm ‖T V − T V′‖_∞ ≤ γ·‖V − V′‖_∞ ⟹ ‖V_k − V*‖_∞ ≤ γᵏ·‖V₀ − V*‖_∞ practical stopping boundif ‖V_{k+1} − V_k‖_∞ < ε then ‖V_{k+1} − V*‖_∞ < ε·γ/(1 − γ)

One sweep costs O(|S|²|A|), so exact DP is only practical for small, enumerable state spaces — and it needs the model. Its real importance is conceptual: every model-free method below is a sampled, incremental approximation of one of these two loops, a pattern called generalized policy iteration (evaluate a bit, improve a bit, repeat).

Takeaway: DP is what RL would be if you knew the rules of the world and could afford to enumerate it. Model-free RL replaces the expectation ∑_{s′}P(s′|s,a) with a single sampled transition.

05 Model-free learning: Monte-Carlo, TD, SARSA, Q-learning

Without P you cannot compute the expectation, but you can sample it. Every method here has the same shape — nudge the current estimate toward a target built from experience.

the universal update estimate ← estimate + α·[ target − estimate ] α = learning rate

Monte-Carlo versus temporal difference

Monte-Carlo waits for the episode to finish and uses the actual return Gₜ as the target. It is unbiased and needs no Markov assumption, but it is high-variance (the return accumulates every subsequent random event) and works only for episodic tasks. TD(0) instead bootstraps: it uses its own estimate of the next state as a stand-in for the rest of the episode, so it can learn online, from incomplete episodes, and with far lower variance — at the cost of bias while that estimate is still wrong.

the two targets, and the TD error MC: V(Sₜ) ← V(Sₜ) + α·[ Gₜ − V(Sₜ) ] TD(0): V(Sₜ) ← V(Sₜ) + α·[ Rₜ₊₁ + γ·V(Sₜ₊₁) − V(Sₜ) ] δₜ = Rₜ₊₁ + γ·V(Sₜ₊₁) − V(Sₜ) ← the TD error: surprise, in units of value n-step interpolates between them; TD(λ) averages over all nG⁽ⁿ⁾ₜ = Rₜ₊₁ + γRₜ₊₂ + … + γⁿ⁻¹Rₜ₊ₙ + γⁿ·V(Sₜ₊ₙ) n = 1 → TD(0), n = ∞ → MC

SARSA versus Q-learning: on-policy or off-policy

Moving from prediction to control means learning Q and acting greedily on it. The two classical algorithms differ in exactly one symbol — what they assume happens next.

on-policy: bootstrap from the action actually taken next SARSA: Q(S,A) ← Q(S,A) + α·[ R + γ·Q(S′, A′) − Q(S,A) ] A′ ~ π (ε-greedy) off-policy: bootstrap from the best action, whatever you actually didQ-learning: Q(S,A) ← Q(S,A) + α·[ R + γ·max_{a′} Q(S′,a′) − Q(S,A) ] expected SARSA: average instead of sample — same bias, less varianceQ(S,A) ← Q(S,A) + α·[ R + γ·∑_{a′} π(a′|S′)·Q(S′,a′) − Q(S,A) ]

Tabular Q-learning converges to Q* with probability 1 provided every state–action pair is visited infinitely often and the learning rate satisfies the Robbins–Monro conditions ∑αₜ = ∞, ∑αₜ² < ∞. Note the first condition is a requirement on exploration: convergence is conditional on never fully abandoning it.

Takeaway: the max in Q-learning is what makes it off-policy — and also what makes it optimistic, because the maximum of noisy estimates is biased upward even when every estimate is individually unbiased.

07 Function approximation and DQN

A table has one entry per state–action pair, which is hopeless once the state is an image or a continuous vector. Replace it with a parameterised function Q(s, a; θ) and fit θ by regression on the TD target.

semi-gradient TD — the target is treated as a constant L(θ) = 𝔼[ ( R + γ·max_{a′} Q(s′, a′; θ⁻) − Q(s, a; θ) )² ] θ ← θ + α·δ·∇θ Q(s, a; θ) ← no gradient flows through the target

It is called semi-gradient because we deliberately do not differentiate the bootstrapped target; doing so gives a different (residual-gradient) algorithm that is more stable but learns much more slowly. The consequence is that this is not gradient descent on any fixed objective, which is where instability comes from.

The deadly triad

Divergence becomes possible when three ingredients are combined: function approximation, bootstrapping, and off-policy updates. Any two are safe; all three can make the values blow up. Deep Q-Networks want all three, so they buy stability with engineering rather than theory.

  • Experience replay. Store transitions in a buffer and train on random minibatches. Breaks the temporal correlation that makes consecutive samples nearly identical, and reuses data many times. Prioritized replay samples in proportion to |δ| and corrects the induced bias with importance weights.
  • Target network. Compute the target with a frozen copy θ⁻, synced every few thousand steps (or Polyak-averaged). Without it the regression target moves every time the weights move — chasing your own tail.
  • Double DQN. The max both selects and evaluates the next action, so noise inflates it. Split the two roles: select with the online network, evaluate with the target network.
  • Dueling architecture. Two heads, V(s) and A(s,a), recombined as Q = V + (A − mean_a A). Learns state value even in states where the action barely matters.
  • Reward clipping, frame stacking, n-step returns, noisy layers, distributional value heads — the rest of the standard toolbox.
Double DQN target — decouple selection from evaluation y = R + γ·Q( s′, argmax_{a′} Q(s′, a′; θ) ; θ⁻ )

Note the structural limitation: the max over actions requires enumerating A, so value-based methods are natural for discrete action sets and awkward for continuous control — which is one of the reasons policy-based methods exist.

Takeaway: replay and target networks are not incidental tricks. They convert a moving, correlated, self-referential problem into something close enough to supervised regression for SGD to work.

08 Policy gradients, REINFORCE, actor-critic

Instead of learning values and deriving a policy, parameterise the policy π_θ(a|s) directly and ascend the gradient of expected return. This handles continuous actions naturally, can represent genuinely stochastic optimal policies, and changes behaviour smoothly rather than flipping an argmax.

The log-derivative trick

The objective is an expectation over trajectories whose distribution depends on θ, so you cannot just push the derivative inside. The identity ∇p = p·∇log p converts it back into an expectation you can sample.

objective, then the trick J(θ) = 𝔼_{τ ~ p_θ}[ R(τ) ] = ∫ p_θ(τ)·R(τ) dτ ∇θ J = ∫ ∇θ p_θ(τ)·R(τ) dτ = ∫ p_θ(τ)·∇θ log p_θ(τ)·R(τ) dτ = 𝔼[ R(τ)·∇θ log p_θ(τ) ] the trajectory likelihood — and why the dynamics vanishlog p_θ(τ) = log p(s₀) + ∑ₜ [ log π_θ(aₜ|sₜ) + log P(sₜ₊₁|sₜ,aₜ) ] ∇θ log p_θ(τ) = ∑ₜ ∇θ log π_θ(aₜ|sₜ) ← P and p(s₀) are free of θ: no model needed

That last line is the reason policy gradients are model-free: the environment's dynamics are constants with respect to θ and differentiate away.

REINFORCE and baselines

Sampling the expectation gives the REINFORCE estimator. Two refinements make it usable. Causality: an action cannot affect rewards that already happened, so replace R(τ) with the return from t onward. Baselines: subtracting any state-dependent b(s) leaves the gradient unbiased — because 𝔼[∇θ log π_θ(a|s)] = 0 — while cutting variance substantially. The best simple baseline is V(s), which turns the weight into the advantage.

Trust regions and PPO, in a paragraph

Raw policy gradients are fragile: one large step can collapse the policy, and because the data was collected under the old policy, a big update invalidates it. Trust-region methods therefore constrain how far the new policy may move — TRPO by a KL-divergence constraint solved with a second-order approximation, and PPO by a far cheaper first-order surrogate that simply clips the probability ratio, removing any incentive to move past the trust region. Combined with GAE (an exponentially weighted average over n-step advantages that trades bias against variance with a parameter λ) and an entropy bonus to keep exploring, PPO is the default on-policy workhorse. Off-policy continuous-control alternatives — DDPG, TD3, SAC — instead keep a replay buffer and learn a deterministic or maximum-entropy stochastic policy against a learned critic.

These are the methods that reappear beyond games. Aligning a language model to human preferences is a policy-gradient problem where the "environment" is a reward model over responses — see Policy / Preference Optimization. Training an agent to use tools over many turns extends the same machinery to long trajectories with sparse, verifiable outcomes — see Agentic RL.

Takeaway: value methods ask "how good is this action?" and act greedily; policy methods ask "should I do this more or less often?" and nudge. Actor-critic keeps both, using the value estimate purely as a variance-reduction device.

09 Exploration versus exploitation

You can only learn about actions you take. An agent that always takes its current best action may be stuck on a mediocre path it happened to find first, and will never collect the evidence that would change its mind. But an agent that explores forever never cashes in what it learned. Every practical scheme is a schedule for shifting between the two.

ε-greedy π(a|s) = 1 − ε + ε/|A| if a = argmax_a Q(s,a) ε/|A| otherwise softmax / Boltzmann — explore in proportion to estimated valueπ(a|s) = exp(Q(s,a)/τ) / ∑_{a′} exp(Q(s,a′)/τ) τ → 0 gives greedy, τ → ∞ gives uniform UCB — optimism in the face of uncertaintya = argmax_a [ Q(s,a) + c·√( ln N(s) / N(s,a) ) ]
  • ε-greedy with decay. Start near 1.0 and anneal toward a small floor (0.01–0.05). Simple and surprisingly hard to beat. Keeping a non-zero floor matters: it is what the "visit every pair infinitely often" convergence condition requires.
  • Optimistic initialisation. Set Q₀ above any achievable value. Every real experience is then a disappointment, which drives systematic exploration for free — but only once, so it does not help in non-stationary environments.
  • UCB. Explores by uncertainty rather than at random: the bonus term shrinks as an action is tried more often, so rarely tried actions look attractive. Principled in bandits, harder to define with function approximation.
  • Entropy bonus. Add β·H(π(·|s)) to the objective in policy-gradient methods, penalising over-confident policies. This is the standard exploration mechanism in PPO, and is the whole idea behind maximum-entropy RL.
  • Intrinsic motivation. When rewards are extremely sparse, add a self-generated bonus for novelty — count-based or pseudo-count bonuses, or prediction error against a random target network.
Takeaway: undirected exploration (ε-greedy) scales badly with the size of the state space, because random walks take exponentially long to reach distant states. Directed exploration — optimism, novelty bonuses — is what makes sparse-reward problems tractable.

10 Pitfalls & what to remember

  • Reward hacking. The agent optimises what you wrote, not what you meant. Watch the behaviour, not just the return curve, and prefer potential-based shaping, which provably preserves the optimal policy.
  • γ too small. A myopic agent cannot solve a long-horizon task no matter how long you train it. Check that 1/(1−γ) exceeds the number of steps between action and consequence.
  • Seed variance. RL results are notoriously unstable across random seeds. A single run proves nothing; report several seeds with a spread.
  • Hidden state. If the observation is not Markov, value estimates are inconsistent by construction. Stack frames or add recurrence.
  • The deadly triad. Function approximation + bootstrapping + off-policy can diverge. If values grow without bound, suspect the target network or the replay ratio before the learning rate.
  • Over-estimation. The max is biased upward with noisy estimates; use Double Q-learning or Double DQN.
  • Evaluating with exploration on. Report performance under the greedy policy, separately from the noisy training returns.
  • Sample cost. Model-free RL routinely needs millions of interactions. If each one is expensive or dangerous, look at offline RL, model-based methods, or imitation learning first.
The one idea: everything reduces to the recursion Gₜ = Rₜ₊₁ + γGₜ₊₁. Take its expectation and you get the Bellman equations; solve them with a model and you get dynamic programming; sample them and you get TD and Q-learning; differentiate the expected return directly and you get policy gradients.
