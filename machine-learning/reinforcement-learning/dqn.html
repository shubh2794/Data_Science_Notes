DQN: Deep Q-Networks from Pixels

One convolutional network, one set of hyperparameters, seven Atari games, and nothing but the screen and the score as input. This page goes past the summary on the hub. It covers why Q-learning on raw pixels was expected to fail, the exact loss and the gradient that comes out of it, the algorithm line by line, why experience replay is what makes it work, the preprocessing and frame stacking that repair a partially observed problem, the network and its parameter budget, the training recipe, how stability was measured when returns are too noisy to read, the results table, and what the 2013 study did not yet have.

Machine Learning Reinforcement Learning Paper deep dive

01 Why Q-learning on pixels was expected to fail

Deep learning assumes many independent, identically distributed samples with fixed labels. RL gives you a few sparse, delayed, noisy rewards, strongly correlated samples, and a data distribution that changes as you learn. The original study set out to show that a convolutional network trained with a Q-learning variant can still learn control policies, directly from raw video.

  • Sparse, delayed reward instead of labels. A supervised network gets a target for every input. Here the only teaching signal is a change in game score, which can arrive thousands of steps after the action that earned it. The credit-assignment machinery for this, bootstrapped TD targets, is set up on the hub (model-free learning).
  • Correlated samples. Consecutive frames are nearly identical. SGD on a stream like that sees a long run of near-duplicates, then a long run of something else, and its estimate of the gradient follows whichever run it is in.
  • A data distribution that moves with the parameters. The agent's behaviour depends on its current Q. A small change to θ can change which part of the game the agent spends its time in, which changes the next training data, which changes θ. The study names this feedback loop as a source of oscillation and divergence.
  • The theory said "careful". Function approximation, bootstrapping and off-policy learning together form the deadly triad. Q-learning with nonlinear function approximators was known to be able to diverge, and most successful RL on rich inputs had relied on hand-crafted features with linear value functions.
What changed. Convolutional networks had just shown they could pull useful features out of raw images when given enough data. The bet was that the same could work for RL if the data could be made to look "enough like" i.i.d. supervised data. Experience replay (§05) is the mechanism that does this.

02 The problem setup: what the agent sees and what it is scored on

The agent sees only the emulator screen. It is not given the emulator's internal state (no game RAM), no object positions, and no hand-designed visual features. It learns from the video input, the reward and terminal signals, and the set of legal actions.

the interface, per time step tobserve xₜ ∈ pixels a raw 210 × 160 RGB frame act aₜ ∈ {1, …, K} K legal actions, 4 to 18 depending on the game receive rₜ the change in game score discount γ used, but its value is not reported in the study the state is the whole history, because one frame is not Markovsₜ = x₁, a₁, x₂, a₂, …, aₜ₋₁, xₜ each distinct sequence is treated as a distinct state of a large but FINITE MDP (every game ends), so standard RL applies to sequences sₜ

Why not just one frame? A single screenshot does not show which way the ball in Pong is moving. That is a partially observed problem (a POMDP, see the hub's MDP section). Defining the state as the full history makes it Markov in principle. In practice the network cannot take an unbounded history, so §06 cuts it down to a fixed window of four frames.

the quantity to learnQ*(s, a) = max_π 𝔼[ Rₜ | sₜ = s, aₜ = a, π ] Rₜ = ∑_(t′ ≥ t) γ^(t′−t) · r_t′ satisfies Q*(s, a) = 𝔼_(s′) [ r + γ · max_a′ Q*(s′, a′) | s, a ] (Bellman optimality)

Value iteration on this equation converges to Q*, but only with one table entry per state, and nothing generalises from one sequence of frames to another. Instead, approximate Q(s, a; θ) ≈ Q*(s, a) with a neural network, which the study calls a Q-network. The derivation of the Bellman equations is on the hub (value functions & Bellman).

03 The loss, the gradient, and why single-sample SGD is just Q-learning

Turn the Bellman equation into regression: the right-hand side, computed with an older copy of the parameters, is the target, and the network is trained to match it in squared error. The loss changes from one iteration to the next because its target does.

the sequence of losses, one per iteration iLᵢ(θᵢ) = 𝔼_(s,a ~ ρ(·)) [ ( yᵢ − Q(s, a; θᵢ) )² ] yᵢ = 𝔼_(s′) [ r + γ · max_a′ Q(s′, a′; θᵢ₋₁) | s, a ] ρ(s, a) the "behaviour distribution": how often the agent's behaviour visits (s, a) θᵢ₋₁ held FIXED while Lᵢ is optimised. The target is a constant, not a function of θᵢ

Deriving the gradient

Because yᵢ does not depend on θᵢ, the chain rule only touches the prediction:

differentiate with the target held constant∇θᵢ Lᵢ = 𝔼[ 2 · (yᵢ − Q(s,a;θᵢ)) · (−∇θᵢ Q(s,a;θᵢ)) ] −½ · ∇θᵢ Lᵢ = 𝔼_(s,a ~ ρ; s′) [ ( r + γ · max_a′ Q(s′,a′;θᵢ₋₁) − Q(s,a;θᵢ) ) · ∇θᵢ Q(s,a;θᵢ) ] └──────────────── TD error δ ────────────────┘

The study writes the second line as "the gradient". Strictly it is minus one half of it, which is the direction a descent step moves in, and the constant folds into the learning rate. Rather than computing the full expectation, the study uses stochastic gradient descent on sampled transitions.

The special case that is classical Q-learning

single samples, and the weights updated after every step (so θᵢ₋₁ = the current θ)θ ← θ + α · δ · ∇θ Q(s, a; θ) δ = r + γ · max_a′ Q(s′, a′; θ) − Q(s, a; θ) tabular case: θ is a table, Q(s,a;θ) = θ[s,a], so ∇θ Q is 1 at entry [s,a] and 0 elsewhere: θ[s,a] ← θ[s,a] + α · δ which is exactly tabular Q-learning

So the method is Q-learning with a network in place of the table. Two properties carry over unchanged:

  • Model-free. Only sampled transitions (s, a, r, s′) are used. The emulator's dynamics are never estimated.
  • Off-policy. The target uses max_a′, so it learns about the greedy policy while the agent behaves ε-greedily. That is what allows old transitions, collected under older and more random behaviour, to be replayed (§05).
one target, by hand (illustrative numbers; the study does not report γ)clipped reward r = +1, γ = 0.99, next-state outputs Q(s′, ·) = [0.4, 1.2, 0.9, 0.7], Q(s, a) = 1.5 y = 1 + 0.99 · max(0.4, 1.2, 0.9, 0.7) = 1 + 1.188 = 2.188 δ = 2.188 − 1.5 = 0.688 per-sample loss δ² ≈ 0.473 terminal s′ instead: y = r = 1, δ = −0.5 (no bootstrap past the end of an episode)
Not gradient descent on a fixed objective. Each Lᵢ is a well-defined regression, but its target moves when θ moves. The full procedure is a sequence of regressions chasing each other, which is why the hub calls it semi-gradient and why convergence is not guaranteed (§12). Optimiser background: gradient descent & the minibatch.

04 Algorithm 1, annotated: deep Q-learning with experience replay

The whole method fits in a dozen lines. Read the comments, especially the one on the target line. The 2013 version computes targets with the same network it is updating.

  1. Initialise replay memory D to capacity N // last N transitions only; oldest overwritten
  2. Initialise action-value function Q with random weights θ
  3. for episode = 1 … M do
  4. initialise sequence s₁ = {x₁}, preprocess φ₁ = φ(s₁) // φ: §06
  5. for t = 1 … T do
  6. with probability ε select a random action aₜ
  7. otherwise aₜ = argmax_a Q(φₜ, a; θ) // one forward pass gives all K values (§07)
  8. execute aₜ in the emulator, observe reward rₜ and image xₜ₊₁
  9. set sₜ₊₁ = sₜ, aₜ, xₜ₊₁ and preprocess φₜ₊₁ = φ(sₜ₊₁)
  10. store transition (φₜ, aₜ, rₜ, φₜ₊₁) in D
  11. sample a random minibatch of transitions (φⱼ, aⱼ, rⱼ, φⱼ₊₁) from D // uniform
  12. yⱼ = rⱼ if φⱼ₊₁ is terminal, else rⱼ + γ · max_a′ Q(φⱼ₊₁, a′; θ) // θ, the CURRENT weights: no separate target network
  13. gradient descent step on (yⱼ − Q(φⱼ, aⱼ; θ))² // §03, target held constant
  14. end for
  15. end for
A correction to a common summary. The hub's §07 lists target networks among DQN's tools, and in the modern DQN they are. But the 2013 study has no periodically synced target copy. The "previous iteration" θᵢ₋₁ in the loss of §03 is, in Algorithm 1, simply the weights as they stand before the current minibatch step. The separate frozen network θ⁻, synced every few thousand steps, was introduced in the later 2015 follow-up (later work, §11). The stability in the 2013 study comes from experience replay alone.
  • Acting and learning are interleaved. Each environment step adds one transition and triggers one minibatch update. Acting uses φₜ, the most recent stack. Learning uses transitions from anywhere in D.
  • The behaviour policy is ε-greedy on the current network, which is exactly the feedback loop of §01. Replay does not break that loop. It slows it down, because each update averages over data produced by many past versions of the policy.
  • Terminal handling is the only branch. At the end of an episode there is no next state to bootstrap from, so the target is the reward alone.

05 Experience replay: three reasons it works, and a toy that shows them

Store every transition and train on uniformly sampled minibatches of them instead of on the transition that just happened. The study gives three reasons, and they are different mechanisms.

data efficiency
Each experience is reused
A transition stays in D until it is overwritten, so it can take part in many weight updates rather than one. Expensive interaction is amortised.
variance
Randomising breaks correlation
Learning directly from consecutive samples is inefficient because they are strongly correlated. Sampling at random from a large memory makes a minibatch look much more like i.i.d. data, which lowers the variance of the update.
stability
The behaviour distribution is averaged
On-policy, the current parameters decide the next training samples. If the greedy action is "move left", the data fills with left-side states, and the network can lock into feedback loops, oscillate or diverge. Replay averages over many past states and behaviours.
what the minibatch gradient estimates, three waysonline: g = δₜ · ∇Q(sₜ, aₜ) one sample, the newest recent window: g = (1/B) ∑_(j = t−B+1 … t) δⱼ · ∇Q(sⱼ, aⱼ) B samples, but CONSECUTIVE uniform replay: g = (1/B) ∑_(j ~ Uniform(D)) δⱼ · ∇Q(sⱼ, aⱼ) B samples, spread over the last N the variance of an average of B samples is σ²/B only if they are uncorrelated; B consecutive frames are nearly the same sample, so the recent window behaves like B ≈ 1

The figure separates these mechanisms. It is a toy, computed live in your browser, and none of its numbers come from the study. It uses a 20-state corridor. Each step moves left or right, and reaching the right end pays +1 and ends the episode. Q is linear in seven overlapping Gaussian bumps over the state plus a bias, separate weights per action, so an update at one state moves the values of its neighbours. That shared generalisation is the property of a deep network that makes correlation harmful. Three learners each act ε-greedily on their own current Q, with ε annealed linearly from 1.0 to a 0.1 floor as in §08, and each makes one update per environment step with the same step size. They differ only in which transitions that update averages over. All three compute targets with their current weights, as Algorithm 1 does.

Online updates vs a recent window vs uniform replay, on a toy corridor run it: the two correlated learners keep spiking while replay settles flat; then shrink the memory to 32 and run again
  • Averaging alone does not help. Decorrelation does. The recent-window learner averages 32 gradients per step, as many as replay does, yet it spikes about as much as the single-sample online learner. Its 32 samples are neighbouring states from one stretch of one trajectory, so they all pull the shared weights the same way. That is the study's second reason, isolated.
  • Capacity matters. Set N = 32 and "uniform replay" samples only from the last 32 transitions, which is nearly the recent window again. A large memory is what spreads the batch over many past states and many past behaviours (the third reason). The study kept the last one million frames (§08).
  • The step size changes how far, not whether. Across the slider's range the replay learner's worst second-half error stays close to its final error, while the two correlated learners keep making excursions several times larger. Larger steps make those excursions bigger. Replay is what lets a given step size stay stable.
  • Honest scope. In this toy nothing diverges. The approximator is linear and small, and the spikes are bounded excursions, not blow-ups. It shows the mechanism, not the size of the effect in a deep network on Atari.

What uniform replay leaves on the table

The memory keeps only the last N transitions and samples them uniformly, so it does not distinguish important transitions from routine ones, and finite capacity means it always overwrites the oldest. The study itself suggests that a more sophisticated sampling strategy might emphasise transitions the agent can learn the most from, much like prioritised sweeping. That idea became prioritised experience replay in later work (§11).

06 Preprocessing and frame stacking: from 210 × 160 colour video to an 84 × 84 × 4 state

The preprocessing map φ does two jobs. It cuts the input dimension so that training is computationally feasible, and it replaces the unbounded history sₜ with a fixed-length window that is close enough to Markov.

the pipeline, per frameraw frame 210 × 160 RGB, 60 Hz, 128-colour palette → greyscale 210 × 160 × 1 → downsample 110 × 84 → crop 84 × 84 roughly the playing area (square because the GPU convolution code expected square inputs) φ: stack the last 4 preprocessed frames of the historyφ(sₜ) = [ x̃ₜ₋₃, x̃ₜ₋₂, x̃ₜ₋₁, x̃ₜ ] ∈ ℝ^(84 × 84 × 4) input size 84 · 84 · 4 = 28 224 numbers (own arithmetic) raw frame 210 · 160 · 3 = 100 800 numbers → one preprocessed frame is 7 056, 7% of that
  • Why four frames repair the POMDP. One frame gives positions. Two give velocities. Three or more give accelerations and short-lived events. Stacking turns "where is the ball?" into "where is the ball and where is it going?", which is most of what these games need. It is still a truncation of the true history, so anything that matters over a longer span (a key picked up a minute ago) is invisible. That is one of the reasons the study gives for the long-horizon games (§10). The recurrent alternative is on the RNNs & LSTMs page.
  • Frame skipping changes what "four frames" spans. The agent acts only every k-th emulator frame and repeats its action on the skipped frames (§08). If the four stacked frames are the agent's own successive observations, they span about 4 · 4 = 16 emulator frames, about 0.27 s at 60 Hz. That is own arithmetic, under that reading of "the last 4 frames of a history".
  • Greyscale is a bet. It throws away colour, which in some games is the only thing distinguishing objects. The baselines of §10 went the other way, treating colour channels as separate object maps with hand-made features.

07 The network: state in, all K action values out, in one pass

The key design choice is the output layer. Several earlier approaches fed the history and the action into the network and output one number, which costs one forward pass per action. Here the state is the only input and there is one output unit per action, so the max and argmax over actions cost a single forward pass.

architecture (no padding; shapes and parameter counts are own arithmetic)layer output shape size rule weights + biases input φ(s) 84 × 84 × 4 conv 16 · 8×8, stride 4 20 × 20 × 16 (84 − 8)/4 + 1 = 20 8·8·4·16 + 16 = 4 112 ReLU conv 32 · 4×4, stride 2 9 × 9 × 32 (20 − 4)/2 + 1 = 9 4·4·16·32 + 32 = 8 224 ReLU flatten 2 592 9 · 9 · 32 fully connected 256 256 2592·256 + 256 = 663 808 ReLU linear output K one Q-value per action 256·K + K total: K = 4 → 677 172 K = 18 → 680 770 the single dense layer holds 663 808 / 677 172 ≈ 98% of all parameters
  • Small by later standards. Two convolutional layers and one hidden dense layer, about 0.68M parameters. Almost all of the capacity is in the dense layer that maps the 2 592 spatial features to 256 units. The two convolutions are cheap feature extractors whose weights are shared across positions. Counting rules: conv shape arithmetic; background: CNNs.
  • No pooling. The architecture has no pooling layers. Strides alone do the downsampling (84 → 20 → 9). A plausible reason, and this is interpretation rather than a claim of the study, is that pooling's translation invariance discards the position information a game agent needs.
  • The output is linear, not softmax. These are regression outputs, values on an unbounded scale, not a distribution over actions. Only the unit for the action actually taken receives a gradient from a given transition. The other K − 1 outputs get zero error for that sample.
  • One network for every game. The same architecture, learning algorithm and hyperparameters were used for all seven games. Only K differs, and the output layer is sized to it. There is no per-game tuning, which is what makes the results table a test of generality.
why the output design matters: cost of choosing one action(s, a) → Q architecture: K forward passes per decision K = 18 → 18 passes s → Q(s, ·) architecture: 1 forward pass per decision regardless of K and the target needs max_a′ Q(s′, a′) for every sample in the minibatch: 1 extra pass, not K

Frame skipping: cheaper decisions, coarser control

Running the emulator one frame forward is far cheaper than a forward pass of the network plus a minibatch update. Choosing an action only every fourth frame lets the agent play roughly k times more game per unit of compute, about 15 decisions per second at 60 Hz with k = 4 (own arithmetic). The price is reaction granularity, and the Space Invaders exception shows it can hide information outright.

Reward clipping: one learning rate for every game, at a cost

what the agent is actually trained onr_train = sign(r_game) ∈ {−1, 0, +1} r_game: +10 (small target) +1000 (big target) → r_train: +1 +1 consequence: |Q| ≤ 1 / (1 − γ) in every game (own arithmetic), so one step size works across them; but the agent cannot tell a 10-point event from a 1000-point one

Game scores differ by orders of magnitude across titles, and the size of the TD error, and so of the gradient, scales with them. Clipping bounds the error scale so a single learning rate can be used for all games. The study states the cost plainly: it can hurt performance, because the agent cannot distinguish rewards of different magnitude. In effect it optimises "number of scoring events, discounted" rather than score.

09 Measuring stability when returns are too noisy to read

In supervised learning, training progress is easy to track: watch the validation loss. In RL the obvious metric, average total reward per episode, is very noisy, because small weight changes shift the distribution of states the policy visits. The study added a second, smoother metric.

the held-out value metricbefore training: run a RANDOM policy, collect a fixed set of states H during training: track (1/|H|) ∑_(s ∈ H) max_a Q(s, a; θ) the average max predicted Q epoch = 50 000 minibatch updates ≈ 30 minutes of training
  • Why it is smoother. The set of states is fixed, so the metric does not inherit the variance of which states the current policy happens to visit. It measures the network's own estimate of how much (discounted, clipped) reward is available from a fixed set of situations.
  • What was seen. In every experiment the average-reward curves were noisy, while the held-out average max-Q rose smoothly. The study reports no divergence in any of its experiments, and is explicit that this is empirical evidence, not a convergence guarantee.
  • Its blind spot. A rising predicted value is not the same as a rising true value. Q-learning's max over noisy estimates is biased upward (the hub's maximisation bias note), so a smoothly rising estimate can also be a smoothly rising over-estimate. The later Double DQN work (§11) showed that this happens.
  • Throughput, own arithmetic. 50 000 updates in about 30 minutes is about 28 minibatch updates per second, each with a forward and backward pass over 32 stacked-frame inputs plus forward passes for the targets.

Reading the value function: the Seaquest trace

The study plots the predicted value over a short segment of Seaquest and interprets it qualitatively. The value jumps when an enemy appears on screen, because a reward has become reachable. It peaks as the torpedo is about to hit, when the reward is nearly certain and only a few discounted steps away. It falls back after the enemy disappears, because the opportunity is gone. The network was never told what an enemy or a torpedo is. A value function that tracks them is evidence that the convolutional features learned game-relevant objects from pixels and score changes alone.

11 What the 2013 study did not have

Most "DQN" implementations today bundle several ideas that came after the original study. All of the following are later work, and they are summarised on the hub's function approximation & DQN section. They are listed here only to separate them from the original method.

ingredientin the 2013 study?what it changes
target network θ⁻No. Targets use the current θ (§04). Added in the 2015 follow-up.The target is computed by a frozen copy that is synced periodically, so it stops moving on every step. This is the most-cited stabiliser, and it is absent here.
Double DQNNoSelect argmax_a′ with the online network and evaluate it with the target network, which reduces the over-estimation that the held-out-Q metric of §09 cannot see.
Dueling headsNo. One linear head over the 256 features (§07).Split the head into V(s) and advantages A(s, a).
prioritised replayNo. Uniform, though the study suggests it as future work (§05).Sample transitions in proportion to their TD error, with importance weights to correct the bias.
Huber / clipped TD error, larger network, more gamesNo. Squared error, the small network of §07, 7 games.Later versions used a larger network and evaluated on many more games.

The contrast with policy-gradient methods (no replay, no max, on-policy minibatch epochs instead) is the subject of the sibling deep dive on PPO.

12 Limitations the original study states, and ones implied by its design

theory
No convergence guarantee
Nonlinear function approximation with bootstrapped off-policy targets has no general convergence proof. The stability evidence is empirical: no divergence was seen in these experiments (§09).
objective
Clipping loses magnitude
Training on sign(r) lets one learning rate serve every game, but the agent cannot tell small rewards from large ones, which can hurt performance (§08).
memory
Uniform replay, finite window
All stored transitions are equally likely to be sampled and the oldest are overwritten, regardless of how informative they are (§05).
evidence
Seven games
One architecture across seven titles is a strong generality test for its time, but it is a small sample of Atari, and the three games far below human hint at systematic gaps.
implied by the design
Short memory, discrete actions
Four stacked frames cannot represent long-range state, and the max over a K-way output only works for a small discrete action set. Continuous control needs other methods (hub: policy gradients).

13 Common misconceptions

"DQN invented the target network." Not in its 2013 form. Algorithm 1 computes max_a′ Q(φⱼ₊₁, a′; θ) with the current weights. The periodically synced frozen copy arrived in the later 2015 follow-up. The original stability story is experience replay (§04, §11).
"It learned from the game's memory or object positions." No. Only pixels, rewards, terminal signals and the set of legal actions. The emulator's internal state was not available, and there were no hand-designed visual features. That is what separates it from the Sarsa, Contingency and HNeat Best baselines (§10).
"Reward clipping is a harmless normalisation." It changes the task. A 1000-point event and a 10-point event both become +1, so the agent maximises the discounted count of scoring events, not the score. The study says this can hurt performance (§08).
"Experience replay works because the minibatch is bigger." It works because the minibatch is decorrelated and spread over many past behaviours. A minibatch of 32 consecutive transitions is about as unstable as a single sample (the toy in §05). Capacity, not batch size, is what spreads the data.
"DQN beat humans at Atari." On three of seven games. It was far below the human expert on Q*bert, Seaquest and Space Invaders, which are games that need long-horizon strategy (§10).
"A smoothly rising Q-curve means the agent is getting better." It means the predictions are stable. The held-out max-Q metric is a stability diagnostic. With the max's upward bias it can rise while being an over-estimate (§09).

14 Takeaways

  • Q-learning with a CNN in place of the table: regress Q(s, a; θ) onto r + γ · max_a′ Q(s′, a′), with the target held constant. Single-sample SGD on this loss is Q-learning.
  • Experience replay is the stabiliser of the 2013 study. It reuses data, decorrelates minibatches, and averages over past behaviour. A periodically synced target network was added only in the later follow-up.
  • The state is four stacked 84 × 84 greyscale frames, a fixed window that repairs most of the partial observability of a single frame.
  • One forward pass gives all K action values, from a network of about 0.68M parameters, 98% of them in one dense layer (own arithmetic).
  • Recipe: RMSProp, minibatch 32, ε from 1.0 to 0.1 over 1M frames, 1M-frame memory, 10M frames, frame skip 4 (3 for Space Invaders), rewards clipped to the sign. Identical for every game.
  • Track stability with the average max-Q on a fixed held-out set, because episode returns are too noisy.
  • Results: better than all prior learning methods on all seven games, better than the human expert on three, and far behind on the long-horizon games.
