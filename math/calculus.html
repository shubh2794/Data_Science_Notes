Calculus

The study of change and accumulation — and, for machine learning, the machinery that turns a loss function into a direction to move. We build it in two halves: the classical analysis (limits → derivatives → Taylor → series → integrals), then the part almost no one teaches properly, matrix differential calculus — the differential-first method that produces every gradient identity you have ever looked up, and that is backpropagation.

01 Two halves of one subject

Calculus answers one question — how does the output change when I nudge the input? — at four levels of generality. Each level is the same idea wearing a bigger coat.

The classical half (§02–§09) is about existence and accuracy: when does a derivative exist, how good is a polynomial approximation, when does an iteration converge, what does an integral mean. The matrix half (§10–§13) is about mechanics: how to actually get ∂L/∂W without drowning in indices.

  • The unifying idea: a derivative is the best linear approximation to a function near a point. Everything else — gradients, Jacobians, matrix derivatives — is that same sentence with different index bookkeeping.
  • The unifying method: compute the differential first (a purely mechanical algebraic manipulation), then read off the derivative from its shape. This is §10, and it is the single highest-leverage technique on this page.
  • What this page is not: it does not cover optimization algorithms. Gradient descent, momentum, Adam, Newton's method, convexity and conditioning live next door on Optimization. This page supplies the derivatives those algorithms consume.
The one sentence · differentiability as linear approximation f(c + u) = f(c) + A(c)·u + r(u) with ‖r(u)‖ / ‖u‖ → 0 as u → 0 the linear part df(c; u) = A(c)·u is the DIFFERENTIAL; A(c) is the DERIVATIVE.

14 Practice, pitfalls, and a cheat sheet

Where calculus actually bites in day-to-day ML work, and the short list worth keeping in working memory.

Gradient checking — the one numerical-differentiation use that matters

When you hand-write a backward pass (a custom layer, a custom loss), verify it against central differences. The relative-error check below is the standard recipe.

Gradient check g_num[i] = [ L(θ + h eᵢ) − L(θ − h eᵢ) ] / (2h), h ≈ 10⁻⁵ … 10⁻⁶ rel_err = ‖g_num − g_analytic‖ / max(‖g_num‖ + ‖g_analytic‖, 10⁻⁸) < 10⁻⁷ excellent · < 10⁻⁵ usually fine · > 10⁻³ you have a bug
  • Use double precision for the check; float32 round-off alone will fail it.
  • Turn off dropout and any other stochasticity, and use a fixed batch — you must differentiate the same function twice.
  • Check only a random subset of coordinates; 2n evaluations is otherwise prohibitive.
  • Avoid kinks: a check near z = 0 for a ReLU will legitimately fail. Perturb away from the non-differentiable set.

Note the pattern: the function is often fine while its derivative is not. A gradient that goes NaN before the loss does is almost always one of these.

Conventions that cause real bugs

  • Numerator vs denominator layout. Is ∂y/∂x for vector y, x an m×n or an n×m matrix? Both conventions are in the wild. Pick one — the numerator (Jacobian) layout ∂y/∂xᵀ ∈ ℝ^{m×n} is used throughout this page — and state it. Nearly every stray transpose is a layout clash.
  • Gradient (column) vs derivative (row). ∇φ = (Dφ)ᵀ. Keeping the two words distinct catches shape errors before the code does.
  • Symmetric or constrained parameters. Differentiating tr(Σ⁻¹S) as if all n² entries of Σ were free gives a different off-diagonal result than treating Σ as symmetric (a factor of 2). The stationary point is the same; a gradient-check is not.
  • Mean vs sum reductions. A 1/m in the loss rescales every gradient. Changing batch size without changing the reduction silently changes the effective learning rate.

The five things to remember. (1) A derivative is a linear approximation — that one sentence generalises to every level. (2) Compute the differential first, then identify. (3) The chain rule is Jacobian multiplication, and the order you multiply in decides whether gradients are cheap. (4) Taylor to second order is the local quadratic model every optimizer secretly optimizes. (5) An expectation is an integral, so the gradient of an expectation needs either the log-derivative trick or reparameterisation. Everything else on this page is a consequence.
