05 Matrices

A matrix is a grid of numbers — and, far more powerfully, a function that transforms vectors. This section is the vocabulary and the easy arithmetic; the hard and interesting operations start in §06.

What a matrix is for

  • Read the same grid several ways in parallel: a data table (features × observations), a system of equations, a set of column vectors side by side, a stack of row vectors, and — the view that matters most — a linear transformation of one space into another.
  • Other everyday roles: storing partial derivatives of a multivariable system (Jacobian / Hessian), holding regressors for a statistical model, geometric transforms in graphics, convolution kernels, transition and adjacency structures.
  • These notes stay with rows × columns grids — things you could print flat. Higher-order arrays (cubes and hypercubes) are tensors; useful for storage and for physical quantities, but out of scope here.

Terminology and notation

  • Bold capital for the whole matrix (A); lowercase with two subscripts for an element (aᵢⱼ or mᵢⱼ). Vocabulary to have straight: row, column, element, diagonal (top-left → bottom-right), anti-diagonal / skew-diagonal (top-right → bottom-left), off-diagonal, block.
  • Rows first, then columns — for sizes and for indices. Conventionally M rows, N columns, so A ∈ ℝ^(M×N) and aᵢⱼ is row i, column j. Mnemonic: "Mr. Nice" — M Rows, N Columns.
  • A matrix can be built out of smaller matrices — block-matrix notation. Purely a bookkeeping device, but it makes big structured matrices readable and some proofs one-line.
  • Dimensionality of a matrix is context-dependent, unlike a vector's. An M×N real matrix can reasonably be called ℝ^(M×N), or ℝ^(MN) if every element is its own dimension, or ℝ^M if you are thinking of it as a bundle of column vectors, or ℝ^N as a stack of rows. State which you mean.

Transpose

  • Same idea as for vectors: swap rows and columns. Element (i, j) of Aᵀ is element (j, i) of A.
  • Transposing twice returns the original — (Aᵀ)ᵀ = A. Central to a great many proofs.
  • A wide M×N matrix becomes a tall N×M one, which is why only square matrices can be symmetric.
  • Common mistake: reversing the order of the rows/columns while flipping. The first row of A must become the first column of Aᵀ, not the last.
  • Preview (§06): transposing a product reverses the order — (AB)ᵀ = BᵀAᵀ. The reversal is not optional; the shapes only line up that way.

Partitioned matrices — the notation, properly

  • The zoo entry above called block notation "pure bookkeeping". It is more than that: partitioning is how you make a big matrix into a small matrix whose entries happen to be matrices, and then reuse every rule you already know. Almost every closed-form result in multivariate statistics is a block computation.
  • Cut a matrix with horizontal and vertical lines. A 2×2 partition of A with m = m₁ + m₂ rows and n = n₁ + n₂ columns produces A₁₁ (m₁×n₁), A₁₂ (m₁×n₂), A₂₁ (m₂×n₁), A₂₂ (m₂×n₂). The only rule is that the cuts go all the way through: blocks in a row share a row count, blocks in a column share a column count.
  • Submatrix vocabulary. A principal submatrix uses the same index set for rows and columns (so it straddles the diagonal); a leading principal submatrix is a principal one anchored at the (1,1) corner and contiguous. Positive-definiteness tests, Cholesky, and the determinant criteria all quantify over these (§17).
  • Transposing a partition transposes the grid and each block: [[A₁₁, A₁₂], [A₂₁, A₂₂]]ᵀ = [[A₁₁ᵀ, A₂₁ᵀ], [A₁₂ᵀ, A₂₂ᵀ]]. Note the blocks swap positions off the diagonal — the same LIVE EVIL reversal you meet in §06, one level up.
  • Addition and scalar multiplication are block-wise, provided the two matrices are conformably partitioned (identical cut positions). Nothing is gained if the cuts disagree — re-cut first.
  • Block diagonal matrices — non-zero blocks only on the diagonal — are the structured cousin of diagonal matrices. The diag(·) operator is overloaded to build them from a list of matrices, and the operation is called the direct sum of matrices, written A₁ ⊕ … ⊕ A_k = diag(A₁, …, A_k). Their inverses, determinants, ranks and eigenvalues all decompose block-by-block, which is why "find a basis that block-diagonalises this" is the goal of half of applied linear algebra.
  • Name collision warning: this ⊕ (stack matrices on a diagonal) is not the ⊕ of a direct sum of subspaces (§04, and again in §08). Context always disambiguates, but the symbol is genuinely overloaded.
  • Where you have already met blocks: the augmented matrix [A | b] is a 1×2 partition (§10), and [A | I] is how the inverse gets computed (§12). The design matrix of a regression with an intercept is [1 | X], and separating those blocks is exactly how "centre the predictors" is justified.

AᵀA — the most important form in applied linear algebra

  • Building it needs matrix multiplication (§06), but the payoff list is worth meeting early. Starting from any matrix A, the product AᵀA is:
  • square, even when A is rectangular; symmetric, even when A isn't; full-rank and invertible whenever A has full column rank (§07, §12); has the same row space as A (§08).
  • It also has orthogonal eigenvectors and non-negative real eigenvalues, i.e. it is positive (semi)definite (§15, §17) — and when A is a mean-centred data matrix it is the covariance matrix (§18), which is why PCA (§19) and least-squares (§14) both end up staring at AᵀA.
  • The same properties hold for AAᵀ; the two differ in size (N×N vs. M×M) and that difference is exactly what the SVD exploits (§16).

Addition, subtraction, scalar multiplication

  • Element-wise, and only for matrices of identical size M×N; the result is M×N. There is no such thing as adding a 3×2 to a 2×3.
  • Commutative: A + B = B + A. Worth saying out loud because matrix multiplication is not (§06) — and the commutativity of addition is the step that proves A + Aᵀ is symmetric.
  • Scalar multiplication multiplies every element, exactly as for vectors, and is therefore commutative: λAB = AλB = ABλ. That freedom to slide a scalar through a product is used constantly in derivations.

"Shifting" a matrix: A + λI

  • Combine the two operations above: add a multiple of the identity. Defined for square matrices only. The result is usually written Ã — similar to, but not the same as, A.
  • Only the diagonal changes. The identity is zero off-diagonal, so every off-diagonal entry survives untouched.
  • What it buys you: shifting makes previously identical rows or columns distinct. Rows that were redundant before the shift are no longer redundant after it — which means a shift turns any rank-deficient matrix into a full-rank one (§07), and therefore an un-invertible matrix into an invertible one (§12).
  • Continuity: at λ = 0, Ã = A; for small λ the shifted matrix is barely perturbed. In practice one chooses λ as small as possible while still large enough to fix the numerical problem — a bias/variance trade in disguise.
  • This is regularization. Ridge regression solves (XᵀX + λI)⁻¹Xᵀy — a shift of XᵀX — which is what makes least-squares work on collinear or under-determined data (§14). The same trick stabilises covariance estimates and shrinks parameters toward zero.
  • Eigen-preview (§15): shifting by λI shifts every eigenvalue by exactly λ while leaving eigenvectors untouched — and the eigenvalue equation (A − λI)v = 0 is itself a shift.

Diagonal and trace

  • diag(A) pulls the diagonal into a vector: vᵢ = aᵢᵢ for i = 1 … min(M, N). This does not require a square matrix. In statistics the diagonal of a covariance matrix holds each variable's variance.
  • The same operator in code runs both ways: given a matrix it extracts the diagonal, given a vector it builds a diagonal matrix (numpy: np.diag).
  • tr(A) is the sum of the diagonal elements — one number summarising a matrix. Off-diagonal entries contribute nothing, so wildly different matrices can share a trace.
  • The trace is defined only for square matrices, even though the diagonal exists for rectangular ones. The reason is downstream: the trace equals the sum of the eigenvalues (§15), and eigendecomposition is a square-matrix affair.
  • Linear: tr(A + B) = tr(A) + tr(B) and tr(λA) = λ·tr(A) — both fall straight out of summing diagonals.
  • Cyclic: tr(AB) = tr(BA) even when AB ≠ BA, and more generally the trace is invariant to cyclic rotation of a product. Special case: tr(vwᵀ) = vᵀw — the trace of an outer product is the dot product (§03).
  • Where it shows up in ML: the Frobenius norm ‖A‖_F = √(tr(AᵀA)) — a matrix's "magnitude", used as a distance between matrices and as a weight-decay penalty; the trace also expresses total variance in PCA (§19) and effective degrees of freedom in ridge regression.

The trace is an inner product in disguise

  • Three more properties finish the trace off, and each one is doing real work later.
  • Transpose-invariant: tr(Aᵀ) = tr(A) — transposing fixes the diagonal.
  • Definite: tr(AᵀA) = 0 if and only if A = 0. Reason: tr(AᵀA) = Σᵢⱼ aᵢⱼ², a sum of squares, which vanishes only when every entry does. This single fact is what upgrades √tr(AᵀA) from "a number" to a genuine norm — and it is the matrix version of the argument that ‖v‖ = 0 ⟹ v = 0.
  • Basis-invariant: tr(P⁻¹AP) = tr(APP⁻¹) = tr(A) by cyclicity. So the trace does not depend on the coordinate system you happen to be using — it is a property of the underlying transformation, not of the grid of numbers. The determinant, the rank and the eigenvalues share that immunity; the individual entries emphatically do not. This is the whole point of similarity, developed below.
  • Put the cyclic property together with tr(AᵀB) = Σᵢⱼ aᵢⱼbᵢⱼ and you have the Frobenius inner product: matrices form a Euclidean space, with lengths, distances and angles, exactly like vectors. That is what licenses phrases such as "the nearest rank-k matrix" (§16) and "the distance between two covariance matrices".
  • Statistical life of the trace. If a random vector x has mean μ and covariance Σ, then a linear map moves them as E[Ax] = Aμ and Var(Ax) = AΣAᵀ, and the expected value of a quadratic form is E[xᵀAx] = tr(AΣ) + μᵀAμ. The proof is one line of trace gymnastics: xᵀAx is a scalar, so it equals its own trace, and E[tr(Axxᵀ)] = tr(A·E[xxᵀ]) = tr(A(Σ + μμᵀ)).
  • That identity is why tr(Σ) is called the total variance of a dataset (§18): it is the sum of the individual variances, and PCA redistributes it across orthogonal directions without changing the total (§19). It is also where "effective degrees of freedom" tr(H) comes from for a smoother or ridge fit ŷ = Hy.

The view that matters most for ML: a matrix is a linear transformation — it sends the input space to an output space while keeping the origin fixed and grid lines straight and evenly spaced. Everything in the zoo above is a statement about what kind of transformation you are holding.
Two habits to build now: always know a matrix's shape before writing an operation (addition needs identical sizes, augmentation needs matching row counts, trace needs squareness), and remember that A + λI is regularization — the one-line fix for rank-deficient, collinear, or ill-conditioned data.

06 Matrix multiplication

Multiplying matrices composes transformations. The rule looks strange until you see the four ways to read it — and until you unlearn the scalar habits: commuting, cancelling, dividing.

Validity: inner dimensions match, outer dimensions survive

  • Write the sizes underneath: (m×n)(n×p) is legal only when the inner dimensions match, and the outer dimensions give the product's size (m×p). Every validity question reduces to this picture.
  • So AB can be legal while BA is undefined (5×2 times 2×7 works; the reverse doesn't). Transposing can rescue a clash: ABᵀ or AᵀB may be fine when AB isn't.
  • Order matters, so the vocabulary does too: AB is "A pre/left-multiplies B", equivalently "B post/right-multiplies A".
  • This also explains vector notation: vᵀw is (1×n)(n×1) — a scalar, the dot product; vwᵀ is (n×1)(1×n) — a matrix, the outer product. Same vectors; transpose placement decides everything.
the rule(AB)ᵢⱼ = ∑ₖ Aᵢₖ Bₖⱼ (m×n)(n×p) → (m×p) AB ≠ BA in general

Four perspectives on the same product

Identical numbers, different insight. Running example: A = [[3,4], [−1,2], [0,4]] times B = [[5,1], [3,1]] = [[27,7], [1,1], [12,4]].

  1. Element: (AB)ᵢⱼ = dot product of row i of A with column j of B; top-left is 3·5 + 4·3 = 27. The diagonal pairs row i with column i — that's why XᵀX is a covariance matrix; the upper and lower triangles pair different rows with columns, which is where QR and generalized eigendecomposition live.
  2. Layer: a sum of outer products (column k of A times row k of B), stacked like transparencies: [[15,3],[−5,−1],[0,0]] + [[12,4],[6,2],[12,4]]. Each layer is rank-1; the sum needn't be. This is the bridge to the SVD — every matrix is a sum of rank-1 pieces.
  3. Column: column j of the product is a combination of A's columns weighted by column j of B: 5·[3,−1,0] + 3·[4,2,4] = [27,1,12]. The regression picture (A = regressors, B = coefficients).
  4. Row: row i of the product is a combination of B's rows weighted by row i of A. The PCA picture (B = data, A = feature weights → component scores).
Immediate corollary: every column of AB lies in C(A) and every row in the row space of B. That one sentence proves the rank rule of §07 and much of §08.

Equations, and diagonal matrices

  • Scalars go anywhere, matrices don't: from B = λ(C + D) you may write AB = λA(C + D), but not AB = λ(C + D)A. Pre-multiply one side ⟹ pre-multiply the other. With rectangular matrices, breaking the rule is usually not just wrong but undefined — sizes are a free correctness check.
  • PRe-multiply affects Rows, POst-multiply affects cOlumns: DA scales row i by dᵢ; AD scales column j by dⱼ.
  • Two diagonals multiply element-wise on the diagonal: diag(a,b,c)·diag(d,e,f) = diag(ad, be, cf) — so standard and Hadamard multiplication coincide there, and diagonal matrices do commute. This is what makes sandwich forms like QΛQᵀ and UΣVᵀ tractable (§15, §16).

LIVE EVIL — operations on a product reverse the order

  • (ABCD)ᵀ = DᵀCᵀBᵀAᵀ, and the same reversal governs the inverse: (ABC)⁻¹ = C⁻¹B⁻¹A⁻¹.
  • Transposing without reversing gives a genuinely different matrix. For A = [[2,4],[1,2]], B = [[0,1],[1,1]]: (AB)ᵀ = [[4,2],[6,3]], but AᵀBᵀ = [[1,3],[2,6]]. Only BᵀAᵀ recovers the right answer. For rectangular matrices the wrong order isn't wrong — it's invalid.
  • Gotcha: an operation valid on a product can be invalid on the pieces. (XᵀX)⁻¹ is routine in least squares even when X⁻¹ doesn't exist. Transposition is always safe; inversion is not.

Matrix-vector multiplication — a matrix is a transformation

  • A matrix times a vector is always a vector: that is the link between matrices and linear transformations. Encode the transform as a matrix, then multiply.
  • Column view: Ax is a combination of A's columns weighted by x. With A = [[4,2],[1,3]], x = [5,2]: 5·[4,1] + 2·[2,3] = [24,11]. Row view: xᵀA combines A's rows, giving the row vector [22,16]. So Ax ≠ xᵀA; for rectangular A at most one is even legal; and xA is simply undefined.
  • Exception: if A = Aᵀ then Ax = (xᵀA)ᵀ — same numbers, different orientation. Proof: (Ax)ᵀ = xᵀAᵀ = xᵀA. (Transpose → expand → simplify is the template for most proofs here.)
  • Pure rotation vs stretch: R(θ) = [[cos θ, −sin θ], [sin θ, cos θ]] sends [1,0] to [cos θ, sin θ] — it turns every vector by θ and changes no length (RᵀR = I, det = 1). A general matrix rotates and stretches; the SVD says exactly that (rotate → stretch → rotate).

Manufacturing symmetric matrices — and the limits

  • Additive (square A only): C = (A + Aᵀ)/2. Proof: (A + Aᵀ)ᵀ = Aᵀ + A and addition commutes, so C = Cᵀ. The ÷2 undoes the doubled diagonal. Size-independent — not a 2×2 fluke.
  • Multiplicative (any A): AᵀA and AAᵀ are always square ((n×m)(m×n)) and always symmetric, since (AᵀA)ᵀ = Aᵀ(Aᵀ)ᵀ = AᵀA — LIVE EVIL plus double-transpose.
  • They are different matrices of different sizes: AᵀA is n×n, AAᵀ is m×m. Which you want depends only on whether your data is observations×features or the reverse — one gives feature covariance, the other observation similarity. These Gram matrices underlie least squares (XᵀX), PCA, and kernel methods.
  • But the product of two symmetric matrices is generally not symmetric: (AB)ᵀ = BᵀAᵀ = BA ≠ AB. [[a,b],[b,c]]·[[d,e],[e,f]] has off-diagonals ae+bf vs bd+ce. Exceptions: constant-diagonal 2×2s (which doesn't survive to 3×3), I, 0, or any pair that commutes. This is precisely the limitation that confines PCA to one symmetric matrix and motivates generalized eigendecomposition behind discriminant analysis.

Block multiplication — the rule scales up unchanged

  • Partition A and B (§05) so that the column cuts of A match the row cuts of B. Then you may multiply as if the blocks were scalars — same recipe, "row of blocks times column of blocks" — provided you never commute anything, because blocks are matrices.
  • Why it works: expand the definition (AB)ᵢⱼ = Σₖ aᵢₖbₖⱼ and split the sum over k at the cut. Each piece of the split is exactly one block product. Nothing new is being claimed; the sum has merely been grouped.
  • The conformability condition is the whole discipline. "A's column cuts = B's row cuts" is the block-level version of "inner dimensions match". Get it wrong and the block products are undefined, which is a much friendlier failure than silently computing the wrong thing.
  • Two special cases you already use daily: taking one block per column of A and one per row of B reproduces the layer perspective (a sum of outer products); taking the whole of A as one block and B's columns as blocks reproduces the column perspective. The four perspectives above are four block partitions.
  • The practical payoff is not elegance but arithmetic: block algorithms are how numerical libraries get cache locality, how a covariance matrix gets updated when new variables arrive, and how "add one more predictor to the regression" becomes a rank-one update instead of a refit.

The Schur complement — the block inverse and the block determinant

  • Once you can multiply blocks you can invert them, and one expression organises the entire computation. For a square A = [[A₁₁, A₁₂], [A₂₁, A₂₂]] with A₁₁ non-singular, the Schur complement of A₁₁ in A is Z = A₂₂ − A₂₁A₁₁⁻¹A₁₂.
  • Everything follows from one factorisation into (block lower triangular)·(block unit upper triangular). Verify it by multiplying out; the point is that the awkward corner has been eliminated, exactly as Gaussian elimination clears a column (§10). The Schur complement is "what is left of A₂₂ after eliminating the first block of variables".
  • Determinant: the factorisation is triangular, so the determinant is the product of the diagonal blocks' determinants — |A| = |A₁₁|·|Z| (§11). This is the block generalisation of "the determinant of a triangular matrix is the product of its diagonal".
  • Inverse: invert the two triangular factors (easy) and multiply back. The bottom-right block of A⁻¹ is exactly Z⁻¹ — a fact with real statistical teeth.
  • Rank: if the partition is a full-rank partitioning — rank(A₁₁) = rank(A) — then Z = 0. The Schur complement measures the information in A₂₂ that A₁₁ does not already contain.
  • Why statisticians care. Apply it to the Gram matrix of an augmented design, A = [X | y]ᵀ[X | y]. Then A₁₁ = XᵀX, A₁₂ = Xᵀy, A₂₂ = yᵀy, and the Schur complement is yᵀy − yᵀX(XᵀX)⁻¹Xᵀy — the residual sum of squares of the least-squares fit (§14). "Eliminate the predictors and see what variance is left" is literally a block elimination.
  • The same corner of the same formula, applied to a covariance matrix, gives the conditional covariance Σ₂₂ − Σ₂₁Σ₁₁⁻¹Σ₁₂ of a Gaussian, and the fact that (A⁻¹)₂₂ = Z⁻¹ is why the precision matrix (the inverse covariance) encodes conditional independence and partial correlations, while the covariance matrix encodes marginal ones. One block identity, two of the most-used facts in multivariate statistics.
  • Cousins worth recognising: the Woodbury / Sherman–Morrison update formulas for (A + UCV)⁻¹ come out of the same 2×2 factorisation read in the other order, and are the standard way to update a fit when data arrives (§12).

Hadamard product, Frobenius dot product, matrix norms

  • Hadamard A ⊙ B: element-wise, cᵢⱼ = aᵢⱼbᵢⱼ. Needs identical shapes, returns that shape, and — unlike standard multiplication — is commutative. (In numpy A*B is Hadamard, A@B is standard; confusing them is a classic silent bug.)
  • Frobenius dot product ⟨A, B⟩_F: same shapes in, one scalar out. Vectorize both (stack the columns) and take the ordinary dot product — equivalently sum all element-wise products. ⟨[[1,5,0],[−4,0,2]], [[4,−1,3],[2,6,7]]⟩_F = 4 − 5 − 8 + 14 = 5. The slick form is tr(AᵀB), which polices its own validity (the trace needs a square argument). It is the inner product that makes matrix space Euclidean — hence a similarity measure between matrices.
  • Frobenius norm: ‖A‖_F = √(∑ᵢⱼ aᵢⱼ²) = √tr(AᵀA) — the matrix with itself, square-rooted. Then ‖A − B‖_F is Euclidean distance between same-sized matrices, the loss minimized by low-rank approximation.
  • Induced (operator) norms measure worst-case stretching, max ‖Ax‖ₚ / ‖x‖ₚ: the 1-norm is the largest absolute column sum, the ∞-norm the largest absolute row sum, and the 2-norm (spectral) is the largest singular value (§16). Careful — the entrywise ℓ₂ norm (Frobenius) is a different number: always ‖A‖₂ ≤ ‖A‖_F.
  • Families: entrywise p-norms (∑|aᵢⱼ|ᵖ)^(1/p) generalize Frobenius (p = 2); Schatten norms apply a p-norm to the singular values instead — Schatten-2 is Frobenius again, Schatten-∞ the spectral norm, Schatten-1 the nuclear norm used as the convex surrogate for rank.
  • Cauchy-Schwarz for matrices: ‖Ax‖ ≤ ‖A‖_F‖x‖ — follows from the row perspective plus the vector inequality. Norms bound how much a transform can amplify.

Hadamard identities worth memorising

  • The element-wise product looks too simple to have a theory, but it interacts with the trace and the diagonal in ways that shorten a lot of derivations.
  • Its identity element is J, the all-ones matrix: A ⊙ J = A. Note that I is not the Hadamard identity — instead A ⊙ I = dg(A), the diagonal matrix built from A's diagonal. Masking with I extracts a diagonal; masking with a 0/1 pattern is what dropout, attention masks and sparsity constraints all do.
  • It is commutative, associative, distributive over addition, and transposes element-wise ((A ⊙ B)ᵀ = Aᵀ ⊙ Bᵀ) — everything ordinary multiplication is, which is exactly what standard matrix multiplication is not.
  • Trace bridges. tr(ABᵀ) = 1ᵀ(A ⊙ B)1 — sum every entry of the Hadamard product and you have the Frobenius inner product. And tr(Aᵀ(B ⊙ C)) = tr((Aᵀ ⊙ Bᵀ)C) lets you slide a Hadamard factor across a trace.
  • Diagonal scaling passes through: for a diagonal M = diag(m), (MA) ⊙ (BᵀM) = M(A ⊙ Bᵀ)M, and tr(AMBᵀM) = mᵀ(A ⊙ B)m. That second identity turns a trace into a quadratic form (§17) and is the workhorse behind weighted-least-squares variance calculations.
  • Schur product theorem: the Hadamard product of two positive semi-definite matrices is positive semi-definite. This is not obvious and it matters: it is why the product of two valid kernels is a valid kernel, and hence why polynomial and RBF kernels can be combined freely.
  • Rank is only bounded, not determined: rank(A ⊙ B) ≤ rank(A)·rank(B). Element-wise multiplication can and usually does destroy structure — two rank-1 matrices Hadamard-multiply to rank 1, but a masked low-rank matrix is generally full rank, which is precisely the difficulty in matrix completion.

The Kronecker product

  • Every product so far has demanded that shapes agree somewhere. The Kronecker product A ⊗ B demands nothing: it is defined for any pair of matrices. Replace each entry aᵢⱼ of A by the whole block aᵢⱼB. An m×n times a p×q gives an mp × nq matrix — a block matrix (§05) with A's pattern and B's texture.
  • Also called the direct or tensor product. It is associative and distributive but not commutative — A ⊗ B and B ⊗ A are the same numbers permuted, and a permutation matrix (the commutation matrix below) converts between them.
  • The mixed-product rule is the one to memorise: (A ⊗ B)(C ⊗ D) = AC ⊗ BD, whenever AC and BD exist. Nearly every other identity is a corollary. Set C = A⁻¹, D = B⁻¹ and you get (A ⊗ B)⁻¹ = A⁻¹ ⊗ B⁻¹; the transpose rule (A ⊗ B)ᵀ = Aᵀ ⊗ Bᵀ comes straight from the definition.
  • Eigenvalues multiply. If A (m×m) has eigenvalues λᵢ and B (p×p) has μⱼ, then A ⊗ B has the mp eigenvalues λᵢμⱼ. Proof: triangularise both (S⁻¹AS = L, T⁻¹BT = M); the mixed-product rule gives (S ⊗ T)⁻¹(A ⊗ B)(S ⊗ T) = L ⊗ M, which is upper triangular with the products on its diagonal, and similar matrices share eigenvalues (see below).
  • Three consequences fall out at once: |A ⊗ B| = |A|ᵖ|B|ᵐ (multiply the eigenvalues), tr(A ⊗ B) = tr(A)·tr(B), and rank(A ⊗ B) = rank(A)·rank(B) (count the non-zero eigenvalues of AAᵀ ⊗ BBᵀ). Also: A, B positive semi-definite ⟹ A ⊗ B positive semi-definite.
  • Caution on eigenvectors. x ⊗ y is an eigenvector of A ⊗ B whenever x, y are eigenvectors of A, B — but the converse fails. With repeated eigenvalues, A ⊗ B has eigenvectors that are not Kronecker products of anything.
  • Where it shows up. Separable structure: a 2-D convolution or blur whose kernel factorises is K_row ⊗ K_col; a matrix-variate normal has covariance Σ ⊗ Ψ (rows and columns each with their own covariance); multi-task and multi-output regression stack per-task designs into a Kronecker form; and in deep learning the K-FAC optimiser approximates a layer's Fisher information as A ⊗ G precisely so that the inverse A⁻¹ ⊗ G⁻¹ costs two small inversions instead of one enormous one. That last line is the mixed-product rule earning its keep.

The vec operator — and the identity behind matrix calculus

  • vec(A) stacks the columns of A one under the other, turning an m×n matrix into an mn-vector. It is defined for every matrix, square or not. (Column-major stacking is the convention; row-major stacking is vec(Aᵀ), and mixing the two is a classic bug.)
  • Two base cases connect it to everything else: vec(abᵀ) = b ⊗ a (the j-th column of abᵀ is bⱼa) and (vec A)ᵀ vec B = tr(AᵀB) — the Frobenius inner product is an ordinary dot product on the vectorised matrices. So the whole geometry of §06's norms section is just ℝ^(mn) in disguise.
  • The identity. vec(ABC) = (Cᵀ ⊗ A) vec(B). Proof: write B = Σⱼ bⱼeⱼᵀ, apply vec(abᵀ) = b ⊗ a termwise, and factor out (Cᵀ ⊗ A). ∎
  • Why it matters. It converts a bilinear expression in a matrix unknown into an ordinary matrix-times-vector in the unknown's entries. That is exactly what a derivative needs: ∂vec(ABC)/∂vec(B) = Cᵀ ⊗ A. Every Jacobian in matrix differential calculus is built this way, and it is why Cᵀ ⊗ A keeps appearing in backpropagation formulas for a weight matrix sandwiched between activations.
  • The three special cases you will actually type: vec(AB) = (Iq ⊗ A) vec B = (Bᵀ ⊗ Iₘ) vec A, and for a vector d, ABd = (dᵀ ⊗ A) vec B. Also the four-factor trace identity tr(ABCD) = (vec Dᵀ)ᵀ(Cᵀ ⊗ A) vec B.
  • Solving matrix equations. The Sylvester equation AX + XB = C looks unlike anything solvable — until you vectorise it into (I ⊗ A + Bᵀ ⊗ I) vec X = vec C, an ordinary linear system (§10). The Lyapunov equation, the discrete-time Riccati recursions and the steady-state covariance of a linear dynamical system all yield to the same move.
  • The commutation matrix K_mn is the unique permutation matrix with K_mn vec(A) = vec(Aᵀ). Being a permutation it is orthogonal, so K_mnᵀ = K_mn⁻¹ = K_nm. Its point in life is to commute a Kronecker product: K_pm(A ⊗ B) = (B ⊗ A)K_qn. It is the bookkeeping device that makes derivatives with respect to Aᵀ behave.
  • The duplication matrix D_n handles symmetry. A symmetric n×n matrix has only n(n+1)/2 distinct entries; write v(A) for that shorter list. Then D_n v(A) = vec(A) — D_n re-duplicates the off-diagonal entries. It has full column rank, so D_nᵀD_n is invertible and the Moore–Penrose inverse D_n⁺ = (D_nᵀD_n)⁻¹D_nᵀ goes the other way. This is how you differentiate with respect to a covariance matrix without pretending its entries are free (§18).
  • Related: N_n = ½(I_{n²} + K_n) is the symmetriser — idempotent, symmetric, and of rank n(n+1)/2. It is the projection onto the space of vectorised symmetric matrices, which is the abstract reason "take the symmetric part, (A + Aᵀ)/2" is the right thing to do.

Matrix norms — the axioms, the induced family, and what they are for

  • The bullets above named several norms; here is the frame they sit in. A matrix norm is any ‖·‖ : ℝ^(m×n) → ℝ satisfying four conditions: (i) non-negative and definite (‖A‖ ≥ 0, = 0 only for A = 0); (ii) absolutely homogeneous (‖γA‖ = |γ|‖A‖); (iii) triangle inequality (‖A + B‖ ≤ ‖A‖ + ‖B‖); and (iv) consistency / submultiplicativity (‖AB‖ ≤ ‖A‖‖B‖).
  • Condition (iv) is the only one that is not inherited from vector norms, and it is the one that pays: it immediately gives ‖Aᵏ‖ ≤ ‖A‖ᵏ, and therefore control over every iterative algorithm that repeatedly applies a matrix. Some authors omit it; the useful norms have it.
  • Induced (operator) norms take a vector norm and ask for the maximum magnification: ‖A‖ = max_{x ≠ 0} ‖Ax‖/‖x‖. All four axioms are then automatic, and so is the everyday inequality ‖Ax‖ ≤ ‖A‖‖x‖. Three members are famous, and only the third is hard:
  • ‖A‖₁ = largest absolute column sum; ‖A‖_∞ = largest absolute row sum. Both are read straight off the matrix — and the two swap under transposition, ‖Aᵀ‖_∞ = ‖A‖₁. Sketch: with ‖x‖₁ = 1 you may pour all the mass onto whichever column is biggest; with ‖x‖_∞ = 1 you may set every xⱼ = ±1 to align the signs of one whole row.
  • ‖A‖₂ — the spectral norm — is √ρ(AᵀA) = σ_max(A), the largest singular value (§16). It cannot be read off the entries; you must decompose. For symmetric A it collapses to ρ(A), the largest eigenvalue in absolute value, and ‖A‖₁ = ‖A‖_∞.
  • Frobenius is not an induced norm — it is the norm coming from the Frobenius inner product, which is why it alone gives you angles between matrices, cos∠(A,B) = ⟨A,B⟩_F/(‖A‖_F‖B‖_F). Via the SVD, ‖A‖²_F = Σᵢ σᵢ² against the spectral norm's σ_max: Frobenius sums the singular values' squares, spectral takes the biggest. Hence the exact sandwich ‖A‖₂ ≤ ‖A‖_F ≤ √rank(A) · ‖A‖₂.
  • Orthogonal invariance. ‖QᵀAQ‖_F = ‖A‖_F and ‖QᵀAQ‖₂ = ‖A‖₂ for orthogonal Q — proof for Frobenius is one line of trace cycling. So both norms measure something about the transformation, not about the coordinate grid, exactly like the trace. Also ‖Q‖₂ = 1 and, for an n×m matrix with orthonormal columns, ‖Q‖_F = √m.
  • All matrix norms are equivalent on a finite-dimensional space: for any two there are constants with r‖A‖_b ≤ ‖A‖_a ≤ s‖A‖_b. So "does this sequence of matrices converge?" has a norm-free answer — pick whichever norm is convenient.
  • The spectral radius is bounded by every consistent norm: ρ(A) ≤ ‖A‖. Proof: for an eigenpair (λ, v) build V = [v | 0 | … | 0], so λV = AV and |λ|‖V‖ = ‖AV‖ ≤ ‖A‖‖V‖. Combined with the row- and column-sum norms, this hands you a free eigenvalue bound: no eigenvalue can exceed the largest absolute row sum. (ρ itself is not a norm — a non-zero nilpotent matrix has ρ = 0.)
  • Powers and series. Aᵏ → 0 if ‖A‖ < 1 for some norm; and in fact Aᵏ → 0 if and only if ρ(A) < 1. That gives the matrix geometric series, (I − A)⁻¹ = I + A + A² + … whenever ρ(A) < 1 — the Neumann series.
  • That last line is not a curiosity. It is the convergence criterion for Jacobi and Gauss–Seidel iterations, the stability condition for a linear dynamical system, the reason a discounted value function satisfies V = (I − γP)⁻¹ r = Σₖ γᵏPᵏr in reinforcement learning (ρ(γP) = γ < 1), and — through ‖A‖₂ as a Lipschitz constant — the basis of spectral normalisation for stabilising GANs and of gradient-explosion analysis in recurrent networks.

What about matrix division?

  • There is no A/B. The scalar trick is to rewrite 2/3 as 2·3⁻¹; the matrix version is AB⁻¹ — or B⁻¹A, and those differ.
  • A⁻¹ is defined by AA⁻¹ = A⁻¹A = I, and a full inverse exists only for square, full-rank matrices — which is exactly why rank is next (§07). Full treatment in §12.
Two things to carry forward: (1) Ax is a weighted sum of A's columns — this idea powers rank, column space, least squares, and PCA. (2) Order is never free: AB ≠ BA, transposes and inverses reverse it, and "dividing" means multiplying by an inverse on a chosen side.

linear maps & change of basis A matrix is a linear map — once you fix a basis

So far a matrix has been a grid we do arithmetic on. The truth underneath is that a matrix is a bookkeeping device for a linear map, chosen relative to a basis. Change the basis and the grid changes while the map does not — which explains where matrix multiplication comes from, what similarity means, and why diagonalising anything is worth the effort.

Linear maps, and the fact that a basis determines everything

  • A linear map (or homomorphism) h : V → W between vector spaces is one that preserves linear combinations: h(c₁v₁ + c₂v₂) = c₁h(v₁) + c₂h(v₂). Preserving addition and scaling separately, preserving combinations of two, and preserving combinations of any number are all the same condition (induct on the number of terms). Every linear map sends 0 to 0, because h(0) = h(0·v) = 0·h(v) = 0.
  • An isomorphism (§04) is a linear map that is also a one-to-one correspondence; a transformation is a linear map from a space to itself. The distinction matters below: transformations get one basis, general maps get two.
  • The pivotal observation: a linear map is completely determined by what it does to a basis. Write v = c₁b₁ + … + cₙbₙ — the coordinates exist and are unique — and linearity forces h(v) = c₁h(b₁) + … + cₙh(bₙ). Choose the n images freely and the whole map is pinned down; there is nothing else to specify.
  • So a map from an n-dimensional space to an m-dimensional one is exactly n vectors in the target, each described by m coordinates. That is m × n numbers. A matrix is not like a linear map; it is the list of those numbers.

Representing a map as a matrix

  • Fix a basis B = ⟨b₁, …, bₙ⟩ for the domain and D = ⟨d₁, …, d_m⟩ for the codomain. The representation of h, written here h[B,D], is the matrix whose j-th column is the coordinate vector of h(bⱼ) with respect to D.
  • Theorem. With that definition, applying the map is matrix-vector multiplication of the representations: h(v)[D] = h[B,D] · v[B]. The proof is one line — expand v in B, push h through by linearity, and collect coordinates — and the definition was chosen precisely to make it true.
  • Read that theorem against the column perspective of §06: Ax is a weighted sum of A's columns. Now you know why the columns are the interesting objects — they are the images of the basis vectors. In the standard basis, column j is literally Ae_j, the place where the j-th axis lands.
  • The converse also holds: any m×n matrix represents some linear map between any pair of spaces of dimensions n and m, once you name bases. So the space of linear maps V → W is isomorphic to ℝ^(m×n): nothing is lost or invented by working with grids of numbers.
  • And this is where matrix multiplication comes from. Compose two maps, g : U → V then h : V → W. Ask for the representation of h ∘ g and grind through the coordinates: entry (i,j) comes out as Σₖ hᵢₖ gₖⱼ. The peculiar-looking rule of §06 is not a convention — it is the unique rule that makes matrices compose the way functions compose. Associativity of matrix multiplication is then just associativity of function composition, and AB ≠ BA is just "doing g then h differs from doing h then g".
  • Everything else lines up too: the identity matrix represents the identity map, the inverse matrix represents the inverse map (which exists exactly when the map is one-to-one and onto), and the rank of a matrix equals the rank of any map it represents — the dimension of the map's range space (§08).

Change of basis: the same vector, a different column

  • Coordinates are basis-relative (§04), so we need a machine for translating between two of them. It is already built: the change of basis matrix is nothing but the representation of the identity map with respect to two different bases, id[B,D] — its columns are the old basis vectors written in the new basis.
  • By the representation theorem, left-multiplying converts: id[B,D] · v[B] = v[D]. A better name would be "change of representation matrix" — the vector never moves; only its description does.
  • Lemma. A matrix changes bases if and only if it is non-singular. (⟹) it represents an invertible map — you can always change back. (⟸) any non-singular matrix is a product of elementary matrices, and each of those carries one basis to another. So "invertible matrix" and "change of coordinates" are the same concept seen from two sides (§12).
  • Concretely, if P is the matrix whose columns are the new basis vectors written in the old coordinates, then v_old = P·v_new and v_new = P⁻¹·v_old. The direction of the inverse trips everyone up once: P takes new coordinates to old ones, because it is built out of the new basis vectors.

Change of basis for a map: matrix equivalence and similarity

  • Now change the bases on both ends. Going "across the top" with the old bases, or "up the left, across, and down the right" through the identity maps, must give the same answer — so the new representation is Ĥ = id[D,D̂] · H · id[B̂,B]. Two nonsingular matrices, one on each side.
  • Matrix equivalence. Same-sized H and Ĥ are matrix equivalent if Ĥ = PHQ for some non-singular P, Q. By the above, that says exactly: they represent the same map, with respect to different pairs of bases.
  • Since P and Q are products of elementary matrices, left-multiplying does row operations and right-multiplying does column operations. So matrix equivalence generalises row equivalence (§10): row-equivalent ⟹ matrix-equivalent, but not conversely — [[1,0],[0,0]] and [[1,1],[0,0]] are matrix equivalent (one column operation apart) yet are their own distinct reduced echelon forms.
  • The classification is complete and startlingly simple. Every m×n matrix of rank k is matrix equivalent to the block partial identity [[I_k, 0], [0, 0]]. Hence: two same-sized matrices are matrix equivalent if and only if they have the same rank. If you are allowed to change both bases, rank is the only thing about a matrix that survives. (In the right pair of bases the map just copies k basis vectors across and annihilates the rest — which is also the skeleton of the SVD, §16.)
  • Similarity is the special case that actually matters for transformations. When domain and codomain are the same space, it is unnatural to use different bases at the two ends — so demand one basis, used twice. Then Q = P⁻¹, and Â = P⁻¹AP. Matrices related this way are similar.
  • Similarity is a special case of matrix equivalence, so similar ⟹ matrix equivalent; the converse fails badly. I and 2I are both rank 2, hence matrix equivalent — but P⁻¹IP = I for every P, so I is similar only to itself. Similarity is a strictly finer partition: each matrix-equivalence class splits into many similarity classes.
  • What survives similarity is what belongs to the map rather than the coordinate grid: rank, determinant, trace, characteristic polynomial, and hence the whole multiset of eigenvalues. The entries themselves survive nothing. This is why "tr(A) = sum of eigenvalues" and "det(A) = product of eigenvalues" are even possible statements (§15).
  • And this is what diagonalisation is. "Diagonalise A" means "find the basis in which this map's matrix is diagonal" — P⁻¹AP = Λ with P's columns the eigenvectors. The map was never complicated; we were looking at it in a badly chosen coordinate system. For symmetric A the good basis is even orthogonal (§17), which is the entire content of PCA (§19). Not every matrix is diagonalisable; the general fallbacks are the Jordan form and — always available, and numerically the right answer — the SVD.

The subspaces belong to the map, not to the grid

  • A linear map has a range space R(h) = {h(v) : v ∈ V} and a null space N(h) = {v : h(v) = 0}. Both are subspaces — closure is immediate from linearity — and under any representation they are exactly the column space and the null space of the matrix (§08).
  • So rank–nullity is a statement about maps: dim R(h) + dim N(h) = dim V. Changing the basis changes every number in the matrix but cannot change these dimensions — they are similarity (indeed, equivalence) invariants.
  • The derivative example above makes it concrete: on P₂, differentiation has range P₁ (dimension 2) and null space the constants (dimension 1), and 2 + 1 = 3. Change to any other basis of P₂ and the matrix changes completely while 2 and 1 do not.
  • This is the honest reason the four fundamental subspaces are worth a whole section: they are the coordinate-free content of a matrix. Everything else on the page is a description that depends on a choice you made.
The one-sentence version: a matrix is a map plus a choice of basis. Multiplication is composition, the inverse is the inverse map, similarity is "same map, different basis", matrix equivalence is "same map, different bases at each end" — and diagonalisation is the search for the basis in which the map finally looks simple.

07 Rank

Rank is the single most informative number about a matrix: how many independent directions it actually spans. Nearly every "is this allowed / will this be stable" question is a rank question in disguise.

Six things about rank

  • Rank is one non-negative integer per matrix — never negative, never fractional. Only the zeros matrix has rank 0.
  • It is bounded: 0 ≤ rank(A) ≤ min(m, n).
  • It is a property of the whole matrix, not of its rows, columns, or subspaces — "the rank of the null space" is meaningless.
  • Full rank means r = min(m, n): full column rank if tall (r = n), full row rank if wide (r = m). Otherwise it's rank-deficient — reduced-rank, degenerate, low-rank, or (if square) singular.
  • Rank counts dimensions of information, not rows or columns: [[1,3,4],[3,9,12]] has 3 columns and 2 rows but rank 1 — every column is a multiple of the others, as is every row.
  • The definition to hold onto: the largest number of columns forming a linearly independent set, which always equals the largest number of independent rows.
rank(A) = dim C(A) = dim C(Aᵀ) = # non-zero singular values 0 ≤ r ≤ min(m, n)

Interpretations, and how to compute it

  • Algebraic: the size of the largest independent subset of columns (or rows). Independence is a property of a set, so "number of independent columns" is shorthand for this.
  • Geometric: the dimensionality of the subspace spanned — emphatically not the ambient dimensionality. [4, 0, 1]ᵀ lives in ℝ³ but spans a line, so rank 1 (every non-zero vector has rank 1).
  • The two views can look totally different and still agree. [[1,1,−4],[2,−1,2]] is three vectors spanning all of ℝ² column-wise, and two vectors spanning a plane inside ℝ³ row-wise: different subspaces, same dimensionality.
  • Three ways to compute: count the largest independent set by inspection (small integer matrices only); count pivots in echelon form (§10); count non-zero singular values from the SVD (§16) — the numerically robust route. np.linalg.matrix_rank does the last one, counting singular values above a tolerance.

Sharper rank bounds, and two factorisations that expose the rank

  • The table above gives ceilings. Three more results give floors and exact values, and they are the ones that settle arguments.
  • Sylvester's law of nullity (a lower bound on a product). If A is n×n and B has n rows, then rank(AB) ≥ rank(A) + rank(B) − n. Together with the ceiling: rank(A) + rank(B) − n ≤ rank(AB) ≤ min(rank A, rank B). The practical reading is that a product can only lose as much rank as the shared dimension allows — multiply two full-rank square matrices and you cannot lose any at all.
  • Sums are two-sided too: |rank(A) − rank(B)| ≤ rank(A + B) ≤ rank(A) + rank(B). The lower bound follows from the upper one applied to A = (A + B) + (−B). So adding a low-rank matrix to a high-rank one cannot collapse it far — the basis of "low-rank plus sparse" decompositions such as robust PCA.
  • Rank is invariant to multiplication by non-singular matrices: rank(PAQ) = rank(A) for non-singular P, Q. That is the rank statement of matrix equivalence (linear maps) — row and column operations cannot create or destroy information, only re-describe it. Corollary: Gaussian elimination is a legitimate way to compute rank.
  • Blocks. Every block of a partitioned matrix has rank at most the whole: rank(Aᵢⱼ) ≤ rank(A); and rank(A) ≤ rank([A₁₁ | A₁₂]) + rank([A₂₁ | A₂₂]), with equality when the two block-rows span orthogonal row spaces. Also rank(A ⊗ B) = rank(A)·rank(B) and rank(A ⊕ B) = rank(A) + rank(B) — Kronecker multiplies rank, direct sum adds it.
  • Full-rank factorisation. Any m×n matrix of rank r > 0 factors as A = L·R with L of size m×r and full column rank, R of size r×n and full row rank. Constructively: let L hold r independent columns of A, and let R hold the coefficients that rebuild every column from them.
  • This is the honest definition of "low rank": a rank-r matrix is exactly one that factors through an r-dimensional bottleneck. It has r(m + n − r) free parameters instead of mn — the compression claim behind matrix factorisation for recommenders, embedding layers, and LoRA-style adapters. Equivalently, expanding the product column-by-row, a rank-r matrix is a sum of exactly r outer products (the layer perspective, §06).
  • Equivalent canonical form. Push the idea further and you may choose non-singular P, Q with PAQ = [[I_r, 0], [0, 0]]. Every matrix of a given size and rank reduces to this one shape; conversely, matrices reduce to the same shape exactly when their ranks agree. Rank is therefore a complete invariant under row-and-column operations — the tidiest theorem about rank there is.
  • The factorisation is not unique (any invertible M gives A = (LM)(M⁻¹R)), and it is not numerically stable. The stable, canonical choice of the same idea is the SVD, which picks L and R orthonormal and the bottleneck diagonal (§16).

Random matrices, and boosting rank by shifting

  • Fill a matrix with floating-point random numbers and it is full rank with probability 1 — an exact dependency among continuous values is a measure-zero event. The exception is a restricted range: random 0/1 entries very much can be dependent (a 4×4 binary matrix of rank 2 is easy to hit).
  • Shifting adds a multiple of the identity: Ã = A + λI, moving the diagonal and leaving everything else alone. Any λ outside the (finite) set of eigenvalues of −A makes Ã full rank, so an arbitrarily tiny λ almost always works: [[1,3,−19],[5,−7,59],[−5,2,−24]] has rank 2, and adding 0.01·I makes it rank 3 while changing the diagonal by under 1%.
  • The trade-off is the whole story: λ → 0 keeps Ã ≈ A (faithful but near-singular); large λ pushes Ã → λI (well-conditioned but informationless). The degenerate extreme: shifting the zeros matrix by λ = 1 raises the rank from 0 to 3 and destroys everything.
  • In statistics and ML this is regularization (matrix smoothing / ridge): (XᵀX + λI)⁻¹Xᵀy is ridge regression, and the same shift stabilizes PCA and generalized eigendecomposition. Choosing λ is application-specific and open; shrinkage methods (§19) are one principled answer.

Rank is hard in practice

  • Floating point can't distinguish a genuinely tiny singular value from a rounded-off zero. Is 3 × 10⁻¹⁵ signal or noise? Software picks a tolerance, and rounding error can land on either side of it.
  • Geometrically: three sensor readings that should lie in a plane will, with a whisker of noise, poke slightly off it — the computer reports rank 3 where the physics says 2. What you want is the numerical rank: how many singular values are large relative to the noise floor. Prefer asking "how fast do the singular values decay?" over "what is the rank?".

Rank and span — the augment-rank test

  • Is v in the span of a set of vectors? Put them in a matrix S, compute r₁ = rank(S) and r₂ = rank([S | v]). Equal ⟹ v is in the span (it added no new direction); one higher ⟹ it is not; smaller ⟹ you made an arithmetic error.
  • This is the same test as "is b reachable by Ax?" — the solvability condition for Ax = b (§08, §10). It answers whether, not with what weights; for those, run Gaussian elimination.
v ∈ span(S) ⟺ rank([S | v]) = rank(S)
Geometric meaning: a rank-deficient transform collapses space — a plane onto a line (or a point). Its determinant is 0 and it has no inverse. Set the determinant to ≈0 in the transform above to see it happen. This is the thread that leads to the inverse, least-squares, and PCA.
Why the fuss: some operations (above all the inverse) exist only at full rank, others merely behave far better there, and numerical algorithms are more reliable on full-rank inputs — which is exactly why regularization exists.

08 The four fundamental subspaces

Every matrix carves its input and output spaces into four subspaces. Rank is the hinge that fixes all of their sizes — this is the "big picture" of linear algebra. The entire chapter is really two questions: Ax = b (can I reach b?) and Ay = 0 (what gets destroyed?).

Column space C(A)

  • The subspace spanned by the columns — every linear combination β₁a₁ + … + βₙaₙ. Also called the range or image.
  • For A ∈ ℝ^(m×n), C(A) ⊂ ℝᵐ — not ℝⁿ. Each of the n columns has m entries, so the ambient space is set by the number of rows. Its dimension is r: if r = m the columns fill all of ℝᵐ; if r < m they span an r-dimensional slice of it.
  • Span vs basis: the columns always span the column space, but they form a basis only when they are linearly independent — i.e. when r equals the number of columns. A matrix and the same matrix with a duplicated column have identical column spaces but different basis status.
  • The solvability statement: Ax = b has an exact solution iff b ∈ C(A), and then x holds the weights on the columns that build b.
  • An easy basis for C(A) is the first r independent columns — easy, not good. The SVD (§16) produces an orthogonal basis for the same space, which is what you actually want numerically.
column spaceC(A) = span(a₁, …, aₙ) = {β₁a₁ + … + βₙaₙ : β ∈ ℝⁿ} C(A) ⊂ ℝᵐ, dim = r

A and AAᵀ share a column space

  • Sizes first: AAᵀ is m×m, so its column space also lives in ℝᵐ. (Note AᵀA could not possibly share it — it lives in ℝⁿ.)
  • By the column perspective of multiplication, every column of AAᵀ is a weighted combination of A's columns, so C(AAᵀ) ⊆ C(A). Both have the same rank (§07), hence the same dimension — and a subspace of equal dimension inside another is the other.
  • Same argument transposed: A and AᵀA have the same row space. This is a form of dimensionality reduction: AᵀA may be far smaller than A yet carries the same row space — the reason covariance matrices are such useful stand-ins for raw data.
  • Same space, different spanning vectors: the columns of A and of AAᵀ are generally different bases for the one subspace.

Is a given vector in the column space?

  • Take A = [[2,1],[4,4],[0,0]] — two independent columns, so C(A) is a plane inside ℝ³. Is v = [4, 12, 0] on it? Yes: 1·[2,4,0] + 2·[1,4,0] = [4,12,0], i.e. Ax = v with x = [1, 2]. Is w = [4, 1, 1]? No — no combination of columns whose third entry is 0 can produce a non-zero third entry, so Ax ≠ w for every x ∈ ℝⁿ.
  • Mechanically, the augment-rank algorithm: build B = [A | v] and compare ranks. Equal ⟹ v ∈ C(A); one higher ⟹ v ∉ C(A).
  • Geometrically: a vector already inside the subspace contributes no new direction, so the dimension can't grow. A vector poking outside adds exactly one new direction. Algebraically: if v is a combination of A's columns, augmenting creates a dependent set, so the rank cannot increase.
  • Corollary: if A is square and full rank, every v ∈ ℝᵐ is in the column space — there is no room for an (m+1)-dimensional subspace in ℝᵐ.
  • The test answers whether, not how. To recover the weights, run Gaussian elimination (§10).

Row space C(Aᵀ)

  • The span of the rows, written R(A) or C(Aᵀ) — the column space of the transpose. It lives in ℝⁿ and also has dimension r.
  • The question changes side: membership is xᵀA = vᵀ, a weighted combination of rows with the weight vector on the left. The augment-rank test still works — append v as an extra row.
  • The two spaces can look nothing alike. For [1, 2, 0, −3] the row space is a line in ℝ⁴ while the column space is all of ℝ¹ — completely different objects, identical dimension (1). For a square full-rank matrix they coincide: C(A) = R(A) = ℝⁿ.

Null space N(A)

  • Every y with Ay = 0 — the combinations of columns that cancel exactly. Also called the kernel. Vectors here are squashed to the origin and can never come back: no matrix B exists with BAy ≠ 0.
  • y = 0 always works; that is the trivial solution and we ignore it. The interesting question is whether a non-trivial y exists.
  • Example: [[1,2],[4,8]]·[−2, 1]ᵀ = [0, 0]ᵀ. And every scalar multiple works too — N([[1,2],[4,8]]) = {σ·[−2, 1]ᵀ}. A null space is a subspace (a line here), not a single vector, so we describe it by a basis.
  • Contrast [[1,2],[4,7]]: no non-trivial y exists. People say it "has no null space"; strictly, the null space is empty (just the origin), dimension 0.
  • The pattern is not a coincidence: [[1,2],[4,8]] is rank 1 and [[1,2],[4,7]] is rank 2. Full column rank ⟹ trivial null space; rank-deficient columns ⟹ non-trivial null space.
  • Sizes: the null vector weights the n columns, so N(A) ⊂ ℝⁿ — the same ambient space as the row space. Null spaces are not just for square matrices: [[1,2],[1,2],[1,2],[1,2]]·[−2,1]ᵀ = 0 works fine for a 4×2 matrix.
null spaceN(A) = {y : Ay = 0}, excluding the trivial y = 0 N(A) ⊂ ℝⁿ, dim = n − r

Left null space, and the geometry of collapse

  • The mirror image, with the vector on the left: yᵀA = 0ᵀ. Transposing gives Aᵀy = 0 — so the left null space is just the ordinary null space of Aᵀ, exactly as the row space is the column space of Aᵀ.
  • It weights the m rows, so N(Aᵀ) ⊂ ℝᵐ. And when A = Aᵀ the two null spaces coincide.
  • Geometry: take M = [[1,2],[2,4]] (singular). The vector y = [−2, 1] is in its null space and My is a single dot at the origin, while u = [−1, 1] maps to an ordinary non-zero vector. The matrix has a one-dimensional direction of total collapse.
  • Nothing is special about M or about y individually — what is special is the pairing. Note also that MAy ≠ AMy for a generic A: sneak a matrix in first and the vector is no longer aligned with M's null direction, so nothing collapses.

Orthogonal subspaces and orthogonal complements

  • Two subspaces are orthogonal when every vector in one is orthogonal to every vector in the other. It suffices to check basis vectors: if v₁ ⟂ w and v₂ ⟂ w then (α₁v₁ + α₂v₂) ⟂ βw, since scaling and summing zeros still gives zero.
  • They must share an ambient space — orthogonality is defined by dot products, which need matching dimensionality.
  • Trap: two perpendicular-looking planes in ℝ³ are not orthogonal subspaces. They intersect in a line, and a vector on that line would have to be orthogonal to itself. Two 2D objects can never be orthogonal subspaces inside 3D. A plane and a line normal to it can.
  • Orthogonal complements: subspaces V and W that are orthogonal and together span the whole ambient space, meeting only at the origin. Every vector in ℝᴺ is then in exactly one of them.

The four subspaces pair up

  • "y is orthogonal to C(A)" means y is orthogonal to every column, i.e. every entry of Aᵀy is zero — which is the definition of the left null space. Starting from orthogonality, we rediscover N(Aᵀ).
  • Likewise "y orthogonal to every row" collects into Ay = 0 — the null space. So the pairings are forced, not designed.
  • Because each pair is an orthogonal complement, the two halves fill the ambient space: every vector in ℝᵐ is either in the column space or the left null space, and every vector in ℝⁿ is either in the row space or the null space (only the zeros vector is in both).
  • Quick check: B = [[1,1],[2,2]] has C(B) = span{[1,2]} and N(Bᵀ) = span{[−2,1]} — dot product 0, visibly perpendicular lines. D = [[1,1],[2,3]] is full rank, so C(D) = ℝ² and its left null space is empty (just the origin): there is nothing left over to be orthogonal to.

Dimensionalities (rank-nullity)

  • Dimension ≠ rank. Rank is one number for the whole matrix; the four subspaces have four dimensions, and they are determined by the rank plus the shape.
  • Example: A = [[1,0,3],[0,4,5],[2,0,6]] is 3×3 with row 3 a multiple of row 1, so r = 2, dim C(A) = dim C(Aᵀ) = 2, and dim N(A) = 1 — a basis for it is [−12, −5, 4]. Column space (2) + left null space (1) = 3 = the ambient dimension.
  • Edge cases sanity-check the rule. [[1,1],[2,3]]: the column space is already all of ℝ², so nothing can be orthogonal to it and the left null space must be empty. The 2×2 zeros matrix: the column space is a point (dimension 0), so its complement must be all of ℝ² — the left null space is 2-dimensional, and any independent pair is a basis for it.
  • Full column rank ⟹ empty null space. Full row rank ⟹ empty left null space.
  • These four dimensions belong to the transformation, not to the grid. Re-describe A in any other pair of bases and every entry changes, yet r, n − r and m − r do not — the column space is the map's range space and the null space is its kernel, both defined without reference to coordinates (linear maps & change of basis). Rank–nullity is a theorem about maps that happens to be checkable on matrices.

Back to Ax = b and Ay = 0

  • Does Ax = b have a solution? Exactly when b ∈ C(A). In statistics the same equation is written Xβ = y — design matrix, regression coefficients, observed data — and nearly every linear model in ML is this equation wearing different letters.
  • If not? Solve Ax = b̂ instead, where b̂ is the point of C(A) closest to b. That is the least-squares solution (§14), the backbone of model fitting.
  • How many solutions? The general solution is x = x_particular + (anything in N(A)), because A(x_p + y) = b + 0 = b. So the solution is unique iff the null space is trivial; otherwise there are infinitely many, one for each null-space vector.
  • Why anyone wants a null space: almost nobody studies Ay = 0 for its own sake — they study the shifted version (A − λI)y = 0. Its non-trivial solutions are eigenvectors and λ the eigenvalues (§15). That single equation reappears as PCA, generalized eigendecomposition, the SVD, Fisher's linear discriminant, and the Rayleigh quotient.

Why it matters: Ax = b is solvable iff b lies in the column space; the null space tells you how many solutions (if any) — a non-trivial null space means infinitely many. Everything downstream (inverse, least-squares, PCA) is a statement about these four spaces.
One picture to keep: A splits ℝⁿ into a row space it maps faithfully onto the column space, and a null space it annihilates; and it splits ℝᵐ into the column space it can reach and a left null space it cannot. Rank r is the width of the channel between them.
