Categorical Data & Chi-Square

Everything so far has been about measurements — heights, times, revenues, numbers you can average. This part is about data that are nothing but counts in boxes: how many first-class passengers survived, how many visitors converted, how many emails were spam. There is no mean to take and no standard deviation to compute, because the categories have no arithmetic. What there is instead is a table, and the only question a table can answer is whether the counts inside it are further from what chance would produce than chance can comfortably explain. Part 5 handed over the whole apparatus of that question — null hypothesis, test statistic, null distribution, p-value, type I and type II error — and this page never re-litigates it; it supplies a new statistic, χ², and a new null distribution to read it against. Part 7 handed over something sharper: it showed that a classical test is usually an approximation to an exact one built by enumeration, and it promised that the exact version for a 2 × 2 table would appear here. It does, in §11, and the promise is kept literally — Fisher's exact test is part 7's permutation test with the table's margins held fixed. Around those two tools sits the part of the subject that actually gets people into trouble: reading a table the right way round, finding out which cell caused a significant result, measuring the size of an association rather than its significance, and knowing why an association can point one way in every subgroup and the other way overall.

01 Counts in boxes: what changes when the data are categorical

A categorical variable records which of a fixed set of classes each unit belongs to. Once you have recorded that, the entire data set is a table of counts — the individual records add nothing. That single fact drives everything on this page: the model is a multinomial, the estimate is a set of proportions, the null hypothesis is a statement about those proportions, and the statistic that measures departure from it compares observed counts to expected counts.

the data
A table of counts
A 2 × 4 table of survivors by ticket class; a 1 × 6 table of sweet colours; a 2 × 2 table of converted-or-not by variant. Part 1 classified these as nominal or ordinal; here they become the whole data set.
the model
Multinomial
n independent units, each landing in category j with probability pⱼ. The counts (O₁, …, O_k) are the sufficient statistic — nothing else about the data matters. §03.
the statistic
χ² = Σ (O − E)²/E
One number summarising the whole table: how far the observed counts sit from the counts the null predicts, each squared difference priced by how big a fluctuation that cell can afford. §04.
the reference
The chi-square distribution
An approximation, valid when the expected counts are not too small — §10 measures exactly how valid — with an exact alternative available by enumeration when they are. §11.

02 Reading a two-way table: three sets of percentages, only one of which answers your question

Before any test there is a reading problem. A two-way table of counts supports three different percentage tables — joint, row and column — and they say different things. Choosing the wrong one is not a rounding error; it inverts the sentence you end up writing. The choice is decided by which variable you are treating as explanatory.

The running table

In 1912 a liner sank; of the 2 229 people aboard, 713 survived. Recording two things about each person — survived or died, and ticket class — gives a 2 × 4 table of counts. This is called a contingency table: it shows the survival counts contingent on ticket class.

What "no association" looks like in percentages

This is the whole idea of the page in one line. Two categorical variables are unassociated when the conditional distributions are all the same — when knowing the column tells you nothing about the row.

03 Expected counts: where row × column / n actually comes from

Every test on this page compares an observed table to a table of expected counts — the counts the null hypothesis predicts. The formula for a contingency table, Eᵢⱼ = RᵢCⱼ/n, is usually presented as a rule to memorise. It is a two-line consequence of the null hypothesis plus maximum likelihood, and seeing the derivation is what makes the degrees-of-freedom count in §05 obvious rather than mysterious.

Case 1 — goodness-of-fit, where the null specifies everything

the model: n independent units, each in category j with probability p_j(O₁, …, O_k) ~ Multinomial(n; p₁, …, p_k) with Σ pⱼ = 1 the marginal distribution of any single count is Binomial, and its mean followsOⱼ ~ Binomial(n, pⱼ) E[Oⱼ] = n pⱼ Var(Oⱼ) = n pⱼ(1 − pⱼ) so under a fully specified null there is nothing to estimateEⱼ = n pⱼ⁰ the null hands you every p, so every E is known before you look

Case 2 — a two-way table, where the null specifies only a form

Now the null does not name the probabilities. It says only that the joint factorises, pᵢⱼ = pᵢ. · p.ⱼ, leaving the marginals free. Those have to be estimated from the data, and maximum likelihood says how.

the multinomial log-likelihood over all r·c cells, with the constraint imposedℓ = Σᵢ Σⱼ Oᵢⱼ ln pᵢⱼ = Σᵢ Σⱼ Oᵢⱼ ( ln αᵢ + ln βⱼ ) writing pᵢⱼ = αᵢβⱼ = Σᵢ Rᵢ ln αᵢ + Σⱼ Cⱼ ln βⱼ the sums separate — the row and column parts do not interact two independent multinomial likelihoods, each maximised at its own relative frequencyα̂ᵢ = Rᵢ/n β̂ⱼ = Cⱼ/n so the fitted cell probability, and the expected count, arep̂ᵢⱼ = (Rᵢ/n)(Cⱼ/n) Eᵢⱼ = n p̂ᵢⱼ = Rᵢ Cⱼ / n

Two properties follow immediately and are worth checking on every table you build by hand, because they catch arithmetic slips instantly:

  • The expected table has the same margins as the observed one. Σⱼ Eᵢⱼ = Rᵢ Σⱼ Cⱼ / n = Rᵢ, and likewise down the columns. The fit does not move the marginals at all; it only redistributes mass inside the table. This is why the χ² statistic is a measure of association and carries no information about the marginals.
  • The deviations sum to zero along every row and every column. Since the margins match, Σⱼ (Oᵢⱼ − Eᵢⱼ) = 0 for each i. In a 2 × 2 table this is severe: fix one deviation and the other three are determined, up to sign. That is one degree of freedom, and §05 turns the observation into a general count.

The same formula, reached from the homogeneity side

The two-way derivation above assumed one sample cross-classified two ways. The homogeneity setting is different: c separate samples of fixed sizes C₁, …, C_c, each producing its own distribution over the r row categories, with the null saying those c distributions are identical. Under that null all n observations are draws from one common distribution q₁, …, q_r, so pool them:

pool everything to estimate the one common distributionq̂ᵢ = Rᵢ / n then Eᵢⱼ = Cⱼ · q̂ᵢ = Cⱼ Rᵢ / n the same expression, reached from a different sampling modelEᵢⱼ = Rᵢ Cⱼ / n column totals FIXED by design here; RANDOM in the independence case

This coincidence is the reason §06 and §07 have identical arithmetic and different meanings. It is not luck: both nulls are "the table is the outer product of its margins", arrived at from opposite directions. §07 lays the two designs side by side.

04 The chi-square statistic, and goodness-of-fit worked from end to end

One statistic serves the whole page. It compares each observed count to its expected count, squares the difference so that departures in either direction count against the null, and divides by the expected count so that a discrepancy of 10 in a cell expecting 15 weighs far more than the same discrepancy in a cell expecting 900.

Pearson's statistic — the definition, and the only formula on this page you must memoriseχ² = Σ_all cells (observed − expected)² / expected = Σ (O − E)²/E large values are evidence against the null; the p-value is always the RIGHT tailp = P( χ²_df ≥ χ²_observed ) there is no left-tail version of this test

Why divide by E, and not by anything else

The divisor is not a convention. It is what turns each term into an approximately squared standard normal, which is what makes the sum approximately chi-square.

each count is Binomial, so its variance is known under the nullOⱼ ~ Binomial(n, pⱼ) E[Oⱼ] = npⱼ = Eⱼ Var(Oⱼ) = npⱼ(1 − pⱼ) = Eⱼ(1 − pⱼ) so the properly standardised deviation would be(Oⱼ − Eⱼ) / √(Eⱼ(1 − pⱼ)) ≈ N(0, 1) for large n, by the CLT of part 3 but Pearson's terms drop the (1 − p) factor, and they are individually TOO SMALL(Oⱼ − Eⱼ)² / Eⱼ has expectation exactly (1 − pⱼ), not 1 and yet the SUM comes out exactly right — this is the small miracle of the statisticE[χ²] = Σⱼ (1 − pⱼ) = k − Σⱼ pⱼ = k − 1 which is the degrees of freedom, EXACTLY, for every n

That last line is not asymptotic. For a fully specified multinomial null the expectation of Pearson's statistic is exactly k − 1 at every sample size, however small — a fact worth checking by simulation, and it holds to Monte-Carlo precision at n = 12 with three categories just as it does at n = 410 with six. The cells are individually under-dispersed by (1 − pⱼ), and the negative correlations the multinomial imposes between counts (one cell going up forces another down) supply exactly the missing amount. The single dropped degree of freedom is the constraint Σ Oⱼ = n.

The condition that licenses the test here. The χ² approximation applies if the counts are independent draws from the population of interest. For sweets in a bag that is a claim about the filling machine: if bags are filled by scooping from a well-mixed hopper the assumption is reasonable; if the machine dispenses a fixed number of each colour per bag it is false, and no amount of sample size repairs it. This is part 2's question, not part 5's, and it is prior to every calculation on this page.

Why not just test each colour separately?

You could. A single category's proportion is testable with the one-proportion z test of part 4, §09 — that is what you would use to answer "are there fewer blue sweets than advertised?". The chi-square test is the extension of that z test to all the categories at once, and the extension is not cosmetic: testing six proportions separately at the 5% level gives roughly a 1 − 0.95⁶ = 26.5% chance of at least one false alarm when the mix is exactly as claimed. The omnibus test holds the overall error rate at 5%. §09 returns to this trade-off, because the price of the omnibus test is that a rejection does not tell you which colour is responsible.

05 Degrees of freedom, counted rather than recalled

Both df rules on this page — k − 1 and (r − 1)(c − 1) — come from one recipe: count the free parameters in the alternative, subtract the free parameters in the null. Doing it that way means you never have to remember a rule, and you get the right answer in the cases the rules do not cover.

the recipedf = (number of free parameters under H_A) − (number of free parameters under H₀) equivalently, and more usefully for a tabledf = (number of cells) − 1 − (number of parameters estimated from the data) the −1 is the constraint ΣO = n, which is always there

Goodness-of-fit

counting for the six-colour testunder H_A: a free distribution on k = 6 categories 6 probabilities, minus Σp = 1 → 5 free under H₀: every p is specified 0 free df = 5 − 0 = 5 = k − 1

If the null is a family rather than a fixed distribution — "the counts follow some Poisson", "the counts follow some normal", binned — then estimating each unknown parameter from the data costs one more degree of freedom, giving k − 1 − m for m estimated parameters. This is the case people get wrong: fitting a Poisson rate from the same counts you are testing and then using k − 1 makes the test anti-conservative. The correction is exactly right only when the parameters are estimated by minimising χ² itself or by maximum likelihood on the grouped counts; estimating from the ungrouped data leaves the df somewhere between k − 1 − m and k − 1, which is an awkward but genuine fact rather than an oversight.

A two-way table

counting for an r × c tableunder H_A: a free distribution on rc cells rc − 1 free under H₀: p_ij = αᵢβⱼ, with Σα = 1 and Σβ = 1 (r − 1) + (c − 1) free df = (rc − 1) − (r − 1) − (c − 1) = rc − r − c + 1 = (r − 1)(c − 1) the same count seen combinatorially, which is the version to picturefix any (r − 1) × (c − 1) block of cells; the margins then FORCE every remaining cell 2 × 4 table → 1 × 3 = 3 free cells 2 × 2 table → 1 × 1 = 1 free cell

The combinatorial reading is the one to keep. In a 2 × 2 table with fixed margins there is genuinely one number to choose: pick the top-left count and every other cell is determined by subtraction. That is why df = 1, why the whole table collapses to a single z statistic (§12), and why Fisher's exact test in §11 only has to enumerate over one index.

Degrees of freedom do not depend on n. This surprises people who have just come from Student's t, where df = n − 1. Here df counts categories, not observations. 06 Testing homogeneity: are these several samples drawn from the same distribution?

The goodness-of-fit test compares one sample against a claimed distribution. The homogeneity test compares several samples against each other with no claimed distribution at all: one categorical variable, measured on c separate groups, and a null that says the groups share a single common distribution. It assumes the observations are independent within each sample and across samples.

Concretely: are the colour mixes of milk-chocolate, peanut and caramel sweets the same? Three samples, one categorical variable with six levels, and a 6 × 3 table. Nothing about the common mix is specified — only that it is common.

The running example, and a subtlety about what is random

Return to the ship. Four ticket classes, one categorical outcome, and the question is whether the survival distribution is the same for all four. But there is a wrinkle worth taking seriously, because it is the kind of thing that decides whether a test means anything.

These data are not a sample. They are every person aboard. There is no sampling variability, because nothing was sampled — so where does the "chance" that a p-value quantifies come from? It comes from the event, not the survey. The 325 first-class passengers can be regarded as 325 independent draws from a probability model that assigns each of them some chance of surviving, that chance being determined by the physical process of the night: finding a route out, reaching a boat, being pulled from the water in time. The 285 second-class passengers are draws from a possibly different model. The null hypothesis is that all four models carry the same survival probability. Under that reading the test is meaningful and the arithmetic is unchanged — but the population being generalised to is a hypothetical one ("ships like this one, nights like this one"), not a population the data were drawn from. Part 2, §02 makes the general version of this argument: you must be able to say what the chance process is before a p-value has a referent.

The test, step by step

  1. State the null as a statement about probabilities, not about the table. H₀ : p(survive | First) = p(survive | Second) = p(survive | Third) = p(survive | Crew). The alternative is that at least two of them differ — it is not directional and it does not say which.
  2. Estimate the one common probability by pooling. Under H₀ all 2 229 observations bear on the same number, so p̂ = 713/2229 = 0.319874. Pooling is only legitimate because the null says there is one thing to pool.
  3. Build the expected table. Multiply each column total by p̂ for the survived row, and by 1 − p̂ for the died row. Equivalently, and identically, Eᵢⱼ = RᵢCⱼ/n — the §03 formula.
  4. Check the expected counts before trusting the reference distribution. Here the smallest is 91.16, so §10's concerns do not arise.
  5. Sum the eight terms to get χ², take df = (r − 1)(c − 1) = 3, and read the right tail.
  6. If you reject, do not stop. A rejection says "not all four are equal" and nothing else. §09's residuals say which classes are responsible; §14's odds ratios say by how much.

What the rejection does and does not say

  • It says the four survival probabilities are not all equal. That is the entire content. It does not say first class was safest, though the percentages obviously do; it does not say by how much; it does not rank the classes.

  • Third class and crew have nearly the same survival rate — 25.21% against 23.55% — so a rejection of the four-way null is not a claim that all four differ from each other. §09 finds the cells that carry the signal, and it is overwhelmingly the first-class column.

A third scheme you will also meet Both margins fixed. Rare by design but the natural conditional reference set, and it is what Fisher's exact test in §11 uses. The same statistic again.
Why the arithmetic can be identical when the models are not. All three sampling schemes have the same conditional likelihood given the margins, and the χ² statistic depends on the data only through the table. The three nulls all say the same thing about the interior of the table — that it is the outer product of its margins — and differ only in which margins were random. The statistic cannot see that difference, so it is the same statistic; the interpretation can see it, so the sentence you write is different. This is a genuinely useful robustness property, not a coincidence to be embarrassed about, and it is why one procedure serves three designs.
"The χ² test showed that ticket class caused the difference in survival." The test is silent on causation. It compares an observed table with the table independence predicts. Whether the association reflects a causal path, a common cause, or the selection of who bought which ticket is a question about the design, not the arithmetic — and part 2, §07 is where it is answered. §17 shows an association that reverses completely once a third variable is accounted for, using nothing but four counts per stratum.
The third question this table format also answers, which is neither of the two. If the same units are measured twice — before and after, or by two raters — then the 2 × 2 table's cells are pairs, not individuals, and neither test above applies. The two margins are not independent samples; they are two views of one sample. That design needs McNemar's test, which looks only at the off-diagonal, and §13 shows it giving p = 0.028 where the misapplied independence test gives p = 0.083 on the same data.

  1. Multiply the whole table by a constant. Use the scale slider.   2. Press "make it exactly independent". The table is replaced by its own expected counts (rounded), χ² falls to almost exactly zero, every residual vanishes, and the p-value goes to nearly 1. 10 The expected-count condition, measured rather than asserted — and Yates' correction

Every textbook attaches a condition to this test: all expected counts should be at least 5, or some variant of it. It is worth being precise about what that statement is. It is not a theorem. It is a rule of thumb, proposed as a rough guide, that has been repeated so often it acquired the appearance of a result. The honest thing to do is to measure the actual error rate and report what it does, which is what this section does.

What is actually being approximated

the exact null distribution of the statistic is DISCRETE — a finite list of values with probabilitiesthe table can only take finitely many configurations, so χ² takes finitely many values the reference distribution is CONTINUOUS, and is only its large-sample limitχ²_observed ⟶ χ²_df in distribution, as n ⟶ ∞ with the cell probabilities held fixed so the real type I error is a step function of n, not a smooth approach to 0.05the approximation error is driven by the LATTICE of achievable values, not by min(E) alone

That last line is the point the rule of thumb obscures. Because the statistic can only land on a discrete set of values, the true tail probability jumps as n changes and the achievable values shuffle past the critical value 3.841. The result is that the true level oscillates around the nominal one instead of converging monotonically to it.

What the numbers actually say

  • Pearson's χ² is far better behaved than its reputation. At n₁ = n₂ = 20 with p = 0.10 — smallest expected count 2, a table the rule of thumb forbids outright — the true level is 0.0387. At p = 0.20, smallest expected 4, it is 0.0502, essentially perfect. The test is not "invalid" below 5; it is somewhat off, in a direction that varies.
  • And when it does fail badly at small counts, it fails conservatively, not liberally. The worst row here is n = 10, p = 0.10: true level 0.0090 against a nominal 0.05. That is a test that almost never rejects — a power problem, not a false-positive problem. The common warning that small expected counts make the test "too likely to reject" is, in this design, backwards.
  • Convergence is not monotone and does not finish. Even at n₁ = n₂ = 200 the exact level is 0.0510, and at 50, 50 it is 0.0569 — further from nominal than at 20, 20. The sawtooth is intrinsic: the statistic is discrete and the reference distribution is not.
  • G² is the one to be careful with. The likelihood-ratio statistic is anti-conservative at small expected counts — 0.0874 where 0.05 was asked for, and 0.1094 at n = 5, more than double the nominal rate. If a table is sparse, G² is the wrong choice, and §12 says why.
  • Fisher's exact test is exact but conservative, by construction — its achievable p-values are a discrete set and it can only reject when one of them falls below 0.05. Its level never exceeds 0.05 (that is what "exact" buys), but at n = 10 it is 0.0128 and it is still only 0.0402 at n = 200. §11 returns to this.
So what should the rule be? State it as what it is. A conventional guideline, widely used and reasonably serviceable, is: all expected counts at least 1, and no more than about 20% of cells below 5. It is a guideline because it is a rough summary of behaviour like the table above, not a derived threshold — nothing distinguishes an expected count of 4.9 from one of 5.1. The operationally useful version is different and more honest: when the expected counts are small, compute the exact test as well and compare. That takes one line of code (§11), it removes the question entirely, and when the two agree you have learned that the approximation was fine for your table rather than for tables in general.

  • The correction applies only to 2 × 2 tables. There is no accepted analogue for larger tables, and applying a per-cell half-unit shrinkage to a 3 × 4 table is not a standard procedure.
  • Practical position: if the table is large enough that it does not matter, do not bother; if it is small enough that it does matter, compute Fisher's exact test instead and skip the approximation to it. What to do when the counts really are too small. Four options, in descending order of preference. (1) Compute the exact test — Fisher for 2 × 2, a network algorithm or a permutation approximation for larger tables (§11). (2) Permute: shuffle one variable's labels among the units, recompute χ² on every shuffle, and use the resulting null distribution — this is part 7, §11 applied verbatim, it works for any table shape, and it needs no expected-count condition at all. (3) Collapse categories, but only if the collapsed grouping is meaningful a priori; merging categories after seeing which ones are sparse is a data-dependent choice that invalidates the p-value. (4) Collect more data. What you should not do is run the approximation anyway and add a footnote.

11 Fisher's exact test: a permutation test on a 2 × 2 table

Part 7 promised this section by name, and the promise is literal: Fisher's exact test is part 7's permutation test applied to a 2 × 2 table, with the reference set taken to be all tables having the same margins. Nothing new is being introduced — the same argument, the same enumeration, the same p-value definition. What is new is that the enumeration has a closed form, because a 2 × 2 table with fixed margins has exactly one free number.

The construction, in part 7's language

  1. Fix the units and their outcomes. Twenty-four people, thirteen of whom had a success and eleven of whom did not. Those thirteen successes are a property of the people, not of the groups.
  2. Assume exchangeability under the null. If group membership is irrelevant to the outcome, then the observed labelling is one of the equally likely ways of dealing twelve "group 1" labels among the twenty-four people. That is part 7, §11's assumption verbatim.
  3. Enumerate the reference set. There are C(24, 12) = 2 704 156 labellings. Every one produces a 2 × 2 table, and every one of those tables has row totals 12 and 12 and column totals 13 and 11 — the margins are properties of the units and the design, so shuffling cannot move them.
  4. Collapse to one index. All that distinguishes the resulting tables is the top-left count a. Counting labellings that give a particular a is a combinatorial exercise with an exact answer: the hypergeometric distribution.
  5. Read off the p-value as the total probability of tables at least as extreme as the observed one. No approximation and no reference distribution to look up — the null distribution is the enumeration.

The other genuine argument: should you condition on both margins at all?

  • The case for conditioning. The margins carry no information about the association — they are ancillary. Conditioning on them removes the nuisance parameter (the common success probability) completely, which is what makes the test exact whatever that unknown probability is. No other test on this page has that property.
  • The case against. In most real designs the column margin was not fixed. In the §07 survey both margins were random; conditioning on an observed random quantity discards information, and the resulting test is conservative — §10 measured levels of 0.0128 where 0.05 was requested. That is real power thrown away, and in a small study power is exactly what you do not have to spare.
  • Middle positions exist and are reasonable. The mid-p adjustment recovers most of the lost level while keeping the conditional machinery. Unconditional exact tests, which maximise the p-value over the nuisance parameter rather than conditioning it away, are more powerful still and are what a careful analysis of a small 2 × 2 would use today; they are more expensive to compute and much less widely implemented.
  • The pragmatic summary. Fisher's exact test is never wrong — it will not exceed its nominal level. It is sometimes needlessly timid. Use it when counts are small; report which two-sided convention you used; and if a decision turns on the difference between p = 0.04 and p = 0.10 in a table with twelve observations per group, the honest conclusion is that the study was too small to decide.
Beyond 2 × 2. The same construction — enumerate all tables with the observed margins, weight each by its probability, and sum over those at least as extreme — works for any r × c table. What breaks is the arithmetic: the reference set is no longer indexed by one number and its size explodes. Exact network algorithms handle moderate tables; beyond that, sample the reference set instead of enumerating it, which is precisely part 7, §13's sampled permutation test. Shuffle one variable's labels across the units, recompute χ², repeat, and use (1 + #{χ²* ≥ χ²_obs})/(B + 1). That estimator needs no expected-count condition, works for any table shape, and its only cost is computation.

12 What else this test is: z², the likelihood ratio, and one family containing both

The chi-square test is not a stand-alone invention. For a 2 × 2 table it is the two-proportion z test, squared. For any table it is the large-sample twin of the multinomial likelihood-ratio test. Both facts are worth deriving, because they say what the test is really measuring and they explain the small-sample behaviour §10 measured.

Relationship 1 — for a 2 × 2 table, χ² = z² exactly

Not approximately, not asymptotically: algebraically, to machine precision, for every table.

Verified on four tables spanning three orders of magnitude in n, the two agree to within 7 × 10⁻¹⁵ — floating-point noise, not a discrepancy. On §07's survey: z = 3.050831, z² = 9.307568 = χ². On first-versus-third class from the ship: χ² = 130.4994, z = 11.4236.

  • Consequence 1: the 2 × 2 chi-square test is inherently two-sided. Squaring throws the sign away. If you have a directional alternative — "the new variant converts better" — use the z test with a one-sided p-value, or Fisher's one-sided test. Halving the chi-square p-value is the same thing, but only for a 2 × 2 and only if you also check the direction.
  • Consequence 2: √(χ²/n) is a natural effect size. That is the phi coefficient φ, and it is exactly the Pearson correlation between the two variables coded as 0/1. §07's table has φ = 0.1364, which is what a highly significant p = 0.0023 looks like when it is turned into a correlation: small. The generalisation to larger tables is Cramér's V = √(χ²/(n·min(r−1, c−1))).
  • Consequence 3: everything part 4, §09 says about a proportion applies here — including that the pooled standard error is right for testing and the unpooled one is right for an interval, which is why a 95% interval for p₁ − p₂ can just barely include zero while the test rejects.

14 How big is it? Risk difference, relative risk, and the odds ratio

A p-value says an association exists. Three numbers say how large it is, and they are not interchangeable — they can be pushed in different directions by the same data, they behave differently under changes of design, and only one of them survives a case-control study. All three come from the same four counts.

the notation, fixed once: rows are the exposure or treatment, column 1 is the outcome outcome no outcome | total exposed a b | a + b p₁ = a/(a + b) unexposed c d | c + d p₀ = c/(c + d) risk difference — the absolute scale, and the one that determines how many people are affectedRD = p₁ − p₀ range (−1, 1); no association ⟺ RD = 0 relative risk (risk ratio) — the multiplicative scale on PROBABILITIESRR = p₁ / p₀ range (0, ∞); no association ⟺ RR = 1 odds, and the odds ratio — the multiplicative scale on ODDSodds(p) = p/(1 − p) OR = [p₁/(1 − p₁)] / [p₀/(1 − p₀)] = ad/bc range (0, ∞); no association ⟺ OR = 1 number needed to treat — the risk difference inverted, for when the outcome is desirableNNT = 1/|RD| "treat this many to produce one extra good outcome"

The cross-product form OR = ad/bc is worth memorising, because it makes the odds ratio's defining property visible at a glance: it is symmetric in the two variables. The odds ratio of the outcome given exposure equals the odds ratio of exposure given the outcome. Neither the risk difference nor the relative risk has that property, and it is the whole reason §16 exists.

  • Add ½ to every cell, not just the empty one. Adding it only where needed introduces a bias that depends on which cell happened to be empty, which is worse than the problem being solved.
  • It is a real bias–variance trade, not a hack. The ½ is the correction that makes the estimator of ln OR approximately median-unbiased for a 2 × 2 table, and it is equivalent to a weak prior.   • Report the exact test alongside it. The correction fixes the estimate; it does not make the interval trustworthy at these counts. Fisher's exact test gives a p-value that needs no correction at all, and an exact conditional interval for the odds ratio exists too.
  • For the test, prefer Fisher; for the estimate, prefer the correction; and be explicit that you used it. A reported odds ratio of 0.036 from a table containing a zero is meaningless without the note that a continuity correction produced it.

17 Simpson's paradox: every subgroup one way, the total the other

A treatment can beat a control in every subgroup and lose in the pooled table. This is not a rounding artefact, a small-sample effect, or a paradox in any logical sense — it is ordinary arithmetic about weighted averages, and it happens in real data often enough that pooling a table without asking what was pooled is a genuine hazard. This section owns the contingency-table version; part 2, §07 owns the causal machinery that resolves it.

The mechanism, which is entirely about the weights

a pooled rate is a weighted average of stratum rates — with weights set by ALLOCATIONp̂(recover | treated) = Σ_s p̂(recover | treated, s) · w_s^treated where w_s^treated = (treated units in stratum s)/(all treated units) the two arms have DIFFERENT weight vectors, and that is the whole paradoxtreated: severe 300/400 = 0.75 mild 100/400 = 0.25 control: severe 100/400 = 0.25 mild 300/400 = 0.75 so the comparison mixes two things that cannot be separated by poolingtreated: 0.75 × 0.70 + 0.25 × 0.90 = 0.525 + 0.225 = 0.750 control: 0.25 × 0.60 + 0.75 × 0.85 = 0.150 + 0.6375 = 0.7875 reweight the control arm to the treated arm's mix and the reversal disappearscontrol at the treated mix: 0.75 × 0.60 + 0.25 × 0.85 = 0.450 + 0.2125 = 0.6625 0.750 vs 0.6625 — the treatment wins by 8.75 points, between its two stratum-specific gains

Three quarters of the treated patients were severe and only a quarter of the controls were. Severe patients recover less often whatever you do. So the treated arm is dragged down by its composition and the control arm is flattered by its own — and the pooled comparison measures the composition difference as much as the treatment.

  • No reversal is possible if the allocation is balanced. Make the weights identical across arms and the pooled difference is a weighted average of the stratum differences, hence between the smallest and the largest of them. A randomised experiment balances the weights in expectation, which is precisely why part 2, §08 insists on randomisation. Simpson's paradox is a symptom of confounded allocation, not an independent phenomenon.
  • The direction of the drag is set by two things at once: the stratum must affect the outcome (severe patients do worse) and it must be associated with the arm (severe patients were preferentially treated). Break either link and the reversal is impossible. Those two conditions are the definition of a confounder.
  • Which table should you act on? Here, the stratified one — because severity was a cause of both the treatment decision and the outcome, so it is a confounder and must be conditioned on. But that is a causal judgement about the world, not something the counts can supply. If the third variable were instead a consequence of the treatment — a side effect, say — then conditioning on it would be exactly the wrong move and the pooled table would be the right one. There is no way to choose from the numbers alone. Part 2, §07 develops this, including the collider case where adjustment actively creates bias.
  • The three-line version. A reversal in the observed conditional probabilities is possible because the two arms average over different mixes. A reversal in the causal quantities is impossible, because those average over the same mix — the population's. Part 2 gives that argument in full.
Slide the allocation and break the aggregate conclusion — while both strata hold firm the within-stratum rates never move; only who gets which treatment does

Failure 2 — ordinal categories thrown away by a nominal test

The χ² test is invariant to permuting rows and columns. Shuffle the four ticket classes into any order and the statistic is unchanged. That invariance is exactly right for nominal categories and it is a waste when the categories are ordered: the test spends its degrees of freedom on alternatives no one believes in, and it ignores the monotone pattern it should be looking for.

  • The decomposition is the real prize. Splitting χ²(df 2) = z²(df 1) + departure(df 1) says that essentially all of the association is a monotone decline in survival with class number, with nothing left over. That is a much stronger scientific statement than "the classes differ".
  • The scores are a modelling choice. Equally spaced scores 1, 2, 3 are conventional and usually adequate; midpoint scores or ridit scores are alternatives. What you may not do is try several and report the best, which is part 5, §13's problem again.
  • Both variables ordinal? Then a correlation-style statistic is available — the linear-by-linear association test, which is (n − 1)r² with r the correlation of the scores. Again one degree of freedom, again far more power against a monotone alternative.

Failure 3 — structural zeros and impossible cells

  • A sampling zero is a cell that could have been non-empty and happened not to be. The test handles those: χ² is defined, G² uses the convention 0 ln 0 = 0, and the only consequence is that the approximation degrades (§10).
  • A structural zero is a cell that cannot exist — patients who never received a treatment cannot have its side effect; a survey branch that was never shown cannot have answers. Running the ordinary test on such a table is wrong, because the null hypothesis of independence predicts a non-zero expected count for a cell the world forbids, and the difference is charged to the statistic as evidence of association.
  • The fix is a quasi-independence model: fit the independence structure to the admissible cells only, by iterative proportional fitting, and reduce the degrees of freedom by one for each excluded cell. For an r × c table with k structural zeros, df = (r − 1)(c − 1) − k, provided the remaining pattern is connected.
  • A zero margin is different again and is fatal. If an entire row or column is empty then some expected count is zero and the statistic is undefined. The category was not observed; drop it and reduce the table's dimensions, remembering that df falls accordingly.

Failure 4 — dependent observations

  • The multinomial model assumes each unit is counted once and independently. Every violation inflates χ², because clustering makes the counts more variable than a multinomial allows while the denominator E stays the same.
  • The commonest form is repeated units. Counting sessions when the unit of randomisation was users is the classic A/B-testing version; a user with forty sessions contributes forty highly correlated observations. The design effect can easily be 3 or 4, meaning the true variance is three or four times the assumed one and the nominal 5% test is really operating at 15% or more.
  • The second commonest is paired data analysed as unpaired, which §13 covers and which goes in the opposite direction — it usually loses power rather than manufacturing significance.
  • Fixes: aggregate to the independent unit (one row per user); use a cluster-robust or survey-weighted test; or permute at the cluster level, which is part 7, §12's exchangeability argument applied at the right granularity.

Failure 5 — testing many tables, or many cells, and reporting the winner

  • Cross-tabulating an outcome against twenty candidate variables and reporting the significant ones is a 20-test family. At α = 0.05, the chance of at least one false positive under complete independence is 1 − 0.95²⁰ = 64%. §09 measured the within-table version: in a 5 × 5 table with no association at all, some cell exceeds 1.96 two thirds of the time.
  • Feature screening by χ² is exactly this procedure with the reporting automated, and it inherits the problem in full. §19 says what to do about it.
  • Corrections and their costs. Bonferroni is safe and blunt; false-discovery-rate control is the right tool when you are screening rather than confirming; and the cleanest fix of all is pre-registration of which tables you intended to look at.
  • The specific trap for tables: collapsing categories after seeing the data. Merging sparse categories is legitimate if the grouping was decided in advance and is substantively meaningful. Merging the categories that happened to be sparse, or splitting at the point that maximises the statistic, is a search whose result the null distribution knows nothing about.
Beyond the test: what modelling adds. Everything on this page is a test plus a couple of summary numbers. The modelling generalisation is the log-linear model, which writes ln E[Oᵢⱼ] = μ + αᵢ + βⱼ + (αβ)ᵢⱼ and treats independence as the hypothesis that the interaction terms vanish. It buys three things a test cannot: it extends to three-way and higher tables where "independence" splits into several distinct hypotheses (mutual, joint, conditional); it lets nested models be compared by differences of G² (§12); and it produces interpretable parameters instead of a single verdict. For a binary outcome it is the same fitted object as logistic regression, seen from the other side. Not covered in this series; worth knowing it exists as soon as a table has three dimensions.

19 The ML translation: where every one of these tools already lives in your stack

Nothing on this page is a statistics-only technique. Every tool has a machine-learning name, and in most cases the machine-learning version is the same arithmetic with the derivation removed.

On this pageIn machine learningWhat the translation buys
2 × 2 contingency table (§07) The confusion matrix — model evaluation, §02. Rows are true class, columns are predicted class, and TP/FP/FN/TN are a, b, c, d. Precision and recall are conditional distributions of §02 read in the two different directions: recall is a column percentage, precision is a row percentage. The eternal confusion between them is §02's row-versus-column question. A χ² test on a confusion matrix asks whether the classifier is better than one that ignores the input — usually not the question, but the same table.
Odds ratio (§14) Logistic regression coefficients — logistic regression. e^β for a binary predictor is exactly ad/bc. Fitting a logistic model to a 2 × 2 table reproduces §15's estimate and standard error exactly. Going the other way, a table gives you an interpretable check on a coefficient. Remember §17: an adjusted coefficient is a conditional odds ratio and will not match the table's marginal one even with no confounding.
G² = 2n·Î(X;Y) (§12) Information gain, the split criterion in a decision tree. Every candidate split evaluates a contingency table of feature-value against label, and the entropy-based gain is the likelihood-ratio statistic divided by 2n. This explains a known bias directly: high-cardinality features produce tables with more columns and therefore more degrees of freedom, so they look better by chance — which is exactly §18's multiplicity failure and exactly why gain ratio and similar corrections exist.
χ² feature screening (§18) SelectKBest with a chi-square score, and every "top correlated features" table. It tests each feature against the label separately, so it inherits every problem on this page: it is blind to interactions, it favours high-cardinality features, its p-values are uncorrected across hundreds of tests, and with a large n everything is significant. Use the statistic as a ranking if you must, never the p-values as evidence, and validate the selection inside cross-validation rather than before it.
McNemar's test (§13) Comparing two models on the same test set — model evaluation, §09. This is the correct test and it is very widely got wrong. The pairs are examples, and the only informative counts are the disagreements: examples model A got right and B got wrong, and vice versa. Comparing two accuracies with a two-proportion test discards the pairing and is the §13 error verbatim. Part 7, §13's paired permutation test is the resampling equivalent.
Homogeneity across groups (§06) Fairness auditing and drift detection. "Does the model's positive rate differ across groups?" is a homogeneity test on a 2 × k table, and demographic parity is its null hypothesis. "Has the input distribution shifted since training?" is a goodness-of-fit test of this month's category counts against the training distribution — with §18's warning attached in neon, because production n is enormous and every drift is significant. Track φ or a distance, not the p-value.
Fisher's exact test (§11) Small-sample evaluation: rare-class subgroups, red-team results, human-annotation batches. Whenever a comparison rests on a handful of examples — 12 failures out of 200 in one subgroup against 4 out of 200 in another — the approximation is exactly where §10 says it should not be trusted, and the exact test costs one function call.
Simpson's paradox (§17) A/B test segment analysis — A/B testing, §08. The classic production version: an experiment ramped mid-flight, so the arms have different mixes of early and late traffic, and the aggregate lift contradicts every segment. Randomisation prevents it; a broken or changing split reintroduces it. The diagnosis is always the same — check whether the arms have the same composition.
Expected counts and sparsity (§10) Rare-category handling in preprocessing. The same instinct that groups categories with fewer than k occurrences into "other" before one-hot encoding is §10's advice about small expected counts — and it carries the same warning, that the grouping must be decided from the training data alone, never from the outcome.
The one-line summary of this section. A contingency table is what you get whenever two categorical things are compared, and that describes a very large fraction of applied machine-learning evaluation. The statistical apparatus — expected counts, residuals, exact tests, effect sizes, the multiplicity discipline — transfers unchanged, and it is usually more careful than what the evaluation script is doing.

20 Practice

The checklist, before you report anything from a table

  1. Say what a row is. One person, one session, one pair, one impression? If units appear more than once, the test is invalid before it starts (§18, failure 4).
  2. Say which margin was fixed by the design. That decides whether you are testing homogeneity or independence (§07), and whether you are allowed a relative risk (§16).
  3. Percentage in the direction the explanatory variable dictates, and write the sentence out. If the sentence is about composition rather than rate, you have percentaged the wrong way (§02).
  4. Compute the expected counts and look at the smallest. If it is small, compute the exact test too and compare rather than consulting a threshold (§10, §11).
  5. Report the statistic, the df, and the p-value together. χ²(3) = 192.34, p < 0.001 — never a bare p-value, because df is what makes it interpretable.
  6. Report an effect size next to it, always. φ, Cramér's V, a risk difference, or an odds ratio with an interval. A p-value without one is not a finding (§18).
  7. If you reject, look at the adjusted residuals to find the cells responsible, and correct the threshold for how many cells you looked at (§09).
  8. Ask what you did not stratify by. If a plausible third variable is associated with both, the pooled table may be telling you the opposite of the truth (§17).
  9. Say what you were entitled to conclude. Association, not causation, unless the design was randomised (§07).

Worked problems

  1. A die is rolled 120 times and shows each face 15, 25, 18, 22, 19, 21 times. Is it fair? Every expected count is 20. χ² = (25 + 25 + 4 + 4 + 1 + 1)/20 = 60/20 = 3.00 on df = 5, and χ²₅,₀.₉₅ = 11.07, so p = 0.700. No evidence of unfairness. Note the statistic is below its mean of 5 — the die is fitting the null slightly better than a fair die typically would.
  2. A 2 × 2 table has a = 30, b = 20, c = 20, d = 30. Give χ², φ, the odds ratio and its interval. χ² = 100(30·30 − 20·20)²/(50·50·50·50) = 100 × 250000/6250000 = 4.000, p = 0.0455. φ = √(4/100) = 0.20. OR = 900/400 = 2.25; ln OR = 0.81093, SE = √(1/30 + 1/20 + 1/20 + 1/30) = √0.166667 = 0.408248, so the 95% interval for OR is (e^0.01077, e^1.61109) = (1.011, 5.008) — it excludes 1, but only just, which is the same "only just" as p = 0.0455.
  3. The same table with every count multiplied by 4. χ² = 16.000, p = 6.3 × 10⁻⁵, φ = 0.20 unchanged, OR = 2.25 unchanged, and the interval narrows to (1.508, 3.357). The association is identical; only the precision improved. This is §18 in four numbers.
  4. A 2 × 2 table is [[10, 2], [3, 9]]. Should you use χ² or Fisher? Margins 12, 12, 13, 11; expected counts 6.5, 5.5, 6.5, 5.5, so the guideline is satisfied. χ² = 8.2238 gives p = 0.00413; Fisher's exact test gives p = 0.01228. They agree in verdict at 5% but differ threefold in p-value. With twelve observations per group, report the exact one.
  5. Why is the expected count for a cell always row × column / n, in one sentence? Because under independence the fitted cell probability is the product of the fitted marginal probabilities, (Rᵢ/n)(Cⱼ/n), and the expected count is n times that.
  6. A 4 × 5 table gives χ² = 26.1. Significant? df = 3 × 4 = 12, χ²₁₂,₀.₉₅ = 21.03, so yes at 5% — but the statistic is only 2.2 times its mean of 12, so this is a moderate result, not an overwhelming one. p = 0.0104.
  7. You compute a risk ratio of 1.2 and an odds ratio of 1.9 on the same table. Is one of them wrong? Neither. OR = RR(1 − p₀)/(1 − p₁), so a gap that size means the outcome is common. Solving 1.9/1.2 = 1.5833 = (1 − p₀)/(1 − 1.2p₀) gives p₀ = 0.648 and p₁ = 0.778 — an outcome occurring in nearly two thirds of the unexposed. The odds ratio is technically correct and rhetorically misleading; report the risk ratio.
  8. An A/B test on 400 000 users gives χ² = 12.5, p = 0.0004. Should you ship? φ = √(12.5/400000) = 0.0056. Converting: with equal arms and a 5% pooled rate, that is a 4.88% versus 5.12% conversion difference. The test is correct and the effect is almost certainly not worth the shipping risk. Compute the absolute lift and its interval before deciding — the A/B testing page is where that decision belongs.
  9. Two classifiers on 1 000 test examples: A is right on 870, B on 850. A significant difference? Not answerable from those numbers. You need the paired counts: examples where A is right and B wrong (b) and the reverse (c), with b − c = 20. If b = 60, c = 40, McNemar gives χ² = 400/100 = 4.00, p = 0.0455. If b = 25, c = 5, it gives χ² = 400/30 = 13.33, p = 0.00026. Same accuracies, wildly different evidence — because the second case has the models agreeing far more often, so the disagreements are more decisive. §13.
  10. A 2 × 2 table has a zero cell: [[0, 15], [6, 9]]. Report something defensible. The odds ratio is 0 with infinite standard error, so no Wald interval exists. Fisher's exact test gives p = 0.0169. With the Haldane–Anscombe correction OR = (0.5 × 9.5)/(15.5 × 6.5) = 0.04715 and SE = 1.52434, giving a 95% interval of (0.00238, 0.93535) — which excludes 1, agreeing with the exact test. Report the exact p-value, the corrected estimate, and the fact that a correction was used.
  11. A table has expected counts 3.2, 4.1, 12.7 and 15.0. Do you run the test? Two of four cells are below 5, which breaches the common guideline. Run Fisher's exact test as well; if the two agree, report either and say so; if they disagree, report the exact one. Do not refuse to analyse the data, and do not run the approximation with a footnote.
  12. Why does the trend test give a smaller p-value than the omnibus test on the same data? Because it spends one degree of freedom instead of c − 1, and it concentrates the alternative on monotone departures. On the three-class table: 130.60 on 1 df beats 131.08 on 2 df, 3.0 × 10⁻³⁰ against 3.4 × 10⁻²⁹. Choosing a narrower alternative buys power when the alternative is right — and loses it when it is wrong, which is why the scores must be chosen before looking.
  13. You add a strong, perfectly balanced covariate to a logistic model and the treatment odds ratio rises from 1.8 to 2.3. Is the unadjusted estimate confounded? No. Balanced means it cannot be a confounder. This is non-collapsibility (§17): 1.8 is the marginal odds ratio and 2.3 the conditional one, and both are correct estimates of different parameters. A risk-difference model would have shown no movement.
  14. In a 3 × 4 table you find one adjusted residual of 2.4. Report it? With 12 cells, the Bonferroni threshold at 5% is Φ⁻¹(1 − 0.025/12) = 2.87, so 2.4 does not clear it. Measured by simulation, the chance that some cell of a null 3 × 4 table exceeds 1.96 is 0.368. Describe the pattern; do not report the cell as a finding.

Where this goes next. Part 9, ANOVA & Multiple Comparisons asks this page's homogeneity question about a numeric outcome: several groups, one measurement each, and a null that they share a common mean. The statistic is an F rather than a χ², and the family relationship is exact — an F is a ratio of two independent chi-squares divided by their degrees of freedom, so §04's additivity is what makes the whole decomposition of variance possible. Two threads carry straight over. First, the multiplicity problem: §09 measured a two-thirds chance of some cell exceeding 1.96 in a null 5 × 5 table, and part 9's pairwise comparisons after a significant F are the same failure with group means in place of cells — which is why that part is called multiple comparisons and spends half its length on the correction. Second, the exact alternative: part 7 owes part 9 a permutation F, obtained by shuffling the group labels and recomputing F on every shuffle, and it stands to the tabulated F exactly as §11's Fisher's exact test stands to the χ² approximation here. The pattern this page and part 7 have now established twice — the classical test is the large-sample approximation to an enumeration — holds there too.
