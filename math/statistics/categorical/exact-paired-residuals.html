09 Which cell did it? Standardised and adjusted residuals

A significant χ² tells you the table is not what independence predicts. It does not tell you where. The answer is in the residuals — exactly as in part 6, §15, where a good R² tells you nothing until you have looked at the residual plot. The counts version has one extra subtlety: the obvious residual is not the one to use.

Three residuals, in increasing order of correctness

the raw residual — has the units of a count, so it is not comparable across cellsO − E a shortfall of 20 means nothing until you know if E was 25 or 2500 the Pearson (standardised) residual — the signed square root of the cell's contributionr = (O − E)/√E and Σ r² = χ² exactly, over the whole table the adjusted (standardised) residual — the one that is approximately N(0, 1)a = (O − E) / √( E · (1 − Rᵢ/n) · (1 − Cⱼ/n) ) for a two-way table a = (O − E) / √( E · (1 − p) ) for goodness-of-fit with p specified

The correction factor is not cosmetic. The Pearson residual has the right numerator and the wrong denominator: √E would be the standard deviation of O if O were Poisson with mean E, but O is a multinomial count constrained by margins that were themselves estimated from the data. The true variance is smaller, and by exactly the factor (1 − Rᵢ/n)(1 − Cⱼ/n). Divide by √E and every residual comes out too small — sometimes dramatically.

the derivation of the correction, for a two-way table under the fitted nullVar(Oᵢⱼ − Eᵢⱼ) ≈ n p̂ᵢ.p̂.ⱼ (1 − p̂ᵢ.)(1 − p̂.ⱼ) = Eᵢⱼ (1 − Rᵢ/n)(1 − Cⱼ/n) worked for the ship's first-class survivor cell: R = 713, C = 325, n = 2229, E = 103.9592Pearson r = (202 − 103.9592)/√103.9592 = 98.0408/10.1960 = 9.616 factors (1 − 713/2229) = 0.680126 (1 − 325/2229) = 0.854195 adjusted a = 98.0408 / √(103.9592 × 0.680126 × 0.854195) = 98.0408/7.7717 = 12.615 the correction is 31% here — the Pearson residual UNDERSTATES the departure badly

  • The Pearson residuals tell the same story with the volume turned down and the rows no longer mirroring, which is why they are misleading for exactly the comparison you want to make. An identity for 2 × 2 tables that is worth knowing. In a 2 × 2 table all four adjusted residuals have the same magnitude, and that magnitude squared is the chi-square statistic — so it is also the two-proportion z of §12. For §07's survey table: all four adjusted residuals are ±3.0508, and 3.0508² = 9.3076 = χ². There is one degree of freedom, so there is one number; the residual analysis of a 2 × 2 table is the test itself and cannot tell you anything new. Residuals earn their keep from 2 × 3 upwards.

The multiplicity problem the residuals create

Reading residuals against ±1.96 is a hypothesis test per cell, and a table has a lot of cells. The omnibus χ² holds the family-wise error rate at 5% by construction; scanning residuals does not, and the gap widens fast.

  • In a 5 × 5 table with no association whatsoever, two thirds of the time some cell exceeds 1.96. Reporting that cell as "the driver" is part 5, §13's problem in its purest form.
  • The cheap fix is Bonferroni: compare each adjusted residual against Φ⁻¹(1 − 0.025/rc). For the ship's eight cells that is 2.734 rather than 1.96, and all eight cells clear it — the association there is not subtle. For a 5 × 5 table it becomes 3.090.
  • Look at residuals only after the omnibus test rejects, and treat them as description rather than as a second round of testing. This is the standard protected-testing discipline and part 9 will formalise it for group comparisons.
  • Residual patterns are more informative than individual residuals, and are not a multiplicity problem at all. A monotone run of residuals across an ordered variable — as here, +12.6, +3.6, −4.7 for First, Second, Third — is a trend, and §18 shows how to test one properly with a single degree of freedom instead of scanning cells.

10 The expected-count condition, measured rather than asserted — and Yates' correction

Every textbook attaches a condition to this test: all expected counts should be at least 5, or some variant of it. It is worth being precise about what that statement is. It is not a theorem. It is a rule of thumb, proposed as a rough guide, that has been repeated so often it acquired the appearance of a result. The honest thing to do is to measure the actual error rate and report what it does, which is what this section does.

What is actually being approximated

the exact null distribution of the statistic is DISCRETE — a finite list of values with probabilitiesthe table can only take finitely many configurations, so χ² takes finitely many values the reference distribution is CONTINUOUS, and is only its large-sample limitχ²_observed ⟶ χ²_df in distribution, as n ⟶ ∞ with the cell probabilities held fixed so the real type I error is a step function of n, not a smooth approach to 0.05the approximation error is driven by the LATTICE of achievable values, not by min(E) alone

That last line is the point the rule of thumb obscures. Because the statistic can only land on a discrete set of values, the true tail probability jumps as n changes and the achievable values shuffle past the critical value 3.841. The result is that the true level oscillates around the nominal one instead of converging monotonically to it.

Under that model the exact null distribution of every test is computable by summing over all (n₁ + 1)(n₂ + 1) outcomes with their binomial weights. No simulation error at all: these are exact numbers, not estimates.

What the numbers actually say

  • Pearson's χ² is far better behaved than its reputation. At n₁ = n₂ = 20 with p = 0.10 — smallest expected count 2, a table the rule of thumb forbids outright — the true level is 0.0387. At p = 0.20, smallest expected 4, it is 0.0502, essentially perfect. The test is not "invalid" below 5; it is somewhat off, in a direction that varies.
  • And when it does fail badly at small counts, it fails conservatively, not liberally. The worst row here is n = 10, p = 0.10: true level 0.0090 against a nominal 0.05. That is a test that almost never rejects — a power problem, not a false-positive problem. The common warning that small expected counts make the test "too likely to reject" is, in this design, backwards.
  • Convergence is not monotone and does not finish. Even at n₁ = n₂ = 200 the exact level is 0.0510, and at 50, 50 it is 0.0569 — further from nominal than at 20, 20. The sawtooth is intrinsic: the statistic is discrete and the reference distribution is not.
  • G² is the one to be careful with. The likelihood-ratio statistic is anti-conservative at small expected counts — 0.0874 where 0.05 was asked for, and 0.1094 at n = 5, more than double the nominal rate. If a table is sparse, G² is the wrong choice, and §12 says why.
  • Fisher's exact test is exact but conservative, by construction — its achievable p-values are a discrete set and it can only reject when one of them falls below 0.05. Its level never exceeds 0.05 (that is what "exact" buys), but at n = 10 it is 0.0128 and it is still only 0.0402 at n = 200. §11 returns to this.
So what should the rule be? State it as what it is. A conventional guideline, widely used and reasonably serviceable, is: all expected counts at least 1, and no more than about 20% of cells below 5. It is a guideline because it is a rough summary of behaviour like the table above, not a derived threshold — nothing distinguishes an expected count of 4.9 from one of 5.1. The operationally useful version is different and more honest: when the expected counts are small, compute the exact test as well and compare. That takes one line of code (§11), it removes the question entirely, and when the two agree you have learned that the approximation was fine for your table rather than for tables in general.

Yates' continuity correction, and why it is contested

The classical patch for a 2 × 2 table is to shrink each absolute deviation by ½ before squaring, on the reasoning that a discrete distribution is being approximated by a continuous one and the half-integer boundary is the right place to cut.

Yates' corrected statistic — 2 × 2 tables only, and it always makes the statistic smallerχ²_Yates = Σ ( |O − E| − 0.5 )² / E with the bracket floored at 0 on the §07 survey table, where every |O − E| = 17uncorrected: χ² = 9.3076, p = 0.002282 corrected: 8.7681, p = 0.003065 on the small table of §08, where it changes the verdicttable [[9, 3], [4, 8]]: uncorrected 4.1958, p = 0.0405 corrected 2.6853, p = 0.1013 Fisher's exact test on the same table gives p = 0.0995 — almost exactly the corrected value

That last coincidence is the key to the whole controversy, and the exact levels above make it unmistakable. Read down the Yates and Fisher columns: 0.0128 / 0.0128, 0.0076 / 0.0076, 0.0011 / 0.0011, 0.0274 / 0.0274, 0.0352 / 0.0352, 0.0402 / 0.0402. Yates' correction is not a general-purpose improvement to the chi-square approximation — it is an approximation to Fisher's exact test, and it therefore inherits Fisher's conservatism exactly.

  • Whether that is a virtue depends on which null distribution you think is right, which is the same argument as §11's conditional-versus-unconditional debate. If you accept conditioning on both margins, Yates is a cheap route to the right answer. If you do not, Yates costs you real power for no benefit.
  • What is not in dispute is that Yates is conservative in the unconditional setting. At n₁ = n₂ = 20, p = 0.5, the corrected test rejects 1.75% of the time when 5% was asked for — it throws away roughly two thirds of its allowance. That directly costs power.
  • The correction applies only to 2 × 2 tables. There is no accepted analogue for larger tables, and applying a per-cell half-unit shrinkage to a 3 × 4 table is not a standard procedure.
  • Practical position: if the table is large enough that it does not matter, do not bother; if it is small enough that it does matter, compute Fisher's exact test instead and skip the approximation to it. Many statistical packages apply Yates by default to 2 × 2 tables — check, because the same data can produce two different p-values from two tools that both call themselves "the chi-square test".
The true type I error rate of four tests, computed exactly, as the sample size grows the sawtooth is real — the statistic is discrete and the reference distribution is not
What to do when the counts really are too small. Four options, in descending order of preference. (1) Compute the exact test — Fisher for 2 × 2, a network algorithm or a permutation approximation for larger tables (§11). (2) Permute: shuffle one variable's labels among the units, recompute χ² on every shuffle, and use the resulting null distribution — this is part 7, §11 applied verbatim, it works for any table shape, and it needs no expected-count condition at all. (3) Collapse categories, but only if the collapsed grouping is meaningful a priori; merging categories after seeing which ones are sparse is a data-dependent choice that invalidates the p-value. (4) Collect more data. What you should not do is run the approximation anyway and add a footnote.

11 Fisher's exact test: a permutation test on a 2 × 2 table

Part 7 promised this section by name, and the promise is literal: Fisher's exact test is part 7's permutation test applied to a 2 × 2 table, with the reference set taken to be all tables having the same margins. Nothing new is being introduced — the same argument, the same enumeration, the same p-value definition. What is new is that the enumeration has a closed form, because a 2 × 2 table with fixed margins has exactly one free number.

The construction, in part 7's language

  1. Fix the units and their outcomes. Twenty-four people, thirteen of whom had a success and eleven of whom did not. Those thirteen successes are a property of the people, not of the groups.
  2. Assume exchangeability under the null. If group membership is irrelevant to the outcome, then the observed labelling is one of the equally likely ways of dealing twelve "group 1" labels among the twenty-four people. That is part 7, §11's assumption verbatim.
  3. Enumerate the reference set. There are C(24, 12) = 2 704 156 labellings. Every one produces a 2 × 2 table, and every one of those tables has row totals 12 and 12 and column totals 13 and 11 — the margins are properties of the units and the design, so shuffling cannot move them.
  4. Collapse to one index. All that distinguishes the resulting tables is the top-left count a. Counting labellings that give a particular a is a combinatorial exercise with an exact answer: the hypergeometric distribution.
  5. Read off the p-value as the total probability of tables at least as extreme as the observed one. No approximation and no reference distribution to look up — the null distribution is the enumeration.
the reference set has one free cell; write the table with row totals R1, R2 and column totals C1, C2 col 1 col 2 | total a determines b = R₁ − a, c = C₁ − a, row 1 a b | R₁ d = R₂ − C₁ + a — every other cell row 2 c d | R₂ total C₁ C₂ | n counting the labellings that produce a given a — choose which successes go to row 1P(a) = C(C₁, a) · C(C₂, R₁ − a) / C(n, R₁) the hypergeometric pmf equivalently, and more symmetrically, in terms of all four marginsP(a) = R₁! The factorial form is the one every textbook prints and the one nobody should implement. 170! already overflows a double; a table with a few hundred observations makes every factorial in that expression infinite and their ratio a NaN. The right implementation sums log-binomial coefficients built from the log-gamma function and exponentiates once at the end — which is what the shared numeric library on this page does, and what makes the figure below work for margins in the thousands as easily as for margins of twelve.

"Two-sided" is genuinely ambiguous here, and you must say which you used

For a symmetric continuous null, doubling a tail and collecting everything at least as extreme are the same operation. The hypergeometric null is discrete and generally asymmetric, so they are not. There are three conventions in circulation.

ConventionDefinitionOn [[3, 7], [12, 4]]Comment
Point probability
used on this page		 Sum P(a) over all tables with P(a) ≤ P(observed). 0.042617 The default in most software. Treats "extreme" as "improbable", which is the likelihood-ordering, and it is the natural reading of "at least as extreme".

Note the consequence in that middle column: 0.0426 and 0.0634 straddle the 5% line on the same table. Reporting "Fisher's exact test, p = ..." without naming the convention is not enough information to reproduce the number. This page uses the point-probability convention throughout, because it is what almost all software returns by default and because it is the direct analogue of part 7's "count the shuffles at least as extreme".

The other genuine argument: should you condition on both margins at all?

  • The case for conditioning. The margins carry no information about the association — they are ancillary. Conditioning on them removes the nuisance parameter (the common success probability) completely, which is what makes the test exact whatever that unknown probability is. No other test on this page has that property.
  • The case against. In most real designs the column margin was not fixed. In the §07 survey both margins were random; conditioning on an observed random quantity discards information, and the resulting test is conservative — §10 measured levels of 0.0128 where 0.05 was requested. That is real power thrown away, and in a small study power is exactly what you do not have to spare.
  • Middle positions exist and are reasonable. The mid-p adjustment recovers most of the lost level while keeping the conditional machinery. Unconditional exact tests, which maximise the p-value over the nuisance parameter rather than conditioning it away, are more powerful still and are what a careful analysis of a small 2 × 2 would use today; they are more expensive to compute and much less widely implemented.
  • The pragmatic summary. Fisher's exact test is never wrong — it will not exceed its nominal level. It is sometimes needlessly timid. Use it when counts are small; report which two-sided convention you used; and if a decision turns on the difference between p = 0.04 and p = 0.10 in a table with twelve observations per group, the honest conclusion is that the study was too small to decide.
Beyond 2 × 2. The same construction — enumerate all tables with the observed margins, weight each by its probability, and sum over those at least as extreme — works for any r × c table. What breaks is the arithmetic: the reference set is no longer indexed by one number and its size explodes. Exact network algorithms handle moderate tables; beyond that, sample the reference set instead of enumerating it, which is precisely part 7, §13's sampled permutation test. Shuffle one variable's labels across the units, recompute χ², repeat, and use (1 + #{χ²* ≥ χ²_obs})/(B + 1). That estimator needs no expected-count condition, works for any table shape, and its only cost is computation.

When it matters, in one line

the practical rule, stated as a comparison rather than a thresholdmin(E) large → χ², G² and Fisher all agree; use whichever is convenient min(E) small → they disagree, and the disagreement is the information so: compute both. If they agree, report either. If they differ, the table is too small for the approximation and the exact answer is the one to report.

12 What else this test is: z², the likelihood ratio, and one family containing both

The chi-square test is not a stand-alone invention. For a 2 × 2 table it is the two-proportion z test, squared. For any table it is the large-sample twin of the multinomial likelihood-ratio test. Both facts are worth deriving, because they say what the test is really measuring and they explain the small-sample behaviour §10 measured.

Relationship 1 — for a 2 × 2 table, χ² = z² exactly

Not approximately, not asymptotically: algebraically, to machine precision, for every table.

write the table with rows as groups and column 1 as "success"group 1: a successes out of n₁ = a + b p̂₁ = a/n₁ group 2: c successes out of n₂ = c + d p̂₂ = c/n₂ pooled: p̂ = (a + c)/n the pooled two-proportion z test of part 5z = (p̂₁ − p̂₂) / √( p̂(1 − p̂)(1/n₁ + 1/n₂) ) the chi-square statistic, in the closed form every 2 × 2 table admitsχ² = n (ad − bc)² / ( (a+b)(c+d)(a+c)(b+d) ) = n (ad − bc)² / (R₁R₂C₁C₂) and the identity, which falls out because every deviation in a 2 × 2 is the same numberO₁₁ − E₁₁ = a − R₁C₁/n = (ad − bc)/n and the other three are ±(ad − bc)/n so χ² = ((ad − bc)/n)² · (1/E₁₁ + 1/E₁₂ + 1/E₂₁ + 1/E₂₂) = n(ad − bc)²/(R₁R₂C₁C₂) = z²

Verified on four tables spanning three orders of magnitude in n, the two agree to within 7 × 10⁻¹⁵ — floating-point noise, not a discrepancy. On §07's survey: z = 3.050831, z² = 9.307568 = χ². On first-versus-third class from the ship: χ² = 130.4994, z = 11.4236.

  • Consequence 1: the 2 × 2 chi-square test is inherently two-sided. Squaring throws the sign away. If you have a directional alternative — "the new variant converts better" — use the z test with a one-sided p-value, or Fisher's one-sided test. Halving the chi-square p-value is the same thing, but only for a 2 × 2 and only if you also check the direction.
  • Consequence 2: √(χ²/n) is a natural effect size. That is the phi coefficient φ, and it is exactly the Pearson correlation between the two variables coded as 0/1. §07's table has φ = 0.1364, which is what a highly significant p = 0.0023 looks like when it is turned into a correlation: small. The generalisation to larger tables is Cramér's V = √(χ²/(n·min(r−1, c−1))).
  • Consequence 3: everything part 4, §09 says about a proportion applies here — including that the pooled standard error is right for testing and the unpooled one is right for an interval, which is why a 95% interval for p₁ − p₂ can just barely include zero while the test rejects.

Prefer Pearson's χ² for sparse tables. This inverts a common expectation, since the likelihood ratio is the more "principled" construction; principle is about the limit, and the limit is what is missing.
  • G² earns its place in model building, not in single tests. Its decisive advantage is additivity: for nested log-linear models the difference of two G² values is itself a likelihood-ratio statistic with the difference in degrees of freedom, so a table's association can be partitioned into interpretable components. Pearson's statistic has no such property. That is why every log-linear modelling framework reports G².
  • G² is the same quantity as information gain. G² = 2n · Î(X; Y) in nats, where Î is the mutual information of the empirical joint distribution. The split criterion in a decision tree and the test statistic in a contingency table are the same formula — §19 makes the connection concrete.
  • Zero counts need care in G² and none in χ². O ln(O/E) is taken as 0 when O = 0, which is the correct limit, but a zero expected count makes both statistics undefined and signals a structural problem rather than a numerical one (§18).

The practical content of that family is short: the choice of statistic is a second-order question, the choice between approximate and exact is a first-order one. When the counts are ample every member agrees; when they are sparse the difference between members is smaller than the difference between all of them and the exact test.

13 Paired binary data: McNemar's test, and the mistake it prevents

A 2 × 2 table can be built from two very different designs, and they look identical on the page. If the four counts are four groups of people, §07's test applies. If they are one group of people measured twice, it does not — and using it anyway is one of the most frequently repeated errors in applied statistics.

The construction

Label the paired table so that a counts pairs positive both times, d pairs negative both times, b pairs positive first and negative second, and c the reverse. The two marginal rates are (a + b)/n and (a + c)/n; they are equal exactly when b = c. The concordant pairs a and d cancel out of the comparison entirely.

The gap between p = 0.028 and p = 0.083 is the entire value of the paired design, and it is the same phenomenon as the paired versus two-sample t test of part 5, §10: pairing removes person-to-person variation from the comparison, and analysing paired data as if it were unpaired throws that reduction away. The 70 concordant pairs tell you the question is stable; they say nothing about whether the intervention moved anyone, and so they are correctly excluded.

  • The direction of the error is not fixed. Here the paired test is more powerful, which is the usual case with positively correlated measurements. If the two measurements were negatively associated the unpaired test could be the more significant one — but it would still be answering a question about a design that was not run.
  • Use the exact binomial version when the discordant count is small. With b + c < 25 or so the normal approximation to a binomial on m trials is doing real work; the exact version costs nothing. At b = 12, c = 4: χ² = 4.0000 gives p = 0.0455 and the exact test gives p = 0.0768 — opposite verdicts at the 5% line.
  • What McNemar tests is marginal homogeneity, not agreement. A table with b = c = 40 and a = d = 10 passes McNemar comfortably, and the two measurements agree only 20% of the time. Agreement is a different question with a different measure (Cohen's κ), and confusing them is common.
  • The generalisation to more than two categories is Stuart–Maxwell for marginal homogeneity and Bowker's test for symmetry of the whole table. Both reduce to McNemar when there are two categories.
  • Where this bites in practice. Comparing two classifiers on the same test set is a paired design — each example is a pair (model A right/wrong, model B right/wrong) — so the correct test is McNemar on the two disagreement counts, not a two-proportion test on the two accuracies. So is a before/after A/B test on the same users, and any interleaving experiment. §19 and the A/B testing page both need this.
