Hypothesis Testing

Part 4 answered "how far off is my number likely to be?" with an interval. This part answers a narrower question — is this particular value still on the table? — and answers it with a single number that almost everybody misreads. The machinery is small: assume the boring explanation, compute how surprising the data would be under it, and reject only if the surprise clears a bar you fixed before you looked. The difficulty is entirely in the interpretation, so a fifth of this page is spent on what a p-value is not, with the arithmetic that proves each misreading wrong.

01 The logic: proof by contradiction, with a probabilistic contradiction

A significance test is one argument, reused everywhere. You are not asked to believe the boring explanation; you are asked to assume it, work out what the world would look like if it were true, and check whether the world you actually got is one it could plausibly have produced. If it is not, you discard the assumption. That is all. Everything else on this page — the tables, the Greek letters, the tests with names — is bookkeeping for that one move.

The move, in five lines

the argument1. Assume H₀: "nothing extraordinary is going on". 2. Under that assumption, derive the distribution of some summary T of the data. 3. Compute the observed value t of T. 4. Ask: how probable is a value of T at least as extreme as t, IF H₀ holds? → the p-value. 5. If that probability is below a threshold fixed IN ADVANCE, discard H₀.

Why it is not quite proof by contradiction

Classical modus tollens is airtight: if H implies D, and D is false, then H is false. A significance test is the probabilistic imitation of that, and the imitation leaks.

the airtight versionH ⟹ D not D ──────── not H the version a test actually usesH₀ makes D very improbable D happened ──────── H₀ is doubtful and this is INVALID as deduction — the standard counterexampleH₀: this person is a member of parliament. D: this person is the Prime Minister. P(D | H₀) ≈ 1/650 — very small. Observe D. Conclude "H₀ is doubtful"? D actually IMPLIES H₀.

So the test's conclusion is not a deduction; it is a decision rule with a controlled long-run error rate. That reframing is the whole contribution of the Neyman–Pearson school (§11): stop pretending the p-value measures how false H₀ is, and instead build a rule whose probability of wrongly rejecting a true H₀ is a number you chose. The rule can be justified even though the underlying inference cannot.

Why the counterexample bites, and when it does not. The Prime Minister case fails because "improbable" was computed for a single arbitrary outcome, not for a tail ordered by how much it favours an alternative. A real test compares H₀ against a specific alternative and calls "extreme" only those outcomes the alternative makes more likely. That is exactly what the Neyman–Pearson lemma formalises, and it is the reason a well-chosen test statistic is not an arbitrary choice.

Failing to reject is not evidence for the null

This is the single most consequential asymmetry in the subject, and it survives no amount of repetition. A large p-value has two completely different causes and the test cannot tell them apart:

cause 1
H₀ really is true
There is no effect, the data look like noise because they are noise, and the p-value is a draw from a uniform distribution that happened to land high.
cause 2
There is an effect and the test could not see it
The sample was too small, the measurement too noisy, or the effect too subtle. The test had low power (§07). "Not significant" here means "not measured", not "not there".
the two claims, in symbols — the second does not follow from the firstobserved: P(data at least this extreme | H₀) = 0.31 ← a large p-value NOT shown: P(H₀ | data) is large ← a different conditional what a non-rejection actually licenses"θ₀ is among the values still compatible with these data" — and so are many others. the honest report is the interval, which names the whole compatible set"the effect is between −0.4 and +2.9" says far more than "p = 0.31".
  • If you want to argue for a null, you need a different tool. Report a confidence interval and show it is tight around zero — an interval of (−0.02, +0.03) on a scale where anything under 0.5 is uninteresting is a genuine argument that the effect is negligible. That is an equivalence test: reverse the burden of proof by making "the effect is bigger than Δ" the null, and reject that. Two one-sided tests at level α against ±Δ is the standard construction.
  • "We found no significant difference" is a statement about the study, not the world. Two studies of the same effect, one with n = 20 and one with n = 2000, will routinely disagree on significance while agreeing perfectly on the estimate.
  • A test is designed to be conservative in one direction only. The framework spends all its protection on avoiding false rejections and leaves false retentions uncontrolled — the type II rate is whatever it happens to be, and nobody ever reports it. §07 and §08 are about paying that debt.
The one-sentence version. A significance test does not tell you whether the null is true. It tells you whether the data would have been surprising if it were — and "surprising" is measured on a scale you fixed before you looked, so that the rate at which you are fooled is a number you own rather than a number you discover.

02 The two hypotheses: choosing them, and where the burden of proof sits

A test needs two statements about the parameter that between them cover every possibility. Which one you call the null is not a technical detail — it decides which mistake the machinery protects you against, and therefore what the result means. Get this backwards and every number afterwards is answering a question you did not ask.

The formal setup

partition the parameter space into two disjoint piecesΘ = Θ₀ ∪ Θ₁, Θ₀ ∩ Θ₁ = ∅ H₀: θ ∈ Θ₀ versus H₁: θ ∈ Θ₁ simple vs composite — a hypothesis that pins the distribution down completely is SIMPLEsimple: H₀: θ = θ₀ one distribution, so P(anything | H₀) is a number composite: H₀: θ ≤ θ₀ a family, so error rates are taken as a supremum over it the test itself is a REJECTION REGION: a set of data outcomesR ⊂ 𝒳, reject H₀ ⟺ observed data ∈ R, usually R = { x : T(x) > c }

Almost every test in practice has Θ₀ a single point (or a half-line whose boundary point is the worst case), and almost every rejection region is "the test statistic is too big". The generality above matters for one thing: it is what makes the error-rate definitions in §07 unambiguous when H₀ is not a single distribution.

Four rules for choosing the null

rule 1
The null is the boring explanation
No effect, no difference, no association, the coin is fair, the drug does nothing, the new model is no better. "Nothing extraordinary is going on."
rule 2
The null is the one you can compute with
"p = ½" gives a distribution; "p ≠ ½" does not. The null must be specific enough to generate a reference distribution — that is why it gets the equals sign.
rule 3
The null is the status quo you would keep
The default action if the evidence is inconclusive. Rejecting it is what triggers a change: ship the model, approve the drug, publish the claim.
rule 4
The alternative is what you hope to establish
The burden of proof is on it. Which means: if being wrong in favour of a claim is the expensive mistake, that claim belongs in H₁.
The asymmetry is a choice about which error you fear. A regulator testing a new drug puts "the drug is unsafe" nowhere near the null — the null is "no benefit", because falsely approving an ineffective drug is the error the system is built to prevent. Reverse the roles and you get a different, equally coherent procedure with a different guarantee. Nothing in the mathematics tells you which to pick; the cost of the two mistakes does.

One-sided or two-sided

two-sided (the default, and the honest default)H₀: θ = θ₀ H₁: θ ≠ θ₀ reject for large |T| p = P( |T| ≥ |t| | H₀ ) for a symmetric null distribution, = 2·P(T ≥ |t|) one-sidedH₀: θ ≤ θ₀ H₁: θ > θ₀ reject for large T only p = P( T ≥ t | θ = θ₀ ) the boundary point is the worst case, so the sup is attained there the exchange rate, for a symmetric null distributionp₍two-sided₎ = 2 × p₍one-sided₎ whenever t falls on the side H₁ points to the one-sided critical value is SMALLER: z₀.₀₅ = 1.64485 vs z₀.₀₂₅ = 1.95996
  • A one-sided test is more powerful against the alternative it names, and blind to the other direction. That is the trade, and it is a real one: at α = 0.05 the one-sided test needs only 1.645 standard errors instead of 1.960, which is roughly the power of an extra 12% of sample. But if the effect goes the other way — the new model is worse — a one-sided test cannot detect it at any sample size. It will simply return a large p-value forever.
  • Use one-sided only when the other direction would trigger the same action as no effect. The genuine case: you will keep the incumbent unless the challenger beats it, and "the challenger is worse" and "the challenger is the same" lead to the identical decision. Then the other tail carries no information you would act on.
  • Report which you used. A p-value with no side attached is ambiguous by a factor of two, which is exactly the factor that separates 0.03 from 0.06.

The dishonesty of picking the side afterwards

Suppose you run a two-sided test, get p = 0.08, notice the effect is positive, and rewrite the alternative as H₁: θ > θ₀ so that the p-value halves to 0.04. This is not a re-analysis; it is a different procedure, and its actual type I error is not 5%.

the procedure you actually ran, stated honestly"reject if the one-sided p-value in WHICHEVER direction the data went is below 0.05" its true type I error, for a symmetric continuous null distributionP(reject | H₀) = P(T > z₀.₀₅) + P(T < −z₀.₀₅) = 0.05 + 0.05 = 0.10 so the label is wrong by a factor of twoadvertised α = 0.05 actual α = 0.10

The two-sided test is the correct accounting for "I did not know which way it would go". Choosing the side after seeing the direction is the smallest possible instance of the p-hacking family in §13 — one binary decision made after looking — and it already doubles the error rate. Larger versions of the same move do far worse.

The test to apply to yourself. Before the data arrive, write down the alternative and the level. If you cannot state which direction you would have called significant before you saw the sign of the effect, you do not have a one-sided test — you have a two-sided test with a mislabelled p-value.

03 The test statistic, its null distribution, and the region that rejects

Everything computable in a test comes from one object: a number summarising the data, whose distribution you know exactly on the assumption that the null is true. Call it the test statistic; call that distribution the null distribution. Where the observed value falls in it is the entire evidence, and the two ways of reading that position — a fixed cut-off, or a tail area — are the critical value and the p-value.

The recipe, and the one form almost every statistic takes

a test statistic measures the distance from what H₀ predicts, in units of the noiseT = (observed − expected under H₀) / SE the two standard instancesz = (estimate − θ₀) / SE SE known or from a large sample → z ~ Normal(0,1) under H₀ t = (estimate − θ₀) / SÊ SE estimated from the data → t ~ t(ν) under H₀ why the division matters — it makes the statistic UNIT-FREE and its null distribution UNIVERSALa 3-gram difference and a 3-metre difference are the same evidence if both are 2 SE. this is the same object as part 4's pivot, with θ replaced by a specific θ₀pivot (x̄ − μ)/(s/√n) — μ unknown, used to build an interval statistic (x̄ − μ₀)/(s/√n) — μ₀ named by H₀, used to build a test

The last two lines are the whole of §09 in miniature. A pivot with the parameter left free rearranges into an interval; the same pivot with the parameter pinned to a hypothesised value becomes a test statistic. The interval and the test are two readings of one calculation, and part 4's §06 pivot construction is where the calculation was set up.

The five steps, once, in full

  1. State H₀ and H₁, and fix α. Before the data. All three.
  2. Choose T, and derive its distribution under H₀. This is the only step that needs mathematics; §11 says where the choice comes from.
  3. Fix the rejection region R = {T ≥ c} (or |T| ≥ c) by solving P(T ∈ R | H₀) = α for the critical value c.
  4. Compute t from the data.
  5. Report. Either "t ∈ R, reject at level α", or the p-value, or — best — the estimate with a confidence interval and the p-value beside it.

A first test, computed to the end

A coin is tossed ten times and comes up tails seven times. Is it biased? The count of tails is a sum of ten 0/1 labels, so under H₀: P(tails) = ½ its mean is 5 and its standard deviation is √(10 × ½ × ½) = 1.58114.

the normal approximationz = (7 − 5)/1.58114 = 1.26491 two-sided p = 2(1 − Φ(1.26491)) = 0.2059 the EXACT answer, from the binomial itselfP(X ≥ 7) = (120 + 45 + 10 + 1)/1024 = 176/1024 = 0.171875 two-sided (by symmetry) = 2 × 0.171875 = 0.34375 the approximation was off by 40% — because n = 10 and the count is an INTEGERwith a continuity correction, z = (6.5 − 5)/1.58114 = 0.94868 two-sided p = 2(1 − Φ(0.94868)) = 0.34278 vs exact 0.34375 ✓

Either way the conclusion is the same — seven tails in ten is entirely unremarkable — but the discrepancy is worth keeping. The normal approximation to a discrete count is a continuous curve being asked about a step function, and at small n it systematically understates the tail unless you shift the boundary by half a unit. Part 3, §10 derives the approximation and its error; the rule of thumb there — np₀ ≥ 10 and n(1−p₀) ≥ 10 — is exactly the condition under which you may skip the correction. Here np₀ = 5, so you may not.

The general lesson, which will recur. The test statistic's null distribution is a model, and the p-value inherits every error in that model. A z statistic whose reference curve is wrong by 40% produces a p-value that is wrong by 40%, and nothing downstream can detect it. §10 lists, for each named test, the assumption whose failure does this.

04 The p-value, defined three ways and computed once

Three definitions, all standard, all equivalent, and each illuminating something the others hide. Learn all three: the tail-area one is how you compute it, the smallest-α one is what it means, and the uniform-distribution one is why the whole scheme controls the error rate at all.

Definition 1 — the tail area under the null

for a simple null and a statistic where large values argue against H₀p = P₍H₀₎( T ≥ t_obs ) t_obs = the value computed from YOUR data for a composite null, take the worst case over itp = sup₍θ ∈ Θ₀₎ Pθ( T ≥ t_obs ) two-sided, symmetric null distributionp = P₍H₀₎( |T| ≥ |t_obs| ) = 2·P₍H₀₎( T ≥ |t_obs| ) in words, and every clause is load-bearing"the probability, IF the null were true, of a result AT LEAST AS EXTREME as the one observed."
  • "If the null were true" — the probability is computed inside a hypothetical world. It is a conditional probability with the null in the condition, which is precisely why it is not a probability about the null (§05).
  • "At least as extreme" — not "equal to". For a continuous statistic, P(T = t) = 0 for every t, so the point probability is useless and a tail is the only thing available. This also means the p-value depends on results you did not get, which is a genuine philosophical oddity and the main Bayesian objection to the whole apparatus.
  • "Extreme" means "in the direction the alternative points", and that direction is set by H₁, not by the data. This is the formal statement of §02's warning.

Definition 2 — the smallest level at which you would have rejected

suppose you have a size-α test for every α, with rejection region Rαp = inf { α : t_obs ∈ Rα } because the regions are nested — a bigger α means a bigger regionα < α′ ⟹ Rα ⊂ Rα′ so there is a single crossing point, and p is it the decision rule, restated — this is the only thing a p-value is USED forreject at level α ⟺ p ≤ α

This is the definition to carry around. It says the p-value is a summary of the whole family of tests at once: instead of reporting a verdict at your level, you report the level at which the verdict would flip, and every reader can apply their own threshold. That is also the honest answer to "why report the p-value rather than reject/retain" — the older name for it, observed significance level, says exactly this.

Definition 3 — the transformation that makes the null distribution uniform

if T is continuous, then under H₀ the p-value is a Uniform(0,1) random variableP = 1 − F₀(T) with F₀ the null cdf of T ⟹ P ~ Uniform(0, 1) under H₀ the proof is one line — the probability integral transformP(P ≤ u) = P(1 − F₀(T) ≤ u) = P(F₀(T) ≥ 1 − u) = P(T ≥ F₀⁻¹(1−u)) = u and THIS is why the level is honouredP(reject | H₀) = P(P ≤ α) = α exactly, for every α under an alternative, the same P is squashed towards zeroP(P ≤ α | H₁) = power ≥ α, and → 1 as the effect or n grows
Read the uniformity result twice, because it explains almost everything downstream. If the null is true, p = 0.03 is exactly as likely as p = 0.53 — one time in a hundred you will see p < 0.01 from pure noise, by construction. It is also why a p-value carries no information about effect size: the transform destroyed the scale. And it is why running k tests under true nulls produces small p-values at a predictable rate — 1 − (1−α)ᵏ — which is the arithmetic behind §13 and part 9.

A worked p-value, with the exact answer beside the approximate one

Ten cups are filled at random with one of two colas; a taster names seven correctly. Can they tell them apart? The claim is directional — a taster who is guessing scores 5, one who can tell scores more — so H₀: p = ½ against H₁: p > ½, one-sided.

the normal approximation, as usually taughtz = (7 − 5)/1.58114 = 1.26491 p = 1 − Φ(1.26491) = 0.1029 the exact binomial p-valuep = P(X ≥ 7 | X ~ Binomial(10, ½)) = 176/1024 = 0.17188 with the continuity correctionz = (6.5 − 5)/1.58114 = 0.94868 p = 1 − Φ(0.94868) = 0.17139 ✓ the verdict is the same at any conventional level0.172 > 0.05 → do not reject. Seven out of ten is not evidence of a discriminating palate.

Note the size of the error in the uncorrected version: 0.103 against a true 0.172, an understatement by 40%. Had the taster scored eight, the exact one-sided p would be 56/1024 = 0.0547 and the uncorrected normal approximation would give 0.0289 — on opposite sides of 0.05. A test whose conclusion depends on which approximation you used is a test you should be computing exactly. With n = 10 you can, and should.

Two conventions worth adopting. Never write p = 0.000 — write p < 0.001, because the computed value is a tail area of a model you do not believe out to six decimal places. And never call a result "marginally significant", "approaching significance", or "trending towards significance": these are all descriptions of a p-value that failed to clear the bar you set, dressed up as a partial success. If the threshold was worth setting, it was worth respecting; if it was not, do not set one and report the interval instead.

05 Seven things a p-value is not, each with the arithmetic

This is the section the page exists for. Every misreading below appears in published work, in textbooks, and in the sentence most readers would have written before opening this page. Each one is answered here not with an assertion but with a calculation whose answer differs from the misreading's, usually by a large factor. The single most useful instrument is the base-rate calculation of §06 — but the others are worth having separately, because they fail for different reasons.

the one true statement, to hold beside all sevenp = P( data at least this extreme | H₀ true ) the conditional runs THIS way. Reversing it is the source of five of the seven errorsP(data | H₀) ≠ P(H₀ | data)
✗ 1. "p = 0.03, so there is a 3% probability that the null hypothesis is true."
This reverses the conditional. P(D | H₀) and P(H₀ | D) are related by Bayes' rule, and the relation involves a term the p-value does not contain: the prior probability that H₀ is true.
what the p-value isp = P(D | H₀) what the misreading claims it isP(H₀ | D) = P(D | H₀)·P(H₀) / [ P(D | H₀)·P(H₀) + P(D | H₁)·P(H₁) ] the two are equal only if the bracketed correction happens to be 1 — it never isP(H₀ | D) = p ⟺ P(H₀)·(1 − p) = P(D | H₁)·P(H₁) an accident, not an identity
The concrete failure. Screen 1 000 candidate genes of which 100 really matter. At α = 0.05 and 80% power you get 80 true and 45 false rejections. Take any one of those 125 "significant" genes: the probability its null is true is 45/125 = 36%, not 5% and not 3%. Change the prior to 1 in 100 and the same p-value carries a 86% chance that the null is true. The p-value did not move; the answer changed by a factor of 24. ✓ Say instead: "if there were no effect, data this extreme would arise 3% of the time."
✗ 2. "p = 0.03, so there is only a 3% chance the result is due to chance."
The same error in folk dress, and the more dangerous one because it sounds like plain English rather than statistics. "Due to chance" means "the null is true", so this is misreading 1 with the conditional hidden inside an idiom. Note also that the p-value was computed assuming chance is the whole story: it is a number produced inside the very hypothesis it is being used to assign a probability to. ✓ Say instead: "chance alone produces a result this extreme 3% of the time."
✗ 3. "p = 0.03, so there is a 97% probability the alternative is true" — or "the effect will replicate 97% of the time."
Two separate errors stacked. The first is 1 − p read as a posterior, which fails for the reason above. The second is a claim about replication, and it is checkable.
take the observed effect AS IF it were the truth, and rerun at the same nreplication power = Φ(|z| − z₍1−α/2₎) + Φ(−|z| − z₍1−α/2₎) at p = 0.05 exactly, so |z| = 1.95996= Φ(0) + Φ(−3.91993) = 0.5000 + 0.00004 = 0.5000 the general picture — and these are the OPTIMISTIC figures, since they assume the estimate is exactoriginal p = 0.05 → replication succeeds 50.0% of the time original p = 0.01 → 73.1% original p = 0.001 → 90.8%
A result that just clears 0.05 is, on the most generous possible assumption, a coin flip to replicate. And the assumption is not generous in practice, because the original estimate was selected for being large (§13, the winner's curse), so the true replication rate is lower still. ✓ Say instead: nothing about replication — the p-value contains no information about it.
✗ 4. "p = 0.001 means the effect is much bigger than one with p = 0.04."
The p-value confounds effect size with sample size and precision, and by construction it cannot be decomposed back into them. Two studies with identical p-values can have effect sizes differing by any factor you like; two studies with identical effect sizes can have p-values differing by any factor you like.
the identity that makes the confusion inevitablez = effect / SE = (effect/σ) × √n so p depends on n as much as on the effect two studies of the same drug, both with σ = 10 mmHg — same p-value, effect sizes 100× apartstudy A: effect 2.00 mmHg, n = 100 SE = 1.00 → z = 2.00, p = 0.0455 study B: effect 0.02 mmHg, n = 1 000 000 SE = 0.01 → z = 2.00, p = 0.0455 and the reverse — one fixed effect of 0.20 mmHg, p-values 10 000× apartn = 400 SE = 0.500 → z = 0.400, p = 0.689 n = 10 000 SE = 0.100 → z = 2.000, p = 0.0455 n = 40 000 SE = 0.050 → z = 4.000, p = 0.0000633
Study A found a 2 mmHg drop, which is worth a prescription; study B found 0.02 mmHg, which is invisible to any patient and to any instrument. Their p-values are the same to three decimals. ✓ Say instead: report the effect and its interval, and let the p-value do only the job it can do.
✗ 5. "Study A got p = 0.02 and study B got p = 0.20, so study A found a much stronger effect."
Not comparable across studies with different n, for exactly the reason above. Worse, this comparison is routinely used to declare that two studies disagree, and that inference is invalid even when the two estimates are nearly identical. The difference between "significant" and "not significant" is not itself significant.
two studies, both estimating the same effect, both with SE = 10study A: estimate 25, SE 10 → z = 2.50, p = 0.0124 "significant" study B: estimate 10, SE 10 → z = 1.00, p = 0.3173 "not significant" now test whether the two studies actually differdifference = 25 − 10 = 15 SE of difference = √(10² + 10²) = 14.142 z = 15/14.142 = 1.0607 p = 0.2888 NOT significant
The two studies are entirely compatible with each other. The headline "A replicated, B failed to replicate" describes an artefact of two arbitrary threshold crossings. ✓ Say instead: test the difference directly, or better, pool them.
✗ 6. "p = 0.35, so we can conclude there is no effect" — or "the two groups are equivalent".

The professional consensus, compressed

In 2016 the American Statistical Association issued a formal statement on p-values — an unusual step for a professional body — because the misreadings above had become endemic. Its six principles are worth reproducing because they are, in effect, the summary of this section:

  1. p-values can indicate how incompatible the data are with a specified statistical model.
  2. p-values do not measure the probability that the studied hypothesis is true, or the probability that the data were produced by random chance alone.
  3. Scientific conclusions and business or policy decisions should not be based only on whether a p-value passes a specific threshold.
  4. Proper inference requires full reporting and transparency.
  5. A p-value, or statistical significance, does not measure the size of an effect or the importance of a result.
  6. By itself, a p-value does not provide a good measure of evidence regarding a model or hypothesis.
Principle 1 is quietly the sharpest. Note what it says the p-value is incompatible with: not "the null hypothesis" but "a specified statistical model". The model includes the null and independence, and the sampling scheme, and the absence of measurement bias, and the fact that you did not look at the data first. A small p-value indicts the whole package. Very often the weakest member of that package is not the null hypothesis at all.

06 The base-rate calculation: why most "significant" results can be false

Of everything in §05, this is the argument that changes how people read a p-value permanently, because it is arithmetic rather than admonition. A test's advertised error rate is P(significant | null true). What a reader wants is P(null true | significant). The two differ by the base rate of real effects in whatever population of hypotheses you are drawing from — and in most research settings that base rate is low enough to flip the answer.

The trade-off, made visible

The two error rates are pushed in opposite directions by the same lever. Move the critical value out and you reject less often: fewer false positives, more false negatives. There is no setting that makes both small; the only thing that shrinks both at once is more data, which narrows both curves.

Why the asymmetry is deliberate

controlled exactly
Type I, at rate α
Because H₀ is a specific distribution, the probability of rejecting under it is computable, and the critical value is chosen to make it come out at α. This works for every n, without knowing the effect size.
not controlled at all
Type II, at whatever rate
H₁ is a family, so β depends on which alternative is true — a number you do not know. You cannot set β in advance without first committing to an effect size you care about. Almost nobody does, which is why so many studies are underpowered.
  • The framework is built to protect the status quo. Its guarantee is "I will not overturn a true null more than 100α% of the time". It offers no guarantee at all about missing real effects. If your costs run the other way — a missed detection is catastrophic, a false alarm is cheap — the standard machinery is protecting the wrong thing, and you should either swap the hypotheses or raise α deliberately.
  • Screening tests get this right and hypothesis tests usually do not. A medical screen is tuned for high sensitivity (power) and tolerates false positives, because the follow-up test is cheap and the missed cancer is not. That is a conscious choice of α and β against costs; a study run at "α = 0.05, power = whatever" is the same choice made by default.
  • The four cells are the confusion matrix. Type I error is 1 − specificity; power is sensitivity, also called recall; PPV from §06 is precision; the prior π is prevalence. Moving the critical value traces out a curve of (false-positive rate, true-positive rate) pairs — which is the ROC curve, exactly. A significance test is one operating point on it, chosen by fixing the false-positive rate at α.
The dictionary, worth memorising once. α = type I rate = false positive rate = 1 − specificity = the significance level = the size. 1 − β = power = sensitivity = recall = the true positive rate. PPV = precision = 1 − FDR. Statistics, medicine and machine learning each named these independently, and the only thing that differs between the three vocabularies is which quantity is treated as the headline.

08 Power: what drives it, how to plan for it, and why post-hoc power is empty

Power is the probability the study will succeed if the effect you are looking for is really there. It is the only design quantity that connects "how much data should I collect?" to "what would I consider worth finding?", and it is the one number that is systematically not computed. Four things move it, three of which you control.

The four levers

everything enters power through ONE combination — the noncentralityΔ = δ√n / σ power = Φ(Δ − z₍1−α/2₎) + Φ(−Δ − z₍1−α/2₎) so the four levers are1. effect size δ bigger effects are easier power ↑ with δ (not yours to choose) 2. sample size n power ↑ with √n yours, and expensive 3. noise σ power ↑ as σ falls yours, via measurement and design 4. level α power ↑ with α yours, but it buys power with false positives note the √n. 09 The duality: a confidence interval is the set of nulls you would not reject

Part 4's interval and this part's test are not two methods that happen to agree. They are one computation read in two directions, and the equivalence is an identity, not an empirical fact. Once you see it, the argument for reporting the interval instead of the p-value becomes hard to resist: the interval answers the test's question for every null value at once, and carries an effect size while doing it.

11 Where the machinery comes from: Neyman–Pearson and the likelihood ratio

§03 said "choose a test statistic" as if it were a matter of taste. It is not. For the cleanest possible testing problem there is a provably optimal statistic, the answer is the likelihood ratio, and every named test in §10 is that answer specialised. This section is the theory that makes the rest of the page non-arbitrary.

The optimality question, posed properly

among all tests with size at most α, which has the largest power?maximise β(θ₁) = Pθ₁(reject) subject to β(θ₀) = Pθ₀(reject) ≤ α a test achieving this is MOST POWERFUL at θ₁; if the SAME test does it for every θ₁ in Θ₁ it is UNIFORMLY most powerful (UMP)UMP tests exist for one-sided problems in nice families, and often NOT otherwise.

The Neyman–Pearson lemma

setting: both hypotheses SIMPLEH₀: θ = θ₀ H₁: θ = θ₁ each names one complete distribution the likelihood ratio statisticT(x) = L(θ₁; x) / L(θ₀; x) = ∏ᵢ f(xᵢ; θ₁) / ∏ᵢ f(xᵢ; θ₀) THE LEMMAIf k is chosen so that Pθ₀( T > k ) = α, then the test "reject when T > k" is the MOST POWERFUL test of size α. No other size-α test has higher power at θ₁.

The proof is short enough to be worth doing, and its idea is the same as the greedy argument for a knapsack: you have a budget of α to spend on rejection, and you should spend it on the outcomes that give the most alternative-probability per unit of null-probability. The likelihood ratio is exactly that exchange rate.

let R* = {T > k} be the likelihood ratio region and R any other region with Pθ₀(R) ≤ αwrite φ* = 1 on R*, 0 elsewhere; φ = 1 on R, 0 elsewhere. key pointwise inequality — check the two cases( φ*(x) − φ(x) ) · ( f₁(x) − k·f₀(x) ) ≥ 0 for EVERY x if x ∈ R*: T > k so f₁ − k f₀ > 0, and φ* − φ = 1 − φ ≥ 0. product ≥ 0 ✓ if x ∉ R*: T ≤ k so f₁ − k f₀ ≤ 0, and φ* − φ = −φ ≤ 0. product ≥ 0 ✓ integrate the inequality over the whole sample space∫ (φ* − φ) f₁ − k ∫ (φ* − φ) f₀ ≥ 0 the first integral is the power difference, the second the size difference[ β*(θ₁) − β(θ₁) ] ≥ k · [ Pθ₀(R*) − Pθ₀(R) ] = k · [ α − Pθ₀(R) ] ≥ 0 since k > 0 and Pθ₀(R) ≤ αβ*(θ₁) ≥ β(θ₁) ∎

And the two-sided test is not UMP, which is not a defect. Point 2 above depended on μ₁ > μ₀ fixing the direction. Against H₁: μ ≠ μ₀ the most powerful test at a given μ₁ > μ₀ is the upper one-sided test, and at μ₁ < μ₀ it is the lower one — no single test is best against both, so no UMP test exists. The two-sided test is the best unbiased one (power never below α), which is the right optimality criterion once you insist on not being worse than random against some alternatives. This is the formal version of §02's rule that you cannot pick the side after looking.

The generalised likelihood ratio test

Real hypotheses are composite and often multi-dimensional — "these three coefficients are all zero" — where the lemma does not apply. The generalisation is to compare the best fit under the null with the best fit overall.

Three tests of one hypothesis, compared numerically

  • The three asymptotic tests are the same test to first order and differ in the second. They are three ways of measuring the same distance on the log-likelihood surface: Wald uses the curvature at the peak, score uses the slope at the null, and the likelihood ratio uses the height difference. If the log-likelihood were exactly quadratic all three would coincide exactly. The gaps between them are a direct readout of how non-quadratic it is — that is, of how far you are from the large-n regime.
  • Here all three are anti-conservative relative to the exact answer, and the Wald test most of all. This is the same defect that made the Wald interval for a proportion fail in part 4, §09, and it has the same cause: estimating the standard error at p̂ rather than at the null makes the denominator small exactly when the numerator is large.
  • The likelihood ratio is invariant to reparameterisation; the Wald test is not. Testing p = ½ and testing log(p/(1−p)) = 0 are the same hypothesis, and give the same λ — but different Wald statistics, because the SE transforms and the estimate does not transform linearly. That is a genuine argument for preferring the likelihood ratio whenever both are available.
  • Wilks' theorem needs the null to be in the interior of the parameter space. Testing "this variance component is zero" puts the null on a boundary, and the limiting distribution is a mixture of chi-squares, not a chi-square. Applying the standard test there is conservative — it produces p-values that are too large — which is a rare direction for a mistake to go, but a mistake nonetheless.
Where the whole catalogue comes from. Every test in §10 is a likelihood ratio test, a score test, or a Wald test for some model. The t test is the likelihood ratio test for a normal mean with unknown variance. The chi-square test of part 8 is the score test for a multinomial. The F test of part 9 is the likelihood ratio test comparing nested normal models. Once you know that, "which test should I use?" becomes "what is my model, and what does the null constrain?" — which is a question you can actually answer.

13 How 5% becomes 60%: p-hacking, forking paths, and the replication crisis

Everything so far assumed one analysis, fixed in advance, run once. Relax that assumption in any of a dozen ordinary-looking ways and the advertised 5% error rate becomes fiction. This section quantifies the damage — with simulations rather than assertions — describes the mechanisms, and reviews what the profession has proposed. The aim is to be fair rather than preachy: several of the proposals have real costs, and one of the most cited critiques has a well-argued rebuttal.

The garden of forking paths: p-hacking without any hacking

The word "hacking" implies intent, and the most important version of the problem requires none. A researcher who runs exactly one analysis, on data they see once, honestly reporting a single p-value, can still be producing an error rate far above 5% — if the analysis they chose was contingent on the data.

the fishing expedition
Many analyses run, best reported
Explicit multiplicity. Correctable in principle, by Bonferroni or by the false discovery rate (part 9). The researcher knows k.
the garden of forking paths
One analysis run, but chosen after seeing the data
Implicit multiplicity. The researcher genuinely ran one test — but would have run a different one on different data. k is the number of paths that could have been taken, and it is unknown even to them. Not correctable after the fact.

The forking-paths version is worse because it is invisible. No amount of scrutinising the reported analysis reveals it; the p-value is correct for the test performed, and the test was performed once. What is wrong is the reference class — the p-value is computed against "this test, repeated" when the honest reference is "this researcher, on fresh data". The only fixes are structural: pre-registration, or a genuinely held-out sample.

Publication bias and the winner's curse

Two effects compound the above, and both are properties of the literature rather than of any individual study.

1. PUBLICATION BIAS: only significant results are published, so the literature IS the "discoveries" column of §06's table. With π = 0.10 and power 0.35published findings: 35 true, 45 false → PPV = 0.4375 most of the published literature in that regime is false, with no fraud anywhere. 2. THE WINNER'S CURSE: conditioning on significance selects for LARGE estimates, so the published effect is biased upward. Exact E[δ̂ | significant] for a normal estimate:power 0.17 → published effect is 2.45× the truth power 0.35 → 1.66× power 0.52 → 1.39× power 0.80 → 1.12× power 0.95 → 1.03× so exaggeration is a direct function of how underpowered the study wasand it explains the replication literature's central finding without any misconduct.
These two combine into a prediction, and the prediction was tested. If the literature is filtered for significance and its studies are underpowered, then replications should (a) frequently fail and (b) find systematically smaller effects. A large coordinated replication of 100 psychology studies found exactly that: 97% of the originals reported significant results, 36% of the replications did, and the replication effect sizes were on average about half the originals. The winner's curse table above predicts a ratio near 2 at typical power levels, which is what was observed. A similar picture emerged from industrial attempts to reproduce preclinical biomedical findings, where reproduction rates in the 10–25% range were reported.

  • The honest summary of the debate. Nearly everyone agrees that thresholded p-values are over-weighted and that intervals and effect sizes should lead. Beyond that, the field splits: one camp wants a stricter threshold, another wants no threshold, and both have coherent arguments. What both agree on is that the underlying problem is incentives — a system that rewards novel positive findings will produce them — and that no change to the statistics can fix an incentive problem by itself.
  • The critique is about the practice, not the mathematics. Nothing in §01–§11 is wrong. A p-value computed correctly means exactly what §04 says it means. Every failure in this section is a failure to run the procedure the theory describes: one pre-specified analysis, one threshold, all results reported.
  • Multiple testing has a full treatment in part 9, "ANOVA & Multiple Comparisons". The explicit-multiplicity half of this problem — k known in advance — has proper machinery: family-wise error rate control by Bonferroni, Holm and Tukey, and false-discovery-rate control by Benjamini–Hochberg, which is the right tool when k is in the thousands and controlling every false positive would leave you with no power at all.
The practical defence, for one analyst working alone. Write down the analysis before you look. Record every analysis you run, including the ones that failed, and report the count. Split the data and keep a holdout you touch exactly once. Report intervals. Treat any result that required a choice made after seeing the data as exploratory and label it so — an exploratory finding is not worthless, it is a hypothesis, and the honest next step is to test it on data that did not generate it.

14 The machine-learning translation: comparing two models honestly

"Model B scores 88.0% and model A scores 84.0%, so B is better" is a hypothesis test with the test omitted. The right analysis is nearly always a paired one, because both models were evaluated on the same examples, and the paired version can turn a hopeless comparison into a decisive one — or expose a difference as noise. Everything in §10 and §13 transfers directly; only the vocabulary changes.

This is the same test as McNemar in spirit and it uses the magnitudes, which McNemar discards for the same reason the sign test does (§10).

The point of this arithmetic is that a 1 000-example test set cannot resolve a one-point accuracy difference, no matter how carefully you compute the p-value afterwards. Leaderboard positions separated by a few tenths of a point on test sets of a few thousand examples are, in the overwhelming majority of cases, noise. Part 4's §13 makes the same point with intervals: put an interval on the metric and the resolution of your evaluation becomes visible immediately.

Repeated evaluation on the same test set is p-hacking

the standard workflow, stated as a statistical proceduretrain a model → evaluate on the test set → adjust → evaluate again → ... → report the best this is EXACTLY "try k analyses, report the smallest p" from §13after k evaluations, P(some model beats the baseline by chance | no real gain) = 1 − (1 − α)ᵏ k = 20 evaluations → 0.642. k = 100 → 0.994. and the reported gain is inflated by the winner's curse of §13the best of k noisy scores has expectation well above the truth, so the held-out number you publish will not reproduce in production.
  • This is the entire reason for the three-way split. Train / validation / test exists so that the set you tune against is not the set you report on. Every hyperparameter search, every architecture comparison, every early-stopping decision is a look at the data — and all of those looks belong to the validation set. The test set gets used once, at the end, and reports a number that means what it says. See model evaluation, §validation.
  • Public benchmarks are a shared test set used thousands of times. When a whole community tunes against one leaderboard, the community collectively p-hacks even though each participant looked once. Reported gains on a long-lived benchmark should be discounted, and the discount grows with the benchmark's age. This is the garden of forking paths at the scale of a field.
  • Cross-validation makes the comparison more precise but not independent. The k fold-level scores share training data, so they are correlated, and treating them as k independent observations understates the standard error — the naive paired t test across folds has a type I rate well above its nominal level. Repeat the whole cross-validation with different splits, or use a corrected variance estimate, and always report the fold-to-fold spread. Model comparison covers the practice.

A/B testing: the same test with the same traps

trap 1
Peeking at the dashboard
The live metric updates continuously and everyone watches it. §13's simulation applies verbatim: 0.05 becomes 0.46 with continuous monitoring. Fix the sample size in advance, or use a sequential method built for it.
trap 2
Many metrics, one winner
Clicks, revenue, retention, session length, and six guardrails. Twenty metrics at 0.05 gives a 64% chance one moves "significantly" under a null change. Name one primary metric in advance; everything else is a guardrail or an exploration.
trap 3
Significant but worthless
§12 at industrial scale. Ten million users make a 0.01% change significant. Define the minimum effect worth shipping before you start, and compare the interval to that, not to zero.
trap 4
Broken independence
Users appear many times; sessions within a user are correlated; network effects leak between arms. The formula's standard error assumes independent observations, and when they are not it is too small — so the test is anti-conservative in a way no amount of data fixes.

The full treatment, including sequential designs and the practical machinery, is in A/B testing; §significance and §pitfalls are the direct continuations of this section.

The three habits that carry all of this. Pair whenever both systems saw the same data — it costs nothing and often changes the verdict. Split so that the set you tune against is never the set you report on, and touch the reporting set once. Report an interval on the difference, not two accuracies side by side — the difference is the quantity you are deciding on, and it is the only one whose uncertainty you can state honestly.

15 Practice

The checklist, before you report any test

  1. Were H₀, H₁, the level and the analysis fixed before the data? If not, the result is exploratory. Say so.
  2. Is the test statistic's null distribution actually right here? Check the assumption that binds: normality at small n, independence always, cell counts for proportions.
  3. Is the sample independent? Clustered, repeated or time-ordered data break every standard error on this page.
  4. Should this be paired? If the same units generated both numbers, yes.
  5. One-sided or two-sided, and was that decided in advance?
  6. How many analyses did you run, or could you have run? Report the count.
  7. What is the effect size, in units a reader understands?
  8. What is the confidence interval? Report it before the p-value.
  9. What power did the study have against the smallest effect that matters? Computed in advance, not from the observed effect.
  10. If you failed to reject: is the interval tight enough to support "no effect", or is the study simply uninformative?

Worked problems

  1. A coin gives 60 heads in 100 tosses. Test fairness. SE = √(100 × ¼) = 5, z = (60 − 50)/5 = 2.00, two-sided p = 0.0455. With continuity correction, z = 9.5/5 = 1.90, p = 0.0574. The exact binomial two-sided p-value is 0.0569. Three answers straddling 0.05 — report the exact one and note the fragility.
  2. Same coin, 600 heads in 1 000 tosses. SE = √(1000 × ¼) = 15.81, z = 100/15.81 = 6.32, p = 2.5 × 10⁻¹⁰. The proportion is identical to problem 1; the p-value moved by eight orders of magnitude. This is §12 in two lines.
  3. A drug lowers blood pressure by 0.4 mmHg in a trial of 40 000, σ = 10. SE = 10/200 = 0.05, z = 8.0, p ≈ 10⁻¹⁵, 95% CI (0.302, 0.498). Overwhelmingly significant, clinically negligible — clinical guidelines treat differences under about 2 mmHg as immaterial. Report the interval and let it speak.
  4. Design: detect a 0.3σ difference between two groups with 90% power at α = 0.05. n = 2 × 10.50742/0.09 = 234 per group by the normal formula; the exact t answer is 235. Halve the effect to 0.15σ and it becomes 934 per group — a fourfold cost for a halved target.
  5. Twelve paired differences: mean 3.1, SD 5.4. SE = 5.4/√12 = 1.5588, t = 1.9887, df = 11, two-sided p = 0.0722. 95% CI 3.1 ± 2.20099 × 1.5588 = (−0.331, 6.531). Not significant, and the interval says why: this study cannot distinguish "no effect" from "an effect of 6", so it has settled nothing.
  6. You test 40 features for association with the outcome, all null, at α = 0.05. Expected false positives = 40 × 0.05 = 2. P(at least one) = 1 − 0.95⁴⁰ = 0.871. You will almost certainly find something, and it will almost certainly be nothing.
  7. Model A is right on 82 of 100 test cases, model B on 88; they disagree on 12, with B right on 9 of those. McNemar: b = 3, c = 9, z = 6/√12 = 1.7321, p = 0.0833; exact p = 2·P(X ≥ 9 | Bin(12, ½)) = 0.1460. Use the exact version at these counts. Not significant — a six-point gap on 100 examples is within noise.
  8. A 95% CI for a difference is (0.4, 3.6). What is the two-sided p-value at H₀: δ = 0? By duality the interval excludes 0, so p < 0.05. More precisely: the centre is 2.0, the half-width 1.6, so SE = 1.6/1.95996 = 0.81634 and z = 2.0/0.81634 = 2.4500, giving p = 0.0143. The interval contained the test all along.
