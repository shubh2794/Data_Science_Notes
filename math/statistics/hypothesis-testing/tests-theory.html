10 The tests you will actually run, with the assumption that breaks each one

Eight named tests, all of them the same statistic — an estimate minus a null value, divided by a standard error — differing only in which standard error and which reference distribution. Learning them as eight recipes is a waste; learning them as one recipe with eight standard errors takes an afternoon and survives contact with the cases nobody taught you.

the one formT = (estimate − null value) / SE(estimate) compare to a reference distribution the only things that change between tests1. what the estimate is 2. the formula for SE 3. z or t, and with how many df

One mean: the z test, the t test, and where the boundary is

The health guideline for lead in drinking water is 15 parts per billion. Five independent samples from a reservoir read 15.1, 16.3, 14.8, 15.9, 15.9. Is the reservoir over the limit?

the hypotheses — the burden of proof is on "over the limit", so that is H₁H₀: μ = 15 ppb H₁: μ > 15 ppb one-sided, α = 0.05 the datax̄ = 15.600 s² = 1.56/4 = 0.390 s = 0.62450 SE = s/√5 = 0.27928 the statistic and its reference distributiont = (15.600 − 15)/0.27928 = 2.14834 df = n − 1 = 4 the p-valuep = P( t₄ ≥ 2.14834 ) = 0.04908 < 0.05, so reject — just. what happens if you carelessly use the normal table insteadp = 1 − Φ(2.14834) = 0.01584 — THREE TIMES too small and the matching one-sided 95% confidence bound, which must agreelower bound = x̄ − t*₄,₀.₉₅·SE = 15.600 − 2.13185 × 0.27928 = 15.0046 > 15 ✓ reject
  • The z/t difference is a factor of three in the p-value at n = 5, and negligible at n = 100. Part 4, §08 derives why: replacing σ by s makes the denominator random too, fattening the tails. The correction shrinks like 1/n: t*(4) = 2.132 against z* = 1.645 is 30% wider, t*(29) = 1.699 is 3% wider, t*(999) = 1.64638 is 0.09% wider.
  • This example is on a knife edge, and that is the point. p = 0.0491. One more measurement, or one measurement 0.1 ppb lower, and it lands the other side. The right report is not "the reservoir is over the limit" but "the mean is 15.60, one-sided 95% lower bound 15.00, p = 0.049" — which makes the fragility visible instead of hiding it behind a verdict.
  • The assumption that actually binds is normality of the population, and at n = 5 you cannot check it. Five points tell you almost nothing about shape. If the measurement process is known to be roughly symmetric the t test is fine; if it might be skewed or occasionally produce a wild reading, the t test's tail probabilities are not trustworthy and part 7's permutation and bootstrap methods are the honest fallback.

Paired versus two-sample: the same data, two answers

Do husbands tend to be older than their wives? Five couples, ages 43/41, 71/70, 32/31, 68/66, 27/26.

the wrong analysis: treat the two columns as independent samplesx̄_h = 48.2 s_h = 20.31502 x̄_w = 46.8 s_w = 20.14200 difference 1.4, SE = √(20.31502²/5 + 20.14200²/5) = 12.79375 t = 1.4/12.79375 = 0.10943, ν ≈ 8, p = 0.9156 "no evidence whatsoever" — because the between-couple spread swamps everything the right analysis: the samples are NOT independent, so work with the differencesd = 2, 1, 1, 2, 1 d̄ = 1.4 s_d = 0.54772 SE = 0.24495 t = 1.4/0.24495 = 5.71548 df = 4 two-sided p = 0.00464 the variance the pairing removeds_h = 20.315 → s_d = 0.548. The design cut the SD by a factor of 37, and the VARIANCE by a factor of 1 376. so the p-value moved by two orders of magnitude on identical numbersunpaired 0.9156 paired 0.00464 — the ANALYSIS did not change the data, it changed which noise it compared against.

Pairing is the single most effective variance-reduction device in the subject, and it is a design decision, not an analytic one. Each couple acts as its own control, so everything that makes couples differ from each other — the thing that produced s = 19.6 — cancels exactly. The cost is degrees of freedom: five pairs give ν = 4 rather than the eight an unpaired design would have. That is almost always a bargain, and it is the same argument as blocking in part 2, §09.

Applying the two-sample test to paired data is not conservative — it is simply wrong. It uses a standard error computed under an independence assumption that is false, and the error can go in either direction. With positively correlated pairs (the usual case) it inflates the SE and destroys power, as above. With negatively correlated pairs it deflates the SE and inflates the type I rate. Neither failure announces itself.

The sign test: the same question with the numbers thrown away

use only the SIGN of each difference. Under H₀ each sign is a fair coinS = #{ dᵢ > 0 } = 5 out of 5 under H₀, S ~ Binomial(5, ½) normal versionz = (5 − 2.5)/(½·√5) = 2.5/1.11803 = 2.23607 one-sided p = 0.01267 exact version — with n = 5 the normal approximation has no business being usedone-sided p = P(S = 5) = (½)⁵ = 1/32 = 0.03125 two-sided p = 2/32 = 0.0625 — does NOT clear 0.05, at any data set of size 5 compare with the paired t on the same datapaired t: p = 0.00464 sign test: p = 0.0625 13× larger
  • The sign test assumes almost nothing and pays for it. No normality, no equal variances, no interval scale — you need only be able to say which of a pair is bigger. In exchange it discards the magnitudes, and magnitudes are most of the information. Against normal data its asymptotic relative efficiency versus the t test is 2/π = 0.637: the sign test needs about 57% more data to match the t test's power.
  • With n = 5 the sign test literally cannot reach two-sided significance. The smallest achievable two-sided p-value is 2·(½)⁵ = 0.0625. This is discreteness (§03) at its most brutal: a perfect result, five out of five, is not significant at 0.05. Knowing the floor of your test before running it is part of design.
  • Where it earns its keep: ordinal data, heavy-tailed data, and any situation where a single wild value would wreck a mean. The signed-rank test sits between the two, using the ranks of the magnitudes but not the magnitudes themselves, and recovers most of the lost efficiency (ARE 3/π = 0.955 against normal data).

Two independent means: Welch or pooled

Two model variants scored on separate held-out sets: variant A, n₁ = 12, mean 8.24, s₁ = 1.36; variant B, n₂ = 15, mean 7.05, s₂ = 2.11.

Welch — the default, and the one to use unless you have a reason not toSE = √(1.36²/12 + 2.11²/15) = √(0.154133 + 0.296807) = 0.671521 t = (8.24 − 7.05)/0.671521 = 1.77210 Welch–Satterthwaite degrees of freedom — generally not an integerν = (s₁²/n₁ + s₂²/n₂)² / [ (s₁²/n₁)²/(n₁−1) + (s₂²/n₂)²/(n₂−1) ] = 0.450940² / (0.154133²/11 + 0.296807²/14) = 24.0585 two-sided p = 0.08904 95% CI for the difference: (−0.196, 2.576) pooled — assumes σ₁ = σ₂, which here is doubtful (s₂/s₁ = 1.55)s_p² = [11(1.36²) + 14(2.11²)]/25 = 82.675/25 = 3.30700 s_p = 1.818516 SE = 1.818516·√(1/12 + 1/15) = 0.704308 t = 1.68960 df = 25 two-sided p = 0.10354 the two answers straddle a threshold, which is why the choice must be made in advanceWelch 0.0890 pooled 0.1035 both > 0.05 here, but not always
  • Use Welch by default. It costs almost nothing when the variances are equal — the df penalty is small and it is barely less powerful — and it stays correct when they are not. The pooled test's advantage is real only when σ₁ = σ₂ exactly and the sample sizes are small; its failure when variances differ and group sizes are unequal is severe. Pairing a small sample with a large variance against a large sample with a small variance can push the pooled test's true type I rate above 0.10 at a nominal 0.05.
  • Do not pre-test for equal variances and then choose. "Run an F test on the variances; if it fails, use Welch" is a two-stage procedure whose combined error rate is not 0.05, and it is the same forking-path error as §02's side-picking. Decide once, in advance, and Welch is the decision that needs no justification.
  • Both tests assume the two samples are independent, which for two model variants evaluated on separate test sets is true — and which is exactly what you should not do. §14 explains why the same test set plus a paired test dominates this design.

Proportions, one and two

Last month 55% of 1 000 sampled voters approved; this month 58% of 1 500. Has approval changed?

H₀: p₁ = p₂, two-sided. The estimate is the difference of two proportionsp̂₂ − p̂₁ = 0.58 − 0.55 = 0.03 SE, UNPOOLED — the version that matches the confidence intervalSE = √( 0.55·0.45/1000 + 0.58·0.42/1500 ) = √0.00040990 = 0.020246 z = 0.03/0.020246 = 1.48178 two-sided p = 0.13840 SE, POOLED — the version that matches the null, since H₀ says the two rates are equalp̄ = (550 + 870)/2500 = 0.568 SE₀ = √( 0.568 × 0.432 × (1/1000 + 1/1500) ) = 0.020223 z = 0.03/0.020223 = 1.48348 two-sided p = 0.13795 and the 95% interval for the difference, from the UNPOOLED SE0.03 ± 1.95996 × 0.020246 = (−0.0097, +0.0697) — contains 0, consistent with p > 0.05
  • Pooled or unpooled: for the test, pooled is marginally preferable; for the interval, you must use unpooled. The null asserts a common rate, so estimating that rate from all 2 500 observations gives a standard error computed under the null, which is the right reference. But an interval must not assume the thing it is trying to bracket, so it uses the separate estimates. Here the two differ in the fourth decimal. When p̂₁ and p̂₂ are far apart they differ more, and the pooled and unpooled tests can straddle a threshold.
  • Report the difference, not the two rates. "55% versus 58%" invites the reader to do the comparison badly (part 4's §07 overlap trap). "+3.0 points, 95% CI −1.0 to +7.0" is the same information, correctly assembled, and makes the width visible: this poll cannot distinguish a one-point drop from a seven-point rise.
  • The count, not the sample size, sets the precision. A conversion test with 45 000 page views and 382 conversions has the precision of a study with a few hundred observations, because the standard error of a proportion depends on np(1−p). Large n with tiny p is not big data.
What to do when an assumption fails. Non-normal and small n → permutation test or the bootstrap (part 7), or a rank test. Unequal variances → Welch, always. Dependent observations (clustered, time series, repeated measures) → the standard error is simply wrong and no reference distribution fixes it; you need a model of the dependence. Counts too small for the normal approximation → the exact binomial, which needs no approximation at all. Outliers → a rank test, or report the analysis with and without them and let the reader see the leverage.

11 Where the machinery comes from: Neyman–Pearson and the likelihood ratio

§03 said "choose a test statistic" as if it were a matter of taste. It is not. For the cleanest possible testing problem there is a provably optimal statistic, the answer is the likelihood ratio, and every named test in §10 is that answer specialised. This section is the theory that makes the rest of the page non-arbitrary.

The optimality question, posed properly

among all tests with size at most α, which has the largest power?maximise β(θ₁) = Pθ₁(reject) subject to β(θ₀) = Pθ₀(reject) ≤ α a test achieving this is MOST POWERFUL at θ₁; if the SAME test does it for every θ₁ in Θ₁ it is UNIFORMLY most powerful (UMP)UMP tests exist for one-sided problems in nice families, and often NOT otherwise.

The Neyman–Pearson lemma

setting: both hypotheses SIMPLEH₀: θ = θ₀ H₁: θ = θ₁ each names one complete distribution the likelihood ratio statisticT(x) = L(θ₁; x) / L(θ₀; x) = ∏ᵢ f(xᵢ; θ₁) / ∏ᵢ f(xᵢ; θ₀) THE LEMMAIf k is chosen so that Pθ₀( T > k ) = α, then the test "reject when T > k" is the MOST POWERFUL test of size α. No other size-α test has higher power at θ₁.

The proof is short enough to be worth doing, and its idea is the same as the greedy argument for a knapsack: you have a budget of α to spend on rejection, and you should spend it on the outcomes that give the most alternative-probability per unit of null-probability. The likelihood ratio is exactly that exchange rate.

let R* = {T > k} be the likelihood ratio region and R any other region with Pθ₀(R) ≤ αwrite φ* = 1 on R*, 0 elsewhere; φ = 1 on R, 0 elsewhere. key pointwise inequality — check the two cases( φ*(x) − φ(x) ) · ( f₁(x) − k·f₀(x) ) ≥ 0 for EVERY x if x ∈ R*: T > k so f₁ − k f₀ > 0, and φ* − φ = 1 − φ ≥ 0. product ≥ 0 ✓ if x ∉ R*: T ≤ k so f₁ − k f₀ ≤ 0, and φ* − φ = −φ ≤ 0. product ≥ 0 ✓ integrate the inequality over the whole sample space∫ (φ* − φ) f₁ − k ∫ (φ* − φ) f₀ ≥ 0 the first integral is the power difference, the second the size difference[ β*(θ₁) − β(θ₁) ] ≥ k · [ Pθ₀(R*) − Pθ₀(R) ] = k · [ α − Pθ₀(R) ] ≥ 0 since k > 0 and Pθ₀(R) ≤ αβ*(θ₁) ≥ β(θ₁) ∎

Worked: the lemma produces the z test, and nothing else could have

X₁,…,Xₙ ~ Normal(μ, σ²) with σ known. Test μ = μ₀ against μ = μ₁ > μ₀log T = log L(μ₁) − log L(μ₀) = −(1/2σ²) [ ∑(xᵢ − μ₁)² − ∑(xᵢ − μ₀)² ] expand both squares; the ∑xᵢ² terms cancel = (1/σ²) [ (μ₁ − μ₀)∑xᵢ ] − (n/2σ²)(μ₁² − μ₀²) everything except ∑xᵢ is a constant, and (μ₁ − μ₀) > 0, soT > k ⟺ ∑xᵢ > k′ ⟺ x̄ > k″ ⟺ (x̄ − μ₀)/(σ/√n) > z₍1−α₎ two consequences worth stating1. The one-sided z test is MOST POWERFUL. It is not a convention; it is the optimum. 2. k″ does not depend on μ₁ — so the same test is optimal for EVERY μ₁ > μ₀: it is UMP.
And the two-sided test is not UMP, which is not a defect. Point 2 above depended on μ₁ > μ₀ fixing the direction. Against H₁: μ ≠ μ₀ the most powerful test at a given μ₁ > μ₀ is the upper one-sided test, and at μ₁ < μ₀ it is the lower one — no single test is best against both, so no UMP test exists. The two-sided test is the best unbiased one (power never below α), which is the right optimality criterion once you insist on not being worse than random against some alternatives. This is the formal version of §02's rule that you cannot pick the side after looking.

The generalised likelihood ratio test

Real hypotheses are composite and often multi-dimensional — "these three coefficients are all zero" — where the lemma does not apply. The generalisation is to compare the best fit under the null with the best fit overall.

the statisticλ = 2 log [ sup₍θ ∈ Θ₎ L(θ) / sup₍θ ∈ Θ₀₎ L(θ) ] = 2 [ ℓ(θ̂) − ℓ(θ̂₀) ] θ̂ = the unrestricted MLE, θ̂₀ = the MLE restricted to Θ₀ WILKS' THEOREM — the reason this is usable at allUnder H₀ and regularity conditions, λ ⇝ χ²₍r − q₎ as n → ∞ r = dim(Θ), q = dim(Θ₀), so the df is the NUMBER OF CONSTRAINTS H₀ imposes. the p-valuep = P( χ²₍r−q₎ > λ_obs ) reject when λ is large note that λ ≥ 0 always, since Θ₀ ⊂ Θ means the unrestricted fit is never worsea bigger model always fits better; λ asks whether it fits better THAN CHANCE would give.

Three tests of one hypothesis, compared numerically

A coin lands heads 62 times in 100 tosses. Test H₀: p = ½ four ways.

1. LIKELIHOOD RATIO (Wilks). λ = 2[ℓ(p̂) − ℓ(p₀)] with p̂ = 0.62λ = 2[ 62·log(0.62/0.5) + 38·log(0.38/0.5) ] = 2[13.3369 − 10.4286] = 5.81661 p = P(χ²₁ > 5.81661) = 0.01588 2. SCORE (Rao). SE evaluated UNDER the null — √(p₀(1−p₀)/n) = 0.05z = (0.62 − 0.50)/0.05 = 2.40000 p = 0.01640 3. WALD. SE evaluated at the ESTIMATE — √(p̂(1−p̂)/n) = 0.048539z = (0.62 − 0.50)/0.048539 = 2.47226 p = 0.01343 4. EXACT BINOMIAL. No asymptotics at allp = P(X ≥ 62) + P(X ≤ 38) = 0.02098 all four agree qualitatively; they differ by up to 56% in the p-valueexact 0.0210 score 0.0164 LR 0.0159 Wald 0.0134
  • The three asymptotic tests are the same test to first order and differ in the second. They are three ways of measuring the same distance on the log-likelihood surface: Wald uses the curvature at the peak, score uses the slope at the null, and the likelihood ratio uses the height difference. If the log-likelihood were exactly quadratic all three would coincide exactly. The gaps between them are a direct readout of how non-quadratic it is — that is, of how far you are from the large-n regime.
  • Here all three are anti-conservative relative to the exact answer, and the Wald test most of all. This is the same defect that made the Wald interval for a proportion fail in part 4, §09, and it has the same cause: estimating the standard error at p̂ rather than at the null makes the denominator small exactly when the numerator is large.
  • The likelihood ratio is invariant to reparameterisation; the Wald test is not. Testing p = ½ and testing log(p/(1−p)) = 0 are the same hypothesis, and give the same λ — but different Wald statistics, because the SE transforms and the estimate does not transform linearly. That is a genuine argument for preferring the likelihood ratio whenever both are available.
  • Wilks' theorem needs the null to be in the interior of the parameter space. Testing "this variance component is zero" puts the null on a boundary, and the limiting distribution is a mixture of chi-squares, not a chi-square. Applying the standard test there is conservative — it produces p-values that are too large — which is a rare direction for a mistake to go, but a mistake nonetheless.
Where the whole catalogue comes from. Every test in §10 is a likelihood ratio test, a score test, or a Wald test for some model. The t test is the likelihood ratio test for a normal mean with unknown variance. The chi-square test of part 8 is the score test for a multinomial. The F test of part 9 is the likelihood ratio test comparing nested normal models. Once you know that, "which test should I use?" becomes "what is my model, and what does the null constrain?" — which is a question you can actually answer.
