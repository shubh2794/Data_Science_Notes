07 Three intervals from one histogram — and why they are different

Once θ̂*₁, …, θ̂*_B exist there are three standard ways to turn them into a confidence interval. On symmetric data all three coincide and the choice does not matter. On skewed data they can point in opposite directions, and understanding why is the difference between using the bootstrap and operating it.

Method 1 — the normal (standard-error) interval

use the bootstrap only for the SE, and assume normality for the shapeθ̂ ± z_{1−α/2} · SÊ_boot SÊ_boot = sd(θ̂*₁, …, θ̂*_B) on the running sample's mean20 ± 1.959964 × 4.944 = (10.31, 29.69)

This is part 4's construction with the formula standard error swapped out for a computed one. It is the least ambitious of the three — it uses one number from the bootstrap and throws the rest of the histogram away — and it inherits every problem the normal approximation has. Its one advantage is that it is symmetric and never produces an interval narrower than the data support. Use it when the bootstrap histogram looks normal and you want a number in one line; otherwise it is dominated by the alternatives.

Method 2 — the percentile interval

read the interval straight off the bootstrap histogram — no distributional assumption at all[ θ̂*_(α/2) , θ̂*_(1−α/2) ] the empirical α/2 and 1−α/2 quantiles of the θ̂* on the running sample's mean, B = 200 000(11.45, 30.65) — noticeably shifted RIGHT of the t interval (9.38, 30.62)

The justification is a change-of-variables argument, and it is the cleverest thing in the section. Suppose some unknown monotone transformation U = m(θ̂) makes the statistic exactly normal, U ~ Normal(φ, c²) with φ = m(θ). You do not need to know m; you only need it to exist.

quantiles survive any monotone transformation, which is the whole tricku*_(α/2) = m( θ̂*_(α/2) ) and on the normal scale u*_(α/2) = φ − z c so the percentile interval on the θ scale IS the z-interval on the u scaleP( θ̂*_(α/2) ≤ θ ≤ θ̂*_(1−α/2) ) = P( u*_(α/2) ≤ φ ≤ u*_(1−α/2) ) = P( U − zc ≤ φ ≤ U + zc ) = P(|Z| ≤ z) = 1 − α the payoff, stated as a property rather than a proofThe percentile interval is TRANSFORMATION-RESPECTING: the interval for log θ is exactly the log of the interval for θ. Of the methods on this page only BCa (§09), which is built on top of it, shares that property — the other three do not.
  • It is also range-respecting. Every endpoint is an actual bootstrap value, so an interval for a correlation stays inside [−1, 1], an interval for a variance stays positive, and an interval for a proportion stays inside [0, 1] — automatically, with no special-casing.
  • An exact normalising transformation almost never exists, so the argument above is a heuristic, not a theorem. §08 measures how much that matters.
  • It cannot escape the data. The endpoints are order statistics of the θ̂*, and for many statistics that traps them inside the observed range — harmless for a mean, fatal for a maximum (§16).

Method 3 — the pivotal (basic) interval

The lecture's motivation is the right one and worth stating before the algebra: bootstrap the error θ̂ − θ rather than θ̂ itself, in the hope that the distribution of the error is less sensitive to where θ happens to sit. A quantity whose distribution does not depend on the unknown parameter is called a pivot; θ̂ − θ is an approximate one, and the derivation is exact given that.

The percentile and pivotal intervals are mirror images of each other about θ̂. If the bootstrap histogram has a long right tail, the percentile interval reaches far to the right of θ̂; the pivotal interval reaches far to the left. On the running sample they are (11.45, 30.65) and (9.35, 28.55) — the percentile interval sits 2.1 minutes above the pivotal one at both ends, and the two have identical widths. They cannot both be right, and there is a real argument on each side.
the case for the reflection, which is a genuine theorem in the right conditionsIf θ̂ is biased UPWARD, so are the θ̂*. The percentile interval inherits the bias; the pivotal interval subtracts it, because 2θ̂ − θ̂*_(β) is a bias-corrected quantity. the case against, which is what §08 actually measuresThe reflection assumes the SHAPE of the bootstrap distribution is a faithful copy of the shape of the sampling distribution. When it is not — and for medians and quantiles it emphatically is not — the reflection amplifies the error instead of cancelling it, and it can put the interval where the parameter provably is not.

Where the pivotal interval visibly breaks the rules

08 What the three intervals actually cover — measured, not claimed

Every interval on this page is labelled 95%. Part 4, §07 made the distinction that matters: nominal coverage is what the label says, actual coverage is the fraction of intervals that contain the parameter when the whole procedure is repeated. They are not the same number, nobody's software tells you the difference, and the only way to find out is to simulate a population you know the answer for. This section does that.

The experiment

Twenty thousand replications at each cell. Each replication draws a fresh sample of size n from a known population, runs B = 999 bootstrap resamples, builds all four intervals, and checks whether each contains the true parameter. Quantiles use the linear-interpolation convention throughout. The Monte-Carlo standard error on a figure near 95% is √(0.95 × 0.05/20000) = 0.15 percentage points, so differences below about half a point should be ignored.

This is not the result the bootstrap is usually sold with, and it is the most useful thing in the section. For a mean, the ordinary t interval beats all three bootstrap intervals at every single one of these nine cells. That is not an accident and not a bug:
  • The t interval is already the right tool for a mean. It has an exact small-sample correction — the t multiplier on n − 1 degrees of freedom — for precisely the extra uncertainty that comes from estimating the spread. The percentile and pivotal intervals have no such correction: they are built on z-like quantiles of a distribution estimated from the same n points, and at n = 10 that costs about five percentage points of coverage on normal data.
  • Skew hurts everything, and the bootstrap does not repair it. Going from Normal to Lognormal at n = 10 costs the t interval eleven points and the bootstrap intervals nine to twelve. Both are failing for the same reason — the sampling distribution of x̄ is skewed, and none of these intervals except the bootstrap-t of §09 knows how to be asymmetric in the right direction.
  • The pivotal interval is the worst of the three under skew, at every skewed cell. Its reflection points the asymmetry the wrong way.
  • So why bootstrap a mean at all? You should not. The bootstrap earns its keep on statistics that have no t interval — which is nearly all of them. This table is here to stop you concluding that resampling is universally better, and to make the next table's message unmissable.

At n = 3 the "95%" bootstrap interval covers three quarters of the time. There is nothing mysterious here: with three observations, F̂ₙ has three atoms, there are exactly C(5, 3) = 10 distinct resamples, and no amount of Monte Carlo extracts information the data does not contain. Every bootstrap result on this page is asymptotic. Below about n = 20 the intervals are optimistic; below about n = 10 they should not be reported.

09 Two better intervals: the bootstrap-t and BCa

§08 left the percentile interval a few points short of its nominal level and the pivotal interval worse. Two standard refinements close most of the gap. They are more work — one needs a second layer of resampling, the other needs a jackknife — and both are worth knowing about even if you only ever call a library function that implements them.

The bootstrap-t (studentised) interval

The reason the t interval beat the bootstrap for a mean in §08 is that it studentises: it divides by an estimated standard error before looking up a critical value, which removes most of the dependence on the unknown scale. The bootstrap-t does the same thing without needing a table — it estimates the distribution of the studentised statistic by resampling.

It pays for that in two currencies: its intervals are wider and much more variable (mean width 1.83 against the percentile interval's 1.07 on that cell), and a single unstable SÊ*_b in the denominator can throw an endpoint a long way. It is also not range-respecting and not transformation-respecting.

BCa: bias-corrected and accelerated

BCa keeps the percentile interval's good properties and fixes its two known deficiencies. It is still [θ̂*_(α₁), θ̂*_(α₂)] — endpoints read off the same histogram — but the two percentages are no longer α/2 and 1 − α/2.

  • BCa is second-order accurate, meaning its coverage error shrinks like 1/n rather than the percentile interval's 1/√n. The measured table above is consistent with that — BCa gains one to two points over the percentile interval at n = 10 and the gap closes as n grows — but a rate is an asymptotic statement and, as the Lognormal n = 10 row shows, "second-order accurate" and "accurate" are different words.
  • It keeps both good properties of the percentile interval: range-respecting and transformation-respecting, because the endpoints are still bootstrap values.
  • It needs a jackknife pass — n extra refits — which is cheap next to B resamples, and it needs B large enough that extreme percentage points are resolvable. If α₁ comes out at 0.004, then B = 1000 puts the endpoint on the 4th smallest replicate. §10's advice to use B ≥ 10 000 for interval endpoints is doubly binding for BCa.
  • It is the default in several standard libraries, and it is the right default. But the honest summary of this section is that no bootstrap interval is trustworthy at n = 10 on a heavily skewed population, and the correct response to that situation is more data or a different question, not a better interval formula.

10 Choosing B: two errors, and only one of them is yours

This is the single most misunderstood point about the bootstrap, and it takes one sentence to state. There are two sources of error, they are governed by two different numbers, and increasing B only touches one of them. Everything else in the section is arithmetic in support of that sentence.

error 1 · yours to control
Monte-Carlo error
The gap between your B resamples and the ideal bootstrap answer (B = ∞). Shrinks like 1/√B. Costs only compute. Reproducibility depends on it: two analysts with the same data and different seeds differ by exactly this much.
error 2 · not yours to control
Statistical error
The gap between the ideal bootstrap answer and the truth. Governed by n. Completely unaffected by B. This is the left-hand gap in §03's diagram, and it is almost always the larger of the two.

From B = 200 to B = 20 000 the spread of the reported standard error fell from 2.094 to 1.992 — and the residual 1.99 is entirely the statistical error, fixed by n = 20 and untouchable by any amount of resampling. If your bootstrap standard error is not precise enough, the answer is more data. The only thing more resamples buy you is that a colleague rerunning your script with a different seed gets the same number.

Practical settings

What you are computingSuggested BWhy
A standard error or a bias estimate1 000 – 2 000The SE only needs the second moment of the θ̂*, which converges fast; B = 1000 gives 2.2% relative accuracy.
A percentile or pivotal interval10 000Endpoints are extreme order statistics and converge far more slowly. Note in the first table that at B = 1000 the 97.5% endpoint still wobbles by ±0.53 minutes — twice the SE's own wobble.
A BCa interval10 000 – 20 000Its corrected percentage points can land far into the tail, where you need replicates to exist.
A published numberas many as you canMonte-Carlo error is the only part of the analysis that is purely your own noise. Drive it below the last digit you report, then report the seed.
A permutation p-value (§11)at least 1/α − 1A different constraint entirely: the smallest achievable p-value is 1/(B+1), so α = 0.05 needs B ≥ 19 to be able to reject at all, and B ≈ 10 000 to report three digits.
  • The Monte-Carlo error of a permutation p-value has its own exact formula. Given the true (exhaustive) p-value p, the sampled estimate has SE = √(p(1−p)/B). At p = 0.05 and B = 1000 that is 0.0069 — so a reported p = 0.05 is really 0.05 ± 0.014 at 95%, which is enough to flip a verdict. If a decision hangs on the third decimal, raise B until it does not.
  • Always fix and report the seed. A bootstrap analysis is not reproducible without one, and "the interval was (11.4, 30.7) at seed 1607, B = 200 000" is a complete specification whereas "(11.4, 30.7)" is not.
  • Reuse the same resamples across statistics. If you want a bootstrap SE for five different statistics, compute all five inside one loop over the resamples. The five will be correlated — which is usually what you want, since it lets you bootstrap differences and ratios between them consistently — and it costs a fifth of the resampling.
