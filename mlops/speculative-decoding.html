Speculative Decoding

Autoregressive decoding emits one token per expensive forward pass. Speculative decoding breaks that lockstep: a small, cheap draft model guesses several tokens ahead, and the large target model verifies them all in a single parallel pass — accepting a whole run at once. With the right acceptance rule it is lossless: the text is sampled from exactly the target's distribution, so quality is provably unchanged.

MLOps & Deployment Inference LLM Serving

01 Why decoding is slow (and how to break the lockstep)

  • To produce N tokens, a plain LLM runs its full stack N times — one token per pass.
  • Each pass is memory-bandwidth-bound, not compute-bound: most wall-clock time goes to streaming the model's weights from memory, while the GPU's arithmetic units sit mostly idle.
  • Key consequence: a single pass that scores γ+1 positions at once costs almost the same wall-clock time as a pass scoring one position — there is spare parallel slack to exploit.

The draft → verify → accept loop, per cycle:

  • Draft. A cheap model q autoregressively guesses the next γ tokens (typically γ ≈ 4–7).
  • Verify in parallel. The target p scores the prefix plus every drafted token in one forward pass — nearly free relative to running p γ times.
  • Accept / correct. A modified rejection rule walks the drafts left-to-right, accepting each, and on the first rejection resamples one corrected token and discards the rest.

Each cycle emits between 1 and γ+1 tokens while invoking the expensive model only once. It composes with the KV cache and with other acceleration techniques.

02 Intuition: autocomplete + proofreader

  • Easy tokens are common. Much of generated text is predictable — closing brackets, common words, boilerplate. A small model gets these right most of the time; the big model only has to check them, which it does in bulk.
  • Verification is cheaper than generation. Asking "are these γ tokens what I would have produced?" runs in parallel; generating them runs serially.
  • Mental model. The draft model is a fast typist filling in obvious words; the target is a meticulous proofreader who reads the whole proposed phrase at once, keeps the correct prefix, and fixes the first mistake — and whose corrections make the final text indistinguishable from text it would have written alone.

03 The acceptance rule, and why it is lossless

At a position, the draft samples x ~ q. Let q(x) be the draft probability and p(x) the target probability for that token.

Accept x with probability tied to how well the draft matched the target:

accept x with probability min(1, p(x) / q(x))
  • If p(x) ≥ q(x) the target likes it at least as much as the draft did — always accept.
  • If p(x) < q(x), accept with probability p(x)/q(x); otherwise reject.

On a rejection, resample one token from the normalized residual distribution:

p′(x) = max(0, p(x) − q(x)) / ∑x′ max(0, p(x′) − q(x′))

Distribution-preservation proof (per position)

The probability the loop outputs token x is the chance it was accepted plus the chance it was reached as a resample:

P(output = x) = min(p(x), q(x)) + (p(x) − min(p(x), q(x))) = p(x)
  • The accepted mass is min(p, q); the leftover p − min(p, q) = max(0, p − q) is exactly recovered by the resample step.
  • So P(output = x) = p(x) for any draft q — the draft affects only speed, never the output distribution. Chaining over the accepted run preserves the full sequence distribution.
  • This is the exact rule, and it is lossless. Relaxed schemes (see variants) trade exactness for more accepted tokens.

04 The speedup calculus: α, γ, and c

Let α be the expected per-token acceptance probability (the acceptance rate), assuming tokens accept independently. Acceptance behaves like a capped geometric process — stop at the first reject, cap at γ, plus one guaranteed corrected/bonus token:

E[tokens] = (1 − αγ+1) / (1 − α)

(As α → 1 this tends to γ+1; as α → 0 it tends to 1.)

Let c = Cdraft / Ctarget be the cost ratio of one draft step to one target step, with c ≪ 1. A cycle costs roughly γ draft steps plus 1 target verification ≈ (γc + 1) target-step-equivalents, and yields E[tokens]:

Speedup = (1 − αγ+1) / ((1 − α)(γc + 1))
  • There is an optimal γ for each (α, c): larger γ raises potential tokens but also raises draft overhead γc and lowers the effective per-token accept chance. More drafting is not always better.
  • A net win requires roughly α > c: the draft must agree often enough to pay for its own cost.
  • α is fundamentally bounded by how far the draft q diverges from the target p — a draft too far from the target accepts rarely. Distilling the draft to mimic the target (or fine-tuning it on the target's own outputs) raises α.

06 When it wins, when it fails

Wins

  • Memory-bandwidth-bound regimes: low-to-moderate batch size / low concurrency, latency-sensitive single- or few-stream serving — where the target's parallel slack exists to absorb verification.
  • Long outputs and large targets: the bigger the target, the more a cheap draft is worth.
  • Predictable structure: code and grounded summarization tend to show higher acceptance.

Failure modes

  • High concurrency / large batches. Once the target is already compute-saturated by many parallel requests, the "free" verification slack vanishes; speedup shrinks and can plateau (degradation reported around ~20–30+ concurrent requests on a single GPU). Tensor parallelism across GPUs mitigates this — a core LLMOps serving trade-off.
  • Poor draft–target alignment / low α. Off-the-shelf drafts underperform on domain-shifted data; rejected drafts are wasted compute.
  • γ set too high under load wastes draft work on tokens that get rejected, causing latency spikes.
  • Memory overhead: an independent draft means a second set of weights resident in GPU memory.

Tuning knobs: draft size/quality (drives both α and c), γ (has an optimum), acceptance scheme (exact vs. relaxed), and whether drafting is a single chain or a branching tree.

07 Variant taxonomy (and lossless vs. lossy)

All differ mainly in how the draft is produced and how candidates are verified.

  • Independent draft model lossless — a separate small LLM, often a smaller member of the same family. Classic, exact with the rejection rule above. Cost: extra weights + alignment burden.
  • Self-speculative / layer-skipping lossless — the target itself drafts by skipping or early-exiting layers, then verifies with the full stack. No second model, no extra weights, inherently aligned.
  • Medusa lossy — adds a few lightweight extra decoding heads on the frozen target's last hidden state, each predicting a future position; candidates combined via tree attention. Uses a typical-acceptance threshold, so it is not distribution-identical. Only the heads are trained.
  • EAGLE (and EAGLE-2/3) — drafts autoregressively at the feature level (the hidden state before the LM head) rather than the token level, reducing uncertainty that hurts token-level drafting; later versions add dynamic draft trees and multi-layer feature fusion. Among the highest accepted lengths reported.
  • Lookahead model-free — training-free Jacobi-style parallel iteration that generates and verifies n-grams against the target, maintaining an n-gram pool. No draft model, no datastore.
  • Prompt / retrieval lookup (n-gram) — draft by copying n-grams from the prompt or a corpus; cheap and effective when output echoes input (RAG, editing, code).

Verification structure. Token-tree / tree attention verifies many candidate continuations (a branching tree of guesses) in one pass via a custom attention mask, raising the expected accepted length beyond a single linear draft chain — building directly on the attention mechanism.

Lossless vs. lossy. The exact modified-rejection rule (independent draft, self-speculative with full verification) preserves p exactly. Threshold / typical-acceptance schemes (e.g. Medusa) trade a small, usually-benign distribution change for more accepted tokens — so "speculative decoding is lossless" is only fully true for the exact variants.

08 Reported speedups (directional)

  • ~2–3× per-token latency is typical for single-stream serving at moderate acceptance (roughly α ≥ 0.6, γ ≥ 5), with zero quality loss for the exact rule and no retraining of the target.
  • Encoder-decoder, 11B-class target: ~3.4× translation (greedy), ~3.1× summarization (greedy), ~2.6× translation (sampling) — identical outputs.
  • 70B-class decoder, distributed: ~2×–2.5× (e.g. ~1.9× summarization, ~2.0× greedy, ~2.5× code) with no quality change; a wide-shallow draft limits communication overhead.
  • Variant numbers (relaxed acceptance, so not distribution-identical) are approximate and hardware/task dependent: Medusa ~2×–2.5×; Lookahead ~1.5×–2.3×; the EAGLE family among the strongest. Treat all of these as directional, not canonical.

09 Takeaways

  • Draft cheap, verify in parallel, accept a run. It converts serial big-model work into parallel big-model work plus cheap serial small-model work.
  • The exact rejection rule is provably lossless — output equals the target's distribution for any draft. Relaxed schemes (Medusa-style thresholds) are lossy by design.
  • Speedup ≈ (1 − αγ+1) / ((1 − α)(γc + 1)): win requires α > c, and γ has an optimum.
  • Best at low concurrency; high batch sizes erode the gain. A serving decision that lives in LLMOps.
  • Raise α by aligning the draft — same-family drafts, self-speculation, or distillation onto target outputs. Composes with the KV cache and the rest of the acceleration stack.
