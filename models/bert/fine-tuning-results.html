16 [CLS], the pooler, and what "C" actually is

The paper defines C as "the final hidden vector corresponding to the first input token ([CLS])" and computes classification as log(softmax(C·Wᵀ)). The released code adds a layer the paper does not mention.

paper (§4.1)logits = W · C W ∈ ℝ^(K × H) released code and the Transformers librarypooled = tanh( W_p · T_[CLS] + b_p ) logits = W · Dropout(pooled) + b
  • The pooler is an H × H dense layer with tanh, trained during pretraining by the NSP objective. BertModel returns it as pooler_output; the library documents it as "the classification token after processing through a linear layer and a tanh activation function … trained from the next sentence prediction (classification) objective during pretraining".
  • BertForSequenceClassification and BertForMultipleChoice classify from pooler_output; token classification and question answering ignore it and use the per-token states.
  • Models pretrained without NSP have no trained pooler: RoBERTa's classification head applies its own dense + tanh layer on the first token, initialised from scratch during fine-tuning.
  • Practical consequence: last_hidden_state[:, 0] and pooler_output are different vectors. Neither is a good sentence embedding without further training (§28).
Takeaway: in the released model, classification reads tanh(W_p·T_[CLS]), not the raw C of the paper. The difference is one pretrained H × H layer — 590,592 parameters in Base.

18 Span question answering: start, end, and the no-answer threshold

For SQuAD the paper adds only a start vector S and an end vector E. Each passage token gets a start score S·Tᵢ and an end score E·Tⱼ; the best span maximises their sum subject to j ≥ i. For SQuAD 2.0, "no answer" is a span that starts and ends at [CLS].

start distribution (end is analogous)P_start(i) = exp(S·Tᵢ) / ∑ⱼ exp(S·Tⱼ) training objective: log-likelihood of the correct start and endℒ = − log P_start(i*) − log P_end(j*) SQuAD 2.0 decision, threshold τ tuned on dev to maximise F1s_null = S·C + E·C ŝ = max_(j ≥ i) S·Tᵢ + E·Tⱼ answer iff ŝ > s_null + τ
Decoding a span from start and end scores toy scores · the best valid span and the no-answer comparison are recomputed as you move τ and the length limit

The start and end scores are invented for illustration (a trained model produces them as S·Tᵢ and E·Tⱼ); every probability, the best span, and the decision are computed from them. The maximum-length limit is a decoding heuristic used by the released SQuAD script (a flag, default 30 tokens), not part of the paper's formula.

  • Start and end are predicted independently; the constraint j ≥ i is applied only at decoding. The most probable start and the most probable end can form an invalid span, which is why decoding searches pairs.
  • Passages longer than the window are split into overlapping chunks (the released script uses a stride, doc_stride, default 128) and the best-scoring span across chunks wins.
  • Recipes: SQuAD v1.1 — 3 epochs, learning rate 5e-5, batch 32 (the best system first fine-tuned on TriviaQA); SQuAD v2.0 — 2 epochs, 5e-5, batch 48, no TriviaQA.
Takeaway: span QA is two token-classification heads plus a search over valid pairs. Unanswerable questions reuse [CLS] as a null span, and a dev-tuned margin τ decides between the best span and "no answer".

Instability on small datasets

  • The paper: "for BERT-Large we found that fine-tuning was sometimes unstable on small datasets, so we ran several random restarts and selected the best model on the Dev set". Restarts changed only data shuffling and classifier initialisation.
  • Later analyses located causes. "On the Stability of Fine-tuning BERT" (arXiv 2006.04884) attributes failed runs mainly to optimisation difficulty early in training (vanishing gradients) and recommends small learning rates with bias correction and more iterations. "Revisiting Few-sample BERT Fine-tuning" (arXiv 2006.05987) points to the released optimizer omitting Adam's bias correction (§32), and finds that re-initialising the top layers and training longer both help.
  • Large datasets (100k+ examples) were "far less sensitive to hyperparameter choice", per the paper.

Alternatives to full fine-tuning

  • Feature-based use keeps BERT frozen (§20). Adapters were first demonstrated on BERT ("Parameter-Efficient Transfer Learning for NLP", arXiv 1902.00751), and low-rank updates generalise the idea — see PEFT and discriminative learning rates.
Takeaway: small learning rate (2e-5 to 5e-5), warm-up, 2–4 epochs, and several seeds on small data. Report a mean over seeds, not the best run.

20 The feature-based alternative: which layers to use

Section 5.3 of the paper freezes BERT-Base, extracts activations from one or more layers, and feeds them to a randomly initialised two-layer 768-dimensional BiLSTM for CoNLL-2003 NER — the ELMo way of using a pretrained model.

  • The last layer is worse than the second-to-last (94.9 vs 95.6): the top layer is most specialised to the pretraining objective. This is a common reason for using a middle or second-to-last layer when extracting frozen features.
  • Advantages the paper gives for feature extraction: tasks whose outputs do not fit an encoder, and the cost saving of computing representations once and running many cheap experiments on top.
Takeaway: frozen BERT features are nearly as good as fine-tuning for NER if you combine the top few layers; the very last layer alone is not the best choice.

21 What BERT learns: attention patterns and probing

A 2019 wave of analysis papers ("BERTology") asked what the pretrained model encodes without any task supervision. Two results are the most cited: individual attention heads align with specific syntactic relations, and different kinds of linguistic information peak at different depths.

Single attention heads as dependency parsers (BERT-Base) sort or filter · each bar is the best single head's accuracy against a fixed-offset baseline · gains are computed

From "What Does BERT Look At?" (arXiv 1906.04341), Table 1, evaluated on the Wall Street Journal dependency annotations. For each relation, the accuracy is how often the dependent's most-attended word is its head, for the single best head (layer-head in the label); the baseline always predicts a fixed relative position (offset in parentheses). "All" asks one head to handle every relation, which no head does well.

Attention patterns

  • Heads fall into recurring patterns: attend broadly, attend to the next or previous token, attend to [SEP], attend to punctuation. Over half of BERT-Base's attention in layers 6–10 goes to [SEP] — against about 1/64 expected for a token appearing twice in 128 — which the authors interpret as a "no-op" when a head's pattern does not apply.
  • Specific heads track syntax: direct objects attend to their verbs (86.8%), determiners to their nouns (94.3%), and one head (5-4) links coreferent mentions with 65% antecedent accuracy, close to a rule-based system (69%).
  • Caution: attention weights are not explanations by themselves; a head can attend to a token whose value vector contributes little. Probing results show what is decodable, not what the model uses.

Layer-wise probing

  • "BERT Rediscovers the Classical NLP Pipeline" (arXiv 1905.05950) trains small probes on mixtures of BERT-Large's layers and finds the order in which information peaks follows the traditional pipeline: "POS tagging, parsing, NER, semantic roles, then coreference" — syntax lower, semantics higher — with the model able to revise lower-level decisions using higher-level context.
  • This matches the feature-based NER result (§20): useful features concentrate in upper-middle layers, and the top layer is shaped by the pretraining objective. General interpretability tools are covered on Transformers — reading the residual stream.
Takeaway: MLM pretraining alone produces heads that approximate specific syntactic relations and layers that recapitulate the NLP pipeline. These are measurements of what can be read out of BERT, not proof of how it computes its answers.
