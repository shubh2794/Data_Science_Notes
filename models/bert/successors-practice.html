24 The BERT family at a glance

Almost every successor changes one of four things: how long and on what it trains, the corruption objective, the parameter budget, or the attention and position scheme. Read the table as a list of ablations that stuck.

  • The through-line: training longer on more data, and getting a loss from more positions, beat architectural novelty for most of 2019–2021.
Takeaway: if you are choosing an encoder today, start from a modern one; the original checkpoint is a reference point and a baseline, not the strongest option.

25 ELECTRA: a loss on every token

MLM gets a gradient from ~15% of positions. ELECTRA keeps a small MLM model as a generator and trains the main model — the discriminator — to say, for every position, whether the token is original or was replaced by a generator sample.

generator (MLM) and discriminator (per-token binary)x̂ᵢ ~ p_G( xᵢ | x_masked ) for i ∈ m D(x, t) = sigmoid( wᵀ h_D(x)ₜ ) combined objective (λ = 50 in the paper)min ∑ₓ ℒ_MLM(x, θ_G) + λ · ℒ_Disc(x, θ_D)
  • If the generator happens to sample the original token, that position is labelled "original" — so the discriminator is never asked to call a correct token fake.
  • The generator works best at 1/4 to 1/2 the discriminator's size; a generator that is too strong makes the task too hard. The generator is discarded after pretraining; only the discriminator is fine-tuned.
  • ELECTRA's own ablation separates the two benefits: "ELECTRA 15%" (discriminator loss only on the masked 15%) does much worse than full ELECTRA, so most of the gain comes from learning from all positions; "Replace MLM" (no [MASK] in the input) slightly beats BERT, so removing the mismatch helps a little.
  • Efficiency: ELECTRA-Small (14M parameters) trained 4 days on one GPU scores 79.9 GLUE dev, above GPT-1 (78.8), which used about 30× more training compute.
Takeaway: ELECTRA fixes MLM's two weaknesses at once — sparse loss and the [MASK] mismatch — and most of the gain comes from the dense loss. It is the strongest argument that BERT's objective, not its architecture, was the bottleneck.

26 RoBERTa, ALBERT, DistilBERT, DeBERTa and ModernBERT in more detail

What each successor measured, with the numbers that justify its design.

RoBERTa — the same model, trained properly

  • Data: BooksCorpus + Wikipedia (16GB), plus CC-News, OpenWebText and Stories, 160GB in total. Its Table 4 accumulates changes on the Large architecture: 16GB at 100K steps with 8K batches → +data → 300K steps → 500K steps, with SQuAD v1.1/2.0, MNLI and SST-2 rising at each step.
  • Byte-level BPE with a 50K vocabulary (as in GPT-2) instead of WordPiece, so there is no [UNK]; peak learning rate and warm-up retuned for the large batch; Adam β₂ = 0.98 for stability.

ALBERT — fewer parameters, not fewer FLOPs

  • Factorised embedding: the vocabulary is embedded into E = 128 dimensions and projected to H. For V = 30,000 and H = 4,096 (xxlarge) that is 30,000·128 + 128·4,096 ≈ 4.4M instead of 30,000·4,096 ≈ 123M parameters.
  • Cross-layer sharing: all layers use the same weights, so parameters stop growing with depth — but each layer still costs the same compute. ALBERT-xxlarge (235M parameters, H = 4,096) is listed as 0.3× BERT-large's training speed.

DistilBERT — compression by distillation

  • Student initialised from every other layer of BERT-Base; trained with a soft-target distillation loss, the MLM loss and a cosine loss aligning hidden states. The resulting 66M-parameter model is 71% faster than BERT-Base on a phone for QA (excluding tokenisation).

DeBERTa — separate content and position

  • Each token has a content vector and uses relative-position embeddings; attention scores sum content-to-content, content-to-position and position-to-content terms. Absolute positions enter only in the "enhanced mask decoder" just before the MLM output.
  • A DeBERTa-Large trained on half of RoBERTa-Large's data beat it on MNLI, SQuAD v2.0 and RACE (per its abstract).

ModernBERT — a 2024 encoder with decoder-era engineering

  • 22 layers (Base, 149M) and 28 layers (Large, 395M); every third layer global attention (RoPE θ = 160,000), the rest a 128-token sliding window (θ = 10,000); vocabulary 50,368 (a multiple of 64); trained on 1.7T tokens at length 1,024, then extended to 8,192 over another 300B tokens.
  • Unpadding removes padding tokens and processes a batch as one concatenated sequence with variable-length attention kernels; together with local attention this is what makes 8k inputs affordable.
Takeaway: RoBERTa is "BERT without NSP, trained ten times harder"; ALBERT trades parameters for compute; DistilBERT compresses; ELECTRA and DeBERTa change the objective and the attention; ModernBERT imports the long-context machinery of modern decoders.

27 BERT vs GPT vs encoder–decoder (T5)

The three Transformer families differ in one mask and one objective. The decision guide in general is Encoder–Decoder Models — choosing; this is the BERT-centred comparison.

BERT (encoder-only)GPT (decoder-only)T5 (encoder–decoder)
Attentionbidirectional in every layercausal in every layerbidirectional encoder; causal decoder with cross-attention
Pretraining objectivemasked-token reconstruction (+ NSP originally)next-token predictionspan corruption: masked spans replaced by sentinels, reconstructed by the decoder
Positions that give a loss~15% of inputsevery positionthe target tokens (about 15% of input tokens corrupted in T5's default)
Generates textnoyesyes, conditioned on the input
Scores a string's probabilityno (pseudo-likelihood at best)yes, exactlyyes, conditionally
Task interfacetask-specific head per taskprompting or fine-tuning, same output layerevery task as text-to-text
Typical strengthsclassification, tagging, span extraction, embeddings, rerankingopen-ended generation, few-shot use of one modeltranslation, summarisation, input-conditioned generation
  • At matched 12 × 768 size, BERT-Base beat GPT-1 on every GLUE task in Table 1 — the fair small-scale comparison favours bidirectionality for understanding tasks.
  • T5's large study (arXiv 1910.10683) found a denoising objective with an encoder–decoder performed best among the objectives it compared on its benchmark mixture; decoder-only models later became the default at large scale for reasons (one stack, dense loss, a prompt interface) that no single controlled comparison settles.
  • For an input that fits in context, a decoder can emulate an encoder by reading the input as a prompt, but with a causal rather than bidirectional mask over it.
Takeaway: choose by output type. A label, a tag or a vector — an encoder. Free text — a decoder or an encoder–decoder.

28 BERT as an embedding model, and Sentence-BERT

Taking a vector straight out of a pretrained BERT and comparing it with cosine similarity works poorly. Sentence-BERT's Table 1 measures how poorly, and its fix — fine-tuning a siamese bi-encoder — is the basis of most dense retrieval models.

Sentence representation (no STS training)Average Spearman ρ × 100 over seven STS sets
BERT [CLS] vector29.19
Mean of BERT token vectors54.81
Mean of GloVe word vectors61.32
SBERT-NLI-base (BERT fine-tuned on NLI as a bi-encoder)74.89
SBERT-NLI-large76.55

Why raw BERT vectors disappoint

  • Nothing in MLM asks any single vector to summarise a sentence, and [CLS] was trained only by NSP; the paper itself says C is not a meaningful sentence representation without fine-tuning.
  • Contextual embeddings are anisotropic — they occupy a narrow cone, so unrelated sentences already have high cosine similarity ("How Contextual are Contextualized Word Representations?", arXiv 1909.00512). Post-hoc whitening (centre and decorrelate) partly corrects this without training.

What Sentence-BERT does

  • One BERT encodes each sentence separately (shared weights); vectors are mean-pooled (its default, which beat [CLS] pooling). For NLI training a classifier sees (u, v, |u − v|); at inference only cosine similarity of u and v is used.
  • Cost: finding the most similar pair among 10,000 sentences takes about 50 million cross-encoder passes (~65 hours with BERT, per the paper) versus about 5 seconds to embed each sentence once with SBERT and compare vectors.
  • Modern retrievers train the same bi-encoder with in-batch contrastive losses (Contrastive Learning — the InfoNCE loss) and store the vectors in an approximate-nearest-neighbour index (Vector Databases). A cross-encoder BERT then reranks the top candidates. BERT embeddings also underlie the BERTScore metric (NLP Evaluation Metrics).
mean pooling with the attention mask mv = ( ∑ᵢ mᵢ · Tᵢ ) / ( ∑ᵢ mᵢ ) in-batch contrastive objective, temperature τℒ = − log [ exp(sim(vᵢ, vᵢ⁺)/τ) / ∑ⱼ exp(sim(vᵢ, vⱼ)/τ) ]
Takeaway: a pretrained BERT gives good token representations, not good sentence vectors — averaged GloVe beats averaged BERT on STS. Sentence-level geometry has to be trained, and a bi-encoder makes search a dot product instead of a forward pass per pair.

29 Using BERT with the Transformers library

The original checkpoints are on the Hub under the google-bert/ namespace (for example google-bert/bert-base-uncased). The notes below follow the library's v5 documentation.

Fill a mask

from transformers import pipeline fill = pipeline(task="fill-mask", model="google-bert/bert-base-uncased") fill("Plants create [MASK] through a process known as photosynthesis.")

Load a model and tokenizer explicitly

import torch from transformers import AutoTokenizer, AutoModel tok = AutoTokenizer.from_pretrained("google-bert/bert-base-uncased") model = AutoModel.from_pretrained("google-bert/bert-base-uncased", attn_implementation="sdpa") batch = tok(["a first text", "a second, longer text"], padding=True, truncation=True, max_length=512, return_tensors="pt") with torch.no_grad(): out = model(**batch) out.last_hidden_state.shape # (2, n, 768): one vector per token out.pooler_output.shape # (2, 768): tanh(W_p · h_[CLS] + b_p)

Things the documentation states that are easy to miss

  • "Inputs should be padded on the right because BERT uses absolute position embeddings."
  • BertConfig() defaults reproduce bert-base-uncased: vocab_size=30522, hidden_size=768, num_hidden_layers=12, num_attention_heads=12, intermediate_size=3072, hidden_act="gelu", dropouts 0.1, max_position_embeddings=512, type_vocab_size=2, initializer_range=0.02, layer_norm_eps=1e-12, pad_token_id=0.
  • In v5, BertTokenizer is the Rust-backed WordPiece tokenizer (the role BertTokenizerFast used to have); the pure-Python implementation is BertTokenizerLegacy. AutoTokenizer picks the right one.
  • The tokenizer returns token_type_ids (segment ids) when given two texts: tok(question, passage) builds [CLS] question [SEP] passage [SEP] with segment 0 then 1.
Takeaway: AutoTokenizer + the BertFor… class matching the head you need; pad on the right; set truncation=True and max_length=512 deliberately; and remember pooler_output is not the raw [CLS] state.
