Donut — OCR-free Document Understanding

An OCR-free document model: instead of running a separate OCR engine and parsing its text, Donut (Document understanding transformer) reads the raw page pixels with a vision encoder and generates the answer directly — a JSON record, a class, a VQA answer — with a Transformer decoder.

01 Why drop OCR?

The classic VDU pipeline is image → OCR → text + boxes → model. Making OCR a hard dependency causes three problems Donut removes.

  • Cost & latency: a separate OCR system is heavy compute on every document.
  • Inflexibility: OCR engines are brittle across languages and document types.
  • Error propagation: an OCR mistake ("0"→"O") flows downstream and the model never sees the truth.
One line: Donut is a vision encoder → text decoder trained end-to-end to map a document image straight to structured output — no OCR in the loop. This is end-to-end learning applied to documents.

03 Architecture

document image ─▶ [ Swin Transformer encoder ] ─▶ image tokens ─▶ [ BART-style decoder ] ─▶ structured text (JSON)
Vision encoder → text decoder the decoder cross-attends to the encoded image
  • Vision encoder: a Swin Transformer turns the page image into a sequence of visual embeddings (hierarchical, windowed attention — good for high-resolution pages).
  • Text decoder: a BART-like autoregressive decoder that generates tokens conditioned on the image embeddings via cross-attention — see Encoder–Decoder Models.
  • Structured output via prompts: a task start-token steers the decoder; for key-information extraction it emits a JSON-like sequence with special field tokens, parsed back into a record.

04 Pretraining: "read the document"

  • Pretext task = pseudo-OCR. Donut is pretrained to read all text in an image (left-to-right, top-to-bottom), which teaches the encoder–decoder to see characters without an external OCR engine.
  • SynthDoG — a Synthetic Document Generator renders millions of realistic pages in multiple languages from text corpora + backgrounds, so pretraining isn't bottlenecked by labeled real documents.
  • Fine-tuning per task: document classification, key-information extraction (CORD receipts, tickets), and DocVQA — each framed as "generate the target sequence."

06 DONUT-hole — making it small

  • Donut's encoder–decoder is sizable; DONUT-hole (2023) compresses it for edge and production key-information-extraction (e.g. logistics).
  • How: knowledge distillation + pruning ("sparsification") — cut model density by ~54% while preserving accuracy.
  • Fidelity check: a Centered Kernel Alignment (CKA) of ~0.79 between original and sparsified representations shows the compressed model keeps the teacher's internal structure.

08 Takeaways

  • OCR-free = a vision encoder–decoder maps document pixels straight to structured output, removing OCR's cost, brittleness, and error propagation.
  • Swin encoder + BART decoder, pretrained to "read" pages, with SynthDoG synthetic data filling the data gap.
  • DONUT-hole distills + prunes it ~54% smaller for edge deployment.
  • The generative, OCR-free counterpart to the OCR-based LayoutLM; an end-to-end take on Document Intelligence.
