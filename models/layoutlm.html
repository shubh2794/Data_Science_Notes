LayoutLM (v1 · v2 · v3)

The model family that brought pretrain-then-fine-tune to visually-rich documents — forms, receipts, invoices, scanned pages. A document isn't just a string of words; where each word sits on the page carries meaning. LayoutLM fuses three modalities — text, 2D layout, and image — in one Transformer.

01 The problem: documents are 2D

  • Plain BERT reads a 1D token stream and throws away the page geometry. But in a form, the label "Total:" and the value "$42.00" mean what they do because of their positions.
  • Visually-rich Document Understanding (VDU) tasks: form/receipt key-value extraction, document classification, document VQA, layout analysis.
  • LayoutLM's idea: feed each token its 2D bounding box (from OCR) alongside the word, so attention can reason over spatial relationships — see Document Intelligence.
One line: LayoutLM = a Transformer encoder that adds 2D positional embeddings (and, increasingly, image features) to text, pretrained on millions of scanned documents, then fine-tuned for extraction, classification, and QA.

02 Layout = 2D position embeddings

Each OCR word comes with a bounding box (x₀, y₀, x₁, y₁), normalized to a 0–1000 grid. LayoutLM embeds those coordinates and adds them to the token embedding. Click a field to see its box.

Bounding boxes → 2D embeddings click a word on the mock invoice
embedding(word) = token + x₀-emb + y₀-emb + x₁-emb + y₁-emb + (width, height) + 1D-position
  • Four coordinate embedding tables (two axes × two corners) plus width/height capture position and size.
  • So two words far apart on the page can attend to each other, and a label can bind to the value beside it — not just the next token in reading order.

03 Architecture

All three versions are a single Transformer encoder fed multiple modalities — what changes is how the image enters and which pretraining objectives bind the modalities. Switch versions to see the wiring.

04 LayoutLM v1 — text + layout

  • Backbone: BERT encoder + the 2D position embeddings above. Image features (Faster R-CNN ROI vectors) are added only at fine-tuning, not during pretraining.
  • Pretraining: Masked Visual-Language Modeling (MVLM) — mask tokens but keep their 2D positions, and predict the word from text + layout context. Plus optional Multi-label Document Classification.
  • Data: IIT-CDIP — ~11M scanned document images.
  • Results (2019): FUNSD 70.7→79.3, receipt (SROIE) 94.0→95.2, RVL-CDIP classification 93.1→94.4.

05 LayoutLM v2 — image in the Transformer

  • Image joins pretraining. A CNN backbone (ResNeXt-FPN) turns the page into a grid of visual tokens that are concatenated with the text+layout tokens into one sequence.
  • Spatial-aware self-attention: a learned relative 2D position bias is added to the attention scores, so "how far apart, and in which direction" directly shapes attention.
  • New objectives alongside MVLM: Text-Image Alignment (predict whether a token's image region was covered) and Text-Image Matching (are this image and text from the same document?).
  • Results: big jumps — FUNSD 0.79→0.84, CORD 0.95→0.96, SROIE 0.95→0.98, RVL-CDIP 0.944→0.956, and DocVQA 0.73→0.87.

06 LayoutLM v3 — unified text & image masking

v3's big simplification: drop the CNN. Treat the image as linear patches (ViT-style) and pretrain text and image with symmetric masking objectives.

ObjectiveWhat it does
MLM (text)Mask words, predict them from text + layout + image context
MIM (image)Mask image patches, predict their discrete visual tokens (BEiT-style tokenizer)
WPA (alignment)Word-Patch Alignment — predict whether a word's corresponding image patch is masked, tying the two modalities together
  • No object-detection backbone → simpler and more parameter-efficient, and the first model to be SOTA on both text-centric (FUNSD, CORD, DocVQA) and image-centric (RVL-CDIP classification, PubLayNet layout analysis) tasks.
  • Unifying the objectives — same masking philosophy for words and patches — is the conceptual core, echoing Transformer + ViT patch tokenization.

08 Takeaways

  • Layout is a modality. Adding 2D bounding-box embeddings to text lets a Transformer reason over page geometry.
  • The arc: v1 fuses text+layout (image late) → v2 pulls image into pretraining with spatial-aware attention → v3 unifies text & image under symmetric masking and drops the CNN.
  • Needs an OCR step to get words + boxes — contrast with the OCR-free Donut.
  • Builds on BERT; the document-domain hub is Document Intelligence.
