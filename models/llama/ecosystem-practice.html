25 Licence and the "open weights" caveat

Llama is usually called open, but what is open is the weights and inference code. Training data and training code are not released, and each generation ships under Meta's own licence and acceptable-use policy rather than a standard open-source licence.

ReleaseLicence terms most often relevant
LLaMA 1Non-commercial research licence; weights granted to researchers on request. The weights circulated publicly about a week after release, outside that process.
Llama 2Community licence permitting commercial use; a separate licence is needed if the licensee's products had more than 700 million monthly active users on the release date; outputs could not be used to improve other large language models.
Llama 3Similar terms, adding attribution ("Built with Meta Llama 3") and a naming requirement for derivative models.
Llama 3.1 – 3.3Output use changed: the licence allows using model outputs, including synthetic data and distillation, to improve other models.
Llama 3.2 vision, Llama 4The acceptable-use terms withheld the multimodal models' rights from individuals and companies based in the EU (for 3.2 vision); Llama 4 ships under its own community licence.
  • The Open Source Initiative has stated that the Llama licences do not meet the Open Source Definition — mainly because of the usage restrictions and the user-count clause.
  • For research on training dynamics, "open weights" is less than it sounds: without the data, results cannot be reproduced and contamination cannot be checked.
  • This page summarises; it is not legal advice. Read the licence of the exact checkpoint you use.
Takeaway: Llama is open-weight, not open-source: downloadable parameters, a custom licence with a user-count threshold and use policy, and no training data.

26 The ecosystem: Alpaca, Vicuna, Code Llama, quantised GGUF

LLaMA's weights arrived when capable open models were scarce, and within weeks a small ecosystem had formed around them: cheap instruction-tuned derivatives, domain continuations, and tools for running the models on consumer hardware.

ProjectBaseWhat it did
Alpaca (Stanford, Mar 2023)LLaMA 7BFine-tuned on 52K instruction-following demonstrations generated by a proprietary model with the self-instruct method — showing that a small SFT set produces chat-like behaviour.
Vicuna (Mar 2023)LLaMA 13BFine-tuned on about 70K user-shared ChatGPT conversations; popularised evaluation with a strong model as judge (see LLM-as-a-Judge).
QLoRA (May 2023)LLaMA up to 65B4-bit frozen base plus LoRA adapters, fine-tuning a 65B on one 48 GB GPU (see PEFT — QLoRA).
Code Llama (Aug 2023)Llama 2Continued training on 500B tokens of code (7B, 13B, 34B; a 70B followed on 1T), then long-context fine-tuning at 16,384 tokens with the RoPE base raised from 10,000 to 1,000,000 — an early instance of raising the base for long context.
Llama Guard (Dec 2023)Llama 2 7BAn input/output safety classifier fine-tuned from a Llama, later versions built on Llama 3.
llama.cpp and GGUFany LlamaA C/C++ inference engine for CPUs and consumer GPUs; GGUF (August 2023) is its single-file format carrying weights, tokenizer and metadata, with block-quantised types such as Q8_0 and Q4_0.
Memory to run a Llama: weights at a given precision, plus KV cache pick a model and a storage format · bits per weight are computed from the block layout · slide context

Q8_0 stores 32 weights as 32 int8 values plus one 16-bit scale (8.5 bits per weight); Q4_0 stores 32 four-bit values plus one 16-bit scale (4.5). Mixed "K-quant" files use different types for different tensors and land roughly between these; see Model Acceleration — quantisation.

Takeaway: much of Llama's influence came from what others built on the weights — instruction-tuned derivatives, adapters, a code family and CPU-friendly quantised formats — and from the fact that all of them could be published.

27 Using Llama with Hugging Face Transformers

Llama 1–3.x text models load as LlamaForCausalLM; Llama 4 as Llama4ForConditionalGeneration. Meta's repositories are gated: the licence must be accepted on the Hub before the weights download.

Chat generation (Llama 3.x)

import torch from transformers import AutoModelForCausalLM, AutoTokenizer model_id = "meta-llama/Llama-3.1-8B-Instruct" tok = AutoTokenizer.from_pretrained(model_id) model = AutoModelForCausalLM.from_pretrained(model_id, dtype=torch.bfloat16, device_map="auto") messages = [{"role": "system", "content": "Answer in one sentence."}, {"role": "user", "content": "What does RMSNorm drop?"}] inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt", return_dict=True).to(model.device) out = model.generate(**inputs, max_new_tokens=64) print(tok.decode(out[0, inputs["input_ids"].shape[-1]:], skip_special_tokens=True))

What the template produces

Options worth knowing

  • dtype (formerly torch_dtype): use bf16 for Llama 3.x and 4; the Transformers docs warn that training in float16 "is known to produce nan".
  • attn_implementation: "sdpa" is the default path; "flash_attention_2" needs fp16/bf16; Llama 4's long-context example uses "flex_attention" with the "hybrid" cache.
  • Quantised loading: the docs show int4 weight-only with TorchAoConfig("int4_weight_only", group_size=128).
  • num_key_value_heads selects MHA, GQA or MQA; head_dim defaults to hidden_size / num_attention_heads but is explicit in the 3.2 configs. In Transformers v5 the config takes RoPE settings as one rope_parameters dictionary (base plus any scaling); released config.json files still use the older rope_theta / rope_scaling keys.
  • Converting Meta's original checkpoints uses the library's Llama conversion script with --llama_version; it performs the Q/K permutation noted in §09.
Takeaway: load with bf16, let apply_chat_template build the prompt, and trust the config for architecture details. Most failures come from the prompt format and special tokens, not the model (§29).
