Multimodal Models

A multimodal model is a network whose inputs, outputs, or both span more than one modality — here, images and text. This hub covers the vision–language branch: dual encoders such as CLIP that map an image and a caption into one shared embedding space, and generative vision–language models such as LLaVA, BLIP-2 and PaliGemma that turn an image into a sequence of tokens a language model can read. The members differ mainly in one question — how pixels become something a text model can use — and this page compares the answers: the connector, the number of visual tokens, what is frozen, and how the stages of training are ordered.

01 What multimodal models are

A vision–language model is a pair (or a fusion) of an image encoder and a text model, trained so that information in the image can influence what the model computes about text. Two families dominate: models that embed images and text separately and compare them, and models that generate text conditioned on an image.

dual encoder — compare in a shared spaces(I, T) = cos( f(I), g(T) ) = f(I)·g(T) / (‖f(I)‖ ‖g(T)‖) generative VLM — next-token prediction conditioned on visual tokensP(y₁…yₘ | I, x) = ∏ₜ P( yₜ | V(I), x, y₍<ₜ₎ ) V(I) = connector( encoder(I) )

Two shapes of the same idea

  • Dual encoders (CLIP, ALIGN, SigLIP) run an image tower and a text tower independently and train them with a contrastive loss so that matching pairs score higher than mismatched ones. Output: one vector per image and one per text. Uses: zero-shot classification, retrieval, and — increasingly — serving as the image encoder inside a generative model.
  • Generative VLMs (Flamingo, BLIP-2, LLaVA, PaliGemma) convert an image into a set of vectors that live in the language model's input space, then let the language model predict text. Output: free-form text — captions, answers, and, with suitable token vocabularies, even boxes and masks.
  • The two are not rivals so much as stages of one pipeline: in every generative model on this page the image encoder was itself pretrained contrastively (CLIP ViT-L/14 in LLaVA and one BLIP-2 variant, EVA-CLIP ViT-g in the other, SigLIP So400m in PaliGemma, and a contrastively pretrained NFNet-F6 in Flamingo).

What changes from member to member

Almost every member reuses a pretrained Vision Transformer and a pretrained text Transformer. What changes is the glue: a single embedding compared by cosine (CLIP), a linear or two-layer MLP projection of every patch (LLaVA), 32 learned queries that summarise the patches (BLIP-2), a resampler plus gated cross-attention layers inside a frozen language model (Flamingo), or a linear projection feeding a decoder that attends bidirectionally over image and prompt (PaliGemma). The design axes section turns those choices into a small set of questions.

Takeaway: a multimodal model is defined less by its encoders — which are usually borrowed — than by how it connects them. Dual encoders align two embeddings; generative VLMs translate an image into tokens a language model can condition on.

Six questions locate any vision–language model. Answering them for a new model usually tells you more about its cost and behaviour than its benchmark table does.

How the axes interact

  • Connector and token count are coupled. A projector keeps every patch, so tokens grow as (resolution / patch)². A query-based connector fixes the count regardless of resolution, which bounds cost but also bounds detail.
  • Freezing and objective are coupled. A frozen language model cannot adapt to a new input distribution, so the connector has to do all the translating — which is why BLIP-2 invests in a 188M-parameter Q-Former while LLaVA, which later unfreezes the LM, gets by with a projector.
  • Resolution and fusion are coupled. Prepending 4,096 visual tokens is affordable for a 2B-parameter decoder (PaliGemma at 896 px) but would be expensive for a 70B one; Flamingo's cross-attention keeps those tokens out of the LM's sequence entirely.
Takeaway: read a new VLM by filling in six cells — objective, fusion point, connector, visual tokens, frozen parts, resolution. The benchmark table then makes sense in terms of the trade-offs those cells imply.

03 How an image becomes tokens

A Vision Transformer cuts an H × W image into non-overlapping p × p patches and emits one vector per patch, plus an optional class token. Everything downstream — a single pooled vector, a projector, a set of queries — starts from that grid.

Left: the patch grid the encoder sees at the chosen resolution. Right: visual tokens the language model receives, next to its context window. For projector-style models the count follows (r / p)²; for query-based connectors it stays fixed whatever the resolution. Presets load each model's published resolution, patch size and context length.

Three ways to hand the grid over

  • Pool it to one vector. CLIP projects the class-token output (for its ViTs) into a joint embedding. One vector per image is ideal for retrieval and useless for asking where something is.
  • Project every patch. LLaVA takes the grid from the penultimate encoder layer and maps each patch vector into the LM's embedding width. Detail is preserved; cost grows quadratically with resolution. At 336 px with 14-px patches that is 576 tokens — about 14% of a 4,096-token context before a word of text.
  • Summarise with queries. BLIP-2's Q-Former learns 32 query vectors that cross-attend to the frozen patch features (257 × 1024 for CLIP ViT-L/14 at 224 px) and output 32 × 768 — the paper calls this a bottleneck that forces the queries to keep what text needs. Flamingo's Perceiver resampler does the same with 64 latents.

Resolution is where the budget bites

PaliGemma keeps every patch and trains three checkpoints at 224, 448 and 896 px: 256, 1,024 and 4,096 image tokens. Doubling the side quadruples the tokens and, with full attention over the prefix, multiplies the image-to-image attention cost by about sixteen. LLaVA-1.5-HD and later "any-resolution" designs instead tile a large image into several encoder-sized crops, encode each separately, and concatenate — trading one enormous grid for several ordinary ones plus a downsampled global view.

Takeaway: visual tokens are the main cost driver of a generative VLM. Projectors scale them with (r / p)²; query-based connectors cap them. Choose the scheme by how much fine detail the task needs.

04 Connectors: linear, MLP, Q-Former, resampler

The connector is usually the only component trained from scratch, so its size is a good first estimate of how much new learning a model has to do. Projectors are small (a few million to about 21 million parameters here); BLIP-2's query transformer is roughly ten to a hundred times larger, and Flamingo's cross-attention stack larger still.

Bars use a logarithmic axis. Projector counts are computed from the published vision and language widths; the Q-Former count is the paper's reported 188M (it contains a BERT-base-initialised Transformer plus new cross-attention layers, so it is not a two-width formula).

What each connector buys

  • Linear (LLaVA, PaliGemma): cheapest possible bridge. PaliGemma's ablation found linear and one-hidden-layer MLP connectors nearly tied when all weights were tuned (77.2 vs 77.1 average transfer score), and linear slightly ahead when everything but the connector was frozen (70.7 vs 69.7).
  • Two-layer MLP (LLaVA-1.5): the LLaVA-1.5 authors report that replacing the linear projection with an MLP improved multimodal capability. The two results are not contradictory — they come from different models, data and training regimes, and they measured different benchmarks.
  • Q-Former (BLIP-2): a 12-layer Transformer initialised from BERT-base with cross-attention to image features inserted, 32 learned queries of width 768, trained first on image–text pairs with no language model attached (contrastive, matching and generation objectives) and then as a soft prompt for a frozen LM.
  • Perceiver resampler + gated cross-attention (Flamingo): 64 latent queries summarise each image; new cross-attention layers inserted between the frozen LM's blocks read them, with a tanh gate initialised at zero so the LM starts out unchanged.
Takeaway: when the LM is trainable, a small projector appears to suffice; when the LM is frozen, the connector has to carry the translation and grows accordingly. Evidence for "MLP beats linear" is model-specific, not a general law.

05 Where vision meets language: the attention wiring

Once the image is a set of vectors, the model still has to decide who may attend to whom. The attention mask is the most compact description of an architecture: it shows whether images and text ever meet, and in which direction information flows.

A toy sequence of image tokens, a three-token text prompt and a three-token answer. Filled cells are allowed attention; the readout counts them from the rule for each design. The Flamingo panel shows visual tokens as keys reached only through the inserted cross-attention layers, never as positions in the text sequence.

Reading the five masks

  • Dual encoder: two disjoint blocks. The image tower attends bidirectionally among patches; CLIP's text tower uses a causal mask. Image and text meet only in the final dot product.
  • Projector into a causal LM (LLaVA): image tokens are simply the first positions of a decoder-only sequence. Every text token can read every image token, but image tokens cannot read the question — they are fixed before the question is known.
  • Q-Former + causal LM (BLIP-2 with OPT): the same causal pattern over far fewer image positions. The question-dependence has to be learned inside the Q-Former; in the instruction-tuned successor, InstructBLIP, the instruction is fed to the Q-Former too.
  • Prefix-LM (PaliGemma): full attention across the image and the prompt, causal attention over the answer. The paper motivates this as letting image tokens "look ahead" at the task, and its ablation found it ahead of both a fully causal mask and a causal mask on the prefix alone.
  • Cross-attention (Flamingo): text positions attend causally to text and, through separate layers, to the visual tokens of the most recent preceding image. The LM's sequence length does not grow with image count.
Takeaway: decoder-only VLMs differ from each other mainly in whether image tokens may see the prompt (prefix-LM) or not (causal), and whether images live in the sequence (prepended tokens) or beside it (cross-attention).

06 Contrastive alignment and zero-shot transfer

The dual-encoder branch is trained on a batch of N image–caption pairs by asking each image to pick out its own caption among the N, and each caption its own image. The loss is an N-way classification in both directions; the temperature decides how sharply it discriminates.

CLIP-style symmetric softmax loss, temperature τℒ = ½ [ −(1/N) ∑ᵢ log softmaxⱼ( sᵢⱼ / τ )ᵢ −(1/N) ∑ⱼ log softmaxᵢ( sᵢⱼ / τ )ⱼ ] SigLIP pairwise sigmoid loss, learnable t and b, zᵢⱼ = +1 on the diagonal, −1 off itℒ = −(1/N) ∑ᵢ ∑ⱼ log σ( zᵢⱼ · ( t·sᵢⱼ + b ) ) zero-shot classification with a dual encoderŷ = argmaxₖ cos( f(I), g("a photo of a {classₖ}") )
A batch of six pairs change temperature, alignment and loss · the matrix is cosine similarity

Similarities come from seeded random unit vectors mixed toward the matched partner by the alignment slider. The softmax loss uses 1/τ as its logit scale; the sigmoid loss uses t = 1/τ and the bias b. SigLIP initialises t = 10 and b = −10 — slide τ to 0.10 and b to −10 to see that starting point.

What the hub needs from this, and where the depth lives

  • CLIP trained on 400 million web pairs with a batch of 32,768 and a learnable logit scale initialised at 1/0.07 ≈ 14.29 and clipped at 100. Its ViT-L/14 at 336 px reached 76.2% zero-shot ImageNet top-1. The full treatment — loss, temperature, prompt ensembling, robustness — is on CLIP.
  • ALIGN showed the recipe survives far noisier data: about 1.8 billion alt-text pairs with what its authors call minimal frequency-based filtering (plus simple image-size and aspect-ratio filters), an EfficientNet image tower and a BERT text tower, 76.4% zero-shot ImageNet top-1.
  • SigLIP replaced the batch-wide softmax with an independent sigmoid per pair, removing the global normalisation. Its authors pushed the batch to one million and found gains saturate: 32k was sufficient. SigLIP's So400m encoder is the image tower PaliGemma builds on.
Takeaway: contrastive pretraining is why the image encoders inside generative VLMs already "speak" something close to language. The loss choice (softmax or sigmoid) mostly changes memory and batch-size behaviour; both produce aligned embeddings.

07 Training stages and what is frozen

Nearly every generative VLM is trained in stages: first align the new connector to the pretrained parts, then teach the whole system to follow tasks. The members disagree sharply about which weights should move at each stage.

Freeze or not

  • The case for freezing is cost and preservation. BLIP-2 reports its entire trainable set as the Q-Former and describes 54× fewer trainable parameters than Flamingo80B. A frozen LM also cannot forget its language skills.
  • The case against comes from PaliGemma: citing captioning-based encoder work, it argues captioning and localisation give the image encoder spatial and relational signal that contrastive training lacks, departs from the earlier PaLI practice of a frozen first stage. Its ablation is more nuanced than the headline: after transfer, freezing the image encoder made no measurable difference, but unfreezing it clearly lowered pretraining perplexity on spatial tasks; every option that froze the language model was significantly worse; and resetting any component hurt badly.
  • The compromise used by LLaVA — freeze everything to align the connector, then unfreeze the LM but keep the encoder frozen — is a widely copied default, especially in the LLaVA lineage of open instruction-tuned VLMs; many later models also unfreeze the encoder. That it is common is an observation about practice, not a result that it is optimal.
Takeaway: training is usually staged, but the frozen set ranges from "everything but the connector" (LLaVA's first stage, BLIP-2) to "nothing" (PaliGemma). Treat freezing as a cost/quality dial, not a fixed rule.

08 Lineage, 2019–2024

Vision–language modelling moved from task-specific fusion encoders trained on curated pairs, to contrastive dual encoders trained on the web, to generative models that bolt a pretrained image encoder onto a pretrained language model.

Vision–language lineage click a milestone · colour marks the family · rows separate the families

Dates are first arXiv submission. The readout reports the gap to the previous milestone in the same family, computed from those dates.

Three eras

  • Fusion encoders (2019): ViLBERT and LXMERT ran detector region features and words through cross-modal Transformer layers, pretrained on curated caption data (about 3.3 million Conceptual Captions pairs for ViLBERT, about 9 million image–sentence pairs for LXMERT) and fine-tuned per task. Strong on VQA, but tied to an object detector and to curated data.
  • Contrastive dual encoders (2021 onward): CLIP and ALIGN dropped the detector and the curation, scaling to hundreds of millions or billions of web pairs. SigLIP (2023) changed the loss; the resulting encoders became the default image towers for what came next.
  • Generative VLMs (2022 onward): Flamingo (2022) connected a frozen encoder to a frozen 70B LM through cross-attention and showed few-shot prompting with images. BLIP-2 (January 2023) did it with a Q-Former; LLaVA (April 2023) with a linear projector and GPT-4-generated instruction data; LLaVA-1.5 (October 2023) with an MLP and academic VQA data; PaliGemma (July 2024) with a linear projector, prefix-LM attention and nothing frozen; PaliGemma 2 (December 2024) paired the same encoder with Gemma 2 at 2B, 9B and 27B.
Takeaway: each era kept the previous era's best component. Contrastive encoders replaced detectors; generative VLMs reused the contrastive encoders and replaced task heads with a language model.

Headline results worth remembering

  • Zero-shot ImageNet: CLIP ViT-L/14@336 76.2%; ALIGN 76.4%; SigLiT (a SigLIP variant with a frozen image tower) 84.5% after two days on four TPUv4 chips.
  • Zero-shot VQAv2 (test-dev): BLIP-2 ViT-g FlanT5-XXL 65.0 against Flamingo80B's 56.3 — the source of the "8.7" headline.
  • Fine-tuned / instruction-tuned VQAv2: LLaVA-1.5 13B 80.0, 7B 78.5; LLaVA-1.5-HD 13B 81.8. Those scores are on a benchmark whose training split is in LLaVA-1.5's instruction mix, so they are not zero-shot and should not be set beside BLIP-2's 65.0.

10 Worked example: what an image costs the language model

Once projected, visual tokens pass through the language model's layers the same way text tokens do, so the standard transformer compute estimate applies to them unchanged. Doing the arithmetic once makes the token-count column of the comparison table concrete.

forward (prefill) compute for T tokens, non-embedding parameters N, L layers, width dC ≈ 2·N·T + 2·L·d·T² (second term: the attention-score term as counted in Scaling Laws, full-attention upper bound; counting the weighted sum over values as well doubles it to 4·L·d·T²) non-embedding parameters of a decoder layer with a gated feed-forward of width fN_layer = (attention projections) + 3·d·f Gemma 2B, multi-query attention (8 heads × 256, one key/value head)18 · [ 2·2048·2048 + 2·2048·256 + 3·2048·16384 ] = 1,981,808,640 ≈ 1.98B

Non-embedding parameters are computed from each model's published layer count, width, attention layout and feed-forward width (norm weights omitted), then compared with the reported figure. Compute uses the 2·N·T + 2·L·d·T² estimate for one forward pass over the whole prompt; it is an approximation that ignores the causal mask's halving of attention work and all kernel-level effects.

Reading the numbers

  • Configs reproduce the reported sizes. Llama 2 7B (32 layers, width 4096, feed-forward 11008) gives about 6.48B non-embedding parameters, plus 2 × 32,000 × 4,096 ≈ 0.26B of embeddings — 6.74B in all. Gemma 2B's layer arithmetic gives 1.98B, matching its reported 1,981,884,416 non-embedding parameters to within the omitted norm weights; its 256k-entry vocabulary adds another 0.52B of embeddings, which is why a "2B" model is closer to 2.5B.
  • The image usually dominates the prompt. At 576 visual tokens and a 128-token question, the image is over 80% of LLaVA-1.5's prefill work. At 4,096 tokens (PaliGemma 896), the image is about 97% of a 128-token prompt's compute — which is why that checkpoint is reserved for tasks that need the detail.
  • Query connectors change the picture. With 32 Q-Former tokens the image becomes a minority of the prompt — about a fifth next to a 128-token question, and shrinking as the text grows — the main computational argument for BLIP-2-style connectors.

What the estimate leaves out

The vision encoder itself runs once per image and is not counted above: a ViT-L/14 at 336 px processes 577 tokens through 24 layers of width 1024, and SigLIP So400m at 896 px processes 4,096 tokens through its own stack, which is far from negligible. Generation cost after prefill depends on the answer length and on the key–value cache, which grows with every visual token kept in the sequence — another point in favour of fixed-size connectors when many images must stay in context.

Takeaway: visual tokens are ordinary tokens to the language model. Multiply their count by roughly 2·N FLOPs each and the cost of a design choice — 32 queries versus 576 patches versus 4,096 patches — becomes a number rather than an impression.

11 How to choose between them

Start from the output you need — an embedding, free text, or structured predictions — and from how much you can afford to fine-tune. The architecture follows.

A decision path

  • Need search, deduplication, zero-shot tagging or a reranker? Use a dual encoder (CLIP or SigLIP family). Embeddings can be precomputed and indexed; nearest-neighbour search over millions of images is cheap. A generative model is usually the wrong tool here.
  • Need open-ended answers or chat about images, and can fine-tune an LLM? A projector-style model (LLaVA-1.5 design) is the simplest to reproduce: freeze the encoder, align a projector, then instruction-tune. Budget for 576 visual tokens per image at 336 px.
  • Need to keep a large LM frozen, or to serve many images per prompt? Query-based connectors (BLIP-2's Q-Former, Flamingo's resampler) cap visual tokens at 32 or 64 per image and leave the LM's weights untouched.
  • Need to fine-tune a small model for a specific task — OCR-heavy VQA, detection, segmentation, captioning in many languages? PaliGemma was designed as a transfer base rather than a chat model; pick the resolution the task demands (896 for dense text).
  • Need documents specifically? Layout-aware and OCR-free document models are covered by the Document AI hub; a general VLM at 896 px competes on some document tasks but not all.

Cost rules of thumb (to be checked on your own setup)

  • Visual tokens add to the LM's sequence, so prefill cost rises roughly linearly with their count for the feed-forward layers and quadratically for attention among them.
  • Freezing the LM reduces optimizer memory in proportion to the frozen share; parameter-efficient methods such as LoRA are a middle path.
  • Folklore to treat carefully: "bigger LM always beats higher resolution". PaliGemma's authors report a model under 3B parameters matching much larger VLMs on many transfer tasks, and show resolution strongly affecting OCR, detection and segmentation; the right trade depends on whether the task is about knowledge or about pixels.
Takeaway: embeddings → dual encoder; conversation with a trainable LM → projector; frozen LM or many images → query connector; small task-specific specialist → prefix-LM transfer base at the resolution the task needs.

14 Failure modes shared across the family

Some weaknesses show up in many members at once because they follow from shared design choices — the contrastive objective, the token budget, the way training data was made. Each is listed with the strength of the evidence behind it.

The recurring problems

Object hallucination — describing objects that are not in the imageInstruction-tuned generative VLMs; the tendency is stronger for objects that frequently co-occur with ones presentLanguage priors from the LM and co-occurrence patterns in instruction dataWell documented by dedicated benchmarks ("Evaluating Object Hallucination in Large Vision-Language Models"); magnitude varies strongly by model and prompt

How to treat these in practice

  • Evaluate on the failure you care about directly — hallucination-specific probes for captioning, compositional probes for retrieval, high-resolution crops for OCR — rather than trusting aggregate VQA scores.
  • For dual encoders, re-ranking the top candidates with a generative or cross-attention model is a common mitigation for order-insensitivity; that it helps is an observation from practice with mixed published evidence.
  • The field-level treatment of hallucination, including in text-only LLMs, lives on Hallucination & Factuality.
Takeaway: most shared failures trace back to three choices — contrastive objectives that do not need word order, token budgets that cap resolution, and language models whose priors can outvote the pixels.

16 Takeaways

The whole hub, compressed into the claims most worth carrying forward, each with the section that supports it.

Architecture

  • Two families, one pipeline. Dual encoders align embeddings; generative VLMs turn an image into tokens for a language model — and usually reuse a contrastively trained encoder to do it (§01).
  • Six axes describe any member: objective, fusion point, connector, visual tokens, frozen set, resolution (§02).
  • Visual tokens are the cost driver. Projectors scale as (r / p)² — 576 at 336 px with 14-px patches, 4,096 at 896 px; query connectors cap at 32 or 64 (§03).
  • Projector and Q-Former connectors range from about 2M to 188M new parameters; Flamingo's resampler and cross-attention layers add about 10.2B. A trainable LM seems to make a small projector enough; a frozen LM pushes the work into the connector (§04).
  • The mask is the architecture. Causal versus prefix-LM decides whether image tokens can see the question; cross-attention keeps images out of the sequence (§05).

Training and evidence

  • Contrastive losses differ in normalisation, not in purpose. Softmax couples the batch; sigmoid treats each pair independently and saturates around 32k batch in SigLIP's experiments (§06).
  • Freezing is a dial. From connector-only (LLaVA stage 1, BLIP-2) to nothing frozen (PaliGemma); PaliGemma's ablation found freezing the LM clearly harmful and freezing the encoder neutral after transfer (§07).
  • An image is expensive. 576 visual tokens cost a 7B decoder about as much prefill compute as a 576-token prompt; at 896 px even a 2B decoder spends most of its prefill on the image (§10).
  • Shared failure modes — object hallucination, order-insensitive matching, small text at low resolution — follow from the design choices above rather than from any one model (§14).
  • Quote carefully. Several headline numbers are points rather than percentages, or depend on which table is used (§15).
Takeaway: to understand a new vision–language model, ask how many tokens an image becomes, how they reach the language model, and which weights moved. Almost everything else is data and scale.
