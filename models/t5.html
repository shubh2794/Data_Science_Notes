T5 — the Text-to-Text Transfer Transformer

T5 is an encoder–decoder Transformer from Google that casts every text task — translation, summarisation, classification, regression, question answering — as "read a string, write a string", and a 2019 study that used that single interface to compare, one factor at a time, the architectures, pretraining objectives, datasets, transfer strategies and scaling choices of the time. This note covers it in detail: the text-to-text format and its task prefixes, the architecture (pre-norm RMS-style layer norm, bias-free dense layers, the bucketed relative position bias, tied embeddings, ReLU feed-forward in the original and GEGLU in v1.1), every released configuration with parameter counts recomputed from the configurations, the SentencePiece vocabulary and its sentinels, how the C4 corpus was filtered, the span-corruption objective worked by hand with its length arithmetic, the systematic study table by table, the pretraining and fine-tuning schedule with Adafactor, the headline results, the successors T5 v1.1, mT5, ByT5, Flan-T5, UL2 and T5Gemma, the compute arithmetic of encoder–decoder against decoder-only models, and practical use with pitfalls.

01 What T5 is

T5 ("Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer", arXiv 1910.10683, JMLR 2020) is two things at once: a family of encoder–decoder Transformers, released at five sizes from 60M to 11B parameters, and a large controlled study of transfer learning for NLP. Both rest on one decision — every task is text in, text out — so the same model, loss, optimiser and decoding procedure serve all of them.

every task, pretraining included: maximise the likelihood of the target string given the input string (teacher forcing)L(θ) = − Σₜ₌₁ᵐ log p_θ(yₜ | y₁ … yₜ₋₁, Enc_θ(x)) wherex = task prefix + input text, y = target text + </s> pretraining input and target come from unlabeled text by span corruptionx = "Thank you <X> me to your party <Y> week." y = "<X> for inviting <Y> last <Z>" inference: decode the target string, then read the answer out of it"mnli hypothesis: … premise: …" → "entailment"; "stsb sentence1: … sentence2: …" → "3.8"

What goes in and what comes out

  • Input: a string that begins with a short task prefix — translate English to German:, summarize:, cola sentence: — tokenized with a 32,000-piece SentencePiece model; up to 512 tokens during pretraining.
  • Output: a string generated token by token: a translation, a summary, a class name such as entailment, a number such as 3.8, or an answer span.
  • Training: pretraining with span corruption on C4 (about 750 GB of filtered English web text), then fine-tuning on each task with the same cross-entropy loss. The released v1.0 checkpoints were pretrained on a mixture of C4 and the supervised tasks (final recipe).

31 Pitfalls

T5's failures are mostly silent: a wrong prefix, a label that tokenizes differently, an fp16 overflow that produces NaN only on some inputs, a brace that became <unk>. The list below is grouped by where they occur.

Numerics and precision

  • fp16 overflow. T5 was trained on TPUs, where the reduced-precision format is bfloat16, which has fp32's exponent range. In fp16 (maximum 65,504) the un-normalised residual stream and feed-forward activations of some checkpoints — v1.1, mT5 and Flan-T5 in particular — can overflow to inf and then NaN. The library's own code shows the workaround: it clamps hidden states to just below the fp16 maximum inside each block when running in fp16, and keeps the feed-forward output projection wo in fp32 (_keep_in_fp32_modules = ["wo"]). Use bf16 or fp32 when you can.
  • Porting to another implementation without the three T5 specifics — no 1/√d_kv, d_model^(−1/2) rescale before a tied output, scale-only norm — gives wrong logits with no error.

Inputs and targets

  • Prefix and field order. v1.0 checkpoints expect the Appendix D forms (mnli hypothesis: … premise: …, stsb sentence1: … sentence2: …); a different order or wording is a different input.
  • Label strings. "entailment" is 4 pieces (▁ · en · tail · ment) and "not_entailment" 5; compare decoded strings, and restrict or validate outputs for classification.
  • Unrepresentable characters. { } ~ <, most CJK characters and newlines do not survive the T5 tokenizer; use mT5 or ByT5, or escape them, for code, JSON or line-structured text.
  • STS-B-style regression needs the 0.2-grid quantisation and a parser for the generated number.

Training

  • Forgetting −100. Padding ids left as 0 in the labels teaches the model to predict padding.
  • v1.1 without dropout overfits small data sets; enable it.
  • Assuming v1.1 works zero-shot. It was never trained on supervised tasks; it must be fine-tuned (or use Flan-T5).
  • Span-corruption lengths. Continuing pretraining with inputs and targets not sized by the helper (568 → 512 / 114 at the defaults) pads or truncates every example.

Reading the paper's numbers

  • Validation versus test. Tables 1–13 and 15 are validation scores of the 34B-token baseline family; Table 14 is test scores of the 1T-token models. Do not mix them.
  • Noise. Differences under 2σ (0.47 GLUE, 0.83 SuperGLUE) are within the paper's own noise estimate.
  • Table 10's d = 2048 adapter row is a copy of the d = 128 row; use Table 16.
Takeaway: the checklist is short — right checkpoint for the job, right prefix and label strings, −100 in labels, bf16 not fp16, a tokenizer that can spell your data.

33 Takeaways

T5 made "every task is text-to-text" the default framing for transfer learning and produced a large controlled comparison of pretraining choices. Its largest model set the state of the art on GLUE and SuperGLUE in 2019, and its successors — v1.1, mT5, ByT5, Flan-T5, UL2 — remained standard encoder–decoder checkpoints for years.

What to remember

  • Design: the 2017 encoder–decoder with scale-only pre-norm, no biases, bucketed relative position biases and a tied (v1.0) or untied (v1.1) output layer.
  • Objective: span corruption — short targets, sentinels, 15% at mean length 3 — chosen from a plateau of similar denoising objectives on cost grounds.
  • Data: C4, cleaned by simple heuristics whose code differs in detail from their description; large enough, per the paper, to train on 1T tokens without repeating data.
  • Evidence: one-factor-at-a-time comparisons with a measured noise floor; read them with the 2σ rule and remember they were run at Base size.
  • Practice: use v1.0 for its built-in prefixes, v1.1 to fine-tune from scratch, Flan-T5 for instructions, mT5 or ByT5 beyond English; bf16, labels with −100, a tokenizer that can spell your data.
Takeaway: read the NLP Models hub for where T5 sits among encoders and encoder–decoders, BERT for the encoder-only recipe it compared against, and GPT for the decoder-only branch that its architecture study found weaker for fine-tuned transfer and that later dominated prompting.
