T5: Text-to-Text Format & Architecture

The model T5 trains: every task cast as a prefixed input string and a target string, the encoder–decoder with bias-free RMS-style pre-norm, 32 log-spaced relative-position buckets, unscaled attention offset by initialisation, the ReLU and GEGLU feed-forward layers, the five configurations, and parameter counts recomputed from them.

02 Text-to-text: every task as a string, named by a prefix

To tell the model which task to perform, T5 prepends a task-specific text prefix to the input. Classification labels become words, regression becomes a number written as text, and reference-resolution tasks become "name the noun". The paper found the exact wording of the prefix had limited impact and treated it as a hyperparameter.

the input is the task name plus each field as "name: value"x = "mnli hypothesis: My feelings towards pigeons are filled with animosity. premise: I hate pigeons." y = "entailment" STS-B: a 1–5 similarity score rounded to the nearest 0.2 and written as a string — a 21-way classificationy = str(round(5 · s) / 5): 3.25 → "3.2", 2.57 → "2.6" classes 1.0, 1.2, …, 5.0 ⇒ (5 − 1) / 0.2 + 1 = 21 an output that is not a valid label is scored as wrongŷ ∉ {entailment, neutral, contradiction} ⇒ incorrect (never observed, per the paper)

Details that differ between the paper's text and its code

  • Field order. Section 2.4 writes MNLI as "mnli premise: … hypothesis: …", but Appendix D, which shows the actual preprocessed examples, has "mnli hypothesis: … premise: …" — the fields appear in alphabetical order of their names (likewise "cb hypothesis: … premise: …"). Use the Appendix D form with the released checkpoints.
  • Label words. Figure 1 shows a CoLA target "not acceptable", but the label names in the dataset code are unacceptable and acceptable, and Appendix D's example target is "acceptable". Multi-word labels use underscores (not_entailment).
  • WSC. Only examples labelled True can be trained on (the referent of a False candidate is unknown); at evaluation a prediction counts as True when its words are a subset of the candidate's or vice versa. WNLI overlaps the WSC training set, so the paper never trains on it and excludes it from validation GLUE averages.

Takeaway: text-to-text removes task-specific heads, so everything learned in pretraining — including the output vocabulary and the decoder — transfers. The cost is that the model must spell its labels, which is why a label must be tokenized and matched exactly, and why a regression target has to be quantised.

03 Architecture at a glance

T5 follows the original Transformer encoder–decoder closely. The paper lists three departures: layer normalisation without a bias and without mean-centring, applied to the input of each sub-layer (pre-norm) with the residual path left un-normalised; a simplified relative position scheme in place of sinusoidal embeddings; and no additive biases. The output softmax shares its weights with the input embedding.

encoder block (N blocks), then a final norm and dropouth ← h + Dropout(SelfAttn_full(LN(h), bias_enc)) h ← h + Dropout(FF(LN(h))) decoder block (N blocks), then a final norm and dropouth ← h + Dropout(SelfAttn_causal(LN(h), bias_dec)) h ← h + Dropout(CrossAttn(LN(h), z)) h ← h + Dropout(FF(LN(h))) output distribution: the tied embedding E; the Hugging Face code rescales by d_model^(−1/2) when tiedp(yₜ | y<ₜ, x) = softmax( E · (d_model^(−1/2) · hₜ) ), E ∈ ℝ^(32,128 × d_model)

What is and is not in a block

  • Attention has four bias-free projections: W_Q, W_K, W_V ∈ ℝ^(d_model × h·d_kv) and W_O ∈ ℝ^(h·d_kv × d_model). The inner width h·d_kv need not equal d_model — T5-3B and T5-11B make it 4× and 16× larger (configurations).
  • Feed-forward is dense–ReLU–dense with no biases (v1.0), or a GEGLU with three matrices (v1.1).
  • Position enters only through the bias added to attention logits, computed in the first layer of each stack and reused by every layer of that stack. Cross-attention has no position bias.
  • Dropout (0.1 in the study) is applied inside the feed-forward network, on each residual branch, on the attention weights, and at the input and output of each stack.

Shapes come from each checkpoint's released config.json (d_model, d_ff, d_kv, num_heads, num_layers, num_decoder_layers, feed_forward_proj, tie_word_embeddings). Parameter counts per block are computed from those shapes; biases are absent everywhere, and each norm has d_model scale parameters.

Takeaway: architecturally T5 is the 2017 encoder–decoder with modern hygiene: pre-norm residuals, scale-only norms, no biases, relative position biases, tied embeddings. The authors deliberately left these choices out of the study as "orthogonal to the experimental factors".

04 The simplified layer norm (RMS-style) and pre-norm residuals

T5's layer normalisation only rescales: it divides each vector by its root-mean-square and multiplies by a learned gain, with no mean subtraction and no additive bias. This is the operation later named RMSNorm; the Hugging Face implementation says so in its comments, and computes the mean square in 32-bit floats even for half-precision inputs.

standard LayerNorm, for comparisonLN(x) = g ⊙ (x − μ) / √(σ² + ε) + b, μ = (1/d) Σᵢ xᵢ, σ² = (1/d) Σᵢ (xᵢ − μ)² T5 layer norm: no centring, no biasT5LN(x) = g ⊙ x / √( (1/d) Σᵢ xᵢ² + ε ), g ∈ ℝ^d initialised to 1, ε = 10⁻⁶ pre-norm residual: the skip path is never normalisedh ← h + F(T5LN(h)) (post-norm would be h ← LN(h + F(h)))

Worked example

Take x = (2, 4, 6, 8). Its mean square is (4 + 16 + 36 + 64)/4 = 30, so T5LN(x) = x / √30 = (0.365, 0.730, 1.095, 1.461) with g = 1. Standard LayerNorm would first subtract the mean 5, giving (−3, −1, 1, 3) / √5 = (−1.342, −0.447, 0.447, 1.342). Adding a constant c to every coordinate changes T5LN's output (the mean is not removed) but leaves LayerNorm's unchanged; scaling x by any positive factor leaves both unchanged (up to ε).

  • Parameters. One gain vector of d_model per norm: two per encoder block, three per decoder block, plus one final norm per stack — 768 × (2·12 + 3·12 + 2) = 47,616 parameters in T5-Base, 0.02% of the model.
  • Why pre-norm. With the norm inside the branch, the residual stream is a sum of branch outputs plus the embedding; gradients reach early layers through the identity path undisturbed, which is generally credited with making deep pre-norm stacks such as T5's 24 + 24 layers easier to train than post-norm ones.
  • A consequence for half precision. Because nothing normalises the residual stream until the final norm, its magnitude can grow with depth — one ingredient of the fp16 overflow problem in pitfalls.
Takeaway: T5's norm is RMSNorm before it had a name: cheaper than LayerNorm (no mean, no bias) and, in the pre-norm position, friendly to deep stacks. Loading T5 weights into a LayerNorm-based implementation silently changes the network.

05 Relative position bias: 32 log-spaced buckets

T5 has no position embeddings on its tokens. Instead, each attention head adds a learned scalar to every query–key logit, chosen by the bucketed offset between the key's and the query's positions. There are 32 buckets per head; small offsets get their own bucket, larger ones share logarithmically wider buckets, and everything beyond the last boundary shares one. The table is learned once per stack — in the first layer — and reused by all layers of that stack; the encoder's and the decoder's tables are separate.

attention logits of head h: no 1/√d_kv scaling in T5 (see the next section)sᵢⱼ = qᵢ · kⱼ + B_h[ bucket(j − i) ], B ∈ ℝ^(32 × heads) per stack bidirectional (encoder): half the buckets for keys after the query, half for keys at or before itn = 32 / 2 = 16, offset r = j − i, base = 16 · [r > 0], a = |r| causal (decoder): future offsets never occur; all 32 buckets measure the distance into the pastn = 32, base = 0, a = max(0, −r) exact buckets for small distances, logarithmic above, capped at the last bucket (max_distance D = 128)e = n / 2; bucket = base + a if a < e bucket = base + min( n − 1, e + ⌊ ln(a / e) / ln(D / e) · (n − e) ⌋ ) otherwise

Worked example: where each bucket starts

StackExact bucketsLogarithmic buckets (distance at which each starts)Last bucket covers
Encoder, per direction (16 buckets)0 – 78, 12, 16, 23, 32, 46, 64, 91distance ≥ 91
Decoder (32 buckets, past only)0 – 1516, 19, 21, 24, 27, 31, 35, 40, 46, 52, 59, 67, 77, 87, 99, 113distance ≥ 113

For the encoder, a = 20 is not exact (20 ≥ 8), so bucket = 8 + ⌊ln(20/8)/ln(16) · 8⌋ = 8 + ⌊0.3305 · 8⌋ = 8 + 2 = 10, the bucket that starts at 16. The formula would reach 16 — one past the last bucket — at a = 128, which is where "max distance 128" comes from; but the cap at n − 1 means the last bucket already starts at 91 in the encoder and 113 in the decoder. The paper's sentence "ranges that increase in size logarithmically up to an offset of 128 beyond which we assign all relative positions to the same embedding" is therefore true but loose: offsets from 91 (encoder) or 113 (decoder) upward already share one value. One more quirk of the encoder: offset 0 goes to bucket 0 and a key after the query has distance at least 1, so bucket 16 ("after, distance 0") can never be selected — the encoder uses 31 of its 32 buckets.

Consequences

  • Cheap and length-agnostic. The whole position mechanism of T5-Base is 32 × 12 = 384 numbers per stack. Nothing ties the model to 512 positions; the n_positions: 512 in the v1.0 configs is informational. Beyond the training length quality is not guaranteed, and attention cost still grows quadratically.
  • A single layer is blind beyond the last boundary — it cannot tell a key 200 tokens away from one 2,000 away — but, as the paper notes, stacked layers can combine local information to build sensitivity to larger offsets.
  • Padding side does not matter for the encoder, because nothing depends on absolute position (the library documentation says left or right padding both work).

Takeaway: T5's position signal is a per-head, per-bucket scalar — fine resolution nearby, coarse far away, nothing beyond the last bucket boundary within a layer. It costs almost no parameters and does not fix a maximum length, which is why T5 checkpoints accept inputs longer than 512 tokens (with no quality guarantee).

06 Attention details: no √d_kv scaling, and the initialisation that replaces it

T5's attention does not divide the logits by √d_kv. The released code (Mesh TensorFlow, and the Hugging Face port, whose comment reads "T5 folds the relative position bias into the attention scores and does not scale the query/key dot product") instead initialises W_Q with a smaller standard deviation so the logits start at the same scale. The paper does not mention this; it is a code-level detail that matters if you port weights.

standard scaled dot-product attentionA = softmax( Q Kᵀ / √d_kv + mask ) V T5 attention: no scaling, position bias addedA = softmax( Q Kᵀ + B + mask ) V initialisation in the released code (factor 1): W_Q absorbs the missing 1/√d_kvW_Q ~ N(0, (d_model · d_kv)^(−1)), W_K, W_V ~ N(0, d_model^(−1)) W_O ~ N(0, (h · d_kv)^(−1)), E ~ N(0, 1) feed-forward initialisationW_in ~ N(0, d_model^(−1)), W_out ~ N(0, d_ff^(−1))

Why the two are equivalent at initialisation

With inputs of unit RMS, a query component qₐ = Σᵢ xᵢ W_Q,ᵢₐ has variance d_model · Var(W_Q) = 1/d_kv under T5's initialisation, versus 1 under the usual one. A logit q · k sums d_kv products, so its variance is d_kv · (1/d_kv) · 1 = 1 — the same as the standard √d_kv-scaled logit. The difference is what happens during training: T5's effective scale is a learned property of W_Q, not a fixed constant.

The tied output projection

Because the embedding E is initialised with unit variance and shared with the softmax layer, v1.0 multiplies the final decoder state by d_model^(−1/2) before the tied projection (768^(−1/2) = 0.0361 for T5-Base). T5 v1.1 unties the two matrices and drops this rescaling; the Hugging Face code decides which to do from the checkpoint's tie_word_embeddings flag. Mixing up the two is a silent error: logits come out √d_model = 27.7 times too large or too small.

Takeaway: when porting T5 to another codebase, three things have no counterpart in a textbook Transformer and each changes outputs silently: no 1/√d_kv in attention, the d_model^(−1/2) rescale before a tied output layer, and the scale-only norm.

07 The feed-forward layer: ReLU in T5, GEGLU in v1.1

The original T5 feed-forward network is two bias-free matrices with a ReLU between them. T5 v1.1 replaces it with GEGLU, from Shazeer's "GLU Variants Improve Transformer" (2020): the hidden layer is the elementwise product of a GELU-activated projection and a second, linear projection. The gate adds a third matrix, so v1.1 shrinks d_ff to keep sizes comparable.

T5 v1.0: W₁ is d × d_ff, W₂ is d_ff × d — 2 · d · d_ff parametersFF_ReLU(x) = max(0, x W₁) W₂ T5 v1.1 (feed_forward_proj = "gated-gelu", tanh approximation of GELU): W₀, W₁ are d × d_ff′ — 3 · d · d_ff′ parametersFF_GEGLU(x) = ( GELU(x W₀) ⊙ x W₁ ) W₂ same parameter count when3 · d · d_ff′ = 2 · d · d_ff ⇒ d_ff′ = (2/3) · d_ff applied to the released shapesBase: 3,072 → 2,048 (released 2,048); Large: 4,096 → 2,730.7 (released 2,816)

What the gate changes

  • A ReLU unit's output depends on one projection and is exactly zero for half its input range. A GEGLU unit multiplies a smooth, mostly-positive GELU of one projection by an unbounded linear value of another, so it can output either sign and its magnitude is modulated by a second direction of the input.
  • The GLU-variants paper reported lower pretraining perplexity for GEGLU and SwiGLU than for ReLU at matched parameters and compute on the T5 setup, and gains on downstream fine-tuning; SwiGLU is the variant most later decoder-only LLMs adopted.
  • The released v1.1 shapes are not all "2/3 of v1.0": Base matches (2,048), Large uses 2,816, and Small changes shape entirely (d_ff 1,024, 6 heads, 8 + 8 layers).

Takeaway: GEGLU is the one architectural change in v1.1 that later models kept; its gated product gives each unit two input directions for 1.5× the matrices, paid for by a narrower hidden layer.

08 Every configuration, and the odd shapes of 3B and 11B

The paper defines five sizes. Small, Base and Large follow BERT's shape conventions (inner attention width equal to d_model, d_ff = 4 · d_model). The 3B and 11B models keep d_model = 1,024 and grow only the attention inner width and the feed-forward width, because, in the paper's words, TPUs "are most efficient for large dense matrix multiplications like those in the Transformer's feed-forward networks".

Reading the odd shapes

  • T5-3B projects 1,024-wide states to a 4,096-wide attention space (32 heads of 128) and back; each attention layer has 4 · 1,024 · 4,096 = 16.8M parameters, four times a d = 1,024 layer's. Its feed-forward layer is 16 · d_model wide.
  • T5-11B goes further: 128 heads of 128 (inner width 16,384) and a 65,536-wide feed-forward layer, 64 · d_model. A single feed-forward matrix is 1,024 × 65,536 = 67.1M parameters; the two of them in one block hold more than all of T5-Small's non-embedding weights.
  • v1.1 reverses the trade. XL and XXL widen d_model (2,048 and 4,096) and use ordinary 64-wide heads — "larger d_model and smaller num_heads and d_ff", as the release notes put it. The residual stream, and hence the embedding, gets wider: XXL's two 32,128 × 4,096 embedding tables (untied) are 263M parameters against 11B's single 32.9M.
  • Size labels are rounded loosely. "Large ≈ 770M" overstates the configuration by 4.4%; "3B" is 2.85B. The paper's own Section 3.7 text says "around 2.8 billion".
Takeaway: the five v1.0 sizes are not one shape scaled up — above Large, only the attention inner width and d_ff grow. Any calculation that assumes inner width = d_model or d_ff = 4·d_model is wrong for T5-3B, T5-11B and v1.1 Small.

09 Parameter counts, recomputed from the configurations

Every T5 parameter sits in a bias-free matrix, a norm gain, a relative-position table or the embedding, so the count is a short formula in the config's numbers. The recount reproduces what the Hugging Face library reports for each checkpoint; the checkpoint files hold one extra relative-bias table (in the first decoder layer's cross-attention) that the code never uses.

with inner = heads · d_kv and k = 2 for ReLU, 3 for GEGLUP_attn = 4 · d · inner P_ff = k · d · d_ff P_norm = d encoder block, decoder blockP_enc_block = P_attn + P_ff + 2d P_dec_block = 2 · P_attn + P_ff + 3d stacks: one 32 × heads bias table and one final norm eachP_encoder = N_enc · P_enc_block + 32·heads + d P_decoder = N_dec · P_dec_block + 32·heads + d total: shared embedding, plus an output matrix only when untied (v1.1, mT5, ByT5, Flan-T5)P = V·d + [untied] · V·d + P_encoder + P_decoder, V = 32,128

Two checks against the paper. Its claim that encoder–decoder attention is "about 10% of the total parameter count" is 12 · 2,359,296 = 28.3M of 222.9M = 12.7% for Base by this count. And its Section 3.2 simplification — an L + L encoder–decoder has about the parameters of a 2L-layer decoder-only model — holds to within that cross-attention share: a 24-layer decoder-only stack of Base width would have 24 × 7,079,424 = 169.9M block parameters against 198.2M for 12 + 12.
