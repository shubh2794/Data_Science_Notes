NLP Evaluation Metrics

How do you score generated text when there are many right answers? The canonical hub — n-gram overlap, embeddings, perplexity, and LLM judges.

NLP Evaluation BLEU · ROUGE · BERTScore

01 Why generation evaluation is hard

Classification has one right label. Generation has a one-to-many map: many fluent, correct outputs exist for one input, so "match the reference" is the wrong frame.

  • "The cat sat on the mat" and "A cat was sitting on the mat" mean the same — surface-overlap metrics punish the paraphrase anyway.
  • Human judgment is the gold standard but slow and costly; automatic metrics are proxies we trust only as far as they correlate with humans.
  • Three families trade off cost vs fidelity: n-gram overlap (cheap, surface), embedding-based (semantic), and LLM-as-a-Judge (flexible, biased).

02 N-gram overlap: BLEU, ROUGE, METEOR, chrF

The oldest, cheapest family: count matching n-grams between candidate and reference. Fast and reproducible — but blind to meaning.

BLEU — precision-oriented (translation)

  • Modified n-gram precision: of the candidate's n-grams, how many appear in the reference (clipped so repeats don't inflate)?
  • Brevity penalty (BP) punishes too-short candidates that would otherwise game precision.
  • Geometric mean over n = 1…4 with weights wn. The default for Machine Translation.
BLEU = BP · exp( Σn=1..4 wn · log pn ) pn = (clipped matching n-grams) / (candidate n-grams) BP = 1 if c > r , else exp(1 − r/c) c = candidate len, r = reference len

ROUGE — recall-oriented (summarization)

ROUGE-N = (overlapping n-grams) / (n-grams in reference) ROUGE-L = LCS(c, r) / len(r)

METEOR & chrF

  • METEOR: aligns unigrams allowing stems and synonyms, then a precision/recall harmonic mean with a fragmentation penalty for word-order scrambling — correlates with humans better than BLEU.
  • chrF: an F-score over character n-grams — robust to morphology and tokenization, strong for many languages.
METEOR = Fmean · (1 − penalty) Fmean = (10 · P · R) / (R + 9 · P) chrF = (1 + β²) · (chrP · chrR) / (β² · chrP + chrR)

03 Embedding-based: BERTScore & MoverScore

N-gram overlap can't see that "car" ≈ "automobile". Embedding metrics compare contextual vectors instead of strings, so paraphrase finally scores well — built on Embeddings.

  • BERTScore: embed every token of candidate and reference with a contextual model, then greedily match each candidate token to its most-similar reference token (and vice-versa) → precision, recall, F1 from those cosine similarities.
  • MoverScore: instead of greedy 1-to-1, solve an earth-mover (optimal transport) problem — the minimum cost to move the candidate's embedding mass onto the reference's. Smoother, captures many-to-one alignment.
  • Both reward meaning over wording: a synonym swap that tanks BLEU barely dents BERTScore.
BERTScore-R = (1/|r|) · Σri ∈ ref maxcj ∈ cand cos(ri, cj) BERTScore-P = (1/|c|) · Σcj ∈ cand maxri ∈ ref cos(cj, ri) F = 2PR/(P+R)
The payoff: embedding metrics catch valid paraphrase that n-gram metrics reject. The cost: you depend on the embedding model's biases, and scores aren't human-interpretable on an absolute scale.

04 Perplexity: intrinsic language-model quality

Overlap and embedding metrics need a reference. Perplexity needs none — it measures how surprised a Language Models is by held-out text, the standard intrinsic metric.

PP(W) = exp( − (1/N) · Σi=1..N log P(wi | w<i) ) equivalently PP = 2^(cross-entropy in bits) lower = better
  • Intuition: the geometric-mean branching factor — a perplexity of 20 means the model is, on average, as unsure as if choosing uniformly among 20 tokens.
  • Lower is better; it falls as a model predicts real text more confidently.
  • What it doesn't measure: truthfulness, helpfulness, or task success. A model can have low perplexity and still be unhelpful — which is exactly why downstream and judge-based metrics exist.
  • Not comparable across different tokenizers/vocabularies — perplexity depends on how text is segmented.

05 The shift to LLM-as-a-Judge

For open-ended tasks (chat, reasoning, writing) no reference exists. The modern answer: ask a strong LLM to grade outputs — flexible, scalable, and the subject of its own note, LLM-as-a-Judge.

  • Pointwise: score one output against a rubric (1–5, or pass/fail on criteria).
  • Pairwise: show two outputs (A vs B), ask which is better — often more reliable than absolute scores, and the basis of preference data.
  • Reference-guided: give the judge a gold answer or rubric to anchor its grading.

Failure modes (why a judge is not ground truth)

  • Position bias: judges favor whichever answer is shown first (or second). Mitigation: swap order and average both directions.
  • Verbosity bias: longer, more confident answers are rated higher regardless of correctness.
  • Self-preference: a model rates outputs from its own family more favorably.
  • Calibration: judge scores cluster and don't span the full scale; small quality gaps get exaggerated or flattened.
Governance link: because judges inherit these biases, LLM-judge pipelines are validated against human labels — see Model Evaluation for the broader discipline of trustworthy measurement.
