Knowledge Graphs

Represent facts as a network of entities connected by typed relations. A knowledge graph stores "who/what relates to what, how" — structured, queryable knowledge that grounds search, reasoning, and retrieval. (This very site is one.)

NLP Knowledge representation Graphs

01 Facts as a graph

  • Nodes are entities (people, places, things, concepts); edges are typed relations between them.
  • Knowledge is stored as triples — (head, relation, tail) — the atom of a knowledge graph.
  • Unlike free text, it's structured: you can query it, traverse it, and reason over it precisely.
One sentence: a knowledge graph turns scattered facts into a connected, queryable network of entities and relations.

02 Triples → graph

Each fact is a subject-predicate-object triple. Pick a sentence to see its triples become a graph.

From a sentence to a knowledge graph Entities become nodes; relations become labeled edges

Standards like RDF formalize triples; SPARQL queries them; ontologies define the allowed entity and relation types.

03 Building one from text

  1. Entity recognition (NER) — find the entities.
  2. Entity linking — resolve "Apple" to the right canonical entity (company vs fruit).
  3. Relation extraction — detect how entities relate ("founded by", "located in").
  4. Deduplication / fusion — merge mentions of the same entity across sources.

04 Knowledge-graph embeddings

  • Embed entities and relations as vectors so that valid triples score high — e.g. TransE: head + relation ≈ tail.
  • Enables link prediction (inferring missing edges) and similarity over entities.
  • Bridges symbolic graphs with the vector world of embeddings and GNNs.

TransE models a relation as a translation in vector space: starting at the head entity h and moving by the relation vector r should land near the tail t. Plausibility is the negative distance — lower distance means a more plausible triple.

geometry h + r ≈ t distance d(h, r, t) = ‖ h + r − t ‖₂ score f(h, r, t) = − ‖ h + r − t ‖ (higher = more plausible)
Equation decoder — f(h, r, t) = − ‖ h + r − t ‖
Say it
“f of h, r, t equals minus the norm of h plus r minus t” — start at the head's vector, step by the relation's vector, measure how far you landed from the tail, and negate that distance so closer means a higher score.
Shapes
h, r, t ∈ ℝᵈ — one learned row each from the entity table and the relation table, all the same width d. h + r − t ∈ ℝᵈ is a residual vector; the norm ‖·‖ reduces it to a non-negative scalar, so f(h, r, t) ≤ 0 is a scalar with 0 as the perfect score.
Scope
The norm runs over the d coordinates of the single residual vector — here the Euclidean ‖·‖₂ of the distance line (TransE is also used with the L1 norm). The ∑ in the margin loss below ranges over every true triple (h, r, t) in the training graph paired with its corrupted triples (h′, r, t′), made by swapping in a random head or tail; nothing sums across relations inside one score.
Plain words
Each relation is a fixed arrow in embedding space. A fact is believable when following the relation's arrow from the head lands you on (or near) the tail; the score is just how close you got, with a minus sign so bigger is better.
Tiny example
d = 2, h = [1, 0], r = [0, 1] → h + r = [1, 1] true t = [0.9, 1.2]: h+r−t = [0.1, −0.2] ‖·‖₂ = 0.2236 f = −0.2236 corr t′ = [−1, 0.5]: h+r−t′ = [2, 0.5] ‖·‖₂ = 2.062 f = −2.062 → true triple ranks first (L1 norm instead: 0.3 vs 2.5 — same order) hinge, γ = 1: max(0, 1 + 0.2236 − 2.062) = 0 hinge, γ = 2: max(0, 2 + 0.2236 − 2.062) = 0.1621
Why it's here
It is the concrete instance of the knowledge-graph embedding idea in §04: the triples of §02 become vector arithmetic, and ranking every candidate tail by this score is exactly the link prediction the §05 viz draws. It is the simplest translation model in the field — the baseline later embedding models are measured against — and the bridge from symbolic facts to the vector world, which is what lets a graph fill in missing edges before serving the grounding and multi-hop uses of §06.

Training uses a margin ranking loss: real triples should score better than corrupted ones (h′, r, t′) by at least a margin γ.

loss L = ∑ max( 0, γ + d(h, r, t) − d(h′, r, t′) )

05 TransE scoring & link prediction

Pick a head entity and a relation; the target point h + r is drawn, and every candidate tail is ranked by distance to it. The closest is TransE's predicted answer — link prediction in 2-D.

h + r ≈ t in 2-D embedding space The star marks h + r; bars rank candidate tails by −distance

This is the same idea as the king − man + woman ≈ queen arithmetic on the Embeddings page — relations become consistent offset directions.

06 Why they matter

  • Grounding & retrieval: structured facts back search and RAG (GraphRAG traverses relations, not just similar chunks).
  • Reasoning: multi-hop questions follow explicit relation paths.
  • Enterprise knowledge: unify entities across siloed databases.

07 Takeaways

  • KG = entities + typed relations, stored as (head, relation, tail) triples.
  • Build from text via NER → entity linking → relation extraction → fusion.
  • KG embeddings (TransE) enable link prediction and connect to GNNs.
  • Ground retrieval & reasoning — structure that plain text lacks.
