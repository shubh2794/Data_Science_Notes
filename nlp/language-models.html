Language Models

Assign a probability to a sequence of tokens — or, equivalently, predict the next token. That single objective, scaled, becomes the modern LLM.

NLP Probabilistic Generation

01 What a language model is

A language model assigns a probability to any sequence of tokens. Generation is the same machine run forward: at each step, predict a distribution over the next token, then sample.

  • The full joint probability of a sequence factorises by the chain rule — a product of one-step next-token predictions, each conditioned on everything before it.
  • So "model the language" and "predict the next token" are the same task: knowing every conditional P(wₜ | context) is exactly enough to score and to generate.
  • Tokens come first (see Tokenization); the model never sees raw characters, only token IDs mapped through an embedding table.
  • Everything that follows — n-grams, neural nets, Transformers — is just a different estimator for those conditional probabilities.
P(w₁ … wn) = ∏t=1..n P(wₜ | w₁ … wt−1)
One idea: a language model is a probability machine over token sequences. To generate is to read those conditionals left-to-right and sample; to evaluate is to multiply them. Every section below is a better way to estimate P(wₜ | context).

02 N-gram models & the Markov assumption

The chain rule is exact but useless on its own — no one has counts for an entire sentence's history. The n-gram model makes it tractable by forgetting all but the last few tokens.

  • Markov assumption: the next token depends only on the previous n−1 tokens, not the whole history. A bigram looks back one token, a trigram two.
  • Estimate each conditional by maximum likelihood — just count and divide: how often did this context lead to this token?
  • Cheap, transparent, and surprisingly strong for short-range structure — but the context window is hard-capped at n, so any longer dependency is invisible.
P(wₜ | w₁ … wt−1) ≈ P(wₜ | wt−n+1 … wt−1) bigram: P(wₜ | wt−1) = count(wt−1, wₜ) / count(wt−1) trigram: P(wₜ | wt−2, wt−1) = count(wt−2, wt−1, wₜ) / count(wt−2, wt−1)
Bigger n captures more context but explodes the table: a vocabulary of |V| tokens has up to |V|n possible n-grams, and almost all of them are never observed. That is the sparsity wall the next section hits.

03 Sparsity & smoothing

Raw counts assign probability zero to anything unseen — and most plausible n-grams are unseen. Zero probabilities are fatal: one zero anywhere makes the whole sequence's probability zero.

  • The problem: a perfectly grammatical trigram that simply never appeared in the corpus gets count = 0 → P = 0. The model declares a valid sentence impossible.
  • Add-k (Laplace) smoothing: pretend every n-gram was seen k extra times. Simple, but it steals too much mass from real counts and over-rewards the unseen.
  • Backoff & interpolation: if the trigram is unseen, fall back to the bigram, then the unigram — mixing higher- and lower-order estimates so there's always some evidence to lean on.
  • Kneser–Ney (the strong classical method): smooth by how many distinct contexts a word completes, not just its raw frequency. "Francisco" is frequent but only ever follows "San", so it should be an unlikely novel continuation — Kneser–Ney captures exactly this.

Smoothing patches the symptom but not the disease: counting treats every token as an opaque symbol. "cat" and "kitten" share no statistics. The cure is to give tokens meaning — which is what neural models do.

04 Perplexity — the intrinsic metric

How good is a language model? Measure how surprised it is by held-out text. Lower perplexity means the model assigned the real continuations high probability.

  • Perplexity is the exponentiated average negative log-likelihood per token — the geometric mean of 1 / P(wₜ | context).
  • Intuition: the average branching factor. A perplexity of 20 means the model is, on average, as uncertain as if choosing uniformly among 20 equally likely next tokens.
  • Lower is better. A perfect model that always assigns probability 1 to the true token has perplexity 1; a uniform guess over |V| tokens has perplexity |V|.
  • It is intrinsic (no downstream task needed) but tokenizer-dependent — compare perplexities only across models that share the same tokenization.
PPL = exp( −(1/N) ∑t=1..N log P(wₜ | w₁ … wt−1) ) equivalently PPL = ( ∏t P(wₜ | context) )−1/N = 2 H where H = cross-entropy in bits

Type or pick a continuation: predictable words keep perplexity low; a surprising word spikes the running score.

05 Neural language models

Neural LMs beat counting by replacing the lookup table with a learned function — tokens become embeddings, so the model generalizes across similar words it never saw together.

The ladder of architectures

  • Feed-forward NLM (Bengio, 2003): concatenate the embeddings of a fixed window of previous tokens, push through an MLP, softmax over the vocabulary. Generalizes — "cat" and "dog" share structure — but the context is still a fixed window.
  • RNN / LSTM: carry a recurrent hidden state that, in principle, summarises the entire history. Variable-length context at last — but training is sequential and long-range gradients fade (vanishing-gradient).
  • Transformer: drop recurrence; let self-attention connect every position to every other directly and in parallel. This is the architecture behind all modern LLMs — see Transformers.

Why neural wins

  • Generalization via embeddings: similar tokens get similar vectors, so evidence is shared across them — no per-n-gram table, no hard zeros.
  • Longer effective context: from fixed windows (n-grams, FFNN) to unbounded-in-principle (RNN) to long, parallel, content-addressed context (attention).
  • Parameters instead of counts: a fixed-size network compresses the corpus into weights, smoothly interpolating to unseen contexts rather than memorising tables.

06 Training objectives

All three read text and predict held-out tokens, but what they predict — and which tokens may see which — defines what the model is good for.

Causal / autoregressive LM (GPT-style)

  • Predict the next token given only the tokens to its left. A causal mask hides the future, so the model can generate left-to-right at inference.
  • Decoder-only. This is the objective that scales into generative LLMs.

Masked LM (BERT-style)

  • Corrupt the input by masking ~15% of tokens; predict the originals using both left and right context (bidirectional). Fill-in-the-blank.
  • Encoder-only. Great representations for classification, retrieval, NER — but it can't generate left-to-right by construction.

Sequence-to-sequence (T5-style)

  • An encoder reads the input bidirectionally; a decoder generates the output autoregressively, attending back to the encoder.
  • Natural for transduction tasks — translation, summarization — where input and output are distinct sequences.

The causal next-token objective looks the most restrictive yet has proven the most general: a model that can continue any prompt can be steered to classify, translate, and reason — see Large Language Models.

07 Decoding & sampling strategies

The model gives a distribution; decoding turns it into text. The strategy trades coherence against diversity — and the same model can sound robotic or unhinged depending on it.

Deterministic search

  • Greedy: always take the single most probable token (argmax). Fast, but myopic — it gets stuck in bland, repetitive loops.
  • Beam search: keep the k highest-probability partial sequences at each step. Better for tasks with one right answer (translation); for open-ended text it produces dull, generic output.

Stochastic sampling

  • Temperature T rescales the logits before softmax. T → 0 approaches greedy (sharp); T = 1 is the raw distribution; T > 1 flattens it, raising diversity and risk.
  • Top-k: keep only the k most probable tokens, renormalise, sample. Caps the tail at a fixed count.
  • Top-p (nucleus): keep the smallest set of tokens whose probability sums to p (e.g. 0.9). The candidate set grows when the model is unsure and shrinks when it's confident — usually the best default.

Lower temperature / smaller k / smaller p ⇒ safer, more repetitive. Higher ⇒ more creative, more error-prone. There is no universally best setting — it depends on whether you want a fact or a poem.

08 From language models to LLMs

Nothing about the objective changes — it's still next-token prediction. What changes is scale: more parameters, more data, more compute. Past a threshold, new abilities emerge.

  • Scaling laws: test loss falls predictably and smoothly as a power law in parameters, data, and compute — which is why scaling is a deliberate strategy, not luck.
  • Emergent abilities: capabilities like in-context learning (learning a task from prompt examples, no weight updates), instruction following, and multi-step reasoning appear only at sufficient scale.
  • Same machine, new behaviour: a pure next-token predictor, scaled, can be prompted to translate, summarise, code, and reason — and aligned via preference optimization to follow instructions.
  • Grounding the model's output in retrieved evidence reduces hallucination — see Retrieval-Augmented Generation.

09 Takeaways

  • A language model assigns probability to token sequences; by the chain rule, that is exactly the same as predicting the next token, one step at a time.
  • N-grams approximate the history with a Markov window and estimate by counting — simple but doomed by sparsity, which smoothing only partly patches.
  • Perplexity measures held-out surprise — the average branching factor; lower is better, but it's tokenizer-dependent.
  • Neural LMs win by representing tokens as embeddings that generalize, culminating in the parallel, long-context Transformer.
  • The causal next-token objective (vs masked or seq2seq) is what scales into generative LLMs.
  • Decoding — greedy, beam, temperature, top-k, top-p — converts the distribution into text and tunes the coherence-vs-diversity dial.
