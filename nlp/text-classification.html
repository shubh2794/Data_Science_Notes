Text Classification & Sentiment

Assigning labels to text — the workhorse task of applied NLP, from spam filters to sentiment to intent routing.

NLP Supervised Sentiment

01 The task & its label schemes

Text classification maps a document to one or more labels from a fixed set. The label scheme decides the output layer and the loss — get it wrong and the model can't even express the right answer.

  • Binary: one decision (spam / not-spam, positive / negative). One sigmoid output, thresholded at 0.5.
  • Multi-class (single-label): exactly one of K classes (topic = sports / politics / tech). A softmax over K logits — the probabilities sum to 1, so classes compete.
  • Multi-label: any subset of K tags can fire at once (an article tagged both "finance" and "tech"). K independent sigmoids — each tag is its own yes/no, no competition.
softmax(z)k = e^(zk) / Σj e^(zj) (single-label: classes compete) σ(zk) = 1 / (1 + e^(−zk)) (multi-label: each tag independent)

Common bug: using softmax for a multi-label problem. Softmax forces the probabilities to compete and sum to 1, so it can never confidently assign two tags at once — use independent sigmoids instead.

02 The classic pipeline: sparse features + a linear head

Before fine-tuned transformers, the strong baseline was sparse features → a linear classifier. It is fast, interpretable, and still hard to beat on small, clean datasets.

Bag-of-Words & TF-IDF

  • Bag-of-Words: represent a document by its word counts, ignoring order. Sparse and vocabulary-sized — see Text Preprocessing for the cleaning that feeds this.
  • TF-IDF reweights counts so common words ("the", "is") shrink and rare, distinctive words grow — sharpening the signal a linear model keys on.
TF-IDF(t, d) = TF(t, d) · log( N / DF(t) ) TF = count of term t in doc d DF = #docs containing t N = total docs

Linear classifiers on top

  • Logistic regression on TF-IDF: a strong, calibrated, interpretable baseline — coefficients tell you which words push a class.
  • Naive Bayes (multinomial): assumes word independence given the class. Cheap, surprisingly competitive on short text, and a classic spam baseline — see the Naive Bayes note for the derivation.
  • Linear SVM: maximum-margin separator over sparse features; long the default for topic classification.
Why it still matters: a TF-IDF + logistic-regression baseline trains in seconds and sets the bar. If a 110M-parameter transformer can't beat it, your data — not your model — is the bottleneck.

03 The modern pipeline: fine-tuned encoders & zero-shot

Dense, contextual representations replaced sparse counts. The dominant recipe is a pretrained encoder with a small classification head fine-tuned on your labels.

Fine-tuned encoder

  • Feed text through an encoder (e.g. BERT); take a single sentence vector via the [CLS] token or by mean-pooling token vectors (which build on Embeddings).
  • Add a linear head W·h + b → softmax/sigmoid, and fine-tune end-to-end. The pretrained backbone already "understands" language, so a few thousand labels often suffice.
h = Encoder(x) ŷ = softmax( W · h[CLS] + b )

Zero-shot & prompt-based

  • Entailment-based zero-shot: pose "this text is about {label}" as a hypothesis and use an NLI model (see Textual Entailment) to score it — classify with no task-specific training.
  • LLM prompting: ask an instruction-tuned model to pick a label directly. Flexible and label-free, but slower, pricier, and less calibrated than a fine-tuned head at scale.

04 Sentiment & aspect-based sentiment

Sentiment analysis is text classification with a polarity target. The subtlety is that one sentence can hold several opinions about different things.

  • Document/sentence sentiment: one polarity for the whole text (positive / negative / neutral). The canonical intro task.
  • Aspect-based sentiment (ABSA): extract (aspect term, polarity) pairs. "The battery is great but the screen is dim" → (battery, +), (screen, −).
  • ABSA is two sub-problems: aspect extraction (a span task, like NER) and aspect polarity (classification conditioned on that span).
Why a single label fails: averaging "great battery" and "dim screen" into one "mixed" verdict throws away exactly the structured opinion a product team needs. ABSA keeps the per-aspect signal.

05 Class imbalance: why accuracy lies

Real corpora are skewed — 1% of emails are fraud, 2% of reviews are 1-star. A model that predicts "majority" for everything scores high accuracy and is useless.

  • Accuracy is the wrong meter: at 99% negatives, "always negative" gets 99% accuracy while catching zero positives. Track precision/recall/F1 on the minority class instead.
  • Resampling: oversample the minority (or SMOTE-style synthesis) / undersample the majority — see Data Sampling & Imbalance for the trade-offs.
  • Class weights: scale each class's loss by its inverse frequency so a rare-class mistake hurts more.
  • Focal loss: down-weight easy, confident examples by a factor (1 − pt)γ so training focuses on the hard, rare cases.
weighted CE: L = − Σk wk · yk · log pk wk ∝ 1 / freq(k) focal loss: L = − (1 − pt)γ · log pt (γ > 0 focuses on hard examples)

06 Evaluation: precision, recall, F1 & the threshold

Classification quality is a trade-off curve, not a single number. Precision and recall pull against each other, and the threshold is the dial between them — a theme shared with Model Evaluation.

precision = TP / (TP + FP) recall = TP / (TP + FN) F1 = 2 · precision · recall / (precision + recall) (harmonic mean)
  • Precision: of what you flagged, how much was right. Recall: of what was truly positive, how much you caught.
  • Threshold: raise it → fewer, surer positives (↑precision, ↓recall); lower it → catch more, with more false alarms (↑recall, ↓precision).
  • Averaging across classes: macro-F1 averages per-class F1 equally (minority counts as much as majority); micro-F1 pools all TP/FP/FN (dominated by frequent classes); weighted averages by support.

MacroMean of per-class F1Minority classes matter equally
