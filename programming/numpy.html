NumPy

One contiguous, single-dtype block of memory and the rules for slicing, aligning, and reducing it. Understanding strides, views, and broadcasting is what turns NumPy from "arrays" into a mental model for every array library after it.

02 The ndarray: shape, dtype & strides

An array is a flat 1-D buffer plus a tiny piece of metadata — a shape and a strides tuple — that tells NumPy how to walk that buffer as if it were n-dimensional.

  • shape = elements per axis. strides = how many bytes to step to advance one index along each axis.
  • C order (row-major, the default): the last axis is fastest — consecutive elements in the last axis are adjacent in memory. For a 4×3 float64 array the strides are (24, 8): step 8 bytes for the next column, 24 bytes (one whole row) for the next row.
  • Fortran order (column-major): the first axis is fastest. The same 4×3 float64 array would have strides (8, 32) — generally written (s, m·s) for an m-row array.
  • The address rule: any element's byte offset is just a dot product of its index tuple with the strides. This is why reshaping, transposing, and slicing can be free — they only rewrite metadata.
offset = base + Σₖ iₖ · strideₖ C-order (m×n, itemsize s): strides = (n·s, s) Fortran-order: strides = (s, m·s) 4×3 float64, C-order: strides = (24, 8)
  • View vs copy at the buffer level: a view keeps the same base buffer and only changes shape/strides (no data moved). A copy allocates a fresh buffer and moves the bytes. The next section turns this distinction into a famous gotcha.

Why row-major matters: iterating along the fast axis walks memory linearly and stays in cache; iterating along the slow axis jumps a stride each step and thrashes cache. Same math, very different speed — layout is a performance knob.

03 Views vs copies — the aliasing gotcha

The single most common NumPy surprise: basic slicing returns a view that shares the parent's memory. Mutate the slice and you silently mutate the parent.

  • Basic slicing → VIEW. y = x[1:7:2] shares x's buffer. Writing y[0] = 99 changes x too. This is the aliasing gotcha — fast and memory-light, but surprising.
  • Fancy / advanced indexing → COPY. Indexing with an integer array (x[[0,3,5]]) or a boolean mask (x[x > 0]) cannot be expressed as offset + stride, so NumPy materializes a fresh buffer. Writing into it never touches the parent.
  • Detect it with .base: a view's .base points at the array it borrows from; a copy's .base is None. np.shares_memory(a, b) answers it directly.
  • The fix for isolation: call .copy() when you want a detached array you can mutate freely.
x[1:7:2] → VIEW · y.base is x · y[0]=99 also changes x x[[0,3,5]] → COPY · z.base is None · z[0]=99 leaves x untouched

Rule of thumb: if a selection could be described by "start, stop, step" it is a view; if it needs an explicit list of positions or a mask it is a copy. When in doubt, .copy() and move on.

04 Broadcasting

Broadcasting lets arrays of different shapes combine without writing loops or physically tiling data. NumPy stretches size-1 axes virtually — with a stride of 0, so no memory is copied.

  • Align right-to-left. Compare shapes from the trailing dimension backward. A missing leading dimension is treated as 1.
  • Compatibility per axis: two dimensions are compatible iff they are equal or one of them is 1. Otherwise → ValueError.
  • Result dimension is the max of the two. The size-1 axis is virtually stretched (stride 0 — the same element is reread), never duplicated in memory.
(8 × 1 × 6 × 1) with ( 7 × 1 × 5) → (8 × 7 × 6 × 5) ✓ (256 × 256 × 3) with ( 3) → (256 × 256 × 3) ✓ (per-channel scale) ( 3) with ( 4) → ValueError ✗ (3 ≠ 4, neither is 1)

Why it's free: a stretched axis is stride-0 — every "row" of the stretched operand points at the same bytes. Broadcasting is a clever read pattern, not a memory blow-up.

05 Axis reductions

Every reduction (sum, mean, max, …) takes an axis. The rule is dead simple: the named axis disappears.

  • For A of shape (m, n):
  • A.sum(axis=0) → shape (n,) — collapse the rows, summing down each column. "Axis 0 (the rows) vanishes."
  • A.sum(axis=1) → shape (m,) — collapse the columns, summing across each row. "Axis 1 (the columns) vanishes."
  • keepdims=True leaves a size-1 axis behind so the result broadcasts straight back against the original — the idiom for row/column normalization.
A.sum(axis=0): (m, n) → (n,) down columns A.sum(axis=1): (m, n) → (m,) across rows A − A.mean(axis=1, keepdims=True) → row-centered (broadcasts (m,1) over (m,n))
Mnemonic: "axis=k is the axis you sum over, so it's the axis that goes away." Forgetting which way axis=0 points is the most common reduction bug — anchor on "axis 0 is the row index, summing it walks down columns."
