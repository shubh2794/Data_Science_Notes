R

A statistics-first language in which the vector, not the scalar, is the unit of data, the model formula is a first-class object, and fitting a regression and reading its inference table is one line each. Where Python is a general-purpose language that acquired a statistics stack, R is a statistics environment that acquired general-purpose features. The craft is to think in whole vectors, to know exactly how a formula like y ~ x * g becomes the columns of a design matrix, and to treat tables and plots as compositions of a small set of verbs and layers.

01 Why R: an environment built around inference

R descends from S, a language designed for interactive data analysis, and its defaults reflect that lineage: missing values are a native type, every model returns standard errors, and the package archive is curated for statistical methodology.

  • Inference is the default output. summary(lm(...)) prints estimates, standard errors, t statistics, p-values, R² and an F test without configuration. Classical methods — hypothesis tests, ANOVA and multiple comparisons, mixed models, survival analysis, GAMs — are usually available first, and most completely, in R.
  • The package ecosystem. CRAN checks every package on several platforms before accepting it and re-checks it against new R releases; Bioconductor does the same for genomics. A new statistical method is frequently published together with its R package.
  • Visualization as a grammar. ggplot2 (§09) describes a chart as data mapped to aesthetics and drawn by layers, which makes complex, publication-quality figures compositional rather than imperative.
  • Literate analysis. R Markdown and Quarto weave code, output and prose into one reproducible report — a natural fit for data storytelling and parameterised reports.
Mental model: R is optimised for the analyst's loop — load, explore, model, check assumptions, plot, report — rather than for building services. That focus explains both its strengths (§07–§09) and its rough edges as a general-purpose language (§11).

02 The vector-first data model and recycling

R has no scalar type. The number 3 is an atomic vector of length 1. Every arithmetic and comparison operator is element-wise over vectors, so the idiomatic loop is usually no loop at all.

  • Atomic vectors are homogeneous. Six atomic types — logical, integer, double, character, complex, raw. Combining types with c() coerces up the hierarchy logical → integer → double → character, so c(1, "a", TRUE) is a character vector "1" "a" "TRUE".
  • Recycling. When two vectors of different length meet in an element-wise operation, the shorter one is repeated to the length of the longer. A length that does not divide evenly still recycles, but with a warning.
  • Indexing is 1-based and takes vectors: positive indices select, negative indices drop, a logical vector filters (and is itself recycled), and names select by label.
  • NA is a value, not an exception. Each type has its own missing value; arithmetic with NA yields NA, comparisons yield NA, and summaries need na.rm = TRUE. NULL is different: the absence of an object, with length 0.
  • Copy-on-modify. y <- x; y[1] <- 99 leaves x unchanged: R copies lazily when a shared object is modified. This removes Python's aliasing surprises (see Python) at the cost of hidden copies inside loops that grow a vector one element at a time.
x <- c(1, 2, 3, 4)
x + c(10, 20)            # recycling: 11 22 13 24
c(1, 2, 3) + c(10, 20)   # 11 22 13, with warning: longer object length is not a multiple
x[c(-1, -2)]             # drop by negative index: 3 4
x[x > 2]                 # logical filter: 3 4
mean(c(2, NA, 4))            # NA
mean(c(2, NA, 4), na.rm = TRUE)  # 3
sqrt(1:5)                # vectorized; no explicit loop
recycling rule for an element-wise operation on lengths n and mlength(result) = max(n, m) result[k] = a[((k − 1) mod n) + 1] ⊕ b[((k − 1) mod m) + 1] warning if max(n, m) is not a multiple of min(n, m)
Why it matters: recycling is what makes x - mean(x) and (x - mean(x)) / sd(x) work without broadcasting rules: a length-1 vector recycles to any length. It is also the source of silent bugs when two columns of unintended lengths meet — the warning only fires when the lengths do not divide.

03 Lists, data frames and tibbles

A list is a heterogeneous vector whose elements can be anything, including other lists. A data frame is a list of equal-length column vectors with a names and a row.names attribute — a table stored column-wise, exactly as a columnar engine stores it.

  • Three ways to extract. df["col"] returns a one-column data frame (a sub-list); df[["col"]] and df$col return the vector itself. df[rows, cols] indexes both dimensions; df[df$x > 0, ] filters rows — the trailing comma means "all columns".
  • Tibbles are data frames with stricter, friendlier behaviour: they print only the first rows and the column types, never convert strings to factors, never use row names, do not partially match column names with $ (a base data frame will silently match df$co to df$colname; a tibble warns and returns NULL), and tbl[, "x"] always returns a tibble rather than dropping to a vector.
  • List-columns. Because a data frame is a list, a column can itself be a list — one fitted model, one nested table or one vector per row — the basis of the nest-and-map workflow for fitting a model per group.
  • Strings are no longer factors by default. Since R 4.0.0, data.frame() and read.csv() use stringsAsFactors = FALSE.
df <- data.frame(id = 1:3, grp = c("a", "b", "a"), y = c(2.1, 3.4, 1.9))
str(df)                  # 'data.frame': 3 obs. of 3 variables
df[df$grp == "a", "y"]   # 2.1 1.9   (drops to a vector)
library(tibble)
tb <- as_tibble(df)
tb[tb$grp == "a", "y"]   # a 2 x 1 tibble   (stays a table)

04 Factors: categorical data with a level set

A factor is an integer vector of codes plus a levels attribute naming the categories. It is how R represents a categorical variable, and it decides how that variable enters a model.

  • Levels are sorted alphabetically by default. factor(c("lo", "hi", "mid")) has levels hi lo mid. Set the order explicitly with factor(x, levels = c("lo", "mid", "hi")); ordered factors (ordered = TRUE) additionally support < comparisons.
  • The first level is the reference in a regression under the default treatment contrasts (§05). relevel(f, ref = "b") changes it, and changes every coefficient's meaning without changing the fitted values.
  • Unused levels persist after filtering, giving empty bars and zero-count table cells; droplevels() removes them.
  • The classic conversion bug. as.numeric() on a factor returns the internal codes, not the labels. A factor of numbers stored as text must go through character first.
  • The forcats package adds the common operations: reorder levels by another variable (fct_reorder, the fix for unsorted bar charts), lump rare levels into "Other" (fct_lump), recode labels.
f <- factor(c("10", "20", "10"))
levels(f)                    # "10" "20"
as.numeric(f)                # 1 2 1      the codes, not the values
as.numeric(as.character(f))  # 10 20 10   correct
Pandas parallel: a factor is a pd.Categorical — integer codes plus categories. The difference is that R's modelling functions act on the factor's level set automatically, while in Python you usually choose an encoder by hand.

05 The formula interface and the design matrix

A formula like y ~ x1 + x2 * x3 is an unevaluated object describing a model's structure. Modelling functions turn it into a numeric design matrix X using the data, then solve a linear algebra problem. Knowing the translation is the difference between fitting the model you meant and one you did not.

Formula operators

SyntaxExpands toMeaning
y ~ a + b1 + a + bMain effects; an intercept is implicit.
y ~ a:b1 + a:bOnly the interaction (product) term.
y ~ a * b1 + a + b + a:bMain effects plus interaction.
y ~ x1 + x2 * x31 + x1 + x2 + x3 + x2:x3: binds tighter than *, which binds tighter than +.
y ~ (a + b + c)^2a + b + c + a:b + a:c + b:cAll terms up to second order.

From terms to columns

A numeric variable becomes one column. A factor with k levels becomes, under the default treatment contrasts, k − 1 indicator columns — one per non-reference level — because together with the intercept a full set of k indicators would be collinear (they sum to the intercept column). An interaction column is the element-wise product of its parents' columns. The model is then the ordinary linear system:

the design matrix and least-squares fit behind lm()y = Xβ + ε β̂ = argmin ‖y − Xβ‖² = (XᵀX)⁻¹Xᵀy (computed by QR, never by inverting XᵀX) treatment coding of a factor g with levels a (reference), b, cx_gb = 1[g = b] x_gc = 1[g = c] a is absorbed by the intercept y ~ x * g: one intercept and one slope per groupŷ = β₀ + β₁x + β₂·1[g=b] + β₃·1[g=c] + β₄·x·1[g=b] + β₅·x·1[g=c] group a: intercept β₀, slope β₁ group b: intercept β₀ + β₂, slope β₁ + β₄

The coefficient on x:gb is therefore a difference in slopes between group b and the reference, not group b's slope. R's heuristic for when a factor gets k − 1 contrast columns versus k indicator columns: a factor in a term is contrast-coded if the term with that factor removed (its margin) is empty or is contained in an earlier term of the model; otherwise it is fully indicator-coded. With no intercept, the first factor in the model is switched to full indicators so that something spans the constant. That is why y ~ x:g produces three columns x:ga, x:gb, x:gc (no x main effect to absorb one), while y ~ x + x:g produces two. The matrix view connects directly to projections and least squares: lm projects y onto the column space of X.

d <- data.frame(x = 1:6, g = factor(rep(c("a", "b", "c"), 2)))
model.matrix(~ x * g, d)
#   (Intercept) x gb gc x:gb x:gc
# 1           1 1  0  0    0    0
# 2           1 2  1  0    2    0
# 3           1 3  0  1    0    3
# ...

06 Interactive: formula → design matrix explorer

An eight-row dataset with a numeric x, a three-level factor g and a two-level factor h. Type a right-hand side (operators + - * : / ^ ( ), 0/1, and I(x^2), I(x^3), log(x)) or pick a preset. The explorer expands the terms in R's order, applies treatment contrasts with R's margin rule, builds X, and fits least squares. Columns that are linear combinations of earlier ones are flagged aliased — reported as NA, just as lm does.

Things to try: g versus g - 1 (the intercept becomes group a's mean, or each group gets its own column); changing the reference level under x * g (every coefficient changes, the fitted values do not); x * g * h (12 columns for 8 rows — the fit runs out of rank, exactly the warning sign of an over-specified model).

07 lm, glm and reading the summary

A fitted model is an object (a list with a class) that generic functions understand: summary, coef, confint, predict, residuals, plot, anova. The same verbs work across hundreds of model types.

fit <- lm(mpg ~ wt + hp, data = mtcars)
summary(fit)

Residuals:

-3.941 -1.600 -0.182  1.050  5.854

Coefficients:
            Estimate Std. Error t value Pr(>|t|)
(Intercept) 37.22727    1.59879  23.285  < 2e-16 ***
wt          -3.87783    0.63273  -6.129 1.12e-06 ***
hp          -0.03177    0.00903  -3.519  0.00145 **

F-statistic: 69.21 on 2 and 29 DF,  p-value: 9.109e-12
  • Estimate βⱼ: each extra 1,000 lb of weight lowers fuel economy by 3.88 mpg at fixed horsepower.
  • t value = Estimate / Std. Error, compared against a t distribution with n − p = 32 − 3 = 29 degrees of freedom; Pr(>|t|) is the two-sided p-value for H₀: βⱼ = 0 given the other terms. The stars are thresholds on that p-value, not effect sizes.
  • Residual standard error is the estimate of σ, √(RSS / (n − p)). Adjusted R² penalises the number of predictors. The F-statistic tests all slopes jointly against the intercept-only model.
  • The theory behind each line — sampling distributions of β̂, the t and F tests — is on Regression & Correlation and Linear Regression.
the quantities in a summary(lm) tableSE(β̂) = σ̂·√diag((XᵀX)⁻¹) t = β̂ⱼ / SE(β̂ⱼ) σ̂ = √( RSS / (n − p) ) F = [ (TSS − RSS) / (p − 1) ] / [ RSS / (n − p) ] R²_adj = 1 − (1 − R²)(n − 1)/(n − p) p counts the intercept

Generalized linear models

glm fits g(E[y]) = Xβ for an exponential-family response by iteratively reweighted least squares. The formula and design matrix are identical; only the family (and its link) changes.

m <- glm(am ~ wt, family = binomial, data = mtcars)   # logistic regression
summary(m)
#             Estimate Std. Error z value Pr(>|z|)
# (Intercept)   12.040      4.510   2.670  0.00759 **
# wt            -4.024      1.436  -2.801  0.00509 **
# (Dispersion parameter for binomial family taken to be 1)
#     Null deviance: 43.230  on 31  degrees of freedom
# Residual deviance: 19.176  on 30  degrees of freedom
# AIC: 23.176
# Number of Fisher Scoring iterations: 6

exp(coef(m))["wt"]                     # odds ratio 0.018 per 1,000 lb
predict(m, data.frame(wt = 3), type = "response")   # probability, not log-odds
anova(m, test = "Chisq")               # deviance (likelihood-ratio) test
  • Coefficients are on the link scale (log-odds here); exp() gives odds ratios. Tests are z (Wald) tests, not t tests, because the dispersion is known.
  • Deviance = −2 × log-likelihood relative to a saturated model. The drop from null to residual deviance (43.23 − 19.18 = 24.05 on 1 df) is a likelihood-ratio test of wt; anova() computes it.
  • Other families: poisson for counts (log link), Gamma for positive skewed data, quasibinomial/quasipoisson to estimate over-dispersion. See Logistic Regression.
Takeaway: predict(m) returns the linear predictor by default; pass type = "response" for probabilities. Mixing the two scales is the single most common glm mistake.

08 The tidyverse: dplyr verbs and pipes

The tidyverse is a family of packages sharing one data model — tidy data: each variable a column, each observation a row, each value a cell — and one style: small functions that take a data frame first and return a data frame, chained with a pipe.

VerbDoesSQL analogue

library(dplyr)
mtcars |>
  filter(hp > 100) |>
  mutate(kpl = mpg * 0.425) |>
  group_by(cyl) |>
  summarise(n = n(), mean_kpl = mean(kpl), .groups = "drop") |>
  arrange(desc(mean_kpl))
  • Pipes. x |> f(y) means f(x, y). The native pipe |> arrived in R 4.1.0; the older %>% from magrittr is equivalent for most uses and supports the . placeholder. Pipes read top-to-bottom in the order the operations happen.
  • Non-standard evaluation. Inside verbs you write hp > 100, not df$hp > 100: the verb evaluates column names in the data frame's scope ("data masking"). Convenient interactively; inside your own functions, refer to columns passed as arguments with {{ col }} or the .data[[name]] pronoun.
  • Column-wise operations. across() applies a function to many columns: summarise(across(where(is.numeric), mean)).
  • The same verbs translate to SQL through dbplyr (see SQL), and to Spark through sparklyr (see Apache Spark): you write dplyr, the backend runs the query.

09 ggplot2 and the grammar of graphics

A chart is not a "chart type"; it is a mapping from data variables to visual properties, drawn by one or more geometric layers, through scales, in a coordinate system, optionally split into facets. ggplot2 exposes each of these as a component you add with +.

ComponentFunctionRole
Dataggplot(df, …)A tidy data frame.
Aesthetic mappingaes(x, y, colour, size, fill, group)Which variable drives which visual channel.
Geomgeom_point, geom_line, geom_col, geom_boxplotThe mark drawn for each observation or group.
Statstat_bin, stat_count, stat_smoothA transformation before drawing; each geom has a default (geom_histogram bins, geom_bar counts, geom_smooth fits).
Scalescale_x_log10, scale_colour_viridis_dMap data values to positions, colours, sizes; draws axes and legends.
Coordinatescoord_flip, coord_polar, coord_cartesianThe space the positions live in; coord_cartesian(xlim) zooms without dropping data.
Facetsfacet_wrap(~ g), facet_grid(r ~ c)Small multiples, one panel per subset.
Themetheme_minimal(), theme(...)Non-data ink: fonts, grid, background.
library(ggplot2)
ggplot(mtcars, aes(x = wt, y = mpg, colour = factor(cyl))) +
  geom_point(size = 2) +
  geom_smooth(method = "lm", se = TRUE) +      # one fit per colour group
  scale_x_continuous("weight (1,000 lb)") +
  facet_wrap(~ am, labeller = label_both) +
  theme_minimal()
  • Mappings inherit. aes() in ggplot() applies to every layer; aes() in a geom applies only there. Mapping colour = factor(cyl) globally is what makes geom_smooth fit one line per group.
  • Mapping vs setting. aes(colour = cyl) maps a variable to colour (and makes a legend); geom_point(colour = "red") sets a constant. Putting a constant inside aes() is a classic mistake.
  • Scale limits drop data. scale_y_continuous(limits = …) removes out-of-range rows before the stat runs, which changes smoothers and boxplots; zoom with coord_cartesian() instead.
  • The grammar is the same one behind most declarative charting libraries; Dashboards covers turning such charts into interactive monitoring views, and Shiny is R's way to build them.

Two traps when switching: R's x[-1] removes the first element while Python's selects the last; and R's 1:n includes n while Python's range(n) stops before it. Python's statsmodels formula API deliberately mimics R's formula syntax, so §05 transfers almost verbatim — though pandas columns of strings are treated as categorical automatically, with alphabetical reference levels just like R.

11 When to use R — and when not to

Reach for R when…Reach for something else when…
The deliverable is inference: effect sizes, confidence intervals, tests, diagnostics.The deliverable is a service: an API, a long-running job, a model behind deployment infrastructure built around Python.
You need a specialised statistical method (mixed models, survival, survey weights, Bayesian hierarchical models, econometrics).You need deep learning; the frameworks, model hubs and GPU tooling are Python-first.
The output is a reproducible report or a publication-quality figure.The data does not fit in memory and you are not using a database or Spark backend.
The team and its reviewers already read R (biostatistics, epidemiology, social science, actuarial work).The rest of the stack is general-purpose engineering and the analysis must live inside it.
  • Performance. Vectorised base functions run in C; explicit R loops are slow mainly when they grow objects one element at a time. Preallocate, vectorise, or use data.table (fast in-memory grouping and joins) or arrow/duckdb for larger-than-memory columnar data.
  • Interop. reticulate calls Python from R (and shares objects); Arrow and Parquet move tables between the two without conversion cost. Mixed teams commonly do modelling and reporting in R and serving in Python.
  • Reproducibility. Pin package versions per project with renv, keep analyses as scripts or Quarto documents rather than console history, and record runs and parameters as you would anywhere else — see Experiment Tracking.
  • Object systems. S3 (informal, dispatch on the class attribute — how summary() works on every model), S4 (formal classes, common in Bioconductor) and R6 (reference semantics, mutable objects). Most analysis code only ever meets S3.
The one idea: R's power is that the statistical model is a first-class citizen — a formula becomes a design matrix, a fit becomes an object with an inference table, a table becomes a plot through a grammar. Use it where that pipeline is the work; hand off to a general-purpose stack where the work is engineering.
