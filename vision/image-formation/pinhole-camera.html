12 The projection family below perspective

Real cameras are perspective. Three approximations to perspective are nevertheless used constantly, and not out of laziness: each of them is affine, and affine models make certain estimation problems solvable in closed form that are otherwise iterative. Knowing exactly what each one throws away tells you exactly when you may use it.

Orthography

drop the depth coordinate. That is the entire model.x = [I₂ₓ₂ | 0] p i.e. x = X, y = Y in homogeneous form — keep w, drop z ⎡ 1 0 0 0 ⎤ x̃ = ⎢ 0 1 0 0 ⎥ p̃ no division anywhere: the result is already inhomogeneous ⎣ 0 0 0 1 ⎦ SCALED ORTHOGRAPHY — the same thing with one global scale, which is what any real sensor needsx = [sI₂ₓ₂ | 0] p with s = f / z̄, z̄ the representative depth of the object

Orthography is exact only for a telecentric lens, and a good approximation for a long focal length viewing an object whose depth extent is small compared with its distance. Its value is that structure and motion can be recovered from an orthographic image sequence by a single singular value decomposition — the factorisation method — with no initialisation and no iteration. Part 7 uses that as the starting point it then refines perspectively.

Para-perspective, and what the family really is

Para-perspective projects each point parallel to the line of sight to the object's centre onto a reference plane, then scales. The result is still affine — still a 3×4 matrix with bottom row [0 0 0 1], still no per-point division — but it captures the first-order depth effect that scaled orthography misses.

para-perspective, for an object whose centre is c = (cₓ, c_y, c_z)x = (f/c_z) · ( X − cₓ(Z − c_z)/c_z ) y = (f/c_z) · ( Y − c_y(Z − c_z)/c_z ) which is affine — written out for c = (0.6, 0.2, 8) and f = 500x = 62.5 · X + 0 · Y − 4.6875 · Z + 37.5 y = 0 · X + 62.5 · Y − 1.5625 · Z + 12.5 (checked: agrees to 2 × 10⁻¹⁴) and here is the unifying statement — the whole family is one Taylor seriesperspective: x = f X / Z, expanded about the object's centre depth Z = c_z scaled orthography: the ZEROTH-order term x ≈ (f/c_z) X para-perspective: the ZEROTH plus FIRST order x ≈ (f/c_z) X − (f cₓ/c_z²)(Z − c_z) perspective: all orders — the exact quotient (verified: para-perspective and the first-order expansion agree to 1.6 × 10⁻¹⁴)

Object-centred projection, and the zoom–dolly ambiguity

Write out perspective with the simple K and stare at the denominator.

the projection, in fullx_s = f (rₓ · p + tₓ)/(r_z · p + t_z) + cₓ y_s = f (r_y · p + t_y)/(r_z · p + t_z) + c_y if the object is small compared with its distance, r_z · p ≪ t_z, and the denominator is ≈ t_zso the size of the projected object depends only on the RATIO f / t_z → a longer lens and a nearer object are indistinguishable from one image. This is a real ambiguity, not a numerical difficulty: infinitely many (f, t_z) pairs produce the same picture. the reparameterisation that separates themlet η_z = 1/t_z and s = η_z f. Then x_s = s (rₓ · p + tₓ)/(1 + η_z r_z · p) + cₓ y_s = s (r_y · p + t_y)/(1 + η_z r_z · p) + c_y s is well determined by the object's apparent SIZE; η_z is determined only by its FORESHORTENING. and as the lens lengthens, η_z → 0 smoothly — orthography is the limit, with nothing going to infinity.

The last clause is the practical payoff. Under the naive parameterisation, approaching orthography means driving both f and t_z to infinity while holding their ratio fixed, which no optimiser will do gracefully. Under (s, η_z) the same limit is η_z → 0, an ordinary finite point in parameter space. This is the reason an orthographic initialisation can be refined continuously into a perspective solution rather than being thrown away.

13 Perspective: one division, and everything it costs

The whole of perspective is x = X/Z, y = Y/Z. Every distinctive property of a photograph — that distant things are small, that parallel lines converge, that a horizon exists, that depth is unrecoverable — is a consequence of that single quotient, and each of them can be derived from it in a line or two.

The map

inhomogeneousx̄ = P_z(p) = ( X/Z , Y/Z , 1 ) homogeneous, where it is linear — drop w rather than z ⎡ 1 0 0 0 ⎤ x̃ = ⎢ 0 1 0 0 ⎥ p̃ the CANONICAL camera: centre at the origin, axis along +z, f = 1 ⎣ 0 0 1 0 ⎦ the 3 × 4 matrix has a one-dimensional null space — spanned by (0, 0, 0, 1), the camera centre — and that null space IS the information the projection destroys

Four consequences, each derived in one line

consequence 1
Depth is gone
Every point λp on the ray through p gives the same (X/Z, Y/Z). The pre-image of a pixel is a whole ray, and no operation on one image narrows it. Recovering depth needs a second constraint — another view, another moment, or an assumption.
consequence 2
Size ∝ 1/depth
An object of height h at depth Z subtends fh/Z pixels. Double the distance, halve the image size — exactly, with no approximation. This is the relation §12's affine models linearise away.
consequence 3
Straight lines stay straight
A 3D line together with the camera centre spans a plane; that plane cuts the image plane in a line, and every point of the 3D line projects onto it. So straightness survives projection exactly. A real photograph bends lines anyway — that is the lens, not the projection, and it is §17.
consequence 4
Parallel lines converge
A family of parallel lines shares one point at infinity, and the projection maps that point somewhere finite. That image is the vanishing point, and it depends only on the direction, never on which line of the family you picked.

Vanishing points and the horizon, worked on the running camera

A 3D direction d is the ideal point (d, 0). Push it through P = K[R|t]: the translation multiplies the zero and drops out entirely, leaving v = K R d. So the vanishing point depends on the camera's orientation and intrinsics only — moving the camera does not move it. That is why vanishing points are what Part 7 uses to calibrate rotation without knowing position.

So the horizon is exactly the row v = c_y = 240, for a camera with no pitch and no roll.

That result deserves its own sentence: for a level camera the horizon passes through the principal point, whatever the camera's height, whatever its focal length, and wherever it stands. It is a statement about orientation and nothing else. Tilt the camera down and the horizon rises above c_y; roll it and the horizon tilts by the roll angle. That is the whole basis of horizon-based attitude estimation.

And the practical corollary: depth from a single row

a ground point at depth z, seen by a camera of height h with a level optical axisp_c = (X, h, z) ⟹ v = f·h/z + c_y ⟹ z = f·h / (v − c_y) worked, running camera: f = 500, h = 1.5 m, c_y = 240 v = 490 → z = 750/250 = 3.00 m v = 333.75 → z = 750/93.75 = 8.00 m ✓ matches the running example v = 297.69 → z = 750/57.69 = 13.00 m ✓ v = 260 → z = 750/20 = 37.50 m v = 241 → z = 750/1 = 750.00 m and there is the catch, in the last two rowsdz/dv = −f·h/(v − c_y)² — the depth error per pixel grows as the SQUARE of the distance. At 3 m, one pixel of row error is 1.2 cm. At 37.5 m it is 1.88 m. At 750 m it is 750 m.

This is the single most useful trick available from one calibrated camera — the ground-plane assumption converts a row into a distance — and it comes with a precision that collapses quadratically as the horizon is approached. Both halves matter equally.

Drag the rails and the camera — vanishing points, the horizon, and depth read off a row the two rails are parallel in the world at every setting; where they meet is K R d
  • Change the rail direction and the vanishing point slides along the horizon. It never leaves it: every horizontal direction's vanishing point lies on the image of the ground plane's line at infinity, which is what "the horizon" means. Set the direction to ±90° and the vanishing point runs off to infinity — the rails become parallel in the image, because they are then parallel to the image plane.
  • Change the rail separation and the vanishing point does not move at all. It depends on direction only. Two rails one metre apart and two rails a kilometre apart converge on the same pixel.
  • Change the camera height and the horizon does not move either. Height changes where the ground is in the image, not where its infinity is. A camera on the floor and a camera on a roof, both level, put the horizon on exactly the same row.
  • Pitch moves the horizon; roll tilts it. Those are the only two things that do. That is why the horizon is an attitude sensor and not a position sensor.
  • Watch the depth-uncertainty figure as the probe approaches the horizon. It is not a numerical artefact; dz/dv genuinely diverges. Anything you want to measure by this trick must be near enough that its row is well clear of c_y.

14 Camera intrinsics: the calibration matrix K

Perspective projection produces a pair of dimensionless ratios. A sensor produces integer row and column indices. K is the affine map between them, and its five entries are the only things about a camera's optics that a linear model can express.

Where it comes from

The honest derivation runs backwards, from pixels to rays, because pixels are what is physically measurable. A pixel index (x_s, y_s) names a cell on a silicon array. Scaling by the pixel pitches (sₓ, s_y) turns indices into millimetres on the sensor; the sensor's origin sits at some point c_s in space and its plane has some orientation R_s. Composing those gives a map from pixel indices to 3D rays.

pixels → 3D, the physically meaningful direction ⎡ s_x 0 0 ⎤ ⎡ x_s ⎤ p = [ R_s | c_s ] ⎢ 0 s_y 0 ⎥ ⎢ y_s ⎥ = M_s x̄_s ⎢ 0 0 0 ⎥ ⎣ 1 ⎦ ⎣ 0 0 1 ⎦ columns 1 and 2 of M_s are the 3D steps taken by one pixel across and one pixel down; column 3 is the 3D position of the pixel array's origin. and the calibration matrix is its inverse, up to the scale that perspective ignores anywayx̃_s = α M_s⁻¹ p_c = K p_c

The three forms of K, and what each parameter is

the general upper-triangular form — five parameters ⎡ f_x s c_x ⎤ K = ⎢ 0 f_y c_y ⎥ ⎣ 0 0 1 ⎦ with the aspect ratio made explicit instead of two focal lengths ⎡ f s c_x ⎤ K = ⎢ 0 af c_y ⎥ a = f_y/f_x, the pixel aspect ratio ⎣ 0 0 1 ⎦ and the form that is adequate for most work — a = 1, s = 0 ⎡ f 0 c_x ⎤ K = ⎢ 0 f c_y ⎥ often with (c_x, c_y) fixed at (W/2, H/2), ⎣ 0 0 1 ⎦ leaving ONE unknown: the focal length so the full mapping, written outx_s = fₓ · (X_c/Z_c) + s · (Y_c/Z_c) + cₓ y_s = f_y · (Y_c/Z_c) + c_y

How many degrees of freedom does K really have?

Three different answers circulate, and all three are correct about different questions. This is worth untangling because it recurs whenever someone says a calibration is "under-determined".

answer A
Eight
If you treat K as an arbitrary 3×3 homogeneous matrix — which is what an estimator that does not impose structure will return — it has 9 − 1 = 8 degrees of freedom.
answer B
Seven
Physically, M_s has 3 for R_s, 3 for c_s and 2 for (sₓ, s_y) = 8; but the distance of the sensor from the centre cannot be separated from the pixel pitch by any image measurement, so one of those eight is unobservable. Seven remain.
answer C
Five — the one that is used
Because K is only ever seen through P = K[R|t], and you may insert R₁ᵀR₁ between them: K → KR₁ and [R|t] → R₁ᵀ[R|t] gives the identical P. The sensor's true orientation and the camera's are not separately observable. Fixing the ambiguity by demanding K be upper triangular leaves exactly 5.
the ambiguity, in one lineP = K[R|t] = (KR₁)(R₁ᵀ[R|t]) for ANY rotation R₁ — the same P, different K and R and the fix, which is a convention rather than a discoverydemand K upper triangular. Then the RQ decomposition of the left 3 × 3 block of P is unique (up to signs, fixed by requiring positive diagonal), and 8 = 5 (K) + 3 (R) with nothing left over.
The clash of notation to be ready for. In numerical linear algebra R means the upper-triangular factor of a QR decomposition. In computer vision R means an orthogonal rotation. Decomposing the camera matrix uses RQ — upper-triangular times orthogonal — so the sentence "compute the RQ decomposition of M to get K and R" contains the letter R twice with two different meanings. The factorisation itself is standard; only the naming is hostile.
Each entry of K, acting alone — the same rays, five different sensors nothing about the scene changes; only the map from rays to pixels does
  • The principal point slides the image; it does not reshape it. Which is exactly why cropping a photograph invalidates a stored calibration: the pixel indices all shift, so (cₓ, c_y) must shift with them, by precisely the crop offset.
  • Two different focal lengths is a pure anisotropic scale. It cannot be distinguished from a scene that is genuinely stretched, which is why a = f_y/fₓ is fixed to 1 whenever anything else is being estimated.
  • Skew slants the columns and leaves the rows alone. That asymmetry is the signature of the upper-triangular convention: the skew term multiplies Y_c/Z_c and lands in the x equation only.
  • None of these sliders changes the scene, the pose, or the rays. Everything on the right of the panel is a property of the sensor and its mounting. That separation — optics in K, geometry in [R|t] — is the whole point of factoring P at all.

15 Focal length, field of view, and the units problem

"Focal length 50" is meaningless without a unit, and the unit is not always millimetres. Getting this wrong is the most common source of a calibration that is quietly off by a factor, so it is worth ten minutes.

Using S rather than W also makes f the same for a landscape and a portrait crop.
The bug. Halving an image's resolution and keeping K unchanged. Every entry of K except the bottom-right scales with resolution: f → f/2, cₓ → (cₓ + 0.5)/2 − 0.5, and likewise c_y. Resizing an image is a similarity transform of the pixel grid, so K → S·K with S = [[k,0,tₓ],[0,k,t_y],[0,0,1]]. The half-pixel offsets in the principal point come from the convention that a pixel's coordinate is its centre; ignoring them costs half a pixel per pyramid level, which compounds.

The zoom–distance ambiguity, made visible

§12 showed algebraically that a small object's image size depends only on f/t_z. The consequence is that a photograph does not tell you the focal length unless the scene has depth extent. Move the camera back and zoom in by the same factor, and the subject is unchanged — but the background is not, and that difference is the only thing that reveals which happened.

a subject 1.8 m tall held at exactly 200 px, with a 10 m background 20 m behind it subject depth f needed subject background 3 m 333.3 px 200 px 144.9 px 10 m 1111.1 px 200 px 370.4 px 30 m 3333.3 px 200 px 666.7 px because the ratio of background to subject size is exactly(f h_b / z_b) / (f h_s / z_s) = (h_b/h_s) · (z_s/z_b) — f cancels entirely so the RELATIVE size of foreground to background depends on POSITION only, never on the lens.

That is the whole content of the dolly-zoom shot, and also of the advice that a portrait lens flatters faces: standing further back and zooming in reduces the depth ratio between the tip of a nose and an ear, which is a change of viewpoint, not of optics. A lens cannot compress perspective; only moving can.

16 Extrinsics, and the camera matrix P = K[R|t]

Everything so far assembles into one 3×4 matrix. Eleven degrees of freedom, five of them about the sensor and six about where the camera is standing, and a single matrix–vector product that carries a world point all the way to a pixel.

The assembly

the chain, one stage at a timep_w ──[R|t]──▶ p_c ──divide by z──▶ normalised (x, y) ──K──▶ pixels (x_s, y_s) and collapsed, because homogeneous coordinates let it collapsex̃_s = K [R | t] p̄_w = P p̄_w P = K[R|t], a 3 × 4 matrix 11 degrees of freedom, and the count matters for part 712 entries − 1 for scale = 11 = 5 (K) + 3 (R) + 3 (t) so 6 point correspondences (2 equations each = 12 ≥ 11) determine P — the minimal case for DLT the invertible 4 × 4 version, when depth must survive the trip ⎡ K 0 ⎤ ⎡ R t ⎤ P̃ = ⎢ ⎥ ⎢ ⎥ = K̃ E and then x̃_s = (x_s, y_s, 1, d) ∼ P̃ p̄_w ⎣ 0ᵀ 1 ⎦ ⎣ 0ᵀ 1 ⎦ carrying a fourth coordinate d means P̃ can be INVERTED: pixels plus disparity → 3D points.
The mistake, made constantly. Reading t as "where the camera is". It is not. t is where the world origin is, expressed in the camera's frame. The camera centre is C = −Rᵀt, and it is also the null vector of P: P(C, 1)ᵀ = K(RC + t) = K(−RRᵀt + t) = 0. On the running example t = (0, 1.5, 5) while the camera actually stands at C = (0, −5, 1.5) — two vectors with the same entries permuted, which is exactly the kind of coincidence that lets a bug survive testing.

The two cases where two images are related by a homography

Mapping one image into another normally needs the depth of every pixel, which is unavailable. There are exactly two situations in which it is not needed, and both matter enormously later.

the general case — needs per-pixel depth, and so is NOT a homographyp ∼ E₀⁻¹K̃₀⁻¹x̃₀ then x̃₁ ∼ K̃₁E₁E₀⁻¹K̃₀⁻¹ x̃₀ = M₁₀ x̃₀ with x̃₀ = (x₀, y₀, 1, d₀) the fourth coordinate d₀ is the disparity, and without it M₁₀ cannot be applied. CASE 1 — every scene point lies on one plane n̂₀ · p + c₀ = 0choose the last row of P₀ to be that plane, so every point on it has d₀ = 0. Then the last column of M₁₀ multiplies zero and can be dropped, as can its last row, leaving x̃₁ ∼ H̃₁₀ x̃₀ a 3 × 3 homography, 8 parameters. This is why a mosaic of a flat wall works. CASE 2 — the camera only ROTATED: t₀ = t₁, so the two centres coincidex̃₁ ∼ K₁R₁R₀⁻¹K₀⁻¹ x̃₀ = K₁R₁₀K₀⁻¹ x̃₀ again a 3 × 3 homography with square pixels and known principal points, it has only 3 (rotation) + 2 (two focal lengths) = 5 free parameters — which is why panorama stitching can recover a focal length it was never told.

Both cases are exact, not approximate, and both are the licence Part 6 needs before it is allowed to estimate a homography from correspondences. Outside them — a camera that translated through a scene with depth — a homography is simply the wrong model, and no amount of robust fitting rescues it.

Projective depth, and why the fourth row is negotiable

write the last row of P̃ as p₃ = s₃[n̂₀ | c₀] with ‖n̂₀‖ = 1d = (s₃/z)(n̂₀ · p_w + c₀) where z is the depth along the optical axis two useful choicesn̂₀ = 0, c₀ = 1 ⟹ d = s₃/z: ordinary DISPARITY, i.e. inverse depth. The reference plane is at infinity. n̂₀, c₀ = a real plane ⟹ d = PROJECTIVE DEPTH: parallax measured from that plane, zero on it.

Inverse depth is the better-conditioned parameterisation for an outdoor camera, because it compresses the huge and badly-determined far field into a small finite range near zero — the same reason §13's depth uncertainty exploded near the horizon, seen from the other side. The plane-plus-parallax choice is what plane-sweep stereo uses in Part 7.

The whole chain, live — orbit the camera round a scene and watch P and the image change together left is the world with the camera drawn in it; right is what that camera records
  • Watch t and C move in opposite ways. Orbiting the camera changes both, and they are never equal except when R = I and the camera sits at the origin. The panel prints P·(C,1)ᵀ every frame; it is the zero vector to machine precision, which is the definition of the camera centre.
  • Changing f changes only K, and the frustum narrows. The pose columns of P all scale, because P = K[R|t] multiplies the first two rows of [R|t] by f — a reminder that the entries of P are not individually meaningful; only the matrix up to scale is.
  • Yaw the camera and the vanishing point of the ground grid slides along the horizon, exactly as §13's KRd predicted. Pitch it and the horizon leaves the principal-point row.
  • The frustum is the pre-image of the image rectangle. Everything inside it is recorded; everything outside is not; and the pyramid's apex — the one point of the scene the camera can never see — is the camera centre itself.

17 Lens distortion, and the exact radius at which it stops being invertible

Everything so far assumed a linear projection, whose defining property is that straight lines stay straight. Real lenses break that, visibly. The repair is a low-order polynomial in the radius, applied between the perspective division and the multiplication by K — and it is the one non-linearity in the whole geometric pipeline.

Where in the chain it goes

the corrected chain — note that distortion acts on NORMALISED coordinates, before Kp_w ──[R|t]──▶ p_c ──÷z──▶ (x, y) ──DISTORT──▶ (x̂, ŷ) ──K──▶ pixels the normalised coordinates, written outx = (rₓ · p + tₓ)/(r_z · p + t_z) y = (r_y · p + t_y)/(r_z · p + t_z) the radial model, with r² = x² + y²x̂ = x (1 + κ₁r² + κ₂r⁴ + κ₃r⁶) ŷ = y (1 + κ₁r² + κ₂r⁴ + κ₃r⁶) then, and only then, the sensor mappingx_s = f x̂ + cₓ y_s = f ŷ + c_y
Why the order matters. Distortion is a property of the lens, and the lens acts before the sensor grid does. Applying it after K — on pixel coordinates measured from the image centre rather than the principal point — is a common and subtle error: it silently ties the distortion centre to the image centre, and those differ by however far the principal point is off, which is exactly the quantity a calibration is trying to measure. It also makes κ₁ depend on resolution, since r is then in pixels.

Undistortion, and the theorem that decides whether it exists

The forward model is a polynomial; the inverse is not, and has no closed form beyond special cases. The standard remedy is a fixed-point iteration, which works beautifully — up to a point that can be located exactly.

The table is the point of the section. A fixed-point undistortion that "usually works" is not usually working for a reason you control; it is working because your lens happens to be mild. The threshold is computable from the coefficient alone, before any image is processed, and a fisheye lens is nowhere near it — which is why fisheyes need a different model entirely, typically an equidistance projection r̂ ∝ φ in the angle off the optical axis rather than a polynomial in the radius.

Tangential distortion

from a lens element not being exactly parallel to the sensor — "decentering"x̂ = x·(radial) + [ 2p₁xy + p₂(r² + 2x²) ] ŷ = y·(radial) + [ p₁(r² + 2y²) + 2p₂xy ] its signature, which distinguishes it from radial distortion at a glanceradial distortion is rotationally symmetric — its displacement field points at the centre. tangential distortion is NOT — its field has a preferred direction, set by (p₁, p₂). Typical magnitudes are an order of magnitude below κ₁'s, which is why it is often dropped.
The convention trap. Some sources define the coefficients the other way round: x = x̂(1 + κ₁r̂² + κ₂r̂⁴), mapping observed to ideal, so that undistortion is the direct evaluation and distortion is the iteration. Both conventions are in use, both call the parameters κ₁, κ₂, and they are not the same numbers. Check which direction a stored calibration meant before using it; the symptom of getting it backwards is a residual distortion of roughly twice the true magnitude, with the sign flipped.
