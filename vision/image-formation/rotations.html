08 Rotation matrices: what the nine numbers mean

Before any parameterisation, the matrix itself. A rotation matrix is not an opaque block of nine numbers — every row and every column has a reading, and being able to look at one and say what it does is worth more than any formula below.

Columns and rows

the COLUMNS are the images of the basis vectorsR = [ Rê₁ | Rê₂ | Rê₃ ] so column j is where the j-th axis went the ROWS are the old axes expressed in the new frameR = [ r₁ᵀ ; r₂ᵀ ; r₃ᵀ ] and for a camera, rᵀ₃ · (p − C) is the DEPTH along the optical axis the defining conditionsRᵀR = RRᵀ = I R⁻¹ = Rᵀ det R = +1 consequences: ‖Rx‖ = ‖x‖, (Rx)·(Ry) = x·y, and R(x × y) = (Rx) × (Ry) worked — read the running example's rotation off its columns ⎡ 1 0 0 ⎤ column 1 = (1, 0, 0) : world X → camera x (right stays right) R = ⎢ 0 0 −1 ⎥ column 2 = (0, 0, 1) : world Y → camera z (forward becomes depth) ⎣ 0 1 0 ⎦ column 3 = (0, −1, 0) : world Z → camera −y (up becomes minus-down) RᵀR = I ✓ det R = 1·(0·0 − (−1)·1) = +1 ✓ so it is a rotation, not a reflection

The spectral picture — why every 3D rotation has an axis

A real 3×3 orthogonal matrix with determinant +1 has characteristic polynomial of odd degree, so it has at least one real eigenvalue; orthogonality forces every eigenvalue to have modulus 1, and the determinant forces the product to be +1. The only possibility is eigenvalues {1, e^{iθ}, e^{−iθ}}.

eigenvalues of any R ∈ SO(3)λ = 1, e^{iθ}, e^{−iθ} and hence, immediately, EULER'S ROTATION THEOREMthe eigenvector for λ = 1 is fixed by R: it is the AXIS. Every 3D rotation is a rotation about one axis. reading the angle off the tracetr R = 1 + 2 cos θ ⟹ θ = arccos( (tr R − 1) / 2 ) worked — the running exampletr R = 1 + 0 + 0 = 1 ⟹ cos θ = 0 ⟹ θ = 90° ✓ it is Rₓ(90°) worked — a rotation of 60° about the axis n̂ = (1, 2, 2)/3, used again in §10 and §11 ⎡ 0.5555556 −0.4662392 0.6884614 ⎤ R = ⎢ 0.6884614 0.7222222 −0.0664529 ⎥ tr R = 0.5555556 + 0.7222222 + 0.7222222 = 2 ⎣ −0.4662392 0.5108974 0.7222222 ⎦ θ = arccos((2 − 1)/2) = arccos(0.5) = 60° ✓

Euler's rotation theorem is what makes the axis/angle representation of §10 possible at all, and the trace formula is the standard way to measure how far apart two orientations are: the geodesic distance between R₁ and R₂ is the rotation angle of R₁ᵀR₂, that is arccos((tr(R₁ᵀR₂) − 1)/2). That is the error metric Part 7 will report for a recovered pose, and it is not the same as the Frobenius norm of the difference.

Numerical hygiene. A matrix that has been updated repeatedly — integrated from a gyroscope, refined by an optimiser — drifts off SO(3): its columns stop being exactly orthonormal, and the drift compounds. Two standard repairs: Gram–Schmidt the columns (cheap, but asymmetric — it privileges the first column), or take the polar factor from an SVD, R ← UVᵀ where R = UΣVᵀ, which is the nearest rotation in the Frobenius sense and is symmetric in its treatment of the axes. This is why so much pose code carries quaternions instead: renormalising a 4-vector is one division.

09 Euler angles, and the exact place they fail

Three angles about three axes. It is the parameterisation everybody meets first, it is the one every user interface exposes, and it is the one that is wrong for almost every purpose in this series. The reasons are specific and provable, not stylistic.

The convention, written out

The source material declines to give the formula on the grounds that Euler angles are a bad idea. That is good advice and bad pedagogy: you cannot recognise a failure you have never seen. Here is the convention this series uses whenever Euler angles appear at all.

ZYX intrinsic — "yaw, then pitch, then roll", applied right to left so ROLL happens firstR(α, β, γ) = R_z(α) · R_y(β) · R_x(γ) α = yaw, β = pitch, γ = roll multiplied out, with c = cos and s = sin ⎡ cαcβ cαsβsγ − sαcγ cαsβcγ + sαsγ ⎤ R = ⎢ sαcβ sαsβsγ + cαcγ sαsβcγ − cαsγ ⎥ ⎣ −sβ cβsγ cβcγ ⎦ and read back out again — note that the FIRST COLUMN carries the whole of ββ = atan2( −R₂₀ , √(R₀₀² + R₁₀²) ) α = atan2( R₁₀ , R₀₀ ) γ = atan2( R₂₁ , R₂₂ ) use atan2, never asin: asin(−R₂₀) loses the quadrant and silently folds β into (−90°, 90°)
There are twenty-four conventions, and they are all called "Euler angles". Choose an ordered triple of axes with no two adjacent ones equal — 12 choices, split into 6 "proper Euler" sequences like ZXZ and 6 "Tait–Bryan" sequences like ZYX — and then choose whether the rotations are about the axes of the fixed frame (extrinsic) or of the body as it turns (intrinsic): 24 in total. The single most useful fact about the family is that an intrinsic sequence equals the same axes reversed, taken extrinsically: intrinsic Z–Y–X is identical to extrinsic X–Y–Z. Every "the angles from library A do not work in library B" bug is somewhere in that list of 24.

Failure 1 — the composition rule is not addition

in 2D this is trueR(θ₁)R(θ₂) = R(θ₁ + θ₂) and the parameters simply add in 3D it is false, and the failure is first-order in the anglesR(α₁,β₁,γ₁) · R(α₂,β₂,γ₂) ≠ R(α₁+α₂, β₁+β₂, γ₁+γ₂) worked: R_x(90°)R_y(90°) sends ê₁ → (0, 1, 0), while R_y(90°)R_x(90°) sends ê₁ → (0, 0, −1). Same two rotations, opposite order, genuinely different results — so no "sum of angles" can describe both.

Averaging two orientations by averaging their Euler angles is therefore meaningless, and so is interpolating between them by interpolating the angles — the intermediate orientations wobble off the shortest path in a way that depends on the arbitrary choice of convention. §11 fixes exactly this.

Failure 2 — gimbal lock, derived rather than described

Set the middle angle to β = 90° in the matrix above. Then cβ = 0 and sβ = 1, and every entry collapses into a function of γ − α alone.

at β = +90° exactly ⎡ 0 sin(γ−α) cos(γ−α) ⎤ R = ⎢ 0 cos(γ−α) −sin(γ−α) ⎥ only the DIFFERENCE γ − α survives ⎣ −1 0 0 ⎦ so, exactly, an entire one-parameter family of triples gives the SAME rotationR(α, 90°, γ) = R(α + δ, 90°, γ + δ) for every δ verified: R(20°, 90°, 35°) and R(60°, 90°, 75°) agree to 1.7 × 10⁻¹⁶ entry by entry and equally R(20°, 90°, 35°) = R(−15°, 90°, 0°), since only α − γ = −15° matters at β = −90° the surviving combination is the SUM insteadR(20°, −90°, 35°) = R(55°, −90°, 0°) because there it is α + γ that is fixed the rate at which the parameterisation degenerates, exactlythe three angle rates generate space-frame angular velocities ω_α = ẑ, ω_β = R_z(α)ŷ, ω_γ = R_z(α)R_y(β)x̂ and the determinant of that 3 × 3 Jacobian is det J = −cos β. |det J| = 1 at β = 0, and 0 at β = ±90°: one whole degree of freedom is gone, not merely ill-conditioned. β = 80° → 0.1736 β = 85° → 0.0872 β = 89° → 0.0175 β = 89.9° → 0.0017

Two consequences follow directly. Near the lock, achieving a small rotation about the lost direction demands an enormous change in α and γ — which is the visible symptom, a control that suddenly spins wildly. And an optimiser parameterising pose by Euler angles will find its Jacobian rank-deficient there, so a Gauss–Newton step becomes singular and the solver stalls or diverges at exactly the pose it needs to pass through. That is the practical reason this series never optimises over Euler angles.

Three rings, one lost axis — the pitch slider starts at 90°, which is the locked configuration at lock, dragging yaw and roll together does nothing at all
  • Press "nudge α and γ together" while β = 90°. The rings visibly turn, and the object does not move by so much as a floating-point unit. That is gimbal lock: two controls that have become the same control.
  • Then set β = 0 and press it again. The same nudge now produces a real rotation. Nothing about the code changed — only the pose.
  • The determinant readout is the honest diagnostic. It is |cos β|, it degrades smoothly, and it is already down to 0.087 at β = 85° — where nudging the frame by one degree about the failing direction costs about 11° of coordinated yaw and roll. Lock is not a knife edge you can steer around; it is a region of increasingly bad conditioning with a hole at the centre.
  • Every convention has a lock; only its location moves. Choosing ZXZ instead of ZYX puts the singularity at β = 0 and β = 180° instead of ±90° — which is worse for a camera, since β = 0 is the resting pose. There is no ordering that removes it, because §07's topology argument forbids one.

10 Axis–angle: the minimal parameterisation, derived

§08 proved that every rotation has an axis. Axis–angle simply uses that: three numbers, ω = θn̂, whose direction is the axis and whose length is the angle. The formula that turns those three numbers into a matrix is derivable in five lines of vector algebra, and deriving it is worth more than memorising it.

The derivation

Split the vector v into the part along the axis, which the rotation cannot touch, and the part perpendicular to it, which simply spins in its own plane.

step 1 — the component ALONG the axis is untouchedv∥ = n̂(n̂ · v) = (n̂n̂ᵀ)v step 2 — the perpendicular residualv⊥ = v − v∥ = (I − n̂n̂ᵀ)v step 3 — the cross product rotates that residual by 90° within its planev× = n̂ × v = [n̂]ₓ v where [n̂]ₓ = [[0, −n̂_z, n̂_y], [n̂_z, 0, −n̂ₓ], [−n̂_y, n̂ₓ, 0]] note ‖v×‖ = ‖v⊥‖, and v× ⊥ v⊥ ⊥ n̂ — so {v⊥, v×} is an orthogonal basis of the spin plane step 4 — going round twice reverses the residual, which pins down [n̂]ₓ²v×× = n̂ × v× = [n̂]ₓ² v = −v⊥ ⟹ v∥ = v + [n̂]ₓ²v = (I + [n̂]ₓ²)v step 5 — spin the in-plane part through θ and add the fixed part backu⊥ = cos θ · v⊥ + sin θ · v× u = u⊥ + v∥ = ( I + sin θ [n̂]ₓ + (1 − cos θ) [n̂]ₓ² ) v RODRIGUES' ROTATION FORMULAR(n̂, θ) = I + sin θ [n̂]ₓ + (1 − cos θ) [n̂]ₓ² equivalently R = cos θ · I + (1 − cos θ) n̂n̂ᵀ + sin θ [n̂]ₓ, using [n̂]ₓ² = n̂n̂ᵀ − I

The same matrix, three other ways

as a MATRIX EXPONENTIAL — a rotation by θ is the limit of k rotations by θ/kR(n̂, θ) = lim_{k→∞} (I + (1/k)[θn̂]ₓ)^k = exp([ω]ₓ) with ω = θn̂ and expanding that series recovers Rodrigues, using [n̂]ₓ^{k+2} = −[n̂]ₓ^kexp([ω]ₓ) = I + θ[n̂]ₓ + (θ²/2)[n̂]ₓ² + (θ³/3!)[n̂]ₓ³ + ⋯ = I + (θ − θ³/3! + ⋯)[n̂]ₓ + (θ²/2 − θ⁴/4! + ⋯)[n̂]ₓ² = I + sin θ [n̂]ₓ + (1 − cos θ) [n̂]ₓ² ✓ LINEARISED, for the small corrections an optimiser actually applies ⎡ 1 −ω_z ω_y ⎤ R(ω) ≈ I + [ω]ₓ = ⎢ ω_z 1 −ω_x ⎥ and R(ω)v ≈ v + ω × v ⎣ −ω_y ω_x 1 ⎦ whose derivative is the single most useful Jacobian in pose estimation∂(Rv)/∂ωᵀ = −[v]ₓ = [[0, z, −y], [−z, 0, x], [y, −x, 0]]

That last Jacobian is why bundle adjustment in Part 7 parameterises pose updates as an axis–angle increment composed onto a current rotation, rather than as absolute angles. The increment is always near zero, where the parameterisation is perfectly conditioned; the accumulated rotation is stored as a matrix or a quaternion, where there is no singularity to hit.

Where axis–angle breaks

not unique
Adding 2π
(n̂, θ) and (n̂, θ + 2πk) are the same rotation, and so are (n̂, θ) and (−n̂, −θ). Restricting to θ ∈ [0, π] almost fixes it — almost, because at exactly θ = π the axes n̂ and −n̂ still give the same rotation.
singular
At θ = 0
The axis becomes undefined: every direction fixes the identity. The recovery formula divides by 2 sin θ and blows up. Code must branch, and the branch threshold is a tuning parameter nobody wants.
singular
At θ = π
sin θ = 0 again, so the antisymmetric part of R vanishes and carries no axis information. The axis has to be dug out of the symmetric part, with a sign that must be resolved case by case. This is the branch that gets written wrong.
excellent
For small rotations
Near θ = 0 the linearised form is accurate to O(θ³) and the parameterisation is minimal, unconstrained and perfectly conditioned. Which is exactly the regime an optimiser lives in.
Rodrigues, built one term at a time — drag the axis, turn the angle, watch v∥, v⊥ and v× the rotated vector is v∥ + cos θ·v⊥ + sin θ·v×, and nothing else

11 Unit quaternions: four numbers, one constraint, no singularity

§07 proved that no three-number scheme can cover SO(3) smoothly. The escape is to use four numbers with one constraint. The cost is a normalisation to maintain; the payoff is a representation with no gimbal lock, no branch at θ = π, a composition rule that is sixteen multiplications, and — uniquely — a sensible way to interpolate.

Definition and the half-angle

a unit quaternion, stored (x, y, z, w) with the scalar LAST — the convention this series usesq = (v, w) = ( sin(θ/2) · n̂ , cos(θ/2) ) ‖q‖ = 1, so q lives on the unit 3-sphere S³ ⊂ ℝ⁴ note the HALF angle. It is not a convention; §11's double cover is its direct consequence. worked — the running rotation, n̂ = (1,2,2)/3 at θ = 60°sin 30° = 0.5, cos 30° = 0.8660254 q = (0.5 · (1/3, 2/3, 2/3), 0.8660254) = (0.1666667, 0.3333333, 0.3333333, 0.8660254) ‖q‖² = 1/36 + 1/9 + 1/9 + 3/4 = 0.0277778 + 0.1111111 + 0.1111111 + 0.75 = 1 exactly ✓ the matrix it stands for ⎡ 1 − 2(y² + z²) 2(xy − zw) 2(xz + yw) ⎤ R = ⎢ 2(xy + zw) 1 − 2(x² + z²) 2(yz − xw) ⎥ ⎣ 2(xz − yw) 2(yz + xw) 1 − 2(x² + y²) ⎦ for the q above this reproduces §10's matrix to 1.1 × 10⁻¹⁶ entry by entry — the two routes agree exactly the diagonal, written symmetrically, which is numerically better behavedR₀₀ = x² + w² − y² − z² R₁₁ = y² + w² − x² − z² R₂₂ = z² + w² − x² − y²

The derivation of that matrix from Rodrigues is two trigonometric identities. With v = sin(θ/2)n̂ and w = cos(θ/2), the identity sin θ = 2 sin(θ/2)cos(θ/2) turns sin θ[n̂]ₓ into 2w[v]ₓ, and 1 − cos θ = 2sin²(θ/2) turns (1 − cos θ)[n̂]ₓ² into 2[v]ₓ². So R = I + 2w[v]ₓ + 2[v]ₓ² — which is also the cheapest way to rotate a single vector without forming the matrix at all.

The algebra

multiplication — and R(q₀q₁) = R(q₀)R(q₁), so quaternions compose exactly as matrices doq₀q₁ = ( v₀ × v₁ + w₀v₁ + w₁v₀ , w₀w₁ − v₀ · v₁ ) it is NOT commutative — the v₀ × v₁ term changes sign — just as 3D rotations are not inverse, for a UNIT quaternion: flip the vector part, or the scalar part, but not bothq⁻¹ = q* = (−v, w) and R(q*) = R(q)ᵀ division, i.e. "the rotation that takes q₁ to q₀"q₀/q₁ = q₀q₁⁻¹ = ( v₀ × v₁ + w₀v₁ − w₁v₀ , −w₀w₁ − v₀ · v₁ ) cost comparison, for composing two rotationsmatrices: 27 multiplies, 18 adds, and 9 numbers of state, drifting off SO(3) quaternions: 16 multiplies, 12 adds, and 4 numbers of state, drifting off S³ and restoring the constraint costs a Gram–Schmidt or an SVD, versus one division by a norm

The double cover, and why it is a feature

antipodal quaternions are the same rotationR(−q) = R(q) for every q — verified: the two matrices agree to 0.0 exactly because every entry of R is QUADRATIC in the components, so signs cancele.g. 2(xy − zw) ↦ 2((−x)(−y) − (−z)(−w)) = 2(xy − zw) ✓ so the map q ↦ R(q) is TWO-to-oneS³ → SO(3) a DOUBLE COVER, and SO(3) ≅ ℝℙ³ = S³ with antipodes glued and this is §07's obstruction seen from above. SO(3) is COMPACT, so it cannot be homeomorphic to any open subset of ℝ³, and no single 3-parameter chart can cover it. S³ is compact too — but it sits inside ℝ⁴ as ‖q‖ = 1, so FOUR numbers plus ONE constraint do cover it, globally and without a singularity. Paying for a constraint is exactly how the obstruction is bought off.

Other than the sign ambiguity, the representation is unique and continuous: as a rotation matrix varies smoothly, a smoothly varying quaternion can always be chosen. That continuity is the property Euler angles lack and the one that makes the next paragraph possible.

Interpolation: slerp

Interpolating orientations is the operation that separates quaternions from everything else. Averaging Euler angles produces a path that depends on the convention and wanders; averaging matrices entrywise produces something that is not a rotation at all. On the unit sphere, the right answer is obvious: travel along the great circle at constant speed.

SLERP — spherical linear interpolation, the constant-speed geodesic1. q_r = q₁ / q₀ = (v_r, w_r) the relative rotation 2. if w_r < 0 then q_r ← −q_r take the SHORT way round (see below) 3. θ_r = 2 · atan2(‖v_r‖, w_r) its total angle 4. n̂_r = v_r / ‖v_r‖ its axis 5. q_a = ( sin(aθ_r/2) n̂_r , cos(aθ_r/2) ) a fraction a of the way 6. return q_a q₀ the equivalent closed form, on the 4-vectors directlyslerp(q₀, q₁; a) = [ sin((1−a)Ω) q₀ + sin(aΩ) q₁ ] / sin Ω with Ω = arccos(q₀ · q₁) the arctangent form of step 3 is preferable when q₀ and q₁ are close, where arccos loses precision step 2 matters — measured on the figure's two orientationsq₀ · q₁ = 0.200142 ⟹ Ω = 78.4547° ⟹ a rotation of 2Ω = 156.9094° using −q₁ instead: Ω = 101.5453° ⟹ a rotation of 203.0906° — the SAME endpoint, the long way round 156.9094 + 203.0906 = 360.0000 exactly. The two paths are the two arcs of one great circle.
Three ways to interpolate the same two orientations — only one of them travels at constant speed the step sizes are measured, not asserted: each bar is the geodesic angle between consecutive frames
  • The slerp bars are all the same height, and the others are not. Constant angular speed is not a detail: it is what makes an interpolated camera path look like a camera move rather than a lurch.
  • nlerp follows the identical path but at a varying speed. Normalising a point on the chord projects it onto the same great circle, so the route is right and the timing is wrong — which is why nlerp is perfectly acceptable for small increments and visibly wrong for large ones. At the default separation its step size swings by a factor of 1.63.
  • The Euler path is a different path, and a longer one. At the default it runs 179.70° against a true geodesic distance of 156.91° — 14.5% of extra travel, spent wandering off the direct route.
  • Switch on "the long way". The endpoints are unchanged — the two end matrices agree to exactly zero — but the journey is 203.09° instead of 156.91°. That is the double cover, made visible: q₁ and −q₁ are the same orientation and different destinations.

The combination that is actually used. Keep the accumulated orientation as a quaternion, because it neither drifts badly nor has a singularity. Parameterise each update as a small axis–angle vector, because it is minimal, unconstrained and perfectly conditioned near zero, and its Jacobian is a one-liner. Compose by quaternion multiply, renormalise, and convert to a matrix only at the moment you need to transform a lot of points. Euler angles appear only in the user interface. Part 7's bundle adjustment does exactly this.
