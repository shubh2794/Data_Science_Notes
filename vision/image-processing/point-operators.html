02 Point operators: one pixel in, one pixel out

The simplest possible image operator ignores every pixel but one. That constraint sounds crippling and is in fact the reason point operators are the workhorse of the whole pipeline: they cannot blur, cannot invent structure, cannot move an edge, and can be implemented as a 256-entry lookup table.

The definition

a point operator, continuous and discreteg(x) = h(f(x)) one input image g(x) = h(f₀(x), …, f_n(x)) several input images, combined pixelwise g(i, j) = h(f(i, j)) on the lattice, which is all we ever compute the two that matter most: GAIN and BIASg(x) = a·f(x) + b a > 0 is the GAIN — loosely, "contrast" b is the BIAS — loosely, "brightness" and their spatially varying versions, which are still point operators at each pixelg(x) = a(x)·f(x) + b(x) a graduated filter; a vignetting correction; a flat-field division

"Loosely" is doing real work in that box. Gain and bias are not contrast and brightness in any perceptual sense; they are the slope and intercept of a straight line. What they do to the two summary statistics is exact and worth memorising, because it is the reason the pair is used at all.

Linear, and not

Multiplicative gain is a linear operator in the exact algebraic sense: it obeys superposition, h(f₀ + f₁) = h(f₀) + h(f₁). Adding a bias does not — a(f₀ + f₁) + b ≠ (af₀ + b) + (af₁ + b) unless b = 0. The affine map is therefore not linear, it is affine, and the distinction is exactly the one Part 1 §03 solved with an extra coordinate. Nobody bothers here, because a point operator is never composed into a matrix chain.

Genuinely non-linear point operators are everywhere and are all just differently shaped curves through the same [0,1] → [0,1] box:

  • Gamma, g = f^γ. Defined and justified in Part 1 §23. §03 below only concerns where in a pipeline you must undo it.
  • Squaring, g = f². Not linear, and used precisely because it is not: the square of a band-pass filtered signal is a local energy estimate, which is how §14's oriented energy and Part 4's corner responses are built.
  • Thresholding, θ(f, t) = 1 if f ≥ t else 0. The most violently non-linear operator on the page, and the gateway to §18's morphology. Choosing t well is Part 5's problem, not this page's.
  • Quantisation / posterisation, g = round(f·L)/L. A staircase. It is what an eight-bit container does to you whether you ask or not, and §07 is about what happens when a point operator amplifies its steps.
  • Colour matrices, g = M f with f a 3-vector. Still a point operator — it looks at one pixel — but a vector-valued one. White balance, RGB→YCbCr, and the primaries conversion of Part 1 §23 are all this.

Compositing and matting, the two-image case

The multi-image form h(f₀, f₁) covers dissolves, differencing, and — most importantly — compositing a foreground over a background using a per-pixel opacity α. This is a point operator with three inputs, and it is the reason images carry a fourth channel at all.

the OVER operator — compositing F onto B with coverage α ∈ [0, 1]C = αF + (1 − α)B the same thing PREMULTIPLIED, which is what image files actually storewrite F′ = αF and carry the pair (F′, α). Then C = F′ + (1 − α)B Premultiplied form is preferred because it makes OVER ASSOCIATIVE — compositing a stack of layers gives the same answer whichever way you bracket it — and because filtering a premultiplied image is correct while filtering a non-premultiplied one is not (§09). two independent half-covering layerscombined coverage = 1 − (1 − 0.5)(1 − 0.5) = 0.75, not 1.0 MATTING is the inverse problem — and it is under-determinedGiven C only, solve C = αF + (1 − α)B for α, F and B. Unknowns per pixel: 3 (F) + 3 (B) + 1 (α) = 7. Equations per pixel: 3. Four short, at every pixel, forever. Every matting algorithm is a different prior.

That count is the honest statement of why matting is hard, and it is the same shape of argument as Part 1 §22's metamers: the measurement is a projection and the projection has a kernel. Blue-screening works only because it legislates B, which removes three unknowns and makes the system determined.

The trap. Blending, resizing and filtering are all weighted averages, and a weighted average of gamma-encoded code values is not the gamma encoding of the weighted average. Averaging code 0 and code 255 gives code 127.5, whose linear luminance is 0.2176 — but the true midpoint in light is 0.5, which encodes to code 186.1. That is a 59-code-value error, and it is why a downsampled image with fine black-and-white detail comes out too dark. §03 says what to do about it.

03 Tone curves, clipping, and where gamma bites

Every point operator on an eight-bit image is a curve from 256 inputs to 256 outputs. Drawing the curve, rather than reasoning about the formula, tells you immediately what it will destroy — because destruction is visible as a flat segment or as a segment that leaves the box.

The lookup table is the operator

For an eight-bit image, every scalar point operator, however exotic, is one array T[0…255]. Compute it once and the per-pixel cost is one memory read, regardless of whether the formula involved a power, an exponential or a spline. Three consequences follow immediately and are worth stating because people rediscover them painfully:

  • Composing point operators is composing tables. Two operators in sequence is T₂[T₁[·]], one table. There is never a reason to make two passes over the pixels.
  • The table is where the information loss is visible. If T maps two distinct inputs to the same output, those two values are now indistinguishable and no later operator can separate them. Count the distinct values in T and you have counted exactly how many grey levels survive.
  • A monotone table is invertible only where it is strictly increasing. A flat run in T is a permanent merge; a clipped run at 0 or 255 is a permanent collapse.

Clipping, and why it is not the same as compression

what the display container forcesg = clip(a·f + b, 0, 255) Above 255: every value maps to 255. The DERIVATIVE of the operator is zero there. Below 0: every value maps to 0. Same. the alternative — a soft shoulder, which compresses instead of clippingg = 255 · (1 − exp(−a·f/255)) or a smoothstep, or an S-curve Slope falls smoothly to a small positive number, never to exactly zero. Contrast in the highlights is reduced; it is not deleted.

The difference matters because clipping is not recoverable and compression is. A clipped highlight has no information in it at all — every pixel in it is the number 255 — so Part 4's gradient there is exactly zero and no detector will find anything. A compressed highlight has a small gradient, which is noisy but present.

Where gamma bites, in one rule

The rule. Operators that are weighted averages of pixel values must be done in linear light: blurring, resizing, pyramid construction, compositing, blending, demosaicing. Operators that are monotone reshapings of a single value can be done in either space, and are usually done in the encoded space because that is where the code values are perceptually spaced: tone curves, thresholds, histogram equalisation. The full argument for why the encoding exists is Part 1 §23; the operational content is this one sentence, and violating it is the single most common cause of images that are "slightly wrong and nobody can say why".

Concretely: to blur an sRGB image correctly you decode with the sRGB transfer function, filter, then re-encode. Skipping the round trip darkens every blurred edge, because the encoding is concave and Jensen's inequality then guarantees that the average of the encoded values is below the encoding of the average. That inequality is not an approximation — it is the definition of concavity — and it is the rigorous version of the 127.5-versus-186.1 trap in §02.

A tone curve, the image it produces, and the histogram it leaves behind watch the flat segments of the curve become spikes in the output histogram

What the figure is showing, stated precisely

  • The slope of the curve is the local contrast gain. Where T′(v) > 1 the histogram is stretched apart and gaps open between output levels; where T′(v) < 1 it is squeezed and levels merge. Total pixel count is conserved, so the output histogram is the input histogram divided by the slope. That is the change-of-variables formula for a density, and it is the entire mechanism behind §05.
  • Posterising to L levels leaves exactly L spikes, no matter what the input looked like. The distinct-level readout drops to L immediately. Nothing downstream can undo it.
  • Clipping shows up as a bar at an end of the histogram, and as a flat run in the curve. Push the gain up with the bias at zero and watch the count of clipped pixels rise while the standard deviation stops rising with it — the spread saturates because the container is full.
  • The default is the identity — a = 1, b = 0, γ = 1 — so the two histograms coincide and no pixel is clipped. Every claim above is something you have to move a slider to see.

04 Histograms and the cumulative distribution

A histogram throws away every pixel's location and keeps only how many pixels had each value. That is a catastrophic loss of information and exactly the right summary for choosing a point operator, because a point operator is blind to location too.

the histogram, and its normalised versionh(v) = #{ (i, j) : f(i, j) = v } for v = 0 … L−1 (L = 256 for eight bits) p(v) = h(v)/N N = total pixels; ∑ᵥ p(v) = 1 p is a PROBABILITY MASS FUNCTION on grey levels — the distribution of a pixel drawn at random. the cumulative distribution — a running sum, one pass, O(L) after the histogramc(v) = (1/N) ∑ᵢ₌₀ᵛ h(i) = c(v−1) + h(v)/N with c(−1) = 0, c(L−1) = 1 c(v) is the fraction of pixels at or below level v — the PERCENTILE of level v. what a histogram gives you for freemean = ∑ᵥ v·p(v) median = the smallest v with c(v) ≥ 0.5 min = smallest v with h(v) > 0 max = largest v with h(v) > 0 variance = ∑ᵥ v²·p(v) − mean² entropy = −∑ᵥ p(v) log₂ p(v) bits per pixel the running patch of §01 — its histogram is 44 spikes in 64 pixelsc(45) = 1/64 = 0.015625 c(50) = 10/64 = 0.15625 c(98) = 32/64 = 0.50000 c(123) = 46/64 = 0.71875 c(133) = 58/64 = 0.90625 c(138) = 64/64 = 1 mean = 95.609375 median = 99.5 entropy = 5.2504 bits (of a possible 8)

The percentile reading is the one that matters. Ask "what fraction of the class scored at or below this grade?" and the answer is c. That is the whole idea of §05: if you can map every grade to its percentile, the grades become uniformly spread by construction — because percentiles are, by definition, uniformly spread.

Three things a histogram cannot tell you

  • Where anything is. An image and any permutation of its pixels have identical histograms. A photograph of a face and the same pixels shuffled into noise are indistinguishable to every operator on §02's list. This is why point operators can never sharpen, denoise or segment.
  • Whether the image is in focus. Blur redistributes values only slightly; the histogram of a blurred image is close to that of the sharp one. Sharpness lives in the joint statistics of neighbouring pixels, which is §08 onwards.
  • What the "right" exposure is. A histogram piled against the left edge might be an under-exposed photograph or a correct photograph of a dark scene. Nothing in the numbers distinguishes them, which is why every automatic exposure algorithm is a heuristic with an assumption bolted on — most commonly the grey-world assumption that the scene averages to middle grey.
Per-channel or on luminance? Equalising R, G and B independently changes the hue of every pixel, because it applies three different curves to the three components of one colour. The usual fix is to convert to a space with a separate lightness axis, apply the curve to lightness only, and convert back — using the colour spaces of Part 1 §23. The cost is that the colour gamut can be exceeded after the round trip, requiring a clip that reintroduces exactly the problem §03 warned about.

05 Histogram equalisation, and what it actually guarantees

Take the tone curve to be the cumulative distribution itself. The result is the one automatic contrast adjustment that needs no parameters at all — and the one whose guarantee is most often overstated.

The construction

the equalisation transfer functionT(v) = round( (L − 1) · c(v) ) L = 256, so T(v) = round(255 · c(v)) g(i, j) = T( f(i, j) ) — still a POINT operator, still one lookup table why this is the right map, in the continuous case — the PROBABILITY INTEGRAL TRANSFORMLet X have continuous, strictly increasing CDF F. Put U = F(X). Then for u ∈ (0,1): P(U ≤ u) = P(F(X) ≤ u) = P(X ≤ F⁻¹(u)) = F(F⁻¹(u)) = u so U ~ Uniform(0,1) EXACTLY. Scale by L − 1 and the output is uniform on the grey range. the same fact read as a change of variables — the density transforms by the derivativep_g(T(v)) = p_f(v) / |T′(v)| and here T′(v) = (L−1)·p_f(v) so p_g = p_f / ((L−1) p_f) = 1/(L−1) — flat, by cancellation.

That cancellation is the whole idea and it is worth staring at. The curve is steep exactly where pixels are crowded, and steepness is what spreads them apart. The map does not know or care what the image contains; it only knows that a percentile axis is uniform by construction.

What is guaranteed, and what is not

The overstatement. "Histogram equalisation makes the histogram flat." On a discrete image it does not, and cannot. T is a function on {0,…,255}; it can only merge levels, never split one. Every pixel that had value v still has one common value T(v) afterwards, so a tall spike stays a tall spike — it just moves. What equalisation actually delivers is that the cumulative distribution is pushed towards the diagonal, which is a much weaker and entirely true statement. The figure measures both, and they disagree.
The theorem that is true. T is a deterministic function of the pixel value, so by the data-processing property of entropy, H(T(X)) ≤ H(X), with equality if and only if T is injective on the levels that actually occur. Equalisation can never increase the information in an image; usually it decreases it. On the 64-pixel patch above, T happens to be injective and the entropy is unchanged at 5.2504 bits exactly. On a 40 000-pixel low-contrast image occupying 136 levels, the same procedure collapses them to 83 and the entropy falls from 6.2147 to 6.1324 bits. It looks better and contains less.

Partial equalisation, and histogram matching

blend the equalising curve with the identity — the one knob worth havingT_α(v) = α·(L−1)·c(v) + (1 − α)·v α = 0 → identity, α = 1 → full equalisation on the running patch: α = 0.5 → mean 113.562, sd 52.992, max CDF deviation 0.2305 α = 1.0 → mean 131.562, sd 73.657, max CDF deviation 0.0781 HISTOGRAM MATCHING — the same trick, aimed at an arbitrary target instead of the uniformwant the output to have CDF c_t. Then T = c_t⁻¹ ∘ c_f i.e. for each level v: find the level w with c_t(w) closest to c_f(v), and map v → w. Equalisation is the special case c_t(w) = (w+1)/L. Matching one photograph's histogram to another's is the crudest possible colour transfer, and is used as a baseline for it.

The interpolation in T_α is not a hack. Full equalisation optimises a criterion — uniformity of the CDF — that nobody actually wants; what people want is "more contrast where it matters, without the mud". α between 0.3 and 0.6 is the usual answer, and §06's local version is the other one.

06 Locally adaptive equalisation, and CLAHE

One curve for the whole image is a bad idea when the whole image has more dynamic range than any part of it. The fix is one curve per region, and the entire difficulty is that "per region" introduces seams and amplifies noise. Both have exact remedies.

The clip limit, and exactly what it bounds

Equalisation's transfer curve is steep where the histogram is tall, and a tall histogram bin in a small, flat block is usually noise — a hundred pixels that all happen to sit within a couple of code values of each other. Amplifying that by the local slope is precisely how AHE turns a smooth sky into visible grain. Clipping bounds the slope directly.

clip, then redistribute — the excess is put back so the curve still reaches L − 1β = c · N_block / L c is the CLIP FACTOR, in units of "mean bin height" h̃(v) = min(h(v), β) + E/L E = ∑ᵥ max(0, h(v) − β) is the clipped-off mass and hence the bound on contrast gain, which is the whole point of the clipT′(v) = (L − 1)·h̃(v)/N_block ≤ (L − 1)(β + E/L)/N_block measured on the figure's corner block — 24 × 24 = 576 pixels, L = 256, so β = 2.25c: c = 1 → β = 2.25 E = 491 of 576 (85.2% of the mass redistributed) → slope bound 1.845 c = 2 → β = 4.50 E = 423 (73.4%) → slope bound 2.724 c = 3 → β = 6.75 E = 362 (62.9%) → slope bound 3.615 c = 4 → β = 9.00 E = 307 (53.3%) → slope bound 4.515 c = 6 → β = 13.50 E = 207 (35.9%) → slope bound 6.334 The bound tracks c closely, which is what makes c a usable dial: it is very nearly "the largest local contrast gain, in multiples". The integer table T rounds, so its largest step can exceed the real-valued bound by at most one.

c = 1 would clip every bin to the mean height, which is the same as doing nothing at all after redistribution — the curve becomes the identity. c → ∞ is plain AHE. Values between 2 and 4 are what people use, and the reason is now visible rather than folkloric: they cap the local contrast gain at 2× to 4×, which is above the gain a real feature needs and below the gain that makes noise objectionable.

07 Why histogram equalisation is often a bad idea

It is the default demonstration in every image processing course and it is rarely the right thing to run on a photograph. Five separate objections, each of which is a real failure mode rather than a matter of taste.

objection 1
It amplifies noise exactly where noise is worst
Dark regions have the most pixels per code value in an under-exposed image, so the CDF is steepest there, so the gain is largest there. But dark regions are also where Part 1 §25's shot noise has the worst signal-to-noise ratio. The operator therefore applies its maximum gain to the noisiest part of the image. The clip limit of §06 exists entirely because of this.
objection 2
It cannot create levels, only merge them
T is a map on 256 symbols. Where it is steep it leaves gaps — output levels that no pixel occupies — and where it is shallow it merges distinct inputs irreversibly. Gaps are visible as banding on smooth gradients; merges are quiet and permanent. The entropy inequality of §05 is the formal statement.
objection 3
It destroys radiometric meaning
After equalisation a pixel's value encodes its rank in this image, not the light that fell on the sensor. Any downstream step that assumed radiometric consistency — stereo matching across two views, temporal differencing, HDR merging, physically based shading estimation — is now comparing two different monotone reparameterisations. If it must be applied, apply the same curve to every image in the set.
objection 4
It optimises a criterion nobody wants
Uniformity of the grey-level distribution is not a perceptual goal. Real photographs have most of their pixels in the midtones and a long thin tail in the highlights, and forcing that tail to occupy a quarter of the range is what makes an equalised image look flat and "muddy". §05's α blend and §06's local version both exist to back away from the criterion.
objection 5
It is content-dependent and therefore unstable
Two consecutive frames of a video that differ only by a bright object entering the corner get two different curves, so the whole background changes brightness. Equalisation applied per frame flickers. Any video use needs the curve temporally smoothed or computed once on a reference frame.
when it is right
Machine consumption, not viewing
Equalisation is a legitimate normaliser when the downstream consumer cares about ordering and not magnitudes: matching under unknown illumination, medical and astronomical images where the interesting structure is genuinely in a narrow band, and as a preprocessing step before a detector that was trained on equalised inputs. Its very defect — that it discards absolute level — is the property being bought.
The practical replacement. For display, a gentle S-curve in linear light plus a mild local operator does everything equalisation was reaching for without any of the above. For analysis, prefer normalising the mean and variance (a two-parameter affine map, invertible, entropy-preserving up to quantisation) over normalising the whole distribution. Both are point operators; both are one lookup table; neither is fashionable, and both are better.
