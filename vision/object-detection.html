Object Detection

Classification answers what is in an image. Detection also answers where, for every instance of every class, and the number of instances is not known in advance. That one change, from a fixed-size output to a variable-size set, explains nearly every component on this page. Anchors and proposals turn the set into a fixed grid of guesses. Non-maximum suppression turns the grid back into a set. DETR removed both by predicting the set directly. The evaluation metric, mAP, has to score a ranked set against another set. Read the families below as different answers to one question: how do you make a network emit a set?

01 The task: a variable-size set of (box, class, score)

A detector outputs a set {(bᵢ, cᵢ, sᵢ)}: an axis-aligned box, a class and a confidence for each object found. Ground truth is a set of (box, class) pairs. Every design decision below is about producing the first set and comparing it with the second.

image→backbone (CNN / ViT)→multi-scale features (FPN)→dense candidates: anchors, points or queries→classify + regress each→NMS or set matching→final detections
§05 · two-stage
Propose, then classify
A region proposal network finds about a thousand class-agnostic candidates. A second head crops features for each and classifies and refines it. Accurate and slower: the R-CNN family.
§06 · one-stage
Classify every anchor at once
Predict class and box offsets directly at every location and anchor of a dense grid. Fast, and dominated by easy negatives until focal loss fixed it: YOLO, SSD, RetinaNet.
§07 · anchor-free
Points instead of boxes
Each feature-map location predicts its distances to the box edges (FCOS), or objects are heatmap peaks at their centres (CenterNet). Fewer hyperparameters.
§10 · set prediction
Emit the set directly
A fixed number of learned queries attend to the image, each predicting one object or "nothing". Training uses a one-to-one Hungarian matching, so there are no anchors and no NMS: DETR.

02 Box parameterisation and regression targets

A box can be written as corners (x₁, y₁, x₂, y₂) or as centre-size (x, y, w, h). The network does not regress either one directly. It regresses an offset relative to a reference box (an anchor or proposal), normalised so that the target is scale-invariant and roughly unit-variance.

targets for ground truth (x, y, w, h) relative to an anchor (xₐ, yₐ, wₐ, hₐ) — the R-CNN / Faster R-CNN encodingtₓ = (x − xₐ) / wₐ t_y = (y − yₐ) / hₐ t_w = log(w / wₐ) t_h = log(h / hₐ) decoding a prediction (t̂ₓ, t̂_y, t̂_w, t̂_h) back into a boxx̂ = xₐ + wₐ·t̂ₓ ŷ = yₐ + hₐ·t̂_y ŵ = wₐ·exp(t̂_w) ĥ = hₐ·exp(t̂_h) smooth-L1 (Huber) loss on each coordinate, β = 1ℓ(d) = 0.5·d² / β if |d| < β, |d| − 0.5·β otherwise
  • Why divide by the anchor size. A 10-pixel error is negligible on a bus and fatal on a bird. Dividing by wₐ makes the target mean the same thing at every scale, so one regression head can serve all of them.
  • Why the log on width and height. Size is multiplicative: doubling and halving should be symmetric, and the decoded exp keeps sizes positive. Implementations also divide the targets by fixed standard deviations (commonly 0.1, 0.1, 0.2, 0.2) so the four loss terms have similar scale.
  • The coordinate losses do not optimise what is scored. Four independent L1 terms treat the coordinates as unrelated and ignore box size. The metric is IoU. That mismatch is what the IoU-family losses of §03 fix. FCOS (§07) uses a different parameterisation: four distances from a point to the edges.

03 IoU, GIoU and DIoU: measuring and optimising overlap

Intersection over union is the currency of detection. It decides which anchors are positives (§04), which boxes NMS removes (§09) and whether a detection counts as correct (§11). As a loss it has one flaw: when two boxes do not overlap, it is zero no matter how far apart they are, so it gives no gradient.

for boxes A, B, and C the smallest axis-aligned box enclosing bothIoU(A, B) = |A ∩ B| / |A ∪ B| ∈ [0, 1] GIoU = IoU − |C \ (A ∪ B)| / |C| ∈ (−1, 1] DIoU = IoU − ρ²(a, b) / c² ∈ (−1, 1] ρ = distance between the box centres a, b; c = diagonal length of C. Losses are 1 − score, each in [0, 2)L_IoU = 1 − IoU L_GIoU = 1 − GIoU L_DIoU = 1 − DIoU
Two boxes, three overlap scores, and the one case where IoU goes silent drag the boxes apart until they stop touching; IoU flattens, GIoU and DIoU keep falling
  • Partial overlap (default): IoU 0.191, GIoU 0.013, DIoU 0.098. GIoU subtracts the empty part of the enclosing box, so it punishes the diagonal misalignment harder than IoU does.
  • Disjoint, close → far apart: IoU is 0.000 in both. GIoU goes from −0.400 to −0.826 and DIoU from −0.294 to −0.521. Only the latter two tell the optimiser which way to move. That is why DETR (§10) and most modern heads use a GIoU or DIoU term.
  • One inside the other: C equals the larger box, so GIoU collapses to IoU (0.093 both). Its extra term is zero and it cannot tell where inside the small box sits. DIoU's centre-distance term still can, which was the motivation for DIoU (CIoU adds an aspect-ratio term on top).
  • Same size, shifted 20 px on a 160-px box: IoU 0.620. The same 20-px shift on a 26-px box leaves IoU at 0.027. Hold that thought until §08.

04 Anchors and label assignment: turning a set into a grid

A network outputs fixed-size tensors, and the scene contains an unknown number of objects. Anchors bridge the two. At every cell of a stride-s feature map, place A reference boxes of several scales and aspect ratios. Each anchor is then a fixed slot that learns "is there an object like me here, and how should I move to fit it?".

output size of an anchor head on an H/s × W/s feature map with A anchors and K classesclassification: (H/s)·(W/s)·A·K box regression: (H/s)·(W/s)·A·4 Faster R-CNN RPN: 3 scales × 3 ratios gives A = 9; a ~1000×600 image at stride 16 gives about 20 000 anchors
  • Assignment is the real training-time decision. An anchor is a positive if its IoU with some ground-truth box exceeds a high threshold (0.7 in the RPN, 0.5 in RetinaNet). It is a negative below a low threshold (0.3 in the RPN, 0.4 in RetinaNet). In-between anchors are ignored. Each ground truth also takes its single best anchor, so that no object is left without one.
  • The resulting imbalance is extreme: thousands to a hundred thousand negatives per image against a handful of positives. Two-stage detectors survive it by sampling (for example 256 anchors at up to 1:1). One-stage detectors needed the focal loss of §06.
  • Anchor shapes are hyperparameters, and they leak dataset bias. YOLOv2 picked its anchor priors by k-means on the training boxes with 1 − IoU as the distance. Objects whose shape no anchor matches are learned poorly. Adaptive assignment (ATSS chooses the IoU threshold per object from its candidates' statistics) and the anchor-free heads of §07 were the responses.

05 Two-stage detectors: R-CNN → Fast R-CNN → Faster R-CNN → Mask R-CNN

The two-stage idea is to split detection into a cheap, class-agnostic "is something here?" stage and an expensive "what is it, exactly where?" stage that runs only on the survivors. Each version moved one more piece inside the network.

ModelProposalsPer-region featuresWhat it fixed
R-CNN (2014)~2000 from selective search (hand-crafted grouping)Warp each crop to 227×227 and run the whole CNN on each; SVM classifiersFirst to show CNN features crush hand-crafted ones for detection. Very slow: one forward pass per proposal.

two-stage training objective (Faster R-CNN, trained jointly)L = L_cls^RPN(objectness) + λ·L_box^RPN + L_cls^head(K+1 classes) + λ·L_box^head box terms apply only to positives; the head's K+1-th class is background
  • Why RoI Align matters. RoI pooling rounds the proposal to the feature grid and then rounds again into bins. At stride 16, one feature cell is 16 pixels, so rounding shifts the box by up to that much. RoI Align samples the feature map bilinearly at regularly spaced points inside each bin, typically 2×2 per bin, and averages them. Nothing is rounded. Mask quality rose substantially and box AP rose by a smaller amount.
  • The second stage refines twice: once from the anchor to the proposal, once from the proposal to the final box. Cascade R-CNN extends this to several stages with rising IoU thresholds, each trained on the previous stage's output distribution.

06 One-stage detectors: YOLO, SSD, and RetinaNet's focal loss

Drop the proposal stage and classify every anchor directly. That is much faster, but now the classifier faces the full imbalance of §04 with no sampling to shield it. The cross-entropy summed over ~100 000 easy negatives swamps the gradient from the few positives.

  • YOLO (2016) divides the image into an S×S grid (7×7). Each cell predicts B = 2 boxes with confidences plus one set of class probabilities, so the output for 20 classes is one 7×7×30 tensor from a single network pass, at real-time speed. Coarse cells hurt small and clustered objects. Later versions added anchors, multi-scale heads and, recently, anchor-free and NMS-free designs.
  • SSD (2016) attaches anchor heads to several feature maps of decreasing resolution. Small objects are predicted from early, high-resolution maps and large ones from late maps. It was multi-scale before FPN, but the early maps were semantically weak.
  • RetinaNet (2017) showed the accuracy gap to two-stage detectors was not structural. It was the loss. With an FPN backbone and the focal loss it matched or beat two-stage accuracy at one-stage speed.
focal loss — p is the predicted probability of the positive class, y ∈ {0,1}p_t = p if y = 1, 1 − p otherwise α_t defined the same way from α CE(p_t) = −log p_t FL(p_t) = −α_t · (1 − p_t)^γ · log p_t RetinaNet: γ = 2, α = 0.25 down-weighting factor FL / CE = α_t · (1 − p_t)^γ, at γ = 2 (ignoring α)p_t = 0.5 → ×1/4 p_t = 0.9 → ×1/100 p_t = 0.968 → ×≈1/1000
  • The (1 − p_t)^γ factor is a soft, automatic hard-example miner. A negative the model already rejects with 99% confidence contributes 10⁻⁴ of its cross-entropy, so the tens of thousands of easy background anchors stop dominating. Hard and misclassified examples (p_t small) keep almost their full loss.
  • α is a separate, smaller lever. It re-weights classes by a constant. It ends up at 0.25, which down-weights positives, because the γ term has already removed most of the negatives' mass. The loss is normalised by the number of positive anchors, not by all anchors.
  • The bias initialisation is half the trick. The final classification bias is set to b = −log((1 − π)/π) with π = 0.01, so every anchor starts predicting "background" at 0.99. Without it, the first iterations produce a huge loss from the negatives and training diverges.

07 Anchor-free detectors: FCOS and CenterNet

Anchors bring hyperparameters (scales, ratios, IoU thresholds) and a large number of mostly useless boxes. Anchor-free detectors make the feature-map location itself the reference.

FCOS — a location (x, y) inside ground-truth box (x₁, y₁, x₂, y₂) regresses four distancesl* = x − x₁ t* = y − y₁ r* = x₂ − x b* = y₂ − y centre-ness, predicted by a parallel branch and multiplied into the class score at test timecentreness = √( min(l*, r*)/max(l*, r*) · min(t*, b*)/max(t*, b*) ) 1 at the centre, → 0 at the edge
  • FCOS (2019) is per-pixel prediction on an FPN. Every location inside a box is a positive. Ambiguity from overlapping boxes is resolved by giving each FPN level a range of box sizes, and then preferring the smallest box. Off-centre locations produce poor boxes, which the centre-ness branch down-weights before NMS. It uses focal loss for classes and an IoU loss for the box.
  • CenterNet ("Objects as Points", 2019) predicts a per-class heatmap at output stride 4, with each object splatted as a Gaussian at its centre, plus a size and a sub-pixel offset at each peak. Detection is peak finding: a 3×3 max-pool keeps local maxima. That replaces box-level NMS for most scenes, though two objects sharing a centre cell collide.
  • The deeper lesson (made explicit by ATSS) is that anchor-based and anchor-free detectors differ mainly in how they choose positives, not in whether a box template exists. Give an anchor-based RetinaNet FCOS's assignment and most of the gap closes.

08 Feature pyramids, and why small objects stay hard

Objects span two orders of magnitude in size. Deep features are semantically strong and spatially coarse. Shallow features are the opposite. A Feature Pyramid Network gives every scale both.

C2 (s=4)C3 (s=8)C4 (s=16)C5 (s=32)→ top-down: upsample ×2 + 1×1 lateral add, then 3×3 smooth →P2 … P5 (+P6, P7)
FPN level for an RoI of size w × h in a two-stage detector (k₀ = 4, canonical size 224)k = ⌊ k₀ + log₂( √(w·h) / 224 ) ⌋ clamped to the available levels
  • Top-down plus lateral connections carry semantics from C5 down to high-resolution maps, where small objects live. Every level gets the same channel width (256), so one shared head can run on all of them.
  • Why small objects are hard, in three independent ways. Information: a 16×16 object at stride 32 is half a feature cell, and it is gone before any head sees it. Assignment: few anchors reach a high IoU with a tiny box, so it gets fewer positives. Metric: IoU is brutal on small boxes. A 4-pixel diagonal error leaves IoU at 0.906 on a 160-px box and 0.558 on a 26-px one. A 4-px horizontal error on a 16-px box gives 0.600, failing every threshold above .6.
  • The remedies are higher input resolution, tiling large images, a P2 level, copy-paste augmentation of small instances, and scale-aware training (SNIP / SNIPER). On COCO, "small" (area < 32² px) AP is typically around half of "large" (> 96² px) AP, even for strong detectors.

09 Non-maximum suppression: from a dense grid back to a set

A dense head fires many overlapping boxes on every object. NMS keeps the best and removes its near-duplicates. It is a greedy, hand-designed, non-differentiable post-process, and its one threshold trades duplicates against missed objects in crowds.

greedy NMS, per class, with IoU threshold τsort candidates by score; keep ← ∅ while candidates remain: m ← highest-scoring remaining box; keep ← keep ∪ {m} remove every remaining b with IoU(m, b) > τ (typical τ = 0.5 – 0.7) Soft-NMS: decay instead of deletes_b ← s_b · exp( −IoU(m, b)² / σ )
Greedy NMS step by step, and the average precision of what it leaves behind step through at τ = 0.5, then try 0.2 and 1.0; hover a box for its score and fate
  • At τ = 0.5 NMS keeps 7 boxes: the best box on each of the four objects plus the three background false positives, which overlap nothing. AP@.50 is 1.000, AP@.75 is 0.752 (the bird's best box has IoU 0.73 and fails at .75), and AP@[.50:.95] is 0.801.
  • Drop τ to 0.3. The two people's best boxes overlap at IoU 0.34, so the left person's box (0.95) suppresses the right person's (0.90). A worse duplicate, #5 at score 0.55 and IoU 0.73 with the right person, happens to survive and rescues AP@.50. The stricter thresholds suffer: AP@[.50:.95] falls to 0.702. At τ = 0.2 the right person is lost outright, AP@.50 = 0.752. Low τ kills crowds.
  • Raise τ to 0.8 or 1.0. Duplicates survive (14 and 15 boxes kept). Each one is a false positive at evaluation time, because a ground-truth box can be matched only once. AP@.50 falls to 0.876 and 0.862. High τ floods duplicates. No single τ is right for both isolated objects and crowds. That tension motivated Soft-NMS, learned NMS, and finally the NMS-free set prediction of §10.

10 DETR: detection as direct set prediction with Hungarian matching

DETR (2020) asks the network for the set itself. A CNN backbone feeds a Transformer encoder. A decoder takes N = 100 learned object queries, and each query cross-attends to the image and outputs one (class, box) pair, where the class may be "no object" ∅. Training needs a rule for which query is responsible for which object, and the answer is the optimal one-to-one assignment.

bipartite matching over permutations σ of the N predictions (ground truth padded with ∅ to size N)σ̂ = argmin_σ ∑ᵢ L_match( yᵢ , ŷ_σ(i) ) solved exactly by the Hungarian algorithm, O(N³) L_match = −𝟙[cᵢ ≠ ∅]·p̂_σ(i)(cᵢ) + 𝟙[cᵢ ≠ ∅]·L_box(bᵢ, b̂_σ(i)) box loss — L1 on normalised (cx, cy, w, h) plus GIoU; the paper uses λ_L1 = 5, λ_iou = 2L_box = λ_iou · (1 − GIoU(b, b̂)) + λ_L1 · ‖b − b̂‖₁ Hungarian loss on the matched pairs; the ∅ class term is down-weighted by 10 against imbalanceL = ∑ᵢ [ −log p̂_σ̂(i)(cᵢ) + 𝟙[cᵢ ≠ ∅]·L_box(bᵢ, b̂_σ̂(i)) ]
  • Why no NMS is needed. One-to-one matching means a second query predicting the same object is matched to ∅ and penalised for not saying "no object". The decoder's self-attention between queries lets them coordinate who takes what. Duplicate removal is learned, not hand-designed.
  • The costs. The original DETR needed about 500 training epochs, against roughly 36 for an FPN Faster R-CNN, and it was weak on small objects: global attention is quadratic in the number of tokens, so it runs only on the coarse C5 map. The matching is also unstable early in training, when every query is equally bad.
  • The fixes made the family state of the art. Deformable DETR attends to a few sampled points across multi-scale maps, converging in about a tenth of the epochs and handling small objects. Later variants added anchor-like query positions, denoising training and many-to-one auxiliary assignment. The attention mechanics are on Attention, and DETR's model card is on Vision Models.

11 Evaluation: mAP@[.5:.95] from precision and recall

A detector's output is a ranked list. Average precision scores the whole ranking at once, for one class and one IoU threshold. COCO's headline "AP" then averages over 10 IoU thresholds and 80 classes. Every step of that chain is a choice worth knowing.

  1. Pool and sort. Collect all detections of class k over the whole test set and sort them by score (at most 100 per image on COCO).
  2. Match greedily. In score order, each detection is a true positive if its IoU with some not-yet-matched ground-truth box of that class is ≥ t, and that ground truth is then consumed. Otherwise it is a false positive. Duplicates are therefore false positives. Unmatched ground truths are false negatives.
  3. Trace the curve. After the n-th detection, precision = TP/n and recall = TP/#GT.
  4. Interpolate and integrate. Replace precision by its running maximum to the right, then average it at 101 equally spaced recall points.
  5. Average. Over thresholds t ∈ {0.50, 0.55, …, 0.95} and over classes.
COCO-style AP for one class at IoU threshold tp_interp(r) = max_{ r′ ≥ r } p(r′) AP_t = (1/101) · ∑_{ r ∈ {0, 0.01, …, 1} } p_interp(r) the headline numberAP@[.5:.95] = (1/10) ∑_{ t = .50, .55, …, .95 } (1/K) ∑ₖ AP_t(k) PASCAL VOC reports only AP@.5 (11-point interpolation in VOC2007, all-point from 2010)
Reported numberWhat it rewards
AP@.50 ("AP50", VOC mAP)Finding objects with roughly right boxes. Lenient: a box shifted by a third of its width can still pass.

The traps. "mAP" means AP@.5 in VOC papers and AP@[.5:.95] in COCO papers, and the two differ by 20–30 points for the same model. Always say which. AP also ignores calibration and the operating point: two detectors with equal AP can need very different score thresholds in deployment, so pick the threshold on validation data for the precision you need. The general precision-recall and threshold machinery is on Model Evaluation.

Takeaways

  • Detection = classification + box regression over a variable-size set. Boxes are regressed as normalised offsets from a reference (Δ/w, log of size ratios), and increasingly with an IoU-family loss.
  • IoU is the currency for assignment, suppression and scoring. GIoU and DIoU keep a gradient when boxes do not overlap.
  • The imbalance between object and background shaped the field. Two-stage designs sample, one-stage designs use focal loss −α_t(1 − p_t)^γ log p_t with γ = 2.
  • FPN gives every scale semantic features. Small objects remain hard for informational, assignment and metric reasons at once.
  • NMS's one threshold trades duplicates against crowd misses. DETR's Hungarian matching removes it by learning one-to-one prediction.
  • Report AP@[.5:.95] together with AP50, AP75 and APₛ/ₘ/ₗ, and never write "mAP" without saying which one.
